## Description

**What would you like to be added**:

Add a lightweight simulator for Kueue. kube-scheduler integration can be considered later as an optional extension, but it should not block the initial simulator.

**Why is this needed**:

The main goal of this simulator is to **simulate a large number of workloads virtually and cheaply without building a real Kubernetes cluster(ex. kwok)**.

Today, it is expensive and slow to validate Kueue behavior with real workloads because it usually requires setting up a real cluster and running real workloads.

A lightweight simulator would make it much easier to:

- test Kueue policy and admission behavior
- compare queueing / preemption / fair sharing configurations
- reproduce workload waiting / admission / eviction scenarios
- run large-scale what-if analysis with low cost
- do regression testing for Kueue changes

For the MVP, it is more important to model **Kueue decision-making** accurately than to model full Kubernetes end-to-end execution.

### Comment by [@abd-ulbasit](https://github.com/abd-ulbasit) — 2026-10-17T10:11:59Z

Hi! I'd like to pick this up. Disclosure: I use AI coding assistants for drafting and code; I review and test everything myself.

Proposal: an offline, deterministic replay tool that runs Kueue's real scheduling cycle (queue manager + cache + scheduler, same wiring as the scheduler unit tests) against a fake client and fake clock. Input: a workload trace (arrival, duration, LocalQueue, priority, requests) plus two scenario files of plain v1beta2 objects (ClusterQueues, Cohorts, flavors, fair sharing). Output: per-LocalQueue/ClusterQueue wait-time percentiles, admissions, evictions and utilisation, and the A-vs-B diff. No new CRD and no API change; only small exported entry points in `pkg/scheduler` (plus possibly a behaviour-neutral deterministic tie-break in the queue manager). It can also import the perf `generator.yaml`, so I can check its predictions against `run-performance-scheduler` (envtest) and against a real cluster.

Plan: (1) KEP `keps/10168-kueue-simulator`, building on and crediting #10234 by @isumitsolanki and @kimminw00's original proposal; (2) a small `pkg/scheduler` PR exporting a single-cycle entry point, an admission-wrapper option and a non-test clock option; (3) the tool under `cmd/experimental/kueue-simulator` with docs. This is complementary to #15614/#15615 (point-in-time "does this job fit now") and unrelated to the TAS `SchedulerSimulator`.
