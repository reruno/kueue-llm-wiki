## Description

**What would you like to be added**:

I’d like ClusterQueue to support automatic quota detection based on node selectors. By passing a match expression (or an empty selector to watch all nodes), the quota can dynamically sync with the cluster's current capacity. This removes the manual overhead of adjusting limits during node pool scaling.

**Why is this needed**:

Currently, users must manually sync ClusterQueue quotas with the underlying infrastructure. I would like Kueue to support a mode where limits default to the actual available resources in the cluster (with configurable headroom for system resources). This allows capacity management to be handled at the node pool level (e.g., via max nodes settings), with Kueue dynamically inheriting those boundaries rather than requiring redundant manual updates."

I've opened my draft as well: [#16110 ](https://github.com/kubernetes-sigs/kueue/pull/16110). I built it on top of the now-merged Dynamic Quota Orchestration framework (KEP-12382) rather than the older standalone NodeQuotaPolicy approach from #10745. The core of it is a built-in local-capacity CapacityProvider that:
- watches Nodes and buckets each into a ResourceFlavor using the flavor's existing nodeLabels (one source of truth, shared with the scheduler),
- sums allocatable and publishes raw capacity to CapacityProvider.status,
- leaves operational headroom to the DQO effectiveCapacityMultiplier (no new knob on the provider),
- is Nodes-only for alpha behind a dedicated NodeCapacityProvider feature gate, with DRA ResourceSlice discovery as a follow-up.

It also works through a couple of things I expect reviewers to care about: the node-label source-of-truth / prerequisites, and capacity ownership & overlap — proportional distribution within a subtree, plus the cross-DQO and overlapping-flavor cases DQO doesn't guard automatically today.
