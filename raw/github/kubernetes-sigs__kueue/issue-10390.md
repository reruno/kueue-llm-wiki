## Description

**What would you like to be cleaned**:
We are currently maintaining a dependency on the https://github.com/kubernetes-sigs/cluster-inventory-api package to inject the secret reader plugin for e2e tests. Used here:
https://github.com/kubernetes-sigs/kueue/blob/9c0749e024fc787f63165c99053ec2c0bd8fd8ff/test/e2e/multikueue/e2e_test.go#L2175-L2178
and here:
https://github.com/kubernetes-sigs/kueue/blob/9c0749e024fc787f63165c99053ec2c0bd8fd8ff/test/e2e/multikueue/e2e_test.go#L2183-L2191

From what I can see, the plugins are already packaged into Docker images:
https://github.com/kubernetes-sigs/cluster-inventory-api/pkgs/container/cluster-inventory-api%2Fsecretreader/783588149?tag=0.1.0

But I think it's private for now. We could see whether it's going to be made public.

**Why is this needed**:
To simplify the end-to-end testing setup and reduce the maintenance overhead.
See: https://github.com/kubernetes-sigs/kueue/pull/10385, https://github.com/kubernetes-sigs/kueue/issues/10380, https://github.com/kubernetes-sigs/kueue/pull/10372

### Comment by [@kahirokunn](https://github.com/kahirokunn) — 2026-06-09T02:59:00Z

Hi @kshalot @vladikkuzn

Sorry for pointing you toward the image-volume path earlier without calling out the older Kubernetes-version case clearly enough.

For the image-volume path, one caveat from the Cluster Inventory API side is that it may be better to wait for kubernetes-sigs/cluster-inventory-api#68 and the next plugin image release, likely `v0.1.3`, before switching the test to the official image:

https://github.com/kubernetes-sigs/cluster-inventory-api/pull/68

That PR fixes the plugin image target-architecture handling. If the Kueue test only needs the amd64 image, `v0.1.2` may already be enough, but waiting for the next release should make the image-volume path cleaner across architectures.

For environments where image volumes are not available, the OCI plugin images can still be consumed with an initContainer-based fallback. I am currently working on documentation for that pattern here:

https://github.com/kubernetes-sigs/cluster-inventory-api/pull/71

If you have any feedback on the fallback approach, I would really appreciate comments or suggestions on that PR. Since Kueue is one of the concrete consumers for this use case, your input would help make the guidance more useful.
