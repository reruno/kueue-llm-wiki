## Description

**What happened**:

**What you expected to happen**:

TAS: NodeHotSwap should not add "late pods" to UnhealthyNodes. 

This is something we encountered investigating the incident mostly fixed by https://github.com/kubernetes-sigs/kueue/issues/10660, but this issue still remains - the "late pods" should not be added to UnhealthyNodes on re-admission.

Consider the following scenario:
1. Workload is running, all Pods are running
2. One of the pods (on Node "x") starts to terminate, and roughly at the same time the Workload is evicted (for another reason) - this removes the Pod from Unhealthy Pods
3. the Pod is terminating very long, either due to Node "x" failure, or just long terminationGracePeriodSeconds
4. the workload is re-admitted and the Pods get to run, the new toplogyAssignement does not mention node "x"
5. the "late pod" - terminating from (2.) is still added to UnhealthyNodes - this triggers unnecessary work by Kueue scheduler 

**How to reproduce it (as minimally and precisely as possible)**:

 I think we can repro  that in integration or e2e tests.

**Anything else we need to know?**:

The scenario encountered on the real cluster also included a custom admission check, but AFAIK it is not relevant for the repro.

Pod that gets deleted triggers Reconcile - https://github.com/kubernetes-sigs/kueue/blob/521454b551084164cf02671578222f68f2a9aef8/pkg/controller/tas/node_controller.go#L131 - and in case when Node X is `NotReady` it might meet requirements to be seen as node that is `NotReady` for over 30s - https://github.com/kubernetes-sigs/kueue/blob/521454b551084164cf02671578222f68f2a9aef8/pkg/controller/tas/node_controller.go#L151
7. The reconcile adds the node to unhealthy nodes list by calling handleUnhealthyNode - https://github.com/kubernetes-sigs/kueue/blob/521454b551084164cf02671578222f68f2a9aef8/pkg/controller/tas/node_controller.go#L180 - but it doesn't exit the `Reconcile` yet
8. `Reconcile` calls reconcileWorkloadsOnNode - https://github.com/kubernetes-sigs/kueue/blob/521454b551084164cf02671578222f68f2a9aef8/pkg/controller/tas/node_controller.go#L476 - and it might fail and return an error for example here - https://github.com/kubernetes-sigs/kueue/blob/521454b551084164cf02671578222f68f2a9aef8/pkg/controller/tas/node_controller.go#L584
9. Reconcile will retrigger because of the error but the pod might be already gone so clearing of unhealthyNodes field will not be performed as this node is no longer connected by anything with the workload.
