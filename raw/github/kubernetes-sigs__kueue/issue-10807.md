## Description


**What happened**:
When a workload has multiple admissionChecks and a newly added admissionCheck transitions to Rejected state, the existing admissionCheck remains in Pending state without updating. More critically, the conditions.Type: Admitted status is not updated to False even though one of the admissionChecks has been rejected.

Current state observed:
```
admissionChecks:
  - name: deploy-to-b300
    state: Pending
    message: 'Reset to Pending after eviction. Previously: Retry'
    retryCount: 4
  - name: my-controller-check
    state: Rejected
    message: 'my message'

conditions:
  - type: Admitted
    status: "True"  # Should be False
    message: The workload is admitted
  - type: Evicted
    status: "True"
    message: At least one admission check is false
```

The Admitted condition still shows status: "True" with message "The workload is admitted", even though  added admissionCheck is in Rejected state.


**What you expected to happen**:
When any admissionCheck transitions to Rejected state, the conditions.Type: Admitted should be updated to status: False with an appropriate reason (e.g., AdmissionCheckFailed) and message indicating which admissionCheck caused the rejection.

Expected state:
```
conditions:
  - type: Admitted
    status: "False"
    reason: AdmissionCheckFailed
    message: 'Admission check is Rejected'
```

**How to reproduce it (as minimally and precisely as possible)**:
1. Create a ClusterQueue with multiple admissionChecks configured.
2. Submit a workload that triggers both admissionChecks.
3. Wait for the workload to be admitted and the remote workload to be created.
4. Trigger eviction on the remote workload.
5. After eviction, observe that all admissionChecks are reset to Pending state.
6. Wait for the additional admissionCheck controller to evaluate its internal logic and transition one admissionCheck to Rejected state while the other admissionCheck remains in Pending state.
7. Verify the Admitted condition status - it incorrectly remains True despite the rejection.
Expected: Admitted condition should be False Actual: Admitted condition remains True with message "The workload is admitted"

`Eviction:` A Workload is evicted from a Worker Cluster.

`Retry:` MultiKueue attempts to evaluate and find resources for the Workload again.

`Rejection:` The `AdmissionCheck` fails to find an available cluster, so it transitions to a Rejected state.

`Expected Behavior:` The controller should update the Workload's overall condition to `Admitted: False` so the client is aware of the failure.

`The Bug:` The controller fails to overwrite the previous state, leaving the Workload condition stuck at `Admitted: True`.

`The Impact (Zombie State):` The client checks the status, sees `Admitted: True`, and assumes the workload is queued or running. In reality, it is internally rejected and permanently stuck with no future progression."
