## Description

**What happened**:

The validation of the FeatureGates happens before the values specified either with ConfigMap or CLI are actually set on the `DefaultMutableFeatureGate`. So, the validation is actually using the default values instead of the ones defined by the user.

**What you expected to happen**:

**How to reproduce it (as minimally and precisely as possible)**:

```
$ kubectl get po kueue-controller-manager-856c45b9dd-qwdbq -n kueue-system -o yaml |grep -e DRAExtendedResources
    - --feature-gates=DRAExtendedResources=true
```

```
kubectl logs -f kueue-controller-manager-856c45b9dd-qwdbq -n kueue-system |grep -e DRAExtendedResources -e DynamicResourceAllocation
{"level":"Level(-2)","ts":"2026-04-30T15:17:38.011102194Z","logger":"setup","caller":"features/kube_features.go:591","msg":"Loaded feature gates","featureGates":{"AdmissionFairSharing":true,"AdmissionGatedBy":false,"AssignQueueLabelsForPods":true,"CustomMetricLabels":false,"DRAExtendedResources":true,"DynamicResourceAllocation":false,
```
According to this code block, the validation should have mentioned `DRAExtendedResources` when enabled should have `DynamicResourceAllocation` enabled as well.

https://github.com/kubernetes-sigs/kueue/blob/f26d35cb3d8a39967839909c66899c86399ce226/pkg/config/validation.go#L532-L536
