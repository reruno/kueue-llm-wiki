## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

➡️⭐ Multiple end users end up making some version of this on their own ⭐⬅️

I need to emit metrics on watch changes in:
- workload admission condition: kueue_workload_admission_condition{phase="", ...}
- workload node assignment: kueue_workload_node_assignment{domain="", domain_id=""...}

The reasoning is similar to https://github.com/kubernetes-sigs/kueue/issues/10505
There is a difference between what Kueue sees for workload scheduling and what the k8s scheduler sees for pod scheduling:
- Its notable to see when the two views diverge
- Platform operators mostly just care about the Kueue view for scheduling questions, and that eventually k8s scheduler catches up. 

Why we shouldn't use kube-state-metrics / the newer RSM:
- KSM doesn't support iterating over arrays
- KSM/RSM depends on a periodic scrape rather than being event driven. I want the historical time accuracy.
- the recommended RSM is still fairly new and evaluation to adopt a new state metrics binary in the system would take a lot more effort. (It doesnt seem like RSM is GA yet: https://github.com/kubernetes-sigs/resource-state-metrics/releases)

**Why is this needed**:
- workload admission condition: construct a timeline for workload admission to eviction
- workload node assignment: view where Kueue assigned the workload even before pods materialize

**Addressing Cardinality Concerns**:
- make this opt-in
- configure an exclude topology configuration for high cardinality domains if that level of granularity isnt needed
- configure which of these metrics you want
