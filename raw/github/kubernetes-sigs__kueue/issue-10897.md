**What would you like to be added**:
Metric dedicated to the resources of CQ workload head. 

kueue_cluster_queue_workload_head_resource_pending

**Why is this needed**:
Context: https://github.com/kubernetes-sigs/kueue/pull/10485#issuecomment-4365189745
Offer more granularity than total pending resource (https://github.com/kubernetes-sigs/kueue/pull/10485) to alert on.

https://github.com/kubernetes-sigs/kueue/pull/10485#issuecomment-4365107644:
> The PR defines "pendingResourcesTotal is the incremental sum of TotalRequests across workloads".
Let's take an example. Say the queue's nominal quota for a resource is 100, resource reservation is 20 and so the unallocated ("remaining nominal") amount is 80. Now, say there are 3 jobs A, B and C with resource needs of 50, 40 and 10, resp. So, pendingResourcesTotal is 100 (A+B+C). It is more than the unallocated amount of 80. So, if we are monitoring the condition if (pendingResourcesTotal <= remaining nominal) then /* some scheduling issue */, that would not trigger, and things would seem normal. However, job A can be admitted. If job A is not admitted for a while, that could be a scheduling problem, but that is not flagged because the metric is a sum across pending workloads rather than per workload.

For this metric, you could alert on this: 
cq workload head <= remaining nominal quota

This would offer more precise granularity on when there's scheduling issues. (Kueue is head of queue blocking per CQ) So this would more precisely tell us, this clusterQueue is blocked on scheduling but potentially shouldn't be (unless there's fragmentation).
