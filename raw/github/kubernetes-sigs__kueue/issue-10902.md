## Description

**What would you like to be added**:
I would like `preferredDuringSchedulingIgnoredDuringExecution` node affinity to not be ignored in TAS

**Why is this needed**:
Improve scheduling configurability

Domains sorting: https://github.com/kubernetes-sigs/kueue/blob/3af386cd515a18d8dfffad4b227d247a6ebf43f8/pkg/cache/scheduler/tas_flavor_snapshot.go#L1548 and with leader: https://github.com/kubernetes-sigs/kueue/blob/3af386cd515a18d8dfffad4b227d247a6ebf43f8/pkg/cache/scheduler/tas_flavor_snapshot.go#L1511

**Concerns**:
Simply adding preferred affinity check at the beginning of `sortedDomains` method changes default behavior of TAS, on the other hand, if you don't define preferred affinity (which wasn't handled before) you will get the same behavior before handling of preferred affinity was introduced.

So currently we have the following order for sorting domains:
- slice-level capacity check
- pod-level capacity check
- lexicographical check

where slice-level and pod-level are configurable with `TASProfileMixed` feature gate.

The easiest solution would be to add affinity check above all of them but the questions is if we need order of these checks to be configurable, and if yes then is it just 1 -> 2, or 2 -> 1 option or something more sophisticated like reordering of these. I'm not sure if there might be added any more checks in future.
