## Description

**What would you like to be added**:

Implement an indexer for Variants within the Concurrent Admission feature to optimize variant lookup and management. Currently, the `getVariantsForParent()` method in `pkg/controller/concurrentadmission/controller.go` (line 205-221) lists all workloads in a namespace and filters them manually. This approach is inefficient and has a TODO comment indicating where indexing should be implemented.

The enhancement should:
- Create an efficient indexer for finding variants by their parent workload
- Integrate the indexer into the controller-runtime's caching mechanism
- Update the `getVariantsForParent()` method to use the new indexer instead of manual filtering
- Ensure all admission/scheduling code paths leverage the optimized lookup

**Why is this needed**:

Currently, every reconciliation of a parent workload requires listing all workloads in the namespace and filtering by parent name. This becomes increasingly expensive as the number of workloads grows. An indexer would provide constant-time lookup for variants belonging to a specific parent workload, significantly improving performance and scalability of the Concurrent Admission feature.

**Completion requirements**:

This enhancement requires the following artifacts:

- [ ] Design doc (optional but recommended for complex indexing strategy)
- [ ] Implementation of variant indexer in the Concurrent Admission controller
- [ ] Updated `getVariantsForParent()` method to use the indexer
- [ ] Unit/integration tests covering the indexer functionality
- [ ] Docs update documenting the performance improvements

**Relevant code reference**:
- [`pkg/controller/concurrentadmission/controller.go`](https://github.com/kubernetes-sigs/kueue/blob/main/pkg/controller/concurrentadmission/controller.go):
  The core logic for variant and parent workload management. The `getVariantsForParent()` method (lines 205-221) is the primary candidate for optimization.
