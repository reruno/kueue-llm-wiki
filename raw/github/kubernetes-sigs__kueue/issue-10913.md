**What happened**:
With the Concurrent Admission feature, the less favorable Variants are deactivated by the concurrentadmission controller when a more favorable Variant is admitted. The controller runs in parallel to Kueue scheduler and there might be an interleaving where:
1) Scheduler admits more favorable Variant
2) Scheduler admits less favorable Variant
3) ConcurrentAdmission controller deactivates less favorable Variant

There's eventual correctness, but we want to eliminate step 2) by adding some checks to scheduler logic that will make sure that if there's more favorable Variant running, scheduler doesn't admit the less favorable one.
