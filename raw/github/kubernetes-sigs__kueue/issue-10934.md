## Description

### What happened?

In `charts/kueue/templates/visibility-apf/flowschema.yaml`:
```yaml
  priorityLevelConfiguration:
    name: kueue-visibility
```

This should use the Helm fullname template to match the PriorityLevelConfiguration name:
```yaml
  priorityLevelConfiguration:
    name: '{{ include "kueue.fullname" . }}-visibility'
```

When `fullnameOverride` or `nameOverride` is set in Helm values, the FlowSchema references a non-existent PriorityLevelConfiguration, breaking the visibility API's API Priority and Fairness configuration.

The PriorityLevelConfiguration in `templates/visibility-apf/prioritylevelconfigurations.yaml` correctly uses the template for its name, but the FlowSchema that references it does not.

### What did you expect to happen?

The FlowSchema should reference the PriorityLevelConfiguration using the same template that creates it, so they always match regardless of Helm release name configuration.

### Environment

- Kueue version: v0.17.2
- Installation method: Helm
- Kubernetes version: 1.30
