## Discussion

### Comment by [@aabhinavvvvvvv](https://github.com/aabhinavvvvvvv) — 2026-05-06T01:14:50Z

This occurs because of the install_prometheus_operator function in the file hack/testing/e2e-common.sh. In Docker-in-Docker CI, it happens because of the lag time in pulling images, pushing the timeout period beyond the hard-coded --timeout=5m in kubectl wait. The easiest fix for this would be increasing the timeout period to --timeout=10m.

### Comment by [@mimowo](https://github.com/mimowo) — 2026-05-15T17:37:56Z

Yes. that would work, but it seems the source of the problem is that the image pull was taking so long. 

We already have pre-pulling for many operators : https://github.com/kubernetes-sigs/kueue/blob/main/hack/testing/e2e-common.sh#L396-L447
but it seems missing for promethues, so we should probably add something like :
```
+  export PROMETHEUS_OPERATOR_IMAGE="quay.io/prometheus-operator/prometheus-operator:${PROMETHEUS_OPERATOR_VERSION}"
+  export PROMETHEUS_CONFIG_RELOADER_IMAGE="quay.io/prometheus-operator/prometheus-config-reloader:${PROMETHEUS_OPERATOR_VERSION}"
```
and 
```
+  if [[ -n ${PROMETHEUS_OPERATOR_VERSION:-} && ("$GINKGO_ARGS" =~ feature:prometheus || ! "$GINKGO_ARGS" =~ "--label-filter") ]]; then
+    e2e_docker_pull_if_needed "${PROMETHEUS_OPERATOR_IMAGE}"
+    e2e_docker_pull_if_needed "${PROMETHEUS_CONFIG_RELOADER_IMAGE}"
+  fi
```
