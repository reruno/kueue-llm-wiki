**What would you like to be added**:
I noticed that if you set your context to a worker cluster, if the prebuilt workload is cancelled because it won on another cluster, its still considered preempted. 

I find that confusing. We should add a new event category. Maybe like "PrebuiltCancelled" or something because this workload on the worker cluster is a "fake" placeholder workload. (Call the event whatever, just something different than a normal preemption)

**Why is this needed**:
Its sorta not really preemption and makes understanding whats happening on a multicluster level confusing.
