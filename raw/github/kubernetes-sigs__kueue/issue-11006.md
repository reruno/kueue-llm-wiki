## Description

**What would you like to be added**:
Namespace selector for webhooks targeting pods, jobs, and deployments that excludes them from targeting objects created in `kube-system` namespace.

It may be also worth it to exclude kueue namespace.

**Why is this needed**:
Currently when `Kueue` is failing, webhooks will block any pod creation in `kube-system` namespace as they have `FailurePolicy: Fail`. This might result in clusters without possibility of failure recovery as various cluster critical pods update or creation will be blocked.

**Completion requirements**:
Addition of namespace exlusions [here](https://github.com/kubernetes-sigs/kueue/blob/3b5147d997cccb8e61ae39032aeddd5c7157ede9/config/components/webhook/manifests.yaml#L188) and in other related webhooks.

### Comment by [@mimowo](https://github.com/mimowo) — 2026-05-07T11:55:13Z

Yes, for sure the current defaults are hard to operationalize on real environments, and this is what we are also facing currently at gke.

Requiring extra label "namespace-managed-by-kueue" on namespaces managed by Kueue seems like a good idea for operationalizing Kueue on prod environments, but that would be a badly breaking change to some of our users, because it would require an explicit opt-in.

So, excluding kube-system and kueue-system by default seems like a sensible compromise - users (platform engineers like at OpenShift or gke) are still free to have have the "namespace-managed-by-kueue" label for more robust setups, but at least we don't mess with the kube-system when installing Kueue OOTB.
