### Comment by [@mszadkow](https://github.com/mszadkow) — 2026-05-21T08:07:49Z

Reconcile reads a stale cache that showed `ClusterName = "worker1"` (already cleared in etcd), so it skipped setting `NominatedClusterNames` but still created worker2's workload.
Once worker2 admitted that workload, every future reconcile tried to promote worker2 to `ClusterName`, but the webhook permanently blocked it because `NominatedClusterNames` was never set.

In another words:
1. Stale cache: ClusterName = "worker1", NominatedClusterNames = nil
2. Nomination guard skipped - worker2 created unconditionally
3. Worker2 admitted → syncReservingRemoteState tries SSA: ClusterName = "worker2", NominatedClusterNames = nil
4. Webhook: oldObj.NominatedClusterNames = nil → doesn't contain "worker2" → rejected forever
