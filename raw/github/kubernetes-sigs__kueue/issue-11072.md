### Comment by [@mimowo](https://github.com/mimowo) — 2026-05-15T13:17:42Z

I have analyzed the issue with the flake debugger skill and this is accurate:
Exact source path that produces the message:

ValidateCreate/ValidateUpdate
→ validateCreate
→ validateTopologyRequest
→ podSets(ctx, trainJob)
→ getChildJobSet(ctx, t)
→ getRuntimeSpec(ctx, trainJob)

The literal error string is constructed in pkg/controller/jobs/trainjob/trainjob_controller.go:

trSpec, err := getRuntimeSpec(ctx, trainJob)
if err != nil {
    return nil, fmt.Errorf("runtime '%s' not found", trainJob.Spec.RuntimeRef.Name)
}

So, the issue is that even thought the test code creates first runtime, then TrainJob, the informer inside Kueue may receive the update on a watch about the TrainJob first. In that case the webhook fails because it cannot verify the TrainerRuntime status.

The options I see:
1. fix the flake using `MustCreateWithRetry` for the child job in all tests. 
2. fix the webhook code by falling back to "real Get" instead of "cache get" when NotFound is returned. 

I guess (2.) is slighlty better long term, but for now (1.) is more important. Also, I'm not totally sure about (2.), because maybe he "real" Get from webhook may cause long webhook delays which can cascade. FInally, I think on more systems realistically the TrainerRuntime is created much earlier than the TrainJob.
