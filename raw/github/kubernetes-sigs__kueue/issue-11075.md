### Comment by [@abdelrahmanmagdii](https://github.com/abdelrahmanmagdii) — 2026-11-15T17:48:52Z

@mimowo
 So most other projects pin a standalone kustomize library, only a few switched to kubectl kustomize. We use kustomize edit which is not on kubectl, kernel-module-management hit this problem and kept the program for edit.

--------Here's a list of what I found----------

**Switched to kubectl kustomize:**

Gateway API ([kubernetes-sigs/gateway-api#381](https://github.com/kubernetes-sigs/gateway-api/issues/381)): kustomize is already in kubectl.
Argo Workflows ([argoproj/argo-workflows#6546](https://github.com/argoproj/argo-workflows/issues/6546)): same reason.
Spark Operator ([kubeflow/spark-operator#2929](https://github.com/kubeflow/spark-operator/issues/2929)): to test the same kubectl apply -k path users install with.
llm-d router ([llm-d/llm-d-router#665](https://github.com/llm-d/llm-d-router/issues/665)): to avoid installing two binaries.
kernel-module-management ([kubernetes-sigs/kernel-module-management#75](https://github.com/kubernetes-sigs/kernel-module-management/issues/75)): switched, but kept the binary for kustomize edit.

**Kept the binary:**

Cluster API ([kubernetes-sigs/cluster-api#2024](https://github.com/kubernetes-sigs/cluster-api/issues/2024)): the kubectl kustomize fallback didn’t work.
JobSet ([kubernetes-sigs/jobset#74](https://github.com/kubernetes-sigs/jobset/issues/74)): added a pinned binary because e2e failed without it.
