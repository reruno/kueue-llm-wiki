## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

We need a way to request Kueue to re-evaluate the node placement of one or more pods of a workload without requeueing the complete workload. Today, it is supported as part of [TAS hot swap](https://kueue.sigs.k8s.io/docs/concepts/topology_aware_scheduling/#hot-swap-support) however, we want the replacement to work without the node being unhealthy or tainted. 
This could be done by adding some annotation, or patching the pods/workloads, or some other external signal that tells kueue to not place the replacement pod for the workload on the same node.

**Why is this needed**:
This is required for operations where we need the node to schedule some other high priority workloads, and want to defragment the cluster.

Definitely an interesting approach. On node replacement though, you probably also need a mechanism to tell that node replacement to match maybe an alternative binpacking strategy. 

There's 2 layers of binpacking:
1. the workload relative to other workloads
2. the pods within the workload relative to itself 

Like what I wonder is... 
- you replace node with a different one
- given clusters are busy, that node is just replaced by a different pod/workload before you get a change to get the big one scheduled
- on node replacement, it may also just result in the same not great topology spread except on a different node (ex: 1 pod on node A gets replaced with 1 pod on node B)
