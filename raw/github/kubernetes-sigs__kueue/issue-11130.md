## Description

**What happened**:

I configured my Kueue installation's `.objectRetentionPolicies` to garbage-collect finished workloads after 1 minute. Then I created an elastic Ray cluster. The Ray cluster scaled up a few times which created new workload slices. Old slices were marked as `Finished` and the controller logs stated they were deleted, but they never terminated.

**What you expected to happen**:

I expected the old Workload objects (which are slices for an elastic Ray cluster) to terminate.

**How to reproduce it (as minimally and precisely as possible)**:

1. Install Kueue and configure `objectRetentionPolicies`:
    ```
    objectRetentionPolicies:
      workloads:
        afterFinished: "1m"
    ```
2. Create an elastic Ray cluster with `inTreeAutoscaling` enabled
3. Trigger scale up such that there is at least one `Finished` `Workload` (slice) that has been replaced by a new `Workload`.
4. Observe Kueue controller logs reporting deletion, but `Finished` workload slice is not deleted.

**Other notes**:

This relates to the change made in https://github.com/kubernetes-sigs/kueue/pull/2686.

**Environment**:
- Kubernetes version (use `kubectl version`): v1.34.6-gke.1154000
- Kueue version (use `git describe --tags --dirty --always`): v0.16.2
- Cloud provider or hardware configuration: Google Cloud Platform (GCP)
