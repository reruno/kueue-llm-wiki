**What would you like to be added**:
Multikueue would need a set of new metrics at various levels: cluster connectivity and status, dispatch performance and errors, evictions/preemptions across clusters, etc. (There are probably more, but these seem to be the most obvious ones.)

  * Cluster connectivity and status:
       * Cluster status: Reachable/active, disconnected, retrying. 
       * Last Reachable time by cluster: when was the cluster last reachable?
       * Sync_errors by cluster by reason: Kube API server returned 4xx/5xx, API server not reachable,  etc.
  * Dispatch performance:
       * Number of workloads dispatched to a cluster as candidate
       * Number of workloads admitted by the cluster? (This may be available in the worker cluster, but not sure if the mgmt cluster can provide more info.)
       * Admission latency by cluster (worker clusters' admission latency metric is not the same)
       * Number of dispatch rounds before admission
       * Number of clusters tried per admission 
       * Number of workloads pending that are eligible for a given cluster
  * Dispatch errors:
       * Number of dispatch rejections, faiilure to submit, etc. by cluster and by reason
  * Cross-cluster evictions:
       * Number of evictions for the same workload across clusters 

**Why is this needed**:
For MultiKueue to move from beta to production readiness, observability is important. Cross-cluster metrics will provide a global visibility.
