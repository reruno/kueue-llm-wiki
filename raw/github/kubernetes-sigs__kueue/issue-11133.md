## Description

### What happened

After upgrading from Kueue v0.11.0 to v0.17.2 using the official Helm chart with default values, the controller crashes in a loop with:
```
{"level":"error","logger":"visibility-server","caller":"visibility/server.go:65","msg":"Unable to apply VisibilityServerOptions","error":"error creating self-signed certificates: open /tmp/apiserver.crt: read-only file system"}
```


### What did you expect to happen

The visibility server should be able to write its self-signed certificates when `enableCertManager: false` (the default).

### Environment

- Kueue version: v0.17.2
- Kubernetes version: 1.30 (EKS)
- Install method: Helm chart with default values
- `enableCertManager`: false (default)

### Root cause

The v0.17.2 Helm chart defaults `controllerManager.manager.containerSecurityContext.readOnlyRootFilesystem` to `true` (new in v0.17.2, not present in v0.11.0). 

When `enableCertManager: false`, the chart provides a `/visibility` emptyDir volume. However, the visibility server binary (`pkg/visibility/server.go:65`) writes its self-signed cert to `/tmp/apiserver.crt` — which is on the read-only root filesystem, not the mounted volume.

### Suggested fix

Add a `/tmp` emptyDir volume mount to the manager deployment template in `charts/kueue/templates/manager/manager.yaml`:

```yaml
volumeMounts:
- mountPath: /tmp
  name: tmp

volumes:
- name: tmp
  emptyDir: {}

We are setting `readOnlyRootFilesystem` on our kueue deployment. I think that the cert needs to be mounted to an emptyDir volume so that the volumes can change (new certs or whatever). If you don't add a volume, readOnlyRootFilesystem will cause the pod to fail to write to disk.

When using cert manager you already attach a volume to mount a secret. We use this in openshift-kueue-operator: https://github.com/openshift/kueue-operator/blob/main/pkg/operator/target_config_reconciler.go#L1783.
