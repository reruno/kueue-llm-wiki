## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

Reorganize `cmd/experimental/agent/` directory structure. Currently, skill definitions (`SKILL.md` files) are placed under `cmd/experimental/agent/skills/`, which implies they belong to an "agent" — but the directory contains no agent definitions, only skills. The `agent/` folder should be removed and `skills/` should be moved up to `cmd/experimental/skills/`.

In the future, if we want to introduce some agents, we can create an `agents` folder at same level as `skills` and put all agents in that folder.

**Why is this needed**:

The current structure is misleading:
- `agent` and `skill` are distinct concepts in Claude Code and Copilot: a skill is a reusable instruction set that runs in the current conversation context, while an agent is an independent subprocess with its own context window
- Placing skills inside an `agent/` folder implies a relationship that doesn't exist
- The `agent/` directory contains only `OWNERS` and a `skills/` subdirectory — there are no actual agent definitions in it
- New contributors looking at `cmd/experimental/agent/skills/` will have to figure out why skills live inside an agent folder
