**What happened**:

We noticed that a workload sometimes gets evicted with a `NodeFailure` error, even when the assigned node is healthy.
In our TAS-enabled cluster, the nodes have a GPU taint. The assigned `ResourceFlavor` has the `spec.tolerations` for this taint. This eviction issue happens if the Pod template does not originally include this toleration.

In the node controller, the node is classified by `classifyTaints(ctx, node.Spec.Taints, workload.PodSetsOnNode(wl, nodeName))` func.
However, `workload.PodSetsOnNode` function only checks `Workload.spec.podSets[*].template.spec.tolerations`. It does not check the tolerations injected by the ResourceFlavor, which results in the taint not being tolerated and marks the node as unhealthy.
It only occurs during the time after the workload is admitted but before the kube-scheduler binds the node, and no other kueue workload is running on that node.

**What you expected to happen**:

TAS NodeHotSwap does not mark a node as unhealthy if the required tolerations are automatically injected by the ResourceFlavor, even if they are missing from the original Pod template.

**How to reproduce it (as minimally and precisely as possible)**:

1. Use Kueue v0.17 (with `TASReplaceNodeOnNodeTaints=true` enabled by default).
2. Set up a node with a taint like `gpu-type=nvidia-a100:NoSchedule`.
3. Create a TAS `ResourceFlavor` with:
    * `spec.nodeTaints` matching that taint.
    * `spec.tolerations` tolerating that taint.
    * `spec.topologyName` using a hostname topology.
4. Create a Workload using that ResourceFlavor. (emulate a binding delay by setting a non-existent scheduler).
6. The workload is terminated by kueue
