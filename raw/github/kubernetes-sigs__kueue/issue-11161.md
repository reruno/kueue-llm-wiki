**What happened**:

`CLAUDE.md` is listed in `.gitignore`, so it is never committed to the repository. Claude Code reads `CLAUDE.md` (not `AGENTS.md`) for repository-level instructions and skill references. As a result, Claude Code users get no awareness of the skills under `cmd/experimental/skills/` and cannot benefit from the preemption, lineage, or flake-debugger runbooks.

**What you expected to happen**:

`CLAUDE.md` should be committed to the repository alongside `AGENTS.md`, pointing Claude Code to `cmd/experimental/skills/README.md` the same way `AGENTS.md` does for other AI tools (Cursor, Codex etc.).

**How to reproduce it (as minimally and precisely as possible)**:

1. Clone the kueue repository.
2. Open it in Claude Code.
3. Ask Claude Code "who preempted my workload?" — it has no knowledge of the runbook in `cmd/experimental/skills/kueue-who-preempted/SKILL.md` because there is no `CLAUDE.md` to load.

**Anything else we need to know?**:

- `AGENTS.md` is already present and committed, but Claude Code does not read `AGENTS.md` (see [claude-code issue #6235](https://github.com/anthropics/claude-code/issues/6235)).
- The fix is to remove `CLAUDE.md` from `.gitignore` and add a `CLAUDE.md` by importing`AGENTS.md`, check https://code.claude.com/docs/en/memory#import-additional-files for detail.
