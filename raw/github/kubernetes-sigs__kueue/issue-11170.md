## Description

## Summary

When using Kueue's pod integration, there is an observable and sometimes significant delay (up to minutes) between a workload being admitted and the scheduling gate (`kueue.x-k8s.io/admission`) being removed from the pod. During this window, the pod remains blocked from Kubernetes scheduling despite the workload already being admitted.

Additionally, there is no metric to observe or alert on this latency today.

## Expected Behavior

Once a workload transitions to `Admitted`, the scheduling gate on its associated pod(s) should be removed promptly (within seconds), unblocking Kubernetes scheduling.

## Observed Behavior

- Workload is `Admitted` (visible in workload status).
- Pod retains the `kueue.x-k8s.io/admission` scheduling gate.
- The gate is eventually removed, but delay can reach **minutes** in production clusters.

## Flow (for reference)

```
1. Pod is created
2. Kueue webhook adds kueue.x-k8s.io/admission scheduling gate to the pod
3. kube-scheduler skips the pod due to the gate
4. Pod controller creates a Workload for the pod
5. Kueue scheduler admits the Workload
6. Pod controller detects admitted workload → patches pod to remove the gate
7. Pod proceeds with kube-scheduler scheduling
```

The delay occurs in the transition from step 5 to step 6.

## Potential Contributing Factors

### 1. Controller queue saturation
`MaxConcurrentReconciles` for the Pod controller defaults to `1` unless `GroupKindConcurrency["Pod"]` is explicitly configured. Under load, the reconcile request (enqueued by `workloadHandler.Update()` when the Workload status changes) may sit behind other items.

### 2. Informer/watch event delivery latency
The trigger for gate removal is a watch event on the Workload object (status change to Admitted). Under apiserver or network load, event delivery can lag.

### 3. Controller manager downtime / leader election
Any Kueue controller restart leaves admitted workloads gated until the new leader reconciles.

## Missing Observability

There is currently **no metric** capturing the time between workload admission and scheduling gate removal. Existing metrics do not cover this window:

| Metric | Measures | Covers gate removal? |
|---|---|---|
| `kueue_admission_wait_time_seconds` | Workload creation → admission | No |
| `kueue_admitted_until_ready_wait_time_seconds` | Admission → pods ready | No (far later) |
| `kueue_ready_wait_time_seconds` | Workload creation → ready | No |

## Request

Add a new histogram metric to make this latency observable:

```
kueue_pod_scheduling_gate_removal_seconds
```

- **Measured from:** `workload.Status.Admission` timestamp
- **Measured to:** moment the gate-removal patch is applied in `pod_controller.go Run()`
- **Labels:** `cluster_queue`, `is_group` (bool)

## Environment

- Kueue version: v0.16.5
- Kubernetes version: v1.34.6
- Pod integration enabled: yes
- Pod groups used: yes (but not in this context)
