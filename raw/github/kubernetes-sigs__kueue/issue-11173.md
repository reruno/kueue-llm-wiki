## Description

**What would you like to be added**:

  A first-class, automated code-coverage pipeline for Kueue with three independent profiles plus a merged view:

  1. **Unit** — already emitted today (`make test` produces `cover.out`); just needs to be published.
  2. **Integration** — `test/integration/...` runs controllers in-process under envtest. Add `-coverpkg=./... -coverprofile` (per-suite, then merged).
  3. **E2E** — `test/e2e/...` and the kueueviz e2e suites run the manager in-cluster on Kind. Build the manager and kueueviz binaries with `go build -cover`, set `GOCOVERDIR` on the in-cluster pods, copy the
  directory out at suite teardown, and convert with `go tool covdata textfmt`.
  4. **Combined** — merge all three profiles with `go tool covdata merge` after normalizing modes, with generated code (deepcopy/conversion/clientset, `vendor/`, mocks/fakes, `*_test.go` helpers) excluded via a
  coverage ignore list.

  Publish in this order of preference depending on what's feasible:

  - **(a)** Codecov, gated on the outcome of [kubernetes/org#6182](https://github.com/kubernetes/org/issues/6182) and the [SIG K8s Infra discussion](https://kubernetes.slack.com/archives/C09QZ4DQB/p1772653699319949) — gives per-PR diff coverage and a hosted UI for free.
  - **(b)** k8s/k8s way https://github.com/kubernetes/test-infra/blob/master/config/jobs/kubernetes/sig-testing/coverage.yaml
  - **(c)** A self-hosted artifact + static dashboard pattern, mirroring
  [`ci-kubernetes-coverage-conformance`](https://prow.k8s.io/view/gs/kubernetes-ci-logs/logs/ci-kubernetes-coverage-conformance/2029251919700037632) — coverage HTML + `cover.out` uploaded to GCS by a periodic
  job.
  - **(d)** Surface a single number on TestGrid as a metric column (like `test-duration-minutes` on
  [periodic-kueue-test-e2e-kueueviz-main](https://testgrid.k8s.io/sig-scheduling#periodic-kueue-test-e2e-kueueviz-main&graph-metrics=test-duration-minutes)). This would require either writing a custom metric
  file the [test-infra metrics pipeline](https://github.com/kubernetes/test-infra/tree/ee95bfb00e7a021518df934a3215e59532319059/metrics) can read, or contributing a new metric extractor upstream — feasibility
  needs confirmation with sig-testing.

  **Why is this needed**:

  - **Find dead code and undertested layers.** Kueue has many integration code paths (MultiKueue, TAS, provisioning admission checks, Fair Sharing, all-or-nothing, deployments/statefulsets, jobset/ray/kubeflow
  integrations). Some files are only ever reachable through e2e (manager bootstrap, webhooks, leader election, in-cluster RBAC paths), some only through integration (envtest reconciliation), and some only
  through unit tests. A per-layer view tells contributors *where* coverage is missing, not just *that* it is missing. The merged view tells maintainers what is genuinely unreachable from any test — strong
  dead-code signal that `go vet`/`unused` cannot give for exported symbols and reflection-driven code.
  - **Catch coverage regressions in review.** Today a refactor can silently delete a code path's only test and nobody notices until a release. Per-PR delta coverage (option a) makes this immediately visible to
  reviewers.
  - **Distinguish "covered" from "covered well".** A function reached by 30 e2e tests and zero unit tests is at higher risk than the per-package number suggests. Three separated profiles surface that; one merged
   number hides it.
  - **Track a release-readiness metric over time.** The Production Readiness section of the README already lists test categories; coverage % per category turns that checklist into a measurable trend that can
  live next to the existing TestGrid dashboards.
  - **Lower the bar for new contributors.** Undertested packages become an obvious "good first issue" pool.

  **Trade-offs to be aware of (and how to mitigate):**

  | Concern | Mitigation |
  | --- | --- |
  | Coverage is a proxy for correctness; chasing % can encourage shallow tests. | Track per-layer trend rather than enforcing a hard threshold; use it as a review aid, not a merge gate, at least initially. |
  | Binary coverage for e2e adds Kind image rebuild + artifact-copy steps; slower e2e jobs. | Run coverage-instrumented e2e only in periodics, not in every presubmit. |
  | Merging profiles across `set`/`count`/`atomic` modes requires consistency. | Standardize all suites on `-covermode=atomic`. |
  | Generated code (deepcopy, conversions, clientset, CRD bindings under `client-go/`, `apis/.../zz_generated*`) inflates the denominator. | Maintain a `.coverignore`-style file and strip matching paths in the
  merge step. |
  | Sharded integration jobs (e.g. `multikueue` shard) produce many `cover.out` files. | Aggregate per-job in postsubmit, then aggregate across jobs in a daily periodic. |
  | Codecov requires a token/secret + ownership; SIG K8s Infra is still deciding the policy ([k/org#6182](https://github.com/kubernetes/org/issues/6182)). | Build the data-collection pipeline first
  (vendor-neutral `cover.out` artifacts in GCS); plug Codecov in once policy lands, fall back to a static dashboard otherwise. |
  | TestGrid metric columns need a numeric field surfaced in a known artifact location. | Confirm with sig-testing whether a new extractor is acceptable, or piggyback on the existing `metrics/` JSON convention.
  |

  **Completion requirements**:

  This enhancement requires the following artifacts:

  - [ ] Design doc — covers: per-layer instrumentation (incl. `go build -cover` for e2e), the coverage-ignore list, merge strategy, where artifacts are stored, and which publishing option (codecov vs.
  GCS+dashboard vs. TestGrid metric) is chosen.
  - [ ] API change — none expected.
  - [ ] Docs update — `README.md` Production Readiness section to link to coverage dashboards, and a short `CONTRIBUTING.md` note on how to read per-layer coverage locally.

  The artifacts should be linked in subsequent comments.
