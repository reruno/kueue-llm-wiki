**What would you like to be added**:
We need resource flavor metrics to help with utilization tracking. Specifically, it would be useful to have a metric to answer questions like "what fraction of time did resource flavor A have reservations last week?"

**Why is this needed**:
Resource flavors may correspond to expensive resources like GPU instance types. So, having utilization metrics for resource flavors would help overall.

### Comment by [@mimowo](https://github.com/mimowo) — 2026-05-15T17:43:09Z

> Specifically, it would be useful to have a metric to answer questions like "what fraction of time did resource flavor A have reservations last week?"

I would like to understand better, what does it mean to have reservations for flavor, like at least one workload running?

In general the metric might be useful, but we need to clarify details:
1. how we measure time - wall time / cpu time (I would probably consider resource-time)
2. what it exactly means "to have reservation" for ResourceFlavor" 

One rough idea is to have a histogram per workload which measures how much time a workload has spent in each flavor. Then having the histogram to know "last week" we could use PromQL queries in Grafana to subtract those AFAIK.

We would need to account for the time at the moment when admission ends.
