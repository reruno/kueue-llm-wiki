## Description

<!-- Please only use this template for submitting clean up requests -->

**What would you like to be cleaned**:

https://github.com/kubernetes-sigs/kind/issues/4157

Kind would prefer that we build the nodes images on releases without relying on official images.

**Why is this needed**:

This can put us in control of when we do e2e testing and not rely on kind to have an official release.

**What we need to do**:

I think we can switch our CI to do `kind build node-image v1.36.0` and that will pull latest release artifacts. And then we can just use that cluster instead of relying on kind to host official images.

### Comment by [@BenTheElder](https://github.com/BenTheElder) — 2026-05-15T19:23:32Z

Yes, you do not have to compile Kubernetes, just download it (which kind can do internally).

https://kind.sigs.k8s.io/docs/user/quick-start/#building-images

The bottleneck is downloading the k8s release tarball, which is pretty similar to the time cost to download the kind-node image.

They're both gzipped tarballs at the end of the day.

You can also use this to test CI builds (need to add a quick recipe for that but it's already possible).

You can consider caching the downloads in GHA by explicitly downloading them and then pointing `kind build node-image` at the downloaded tarball, but I'm not sure how well their cache performs.
