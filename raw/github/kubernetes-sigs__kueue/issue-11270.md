## Description

<!-- Please only use this template for submitting clean up requests -->

**What would you like to be cleaned**:

kueue-controller-manager currently is requesting RBAC update to spec which it is not using, and should not be using unless good reasons

Example, for localQueues we have rbac to delete/create/update/patch, but `kueue-controller-manager` should only be updating finalizers and status, see [here](https://github.com/kubernetes-sigs/kueue/blob/main/pkg/controller/core/localqueue_controller.go#L172)

Analogous controls we give to Topology, ResourceFlavor, ClusterQueue etc.

The only exception where we should keep is the update to ClusterQueue as this is going to be temporarily used  (alpha1) by the MultiKueue global quotas. Later it will be dropped too.

Another exception is Workload, but this is a semi-internal CRD.

**Why is this needed**:

* To make it clear that kueue-controller-manager does not update spec for the Kueue CRDs. These are left to be managed by users / admins.
* Currently it is easy to miss during review that a controller may start using update on LQ or CQ, because the RBAC would remain unchanged.
