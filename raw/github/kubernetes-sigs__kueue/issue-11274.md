**What would you like to be cleaned**:

This is a follow up to https://github.com/kubernetes-sigs/kueue/issues/10995 as `kueue-test-e2e-sequential-baseline-main` is currently one of the longest suites

I reviewed the existing tests and I think the following optimizations can be made:
1. [ ] Remove the deprecated `--visibility-server-port` in favor of `visibilityServer.bindPort`, see deprecation note [here](https://kueue.sigs.k8s.io/docs/tasks/manage/monitor_pending_workloads/pending_workloads_on_demand/#monitor-pending-workloads-on-demand)

Expected saving: ~30s

2. [ ] Consolidate Failure Recovery tests to share one kubelet outage

The two Failure Recovery specs currently stop and restart kubelet independently. Refactor them so both scenarios use pods on the same worker node and share a single kubelet stop/start cycle. 

Expected saving: ~2min

3. [ ] Make default-config assumptions explicit and remove redundant visibility config restore

The visibility config API test currently restores the original Kueue configuration in cleanup, costing ~27–30s.

Instead, make the default-configuration invariant explicit: group tests that assume the default config, such as certs and HA failover, under a default-config setup that restores `defaultKueueCfg` once in `BeforeAll`.

Then remove the redundant visibility-test cleanup:

- `ginkgo.By("Restoring original configuration")`
- `UpdateKueueConfigurationAndRestart(... defaultKueueCfg ...)`

Expected saving: ~30s.


**Why is this needed**:

It would be great to have all suites running below 25min.
