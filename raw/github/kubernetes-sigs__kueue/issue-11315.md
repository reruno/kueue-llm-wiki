Seems like this is also related to https://github.com/kubernetes-sigs/kueue/pull/11184, I've cherry-picked and now it doesn't fail after 300 run (previously were failing after 5-10 runs)

**What was failing in CI**
The flake was not a Kueue admission/timing issue. The RayJob was admitted, the cluster became ready (HeadPodReady, RayClusterProvisioned), but the Ray job itself failed almost immediately with:
```
runtime_env setup failed
HTTP 405 Method Not Allowed: POST; use OPTIONS or GET
```
That means Ray’s runtime-env agent received a POST on an endpoint that only accepts GET/OPTIONS — typically a sign the cluster or agent wasn’t fully wired up, or HTTP was hitting the wrong service (e.g. dashboard static handler instead of the runtime-env API).
