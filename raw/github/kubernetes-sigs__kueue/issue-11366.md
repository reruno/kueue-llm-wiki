## Description

**What would you like to be added**:

Enable wait for Pods ready by default as a safety net.

The main consideration I think is backwards compatibility, but maybe with a suffiently large timeout this would be acceptable. This is still a beta feature, I think this could go by default:

```yaml
waitForPodsReady:
  timeout: 1h
  recoveryTimeout: 1h
  blockAdmission: false
  requeuingStrategy:
    backoffBaseSeconds: 60
    backoffMaxSeconds: 3600
    backoffLimitCount: null // endless
    timestamp: Eviction
```
This is our recommendation basically with an extended timeout.

I wanted to post it long time ago, but the KEP DRA was the main trigger: https://github.com/kubernetes-sigs/kueue/pull/10283/changes#diff-9992bde183489d9f804057ec1cebd8b81b2470c8a9430abffee5ad8db5278e93R321

**Why is this needed**:

We have multiple incidents where waitForPodsReady could have mitigated the issue, and so we now always recommend it to all users, but sometimes only after an incident.
