## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

Currently we have a limit of only 8 PodSets per workload which I would like to increase to 16.

**Why is this needed**:

* some integrations consume multiple-PodSets just for their operation, for example Ray has 1 head, 1 submitter job, 1 redis cleanup job, this leaves only 5 PodSets for workers, see discussion here: https://github.com/kubernetes-sigs/kueue/pull/11260/#issuecomment-4487814710
* some users prefer to split a big JobSet into multiple smaller ReplicatedJobs with different PodSets so that they are admitted to different flavors independently, increasing the granularity of admission
