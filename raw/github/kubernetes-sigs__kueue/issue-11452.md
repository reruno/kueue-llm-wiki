## Description

<!-- Please only use this template for submitting clean up requests -->

**What would you like to be cleaned**:

When eviction is ongoing, ie. status.clusterName is still assigned (and the status.admissionCheck.state=Retry) we should skip the cluster nomination phase completely.

**Why is this needed**:

* Not skipping the nomination leads to subtle race conditions as this one fixed here: https://github.com/kubernetes-sigs/kueue/pull/11378
* currently different dispatchers need to re-implement the skip by themselves which is code duplication, and also requires non-obvious checks from the authors of external disaptchers, 
- [AllAtOnce](https://github.com/kubernetes-sigs/kueue/pull/11378/changes#diff-a09b1d2caac9c60d2112a557a72bb2495f52f4c9ac6d161c3b30f1a3a6be24b6R771-R773)
- [Incremental](https://github.com/kubernetes-sigs/kueue/blob/main/pkg/controller/workloaddispatcher/incrementaldispatcher.go#L103-L112)

I think this code should be moved into workload go and skip the nomination phase (copied from the incremental dispatcher):

```golang
	if mkAc == nil || mkAc.State != kueue.CheckStatePending {
		log.V(3).Info("AdmissionCheckState is not in Pending, skip the reconciliation")
		return reconcile.Result{}, nil
	}

	// The workload is already assigned to a cluster, no need to nominate workers.
	if wl.Status.ClusterName != nil {
		log.V(3).Info("The workload is already assigned to a cluster, no need to nominate workers")
		return reconcile.Result{}, nil
	}
```
