## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

The ability to filter Workloads server-side using kubectl --field-selector. For example, listing all workloads that currently have quota reserved, or all workloads reserved in a specific ClusterQueue, without fetching every workload and filtering client-side.

**Why is this needed**:

- Today, filtering workloads by status requires either `kueuectl list workload --status` (which fetches all workloads then filters client-side). There is no way to use native `kubectl --field-selector` on Workload beyond `metadata.name` and `metadata.namespace`.
- At scale, listing all workloads and discarding most of them is inefficient. Server-side filtering reduces API traffic and response size.
- kubectl is the standard tool for interacting with Kubernetes resources. Operators and tooling (dashboards, scripts, monitoring) should be able to query workloads by reservation or admission status using standard Kubernetes mechanisms.
