## Description

**What happened**:

A standalone Kueue-managed elastic RayCluster is continuously updated by Kueue.

The `kueue.x-k8s.io/raycluster-generation` annotation tracks the RayCluster's own `metadata.generation`, but remains one value behind. For example:

```console
metadata.generation: 273390
kueue.x-k8s.io/raycluster-generation: "273389"
```

A later read showed the same pattern:

```console
metadata.generation: 273462
kueue.x-k8s.io/raycluster-generation: "273461"
```

Kueue logs showed repeated RayCluster reconciles followed by RayCluster update webhook calls from the Kueue controller manager.

This is a self-triggered loop in the RayCluster custom annotation path. For standalone RayClusters, `GetCustomAnnotations` calls `GetWorkloadslicingRayClusterCustomAnnotations(ctx, c, j.Object(), podSets, j.Name)`. That helper fetches the same RayCluster and returns the fetched RayCluster generation as an annotation to write back onto the RayCluster. The metadata patch then advances the RayCluster generation, making the annotation stale again.

**What you expected to happen**:

Kueue should not continuously patch a standalone elastic RayCluster when its replica counts have not changed.

The `raycluster-generation` annotation is useful for RayJob and RayService, where the top-level object needs to account for an underlying RayCluster generation. A standalone RayCluster should not write its own generation back onto itself.

**How to reproduce it (as minimally and precisely as possible)**:

1. Install Kueue v0.16.5 with `ElasticJobsViaWorkloadSlices=true`.
2. Enable the RayCluster integration.
3. Create a standalone RayCluster with:

```yaml
metadata:
  annotations:
    kueue.x-k8s.io/elastic-job: "true"
  labels:
    kueue.x-k8s.io/queue-name: <local-queue>
```

4. Inspect the RayCluster generation and annotation repeatedly:

```sh
kubectl get raycluster.ray.io <name> -n <namespace> \
  -o jsonpath='{.metadata.generation}{"\t"}{.metadata.annotations.kueue\.x-k8s\.io/raycluster-generation}{"\n"}'
```

**Anything else we need to know?**:

This may be related to #10160, which added generation-based elastic workload names on the release-0.16 branch.

A fix is to omit `kueue.x-k8s.io/raycluster-generation` when the `jobObject` is the same standalone RayCluster as `rayClusterName`.
