## Description

**What happened**:
When the WebSocket connection fails on the workload detail or local queue detail pages, the page gets stuck on a loading spinner forever. The error message never appears.

This happens because the component checks whether data has loaded before it checks for errors. If the connection fails, data stays empty so the spinner keeps rendering and the error check is never reached.

**What you expected to happen**:
The page should show the error message when the WebSocket connection fails instead of spinning indefinitely.

**How to reproduce it (as minimally and precisely as possible)**:
1. Run the kueueviz frontend locally
2. Navigate to any workload detail or local queue detail page without a backend running
3. The page shows a spinner forever instead of the connection error

**Anything else we need to know?**:
The fix is to check for errors before checking for missing data so the error message renders when the connection fails. Happy to open a PR if this is not being worked on.
