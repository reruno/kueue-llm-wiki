**What happened**:
`kueue_admission_cycle_preemption_skips` as a gauge is not a good historical signal. It reflects the last reported cycle with skips and can disappear with cleanup/resync. Scrape timing can also easily miss or misrepresent short-lived skip behavior. It should probably be a counter

As an example, over a span of 4 hours, I got 0 preemption skips from the metrics. But saw several indictions in the logs that preemption skips happened. 

I think whats happening is this: 
It latches at the last cycle's skip count and stays there until the next cycle that has skips overwrites it.

**What you expected to happen**:
Instead of gauge, you probably want to change this from a gauge to a counter and need to add a reason label. 
We probably want a new metric `kueue_admission_cycle_preemption_skips_total` added so as not to break backwards compatibility. But I'm curious if people are successfully using `kueue_admission_cycle_preemption_skips` in dashboards.
