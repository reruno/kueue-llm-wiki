## Description

**What happened**:
When navigating to any of the list pages (ClusterQueues, Cohorts, LocalQueues, ResourceFlavors, Workloads) in KueueViz, the UI briefly renders the "No resources found" empty state message on every page load or refresh. A split second later, once the WebSocket connection completes and receives the data, the message disappears and is replaced by the actual resource table.

This happens because the initial array state is set to `[]`. Before the WebSocket connects and streams the data, the render function instantly detects a list length of `0` and renders the empty state UI, causing a jarring visual flash.

**What you expected to happen**:
The UI should display a loading indicator (like a spinner) while waiting for the WebSocket to establish a connection and stream initial data, rather than prematurely declaring the list is empty.

**How to reproduce it (as minimally and precisely as possible)**:
1. Run KueueViz locally.
2. Navigate to the "Cluster Queues" or "Workloads" page.
3. Refresh the page. You will see a flash of "No Cluster Queues found" or "No Workloads found" before the actual rows populate.

**Anything else we need to know?**:
The fix is to differentiate between the initial uninitialized state (raw WebSocket data is `null`) and a genuinely empty list (data is fetched but contains 0 items). We should show a loading spinner when data is `null`, and only render the empty list text when data is received and empty. Happy to open a PR for this!
