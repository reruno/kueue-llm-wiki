**What would you like to be added**:
When a DRA driver publishes devices with device.Capacity fields ([KEP-5075](https://github.com/kubernetes/enhancements/issues/5075)), the kube-scheduler tracks capacity consumption to prevent over-allocation of shared resources. Kueue needs capacity-based quota management for these devices. For example, a GPU that supports time-slicing or MPS can serve multiple workloads concurrently, each consuming a fraction of the device's compute and memory capacity. Device-count quota cannot express as one device counted as "1 GPU" might serve 4 workloads at 25% each, or 2 workloads at 50% each. Capacity-based quota charges workloads based on the actual capacity they consume from the device.

**Why is this needed**:
Fractional GPU sharing via time-slicing and MPS is widely used to improve GPU utilization for inference and small training workloads. Without capacity-based quota, admins cannot distinguish between a workload using 25% of a GPU and one using 100%. Both consume "1 GPU" in device-count quota, leading to either over-admission (cluster runs out of capacity) or under-utilization (quota blocks workloads that would fit). This is the complement to Partitionable Devices (#10108): PD handles static partitioning (MIG), while Consumable Capacity handles dynamic sharing (time-slicing, MPS).
