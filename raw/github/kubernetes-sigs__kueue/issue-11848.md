## Description

# Disable the unnecessary `MutatingAdmissionPolicy` admission plugin for the visibility server

## What happened

After installing Kueue v0.18.0 with the default `VisibilityOnDemand` feature enabled, the `kueue-controller-manager` repeatedly logs RBAC errors for the following cluster-scoped resources:

* `mutatingadmissionpolicies.admissionregistration.k8s.io`
* `mutatingadmissionpolicybindings.admissionregistration.k8s.io`

Example errors:

```text
E0530 14:32:09.513899       1 reflector.go:227] "Failed to watch" err="failed to list *v1.MutatingAdmissionPolicy: mutatingadmissionpolicies.admissionregistration.k8s.io is forbidden: User \"system:serviceaccount:kueue-system:kueue-controller-manager\" cannot list resource \"mutatingadmissionpolicies\" in API group \"admissionregistration.k8s.io\" at the cluster scope" logger="UnhandledError" reflector="k8s.io/client-go/informers/factory.go:177" type="*v1.MutatingAdmissionPolicy"

E0530 14:32:31.500030       1 reflector.go:227] "Failed to watch" err="failed to list *v1.MutatingAdmissionPolicyBinding: mutatingadmissionpolicybindings.admissionregistration.k8s.io is forbidden: User \"system:serviceaccount:kueue-system:kueue-controller-manager\" cannot list resource \"mutatingadmissionpolicybindings\" in API group \"admissionregistration.k8s.io\" at the cluster scope" logger="UnhandledError" reflector="k8s.io/client-go/informers/factory.go:177" type="*v1.MutatingAdmissionPolicyBinding"
```

This looks similar to the previous `ValidatingAdmissionPolicy` issue fixed by #3908.

Kueue v0.18.0 uses Kubernetes v0.36.1 libraries. In that version, the generic apiserver admission options include `mutatingadmissionpolicy.PluginName` in `RecommendedPluginOrder`. Kueue’s visibility server disables several admission plugins, but it does not currently disable `MutatingAdmissionPolicy`.

When the `MutatingAdmissionPolicy` admission plugin is initialized, it creates informers for both `MutatingAdmissionPolicy` and `MutatingAdmissionPolicyBinding`. As a result, the controller attempts to list/watch these resources even though the visibility server does not appear to need them.

## Evidence

* Kueue v0.18.0 visibility server disables several admission plugins, but not `mutatingadmissionpolicy.PluginName`:
  https://github.com/kubernetes-sigs/kueue/blob/a7bc363b5eb50b9126baf41d4ca1dbf35c138852/pkg/visibility/server.go#L60-L65

* Kubernetes apiserver includes `mutatingadmissionpolicy.PluginName` in `RecommendedPluginOrder`:
  https://github.com/kubernetes/apiserver/blob/f5c87c5976dc9966aa63ea0021d5baf9ceef2efc/pkg/server/options/admission.go#L95-L97

* The `MutatingAdmissionPolicy` admission plugin creates informers for both policy and binding resources:
  https://github.com/kubernetes/apiserver/blob/f5c87c5976dc9966aa63ea0021d5baf9ceef2efc/pkg/admission/plugin/policy/mutating/plugin.go#L83-L86

## What you expected to happen

`kueue-controller-manager` should not attempt to list/watch `MutatingAdmissionPolicy` or `MutatingAdmissionPolicyBinding` resources unless Kueue actually needs them.

A possible fix would be to disable the unnecessary `MutatingAdmissionPolicy` admission plugin for the visibility server, similar to #3908:

```go
import mutatingadmissionpolicy "k8s.io/apiserver/pkg/admission/plugin/policy/mutating"

disabledPlugins = []string{
    mutatingadmissionpolicy.PluginName,
    validatingadmissionpolicy.PluginName,
    resourcequota.PluginName,
    validatingwebhook.PluginName,
    mutatingwebhook.PluginName,
}
```

## How to reproduce it as minimally and precisely as possible

I reproduced this issue using the following commands:

### 1. Create a kind cluster

```bash
kind create cluster --image kindest/node:v1.32.11
```

### 2. Install Kueue v0.18.0

```bash
helm install kueue oci://registry.k8s.io/kueue/charts/kueue \
  --version=0.18.0 \
  --namespace kueue-system \
  --create-namespace
```

### 3. Check the controller manager logs

```bash
kubectl logs -n kueue-system deploy/kueue-controller-manager
```

The logs contain repeated errors similar to:

```text
failed to list *v1.MutatingAdmissionPolicy: mutatingadmissionpolicies.admissionregistration.k8s.io is forbidden

failed to list *v1.MutatingAdmissionPolicyBinding: mutatingadmissionpolicybindings.admissionregistration.k8s.io is forbidden
```

## Anything else we need to know?

This appears to be the same class of issue as #3908. In that case, the fix was to disable an unnecessary admission plugin for the visibility server rather than granting extra RBAC permissions.

For this issue, it seems better to disable the `MutatingAdmissionPolicy` admission plugin in the visibility server instead of adding `get/list/watch` permissions for `mutatingadmissionpolicies` and `mutatingadmissionpolicybindings`.
