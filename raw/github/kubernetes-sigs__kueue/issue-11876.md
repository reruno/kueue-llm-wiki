## Description

**What happened**:
When navigating directly between two detail pages of the same resource type (e.g., transitioning from `/cohort/research` to `/cohort/engineering`), the UI briefly renders the data and charts of the *previous* cohort before loading the new one. 

This visual layout bleed happens because `CohortDetail.jsx` and `ClusterQueueDetail.jsx` copy the incoming WebSocket data into a local `useState` hook and run a `useEffect` hook to sort the list. 

Using `useEffect` + `useState` to copy and sort derived state from props/hooks is a known React anti-pattern that:
1. Triggers an extra unnecessary render cycle.
2. Creates a lag between the WebSocket connection updating and the state updating, causing stale data to flash.

**What you expected to happen**:
The detail views should derive the sorted queues synchronously using the `useMemo` hook directly from the WebSocket hook's return value. When the route parameters change, the derived state should instantly evaluate to `null` (loading) or compute the new sorted dataset in a single, synchronous render pass, preventing any stale data leaks.

**How to reproduce it (as minimally and precisely as possible)**:
1. Open KueueViz.
2. Navigate to `/cohort/research`.
3. Click a link to navigate directly to `/cohort/engineering` (or change the URL route parameter directly).
4. Observe the previous cohort's queues are briefly visible before the page transitions.

**Affected Files**:
* `cmd/kueueviz/frontend/src/CohortDetail.jsx`
* `cmd/kueueviz/frontend/src/ClusterQueueDetail.jsx`

**Anything else we need to know?**:
Refactoring these components to use `useMemo` for sorting and rendering will align the detail page architecture with modern, high-performance React design patterns (similar to our recent fix on the list pages). Happy to implement and open a PR!
