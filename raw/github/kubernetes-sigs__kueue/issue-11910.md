## Description

**What would you like to be added**:
We would like to introduce stable sorting for Topology Aware Scheduling (TAS) node allocation when TAS scoring yields equal scores for multiple domains/nodes. 

Currently, when multiple equivalent nodes/domains are available, the selection across different TAS placement algorithms can be non-deterministic (e.g., when the `TASBalancedPlacement` feature gate is enabled, nodes with equal capacities and entropies might be selected randomly). 

We should ensure that all TAS sorting paths have a consistent, stable tie-breaker. One potential approach could be to fall back to comparing the domain's `levelValues` (which include the node name or topology values) to break the tie, similar to how it is currently handled in the fallback `sortedDomains` logic.

**Why is this needed**:
In environments where workloads require specific physical topologies (e.g., hardware accelerators interconnected at the rack or block level), unpredictable scheduling reduces the opportunity for infrastructure reuse. When consecutive, identical requests arrive in a cluster with symmetric free capacity, an unstable sort means Kueue might distribute them across completely different, equivalent nodes each time. 

By ensuring a stable sort order across all TAS algorithms, Kueue will predictably prioritize the same nodes when scores are tied. This predictability is highly beneficial for systems relying on external admission checks like dynamic hardware provisioning, as it maximizes the reuse of existing underlying infrastructure and minimizes fragmentation over time.
