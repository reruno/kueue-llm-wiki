## Description

## What happened
A Kubeflow TrainJob is managed by Kueue. The corresponding Workload has been successfully admitted (`ADMITTED=true`) and occupied ClusterQueue resources, but the TrainJob remains stuck in `Suspended` state permanently. No child Job/Pod gets created and training cannot start.

## Steps to reproduce
1. Deploy Kueue v0.17.3 on Kubernetes v1.36, create ClusterQueue and LocalQueue with sufficient CPU/memory resource quota.
2. Prepare target PVC and custom training image, then submit a YOLOv7 TrainJob via Kubeflow Trainer v2.1.0. Each node requests 12 CPU / 24Gi memory and limits 12 CPU / 26Gi memory.
3. Check Workload status: bound to LocalQueue and marked as ADMITTED=true. However parent TrainJob stays Suspended and no training Pod is spawned at all.

## Expected behavior
After Workload is admitted by Kueue, Kueue should unset the TrainJob suspend flag automatically, then TrainJob controller creates child Jobs and corresponding training Pods normally.

## Environment
- Kubernetes Version: v1.36
- Kueue Version: v0.17.3
- OS: Ubuntu 22.04
- Kubeflow Trainer Operator Version: v2.1.0

### Comment by [@cih9088](https://github.com/cih9088) — 2026-06-09T02:26:57Z

I had the same issue and here is why.

1. https://github.com/kubeflow/trainer/pull/3309 has been introduced in Trainer `v2.2.0` so `v2.1.0` keeps `PodTemplateOverrides` not `RuntimePatches`.
2. https://github.com/kubernetes-sigs/kueue/pull/10127 has been introduced in Kueue `v0.17.0` which now uses `RuntimePatches`. In turns, `RuntimePatches` [set by the webhook](https://github.com/kubernetes-sigs/kueue/blob/main/pkg/controller/jobs/trainjob/trainjob_webhook.go#L93) is ignored because it is not defined in CRD which causes `kueue runtime patch not found` [error](https://github.com/kubernetes-sigs/kueue/blob/main/pkg/controller/jobs/trainjob/trainjob_controller.go#L279) and cannot reach to [unsuspend method](https://github.com/kubernetes-sigs/kueue/blob/main/pkg/controller/jobs/trainjob/trainjob_controller.go#L288).

You should either upgrade Trainer to `v2.2.0` or downgrade Kueue to `v0.16.9`.
If you choose to upgrade the Trainer and installed it using Helm before, make sure you deleted CRDs as CRDs are not deleted by Trainer chart.
