## Description

  **What would you like to be added:**                                                                                                                                                                             
                                                                                                                                                                                                                   
  Kueue integration adapter for [DisaggregatedSet](https://github.com/kubernetes-sigs/lws/tree/main/keps/766-DisaggregatedSet), the LWS CRD that wraps multiple LeaderWorkerSets (e.g., prefill + decode) as a single logical unit for disaggregated inference.                                                                                                                                                                 
                                                                                                                                                                                                                   
  **Why is this needed:**                                                                                                                                                                                          
                                                                                                                                                                                                                   
  [llm-d](https://github.com/llm-d/llm-d) deploys disaggregated LLM inference as separate prefill and decode LWS objects with fundamentally different resource shapes, for example 8 prefill replicas at 1 GPU each vs 2 decode replicas at 4 GPUs each. These must run together for the inference service to function.                                                                                       
                                                                                                                                                                                                                  Today these LWS objects are admitted as independent Workloads. While this works when quota is plentiful, it creates problems as clusters scale:

  1. **Partial admission.** Under quota pressure, Kueue can admit prefill but not decode (or vice versa). The admitted half holds GPUs without serving traffic until the other half is also admitted. A single Workload with gang semantics would prevent this.

  2. **Fragmented preemption.** When reclaiming GPUs for higher-priority training, Kueue selects preemption victims independently. It may preempt only one role, leaving a broken half-deployment that still holds quota. Unified preemption of the full deployment requires a single Workload representing both roles.

These problems can be worked around today but they become harder to manage at scale with dozens of inference deployments sharing GPU pools with training workloads.

DisaggregatedSet groups the constituent LWS objects into one parent. A Kueue adapter (same pattern as JobSet) would create one Workload per DisaggregatedSet, giving atomic admission and preemption with existing Kueue primitives. No new scheduler concepts needed.

  **Dependencies:**

  - DisaggregatedSet tagged release (tracking LWS v0.9.0: kubernetes-sigs/lws#744)                        
  - Status reporting: kubernetes-sigs/lws#868
  - llm-d adoption: llm-d/llm-d#1485
