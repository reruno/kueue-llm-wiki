## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

I would like to add the `maxPriorityThreshold` configuration option to `reclaimWithinCohort` for clusterQueues. To maintain API consistency with `borrowWithinCohort`, this may involve transitioning `reclaimWithinCohort` from a plain string enum to a structured object containing a `policy` field and a `maxPriorityThreshold` field.

**Why is this needed**:

This would allow further granularity when defining what resources can be reclaimed within a cohort. When submitting a workload in a cohort, at the moment, you can either set `Never`, `LowerPriority` or `Any`. This means that you cannot protect specifically high priority workloads from another clusterQueue while also allowing for any other workloads of the same or lower priority to be preempted.
