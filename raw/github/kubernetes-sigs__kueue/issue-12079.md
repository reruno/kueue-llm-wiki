## Description

/kind bug

**What happened**:

In PR [#6906](https://github.com/kubernetes-sigs/kueue/pull/6906), the ClusterQueue coveredResources and flavors limits were increased to 64, and #7063 / [#7064](https://github.com/kubernetes-sigs/kueue/pull/7064) increased the matching limits on the Resources under FlavorQuotas and on FlavorsReservation and FlavorsUsage under ClusterQueueStatus. However, the corresponding LocalQueue **status** fields still use the old limit of 16, including [FlavorsReservation and FlavorUsage under LocalQueueStatus (v1beta1)](https://github.com/kubernetes-sigs/kueue/blob/37aba3a7140828eecc9b810d271da66806741c61/apis/kueue/v1beta1/localqueue_types.go#L137-L151), [the same fields in v1beta2](https://github.com/kubernetes-sigs/kueue/blob/37aba3a7140828eecc9b810d271da66806741c61/apis/kueue/v1beta2/localqueue_types.go#L103-L117), and the per-flavor `resources` lists under LocalQueueFlavorUsage.

So when a LocalQueue references a ClusterQueue with more than 16 flavors (valid since #6906), every LocalQueue status update is rejected by the API server once workloads reserve quota in more than 16 flavors:

```
LocalQueue.kueue.x-k8s.io "..." is invalid: status.flavorsReservation: Too many: 23: must have at most 16 items
```

Because the entire status update fails, the LocalQueue also stops receiving updates to its `Active` condition and its pending/reserving/admitted workload counts.

**What you expected to happen**:

The above fields should have MaxItems of 64 to match the limit on flavors in a ClusterQueue, so that the LocalQueue status can be reported for any valid ClusterQueue.

**How to reproduce it (as minimally and precisely as possible)**:

1. Create a ClusterQueue with more than 16 flavors in a resource group, and a LocalQueue pointing to it.
2. Submit workloads through the LocalQueue so that quota is reserved in more than 16 flavors.
3. The LocalQueue controller's status updates are rejected with the error above.

**Anything else we need to know?**:

Observed in a production cluster running Kueue v0.15.4 with a 23-flavor ClusterQueue. The deprecated v1beta1 `status.flavors` field has the same 16-item limit.
