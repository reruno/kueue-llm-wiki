**What would you like to be added**:
We need the ability for Kueue to partially admit an ElasticWorkloadSlice that represents a ScaleUp activity.

Currently, if a massive ScaleUp request exceeds the remaining cohort or flavor quota, the entire request is blocked. However Kueue should be able to admit a smaller, partial slice of the request—up to the maximum available quota limit—instead of taking an all-or-nothing approach.

**Why is this needed**:
For example, a RayCluster might trigger a massive scale-up request to its maximum configured pod count. If that full request slightly exceeds the available quota, Kueue blocks the entire ScaleUp activity.

However, elastic frameworks like Ray can still make great progress and run efficiently with a partial scale-up (e.g., getting 50 out of 100 requested workers). Admitting a partial slice ensures that available cluster capacity doesn't sit idle while waiting for a massive block of quota to clear.
