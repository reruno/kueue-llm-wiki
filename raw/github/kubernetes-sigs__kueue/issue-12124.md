## Description

<!-- Please only use this template for submitting clean up requests -->

**What would you like to be cleaned**:

Reduce how often the e2e suites restart the kueue controller manager, and make each remaining restart cheaper:

1. Drop restarts no test depends on: the `AfterSuite` config resets in the sequential suites (`test/e2e/sequential/baseline/suite_test.go:67`, `test/e2e/sequential/extended/suite_test.go:73`) restore the default configuration moments before the kind cluster is torn down.
2. Parallelize grouped restarts: the `MultiKueueOrchestratedPreemption` block in `test/e2e/multikueue/sequential/e2e_test.go` restarts the manager and both worker clusters sequentially in `BeforeAll` and again in `AfterAll`. Restarting the three clusters concurrently cuts each block from roughly 75s to 25s.
3. Run the e2e deployment with one replica instead of two: `test/e2e/config/default/kustomization.yaml` sets `count: 2`, so every restart pays for a two-pod rolling update. A one-replica default halves the restart cost; a two-replica overlay covers the HA failover specs that need it.


**Why is this needed**:

Restarts dominate the sequential suites. Counting `Kueue restarted` events in recent CI build logs: 17 restarts in sequential-baseline, 6 in sequential-extended, and 12 per cluster (x3 clusters) in multikueue-sequential.

Each restart takes about 25s with two replicas. In a local A/B run of `make test-e2e-sequential-baseline` with `count: 1`, the mean restart dropped from 24.7s (n=15) to 13.8s (n=16) and the whole make target from 792s to 633s (-20%), with no new failures. Together, the three changes could save roughly 5+ minutes per CI cycle across the three suites.

Could contribute to #11606.
