**Which test is flaking?**:

**Link to failed CI job or steps to reproduce locally**:

Example: https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/12127/pull-kueue-test-e2e-extended-shard-2-release-0-18-1-35/2065125939318099968

**Failure message or logs**:
```
There are no nodes that your pod can schedule to - check your requests, tolerations, and node selectors ((combined from similar events): 0/149 nodes are available: 117 Insufficient cpu, 32 node(s) had untolerated taint(s). no new claims to deallocate, preemption: 0/149 nodes are available: 117 No preemption victims found for incoming pod, 32 Preemption is not helpful for scheduling.)
```

**Anything else we need to know?**:

We probably could fix it by setting a higher timeout in test-infra like that:

```yaml
- name: pull-kueue-test-e2e-extended-shard-2-release-0-18-1-35
  decorate: true
  decoration_config:
    pod_unscheduled_timeout: 10m
```
