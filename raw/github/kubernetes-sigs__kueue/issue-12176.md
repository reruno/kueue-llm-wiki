**What would you like to be cleaned**:

I would like to runt the KubeRay test parameters for shorter CI execution times

For example look here: https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/12172/pull-kueue-test-e2e-extended-shard-2-release-0-18-1-35/2065360364047962112

We see that "End To End Extended Suite: kueue/kind-node:v1.35.5: [It] Kuberay Should run a rayjob with InTreeAutoscaling [area:singlecluster, feature:kuberay, Serial, shard:kuberay-b]" took 3min 30s. This is too long.

I think the main reason is because we use 60s tasks. I think this number was arbitrary and never tunes. Using 30s should also be save and already improve the build times by 1min.

One approach we could consider - see what is the timeout to make the jobs sometimes fail, and starting from here try to estimante how much we need to extend the timeout to be safe.

**Why is this needed**:

To improve the performence of the KubaRay builds which are very long
