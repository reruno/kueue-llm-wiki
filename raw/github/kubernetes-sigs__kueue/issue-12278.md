**What would you like to be cleaned**:

Attempt to run KubeRay tests in parallel again. We've disabled the parallelism for the KubeRay jobs in order to provide stability in https://github.com/kubernetes-sigs/kueue/pull/11685

I think now it might be possible, becasue:
- previously we didn't use sharding and we installed all controllers (JobSet, LWS, Appwapper on the nodes, taking much more CPU)
- we can not better control the parallelism by E2E_NPROC

Note that currently we use [E2E_NPROC=4](https://github.com/kubernetes-sigs/kueue/blob/f6efc55965b50e8271f82c721120500dd3d3dc97/Makefile-test.mk#L245) which does not make sense since we run all tests sequentially.

So, I would propose run the tests in parallel with E2E_NPROC=2

Using just E2E_NPROC=2, and with the nodes signifficantly offloaded recently I think there are chances it will be stable.

If we face flakes we can withdraw ofc.

**Why is this needed**:

To improve build times, part of https://github.com/kubernetes-sigs/kueue/issues/11606
