## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

`kueue_cluster_queue_lendable_resources` - Instantaneous amount of quota a ClusterQueue can lend to peers now, for one flavor-resource pair.
`kueue_cohort_lendable_resources` - Total instantaneous lendable capacity available in a cohort for each flavor-resource.

Introduce a new metric that help to understand current amount of resource quota that this ClusterQueue can expose to peers in its Cohort right now.
Another metric that aggregates the amount of sharable resource quota of all CLusterQueues in the given Cohort.
This should represent shareable slack, not static limits.

Pending/terminating/stopped ClusterQueues should not be treated as lenders. If state gating is imperfect, the metric can report shareable quota that is not actually borrowable.

**Why is this needed**:

Existing metrics give static limits and usage, but not real-time exportable capacity.
This directly answers: how much can others borrow from this ClusterQueue now.
It aligns with cohort borrowing and fair-sharing behavior better than nominal, lending limit, or usage alone.

**Risks/Open questions**:

1. Ambiguity due to reservation phase:
If we base it on reservation (which is correct for safety), users may think capacity is “missing” while workloads are only quota-reserved, not yet admitted/running. 
If we base it on admitted usage, you risk over-promising shareable capacity.
We must explicitly define whether it is reservation-based or admitted-usage-based.

2. ClusterQueue/Cohort state updates are event-driven and concurrent. The metric can oscillate quickly during bursts, preemption, or admission retries, producing noisy alerts and dashboard confusion.
