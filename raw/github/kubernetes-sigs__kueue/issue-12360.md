Plan: follow the `scheduler_test.go` split style: same package core, no build tags, and split by topic into `workload_controller_<topic>_test.go`.

Since most of the file is one large table-driven `TestReconcile`, I would first extract a shared case type/helper, then move topic-specific case maps into separate `TestReconcileXxx` functions.

I’m thinking of this split:

- base `workload_controller_test.go`: shared helper/type, existing smaller `Test*` funcs, admit/checks, finalizer/orphaned, retention, max-exec, `AdmissionGatedBy`
- `workload_controller_dra_test.go`: DRA / `KueueDRAIntegration`
- `workload_controller_requeue_test.go`: requeue, backoff, WorkloadRequeued, admission-check delay
- `workload_controller_eviction_test.go`: eviction, StopPolicy, deactivation / retry checks
- `workload_controller_inadmissible_test.go`: LQ/CQ deleted, hold, terminating → Inadmissible

I would keep the base file relatively broad, similar to the scheduler split, and only split out the larger cohesive concerns to avoid over-fragmenting.

Does this granularity sound right, or would you prefer fewer/coarser files? I can also keep the helper extraction and file split as separate commits to make the diff easier to review.
