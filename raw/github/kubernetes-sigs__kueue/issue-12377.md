## Discussion

### Comment by [@mimowo](https://github.com/mimowo) — 2026-06-19T15:32:56Z

I looked at the logs and it doesn't seem like an issue with Kueue itself, some of the created Pods didn't finish on time. 

For reference the AppWrapper -> Jobset created the following pods, and they reported as Running:
`job-set-replicated-job-1-0-1-8jbj4`, and `job-set-replicated-job-1-1-0-vhk4j` on kind-worker2 [log](https://storage.googleapis.com/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/12375/pull-kueue-test-e2e-sequential-extended-shard-0-main/2067905046967750656/artifacts/run-test-e2e-sequential-extended-1.35.5/kind-worker2/kubelet.log).

However, `job-set-replicated-job-1-1-1-vmnk5` and `job-set-replicated-job-1-0-0-28b76` on [kind-worker](https://storage.googleapis.com/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/12375/pull-kueue-test-e2e-sequential-extended-shard-0-main/2067905046967750656/artifacts/run-test-e2e-sequential-extended-1.35.5/kind-worker/kubelet.log) didn't finish.

This is a known issue that is why we have 90s timeouts, but here it seems it wasn't enough. 

One thing I noticed we don't give the containers any mem guaranteed so maybe this is where we could start. Also CPU is very minimal. I think we can bump that. This should allow to give the container more time to finish.

Another approach might be to use Job's SuccessPolicy to report the JobSet, and AppWapper as finish whenever any of the Pods complete. This seems reasonable, we don't really care about all the pods completing from Kueue's PoV.
