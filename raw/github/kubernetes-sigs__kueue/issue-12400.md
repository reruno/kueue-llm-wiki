## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

Add a new field `ExpectedFrameworks []string` in `MultiKueueClusterSpec` to specify which frameworks this worker cluster supports. Therefore, different worker clusters can support different frameworks.

Then, MultiKueue will only watch the worker-cluster CRDs that are specified in `ExpectedFrameworks`. In addition, MultiKueue will only dispatch workloads to worker clusters that support the required frameworks.

**Why is this needed**:

Currently, MultiKueue forces all worker clusters support all frameworks in [Integrations.Frameworks](https://github.com/kubernetes-sigs/kueue/blob/ab2dff32b9c8500357bc8129fd4e1e6fd0e10b8e/apis/config/v1beta2/configuration_types.go#L506). If a worker cluster doesn't have one of the CRDs installed, the manager cluster will not dispatch any kind of workloads to the worker cluster.

However, in some cases, we want different worker clusters to be responsible for different workloads. For example, for CPU-only worker clusters, I want to install Spark operator but not Kubeflow trainer. However, for GPU clusters, I only want to install Kubeflow trainer and I don't want to run Spark jobs in GPU cluster.
