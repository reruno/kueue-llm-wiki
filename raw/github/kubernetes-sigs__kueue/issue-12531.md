## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
An attacker can silently extract sensitive real-time Kubernetes cluster metadata, including all Workloads, LocalQueues, ClusterQueues, Cohorts, and ResourceFlavors, by luring a cluster admin or developer to an external website. This defeats the boundary isolation of the local KueueViz dashboard and allows unauthorized cross-origin data extraction.

### Data Flow
- **cmd/kueueviz/backend/handlers/websocket_handler.go:36**: The gorilla/websocket upgrader explicitly bypasses the Origin check by returning true unconditionally.
- **cmd/kueueviz/backend/handlers/websocket_handler.go:50**: GenericWebSocketHandler upgrades the incoming HTTP request to a WebSocket regardless of the Origin header, fully bypassing CORS restrictions.
- **cmd/kueueviz/backend/handlers/websocket_handler.go:81**: handleInformerUpdates begins streaming real-time cluster workloads, queues, and metadata over the established WebSocket to the cross-origin client.

### Reproduction
**Preconditions**: The KueueViz backend must be running. By default, it is deployed without TokenReview authentication (e.g., via local port-forwarding as described in INSTALL.md on port 8081).
**Steps**:
1. Create an HTML page hosted on any origin (e.g., http://malicious.example.com) with the reproduction script below.
2. Ensure the victim (e.g., a cluster admin or developer) has KueueViz port-forwarded to localhost.
3. Lure the victim into opening the malicious HTML page in their browser.
4. The script will establish a WebSocket connection to `ws://localhost:8081/ws/workloads` without any CORS or Origin errors.
5. The script will receive the JSON stream of all Workload metadata from the cluster and can easily exfiltrate it.

### Vulnerable Code
```
	CheckOrigin: func(r *http.Request) bool {
		return true
	},
```

### Remediation
Enforce strict Origin validation in the WebSocket upgrader, aligning it with the existing HTTP CORS configuration.

Suggested Fix:
```
Remove the custom `CheckOrigin` function to use the secure `gorilla/websocket` default (which strictly compares the Origin header against the Host header), or implement custom validation logic based on the `KUEUEVIZ_ALLOWED_ORIGINS` setting.

var upgrader = websocket.Upgrader{
	Subprotocols: []string{middleware.WebSocketBaseProtocol},
	// Use the default CheckOrigin for strict Host/Origin matching.
}
```
