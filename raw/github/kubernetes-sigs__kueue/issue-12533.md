## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
Complete Denial of Service (DoS) of the Kueue scheduler. A malicious or careless tenant can halt the scheduling of all workloads across all namespaces in the cluster by simply deleting their own LocalQueue after a workload is admitted.

### Data Flow
- **pkg/controller/core/workload_controller.go:816**: When a LocalQueue is deleted, reconcileOnLocalQueueActiveState does not evict an already-admitted Workload if the StopPolicy is not HoldAndDrain. The Workload remains in the scheduler cache.
- **pkg/scheduler/scheduler.go:301**: The Kueue scheduling loop calls s.cache.Snapshot(ctx, snapshotOpts...) to begin the next cycle.
- **pkg/cache/scheduler/snapshot.go:255**: snapshotClusterQueue iterates over cached workloads and calls wl.CalcLocalQueueFSUsage.
- **pkg/workload/workload.go:422**: CalcLocalQueueFSUsage attempts to fetch the deleted LocalQueue via c.Get, which returns a NotFound error.
- **pkg/cache/scheduler/snapshot.go:257**: The error propagates, causing snapshotClusterQueue to return an error.
- **pkg/scheduler/scheduler.go:304**: The scheduling loop aborts and returns wait.SlowDown. This happens every cycle, causing a persistent Denial of Service across the entire cluster.

### Reproduction
**Preconditions**: Kueue must be running with the AdmissionFairSharing feature enabled in its configuration.
**Steps**:
1. Create a ClusterQueue.
2. Create a LocalQueue referencing the ClusterQueue.
3. Submit a Workload to the LocalQueue and wait for it to be Admitted (QuotaReserved).
4. Delete the LocalQueue using 'kubectl delete localqueue <name>'.
5. Observe the Kueue controller logs. The scheduler will continuously log 'failed to build snapshot for scheduling' and cease scheduling any new workloads.

### Vulnerable Code
```
usage, err := wl.CalcLocalQueueFSUsage(ctx, c.client, resourceWeights, afsEntryPenalties, afsConsumedResources)
if err != nil {
	return nil, fmt.Errorf("failed to calculate LocalQueue FS usage for LocalQueue %v", client.ObjectKey{Namespace: wl.Obj.Namespace, Name: string(wl.Obj.Spec.QueueName)})
}
```

### Remediation
Handle missing LocalQueues gracefully during snapshot generation.

Suggested Fix:
```
In pkg/workload/workload.go, update CalcLocalQueueFSUsage to ignore NotFound errors and use a default fair-sharing weight (e.g., 1.0) if the LocalQueue is missing. Alternatively, ignore workloads with missing queues during the snapshot.
```
