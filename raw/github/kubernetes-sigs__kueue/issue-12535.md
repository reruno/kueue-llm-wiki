## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
A low-privileged user can intentionally or accidentally crash the `kueueviz` backend, making the dashboard unavailable for all users. In moderately sized clusters, regular usage will naturally trigger this OOM failure.

### Data Flow
- **cmd/kueueviz/backend/handlers/workloads_dashboard.go:51**: fetchWorkloadsDashboardData lists all Workloads in the requested namespace (or cluster-wide if omitted).
- **cmd/kueueviz/backend/handlers/workloads_dashboard.go:62**: A for loop iterates over each Workload.
- **cmd/kueueviz/backend/handlers/workloads_dashboard.go:69**: Inside the loop, h.client.List is called to list ALL Pods in the Workload's namespace. The informer cache deep-copies all Pod structs into the pl slice.
- **cmd/kueueviz/backend/handlers/websocket_handler.go:138**: Because this handler uses informers, any Pod or Workload update triggers a broadcast, repeating this massive O(W*P) allocation on every small cluster event.

### Reproduction
**Preconditions**: The kueueviz backend is running. An attacker has permission to create Workloads and Pods in any namespace, OR the cluster natively runs a large volume of Workloads and Pods in a single namespace.
**Steps**:
1. Create 500 dummy Workloads and 1,000 dummy Pods in the `default` namespace.
2. Open a WebSocket connection to `/ws/workloads/dashboard?namespace=default` using a valid authentication subprotocol or token header.
3. Observe the kueueviz backend process spiking in CPU and Memory usage.
4. The server will attempt to allocate 500 * 1,000 = 500,000 deep-copied Pod objects into memory, likely triggering an Out Of Memory (OOM) crash.

### Vulnerable Code
```
pl := &corev1.PodList{}
err = h.client.List(ctx, pl, ctrlclient.InNamespace(namespace))
```

### Remediation
Refactor the pod listing logic to operate in O(P) instead of O(W*P) by performing the pod list query outside the workload loop and grouping the pods by their job UID.

Suggested Fix:
```
Before iterating over `wql.Items`, initialize a single `&corev1.PodList{}` and call `h.client.List` for the namespace. Iterate over the retrieved pods to construct a map of `controller-uid` to a slice of pod details (`map[string][]map[string]any`). Finally, loop over `wql.Items` and attach the pod details by looking up `workload.Labels["kueue.x-k8s.io/job-uid"]` in the pre-computed map.
```
