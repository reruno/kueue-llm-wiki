## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
Legitimate tenants who use AdmissionChecks (e.g., for TopologyAwareScheduling or external provisioning) will permanently leak their fair sharing penalties. Over time, their `LocalQueue`'s `FSUsage` will artificially inflate, pushing them to the absolute bottom of the scheduler's priority queue. This results in a persistent Denial of Service (DoS) for those tenants, as their future workloads will be permanently starved by the scheduler.

### Data Flow
- **pkg/scheduler/scheduler.go:812**: Scheduler assumes the workload and calls `s.updateEntryPenalty(log, e, add)`. The workload transitions to `QuotaReserved`.
- **pkg/controller/core/workload_controller.go:1174**: Informer processes `Pending` -> `QuotaReserved`. `status == workload.StatusAdmitted` is false, so `updateAfsConsumedUsage` is SKIPPED.
- **pkg/controller/core/workload_controller.go:1219**: Later, the workload passes AdmissionChecks and transitions `QuotaReserved` -> `Admitted`. This falls to the `default:` case in the switch statement.
- **pkg/controller/core/workload_controller.go:1222**: `updateAfsConsumedUsage` is never called. The initial penalty added by the scheduler is never subtracted via `AfsEntryPenalties.Sub()`.

### Reproduction
**Preconditions**: AdmissionFairSharing must be enabled. A Workload must be created that requires an AdmissionCheck (e.g., ProvisioningRequest, MultiKueue).
**Steps**:
1. Create a Workload that is bound by an AdmissionCheck.
2. The scheduler processes the Workload, adds the penalty to `AfsEntryPenalties`, and sets its status to `QuotaReserved`.
3. Fulfill the AdmissionCheck so the Workload transitions to `Admitted`.
4. Inspect the Kueue cache (or logs); observe that `AfsEntryPenalties.Sub()` is never called.
5. Delete or finish the Workload.
6. The penalty permanently remains on the LocalQueue until the LocalQueue itself is destroyed.

### Vulnerable Code
```
if afs.Enabled(r.admissionFSConfig) && status == workload.StatusAdmitted && r.cache.ClusterQueueUsesAdmissionFairSharing(wlCopy.Status.Admission.ClusterQueue) {
	r.updateAfsConsumedUsage(log, wlCopy)
}
```

### Remediation
Ensure `updateAfsConsumedUsage` is called when a Workload transitions to `Admitted`, regardless of whether its previous state was `Pending` or `QuotaReserved`.

Suggested Fix:
```
Add a specific switch case for `prevStatus == workload.StatusQuotaReserved && status == workload.StatusAdmitted` that calls `r.updateAfsConsumedUsage(log, wlCopy)` before falling through to the cache update logic.
```
