## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
Triggers an infinite loop in the scheduler, freezing the main scheduling goroutine. This results in a complete Denial of Service (DoS) for all queues managed by Kueue.

### Data Flow
- **pkg/scheduler/preemption/fairsharing/ordering.go:94**: When a standalone ClusterQueue (no Cohort) is preempting, TargetClusterQueueOrdering.Iter() yields it via an unbounded loop `for targetCq.HasWorkload()`.
- **pkg/scheduler/preemption/preemption.go:452**: runSecondFsStrategy evaluates LessThanInitialShare. For a standalone CQ, the target and preemptor shares are identical, so this always evaluates to false.
- **pkg/scheduler/preemption/preemption.go:467**: Since passed is false, ordering.DropQueue(candCQ) is called.
- **pkg/scheduler/preemption/fairsharing/ordering.go:124**: DropQueue inserts the CQ into prunedClusterQueues, but does NOT consume the workload from targetCq (unlike PopWorkload).
- **pkg/scheduler/preemption/fairsharing/ordering.go:96**: Because the workload was never popped, `targetCq.HasWorkload()` remains true indefinitely. The `Iter()` loop yields the same candidate CQ repeatedly, locking the CPU.

### Reproduction
**Preconditions**:
FairSharing preemption must be enabled, and a ClusterQueue must be configured without a Cohort (standalone).

**Steps**:
1. Create a standalone ClusterQueue (no cohort) and an associated LocalQueue.
2. Submit a Workload that fits in the ClusterQueue to consume its quota.
3. Submit a higher-priority Workload that requires preemption to fit.
4. When the scheduler evaluates FairSharing strategies, the first strategy may fail, passing retry candidates to `runSecondFsStrategy`.
5. Observe the Kueue controller manager peg the CPU to 100% and freeze as it spins in the `Iter()` loop.

### Vulnerable Code
```
ordering.DropQueue(candCQ)
```

### Remediation
Prevent standalone ClusterQueues from hanging the `Iter()` loop when dropped.

Suggested Fix:
```
Modify `TargetClusterQueueOrdering.Iter()` so the loop for standalone CQs checks the pruned list: `for targetCq.HasWorkload() && !t.prunedClusterQueues.Has(targetCq.targetCq) {`
```
