## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_
### Impact
A tenant can exploit this bug to schedule large driver pods onto restricted or expensive node pools (e.g. GPUs) without Kueue accounting for those resources against the expensive node pool's quota. This leads to quota bypass, resource theft, and potential denial of service (OOM/CPU starvation) on the restricted nodes.

### Data Flow
- **pkg/controller/jobs/sparkapplication/sparkapplication_controller.go:167**: User sets `spec.nodeSelector: {}` (or any valid map) on the SparkApplication. Kueue reads this into `nodeSelector = j.Spec.NodeSelector`.
- **pkg/controller/jobs/sparkapplication/sparkapplication_controller.go:216**: mutatePodSetInfoFor(driver) executes first. The driver's ResourceFlavor node selector is computed and injected into the global `j.Spec.NodeSelector`.
- **pkg/controller/jobs/sparkapplication/sparkapplication_controller.go:216**: mutatePodSetInfoFor(executor) executes next. `j.Spec.NodeSelector` is OVERWRITTEN by the executor's ResourceFlavor node selector.
- **pkg/controller/jobs/sparkapplication/sparkapplication_controller.go:225**: The function returns. The Spark Operator consumes the global `j.Spec.NodeSelector` and schedules BOTH the driver and executor pods onto the executor's flavor node pool.

### Reproduction
**Preconditions**:
1. Kueue must be configured with a `ClusterQueue` containing two `ResourceFlavors`: `cpu-flavor` (e.g. nodeSelector: `node-type: cpu`) and `gpu-flavor` (e.g. nodeSelector: `node-type: gpu`).
2. The Spark operator must be installed and the `sparkoperator.k8s.io/sparkapplication` integration enabled in Kueue.

**Steps**:
1. Submit a `SparkApplication` with `spec.nodeSelector: {}`.
2. Define the `driver` pod spec to request CPU resources (which Kueue will match to `cpu-flavor`).
3. Define the `executor` pod spec to request GPU resources (which Kueue will match to `gpu-flavor`).
4. Wait for Kueue to admit the workload.
5. Observe the created `SparkApplication` object's `spec.nodeSelector` field. It will match the GPU flavor.

### Vulnerable Code
```
if j.Spec.NodeSelector != nil {
	j.Spec.NodeSelector = sparkPodSetInfo.NodeSelector
} else {
```

### Remediation
Do not overwrite the global `j.Spec.NodeSelector` during `RunWithPodSetsInfo`. Instead, migrate the injected node selectors into the role-specific `sparkPodSpec.NodeSelector` fields and clear the global `j.Spec.NodeSelector`.

Suggested Fix:
```
Change the assignment in `RunWithPodSetsInfo` to always apply to `sparkPodSpec.NodeSelector` and explicitly clear `j.Spec.NodeSelector`:

go
		sparkPodSpec.NodeSelector = sparkPodSetInfo.NodeSelector
		j.Spec.NodeSelector = nil
```
Apply a similar fix to `RestorePodSetsInfo` to ensure correctness during suspension.
