## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
A low-privileged user (e.g., a developer with permissions to create Events in a specific namespace) can permanently block administrators and other users from viewing the details of a targeted workload. Viewing the workload crashes the entire SPA, requiring a full page refresh and rendering the page unusable as long as the malicious event exists.

### Data Flow
- **cmd/kueueviz/backend/handlers/workloads.go:131**: Backend fetches corev1.EventList and sends the events via WebSocket to the frontend. The `firstTimestamp` field in Kubernetes Events is optional (`omitempty`).
- **cmd/kueueviz/frontend/src/WorkloadDetail.jsx:30**: Frontend receives the events via `useWebSocket` and stores them in `eventData`.
- **cmd/kueueviz/frontend/src/WorkloadDetail.jsx:93**: If `event.firstTimestamp` is undefined, `new Date(undefined)` evaluates to an `Invalid Date` object. Calling `.toISOString()` on an `Invalid Date` object synchronously throws a `RangeError: Invalid time value`.

### Reproduction
**Preconditions**:
The Kueueviz backend and frontend must be running. A workload named 'test-workload' must exist in the 'default' namespace.

**Steps**:
1. Create an Event for the workload using the Kubernetes API or kubectl, intentionally omitting the `firstTimestamp` field.
2. Open a web browser and navigate to the WorkloadDetail page for the 'test-workload' in the 'default' namespace (e.g., http://localhost:8080/workload/default/test-workload).
3. Observe that the React application immediately crashes and unmounts, displaying a blank white screen instead of rendering the workload details.

### Vulnerable Code
```
                  <TableCell>
                    {new Date(event.firstTimestamp).toISOString().replace('T', '@').slice(0, 19)} UTC
                  </TableCell>
```

### Remediation
Implement defensive checks for the `firstTimestamp` value before calling `.toISOString()`, and provide a fallback string if the timestamp is undefined or invalid.

Suggested Fix:
```
Replace the vulnerable line with: `{event.firstTimestamp ? new Date(event.firstTimestamp).toISOString().replace('T', '@').slice(0, 19) + ' UTC' : 'N/A'}`
```
