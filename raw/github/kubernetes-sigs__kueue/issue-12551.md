## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_
### Impact
Users executing operational commands with `--dry-run` to safely test configuration or verify permissions will accidentally trigger mutating changes on the cluster. In a production setting, running `kueuectl stop clusterqueue <name> --dry-run=server` in an automated CI/CD pipeline or operator script will unexpectedly halt production workloads, leading to denial of service. The exact same vulnerability applies to `kueuectl resume`.

### Data Flow
- **cmd/kueuectl/app/resume/resume.go:37**: The `--dry-run` persistent flag is added to the parent `resume` command via `flags.AddDryRunFlag(cmd)`, meaning it is parsed and accepted by all subcommands without triggering an unknown flag error.
- **cmd/kueuectl/app/resume/resume_clusterqueue.go:98**: The `ClusterQueueOptions.Run` function executes, bypassing any checks for the `dryrun.Strategy` value.
- **cmd/kueuectl/app/resume/resume_clusterqueue.go:107**: `opts := metav1.PatchOptions{}` is initialized empty, omitting `DryRun: []string{metav1.DryRunAll}` even if `--dry-run=server` was specified.
- **cmd/kueuectl/app/resume/resume_clusterqueue.go:114**: The `Patch` API call is executed unconditionally, mutating the remote cluster state regardless of the user's explicit request for a client or server dry-run.

### Reproduction
**Preconditions**:
A Kubernetes cluster must be running with the Kueue controller installed. `kueuectl` must be compiled.

**Steps**:
1. Create a dummy ClusterQueue named `test-queue` using `kueuectl create clusterqueue test-queue`.
2. Stop the queue explicitly using `kueuectl stop clusterqueue test-queue`.
3. Verify the stop policy is Hold: `kubectl get clusterqueue test-queue -o jsonpath='{.spec.stopPolicy}'`.
4. Run the resume command with `--dry-run=client` to simulate resuming it: `kueuectl resume clusterqueue test-queue --dry-run=client`.
5. Observe the queue state again: `kubectl get clusterqueue test-queue -o jsonpath='{.spec.stopPolicy}'`.

### Vulnerable Code
```
	opts := metav1.PatchOptions{}
	patch := client.MergeFrom(cqOriginal)
	data, err := patch.Data(cq)
	if err != nil {
		return err
	}
	cq, err = o.Client.ClusterQueues().
		Patch(ctx, o.ClusterQueueName, types.MergePatchType, data, opts)
```

### Remediation
Retrieve the `dryrun.Strategy` in the `Complete` method, enforce it in `Run`, and properly populate `metav1.PatchOptions{DryRun: []string{metav1.DryRunAll}}` if the strategy is `Server`.

Suggested Fix:
```
Add `DryRunStrategy dryrun.Strategy` to `ClusterQueueOptions` and `LocalQueueOptions`. Update the `Complete` method to parse it: `o.DryRunStrategy, err = dryrun.GetStrategy(cmd)`. Update `Run` to return early or skip the `Patch` call if `o.DryRunStrategy == dryrun.Client`, and add `opts.DryRun = []string{metav1.DryRunAll}` if it is `dryrun.Server`.
```
