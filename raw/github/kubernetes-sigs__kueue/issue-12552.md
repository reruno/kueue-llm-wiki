## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
Users can bypass intended field immutability on workloads that are actively admitted, altering their logical association with queues and priority classes without triggering expected re-admission or rejection.

### Data Flow
- **apis/kueue/v1beta2/workload_types.go:1118**: User patches an Admitted workload by removing the 'queueName' field. Because 'has(self.spec.queueName)' evaluates to false, the ternary operator evaluates to 'true'.
- **apis/kueue/v1beta2/workload_types.go:1118**: User patches the workload again, adding a different 'queueName'. Because 'has(oldSelf.spec.queueName)' evaluates to false, the ternary evaluates to 'true', successfully bypassing the immutability check.

### Reproduction
**Preconditions**:
A workload is admitted (QuotaReserved is True).

**Steps**:
1. Submit a JSON patch to the workload removing the 'queueName' field: `[{"op": "remove", "path": "/spec/queueName"}]`
2. Submit a second JSON patch adding a new 'queueName': `[{"op": "add", "path": "/spec/queueName", "value": "new-queue"}]`

### Vulnerable Code
```
has(oldSelf.spec.queueName) && has(self.spec.queueName) ? oldSelf.spec.queueName == self.spec.queueName : true
```

### Remediation
Use default values for missing fields during comparison instead of skipping the comparison.

Suggested Fix:
```
Change the CEL rules to emulate the maximumExecutionTimeSeconds rule. E.g., `((has(oldSelf.spec.queueName)?oldSelf.spec.queueName:"") == (has(self.spec.queueName)?self.spec.queueName:""))`
```
