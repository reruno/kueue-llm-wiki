## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
A single preempted workload in the cluster will inadvertently render the KueueViz dashboard fully unusable for all users due to client-side resource exhaustion (browser freeze).

### Data Flow
- **cmd/kueueviz/frontend/src/Dashboard.jsx:45**: The `useWebSocket` hook returns a new `kueueData` object instance each time a WebSocket message arrives.
- **cmd/kueueviz/frontend/src/Dashboard.jsx:48**: The `useEffect` dependency array includes `[kueueData, kueueError]`, meaning the effect re-runs completely on every WebSocket message.
- **cmd/kueueviz/frontend/src/Dashboard.jsx:63**: The code indiscriminately iterates over every workload. For any workload where `preempted` is true, it triggers a new `toast.error`.

### Reproduction
**Preconditions**:
1. KueueViz is running.
2. There is at least one Workload in the cluster that has the `kueue.x-k8s.io/preempted` condition.

**Steps**:
1. Create a Workload and set its `Preempted` status condition to true (or allow Kueue to naturally preempt a workload).
2. Open the KueueViz Dashboard in a browser window.
3. Trigger frequent background changes in the cluster (e.g., standard pod churn or status updates), forcing the backend informer to emit new WebSocket data frames.
4. On every single frame received, the `useEffect` runs and generates an entirely new toast notification for the preempted workload.
5. The browser DOM will rapidly fill with thousands of toast components.

### Vulnerable Code
```
      kueueData.workloads?.items?.forEach(workload => {
        if (workload.preemption?.preempted) {
          toast.error(`Workload ${workload.metadata?.name} was preempted: ${workload.preemption.reason}`);
        }
      });
```

### Remediation
Implement deduplication or tracking for workload preemption toasts so they are only displayed once.

Suggested Fix:
```
Supply a unique `toastId` corresponding to the workload UID when invoking the toast, which utilizes `react-toastify`'s built-in deduplication: `toast.error(msg, { toastId: workload.metadata.uid })`. Alternatively, track notified workloads using a `useRef` array.
```
