## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
Running applications as the root user inside a container violates the principle of least privilege. If an attacker discovers and exploits a vulnerability in the application (e.g., in the Node.js runtime or the `serve` dependency), they will gain root-level execution within the container. This significantly increases the risk of container escape and horizontal escalation within the Kubernetes cluster.

### Data Flow
None

### Reproduction
**Preconditions**:
Docker must be installed and the image must be built from the target Dockerfile.

**Steps**:
1. Build the docker image using the Dockerfile.
2. Run the container as a daemon.
3. Execute the `whoami` or `id` command inside the running container to check the effective user.

### Vulnerable Code
```
FROM node:25-slim AS runtime

WORKDIR /app

RUN npm install -g serve

# ... 

ENTRYPOINT ["serve", "-s", "build", "-l", "tcp://0.0.0.0:8080"]
```

### Remediation
Create or use an existing non-root user and switch to it before executing the entrypoint.

Suggested Fix:
```
Add the `USER node` directive to the runtime stage just before the `ENTRYPOINT`. The official Node.js image provides the unprivileged `node` user by default.
```
