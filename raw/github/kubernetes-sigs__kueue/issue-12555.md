## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
A low-privileged tenant (namespace admin) can intentionally crash the cluster-wide Kueue controller via a data race, denying queueing, admission, and scheduling services to all other tenants in the Kubernetes cluster.

### Data Flow
- **pkg/cache/scheduler/cache.go:627**: Cache.UpdateLocalQueue avoids Cache.Lock() if the ClusterQueue reference is unchanged, proceeding to call c.updateLqMetricLabels(newQ)
- **pkg/cache/scheduler/cache.go:654**: updateLqMetricLabels acquires cachedLq.Lock() and assigns a newly allocated slice to cachedLq.customMetricLabelValues
- **pkg/cache/scheduler/localqueue.go:69**: Concurrently, Cache.ResyncGaugeMetrics iterates through queues while holding Cache.RLock() (but NOT cachedLq.RLock()) and calls reportActiveWorkloads
- **pkg/cache/scheduler/localqueue.go:75**: reportActiveWorkloads passes q.customMetricLabelValues to metrics exporters without holding q.RLock(), leading to a classic Go slice header data race

### Reproduction
**Preconditions**:
The Kueue controller must be running with the alpha feature gate 'CustomMetricLabels' enabled. The attacker needs RBAC permission to patch/update a LocalQueue in their namespace.

**Steps**:
1. Create a ClusterQueue and a valid LocalQueue referencing it.
2. Launch a background process that rapidly patches the labels on the LocalQueue. This frequently invokes UpdateLocalQueue -> updateLqMetricLabels in the controller.
3. Concurrently, launch a process that rapidly creates and deletes Workloads referencing the LocalQueue. This triggers workload state updates and metric reporting (ResyncGaugeMetrics/reportActiveWorkloads).
4. Observe the Kueue controller pod panicking due to a torn read of the slice header.

### Vulnerable Code
```
metrics.ReportLocalQueueAdmittedActiveWorkloads(lqRef, q.admittedWorkloads, q.customMetricLabelValues, tracker)
metrics.ReportLocalQueueReservingActiveWorkloads(lqRef, q.reservingWorkloads, q.customMetricLabelValues, tracker)
```

### Remediation
Synchronize the reads of `customMetricLabelValues` in the `LocalQueue` metric reporters by acquiring `q.RLock()`.

Suggested Fix:
```
In `pkg/cache/scheduler/localqueue.go`, add `q.RLock()` and `defer q.RUnlock()` at the beginning of both `reportActiveWorkloads` and `reportResourceMetrics` methods.
```
