## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
An attacker can exhaust the server's resources (file descriptors, memory, goroutines) by keeping many connections open indefinitely (a Slowloris attack), leading to a Denial of Service (DoS) for legitimate users.

### Data Flow
- **cmd/kueueviz/backend/main.go:51**: The HTTP server is initialized without setting `ReadTimeout`, `WriteTimeout`, or `IdleTimeout`.
- **cmd/kueueviz/backend/main.go:81**: The server listens and serves requests using `srv.ListenAndServe()`, relying on the default Go `net/http` configuration which allows connections to remain open indefinitely.

### Reproduction
**Preconditions**:
The kueueviz backend server is running and accessible.

**Steps**:
1. Open a raw TCP connection to the server port.
2. Send a partial HTTP request (e.g., `GET / HTTP/1.1\r\nHost: localhost\r\n`) and keep the connection open without sending the terminating `\r\n\r\n`.
3. Open many such connections concurrently.

### Vulnerable Code
```
	srv := &http.Server{
		Addr:    serverConfig.GetServerAddress(),
		Handler: r.Handler(),
	}
```

### Remediation
Configure appropriate timeouts on the `http.Server` instance.

Suggested Fix:
```
srv := &http.Server{
	Addr:         serverConfig.GetServerAddress(),
	Handler:      r.Handler(),
	ReadTimeout:  10 * time.Second,
	WriteTimeout: 10 * time.Second,
	IdleTimeout:  120 * time.Second,
}
```
