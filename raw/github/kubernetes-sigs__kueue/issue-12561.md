## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
An unauthenticated attacker can trivially exhaust the backend's memory (since invalid tokens are cached in an unbounded map until the 1-minute eviction ticker fires) and simultaneously launch a Denial of Service attack against the Kubernetes API server by forcing it to process thousands of bogus `TokenReview` requests.

### Data Flow
- **cmd/kueueviz/backend/middleware/auth.go:61**: The authenticator extracts an unauthenticated, user-provided token from the request header.
- **cmd/kueueviz/backend/middleware/auth.go:70**: If the token is not found in the local cache, the backend immediately calls `reviewToken`.
- **cmd/kueueviz/backend/middleware/auth.go:106**: The backend submits a synchronous `TokenReview` request to the Kubernetes API server for every unique invalid token.

### Reproduction
**Preconditions**:
KueueViz backend is running with `KUEUEVIZ_AUTH_MODE=TokenReview`.

**Steps**:
1. Send thousands of HTTP requests to a protected KueueViz endpoint, each containing a unique, randomly generated Bearer token.
2. Observe the KueueViz backend forwarding all requests to the Kubernetes API server.

### Vulnerable Code
```
result, err := a.clientset.AuthenticationV1().TokenReviews().Create(ctx, review, metav1.CreateOptions{})
```

### Remediation
Implement rate limiting and bound the token cache size.

Suggested Fix:
```
Add an IP-based or global rate limiter before the authentication middleware to throttle excessive requests with invalid tokens. Additionally, replace the unbounded map in `tokenReviewCache` with an LRU cache (e.g., `hashicorp/golang-lru`) to strictly bound memory consumption.
```
