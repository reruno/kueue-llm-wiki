## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
Navigating to an invalid resource causes a persistent client-side Denial of Service (DoS) for the user. Because the application lacks a React ErrorBoundary, the entire UI unmounts. Attackers could send links to invalid cohorts to administrators, causing their dashboards to crash upon visitation.

### Data Flow
- **cmd/kueueviz/backend/handlers/cohorts.go:94**: When a non-existent cohort is requested, `client.Get` fails and the backend writes an error JSON: `{"error": "error fetching cohort..."}` to the WebSocket.
- **cmd/kueueviz/frontend/src/useWebSocket.js:46**: `useWebSocket` parses the JSON and calls `setData({"error": "..."})`.
- **cmd/kueueviz/frontend/src/CohortDetail.jsx:38**: `useEffect` detects `cohortData` and sets `cohortDetails` to the error object, which lacks the `clusterQueues` property.
- **cmd/kueueviz/frontend/src/CohortDetail.jsx:56**: The component attempts to read `.length` on `cohortDetails.clusterQueues` (which is undefined), throwing a TypeError and crashing the React application.

### Reproduction
**Preconditions**:
The Kueueviz frontend and backend must be running.

**Steps**:
1. Open a web browser.
2. Navigate to a URL for a cohort that does not exist in the cluster (e.g., `http://localhost:3000/cohort/invalid-cohort-name`).
3. Observe the page state.

### Vulnerable Code
```go
      <Typography variant="body1"><strong>Number of Cluster Queues:</strong> {cohortDetails.clusterQueues.length}</Typography>
```

### Remediation
Check for the presence of the `error` field in the API response data and handle it gracefully, and wrap the application in a React ErrorBoundary.

Suggested Fix:
```
Add a check before rendering: `if (cohortDetails.error) return <ErrorMessage error={cohortDetails.error} />;` and safely access arrays using optional chaining `cohortDetails.clusterQueues?.length || 0`.
```
