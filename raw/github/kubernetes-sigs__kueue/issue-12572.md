## Description

_Note: This issue was initially flagged by an automated AI security scan and has been manually triaged by a human_

### Impact
Administrators updating ResourceFlavors will inadvertently cause Topologies to become orphaned zombie resources (stuck in Terminating state forever) due to unhandled Update events. This requires manual intervention via API patching to remove the finalizers.

### Data Flow
- **pkg/controller/tas/topology_controller.go:67**: The topology reconciler registers `resourceFlavorHandler` to watch for `ResourceFlavor` events.
- **pkg/controller/tas/topology_controller.go:172**: The `Update` handler ignores the update event when a `ResourceFlavor` is modified.
- **pkg/controller/tas/topology_controller.go:88**: If a `Topology` was deleted, it waits for all `ResourceFlavors` referencing it to be deleted or updated before its `kueue.x-k8s.io/resource-in-use` finalizer can be removed. Because `Update` events are ignored, updating a `ResourceFlavor` to stop referencing the `Topology` fails to requeue the `Topology`.

### Reproduction
**Preconditions**:
A Kubernetes cluster running the Kueue controller.

**Steps**:
1. Create a Topology named `test-topo`.
2. Create a ResourceFlavor named `test-flavor` with `topologyName: test-topo`.
3. Wait for `test-topo` to be assigned the `kueue.x-k8s.io/resource-in-use` finalizer by the TAS topology controller.
4. Delete the Topology `test-topo`. Since it's referenced by the flavor, it enters the `Terminating` state.
5. Update the ResourceFlavor `test-flavor` to set `topologyName` to `null` (or a different topology).
6. Observe that `test-topo` remains stuck in the `Terminating` state indefinitely because the topology controller never receives the `Update` trigger to re-evaluate the finalizer.

### Vulnerable Code
```go
func (h *resourceFlavorHandler) Update(context.Context, event.UpdateEvent, workqueue.TypedRateLimitingInterface[reconcile.Request]) {
}
```

### Remediation
Implement the `Update` method in `resourceFlavorHandler` to enqueue the previous `TopologyName` when a `ResourceFlavor` is updated.

Suggested Fix:
```go
func (h *resourceFlavorHandler) Update(_ context.Context, e event.UpdateEvent, q workqueue.TypedRateLimitingInterface[reconcile.Request]) {
	oldFlavor, isOldFlavor := e.ObjectOld.(*kueue.ResourceFlavor)
	if !isOldFlavor || oldFlavor.Spec.TopologyName == nil {
		return
	}
	// Queue the old topology so its finalizer can be evaluated and potentially removed.
	q.AddAfter(reconcile.Request{
		NamespacedName: types.NamespacedName{
			Name: string(*oldFlavor.Spec.TopologyName),
		},
	}, constants.UpdatesBatchPeriod)
}
```
