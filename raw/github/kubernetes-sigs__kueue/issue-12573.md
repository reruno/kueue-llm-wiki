### Comment by [@ivnovakov](https://github.com/ivnovakov) — 2026-11-09T17:31:01Z

I checked the 4 remaining items against current main.

- [#12570](https://github.com/kubernetes-sigs/kueue/issues/12570) is not reachable. The CEL rule on `ResourceGroup` blocks it. Details are in the issue.
- [#12538](https://github.com/kubernetes-sigs/kueue/issues/12538) is partly fixed on main. [#14269](https://github.com/kubernetes-sigs/kueue/pull/14269) and [#16125](https://github.com/kubernetes-sigs/kueue/pull/16125) stop the capacity inflation. The replaced slice can still appear twice in the targets, so with `withinClusterQueue: Any` it can be evicted as `Preempted`. [#13185](https://github.com/kubernetes-sigs/kueue/pull/13185) fixes that, but it needs a rebase, and the comments from @apullo777 are still open.
- [#12548](https://github.com/kubernetes-sigs/kueue/issues/12548) is still valid on main. A Workload with a forged owner still reaches the remote Job deletion. It needs Workload create rights, which `batch-user-role` does not grant by default. [#13213](https://github.com/kubernetes-sigs/kueue/pull/13213) adds an ownership check, but only behind an alpha gate that is off by default. It also needs a rebase, and [#14134](https://github.com/kubernetes-sigs/kueue/issues/14134) tracks its naming gap for sliced jobs.
- [#12572](https://github.com/kubernetes-sigs/kueue/issues/12572) is not reachable as described, since `topologyName` is immutable. A smaller race remains between the TAS cache update and the Topology requeue. [#13186](https://github.com/kubernetes-sigs/kueue/pull/13186) fixes it with a 1-minute requeue. @vladikkuzn suggested the existing `spec.topologyName` index instead, which avoids polling.

All four are `lifecycle/stale` and go rotten in late November. I pinged the authors of the three PRs.
