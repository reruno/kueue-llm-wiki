## Description

**What would you like to be added**:

Here's an example of pprof CPU flame chart on 2500 nodes cluster with 15 resource flavors with TAS enabled (GC function calls excluded).

<img width="2555" height="907" alt="Image" src="https://github.com/user-attachments/assets/bcb31f16-b678-43f2-89c2-4c1bc08eca1d" />

There are some substeps of the snapshot building that could be improved:
- Node Copying (`addNodes`):
  The node information we store rather doesn't change very frequently:
  ```go
  type nodeInfo struct {
  	Name        string
  	Labels      map[string]string
  	Taints      []corev1.Taint
  	Allocatable corev1.ResourceList
  }
  ```
  So there is room for improvement to not copy them on every snapshot building. We can introduce a `generation` counter on the nodes cache and reuse the pre-built snapshot tree in-place if the generation doesn't change, completely bypassing the tree-building phase.
  
- Tree building (`initialize`):
  We don't have to rebuild the parent-child pointers (`dom.parent` and `dom.children`) on every cycle if the nodes list hasn't changed.
  
- Eliminate `usagePerNode` map cloning:
  Currently, `usagePerNode()` copies `map[string]resources.Requests{}` (a map of maps) to defend against concurrent modifications during iteration. We can replace this with read and subtract in a lock without cloning the maps.

**Why is this needed**:

At large scales (e.g., 2,500+ nodes and multiple resource flavors), rebuilding the TAS topology snapshot from scratch on every scheduling cycle creates significant CPU overhead and heavy garbage collection pressure.
