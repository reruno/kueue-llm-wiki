Passing batch Job integration tests repeatedly log errors from `startJob`:

`Job.batch "<name>" is invalid: spec.template: ... field is immutable`

This [main Prow run](https://prow.k8s.io/view/gs/kubernetes-ci-logs/logs/periodic-kueue-test-integration-shard-2-main/2070521276593606656) contains 25 `Unsuspending job` occurrences from `ReconcileGenericJob`.

**What you expected to happen**:

The controller and tests should not repeatedly attempt an invalid PodTemplate
update after a Job's template becomes immutable.

**How to reproduce it (as minimally and precisely as possible)**:

Run the batch Job integration suite:

```shell
make compile-crd-manifests
KUBEBUILDER_ASSETS="$(bin/setup-envtest use 1.36.2 -p path)" \
  bin/ginkgo -v ./test/integration/singlecluster/controller/jobs/job/...
```

Search the output for `Unsuspending job` and `field is immutable`. The suite
passes despite the repeated reconciliation errors.
