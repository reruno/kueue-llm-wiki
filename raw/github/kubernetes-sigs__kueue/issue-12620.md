## Description

<!-- Please only use this template for submitting clean up requests -->

**What would you like to be cleaned**:

Deprecate and eventually drop the Kubeflow trainer V1 integration. 

The remainig question is **when** we drop the support. I believe tentatively 0.20 is ok, but we may re-consider based on user feedback.

**Why is this needed**:

Kubeflow Trainer v1 itself is no longer maintained: https://www.kubeflow.org/docs/components/trainer/legacy-v1/, and so it no longer receives dependency updates which puts Kueue at risk, see discussion in https://github.com/kubernetes-sigs/kueue/issues/11273

### Comment by [@andreyvelich](https://github.com/andreyvelich) — 2026-07-07T23:34:53Z

>is v2 already battle tested by some users?

We have existing internal customers who have already migrated to the TrainJob in production, and actively using it day to day.
So I see more and more users actively moving to V2.

Some folks are waiting for a few features like elastic TrainJobs to have 1-1 compatibility with v1 features, and we have an open proposal: https://github.com/kubeflow/trainer/pull/3654 (cc @aniket2405  @akshaychitneni @Ronkahn21)

>are there any breaking API changes expected in the coming releases?

One of the blockers we discuss with @kannon92 is JobSet V1 API graduation: https://github.com/kubernetes-sigs/jobset/issues/380
I would love to just push JobSet API to v1 ASAP, so users will stop using an alpha API.
IIUC, we want to push this forward after integrating JobSet with WAS.
