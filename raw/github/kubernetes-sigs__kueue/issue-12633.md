## Description

**What would you like to be cleaned**:

KueueViz, for its frontend part, has an e2e test suite ([here](https://github.com/kubernetes-sigs/kueue/blob/bee9304a8aa9a83412b5d91516fdd3779ff1b331/test/e2e/kueueviz/cypress/e2e/app.cy.js)) but a very limited coverage of unit tests (for [ErrorMessage](https://github.com/kubernetes-sigs/kueue/blob/bee9304a8aa9a83412b5d91516fdd3779ff1b331/cmd/kueueviz/frontend/src/ErrorMessage.test.js), [UsageBar](https://github.com/kubernetes-sigs/kueue/blob/bee9304a8aa9a83412b5d91516fdd3779ff1b331/cmd/kueueviz/frontend/src/UsageBar.test.js) and [useWebSocket](https://github.com/kubernetes-sigs/kueue/blob/bee9304a8aa9a83412b5d91516fdd3779ff1b331/cmd/kueueviz/frontend/src/useWebSocket.test.js) - but not for most of the components).

The existing unit tests are JS-level only, with no DOM operations.

For healthiest growth, we should add DOM-level unit tests, and coverage for all components.

**Why is this needed**:

This will allow unit-testing any code changes in the components, including edge cases.

While this can be technically covered within the existing framework of Cypress e2e tests, such strategy is suboptimal: e2e tests are inherently less stable and costly to run (incl. latency); developing a project should not rely so heavily on those.

(A direct trigger to create this issue was reviewing #12613)
