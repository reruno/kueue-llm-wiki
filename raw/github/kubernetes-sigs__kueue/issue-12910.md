## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:
I would like the ability to scope resource transformation rules to specific resource flavors or node labels rather than being global.

**Why is this needed**:
In the [docs](https://kueue.sigs.k8s.io/docs/tasks/manage/administer_cluster_quotas/#transform-resources-for-quota-management) for quota management, resource transformations are listed as one possible way to create a compute-credit resource that can be quota-managed. Because transforms apply globally, however, and cannot currently refer to e.g. node labels or similar as a kind of gating mechanism, this approach cannot be used in the common case (like [this](https://github.com/kubernetes-sigs/kueue/discussions/10896)) where accelerator types are specified via node affinity rules while accelerator counts remain a flat resource. This also leaks over into fair sharing weights, where again the lack of accelerator-specific resources and transformations prevent more accurate weighting of queues.

It's somewhat related to https://github.com/kubernetes-sigs/kueue/issues/8902, and could be used as a way to implement it (create flavor-specific transforms, have fair sharing be based on the credit resource share).
