## Description

## What happened

When `kubeflow.org/mpijob` is included in Kueue's `integrations.frameworks`, the MultiKueue cluster reconciler tries to watch `kubeflow.org/v2beta1, Kind=MPIJob` on worker clusters. Workers running the Kubeflow Training Operator (v1.7+) only serve MPIJob at `kubeflow.org/v1`, causing:

```
"Unable to start the watcher","clusterName":"worker-a","kind":"kubeflow.org/v2beta1, Kind=MPIJob",
"error":"no matches for kind \"MPIJob\" in version \"kubeflow.org/v2beta1\""
```

This error is **fatal to the MultiKueueCluster** — the cluster goes `Active=False` and **all workload dispatch is blocked** (not just MPIJob types).

## Root cause

Kueue's MPIJob adapter imports from the standalone (maintenance-mode) MPI Operator:

```go
// pkg/controller/jobs/mpijob/mpijob_controller.go
kfmpi "github.com/kubeflow/mpi-operator/pkg/apis/kubeflow/v2beta1"
```

But the actively maintained [kubeflow/training-operator](https://github.com/kubeflow/training-operator) (v1.7+) absorbed MPIJob and serves it only at `v1`:
- CRD: [kubeflow.org_mpijobs.yaml](https://github.com/kubeflow/training-operator/blob/v1.9.3/manifests/base/crds/kubeflow.org_mpijobs.yaml) — versions: [{name: v1, served: true, storage: true}]

The standalone `kubeflow/mpi-operator` repo (which defined v2beta1) is in maintenance mode.

## Impact

- Tested on Kueue v0.17.6 and v0.18.2 — same behavior on both
- Workaround: remove `kubeflow.org/mpijob` from integrations.frameworks (MPIJob cannot be managed by Kueue at all)
- All other Kubeflow job types (PyTorchJob, TFJob, XGBoostJob, PaddleJob, JAXJob) work because they use v1 consistently
- When enabled, it blocks ALL MultiKueue dispatch, not just MPIJob

## Suggested fix

Update the import to the Training Operator v1 API, or support version negotiation via API discovery.

## Environment

- Kueue version: v0.17.6, v0.18.2
- Kubernetes version: 1.35 (AKS)
- Training Operator version: v1.9.3

### Comment by [@andreyvelich](https://github.com/andreyvelich) — 2026-07-15T14:08:35Z

Training Operator v1 doesn't support `v2beta1` API of MPIJob. You need to install MPI-Operator for that.

Alternatively, you can simple install TrainJob controller (e.g. Kubeflow Trainer) which supports the same MPI capabilities as MPI-Operator. You can read more about MPI Policy here: https://trainer.kubeflow.org/en/latest/operator-guides/ml-policy.html#mpi
 
One of the Runtime example that uses MPI: https://github.com/kubeflow/trainer/blob/master/manifests/base/runtimes/deepspeed_distributed.yaml
