## Description

**What would you like to be added:**

Architecturally refactor Kueue's placement logic to utilize the high-level ScheduleWorkload function to be provided by the [Scheduler Library](https://github.com/kubernetes-sigs/scheduler-library/tree/main). In this model, the base scheduling mechanics-including fine-grained pod-to-node mapping, bin-packing, and standard preemption-are delegated to and handled by the WAS (Workload Aware-Scheduler) algorithms. Kueue retains its role as the high-level orchestrator but extends and drives the core WAS execution cycle. Custom Kueue policies (such as fair-sharing, dynamic preemption logic, and queue prioritization) will be injected natively into the WAS scheduling cycle using specialized WAS extension points (e.g., fine-grained workload ordering or custom preemption scoring).

This change corresponds to _Strategic Track 4: Deep Integration between WAS and Kueue Implementation_ from the [WAS and Kueue integration strategy](https://docs.google.com/document/d/13I3bMY-abBtsWmDhCl4RdDHKchHeB3G8zMSTpplmxHA/edit?usp=sharing) document.

**Why is this needed:**

Currently, both Kueue and the upstream scheduler maintain separate logic for Topology-Aware Scheduling (TAS) and gang placement. Running these parallel evaluations is resource-intensive, creates latency, and introduces the risk of state divergence (the "split-brain" problem).

By leveraging ScheduleWorkload for the mechanical heavy lifting and WAS extension points for policy enforcement, Kueue eliminates the prohibitive cost of duplicating complex hardware features (like advanced topology tracking or Dynamic Resource Allocation) inside its own codebase. This approach guarantees identical placement simulation while allowing Kueue to inject its advanced fair-sharing and queuing rules directly into the WAS cycle, eliminating the need to build "wrapper" logic or maintain a fully separate, competing scheduling loop.

**Completion requirements:**

- Integrate the high-level ScheduleWorkload function from the Scheduler Library into Kueue's admission evaluation paths.
- Implement Kueue-specific logic (fair-sharing, dynamic priority) as plugins for WAS Extension Points to drive the simulation logic.
- Deprecate Kueue's internal custom algorithm modules for fine-grained bin-packing and TAS, relying on the library's high-level assignment output.
- Adapt Kueue's admission controller to act based on the exact assignments (e.g., node groups, slices) returned by ScheduleWorkload.
- Redesign integration tests to validate placement correctness, policy extension stability, and loop isolation under high throughput scenarios.

Implementation of this feature depends on https://github.com/kubernetes-sigs/kueue/issues/13149, implementation of the ScheduleWorkload function in Scheduler Library and implementation of the required extension points in WAS.
