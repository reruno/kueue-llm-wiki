**What would you like to be cleaned:**

Existing integration tests cover some hierarchical cohort behavior (borrowing, lendingLimit, reparenting metrics), but several scheduling scenarios have no dedicated test coverage: mid-tree deletion, cycle detection, borrowingLimit enforcement, and isolated org burst queues. There is also no e2e smoke test for hierarchical cohorts.

Following [reviewer feedback on #13295](https://github.com/kubernetes-sigs/kueue/pull/13295#discussion_r3661483135), the approach is to keep one e2e smoke test and move the rest to integration tests in `scheduler_test.go`, since the assertions only read CQ status counters or webhook errors and don't require real nodes.

### E2e (in `test/e2e/singlecluster/baseline/hierarchical_cohort_test.go`)

| # | Scenario | What It Validates |
|---|----------|-------------------|
| T1 | Basic Hierarchical Borrowing | CQ with 0 nominal quota borrows through a parent Cohort CRD hierarchy. Smoke test proving CRD install, webhooks, and borrowing on a real cluster. |

### Integration (in `test/integration/singlecluster/scheduler/scheduler_test.go`)

| # | Scenario | What It Validates |
|---|----------|-------------------|
| T2 | Reparenting | Updating `parentName` dynamically changes which subtree a CQ can borrow from |
| T3 | Delete Mid-Tree Cohort | Admitted workloads survive mid-tree deletion; new borrowing is blocked |
| T5 | Hierarchical LendingLimit | `lendingLimit` on a Cohort caps sibling borrowing (webhook validation already covered in `cohort_test.go:173`) |
| T6 | Hierarchical BorrowingLimit | `borrowingLimit: 0` enforces one-directional borrowing (webhook validation already covered in `cohort_test.go:153`) |
| T7 | Isolated Orgs + Burst Queue | Isolated orgs with shared root-level burst CQ (KEP-79 Story 2) |

### Blocked on #13553

| # | Scenario | What It Validates |
|---|----------|-------------------|
| T4 | Cycle Detection | Mutual parent cycle halts admissions. Blocked on #13553 (controller panic on cohort cycles). Will be added as integration test after the fix lands. |

**Why is this needed:**

These scenarios cover hierarchical cohort scheduling behavior that has no dedicated test coverage today. T1 stays as e2e to prove the full stack works on a real cluster. The remaining scenarios move to integration tests to minimize CI cost while still validating scheduler logic.
