## Description

**What would you like to be added**:
Support for using the MultiKueue manager as a true central scheduler across all worker clusters. 

In this model, each worker cluster acts purely as a compute pool with a single, massive quota per resource flavor. All admission, preemption, and fair-sharing decisions happen exclusively in the central manager cluster. All project and team-specific quotas are defined and managed only on the manager.

<img width="3044" height="1204" alt="Image" src="https://github.com/user-attachments/assets/5cbf802a-2272-4153-8f98-cac9c49e9c87" />

**Why is this needed**:
Currently, MultiKueue delegates final scheduling decisions to the worker clusters. While this works well for many setups, it can make it difficult to achieve strict global fair sharing and cross-cluster preemption across an entire fleet.

Allowing the central manager to make these decisions would help organizations that manage compute capacity across multiple regions or clouds to better optimize their resources. It would also significantly simplify cluster administration by consolidating team quota management into a single control plane, rather than needing to manage quotas for teams/projects across every worker cluster.
