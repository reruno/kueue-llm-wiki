## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

I would like to support a strategy when the priority boost is effective.
I am considering the following approache:

The workload can have only one boost value parameter, but external systems (e.g., priority-booster) can specify when the priority is boosted.
The `.spec.priorityBoost.whenCanBoost: PreempteeWithinClusterQueue` indicates that the priority will be boosted with `.spec.priorityBoost.value` value.

```yaml
apiVersion: kueue.x-k8s.io/v1beta2
kind: Workload
metadata:
  name: sample
  namespace: example
spec:
  priorityBoost:
    value: 100
    whenCanBoost: Always | PreempteeWithinClusterQueue
  ...
```

**Why is this needed**:

In some scenario, I want to boost priority only when the preemptee Workloads (victims) are the same ClusterQueue so that the boost mechanism can avoid preempting other project quotas.
