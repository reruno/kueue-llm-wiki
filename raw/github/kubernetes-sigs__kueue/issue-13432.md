### Comment by [@Vaishnav88sk](https://github.com/Vaishnav88sk) — 2026-07-24T07:47:01Z

Makes sense. Extending `QueuesSet` in the generator framework to support a configurable `LocalQueuesCount` per `ClusterQueue` shouldn't be too invasive. We can likely handle the workload distribution by just allocating them round-robin across the generated LQs for each CQ to ensure they all actively compete.

The proposed scale (10 LQs per CQ, 10 CQs per cohort, 2 cohorts) sounds like a solid starting point to expose any FairSharing calculation overhead. We can definitely start there for the prototype and iterate on the exact topology depth/scale once we see the initial benchmark numbers.
