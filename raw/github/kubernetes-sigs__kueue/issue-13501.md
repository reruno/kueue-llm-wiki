## Description

## Summary

Harden the release-tag replacement flow so transient GitHub API/auth/network failures and failed tag updates cannot leave an existing draft release without its tag.

## Required changes

- In `.github/actions/create-release-tag/action.yml`, distinguish a confirmed “release not found” response from other failures returned by `gh release view`.
- Abort on authentication, authorization, API, or network lookup failures instead of treating them as a missing release.
- Preserve an existing remote tag until the replacement annotated tag has been created successfully locally.
- Replace the remote ref using a guarded update (for example, `--force-with-lease`) rather than deleting the remote tag before the replacement is ready.
- Retain clear issue-comment error reporting for failed operations.

## Rationale

The current replacement flow may interpret a failed release lookup as absence and remove an existing remote tag. If local tag creation or pushing then fails, a draft release can be left untagged.

## Affected area

- `.github/actions/create-release-tag/action.yml`

## Acceptance criteria

- Only a confirmed not-found response permits the “no release” path.
- Non-not-found release lookup failures stop the action without modifying local or remote tags.
- A failed local tag creation leaves the remote tag unchanged.
- A failed remote update leaves the existing remote tag protected by guarded replacement semantics.
- The action continues to report actionable failures to the configured GitHub issue.
