## Description

**What would you like to be cleaned up:**

The ClusterQueue heap comparator and the lock-free Snapshot sort now use two different sources for a LocalQueue's fair-sharing weight:

- The heap path (`queueOrderingFunc`) reads the cached weights (`c.lqWeights`), populated and kept in sync through the LocalQueue Add/Update/Delete hooks. It never performs an API read. This was introduced in #13476.
- The Snapshot path (`buildSnapshotSort`) still resolves the weight per sort by calling `afs.ResolveLQWeight`, which performs a LocalQueue `client.Get`, and falls back to base ordering for the whole snapshot on error.

Having two weight-lookup paths means the heap ordering and the pending-workload visibility snapshot can quietly diverge on weight source and fallback behavior. Ideally the Snapshot sort should read from the same cached weights as the heap.

**Why is this needed:**

Keeping a single source of truth for LocalQueue weights avoids the two paths drifting apart (for example if the cache semantics or the default-weight fallback change on one side but not the other), and removes a fresh set of LocalQueue reads each time a snapshot is built.

**Constraint to be careful about:**

`Snapshot()` sorts after releasing `c.rwm`, so `buildSnapshotSort` cannot read `c.lqWeights` directly during the sort. Reading the shared map without the lock would reintroduce the same mid-sort consistency issue that #12740 fixed for the sticky workload. The weights would need to be copied under the same RLock that collects the elements, and that copy passed into the comparator (the same pattern `buildSnapshotSort` already uses to pre-compute per-LocalQueue usage into `usageCache`).

**Additional context:**

Follow-up from the review of #13476 (the heap-comparator weight-caching fix). See https://github.com/kubernetes-sigs/kueue/pull/PRNUMBER for the reviewer discussion (apullo777's `buildSnapshotSort` comment).

Relevant code:
- `pkg/cache/queue/cluster_queue.go` `buildSnapshotSort` (the `getLQWeight` closure that calls `afs.ResolveLQWeight`)
- `pkg/cache/queue/cluster_queue.go` `queueOrderingFunc` (the cached-weight getter over `c.lqWeights`)
