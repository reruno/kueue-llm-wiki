## Description

## Summary

Release ChatOps can fail without recording the failure in the release issue when a release branch/tag is absent and the workflow cannot locate the local `report-result` action.

## Reproduction

1. Create a new release issue.
2. Run `/sync-release-notes`.
3. Run `/tag-release`.

Observed errors include:

- `A branch or tag with the name 'release-0.20' could not be found`
- `Can't find 'action.yml', 'action.yaml' or 'Dockerfile' under '.../.automation/.github/actions/report-result'`

## Required changes

Ensure the release automation reports these failures to the release issue rather than failing silently. In particular, verify the checkout/action path used by the release workflow and ensure missing release branch/tag errors are captured and passed through the release-result reporting mechanism.

## Affected areas

- Release ChatOps workflows, including the `/sync-release-notes` and `/tag-release` paths
- Checkout/workspace setup for local GitHub Actions used by release automation
- `.github/actions/report-result` invocation and failure reporting

## Acceptance criteria

- The reproduction above produces a visible, actionable failure entry on the release issue.
- A missing release branch or tag is reported with its error details.
- The release workflow can resolve the local `report-result` action from its checkout/workspace, or reports a clear setup failure if that is impossible.
- The original release command exit status remains non-zero on failure.
