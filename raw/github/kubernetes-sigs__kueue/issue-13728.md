## Description

As I'm working on was related tasks, it is really difficult to build features based on kube main if we are importing 1.36 apis.

The main problem is that 1.37 has v1beta1 apis for scheduling apis while 1.36 still has alpha APIs.

For #13306, we are going to need to rely on stable APIs for Job API and other controllers. 
I suggest that we test WAS against stable k8s versions. For 1.36 we can at least pilot some ideas like WASPodGroups or Bring your own PodGroups but we would have to use 1.36 apis for now. 

If we really need a lane for building on main, we can continue to support that but its difficult to write code against this as we have to fix the imports to match kube main.

**Proposal**

- WAS lanes for each k8s version
  - 1.36 kind 
  - 1.37 kind (main for now)

Validating features like Gang Jobs or Bring your own PodGroup would need to slightly differ based on the k8s versions for now.
