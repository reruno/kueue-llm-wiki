## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:
Topology Aware Scheduling (TAS) in Kueue currently optimizes for maximum workload density to improve communication throughput and minimize latency. While beneficial for ML training workloads, this dense packing is problematic for user-facing (inference) workloads where high availability is critical – concentrating all pods in a single topological domain means a localized failure can take down the entire service. 

This enhancement adds **Topology Spreading** to Kueue: the ability to distribute workloads across domains (zones, racks, TPU partitions, etc.) to achieve availability goals, while still applying bin-packing within those constraints to avoid unnecessary fragmentation.

**Why is this needed**:
Mixed training/inference deployments on shared Kueue infrastructure require availability guarantees that dense packing cannot provide. Without spreading, a single zone or rack failure can take down an entire inference service. This feature enables operators to express HA constraints at the Kueue level so they are enforced during admission, without requiring per-pod `topologySpreadConstraints` that do not understand Kueue's workload model.
