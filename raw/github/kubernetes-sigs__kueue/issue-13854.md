## Description

**What would you like to be added**:

Gaps in user-facing scheduling visibility remain after [KEP-10852](https://github.com/kubernetes-sigs/kueue/pull/11720), which added structured reason codes for pending workloads (v0.19). This issue tracks what's still missing:

1. **Quota context for non-admin users.** `batch-user` can see usage (`LocalQueue.status.flavorUsage`) but not limits — those live on ClusterQueue spec (`batch-admin` only). #3122 added `LocalQueueFlavorStatus` for this, dropped in #6777 without a committed successor, leaving non-admin users without namespace-scoped quota visibility.

2. **Wait-time signal.** Visibility API gives queue position but not estimated wait time. Tracked in #13159.

3. **Pre-submission feasibility.** Per-flavor `FlavorAssignmentAttempts` exist in the assignment and are surfaced via KEP-10852 metrics post-submission, but there is no pre-submission dry-run surface that exposes them before a workload is created.

4. **Fair sharing transparency.** LQ `weightedShare` is dead code for AdmissionFairSharing (#11279). The AFS-derived share used by `queueOrderingFunc` for cross-LQ ordering is not surfaced on LQ status — users see `consumedResources` but not the score that determines admission order.

**Why is this needed**:

Users see "Pending" with a reason code but no numbers to understand the gap or timeline. Related issues:

- #3122, #6777, #12282, #7538 — quota/capacity visibility
- #13159, #9980, #754 — wait-time and queue depth
- #11843, #11842, #13283 — granular pending reasons
- #10897, #11279 — fair sharing visibility
- #10614 — MultiKueue ordering

Does not duplicate: #11279 (LQ weightedShare gap), #11843 (pending reason labels), #13283 (scheduler-library reasons), #13159 (wait-time estimation), or #10553 (visibility server architecture). This umbrella coordinates across those efforts.

**Completion requirements**:

- [ ] **Quota context** — namespace-scoped quota visibility without CQ read access. Approaches: extend VisibilityOnDemand, CRD-request pattern (cf. KEP-5677), or `kueuectl`. Replaces #3122/#6777 gap.
- [ ] **Wait-time estimation** — #13159.
- [ ] **Feasibility query** — pre-submission dry-run exposing admission evaluation on-demand.
- [ ] **Fair sharing transparency** — expose AFS-derived scores. Related: #10897, #11279.

Notes:
- Builds on [KEP-10852](https://github.com/kubernetes-sigs/kueue/pull/11720), does not replace it
- Does not re-add fields to LQ status (#6777)
- Should align with #10553 on visibility server architecture
- Borrowing/autoscaling make static numbers misleading — data should be point-in-time

I mean before the user creates the Workload. A dry-run check answering "if I submit this resource request to this LocalQueue, would it be admitted right now, and if not, what's blocking it?" Today users can only discover this by creating the workload and waiting for the scheduler to evaluate it.

I was referring to the QuotaReserved condition reason, not the metric label. Agreed that KEP-10852's updated reason set is a significant improvement, and good to know #13063 enables it by default in the next patch. This umbrella builds on that foundation. The remaining gap is that while the condition message includes partial quota numbers (e.g., "X more needed"), there's no structured, machine-parseable quota data (total, used, remaining per resource) that dashboards or tooling can consume without parsing free-text strings.
