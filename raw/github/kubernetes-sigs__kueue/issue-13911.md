## Description

### Problem Description

Currently, `workload.AdjustResources` performs individual API client lookups (`cl.Get`) to fetch `RuntimeClass` objects when calculating pod overhead.

Following the `LimitRanges` caching pattern from #13681, `RuntimeClasses` should also be cached in the queue manager using event handlers and passed into `AdjustResources` to eliminate redundant API server calls.

### Proposed Solution

1. Add a thread-safe `RuntimeClasses` cache store in `pkg/cache/queue/runtime_classes.go`.
2. Expose `RuntimeClassCache()` on `queue.Manager`.
3. Update `workload_controller` event handlers (`resourceUpdatesHandler`) to watch and cache `RuntimeClass` objects.
4. Pass cached `RuntimeClass` objects to `workload.AdjustResources`.
