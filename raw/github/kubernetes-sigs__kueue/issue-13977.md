**What would you like to be cleaned**:

I'd like to add a KEP for the Sticky ClusterQueue Head Policy mechanism while implementations have already been released in a few releases ago.

**Why is this needed**:

Previously, we implemented its mechanism as part of https://github.com/kubernetes-sigs/kueue/pull/7157 w/o KEP process. Initially, it was a small improvement, but today it is our BestEffortFIFO scheduling foundation and are grown. Preserving its technical document allows us to keep its mechanism safty (e.g., compatibility with the coming new features) and bring light the oversight.
