## Description

**What happened**:

When a ClusterQueue references a Cohort whose parent hierarchy contains a cycle, the scheduler cache rejects the hierarchy for scheduling but the ClusterQueue `Active` condition does not report the cycle. Depending on event ordering and version, the condition can still report `Ready` and "Can admit new workloads" even though the ClusterQueue is excluded from scheduler snapshots.

PR #13571 prevents the related controller panic and restores scheduler-cache state after the cycle is repaired, but intentionally does not change ClusterQueue readiness reporting.

**What you expected to happen**:

The ClusterQueue should report `Active=False` with a clear reason and message while its Cohort hierarchy has a cycle. The condition should refresh both when a cycle is introduced and when it is repaired.

**How to reproduce it (as minimally and precisely as possible)**:

1. Create a Cohort whose `spec.parentName` points to itself, or create two Cohorts whose parents point to each other.
2. Create a ClusterQueue that references one of the cyclic Cohorts.
3. Inspect the ClusterQueue `Active` condition.
4. Repair the Cohort parent edge and inspect the condition again.

**Anything else we need to know?**:

This is the secondary status-reporting issue described in #13553. A complete fix needs to refresh affected ClusterQueue status when a Cohort cycle is introduced or repaired; it should not be implemented only as a local readiness check that lacks the required reconciliation events.

I think #13774 fixed this. I tried the repro on main (eb8fd70bb) with a Kueue manager and a real apiserver:

```
cycle (self -> self, and a <-> b):
  cq-self  Active=False CohortCycleDetected: Can't admit new workloads: Cohort "self" has a cycle in hierarchy.
  cq-ab    Active=False CohortCycleDetected: Can't admit new workloads: Cohort "a" has a cycle in hierarchy.
after removing the parent edges:
  cq-self  Active=True Ready: Can admit new workloads
  cq-ab    Active=True Ready: Can admit new workloads
cycle a <-> b again, then repaired again:
  cq-ab    Active=False CohortCycleDetected ... -> Active=True Ready
```

The condition updates both when the cycle shows up and when it's fixed. @YQ-Wang ok to close, or is there a case I'm missing?
