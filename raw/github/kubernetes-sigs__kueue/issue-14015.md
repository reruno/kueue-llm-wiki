## Description

**What happened**:

A non-negative transformation factor does not make the contribution non-negative. Transformations multiply what the PodSet requested, so a negative request produces a negative output, and that subtracts from whatever else lands on the same key.

```yaml
resources:
  transformations:
  - input: example.com/real-gpu
    strategy: Replace
    outputs:
      example.com/gpu-quota: "1"
  - input: example.com/credit
    strategy: Replace
    outputs:
      example.com/gpu-quota: "1"
```

Both factors are `1`. A PodSet asking for `example.com/real-gpu: 8` and `example.com/credit: -3` is charged:

```
example.com/gpu-quota = 5
```

`FloorToZero` runs afterwards and sees a positive total, so nothing reports it. The same applies to a negative `multiplyBy` operand, which flips the sign of every output the transformation produces.

**What you expected to happen**:

A charge of 8, or a refusal. Not 8 quietly becoming 5.

**How to reproduce it (as minimally and precisely as possible)**:

The configuration above, through `NewInfo`. Measured: `gpu-quota = 5`.

**Anything else we need to know?**:

Not the same as #13985. A negative factor there is deliberate, the way a per-unit allowance is written, and #13986 keeps it working while stopping the total it generates from being spent outside those outputs. Here the operator's configuration is entirely non-negative and the sign comes from the Workload, so the allowance is one the operator never wrote and #13986 does not reach it: the two contributions are both outputs, they cancel where outputs are meant to, and the result stays positive.

Not the same as #13991 either, which is `spec.overhead` rather than a container request, and not #13990, which is the map walk deciding which of two contributions survives. This one is deterministic and both contributions arrive.

`WorkloadValidateResourcesAreNonNegative` refuses a negative container request at the webhook, so what is left is a Workload created before that gate existed, one created while it was disabled, or one arriving through a path that does not go past the webhook. The gate is Beta and can be turned off, so a premise that rests on it is a premise an administrator can remove.

Refusing the operand where the merge happens covers all of those, and is what KEP-2941 asks for on the resources a `firstAvailable` envelope is charged on.

/kind bug
