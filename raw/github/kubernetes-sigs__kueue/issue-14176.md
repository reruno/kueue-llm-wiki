## Description

**What would you like to be cleaned**:

Context: This is a part of #13149.
Kueue already delegates node-pod matching to WAS scheduling library (since #13261, behind the `SchedulerLibraryIntegration` FG).

Yet, some bits of node-filtering logic remain undelegated, even under this FG:

1. General node health checks, like [here](https://github.com/kubernetes-sigs/kueue/blob/3368db7956cf419c6e0fc55a58271441241d458a/pkg/cache/scheduler/tas_nodes_cache.go#L40-L41)
2. Restricting to a flavor, [here](https://github.com/kubernetes-sigs/kueue/blob/156bbffa82c3a1851e68be5bd6739a2b7cf0ac92/pkg/cache/scheduler/tas_nodes_cache.go#L63-L73)

**Why is this needed**:

Ideally, when integrated with WAS, Kueue should not deal with node filtering at all.
All this logic should be delegated to WAS. Specifically:

* For # 1: just remove those checks; WAS will handle them on its side.
* For # 2: the concept of "flavor" is Kueue-specific, so it can't be delegated.
  Moreover, restrict nodes by flavor might be beneficial for performance. (Yet, we shouldn't do it too early; cf. #13723).
  However, matching be flavor should be expressed by a NodeSelector, passed down to the WAS library.
  Kueue should not match a selector against nodes on its own.

**Caveat:** the Kueue-side filtering should **stay** as long as the `SchedulerLibraryIntegration` FG is disabled.
