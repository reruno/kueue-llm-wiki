## Description

**What happened**:

The StatefulSet reconcile looks the Workload name up and lists the Pods before it starts either branch:

```go
wlName, err := findWorkloadName(ctx, r.client, sts)
if err != nil {
	return ctrl.Result{}, err
}

podList := &corev1.PodList{}
if err := r.client.List(ctx, podList, client.InNamespace(req.Namespace), client.MatchingFields{
	podcontroller.PodGroupNameCacheKey: wlName,
	...
}); err != nil {
	return ctrl.Result{}, err
}
```

Both are there for the Pods. `wlName` is the field-selector key the list is built from, and `podList` is what the queue-label sync and the finalization walk. `reconcileWorkload` takes only the StatefulSet, and resolves the name again for itself:

```go
func (r *Reconciler) reconcileWorkload(ctx context.Context, sts *appsv1.StatefulSet) error {
	...
	wlName, err := findWorkloadName(ctx, r.client, sts)
```

So a Pod list that fails, or a name lookup that fails, returns before the Workload is looked at, even though neither result reaches the Workload path. This is the shape #14013 reported for the queue-label patch, and #14117 moves that patch onto the Pod branch. These two steps are still in front of both branches.

**What you expected to happen**:

A failure that belongs to the Pods leaves the Workload alone. Creating or updating the Workload does not need the Pod list, so a transient list error should not hold it back any more than a Pod patch does.

**How to reproduce it (as minimally and precisely as possible)**:

A StatefulSet with a queue name and no Workload yet, and a client whose `List` fails for Pods. The reconcile returns that error and no Workload is created, though `reconcileWorkload` would have created one from the StatefulSet alone.

**Anything else we need to know?**:

The fix looks like moving both steps into the Pod branch, so the branch owns everything it needs and the Workload branch starts from the StatefulSet:

```go
eg.Go(func() error {
	wlName, err := findWorkloadName(ctx, r.client, sts)
	if err != nil {
		return err
	}
	podList := &corev1.PodList{}
	if err := r.client.List(ctx, podList, ...); err != nil {
		return err
	}
	if err := r.syncQueueLabel(ctx, sts, podList.Items); err != nil {
		return err
	}
	return r.finalizePods(ctx, sts, podList.Items)
})
```

That does mean two `findWorkloadName` calls per reconcile, one per branch, where there is one today. They are cache reads and the second already happens, so the cost is one more cached Get on the Pod side.

I left this out of #14117 deliberately, to keep that change to the failure #14013 reported. Filing it so the remaining half is written down rather than assumed. Happy to send the patch.

The same reconcile has a related thing worth a separate look: both branches receive the same `*appsv1.StatefulSet`. That is safe while `reconcileWorkload` only reads it, which it does today, but #13675 adds a `syncReplicas` that writes `sts.Spec.Replicas` from inside `reconcileWorkload`, and `syncQueueLabel` reads that same field.

I would still like your view on the consequence. `syncQueueLabel` returns at its first line when `replicas` is 0, so at zero replicas the list is the last step before the two branches, and the Workload branch is where `releaseScaleDownReservation` runs. A failure there keeps the quota reservation on a StatefulSet that has no Pods to run. Nothing else releases it.

On #14361 you raised the opposite risk, that we create a Workload and hold quota while the Pods stay gated. Holding quota at zero replicas looks heavier to me. I may be weighing it wrong.

// branch. The Pod list in front of both branches is there for the Pod branch,

func TestReconcileReleasesTheReservationWhenScaledToZero(t *testing.T) {
	errListPods := errors.New("listing pods")

	cases := map[string]struct {
		listFails bool
		wantErr   error
		wantHeld  bool
	}{
		"the reservation is released": {},
		"a failing pod list holds the reservation": {
			listFails: true,
			wantErr:   errListPods,
			wantHeld:  true,
		},
	}

	for name, tc := range cases {
		t.Run(name, func(t *testing.T) {
			ctx, _ := utiltesting.ContextWithLog(t)

			sts := statefulsettesting.MakeStatefulSet("sts", "ns").
				UID("sts-uid").
				Replicas(0).
				Queue("lq").
				Obj()
			wl := utiltestingapi.MakeWorkload(GetWorkloadName("sts-uid", "sts"), "ns").

					Type:   kueue.WorkloadQuotaReserved,
					Status: metav1.ConditionTrue,
					Reason: "Admitted",
				}).
				Obj()

			clientBuilder := utiltesting.NewClientBuilder().
				WithObjects(sts, wl).
				WithStatusSubresource(sts, wl)
			if tc.listFails {
				clientBuilder = clientBuilder.WithInterceptorFuncs(interceptor.Funcs{
					List: func(ctx context.Context, c client.WithWatch, list client.ObjectList, opts ...client.ListOption) error {
						if _, isPods := list.(*corev1.PodList); isPods {
							return errListPods
						}
						return c.List(ctx, list, opts...)
					},
				})
			}
			indexer := utiltesting.AsIndexer(clientBuilder)
			if err := indexer.IndexField(ctx, &corev1.Pod{}, podcontroller.PodGroupNameCacheKey, podcontroller.IndexPodGroupName); err != nil {

			}
			cl := clientBuilder.Build()

			reconciler, err := NewReconciler(ctx, cl, indexer, &utiltesting.EventRecorder{})
			if err != nil {
				t.Fatalf("Creating the reconciler: %v", err)
			}

			_, err = reconciler.Reconcile(ctx, reconcile.Request{NamespacedName: client.ObjectKeyFromObject(sts)})

			if held != tc.wantHeld {
				t.Errorf("quota reservation still held = %v, want %v", held, tc.wantHeld)
			}
		})
	}
