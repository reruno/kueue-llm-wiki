## Description

**What would you like to be added**:

Explore routing **manager-driven elastic `RayCluster` resize** through the same
`worker→manager` **reverse elastic sync** path proposed by KEP-13243
(#13494 / area/elastic-jobs), instead of the current separate `manager→worker`
admit-first path (`ElasticReplicaSync` in
`pkg/controller/jobs/ray/ray_multikueue_adapter.go`).

Today there are two parallel manager↔worker replica mechanisms in the shared Ray
adapter:

- **Manager-driven (autoscaling off)** — `ElasticReplicaSync`: a manager-side
  replica edit creates a new workload slice, is **admitted on the manager first**,
  and only then is the new size forwarded to the worker `RayCluster`
  (`syncElastic` / `needElasticSync`).
- **Worker-driven (autoscaling on)** — the reverse elastic sync from KEP-13243:
  the worker Ray autoscaler resizes the worker `RayCluster`, and the change is
  reflected back onto the manager (as annotations) where workload-slicing
  re-reserves quota, then the admitted slice is repointed.

The proposal is to let a **manual** manager-side resize reuse the reverse-sync
downstream, so the two collapse into one mechanism:

```
manager edits RayCluster replicas
  → patch the worker RayCluster directly (do NOT admit first)
  → KubeRay creates the new Pods, which Kueue keeps scheduling-gated (zero usage)
  → reverse sync reflects the worker counts onto the manager → new workload slice
  → the new slice is admitted on the manager (quota gate happens here)
  → the admitted slice is repointed onto the worker RayCluster → Pods are ungated
```

From step 2 onward this is **identical to the autoscaler flow**, so the
manager-driven `ElasticReplicaSync` forward path could potentially be removed and
manual + autoscaled resizes served by a single reverse-sync hook.

**Why it is feasible (quota safety is preserved):**

The initial concern is that patching the worker `RayCluster` before manager
admission would let the worker consume resources before Kueue grants quota. It
does not: the Pods KubeRay creates are **held by Kueue's scheduling gate** and
consume nothing until ungated, and ungating is driven by admission of the new
workload slice on the manager. So "patch worker first" moves the quota gate from
*before the spec is forwarded* to *before the Pods are ungated* — the gate itself
is never bypassed. This works with autoscaling **off** (single writer, no
manager/autoscaler write-write race).

**Tradeoffs / open questions (why this is a design choice, not an obvious win):**

- **Not a latency win — a code-unification win.** The worker-first flow adds
  round-trips (manager→worker→manager→worker) versus admit-first (admit→worker).
  The manual path is not latency-sensitive, so the benefit is a single shared
  downstream mechanism, not speed.
- **Reverse sync is gated behind `AutoscalingEnabled` in KEP-13243.** Serving the
  autoscaling-**off** manual case would require running the reverse direction
  unconditionally (or under a broader predicate).
- **Source of truth: spec vs. annotation.** KEP-13243 reflects worker counts onto
  the manager **as annotations, leaving the manager spec untouched**. A manual
  edit, by definition, writes the manager **spec**. The design must define which
  drives PodSet derivation and keep spec and annotation consistent. The webhook
  "pin + revert manager edits" trick used under autoscaling does not apply here
  because the manager is the legitimate writer.
- **Messier quota-starvation intermediate state.** Admit-first leaves the worker
  untouched and the workload cleanly pending when quota is unavailable.
  Worker-first leaves the worker `RayCluster` already at the target size with
  Pods gated until quota frees. This is safe (zero usage) but is the same
  partially-gated state the autoscaler would produce, so its handling can be
  shared with KEP-13243's handover/`OutOfSync` semantics.

Related work: `RemoteSpecSyncer` forward hook (#14036, merged; RayService
`serveConfigV2`), which is the other manager→worker spec-sync case and could share
a generalized `NeedsSync/Apply` "remote mutator" abstraction; KEP-13243 reverse
elastic sync (#13494).
