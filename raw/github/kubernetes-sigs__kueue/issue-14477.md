## Description

**What would you like to be added**:

Make the number of Workloads popped per ClusterQueue per scheduling cycle configurable, defaulting to 1 for compatibility. Today `Manager.heads()` pops exactly one:

```go
for cqName, cq := range m.hm.ClusterQueues() {
    wl := cq.Pop()   // singular
```

(`pkg/cache/queue/manager.go`, unchanged through v0.20-devel.)

Ideally exposed via the Scheduler Configuration API proposed in #14190 rather than a feature gate.

**Why is this needed**:

A queue's drain rate is capped at one admission per cycle regardless of available quota, so wait time scales with queue depth instead of contention.

Measured on a production GPU cluster (~1,300 nodes, v0.18.x, Fair Sharing + TAS):

| Metric | Value |
|---|---|
| Scheduling cycles | ~25/min |
| Admit rate per pop | 38% (600 admitted / 970 skipped over 65 min) |
| Effective throughput | ~9.6 admissions/min |
| Queue depth | 536 |
| Predicted wait | ~56 min |
| Measured p50 | 64 min (p90 78, n=1,156) |

Shallow queues on the same cluster admit at p50 12s. One traced Workload logged 43 scheduler events at creation, then zero for 55 minutes, then admitted with `wait time since queued was 3466s` — never rejected, evicted, or inadmissible. It simply was not popped.

Caveat: ~62% of pops already fail (`overlapping preemption targets with another workload`, `Workload no longer fits after processing another workload`). Raising the batch size alone could multiply recompute cost — see #14157.

Related: #14190, #14090 (one slot per CQ drops second-pass Workloads), #14157, #13884.
