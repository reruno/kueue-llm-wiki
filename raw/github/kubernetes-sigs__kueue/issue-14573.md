## Description

**What happened**:

When a ResourceClaimTemplate uses a CEL device selector, Kueue's
`validateCELSelectorsAgainstDevices` flattens all listed ResourceSlices without
filtering by the highest pool generation or checking whether the pool is complete.

During a ResourceSlice pool update, an old-generation device and a device from an
incomplete newer generation can therefore be counted together. Kueue may return
device quota even though the upstream DRA allocator skips the incomplete pool.

**What you expected to happen**:

Kueue should use the same ResourceSlice semantics as DRA allocation: only devices
from the highest generation should be considered, and an incomplete pool should
cause the workload to wait or be retried rather than pass availability validation.

**How to reproduce it (as minimally and precisely as possible)**:

1. Create a ResourceClaimTemplate requesting two devices from the same DeviceClass
   with a CEL selector.
2. Publish one matching ResourceSlice for generation 1.
3. Start updating the pool to generation 2 with `resourceSliceCount: 2`, but make
   only one generation-2 slice visible.
4. Submit a Workload referencing the ResourceClaimTemplate.

A minimal reproduction using the current source returns:

```text
resources=map[main:map[gpu:{{2 0} {<nil>} 2 DecimalSI}]] errors=[]
```

The old generation and incomplete new generation are counted together. The upstream
DRA allocator does not allocate from incomplete pools.

Relevant code:

- `pkg/dra/claims.go`: `validateCELSelectorsAgainstDevices`
- `pkg/dra/counters.go`: latest-generation and complete-pool filtering
- Kubernetes ResourceSlice API documentation requires consumers to use the highest
  generation and detect incomplete pools.

**Anything else we need to know?**:

The current code comment says this validation prevents workloads that cannot be
scheduled from entering the scheduling heap. The reproduced behavior violates
that intended guarantee.

The existing `go test ./pkg/dra` tests pass, but there is no regression test covering
stale or incomplete ResourceSlice pools.

AI assistance was used for source inspection and reproduction research. The report
and all technical claims were reviewed against the Kueue source and local Kubernetes
dependencies.
