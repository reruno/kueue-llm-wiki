**What happened**:
I have a Statefulset that mounts persistent volumes to its pods. I added Kueue labels to the podtemplate to start managing the pods with Kueue. The relevant ClusterQueue has quota for a ResourceFlavor with a Topology. When the StatefulSet starts rolling out the changes to the podtemplates, newly created pods are  unschedulable because TAS assigned a node via nodeSelector that does not match the node where the persistent volume is bound.

It seems to be a general problem that TAS does not consider bound volumes for node assignment.

**What you expected to happen**:
TAS assigns the node where the persistent volume is bound.

**How to reproduce it (as minimally and precisely as possible)**:
1. Create ResourceFlavor with topology that uses host as lowest level, ClusterQueue with quota in that flavor and a LocalQueue
2. Create a StatefulSet with 1 replica that is not managed by Kueue and that mounts a rwo persistent volume via volumeClaimTemplate.
3. Apply this patch to the StatefulSet:
```
spec:
  template:
    metadata:
      labels:
        kueue.x-k8s.io/queue-name: <name of local queue>
```
