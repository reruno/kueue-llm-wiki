## Description

## Summary

Add regression assertions for the `admission.Warnings` value returned by webhook `ValidateCreate` and `ValidateUpdate` test calls that currently discard that return value.

## Rationale

Each of the nine scoped webhook methods returns nil warnings on every path today. The assertions protect this behavior from regressions. This is not missing warning behavior.

`PodWebhook.ValidateCreate` and `PodWebhook.ValidateUpdate` are excluded. They can emit warnings through `warningForPodManagedLabel`, and their warnings are already asserted.

## Scope

Update these test call sites to capture warnings and assert `admission.Warnings(nil)`, while preserving the existing error assertions:

### `ValidateCreate` in integrations updated by #14688

- `pkg/controller/jobs/raycluster/raycluster_webhook_test.go:601`
- `pkg/controller/jobs/rayjob/rayjob_webhook_test.go:626`
- `pkg/controller/jobs/rayservice/rayservice_webhook_test.go:142`
- `pkg/controller/jobs/sparkapplication/sparkapplication_webhook_test.go:111`

### `ValidateCreate` in other integrations

- `pkg/controller/jobs/jobset/jobset_webhook_test.go:322`
- `pkg/controller/jobs/mpijob/mpijob_webhook_test.go:331`
- `pkg/controller/jobs/trainjob/trainjob_webhook_test.go:178`

### `ValidateUpdate` in other integrations

- `pkg/controller/jobs/leaderworkerset/leaderworkerset_webhook_test.go:1604`
- `pkg/controller/jobs/statefulset/statefulset_webhook_test.go:1065`

## Notes

- `leaderworkerset_webhook.go:172` and `statefulset_webhook.go:148` use named `warnings admission.Warnings` return values, but do not assign them. Both return `warnings, allErrs.ToAggregate()`. Their signatures suggest warning flow, but they currently return nil warnings.
- Do not add `ValidateDelete` coverage as part of this cleanup. There are no `ValidateDelete` test call sites. All 19 implementations currently return `nil, nil`, so that is separate absent coverage.

## Acceptance criteria

- All nine scoped tests capture the `admission.Warnings` result.
- All nine scoped tests assert `admission.Warnings(nil)`.
- Existing validation-error coverage remains intact.
- No webhook runtime behavior changes.
