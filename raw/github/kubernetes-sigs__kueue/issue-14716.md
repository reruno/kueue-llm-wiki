## Description

As we start having release planning, we realize that tracking KEP PRs leads to some challenges.

We need to track the overall graduation of a feature like we do in Kubernetes.

One suggestion is to have a tracking issue like we have in k/enhancements.

## Proposal

### Feature Tracking

Features should follow a template like we have in [k/enhancements](https://github.com/kubernetes/enhancements/blob/master/.github/ISSUE_TEMPLATE/enhancement.md). 

I think we should define one that we want to support. Some issues with the current Kubernetes enhancement is that issue modification is limited to people with write access. This comes up a lot in kubernetes when people transition roles and the issue is left abandoned. The only thing to do is having someelse copy the issue and work on it under their name.

One idea we floated around in sig-release is to move the PR tracking to an issue and leave the issue simple. So we could have just a motivation / description and then we link PRs to that issue. And we can add labels to track stage.

Work needed:

- Define an issue template for features
- For 0.20 features, we could create tracking issues (or reuse existing ones)
- Update board to track issues and link/comment on the KEP.

### Project Board

Features can be separated into stages (alpha, beta, stable). I expect Kueue will focus more on alpha and beta but it would be nice to have a simple way for folks to know what features they can help with.

We should also have a milestone tag (0.20) that we can filter for issues so we can find what features we want to target for each project.
