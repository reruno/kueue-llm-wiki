## Description

## Summary

Correct the comment in `pkg/metrics/metrics.go` for `RecordPodSchedulingGateRemovalSeconds`.

The comment currently says that `WorkloadAdmitted.LastTransitionTime` comes from the Kubernetes API server. The Kueue controller manager calculates this transition time. The comment must describe the actual timestamp source.

## Rationale

The metric still needs to clamp negative latency values to zero. A negative value can occur when the controller's current time is earlier than the recorded transition time, for example after a leader handoff or a wall-clock adjustment. The updated comment must explain this behavior without attributing `LastTransitionTime` to the API server.

## Affected area

- `pkg/metrics/metrics.go`
- `RecordPodSchedulingGateRemovalSeconds`

## Acceptance criteria

- The comment identifies the Kueue controller manager as the source of `WorkloadAdmitted.LastTransitionTime`.
- The comment accurately explains why latency can be negative.
- The code continues to clamp negative observations to zero.
