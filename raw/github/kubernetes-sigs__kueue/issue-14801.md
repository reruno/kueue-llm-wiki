## Description

## Summary

The core workload indexer does not handle an extended resource when the resource is specified only in a container's `Resources.Limits`.

`pkg/controller/core/indexer/indexer.go` currently obtains the extended-resource value from resource requests. Kubernetes resource handling can expose an extended resource through limits without an explicit request. This limits-only case must be indexed correctly.

## Required changes

- Update the extended-resource indexing logic to account for extended resources specified only in container limits.
- Preserve the existing request-based behavior.
- Add regression tests for a Workload that specifies an extended resource only in container limits.

## Rationale

A limits-only extended resource can be missed by the current indexer. The missed resource can cause incorrect workload selection or handling in code that relies on the extended-resource index.

## Affected area

- `pkg/controller/core/indexer/indexer.go`
- Core indexer tests

## Acceptance criteria

- The indexer recognizes an extended resource that exists only in `Resources.Limits`.
- Existing request-based indexing behavior remains unchanged.
- Regression tests cover the limits-only case.
