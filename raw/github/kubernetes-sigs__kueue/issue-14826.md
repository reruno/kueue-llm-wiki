## Description

**What would you like to be added**:

Track feedback and the graduation of `MultiKueueBatchJobClearingTTLSecondsAfterFinishedOnWorkerCluster` from Beta to GA.

PR #14734 introduces the gate as Beta and enabled by default on `main`. When enabled, MultiKueue clears `spec.ttlSecondsAfterFinished` when creating a remote batch Job so that the worker TTL controller cannot delete the Job before its terminal status is synchronized to the manager. Disabling the gate restores the previous propagation behavior as a compatibility escape hatch.

The planned backports to release-0.18 and release-0.19 should introduce the gate as Alpha and disabled by default. This issue follows the rollout discussed in https://github.com/kubernetes-sigs/kueue/pull/14734#discussion_r3857316538.

**Why is this needed**:

Before GA, we should collect operational feedback from both behaviors and determine whether users need a dedicated worker-side cleanup configuration. In particular, we should validate the trade-off between reliable terminal-status synchronization and cleanup of remote Jobs when a worker cluster is disconnected for an extended period.

**Completion requirements**:

- [x] Merge #14734 with the gate Beta and enabled by default on `main`.
- [x] Backport the change to release-0.18 with the gate Alpha and disabled by default: #14827.
- [x] Backport the change to release-0.19 with the gate Alpha and disabled by default: #14828.
- [ ] Collect feedback from users running with the gate enabled and disabled, including behavior during worker-cluster disconnection and reconnection.
