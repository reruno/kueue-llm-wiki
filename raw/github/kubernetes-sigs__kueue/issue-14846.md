**What happened**:
`validateQualifiedName` in `pkg/config/validation.go` (a port of [the upstream Kubernetes validation function](https://github.com/kubernetes/kubernetes/blob/f5ab85e7c9d716e8bc5cf467ba931d8e8123764f/pkg/apis/resource/validation/validation.go#L1342-L1373)) has an existing TODO noting the port is incomplete:

```
switch len(parts) {
case 1: ...
case 2: ...
// no default case
}
```

A qualified name is split on `/;` only `len(parts) == 1` and `len(parts) == 2` are handled. A name with more than one slash (e.g. `"a/b/c"`) matches neither case, so `allErrs` stays empty and the name is silently accepted as valid.

**Where this is reachable:**
The only current caller is `pkg/config/validation.go:638`, validating `DeviceClassMapping.Sources[].Capacity.Name` (the DRA `KueueDRAIntegrationConsumableCapacity` config path). A malformed capacity name with 2+ slashes in the Kueue Configuration file passes validation silently.

**Why the upstream "ratcheting" caution likely doesn't apply here:**
The TODO notes the fix "should be introduced carefully, possibly using ratcheting to avoid breaking existing, non-compliant objects" — but that concern was copied from the upstream context, where it validates a live Kubernetes CRD field against persisted cluster objects. This call site instead validates Kueue's own static `Configuration` file, re-validated fresh on every controller-manager startup — there's no persisted object to "grandfather in," so failing fast on an invalid config at startup is the correct, expected behavior rather than a breaking change to guard against.

**Proposed fix:**
Add a default: case to the switch, rejecting the value with a `field.Invalid` error (matching upstream's actual fixed message), since this specific caller doesn't need ratcheting.

**What you expected to happen**:
A qualified name with more than one slash should be rejected during config validation, the same way names with an empty domain or empty name segment already are.

**How to reproduce it (as minimally and precisely as possible)**:

1. Enable the `KueueDRAIntegrationConsumableCapacity` feature gate.
2. In Kueue's Configuration, add a `DeviceClassMapping` with a `sources[].capacity.name` containing more than one slash, e.g. `"a/b/c"`.
3. Start the controller-manager (or run the config validation directly).
4. Observe: no validation error is returned for the malformed name.

**Anything else we need to know?**:
Verified via static code reading (traced the switch statement and its single call site), not yet reproduced against a running cluster/controller-manager — happy to add a unit test alongside a fix if this is confirmed as intended behavior to change.
