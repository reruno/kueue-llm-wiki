Requires #14794
Follow up to #13702

**What would you like to be added**:
The current mechanizm of Pod to Workload matching is limited by requiring the pods to be annotated with the name of their workload.
This is especially problematic with custom job controllers - if a user does not consider adding the correct annotation to the pod template of a job, the pod will not be able to identify their WL in the current implementation of the SchedulerSimulator WAS integration.

We would like a more generic mechanizm implemented.
It would most likely have to be based around tracking and comparing workloads against Pod owners.

**Why is this needed**:
To ensure custom job controllers created by Kueue users allow using WAS simulation out-of-the-box.

**Completion requirements**:
The mechanism is implemented and tested.
