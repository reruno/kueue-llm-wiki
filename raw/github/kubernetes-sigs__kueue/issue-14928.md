## Description

## Summary

Refactor RayCluster test tables that use a boolean expected-error field so that they store an expected `error` value instead.

Start with `TestBuildPodSets` in `pkg/controller/jobs/raycluster/common_test.go`, where `wantErr bool` currently only checks whether an error exists.

## Rationale

An `error` field lets tests verify the expected error condition or message. This gives stronger coverage than a boolean error-presence check.

## Affected area

- `pkg/controller/jobs/raycluster/common_test.go`
- Other nearby RayCluster test tables that use the same `wantErr bool` pattern, if the refactor can be applied consistently.

## Acceptance criteria

- Replace applicable `wantErr bool` fields with an expected `error` field.
- Update assertions to distinguish success from an expected error.
- Preserve existing successful test coverage.
- Add error-content checks when a stable error contract exists.
