**What would you like to be cleaned**:

I would like to investigate the use of workload.Info store the effective resources used for scheduling in workload.Info instead.

**Why is this needed**:

1. AdjustResources is very error prone. It was a source of multiple bugs in the past, just to list a few:
 - https://github.com/kubernetes-sigs/kueue/pull/10158
 - https://github.com/kubernetes-sigs/kueue/pull/9939
 - https://github.com/kubernetes-sigs/kueue/pull/14433 (current)
(but probably many more)
2. It raises performance concerns because it requires deepCopy to ensure the adjusted resources are not preserved in the workload object
3. I think it makes other PRs more complex than needed otherwise, eg: https://github.com/kubernetes-sigs/kueue/pull/14958/changes#diff-a7490e7f5efa2a59ab508f592b67dd6e7530b9d2e1b19a1b6a7438e6c2386905R367-R368 (TBD)

### Comment by [@qiujiaro](https://github.com/qiujiaro) — 2026-09-01T08:21:58Z


### Resource consumers

| Category | Consumer | Required data | Current resource view |
|---|---|---|---|
| A | Extended-resource DRA | Container-level effective requests | `raw` or `adjusted`, depending on the call path |
| B | Validation | Container/PodSpec requests and limits | Reads `Info.Obj`, which may be `raw` or `adjusted` |
| C | `NewInfo` / `Info.Update` | PodSet-level aggregated resources | Usually receives an `adjusted` Workload in the seven identified paths |

### Call-stack categories


| Category | Call sites | Current issue |
|---|---|---|
| A(adjusted) + C(adjusted) | `RequeueWorkload`, `queueReconcileForPending` | ordering may therefore matter for correctness |
| A(raw) + C(adjusted) | `addLocalQueueLocked`, `Create`, `Update`, `deviceClassHandler.reconcileWorkloads` | DRA and `Info` may observe different requests |
| A(raw) → A(adjusted) + C(adjusted) | `Reconcile → NeedsDRAReconcile(raw) → handleDRA → AdjustResources → DRA processing → NewInfo` | Initial DRA detection and subsequent processing use different resource views |
| B(`Info.Obj`) | `Scheduler.nominate`, `getQueueBlocker` | Behavior depends on whether `Info.Obj` contains raw or adjusted resources |


### Possible migration changes

| Category | Change |
|---|---|
| A/DRA | Make functions that inspect container requests, such as `NeedsDRAReconcile` and `ResolveExtendedResourceQuota`, consume an explicit effective-resource view |
| B/Validation | Decide explicitly whether each validation path requires raw PodSpec data, effective resource data, or current external constraints such as LimitRange. |
| C/Info | Pass effective resources to `NewInfo`/`Info.Update`, for example through an `InfoOption` |

One possible unified data flow is:

```text
ComputeEffectiveResources(raw Workload)
├─ A: DRA
├─ B: Validation
└─ C: NewInfo/Info.Update
```

Under this design, `AdjustResources` can be removed after all relevant consumers use the same explicit resource view.
