## Description

**What would you like to be added**:

I'd like to propose a small regression check for Kueue's generated RBAC manifests.

`config/components/rbac/kustomization.yaml` notes that the RoleBinding and ClusterRoleBinding subjects must stay in sync with the controller ServiceAccount. I put that relationship into a 35-line IaC-Guard-V 0.1.0a10 contract and tested it against current main (`ea11d394bb70b303a4e08bef4fb79dc96dfefa79`).

The current manifests pass. All five bindings are found, and all 15 subject, `roleRef`, and scope checks return `SATISFIED`.

I also tried three local changes:

- removed a referenced Role
- removed the controller ServiceAccount
- changed a RoleBinding to use a `roleRef` with invalid scope

Each change returns `VIOLATED`.

The check only reads generated manifests. It does not connect to a cluster or use credentials. Installing the pinned package requires PyPI access, but contract verification itself runs offline.

Would maintainers be interested in a small PR that adds the contract and a read-only `verify-iac-contract` make target? I can leave the target optional at first or add it to `verify-checks`, depending on what the project prefers.

IaC-Guard-V 0.1.0a10: https://github.com/lokesh0186/iac-guard-v/releases/tag/v0.1.0-alpha.10

**Why is this needed**:

Kueue's existing tests cover rendering and specific RBAC fields. This would add one check that verifies all five bindings still resolve to the intended ServiceAccount and Role or ClusterRole. The current manifests pass, so this is a regression-prevention proposal rather than a report of a current bug.

**Completion requirements**:

If accepted, the PR would contain the contract and one read-only make target. It would not change an API.
