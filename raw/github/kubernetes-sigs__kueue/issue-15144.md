**What happened**:
 Kueue can correctly determine that a Workload is not admissible but fail to persist the corresponding QuotaReserved=False condition because the condition reason is empty. The scheduler generates the following diagnostic message.

 ```                                                                                                                                                                                                                
   couldn't assign flavors to pod set main: resource example.com/gpu unavailable in ClusterQueue                                                                                                                    
 ```                                                                                                                                                                                                                                                                                                                                                                                                                                 
 However, the condition reason is empty:  

 ```                                                                                                                                                                                                                
   Reason=""                                                                                                                                                                                                        
 ```                                                                                                                                                                                                                
The Kubernetes API server rejects the status update because metav1.Condition.Reason must contain at least one character. As a result, the expected QuotaReserved=False condition is not persisted in the Workload status.                                                                                                                                                                                                            

**What you expected to happen**:

The Workload should remain inadmissible and persist a condition such as: 
                                                                                
 ```                                                                                                                                                                                                                
   type: QuotaReserved                                                                                                                                                                                              
   status: "False"                                                                                                                                                                                                  
   reason: NoMatchingFlavor                                                                                                                                                                                         
   message: couldn't assign flavors to pod set main: resource example.com/gpu unavailable in ClusterQueue                                                                                                           
 ```    

**How to reproduce it (as minimally and precisely as possible)**: 
                                                                                          
 1. Use the current Kueue main, where UnadmittedWorkloadsObservability is Beta and enabled by default.                                                                                                              
 2. Create a ResourceFlavor, ClusterQueue, and LocalQueue.                                                                                                                                                          
 3. Configure the ClusterQueue with quota for cpu and memory, but without quota for example.com/gpu.                                                                                                                
 4. Create a Job with the following container resource requests: 
                                                                                             
 ```                                                                                                                                                                                                                
   resources:                                                                                                                                                                                                       
     requests:                                                                                                                                                                                                      
       cpu: "1"                                                                                                                                                                                                     
       memory: 1Mi                                                                                                                                                                                                  
       example.com/gpu: "1"                                                                                                                                                                                         
 ```         
I have a PR with the unit-test reproducer of the issue - https://github.com/kubernetes-sigs/kueue/pull/15054

**Anything else we need to know?**:

The scheduler correctly determines that the Workload cannot be admitted because one of its resource requests cannot be assigned to a ClusterQueue flavor.  
The Workload-level no-fit reason is calculated from the flavor-assignment attempts. Successful resource assignments do not provide a no-fit reason. In this case, the resource request that cannot be assigned does not produce a failed flavor-assignment attempt containing NoMatchingFlavor. Consequently, the reason resolver has no reason to select and leaves Assignment.NoFitReason empty.                                

UnadmittedWorkloadsObservability is a Beta feature and is enabled by default. When it is enabled, the reason is returned unchanged instead of being replaced by the generic Pending fallback. Since the reason is empty, the scheduler attempts to publish a condition with an empty Reason, which the API server rejects.
