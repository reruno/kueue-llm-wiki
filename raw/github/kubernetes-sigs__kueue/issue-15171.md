## Description

**What would you like to be added**:

A `Warning` event when Kueue cannot resolve a `scheduling.k8s.io` `PriorityClass`, for the paths where no Pod is ever created.

#3439 asked for this for `WorkloadPriorityClass` and #13775 added it in `ExtractPriority`. The two `PriorityClass` branches below it were left alone:

https://github.com/kubernetes-sigs/kueue/blob/42155a8cd3d7dbca49fac6750b65029fdeca1ab5/pkg/controller/jobframework/reconciler.go#L1850-L1853

and `TestExtractPriority` pins that they stay quiet:

https://github.com/kubernetes-sigs/kueue/blob/42155a8cd3d7dbca49fac6750b65029fdeca1ab5/pkg/controller/jobframework/workload_priority_test.go#L502-L507

**Why is this needed**:

That comment holds while a Pod reaches the API server, which then refuses the name. It does not hold for a suspended Job. No Pod is created, so Kueue is the only thing that resolves the reference, and it resolves it silently.

envtest on 42155a8, one Job per case in its own namespace, events polled for ten seconds:

```
control, no priority class
  workload created : true
  events on job    : Normal/CreatedWorkload

WorkloadPriorityClass "does-not-exist"
  workload created : false
  events on job    : Warning/WorkloadPriorityClassNotFound "WorkloadPriorityClass \"does-not-exist\" not found"

PriorityClass "does-not-exist"
  workload created : false
  events on job    : (none)
```

All three Jobs stay suspended. The third one leaves only this:

```
ERROR  job  controller/controller.go:494  Reconciler error
{"namespace": "zzrepro-vzdrf", "name": "repro-pc",
 "error": "PriorityClass.scheduling.k8s.io \"does-not-exist\" not found"}
```

which is where #3439 started.

`MPIJob.PriorityClass()` resolves `.spec.runPolicy.schedulingPolicy.priorityClass` ahead of the launcher and worker templates, so the name Kueue looks up there is not necessarily one that appears on a Pod at all.
