**What would you like to be cleaned**:

I would propose better defining our packages for testing helpers, I propose:

```
pkg/util/testing/                  # Environment-independent test helpers; reusable by unit, integration, and E2E tests
pkg/util/testingjobs/              # Fluent builders for job types; reusable by unit, integration, and E2E tests

test/util/behavioral/              # API-backed Ginkgo helpers; reusable by integration and E2E tests
test/util/behavioral/e2e/          # Helpers requiring a real cluster; used by E2E tests only

test/integration/framework/        # Envtest and controller-manager lifecycle; used by integration tests only
```

What goes into "test/util/behavioral"?

- RunSuite, reporting and behavioral timeouts.
- Gomega condition, event and error matchers.
- Generic create/delete/cleanup helpers.
- Workload, queue and admission-check assertions.- 
- Namespace creation and deletion.
- Status mutations simulating external actors: SetQuotaReservation, SetWorkloadsAdmissionCheck, SetPodsPhase, SetCapacityProviderStatus
- Queue and workload lifecycle helpers.
- Pod/job state assertions.
- Event observations.
- In-process metrics assertions.
- Scheduling helpers.
- Client-only KubeRay helpers.
- MultiKueue behavioral assertions that work with supplied clients.

We may have the structure like:

```
test/util/behavioral/
  suite.go
  constants.go
  assertions.go
  objects.go
  namespace.go
  workload.go
  queues.go
  admissionchecks.go
  pods.go
  jobs.go
  events.go
  metrics.go
  scheduling.go
  multikueue.go
  kuberay.go
  capacityprovider.go
```

What goes into "test/util/behavioral/e2e"?

- RunE2ESuite.
- Kubeconfig context and authenticated-client creation.
- REST, visibility and generated clientsets.
- Kueue and external-operator availability checks.
- Controller restarts and leader failover.
- Deployment rollout manipulation.
- Pod/container exec.
- kind-specific operations.
- E2E image discovery.
 Updating deployed Kueue configuration and restarting it.
- External Prometheus creation, scraping and target assertions.
- MultiKueue service accounts, RBAC, kubeconfigs and secrets.
- DRA example-driver availability.
- Kubernetes server/version discovery.

```
test/util/behavioral/e2e/
  suite.go
  environment.go
  images.go
  clients.go
  components.go
  restart.go
  exec.go
  metrics.go
  multikueue.go
  dra.go
```

**Why is this needed**:

- We now have many testing helpers in  `test/util` and in `pkg/util/` , and it is confusing for developers what to place where.
- the current packages and files are getting too coupled
