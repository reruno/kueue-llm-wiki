## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

A way to explicitly mark a Pod as no longer part of its group — e.g. an annotation like `kueue.x-k8s.io/pod-inactive: "true"` — so Kueue stops counting it among the group's active pods and does not delete the replacement Pod as an excess pod.

  Today `isPodRunnableOrSucceeded` counts a Pod as active unless it is `Failed`, or is terminating *and* has no `nodeName`. A Pod that is terminating on a node therefore still counts, so the moment an external controller creates the replacement, the group has `groupTotalCount + 1` active pods and Kueue removes one. Since `sortActivePods` prefers to keep the oldest pods, the one deleted is the
  new replacement rather than the dying pod.

  This matters specifically for the plain Pod group integration, where replacements are created by an external controller that has no way to coordinate its create with Kueue's view of the outgoing pod.

  Marking a pod should not evict the workload or shrink the group: the freed slot stays reserved so the replacement can be admitted into it, including TAS re-placement onto a new node.

  If a supported way to do this already exists, please point us at it. `kueue.x-k8s.io/retriable-in-group: "false"` looks close but has the opposite effect — it marks the group as non-retriable so the whole group
  finishes.

**Why is this needed**:

With the pod group integration we frequently hit excess-pod deletions caused by a race between our external platform terminating a failing pod and creating its replacement. Kueue still sees the terminating pod as active and deletes the replacement; our controller creates another; Kueue deletes that one too. The loop wastes job time, blocks fast node replacement, and exhausts the job's retry limit.
