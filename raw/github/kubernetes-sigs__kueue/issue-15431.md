### Comment by [@apullo777](https://github.com/apullo777) — 2026-09-18T13:01:52Z

I took a look at the failure, and this seems to be a transient GitHub release download issue rather than a populator failure.

The populator e2e applies the Kueue release URL directly with `kubectl`. Here GitHub returned a burst of 500s, and kubectl's short retry window wasn't enough to get past it.

It looks like we can switch this path to the existing `e2e_kubectl_apply_url` helper, which already retries the download before applying it. Does that sound like the right fix? If so, I can send a PR :)

### Comment by [@mimowo](https://github.com/mimowo) — 2026-09-18T13:08:42Z

sounds good,yes, we introduced the re-trying `e2e_kubectl_apply_url` helper for such cases specifically, as we observe transient GH availability sometimes
