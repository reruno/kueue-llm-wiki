## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

Make the queue readiness verification steps in the documentation show the information they ask users to check. Two possible approaches:

- Add `ACTIVE` and `REASON` printer columns for ClusterQueue and LocalQueue, using each resource's existing `Active` condition, and update the example output. These could be wide-only fields as well.
- Alternatively, keep the current printer columns and update the documentation to inspect the Active condition explicitly, for example using `kubectl wait --for=condition=Active` or JSONPath.

Either approach would address the mismatch; maintainer guidance on the preferred direction would be helpful. Happy to send a PR once there is agreement on the preferred approach.

For example, the additional columns for ClusterQueues could show:

```text
NAME       ACTIVE   REASON
healthy    True     Ready
blocked    False    FlavorNotFound
paused     False    Stopped
```

`REASON` would explain the Active condition, rather than summarize every condition on the resource. No new status field is needed.

**Why is this needed**:

The [Quick Start](https://kueue.sigs.k8s.io/docs/getting-started/quick-start/) asks users to verify that a ClusterQueue is active using `kubectl get clusterqueue cluster-queue -o wide`, and that a LocalQueue is ready using `kubectl get localqueue user-queue -n default`. Neither table displays the Active condition.

The [MultiKueue development setup](https://kueue.sigs.k8s.io/docs/tasks/dev/setup_multikueue_development_environment/#step-6-validate-the-setup) similarly asks users to verify component activity with table output, but its ClusterQueue row does not show readiness.

These columns would help distinguish a healthy empty queue from an inactive queue and show the cause without requiring a separate describe or YAML inspection. `kueuectl list clusterqueue` already displays ACTIVE; adding REASON would make the output more informative.
