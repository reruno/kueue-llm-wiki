**What would you like to be added**:
Use Deployment UID for the `kueue.x-k8s.io/job-uid` label in Deployment workloads.

**Why is this needed**:
Currently, we set the Pod UID as the value of the `kueue.x-k8s.io/job-uid` label. It would be great to use the Deployment UID instead. This would make it easier to use the topology spreading feature without relying on `workloadLabelSelectors`.

### Comment by [@mbobrovskyi](https://github.com/mbobrovskyi) — 2026-09-16T08:23:47Z

The label is set on the Workload in the jobframework reconciler, so there's no clean way to inject the Deployment UID at webhook time without the reconciler special-casing Deployment pods – which the job framework, as an abstraction, shouldn't need to do.                                                        
                                                                                                                                                            
In my opinion, the cleaner solution is to create prebuilt Workloads for Deployment pods, similar to what StatefulSet and LeaderWorkerSet do. This pattern naturally sets the Deployment UID on the Workload without adding Deployment-specific logic to the job framework.

### Comment by [@mimowo](https://github.com/mimowo) — 2026-09-16T08:36:34Z

### Comment by [@rjgoyln](https://github.com/rjgoyln) — 2026-09-16T08:59:12Z

One data point on the prebuilt route: Deployment Pods are single-Pod workloads, so `EnsurePrebuiltWorkloadOwnership` makes the Pod the controller and overwrites `job-uid` with the Pod UID (`jobframework/reconciler.go:1434`). I verified this with a test. The group Workload path used by StatefulSet/LWS doesn't have this issue.

So the prebuilt approach would still require a job framework change and a Deployment reconciler.

I have an alternative working behind `DeploymentJobUIDLabel`: the Pod integration resolves the Deployment UID while constructing the Workload and sets it only on the Workload. It only requires one ReplicaSet lookup and doesn't modify the Pod or job framework.

Would you like me to open a PR for this approach?

### Comment by [@mimowo](https://github.com/mimowo) — 2026-09-16T09:03:01Z
