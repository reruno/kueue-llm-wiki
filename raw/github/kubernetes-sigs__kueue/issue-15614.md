## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:
A non-destructive simulation capability for Kueue that evaluates what is likely to happen *before* a workload is actually submitted and saved to etcd. 

Specifically, this would introduce:
1. A new backend API endpoint (e.g. `/simulate` subresource) that evaluates a hypothetical workload against the scheduler's snapshot cache.
2. A `kueuectl simulate -f job.yaml` CLI command.
3. Structured output detailing the reasons for admission failure (Quota, Flavor, Topology, etc.) without making any changes to the actual cluster.

**Why is this needed**:
Currently, users often follow this flow for validating workloads:
1. Submit workload -> Stays pending
2. Inspect Workload / ClusterQueue / events
3. Find quota, topology, flavor, or scheduling issue
4. Modify workload
5. Try again

For large GPU/AI/HPC clusters, this trial-and-error cycle becomes expensive and frustrating. Furthermore, AI agents (like reShapr via MCP) and CI/CD pipelines need a way to negotiate and validate scheduling feasibility asynchronously before clogging the queue with inadmissible workloads. Standard `--dry-run=server` does not solve this because it only hits the validating webhooks, missing the asynchronous Kueue scheduler completely.
