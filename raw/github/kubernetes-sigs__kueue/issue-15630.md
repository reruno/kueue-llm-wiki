**What happened**:

With the SchedulerLibraryIntegration feature gate enabled, TAS fails the whole flavor assignment for a Workload whose PodSet template sets `spec.schedulerName` to a name other than `default-scheduler`.

```shell
unable to calculate domain capacities for PodSet main, error: failed to get framework: profile not found for scheduler name "secondary-scheduler"
```

**What you expected to happen**:

Regardless of .spec.schedulerName, WAS simulator should work well.
