## Description

# TAS: a re-queued second pass replays the workload's pre-commit shape and overwrites the assignment the ungater already consumed

**Affected:** v0.19.2 (mechanism exists wherever second-pass replacement runs; untested elsewhere). Gates: `TopologyAwareScheduling`, failed-node replacement (taints).

*All code references are pinned to tag `v0.19.2`.*

## What happened

Two consecutive second-pass replacements raced on one marked workload (production trace;
16-pod job; node names condensed: `U` = unhealthy-marked node, `P` = round-1 replacement, `Q` =
round-2's):

1. `U` gets marked onto the workload (`status.unhealthyNodes=[U]`); the ungater refuses to ungate a
   pod onto it ([`topology_ungater.go:285`](https://github.com/kubernetes-sigs/kueue/blob/v0.19.2/pkg/controller/tas/topology_ungater.go#L285)).
2. **Round 1, cycle 509586, 11:36:48.820**: [`tas_flavor_snapshot.go:631`](https://github.com/kubernetes-sigs/kueue/blob/v0.19.2/pkg/cache/scheduler/tas_flavor_snapshot.go#L631) swaps `U → P`;
   scheduler commits TA′ at 11:36:50.715.
3. **11:36:50.719 (+4ms)**: ungater pins a pod from TA′ ([`topology_ungater.go:311`](https://github.com/kubernetes-sigs/kueue/blob/v0.19.2/pkg/controller/tas/topology_ungater.go#L311)) onto `P`.
4. Meanwhile ordinary update traffic in the same ~600ms had already re-enqueued a further second
   pass: [`QueueSecondPassIfNeeded`/`AfterFunc`](https://github.com/kubernetes-sigs/kueue/blob/v0.19.2/pkg/cache/queue/manager.go#L991-L1013) carry the workload object **captured at event time**
   — marks on, TA still containing `U` — so `NeedsSecondPass` is true when dequeued
   (second-pass queued 11:36:51.122).
5. **Round 2, cycle 509588, 11:36:52.756**: recomputes off that stale shape (`U → Q`; its own log
   still shows `U` in `existingAssignment`) and commits **TA″ over TA′** via
   [`admit()` → `e.Obj.DeepCopy()` + `PatchAdmissionStatus`](https://github.com/kubernetes-sigs/kueue/blob/v0.19.2/pkg/scheduler/scheduler.go#L975-L994) — no fence, no conflict.
6. The pod pinned onto `P` is orphaned forever: failed-node replacement only terminates
   Pending+never-bound pods ([`node_controller.go:695`](https://github.com/kubernetes-sigs/kueue/blob/v0.19.2/pkg/controller/tas/node_controller.go#L695-L697)); the mismatch detector
   ([`topology_ungater.go:511`](https://github.com/kubernetes-sigs/kueue/blob/v0.19.2/pkg/controller/tas/topology_ungater.go#L511)) only scans at ungate time, so a Running pod is never re-checked.
   `P` stays physically full but ledger-free — a phantom re-targeted by legal whole-node
   admissions until hand-cleanup. Status looks healthy: TA″ matches 15 of 16 pods.

## What you expected to happen

Second passes evaluate the workload's *current* state; a replacement commit never overwrites an
assignment whose pods are already pinned; orphans are detected and repaired.

## Reproduce (unit sketch)

Seed a marked workload; run a replacement pass that commits while the ungater pins rank k to the
new domain; replay a stale (event-time) copy through the second-pass queue. Assert: TA preserves
rank k's domain, or the pass fails/evicts rank k's pod. Today it does neither.

## Anything else

- **Sibling of #15504**: same root — event-time object copies carried through the second-pass /
  release paths, then loosely applied whole-status
  ([`prepareWorkloadPatch`](https://github.com/kubernetes-sigs/kueue/blob/v0.19.2/pkg/workload/patching/patching.go#L149)).
- Fix landscape: #15571 (fresh placement + fire-time re-read) and the in-flight #14078 (refresh
  before delayed second-pass retries) each cover this issue's observed vector — on refresh the
  live object says `NeedsSecondPass=false`, so the superseding pass never runs. Neither closes the
  publication window: a legitimate pass can still overwrite an assignment whose pods were pinned
  mid-gap (#14078's thread also reports a lost-entry regression).
- Fix direction: (i) a replacement commit first checks for pods already pinned from the
  assignment it would replace (or fails and re-reads); (ii) extend the mismatch detector to
  Running pods; (iii) `requeueAndUpdate`'s same-cycle release writes still act on the entry
  snapshot even after #15571.

## Environment

EKS 1.32-era; Kueue v0.19.2; 8-GPU nodes; hostname-only topology.

### Comment by [@bolubo](https://github.com/bolubo) — 2026-09-23T11:19:54Z

@mimowo I like this direction, and I took the cache-side skip you sketched for a spin on the #15761 head. Notes:

- The cache already sees every write, so it can remember the RV it has seen per workload. A second pass can skip its entry when that RV no longer matches the entry's snapshot, the same way `nominate()` skips first passes the cache accounts for. In the replay: heal seen first, zero writes, admission stays on x2; eviction seen first, zero writes, no resurrection; a normal pass still lands with one write.
- The check alone can't fence a write that lands after the last observation. We replayed that one: the compare passes while the cache lags, and the loose write lands. So I'd keep the RV-carrying second-pass write as the backstop. The check removes the conflict plus backoff from the common case, which is where the latency worry was.
- Your DeleteWorkload point is the one I'd build on. Dropping just the delete isn't enough though: the stale entry has already pushed its snapshot into the cache, and if the newer state was processed first, no event is left to fix it. I replayed that order: API on x2, cache on x1, nothing coming. With the check in front, that overwrite never happens, so the conflict path stays simple: no delete, no Get, no cache write. The current head repair fails the same way: it either empties the accounting on a skipped read or restores a pre-eviction usage on a lagging one. That is also why I would not reach for restoring the previous state: what it puts back is the stale snapshot itself.
- #14078 looks like the sequencing half; this is the commit-time half. I think they compose.

One thing I'd like to align on: where the RV-aware state should live, and whether a skip is silent or emits an event. Patch and replays ready if useful.
