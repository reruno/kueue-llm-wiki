## Description

**What happened**:

`kueuectl list pods --for pod/NAME` cannot list Pods that belong to an annotation-based Pod group. `Pod.PodLabelSelector()` in `pkg/controller/jobs/pod/pod_controller.go` builds `kueue.x-k8s.io/pod-group-name=<value>` from `pod.Labels`. When the group name is present only in the Pod group annotation, the value is empty. The API server then returns no Pods because label selectors cannot match annotations.

**What you expected to happen**:

For a Pod that belongs to an annotation-based Pod group, `kueuectl list pods --for pod/NAME` should list all Pods in that group.

**How to reproduce it (as minimally and precisely as possible)**:

1. Create or manage Pods with Kueue where the Pod group name is defined through the supported Pod group annotation and the `kueue.x-k8s.io/pod-group-name` label is absent.
2. Run `kueuectl list pods --for pod/NAME`.
3. Observe that the command sends an empty Pod group label selector and returns no Pods.

**Anything else we need to know?**:

Update the `list pods` path to identify annotation-based Pod groups. Because Kubernetes label selectors cannot select annotation values, list Pods in the target namespace and filter the results client-side by the Pod group annotation. Preserve the existing behavior for label-based Pod groups and standalone Pods.

Acceptance criteria:
- `kueuectl list pods --for pod/NAME` lists all Pods in an annotation-based Pod group.
- The command does not send an empty `kueue.x-k8s.io/pod-group-name` label selector.
- Tests cover annotation-based Pod groups and selector behavior.
