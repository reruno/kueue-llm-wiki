**What happened**:

When validating a `Workload` where `admission.podSetAssignments[].resourceUsage` is not evenly divisible by the assigned pod count, the admission webhook in `pkg/webhooks/workload_webhook.go` returns an error message containing the memory address of the pod count pointer instead of the actual pod count.

For example:

```text
is not a multiple of 21678974853132
```

**What you expected to happen**:

The error message should contain the actual pod count. For example, if the pod count is `3`:

```text
is not a multiple of 3
```

**How to reproduce it (as minimally and precisely as possible)**:

In `pkg/webhooks/workload_webhook.go` around lines 312–318:

```go
if count := ptr.Deref(ps.Count, 0); count > 0 {
    for k, v := range ps.ResourceUsage {
        if (resources.ResourceValue(k, v) % int64(count)) != 0 {
            allErrs = append(allErrs, field.Invalid(
                psaPath.Child("resourceUsage").Key(string(k)),
                v,
                fmt.Sprintf("is not a multiple of %d", ps.Count),
            ))
        }
    }
}
```

`ps.Count` is dereferenced into `count` for the divisibility check, but the error message passes `ps.Count` (`*int32`) to `fmt.Sprintf` instead of the dereferenced `count`.

This results in the pointer value being formatted as a decimal integer.

**Anything else we need to know?**:

This was missed by the existing test case, `assignment usage should be divisible by count`, in `pkg/webhooks/workload_webhook_test.go`. The test checks `field.Invalid(..., nil, "")` with an empty detail string, so it does not verify the actual error message.

The fix should be straightforward:

* Change `ps.Count` to `count` in the `fmt.Sprintf` call in `pkg/webhooks/workload_webhook.go`.
* Update the unit test in `pkg/webhooks/workload_webhook_test.go` to check for the expected detail string: `"is not a multiple of 3"`.
