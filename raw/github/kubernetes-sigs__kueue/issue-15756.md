## Description

**What would you like to be cleaned**:

Refactor the shared setup and cleanup in `test/e2e/multikueue/extended/e2e_test.go` to avoid recreating the full MultiKueue test environment for every spec.

The current outer `BeforeEach` and `AfterEach` recreate and delete namespaces, `MultiKueueCluster` objects, a `MultiKueueConfig`, an `AdmissionCheck`, priority classes, resource flavors, ClusterQueues, and LocalQueues for every selected spec. Investigate reusing appropriate fixtures with `BeforeAll` and `AfterAll`, likely within integration-specific `Ordered` containers rather than by making the entire suite ordered.

The refactoring should preserve test isolation and parallel execution where possible. Resources created or mutated by an individual spec must not leak state or quota usage into later specs.

Original discussion: https://github.com/kubernetes-sigs/kueue/pull/15725#discussion_r4041717580

**Why is this needed**:

Repeatedly provisioning and deleting the same MultiKueue infrastructure increases the runtime and resource cost of the extended E2E suite. Reusing stable fixtures within safe boundaries should reduce that overhead without serializing unrelated integrations or introducing cross-test interference.
