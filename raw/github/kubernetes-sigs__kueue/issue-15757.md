## Description

**What would you like to be cleaned**:

Decompose `test/e2e/multikueue/extended/e2e_test.go` into integration-specific test files. For example, move LeaderWorkerSet and KubeRay coverage into dedicated files, and apply the same organization to the other integrations where useful.

Keep suite-wide client initialization and genuinely shared fixture helpers in common files, while colocating integration-specific tests, labels, setup, and helpers with their respective integration.

### Migration checklist

- [x] KubeRay → `kuberay_test.go` ([#15872](https://github.com/kubernetes-sigs/kueue/pull/15872))
  - `Should run a RayJob on worker if admitted`
  - `Should run a RayCluster on worker if admitted`
  - `Should scale an elastic RayCluster on worker if admitted`
  - `Should run a RayService on worker if admitted`
- [x] LeaderWorkerSet → `leaderworkerset_test.go` ([#15886](https://github.com/kubernetes-sigs/kueue/pull/15886))
  - `Should sync a LeaderWorkerSet and run replicas on worker cluster`
  - `Should dispatch all LeaderWorkerSet workloads to the same worker`
- [x] JobSet → `jobset_test.go` ([#15935](https://github.com/kubernetes-sigs/kueue/pull/15935))
  - `Should run a jobSet on worker if admitted`
- [x] AppWrapper → `appwrapper_test.go` ([#15935](https://github.com/kubernetes-sigs/kueue/pull/15935))
  - `Should run an appwrapper containing a job on worker if admitted`
- [x] Kubeflow PyTorchJob → `pytorchjob_test.go` ([#15925](https://github.com/kubernetes-sigs/kueue/pull/15925))
  - `Should run a kubeflow PyTorchJob on worker if admitted`
- [x] MPIJob → `mpijob_test.go` ([#15925](https://github.com/kubernetes-sigs/kueue/pull/15925))
  - `Should run a MPIJob on worker if admitted`
- [x] TrainJob → `trainjob_test.go` ([#15925](https://github.com/kubernetes-sigs/kueue/pull/15925))
  - `Should run a TrainJob on worker if admitted`

`ray_autoscaling_test.go` is already integration-specific and is not part of this migration checklist.

Original discussion: https://github.com/kubernetes-sigs/kueue/pull/15725#discussion_r4041727978

**Why is this needed**:

The current file contains tests for many independent integrations and has become difficult to navigate and review. Separating tests by integration will make ownership and feature-specific setup clearer, reduce merge conflicts, and make future additions easier to review without changing test behavior.
