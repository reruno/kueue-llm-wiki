## Description

**What happened**:

   A LeaderWorkerSet created while its namespace did not match the LWS webhook's `namespaceSelector` (a label was removed and restored minutes later) stays half-adopted. (This could happen for other cases when the LWS object is created while the admission webhook is blind to it, and the reconciler adopts it later)

   - The LWS reconciler later creates the group Workload and it is Admitted (its watch only needs the queue-name label), so from Kueue's side the job looks fully managed and quota is reserved.
   - But the LWS pod templates never got the webhook mutations: `kueue.x-k8s.io/pod-suspending-parent: leaderworkerset.x-k8s.io/leaderworkerset` and `kueue.x-k8s.io/pod-group-serving: "true"`
 (`leaderworkerset_webhook.go`).
   - Every pod created from that template falls through both management paths:
     1. the pod webhook skips it, because `FindAncestorJobManagedByKueue` sees an ancestor with a queue-name label and assumes it is already managed;
     2. the LWS reconciler's pod handler ignores it, because it only enqueues pods carrying the `pod-suspending-parent` annotation.

   So the Workload is Admitted while its pods run without gates or the `kueue.x-k8s.io/managed` label, consuming capacity Kueue counts as free. Recreating the pods does not heal it, since the stale state is in the
 LWS object. We found it by diffing pod labels across groups.

   **What you expected to happen**:

   An LWS that missed its webhook mutation should get re-stamped by the reconciler, or at least surface a condition/event/log about it, instead of running pods outside quota under an Admitted workload.

   **How to reproduce it (as minimally and precisely as possible)**:

   1. Make the LWS mutating webhook's `namespaceSelector` not match namespace `foo`.
   2. Create a LeaderWorkerSet with a queue-name label in `foo`.
   3. Make the namespace match the selector again (for example, add the label).
   4. Observe: a group Workload appears and is Admitted; pods come up without `kueue.x-k8s.io/managed` or scheduling gates, and never acquire them.

   **Anything else we need to know?**:

   Suggested fix: in the LWS reconciler, when an LWS with a queue-name label has an admitted Workload but its leader/worker pod templates lack `pod-suspending-parent`, patch the template and roll the groups. There
 is precedent for this kind of backfill (#13968 the queue-name backfill for pre-#4932 LWSs).
