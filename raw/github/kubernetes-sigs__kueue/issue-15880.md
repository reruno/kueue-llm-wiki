## Description

**What happened**:

The StatefulSet validating webhook applies `ValidateTASPodSetRequest` in `ValidateCreate`, but it does not apply the same validation in `ValidateUpdate`. An update can therefore introduce invalid TopologyAwareScheduling (TAS) annotations into `spec.template.metadata`.

**What you expected to happen**:

The StatefulSet validating webhook should validate TAS metadata during `ValidateUpdate` when the `TopologyAwareScheduling` feature gate is enabled.

**How to reproduce it (as minimally and precisely as possible)**:

1. Enable the `TopologyAwareScheduling` feature gate.
2. Create a valid StatefulSet.
3. Update `spec.template.metadata.annotations` with an invalid TAS annotation combination, such as a required topology together with `kueue.x-k8s.io/podset-unconstrained-topology: "false"`.
4. Observe that the update bypasses `ValidateTASPodSetRequest`.

**Anything else we need to know?**:

Update `pkg/controller/jobs/statefulset/statefulset_webhook.go` to call `jobframework.ValidateTASPodSetRequest` from `ValidateUpdate`, using the `spec.template.metadata` field path. Add coverage that verifies invalid TAS annotations are rejected on update.
