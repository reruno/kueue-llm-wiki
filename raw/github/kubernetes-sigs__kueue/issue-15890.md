## Description

**What happened**:

Five CRDs have no `<crd>_editor_role.yaml` / `<crd>_viewer_role.yaml` in [config/components/rbac](https://github.com/kubernetes-sigs/kueue/tree/main/config/components/rbac):

- AdmissionCheck
- MultiKueueCluster
- MultiKueueConfig
- ProvisioningRequestConfig
- WorkloadPriorityClass

They only appear in the generated manager [role.yaml](https://github.com/kubernetes-sigs/kueue/blob/main/config/components/rbac/role.yaml), which is for Kueue's own service account. Nothing carries the `rbac.kueue.x-k8s.io/batch-admin` label for them, so `kueue-batch-admin-role` aggregates no rules and a subject bound to it gets no access at all.

Most other CRDs do have the pair: ClusterQueue, LocalQueue, ResourceFlavor, Workload, Topology and Cohort.

**What you expected to happen**:

`kueue-batch-admin-role` describes itself as ["permissions for end users to manage all kueue objects"](https://github.com/kubernetes-sigs/kueue/blob/main/config/components/rbac/batch_admin_role.yaml), so an admin bound to it should be able to manage these five too.

All five are cluster-scoped, so following the convention for cluster-scoped CRDs (admin can edit
and view, users cannot view), each needs a pair modelled on [clusterqueue_editor_role.yaml](https://github.com/kubernetes-sigs/kueue/blob/main/config/components/rbac/clusterqueue_editor_role.yaml) and [clusterqueue_viewer_role.yaml](https://github.com/kubernetes-sigs/kueue/blob/main/config/components/rbac/clusterqueue_viewer_role.yaml):

- editor: `rbac.kueue.x-k8s.io/role` + `rbac.kueue.x-k8s.io/batch-admin`
- viewer: the same, plus `rbac.authorization.k8s.io/aggregate-to-admin`

**How to reproduce it (as minimally and precisely as possible)**:

On a cluster with Kueue installed:

```console
$ kubectl create clusterrolebinding demo --clusterrole=kueue-batch-admin-role --user=demo
$ kubectl auth can-i create admissionchecks --as=demo -A
no
$ kubectl auth can-i create clusterqueues --as=demo -A
yes
```

Same result for `multikueueclusters`, `multikueueconfigs`, `provisioningrequestconfigs` and
`workloadpriorityclasses`.

Or just check which rules got aggregated:

```console
$ kubectl get clusterrole kueue-batch-admin-role -o json | jq '.rules[].resources[]' | sort -u
```

**Anything else we need to know?**:

The practical impact is that managing MultiKueue or AdmissionChecks or other mentioned CRDs requires `cluster-admin`, which isn't always available on managed platforms.
