### Comment by [@YQ-Wang](https://github.com/YQ-Wang) — 2026-10-14T00:07:52Z

Hi @kannon92 Thanks for reopening. The job is failing for two reasons:
1. #15982 accidentally reverted the calibration from #15952, so the checker is enforcing the original 75 workloads/s floor again.
2. Throughput dropped from about 46 to about 33 workloads/s starting with the first run that included #16235, which turned on `MultiKueueOrchestratedPreemption` by default. Each Workload replicated to a worker got two redundant status writes. #17157 removes them, which brought local throughput back to the same level as with the gate disabled.
Also opened a follow-up #17158 to restore the calibrated expectations.
