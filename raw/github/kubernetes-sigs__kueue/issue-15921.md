## Description

### What happened

The integration test suite `test/integration/singlecluster/controller/concurrentadmission` failed in CI with a flake in `[AfterEach]` cleanup.

- Failing spec: `Concurrent Admission when Should assign flavors with respect to constraints [AfterEach] Creates variants for all flavors in the ClusterQueue`
- Failure location: `test/integration/singlecluster/controller/concurrentadmission/concurrent_admission_test.go:91`
- Underlying `Eventually` failure: `test/util/util.go:236` — `Error matcher expects an error. Got: <nil>: nil`
- Root symptom: `[FAILED] Timed out after 45.004s. Object still exists` for `ClusterQueue` `cq-constraints`. The object had `deletionTimestamp` set and the finalizer `kueue.x-k8s.io/resource-in-use` still present, so deletion did not complete within the timeout.

### CI reference

- PR: kubernetes-sigs/kueue#15919
- Job: `pull-kueue-test-integration-shard-1-main`
- Prow link: https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/15919/pull-kueue-test-integration-shard-1-main/2102059526168514560
- Reported by: @tenzen-y

### Suggested investigation

- Check why the `kueue.x-k8s.io/resource-in-use` finalizer on `ClusterQueue` `cq-constraints` was not removed within 45s during test cleanup. This suggests the workload admitted against the `ClusterQueue` was not finalized/evicted in time, or the finalizer-removal reconcile loop lagged under test load.
- Confirm whether the wait timeout in the `AfterEach` cleanup helper (`test/util/util.go:236`) is too tight for this suite, or if there is a real reconciliation delay in removing `kueue.x-k8s.io/resource-in-use`.

### Acceptance criteria

- Root cause identified for the delayed ClusterQueue finalizer removal, or the test cleanup timeout adjusted with justification.
- Test passes reliably across repeated CI runs.
