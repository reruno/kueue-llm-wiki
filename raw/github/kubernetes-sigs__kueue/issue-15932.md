## Description

**What would you like to be cleaned**:

The AfterEach teardown in integration tests (for example test/integration/singlecluster/controller/concurrentadmission/concurrent_admission_test.go) deletes the ClusterQueue while a spec's Workloads may still be racing toward admission. The ClusterQueue's resource-in-use finalizer only clears once ClusterQueueEmpty() reports no reserving workloads (pkg/controller/core/clusterqueue_controller.go:194-198), so specs currently work around this by waiting for admission (workload.IsAdmitted) before returning. This is the same class of flake fixed in #14196, #13493, and #15921/#15927.

Delete Workloads before their owning ClusterQueue in the shared test cleanup, or otherwise make teardown tolerate in-flight admission, so individual specs don't need this wait.

Where a spec does need to wait for admission, prefer util.ExpectWorkloadsToBeAdmitted(ctx, k8sClient, wl) over a bespoke workload.IsAdmitted(...) check, since it also confirms the reconciler has no more pending work.

**Why is this needed**:

#14196, #13493, and #15927 each patched a different spec with the same wait-for-admission workaround. Fixing the cleanup ordering once removes a recurring source of flakiness instead of patching each new spec as it flakes.
