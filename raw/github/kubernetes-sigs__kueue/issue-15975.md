**Which test is flaking?**:

**Link to failed CI job or steps to reproduce locally**:

https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/13730/pull-kueue-verify-website-links-preview-main/2102054102073610240

PR #13730, commit ff4976d5b979cbff310db7fa0f3eb47f62ac01ff.

**Failure message or logs**:
```
[verify-website-links-preview] preview not ready (state='none'), attempt 1/20. 
... 
[verify-website-links-preview] preview not ready (state='none'), attempt 20/20. 
[verify-website-links-preview] ERROR: no ready same-commit deploy preview for ff4976d5b979cbff310db7fa0f3eb47f62ac01ff after bounded wait. make-timing: started=2026-09-21T15:15:44Z finished=2026-09-21T15:25:21Z status=1 duration=577s
```

**Anything else we need to know?**:

The preview was not missing. Netlify had already created the exact-commit deploy, but it was still queued:

| Time | Event |
| --- | --- |
| 15:15:24Z | Netlify creates the deploy, state `enqueued` |
| 15:15:44Z | Prow starts polling |
| 15:25:21Z | Prow gives up after 20 attempts |
| 15:36:45Z | `deploy/netlify` is finally posted as `failure` |

`verify-preview.sh` currently observes the GitHub `deploy/netlify` status, so an exact deploy that is still `enqueued` looks the same as one that was never created: both appear as `state='none'`.

I don't think increasing the bounded wait alone is a good fix. The 40 attempts proposed in #14706 would still have expired before the status appeared here, and this deploy ultimately failed anyway.

A small improvement could be to consult Netlify's public deploy API when the bounded wait expires. For this commit it reported `state: enqueued` while Prow was polling and later `state: error.` That would let the failure distinguish a queued/failed deploy from one that was never created, without changing the current wait policy.

If this turns out to happen often enough, we could separately consider whether a confirmed `enqueued` deploy should use a different wait budget.

This is different from #14684, where the observed Prow run was aborted by the trigger plugin after the PR merged.
