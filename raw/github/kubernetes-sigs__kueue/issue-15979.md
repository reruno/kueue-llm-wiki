**What would you like to be added**:

Define the validation rules for ResourceTransformations in ConfigAPI. 

Some of the confiugrations are seemingly non-sensical:
1. resource in "input" which matches excludeResourcePrefixes
2. resource in "output" which matches excludeResourcePrefixes

(1.) was attempted in https://github.com/kubernetes-sigs/kueue/pull/15926, but I decided to revert the PR, because it seems such configurations could be sensible - I can imagine the "input" is "replaced", and so excludeResourcePrefixes wouldn't affect them.

**Why is this needed**:

- To pick up early on configuration problems; fail fast
- To align on the validation rules before proceeding with PR
