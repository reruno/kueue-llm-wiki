## Description

**What would you like to be added**:

An explicit `--metrics-authentication` boolean flag, defaulting to `true`, to allow a scraper in the same pod to collect Kueue metrics over HTTPS without bearer-token authentication.

With the flag set to `false`, require `metrics.bindAddress` to contain an explicit IPv4 or IPv6 loopback IP and port (for example, `127.0.0.1:8443` or `[::1]:8443`). Reject wildcard, non-loopback, hostname-based and malformed addresses at startup. Preserve the existing `"0"` value for disabling metrics.

Keep TLS enabled in both modes. When authentication is enabled, preserve controller-runtime's authentication/authorization filter. When disabled, omit that filter so metrics scraping does not require TokenReview or SubjectAccessReview calls. Preserve certificate loading/rotation, webhook behavior, authenticated defaults and upstream RBAC manifests.

**Why is this needed**:

**Urgent: this is currently blocking Kueue integration at Stripe.** We need a supported way for a trusted pod-local scraper to collect metrics without bearer-token authentication while retaining HTTPS and metrics collection.

Some deployments authenticate the controller to Kubernetes using client certificates and collect metrics through a sidecar in the same pod. The controller's Kubernetes credentials and the scraper's credentials serve different purposes; a pod-local scraper may not have a bearer token or need API-server-mediated authentication.

In v0.19.5 (`8e60d76a91bb9a45754218e569de1088f862ac75`), `cmd/kueue/main.go` unconditionally sets both `SecureServing: true` and `FilterProvider: filters.WithAuthenticationAndAuthorization`. This prevents opting out of review-based authentication while retaining HTTPS for a loopback-only endpoint.

Related historical discussions: #663 (closed; older auth-proxy configuration) and #4841 (closed; HTTP and alternative authentication discussion). This proposal retains HTTPS and limits the opt-out to loopback.

**Completion requirements**:

- Default and explicit `true` preserve authentication and authorization.
- Explicit `false` permits HTTPS scraping without a bearer token and without either review API call.
- Tests cover IPv4/IPv6 loopback, unsafe/malformed addresses, startup rejection, disabled metrics, certificate loading/rotation and verified TLS connections.
- Document that all containers in the pod can access loopback; it is a pod-level boundary, not container isolation. Host-networked pods share the node network namespace.
- Document scraper CA trust and certificate-matching TLS server-name configuration: a DNS-only certificate does not automatically validate against `127.0.0.1`. Scraper configuration and any removal of unused metrics-auth RBAC in a downstream deployment are separate changes.
