## Description

**What happened**:

For classic preemption, when `borrowWithinCohort` is set to `Never` and `withinClusterQueue` is not `Never`, the preemptor will not preempt lower-priority tasks within the same queue.
> Note: Fair preemption does not have this problem.

**What you expected to happen**:

I want high-priority tasks to be able to preempt low-priority tasks within the same queue when can not reclaim quota from other queue. 
Under the current standard preemption model, when `borrowWithinCohort` is set to `Never`, this behavior cannot be controlled via `withinClusterQueue`. I believe this behavior should be governed by the `withinClusterQueue` parameter.

**How to reproduce it (as minimally and precisely as possible)**:

Use two ClusterQueues in the same cohort:

- `cq1`: nominal quota `2 CPU`
- `cq2`: nominal quota `2 CPU`, empty
- `cq1` configuration:
  - `withinClusterQueue: LowerPriority`
  - `reclaimWithinCohort: Any`
  - `borrowWithinCohort.policy: Never`

1. Submit a low-priority Workload to `cq1` requesting `4 CPU`.
2. The Workload is admitted and borrows `2 CPU` from the cohort.
3. Submit a high-priority Workload to `cq1` requesting `4 CPU`.

Then high-priority Workload cannot preempt low-priority Workload.

### Comment by [@dkaluza](https://github.com/dkaluza) — 2026-09-23T12:15:54Z

For me this indeed sounds like a bug in current implementation - in the given example the quota situation does not change at all. So preemptions in the same CQ that already is borrowing this quota should be allowed.

I would generally go with a rule of a thumb - if withinClusterQueue is not Never - workloads should be always able to preempt other workloads from the same CQ according to the value - Any or LowerPriority, regardless of the fact whether they are borrowing or not.
(Obviously this should still follow normal borrowing/lending limits after the admission)
