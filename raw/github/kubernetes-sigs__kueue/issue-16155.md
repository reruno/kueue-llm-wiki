## Description

**What would you like to be cleaned**:

`e2e_docker_pull_if_needed` in `hack/testing/e2e-common.sh` spends the full 7-attempt backoff when a `docker pull` fails because the tag does not exist and the registry reported that as a 401 with no reason. Make it fail fast again without giving back the retry that a degraded registry needs.

The pull output alone cannot separate the two, since quay.io answers both a degraded token service and a missing tag with a bare `unauthorized`. A manifest lookup is the likely discriminator.

**Why is this needed**:

[PR #16148](https://github.com/kubernetes-sigs/kueue/pull/16148) removed a bare `unauthorized` from `E2E_NON_RETRIABLE_IMAGE_ERRORS` so that a 401 from a degraded registry no longer kills e2e cluster bring-up before any spec runs, fixing [#16115](https://github.com/kubernetes-sigs/kueue/issues/16115). The trade-off it accepted is that a tag which does not exist now takes 188s to fail instead of failing immediately, and a mistaken dependency version bump is the normal way that happens.
