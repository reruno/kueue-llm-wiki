## Description

**What happened**:

In `pkg/controller/jobframework/reconciler.go`, `prepareWorkloadSliceForScaleUp` copies `MinCount` from `prevWl.Spec.PodSets[i]` into the current PodSet at index `i`. If the current workload adds a PodSet beyond the predecessor's length, reconciliation can panic. If PodSets change order, it can copy the wrong floor.

**What you expected to happen**:

Match predecessor PodSets by name. Copy `MinCount` only from a matching predecessor. Keep the initialized floor for a new PodSet.

**How to reproduce it (as minimally and precisely as possible)**:

Enable partial elastic scale-up and create a replacement workload with either an added PodSet or reordered PodSets relative to its active predecessor. Observe a panic for an added PodSet past the predecessor's length, or an incorrect `MinCount` for reordered PodSets.

**Anything else we need to know?**:

Add unit coverage for added and reordered PodSets, plus integration coverage for the affected controller behavior.
