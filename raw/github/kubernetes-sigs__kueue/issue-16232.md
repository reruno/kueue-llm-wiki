## Description

**What would you like to be added**:

Add an optional `managerConfig.controllerManagerConfigOverrides` map so users can customize individual manager settings while keeping the remaining chart defaults. For example:

```yaml
managerConfig:
  controllerManagerConfigOverrides:
    managedJobsNamespaceSelector:
      matchExpressions:
        - key: kubernetes.io/metadata.name
          operator: NotIn
          values: [kube-system, kueue-system, platform-system]
    integrations:
      frameworks: ["batch/job", "pod", "kubeflow.org/pytorchjob"]
```

Merge this map on top of the existing `controllerManagerConfigYaml` before rendering the manager ConfigMap and deriving webhook settings. Maps merge recursively; lists and scalars replace existing values.

Consumers that derive settings from the manager configuration, including the experimental Kueue Populator's namespace selector, should use the same merged configuration when adopting this feature.

The map defaults to `{}`. Existing string-based configuration and certificate-management behavior remain supported and unchanged when no overrides are supplied.

**Why is this needed**:

The current value is a single YAML string. To change a few fields while retaining the other chart defaults, users must copy the full configuration. We do this today for a small number of settings.

On each chart upgrade, that copy must be manually synchronized with upstream defaults. Otherwise, it can silently retain old settings. Structured overrides would let users maintain only their intentional changes and inherit the remaining defaults from the target chart. Overridden lists would still be maintained explicitly.

Happy to send a PR with compatibility and merge-behavior tests.
