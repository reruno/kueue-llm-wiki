**What would you like to be cleaned**:
Two independent read-only checks in `make verify`:

**Part 1: every file the Helm chart ships is listed in its `kustomization.yaml`**
`hack/processing-plan.yaml` builds the Helm chart from globs such as `./config/components/rbac/*.yaml`, while kustomize only includes the files listed in `kustomization.yaml`. 

The check reads those globs and their `excludes`, and fails when a matched file is not listed.

 **Part 2: every resource granted to the manager has editor and viewer ClusterRoles**
Every resource in `config/components/rbac/role.yaml`, which is generated from the  `+kubebuilder:rbac` markers, must be granted by some `*_editor_role.yaml` and some  `*_viewer_role.yaml`, unless it is on an exclusion list with a reason. 

Using the manager role as the source covers both Kueue CRDs and integration CRDs such as AppWrapper. Only the rules are compared; verbs and aggregation labels are not.

Most exclusions are resources the controller only reads or creates (nodes,  namespaces, DRA, ...). **Alpha APIs** need discussion:
- `capacityproviders` and `dynamicquotaorchestrators` are granted  to the manager but have no editor/viewer roles. 

Should they get roles now, or stay excluded until they graduate? (In the other direction, `preemptionconfigs` has roles but is not in the manager role.) 


**Why is this needed**:
Both types of omissions have impacted users and were identified manually.

 - Missing editor/viewer roles: five Kueue CRDs (#15890, fixed in #16028) and AppWrapper (#16096), which left users bound to the batch roles without access. 
- Missing kustomization entries for the SparkApplication roles (#9911) and the Cohort CRD (#2995).
