## Description

**What happened**:

The workload detail page in KueueViz shows no ClusterQueue, and the link on it points to `/cluster-queue/undefined`.

`fetchWorkloadDetails` in `cmd/kueueviz/backend/handlers/workloads.go` builds a `workloadResult` with `ClusterQueueName` and `Preemption`, then returns the bare `Workload` (`return w, nil`). So `clusterQueueName` and `preemption` never reach the frontend. `WorkloadDetail.jsx` reads `workload.clusterQueueName`.

This looks like a regression from #7663, which moved the backend to the typed client. Before that change the handler set these fields on the returned object.

**What you expected to happen**:

The `/ws/workload/:namespace/:workload_name` response includes `clusterQueueName` (or `Unknown`) and `preemption`.

**How to reproduce it (as minimally and precisely as possible)**:

1. Run KueueViz against a cluster with a LocalQueue pointing to a ClusterQueue.
2. Submit a job to that LocalQueue.
3. Open the workload detail page. The ClusterQueue field is empty.

Or: call `fetchWorkloadDetails` in a unit test and marshal the result. It has no `clusterQueueName` key.

**Anything else we need to know?**:

Fix is a one line change to `return res, nil`. I have a PR ready with tests.

**Environment**:
- Kueue version: main at 9e9112f94
