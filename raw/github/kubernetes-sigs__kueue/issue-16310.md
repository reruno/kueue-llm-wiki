## Description

**What would you like to be cleaned**:

`Cache.CohortStats` computes the dominant resource share without checking for a Cohort cycle. `calculateLendable` walks to the root with `for root.HasParent()`, which does not terminate on a cycle, so the call spins while holding `c.RLock()`.

It is the only one of the four cache-side `dominantResourceShare` callers that does not guard:

| caller | guard |
| --- | --- |
| `clusterqueue.go:612` `reportWeightedShare` | `if c.HasParent() && hierarchy.HasCycle(c.Parent()) { return }` |
| `cache.go:613` `ResyncCohortGaugeMetrics` | `if cohort == nil \|\| hierarchy.HasCycle(cohort) { return }` |
| `cache.go:955` `ClusterQueueStats` | `&& (!cq.HasParent() \|\| !hierarchy.HasCycle(cq.Parent()))` |
| `cache.go:977` `CohortStats` | none |

The only caller is `CohortReconciler.updateCohortStatusIfChanged` (`cohort_controller.go:254`), and that reconcile returns early when `AddOrUpdateCohort` reports `ErrCohortHasCycle` (`cohort_controller.go:224-228`), with a comment saying it skips consumers that need a valid tree. `AddOrUpdateCohort` reports that error for any cohort inside a cycle, because `updateCohort` calls `updateCohortTreeResources`, which checks `HasCycle` first. Cohort reconciles are also serial: `config/components/manager/controller_manager_config.yaml` sets `Cohort.kueue.x-k8s.io: 1`, and controller-runtime defaults to 1 anyway.

So the guard currently lives in the caller instead of in the function. Two things that changes:

1. Raising Cohort concurrency above 1 opens an interleaving where one reconcile passes `AddOrUpdateCohort` before another persists the cycle edge, and then reaches `CohortStats` on a now-cyclic cohort. I have not reproduced that, and it needs a non-default config plus precise timing.
2. Any new caller of `CohortStats` inherits the requirement to guard, with nothing in the function or its signature saying so.

**Why is this needed**:

If it is ever reached, the failure is bad out of proportion to its likelihood. The spin holds `c.RLock()`, so the next `c.Lock()` blocks forever, and after that every reader blocks too. That wedges the scheduler cache and stops admission. I have reproduced the spin in a unit test, not the cache wedge.

Calling the function directly hangs at `main` `34de2e998`. `TestCohortCycleRequiredGuards` already builds a borrowing Cohort in a cyclic hierarchy, which is the state needed to reach the walk, so adding one call to the end of it is enough:

```go
if _, err := cache.CohortStats(utiltestingapi.MakeCohort("parent").Obj()); err != nil {
    t.Fatalf("Getting Cohort stats during cycle: %v", err)
}
```

```
panic: test timed out after 30s
	TestCohortCycleRequiredGuards (30s)
```

#15955 removes the walk from this path, so it stops the spin once merged, leaving a stale `WeightedShare` instead. The guard is still missing though. After that change the only thing preventing the spin is that nothing walks the tree any more, so if anyone adds a walk back here it spins again and nothing catches it.
