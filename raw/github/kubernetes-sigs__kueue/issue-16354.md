## Description

TAS currently drops capacity accounting for bound Pods after their Workload stops holding an active quota reservation.

When a TAS Workload is deactivated or finished, the scheduler cache removes the Workload's TAS reservation. If one of the Workload's Pods is still bound to a node and non-terminal, that Pod still consumes physical node resources. However, because the Pod has TAS annotations, the Pod usage controller excludes it from the non-TAS pod usage cache. As a result, TAS snapshots account for the resource in neither Workload TAS usage nor pod usage, and a subsequent TAS Workload can be admitted onto already occupied capacity.

To reproduce the issue, please run the unit tests: https://github.com/kubernetes-sigs/kueue/pull/16355/changes#diff-95ef2b4868044a4fbcc96fcda6df858f3b79548d2e4548fafcd9280114928dfc

## For  extract the shared physical Pod tracker. Preparatory refactor.

The purpose of PR 1 is to extract the existing tracker from WAS to form a reusable base component for subsequent TAS residual occupancy fixes. Elastic replacement metering and residual occupancy scheduling policies are handled by PR 2 and PR 3, respectively.

### 1. For the shared tracker 

Move the implementation to pkg/cache/scheduler/podtracker, removing dependencies on WAS and scheduler-library.

The tracker maintains two indices:

```
Tracker {
    mutex: RWMutex

    pods:
        Map<PodKey, ReadOnlyPod>

    workloadPods:
        Map<WorkloadKey, Map<PodKey, ReadOnlyPod>>
}

PodKey     = (namespace, podName)
WorkloadKey = (namespace, workloadName)
```

The primary index stores observed Pod objects; secondary indices associate Workloads based on WorkloadAnnotation. Complete Pod objects retain information such as UIDs, owner references, nodes, and resource requests for consumers to make determinations.

The responsibilities of the tracker are restricted to state storage:

- Track, Untrack: Update Pods and their associated indices.
- Pods, PodsForWorkload: Read all Pods or Pods associated with a specified Workload.
- Clone: Create a copy with independent indices.
- RemoveWorkload: Remove Pods associated with a specific Workload from the current tracker, used for replacing state in simulated replicas.

Workload annotation associations do not directly prove ownership, nor do they signify that a Pod is covered by a quota reservation. These determinations are made by consumers such as TAS.

### 2. State Updates and Snapshot Isolation

All index updates are performed within the same write lock. When updating an existing Pod, indices are first cleaned up based on the old object before saving the new object, handling annotation changes, annotation deletions, and the replacement of Pods with the same name.

Input Pods are deep-copied on write; stored Pods remain read-only. When cloning, both layers of indices are copied while sharing read-only Pod objects.

```
Track(pod):
    if pod == nil:
        return

    with writeLock:
        key = podKey(pod)

        removeOldPodAndWorkloadIndex(key)

stored = deepCopy(pod)
        pods[key] = stored

        if stored.workloadAnnotation is not empty:
            wlKey = workloadKey(stored)
            getOrCreate(workloadPods[wlKey])[key] = stored

Untrack(key):
    with writeLock:
        old = pods[key]
        removeOldPodAndWorkloadIndex(key)
        return old?.nodeName or ""

Clone():
    with readLock:
        return Tracker {
            pods = shallowCopy(pods)
            workloadPods = {
                wlKey: shallowCopy(podMap)
                for each (wlKey, podMap) in workloadPods
            }
        }
```

This way, when the real-time tracker updates a Pod or deletes an index, it will not alter the already-created simulation snapshot.

### 3. WAS Integration Method

WAS continues to update the real-time tracker through the original Pod event entry point. When creating the simulator, it clones the state and then replaces the real Pods of the assumed Workload with virtual Pods in the replica.

```
WASFactory {
    livePods: Tracker
}

TrackPod(pod):
    livePods.Track(pod)

UntrackPod(key):
    return livePods.Untrack(key)

NewSimulator(nodes, assumedWorkloads):
    state = livePods.Clone()

    for each workload in assumedWorkloads:
        virtualPods = buildVirtualPods(workload)

        if virtualPods is empty:
            continue

        state.RemoveWorkload(workload.key)

        for each pod in virtualPods:
            state.Track(pod)

    snapshot = buildSchedulerSnapshot(nodes, state.Pods())
    return Simulator(snapshot, state)

PreemptWorkload(workloadKey):
    return snapshot.PreemptPods(
        state.PodsForWorkload(workloadKey)
    )
```

Here, RemoveWorkload operates on simulated replicas. The real-time tracker still retains the actually observed Pods for use in subsequent scheduling cycles.

### 4. Integration with Subsequent TAS Fixes

This time, the tracker implementation is shared first, without changing the attribution of real-time instances or placing the TAS metering logic into the tracker.

When PR 3 is integrated later, the following relationships must be observed:

```
Pod events
    -> update physical Pod state

Workload reservation events
    -> update reservation state

Physical Pod state + reservation state
    -> determine residual occupancy
    -> update TAS capacity accounting
```
