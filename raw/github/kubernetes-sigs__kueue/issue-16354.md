## Description

TAS currently drops capacity accounting for bound Pods after their Workload stops holding an active quota reservation.

When a TAS Workload is deactivated or finished, the scheduler cache removes the Workload's TAS reservation. If one of the Workload's Pods is still bound to a node and non-terminal, that Pod still consumes physical node resources. However, because the Pod has TAS annotations, the Pod usage controller excludes it from the non-TAS pod usage cache. As a result, TAS snapshots account for the resource in neither Workload TAS usage nor pod usage, and a subsequent TAS Workload can be admitted onto already occupied capacity.

To reproduce the issue, please run the unit tests: https://github.com/kubernetes-sigs/kueue/pull/16355/changes#diff-95ef2b4868044a4fbcc96fcda6df858f3b79548d2e4548fafcd9280114928dfc
