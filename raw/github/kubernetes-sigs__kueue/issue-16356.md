## Description

**What happened**:

DQO discovery can aggregate more than 128 distinct flavors from valid referenced CapacityProviders, but `status.effectiveCapacity.flavors` has `MaxItems=128`. The status update can be rejected, leaving effective capacity unavailable.

**What you expected to happen**:

DQO handles valid provider configurations without attempting an invalid status update.

**How to reproduce it (as minimally and precisely as possible)**:

Configure three synchronized CapacityProviders with 64, 64, and 1 distinct orchestrated flavors. Reference all three from one DQO. Discovery creates 129 `EffectiveCapacityFlavor` entries, which exceed the status schema limit.

**Anything else we need to know?**:

Consider raising the aggregate limit to cover valid configurations, or adding soft validation that disables the DQO when aggregated flavors exceed the supported limit. Keep the API marker and generated CRDs consistent with the chosen behavior. Add a test for more than 128 distinct flavors. Relevant code: `apis/kueue/v1alpha1/dynamicquotaorchestrator_types.go`, `apis/kueue/v1alpha1/capacityprovider_types.go`, and `pkg/controller/core/dqo/discovery.go`.
