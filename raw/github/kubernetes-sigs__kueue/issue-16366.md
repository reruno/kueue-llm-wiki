## Description

**What would you like to be cleaned**:

Make `WorkloadLevelWaitForPodsReady` safe when the Kueue config omits `waitForPodsReady`. Handle a `kueue.x-k8s.io/wait-for-pods-ready` annotation that specifies `timeoutSeconds` but omits `recoveryTimeoutSeconds`. Check the defaulting and validation paths and `pkg/controller/core/workload_controller.go` (`determineTimeouts`). Add regression coverage for the absent config block.

**Why is this needed**:

The `waitForPodsReady` block is absent by default. In that case, `maxTimeoutOnWorkload` is not defaulted, and the omitted recovery timeout can cause `determineTimeouts` to panic. The controller must not panic; the annotation must either use a defined safe fallback or be rejected with a clear validation error.
