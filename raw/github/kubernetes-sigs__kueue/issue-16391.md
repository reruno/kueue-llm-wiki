## Description

**What happened**:

On the LocalQueue detail page, the "Admitted Workloads" table has two problems:

1. The table header defines two columns (`Name` and `Status`), but each body row only renders one `<TableCell>` (the name link). The `Status` column is never populated, leaving the table misaligned and the workload status invisible.

   - Header: `cmd/kueueviz/frontend/src/LocalQueueDetail.jsx` lines 102-103
   - Body: lines 107-110 (only one `<TableCell>` per row)

2. In `cmd/kueueviz/backend/handlers/local_queue_workloads.go`, `fetchLocalQueueWorkloads` declares `var workloads []any`. When no workloads match the queue, this nil slice serializes to JSON `null` instead of `[]`. On the frontend, `if (workloadsData)` treats `null` as falsy and skips `setWorkloads(...)`, so previously displayed workloads are never cleared from the view after they are removed.

**What you expected to happen**:

1. Each workload row should include a second cell displaying the condition type (matching the Status header), like the main Workloads page does.
2. `fetchLocalQueueWorkloads` should return an empty slice `[]` (not `null`) when no workloads belong to the queue, so the frontend can properly clear stale data.

**How to reproduce it (as minimally and precisely as possible)**:

1. Run KueueViz and navigate to any LocalQueue detail page with workloads.
2. The "Admitted Workloads" table shows a Status header but no status values.
3. Delete all workloads for the queue. The table still shows the old workloads.

**Environment**:
- Kueue version: main at `8a24707ebc`
