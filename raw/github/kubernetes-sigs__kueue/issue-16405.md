## Description

<!-- Please only use this template for submitting clean up requests -->

**What would you like to be cleaned**:

`resources.Requests` (`MapRequests` and `SliceRequests`) hold `int64` values and saturate at `math.MaxInt64`: `Add`, `Sub` and `Mul` go through `SaturatingAdd`, `SaturatingSub` and `SaturatingMul`, and #14520 adds `SaturatingDiv` for `Divide`. Since #15026, `resources.Amount` is exact past the `int64` boundary and is what ClusterQueue, LocalQueue and Cohort usage is accounted in.

Move the values in `Requests` onto `Amount`, so per-workload requests and the usage they feed share one representation, and drop the saturating helpers once nothing uses them.

**Why is this needed**:

The two representations now part ways at the boundary. A Workload whose total overflows `int64` is held as `math.MaxInt64` in `Requests`, so what reaches usage is `math.MaxInt64` rather than the real total, while the quota arithmetic around it is exact. One representation removes that seam and the special cases that guard it (#14371, #14520).

`Amount` is 16 bytes where `int64` is 8, and `Requests` sit on the scheduling hot path, so this should be measured with the existing scheduler benchmarks before switching. Requested by @mimowo as a follow-up to #14520.
