### Comment by [@yuluo-yx](https://github.com/yuluo-yx) — 2026-10-01T02:41:32Z

I think this issue is product bug.

cause in `shouldn't re-admit workload with WaitingForReplacementPods=True and fast admission`. After confirming `BackoffFinished`, the test expects the workload to still not have `QuotaReserved/Admitted`, but actually it was admitted again by the scheduler within about 48ms.

`workload.IsAdmissible` only blocks re-enqueuing when `WaitingForReplacementPods=True`: the release-0.19 logic in `pkg/workload/workload.go` considers it admissible only if `!WaitingForReplacementPods`.
