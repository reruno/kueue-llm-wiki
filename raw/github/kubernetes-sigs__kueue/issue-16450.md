## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

An option to increase the interval used for [requeueing inadmissible workkiads](https://github.com/kubernetes-sigs/kueue/blob/59c8904a016ec3ae257aa599e6dd377b13f8be6c/pkg/cache/queue/inadmissible_workloads.go#L36). I imagine this could land as a ConfigAPI option under scheduler.requeuing.interval. 

In the meanwhile I imagine we can have a FG which hardcodes the interval to 30s and backported, because this is a problem on large clusters.

**Why is this needed**:

 This interval is only 1s by default which is often not enough on large clusters. As a consequence scheduler keeps checking the same "head" workload in every scheduling cycle.

**Completion requirements**:

This enhancement requires the following artifacts:

- [ ] Design doc
- [ ] API change
- [ ] Docs update

The over 120 min `PendingEvaluation` implies that some workloads are not evaluated by kueue-scheduler for a long term which is caused by cq head reset.

Because Kueue injects requeued inadmissible workloads into the head of cqs once the requeuer triggers an inadmissible workload requeue.
