**What happened**:

Running the /merge-main-into-website ChatOps command fails with:                                                                                          
                                                                                                                                                            
```
Automatic merge failed; fix conflicts and then commit the result.
fatal: Unable to create '/home/runner/work/kueue/kueue/.git/index.lock': File exists.
Another git process seems to be running in this repository, or the lock file may be stale
Error: Process completed with exit code 128.
```

**What you expected to happen**:

The action resolves merge conflicts automatically by preferring main, commits the result, and pushes the website branch.

**How to reproduce it (as minimally and precisely as possible)**:

Trigger /merge-main-into-website when the website branch has a rename/delete conflict with main — a conflict that git merge -X theirs cannot resolve on its own and falls into the manual-resolution loop.

**Anything else we need to know?**:

The root cause is a race condition in the conflict-resolution loop in `.github/actions/merge-main-into-website/action.yml`. The process substitution `< <(git diff --name-only --diff-filter=U -z`) starts `git diff` as a background subprocess. Because bash pipes the output lazily, `git diff` may still be running (holding internal git state) when the `while` loop body starts executing `git checkout --theirs` or `git add` – write operations that need to create `index.lock`.
This causes the lock conflict.
