## Description

**What would you like to be added**:

Graduate the `SkipChildJobSuspension` feature gate to Beta and enable it by default after the Alpha evaluation period.

This tracks the follow-up to https://github.com/kubernetes-sigs/kueue/pull/16370, which introduced the feature as Beta and enabled by default. https://github.com/kubernetes-sigs/kueue/pull/16436 changed it to Alpha and disabled by default in v0.20 to allow more time to evaluate the behavior.

@kevin85421 may revisit this in a few months; no target release or firm deadline is set.

**Why is this needed**:

With `SkipChildJobSuspension` enabled, the generic job reconciler leaves managed child-job lifecycle management to the ancestor's controller. This avoids suspending a running child (for example, a RayJob's RayCluster) during MultiKueue Workload-slice replacement when the old Workload is finished before the replacement is claimed, even though the replacement already has admission.

Keep a dedicated tracking issue for evaluating this behavior and promoting it to Beta once it is ready.

**Completion requirements**:

- [ ] Evaluate child-job lifecycle behavior with the feature enabled, including ancestor Workload absence or loss of admission and MultiKueue Workload-slice replacement.
- [ ] Address any issues found during Alpha evaluation and confirm sufficient test coverage.
- [ ] Promote the feature gate to Beta and enable it by default in the agreed future release, updating the versioned feature-gate lists and lifecycle reference.
- [ ] Update documentation and release notes for the graduation.

The artifacts should be linked in subsequent comments.

A new design doc or API change is not currently anticipated for this feature-gate graduation; confirm this during evaluation.
