## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

A new `integrations.annotationKeysToCopy` field in the Kueue Configuration, analogous to `integrations.labelKeysToCopy` ([KEP-1834](https://github.com/kubernetes-sigs/kueue/tree/36c42c8dfc10abcf90b15fa9c7cba6e28038b471/keps/1834-copy-labels-into-workload)). This is a list of annotation keys copied from the job object into the Workload at creation time, for every integration.

- Same semantics as `labelKeysToCopy`. Missing keys are skipped, values are copied only at creation, and pods in a pod group must agree on a listed key's value.
- Independent of the `CustomMetricLabels` feature gate. With the gate on, the copied set is the union of this list and the `metrics.customLabels` annotation sources.
- Keys under the reserved `kueue.x-k8s.io/` prefix are rejected at configuration validation.
- No feature gate: an empty list (the default) changes nothing.

**Why is this needed**:

Currently, an annotation reaches the Workload only as a `metrics.customLabels` source, which ties a general need to an alpha metrics feature. Labels have had a gate-independent option since [KEP-1834](https://github.com/kubernetes-sigs/kueue/tree/36c42c8dfc10abcf90b15fa9c7cba6e28038b471/keps/1834-copy-labels-into-workload). Annotations should have the same. Here is the original context: #16187 (fix for #13277).
