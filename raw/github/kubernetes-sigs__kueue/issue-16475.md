**What would you like to be added**:
A /update-krew-index ChatOps command on release issues that allows the release team to manually trigger a krew-index PR for a given release version.

**Why is this needed**:
When two releases land close together (e.g. v0.19 and v0.20), the krew-release bot creates two concurrent PRs against kubernetes-sigs/krew-index. The first to merge shifts the base, leaving the second PR stuck with conflicts that the bot will not auto-resolve. There is currently no way to re-trigger the krew-index update without cutting a new release. A dedicated ChatOps command lets the release team close the conflicted PR and recreate it on demand.

**Completion requirements**:
  - [ ] Add /update-krew-index command to release-utils.yml
