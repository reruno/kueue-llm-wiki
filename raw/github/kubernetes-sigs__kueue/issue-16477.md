## Description

/king bug

This is a follow up to track the fixes initially proposed in https://github.com/kubernetes-sigs/kueue/pull/15026 that I decided to de-couple during review:
1.  **Invalid integer shares** -Very large computed shares can produce invalid, potentially negative values when converted to `int64` , see code: 
2.  **Incorrect ordering of zero-weight borrowers** -  A zero-weight CQ or Cohort that is borrowing but has a calculated borrowing ratio of zero can receive share `0` instead of `+Inf`.

These could probably be fixed in separate PRs, ideally with integration or high-level unit tests.
