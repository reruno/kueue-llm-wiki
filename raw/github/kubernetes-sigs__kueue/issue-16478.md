## Description

## Goal

KEP-12100 ("Partial Replica ScaleUp for ElasticJob") Alpha only supports `RayJob`/`RayService`/`RayCluster`. 
Beta graduation requires adding `batch/v1 Job` support. 
Enabling `elastic-job` on a Job today does not guarantee the Job is actually in a state where Kubernetes will accept a live
parallelism/completions change.
Moreover the shared ungater's Pod-selection logic was designed before any integration had a completion-index concept to respect.
We need to close those gaps so `batch.Job `partial scale-up works end-to-end with the same guarantees as the Ray integrations.

Relates to #12100

## Tasks

- [ ] **KEP 12100 update.** 
`keps/12100-partial-scaleup-for-elasticjob/README.md` currently states only `RayJob`/`RayService`/`RayCluster` support partial scale-up. 
Add a Job-specific design section and update the Beta graduation criteria checklist item ("Add integration for batch.Job").

- [ ] **Webhook validation for Indexed + synced completions.** 
`batch/v1` only allows mutating `.spec.parallelism` on an already-running Job together with `.spec.completions`, and only under `completionMode: Indexed`.
Nothing today stops a user from setting `kueue.x-k8s.io/elastic-job: "true"` on a `NonIndexed` Job, 
or an `Indexed` Job whose `completions`/`parallelism` aren't kept in sync. 
Add a check (mirroring RayCluster's `validateElasticJob`) requiring Indexed mode and `completions == parallelism` whenever `elastic-job` is enabled for a Job.

- [ ] **Completion-index-aware ungating.** 
`pkg/controller/elasticjobs/elastic_job_ungater.go` picks which gated Pods to release by sorting on Pod name. 
For an Indexed Job, the completion index lives in the `batch.kubernetes.io/job-completion-index` Pod label, which has no relation to the Pod's randomly-suffixed name.
Because the built-in Job controller counts gated-but-existing Pods against `.spec.parallelism`, an arbitrary name-based selection can leave specific completion indices gated indefinitely while others run — stalling `.spec.completions` even when enough quota was granted overall.
The ungater needs to prefer the lowest completion index when the label is present, without changing the existing name-based behavior for RayCluster/RayJob/RayService (which have no completion-index concept).

- [ ] **Integration test for a live parallelism/completions scale-up.**
Add a test mirroring `raycluster_controller_partial_scaleup_test.go`'s partial scale-up flow for the Job integration.
