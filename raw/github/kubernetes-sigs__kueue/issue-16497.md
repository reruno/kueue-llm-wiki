## Description

**What happened**:

With the `FailureRecoveryPolicy` feature gate enabled, the pod termination controller sets a `KueueFailureRecovery` condition and emits a `Warning` event when it force-terminates a Pod on an unreachable node. The grace period in that message is wrong whenever the Pod has a non-zero `deletionGracePeriodSeconds`.

For a Pod deleted with a 30s grace period, both the condition and the event say:

```
Pod forcefully terminated after 1m0.00000003s grace period due to unreachable node `unreachable-node` (triggered by `kueue.x-k8s.io/safe-to-forcefully-delete` annotation)
```

The cause is in `pkg/controller/failurerecovery/pod_termination_controller.go`:

```go
totalDeletionGracePeriod := time.Duration(ptr.Deref(pod.DeletionGracePeriodSeconds, 0)) + r.forcefulTerminationGracePeriod
```

`DeletionGracePeriodSeconds` is a number of seconds, but `time.Duration(n)` is `n` nanoseconds, so 30 becomes 30ns.

Only the message is wrong. The controller decides when to terminate from `deletionTimestamp + forcefulTerminationGracePeriod`, so termination timing is not affected.

**What you expected to happen**:

`Pod forcefully terminated after 1m30s grace period ...`, which is 30s `deletionGracePeriodSeconds` plus the 1m forceful termination grace period.

KEP-6757 (`keps/6757-failure-recovery/README.md`, Observability) defines the message as "grace period = `terminationGracePeriodSeconds` + 60s" and gives the example `terminationGracePeriodSeconds: 30` -> "Pod forcefully terminated after 90s grace period ...".

**How to reproduce it (as minimally and precisely as possible)**:

Add a case to `TestReconciler` in `pkg/controller/failurerecovery/pod_termination_controller_test.go` that is the same as "forceful termination grace period elapsed for pod", but with `pod.DeletionGracePeriodSeconds = 30` and an expected message of `1m30s`. Then run:

```
go test ./pkg/controller/failurerecovery/ -run 'TestReconciler' -count=1
```

On main (36c42c8d) the case fails, for both the condition and the event:

```
  "Pod forcefully terminated after 1m",
- "30",
+ "0.00000003",
  "s grace period due to unreachable node `unreachable-node` (trigg",
```

The existing test cases never set `DeletionGracePeriodSeconds`, which is why they all expect `1m0s` and do not catch this.

**Anything else we need to know?**:

Suggested fix: multiply by `time.Second`:

```go
totalDeletionGracePeriod := time.Duration(ptr.Deref(pod.DeletionGracePeriodSeconds, 0))*time.Second + r.forcefulTerminationGracePeriod
```

I have this fix and a regression test case ready locally and can open a PR.
