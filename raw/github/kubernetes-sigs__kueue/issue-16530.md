## Description

**What happened**:

For a Cohort with `fairSharing.weight: 0` that borrows, `kueue_cohort_weighted_share` reports `+Inf`, while its help text says "If the Cohort has a weight of zero and is borrowing, this will return NaN." For a ClusterQueue in the same state, `kueue_cluster_queue_weighted_share` reports `NaN`, as its help text says.

**What you expected to happen**:

The Cohort metric to match its help text, and both metrics to report the same value for the same state. I don't know whether NaN or +Inf is the intended value.

**How to reproduce it (as minimally and precisely as possible)**:

1. Enable fair sharing. Create a Cohort `root` with a nominal quota of 4 CPU, a Cohort `child` with `fairSharing.weight: 0` and `parentName: root`, and a ClusterQueue in `child` with `fairSharing.weight: 0` and a nominal quota of 0 CPU.
2. Admit a workload that requests 2 CPU in that ClusterQueue.
3. Check the two metrics. In the integration suite the gauges hold:

```
kueue_cluster_queue_weighted_share{cluster_queue="<cq>",cohort="child",replica_role="standalone"} NaN
kueue_cohort_weighted_share{cohort="child",replica_role="standalone"} +Inf
```

The status of the `child` Cohort shows `weightedShare: 9223372036854775807`.

**Anything else we need to know?**:

The ClusterQueue reporting turns `+Inf` into `NaN` before it sets the gauge (https://github.com/kubernetes-sigs/kueue/blob/5cb82c5a4159007df57ebb7649160da5c4dc5c66/pkg/cache/scheduler/clusterqueue.go#L622, https://github.com/kubernetes-sigs/kueue/blob/5cb82c5a4159007df57ebb7649160da5c4dc5c66/pkg/controller/core/clusterqueue_controller.go#L567), while the Cohort reporting passes the share through (https://github.com/kubernetes-sigs/kueue/blob/5cb82c5a4159007df57ebb7649160da5c4dc5c66/pkg/cache/scheduler/cache.go#L624, https://github.com/kubernetes-sigs/kueue/blob/5cb82c5a4159007df57ebb7649160da5c4dc5c66/pkg/controller/core/cohort_controller.go#L261). I couldn't find a test that checks the Cohort metric for a zero-weight Cohort. #16488 adds one more state that reaches this path, a zero-weight Cohort that borrows only resources with nothing lendable, and mentions the difference in its notes.

Related: #16477

I checked the git history and confirmed that `NaN` is indeed the intended value here:

- In #7338 (`4d8832042`, *"report NaN instead of max_int when weight is 0"*), both `ClusterQueueWeightedShare` and `CohortWeightedShare` help strings in `pkg/metrics/metrics.go` were updated to specify `NaN`, and the `if weightedShare == math.Inf(1) { weightedShare = math.NaN() }` conversion was added to `ClusterQueueReconciler.updateCqStatusIfChanged`, but was missed in `CohortReconciler.updateCohortStatusIfChanged`.
- Later, #10552 (`b13b07c86`) mirrored the controller logic into `Cache.ResyncCohortGaugeMetrics`, carrying over the same omission.

I have a fix and tests ready and will open a PR shortly!
