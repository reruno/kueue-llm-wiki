## Description

**What happened**:

When a ClusterQueue or MultiKueueCluster is deleted, three MultiKueue counters keep their series, while the other ClusterQueue counters and the MultiKueue gauge are removed:

| Metric | Type | Series removed after deletion |
|---|---|---|
| `kueue_admitted_workloads_total` | Counter | Yes |
| `multikueue_cluster_status` | Gauge | Yes |
| `multikueue_workloads_dispatched_total` | Counter | No |
| `multikueue_workloads_admitted_total` | Counter | No |
| `multikueue_workloads_evicted_total` | Counter | No |

- If a ClusterQueue or MultiKueueCluster is recreated with the same name, the counters continue from the old values instead of starting from zero.
- If it is not recreated, the old series stay with frozen values until the manager restarts, so deleted ClusterQueues and worker clusters still appear when listing label values (for example in Grafana variables).

**What you expected to happen**:

When a ClusterQueue or MultiKueueCluster is deleted, its series in these three counters are removed, the same as for the MultiKueue gauges and the regular ClusterQueue counters.

**How to reproduce it (as minimally and precisely as possible)**:

```shell
# 0. Set up MultiKueue with one manager and one worker cluster, using
#    ClusterQueue "cluster-queue", LocalQueue "default/user-queue",
#    and MultiKueueCluster "multikueue-test-worker1"

# 1. On the manager, allow metrics access and port-forward the metrics endpoint
$ kubectl create clusterrolebinding kueue-metrics-reader-rolebinding \
    --clusterrole=kueue-metrics-reader --serviceaccount=kueue-system:kueue-controller-manager
$ TOKEN=$(kubectl -n kueue-system create token kueue-controller-manager)
$ kubectl -n kueue-system port-forward svc/kueue-controller-manager-metrics-service 8443:8443 &

# 2. Run a Job through MultiKueue
$ cat <<EOF | kubectl create -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: sample-job
  namespace: default
  labels:
    kueue.x-k8s.io/queue-name: user-queue
spec:
  template:
    spec:
      restartPolicy: Never
      containers:
      - name: main
        image: busybox:1.36
        command: ["sleep", "10"]
        resources:
          requests:
            cpu: 100m
EOF
$ kubectl -n default wait --for=condition=Complete job/sample-job

# 3. Obtain metrics
$ curl -ks -H "Authorization: Bearer $TOKEN" https://127.0.0.1:8443/metrics \
    | grep -E '^(kueue_admitted_workloads_total|multikueue_workloads_(admitted|dispatched)_total)\{.*cluster_queue="cluster-queue"'
kueue_admitted_workloads_total{cluster_queue="cluster-queue",priority_class="",replica_role="leader"} 1
multikueue_workloads_admitted_total{cluster="multikueue-test-worker1",cluster_queue="cluster-queue",replica_role="leader"} 1
multikueue_workloads_dispatched_total{cluster="multikueue-test-worker1",cluster_queue="cluster-queue",replica_role="leader"} 1

# 4. Delete the LocalQueue, ClusterQueue, and MultiKueueCluster, then obtain metrics again
$ kubectl delete localqueue -n default user-queue
$ kubectl delete clusterqueue cluster-queue
$ kubectl delete multikueuecluster multikueue-test-worker1
# OUTPUT: kueue_admitted_workloads_total is gone, but the MultiKueue counters remain
multikueue_workloads_admitted_total{cluster="multikueue-test-worker1",cluster_queue="cluster-queue",replica_role="leader"} 1
multikueue_workloads_dispatched_total{cluster="multikueue-test-worker1",cluster_queue="cluster-queue",replica_role="leader"} 1

# 5. Recreate the objects with the same names, delete and rerun the Job from step 2, then obtain metrics again
# OUTPUT: kueue_admitted_workloads_total starts from 1, but the MultiKueue counters continue from the old values
kueue_admitted_workloads_total{cluster_queue="cluster-queue",priority_class="",replica_role="leader"} 1
multikueue_workloads_admitted_total{cluster="multikueue-test-worker1",cluster_queue="cluster-queue",replica_role="leader"} 2
multikueue_workloads_dispatched_total{cluster="multikueue-test-worker1",cluster_queue="cluster-queue",replica_role="leader"} 2
```

**Anything else we need to know?**:

- The MultiKueue ClusterQueue reconciler, which calls `ClearMultiKueueClusterQueueMetrics` when a ClusterQueue is deleted, is only registered when the `MultiKueueManagerQuotaAutomation` feature gate (alpha, off by default) is enabled. With default settings, only `ClearClusterQueueMetrics` runs on ClusterQueue deletion.
- History: the counters were added in #12782 and #13050, and the MultiKueue cleanup functions were added later in #13798 for the `multikueue_cluster_status` gauge, which may be why the counters were not covered.
