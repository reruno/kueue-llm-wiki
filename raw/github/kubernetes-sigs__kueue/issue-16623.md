## Description


**What happened**:

When an elastic Job is scaled up, the old workload slice is replaced by a new one, but `kueue_replaced_workload_slices_total` never appears on the metrics endpoint. Other ClusterQueue counters for the same scale-up are reported:

| Metric | Type | Documented | Exposed on `/metrics` |
|---|---|---|---|
| `kueue_admitted_workloads_total` | Counter | Yes | Yes |
| `kueue_replaced_workload_slices_total` | Counter | Yes | No |

**What you expected to happen**:

`kueue_replaced_workload_slices_total` is exposed on `/metrics` and is incremented each time a workload slice is replaced, as described in the [metrics reference](https://kueue.sigs.k8s.io/docs/reference/metrics/).

**How to reproduce it (as minimally and precisely as possible)**:

```shell
# 0. Install Kueue with default settings (ElasticJobsViaWorkloadSlices is enabled by default since v0.18),
#    and create ResourceFlavor "default-flavor", ClusterQueue "cluster-queue" (cpu nominalQuota: 2),
#    and LocalQueue "default/user-queue"

# 1. Allow metrics access and port-forward the metrics endpoint
$ kubectl create clusterrolebinding kueue-metrics-reader-rolebinding \
    --clusterrole=kueue-metrics-reader --serviceaccount=kueue-system:kueue-controller-manager
$ TOKEN=$(kubectl -n kueue-system create token kueue-controller-manager)
$ kubectl -n kueue-system port-forward svc/kueue-controller-manager-metrics-service 18443:8443 &

# 2. Create an elastic Job with parallelism 1
$ cat <<EOF | kubectl create -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: sample-elastic-job
  namespace: default
  labels:
    kueue.x-k8s.io/queue-name: user-queue
  annotations:
    kueue.x-k8s.io/elastic-job: "true"
spec:
  parallelism: 1
  template:
    spec:
      restartPolicy: Never
      containers:
      - name: main
        image: busybox:1.36
        command: ["sleep", "600"]
        resources:
          requests:
            cpu: 100m
EOF
$ kubectl -n default get workloads
NAME                           QUEUE        RESERVED IN     ADMITTED   FINISHED   AGE
job-sample-elastic-job-a0386   user-queue   cluster-queue   True                  8s

# 3. Scale the Job up to parallelism 2; the old slice is replaced by the new one
$ kubectl -n default patch job sample-elastic-job --type=merge -p '{"spec":{"parallelism":2}}'
$ kubectl -n default get workloads
NAME                           QUEUE        RESERVED IN     ADMITTED   FINISHED   AGE
job-sample-elastic-job-9ca1b   user-queue   cluster-queue   True                  11s
job-sample-elastic-job-a0386   user-queue   cluster-queue   True       True       32s
$ kubectl -n default get events --field-selector reason=WorkloadSliceReplaced \
    -o custom-columns=OBJECT:.involvedObject.name,REASON:.reason,MESSAGE:.message
OBJECT                         REASON                  MESSAGE
job-sample-elastic-job-a0386   WorkloadSliceReplaced   Replaced to accommodate a workload (UID: f81429d4-dc80-4dd7-83da-a9acc3ac2f95, JobUID: 08c38f44-0c4a-475c-9349-36b08212820b) due to workload slice aggregation

# 4. Obtain metrics
$ curl -ks -H "Authorization: Bearer $TOKEN" https://127.0.0.1:18443/metrics \
    | grep -E '^kueue_(admitted_workloads_total|replaced_workload_slices_total)\{'
# OUTPUT: kueue_admitted_workloads_total counts both slices, but kueue_replaced_workload_slices_total is missing
kueue_admitted_workloads_total{cluster_queue="cluster-queue",priority_class="",replica_role="leader"} 2
$ curl -ks -H "Authorization: Bearer $TOKEN" https://127.0.0.1:18443/metrics | grep -c 'replaced_workload_slices'
0
```

**Anything else we need to know?**:

- History: the counter was added in #5510 (v0.13.0) together with the initial KEP-77 implementation, but it was never added to `Register()`. KEP-77 lists it as a completed Beta criterion ("Metrics for slice lifecycle transitions (`replaced_workload_slices_total`)").
