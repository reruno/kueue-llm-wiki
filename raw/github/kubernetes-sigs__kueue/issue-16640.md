## Description

**What would you like to be cleaned**:

Follow up on @tenzen-y's comments in [PR #16379](https://github.com/kubernetes-sigs/kueue/pull/16379):

- In `pkg/metrics/localqueue.go`, define a dedicated error for invalid LocalQueue metrics selectors and wrap it when `NewLocalQueueMetricsConfig` rejects a selector. Preserve the underlying parsing error and configuration-path context. [Review comment](https://github.com/kubernetes-sigs/kueue/pull/16379#discussion_r4174529276).
- In `pkg/metrics/localqueue_test.go`, change `wantErr` from `bool` to `error`. Replace the error-presence assertion with `cmp.Diff` and `cmpopts.EquateErrors()` to distinguish expected errors. [Error type comment](https://github.com/kubernetes-sigs/kueue/pull/16379#discussion_r4174531541), [comparison comment](https://github.com/kubernetes-sigs/kueue/pull/16379#discussion_r4174532534).

Acceptance criteria: Tests distinguish the dedicated selector error from unrelated errors and retain coverage for nil configuration, valid selectors, and disabled metrics. Invalid enabled selectors must still fail startup.

**Why is this needed**:

A dedicated error makes selector failures identifiable. Error-aware assertions verify the expected failure rather than accepting any error.
