## Description

**What happened**:

On a MultiKueue worker cluster, an elastic RayCluster Workload slice was replaced successfully, but the old slice's `Finished=True` condition contained an empty `JobUID`:

```text
Replaced to accommodate a workload (UID: <replacement-workload-uid>, JobUID: ) due to workload slice aggregation
```

The condition reason was `WorkloadSliceReplaced`. The replacement Workload subsequently had the correct `kueue.x-k8s.io/job-uid` label and RayCluster controller owner reference, but the old slice's message remained unchanged.

The replacement completed successfully and the RayCluster remained ready. This appears to be a condition-message observability defect rather than a failed replacement or admission. The issue is consistent with the controller ordering described below.

**What you expected to happen**:

The replacement message should handle a temporarily unavailable Job UID explicitly, for example by displaying `UNKNOWN` or omitting the field. Including the replacement Workload's namespace/name would also make the message easier to use for troubleshooting.

A valid MultiKueue lifecycle should not leave an unexplained blank identifier in a persistent condition message.

**How to reproduce it (as minimally and precisely as possible)**:

1. Configure MultiKueue with elastic RayCluster workload slices enabled.
2. Run an elastic RayCluster on a worker cluster and trigger a resize that creates a replacement slice on the manager, which MultiKueue dispatches to the worker.
3. Allow the worker scheduler to admit the replacement before the worker job controller attaches its owner reference and Job UID label. This ordering is timing-dependent.
4. Inspect the old slice's `Finished` condition: the replacement Workload UID is populated, but `JobUID` is empty.
5. Inspect the replacement after the job controller reconciles it: the Job UID label and RayCluster ownership are present, while the old slice's message still contains the blank value.

**Anything else we need to know?**:

The local source inspection matches the observed ordering:

- `cloneForCreate` in `pkg/controller/admissionchecks/multikueue/workload.go` explicitly deletes `constants.JobUIDLabel` from worker Workload copies.
- `EnsurePrebuiltWorkloadOwnership` in `pkg/controller/jobframework/reconciler.go` attaches the worker job's controller reference and Job UID label later.
- `replaceWorkloadSlice` in `pkg/scheduler/scheduler.go` directly interpolates `newSlice.Labels[controllerconstants.JobUIDLabel]` without handling an absent/empty label.
- In contrast, the preemption message formatter in `pkg/scheduler/preemption/preemption.go` uses `UNKNOWN` when the Job UID is unavailable.

These code paths explain why a replacement can succeed while recording the empty field. Deployment-specific identifiers and operational metadata are omitted from this report.
