## Description

**What happened**:

MultiKueue dispatches Plain Pods by copying an already-admitted manager Pod. Manager ServiceAccount-injected `imagePullSecrets` and OpenShift SCC-assigned user IDs can therefore reach the worker, where they may be invalid.

Affected code: `syncLocalPodWithRemote` in `pkg/controller/jobs/pod/pod_multikueue_adapter.go` copies `localPod.Spec` into the worker Pod.

**What you expected to happen**:

Worker admission should apply worker-local defaults and security policy, without reusing manager-only admission mutations. Update the Plain Pod dispatch path to distinguish these mutations from explicit user settings. Add regression coverage for injected image pull secrets and SCC-assigned user IDs while preserving explicit user configuration.

**How to reproduce it (as minimally and precisely as possible)**:

1. Configure MultiKueue Plain Pods across manager and worker clusters with different ServiceAccount image pull secrets or OpenShift SCC defaults.
2. Submit a Pod without explicit image pull secrets or user IDs.
3. Inspect the dispatched worker Pod for manager-injected values.

This reproduction follows the report in #16504; it has not been independently executed.

**Anything else we need to know?**:

Dependency synchronization is out of scope.
