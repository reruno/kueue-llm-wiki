## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

A KubeVirt `VirtualMachine` integration, so Kueue can queue, admit and preempt VMs the way it does Jobs. Suspend maps to `runStrategy: Halted`, quota is charged from the VM spec, and already-running VMs are adopted and counted rather than halted.

**Why is this needed**:

DRA is making GPUs partitionable and assignable to VMs. Once a node offers many GPU partitions, nothing stops one tenant claiming all of them. Hardware isolation and topology-aware placement are being solved upstream. Quota across tenants is not.

KubeVirt's `application-aware-quota` and `managed-tenant-quota` are namespace-scoped accounting. They give no borrowing with reclaim, no priority or preemption across tenants, no shared accounting with the containers on the same nodes, and no device or topology feasibility check at admission. Kueue already has all four. `managed-tenant-quota` exists only because quota cannot model a live-migration target that briefly coexists with the source, which Kueue already models for elastic scale-up.

The plain pod integration is not a workaround: with `runStrategy: Always` KubeVirt recreates the VMI after each eviction, so eviction repeats and the backoff resets.
