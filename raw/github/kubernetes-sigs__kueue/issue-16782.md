## Description

**What happened**:
`FinishWorkloads` in `test/util/behavioral/workload.go` fetches `newWL`, but appends the Finished condition to the caller's `w.Status.Conditions`. Updating status can discard server-added conditions and reuse the caller's backing array.

**What you expected to happen**:
Append the Finished condition to the freshly fetched `newWL.Status.Conditions`. Preserve existing server conditions and leave the caller's conditions unchanged.

**How to reproduce it (as minimally and precisely as possible)**:
1. Keep a Workload object whose conditions are stale.
2. Add a condition to that Workload on the server.
3. Call `FinishWorkloads` with the stale object.
4. Observe that the status update drops the server-added condition.

**Anything else we need to know?**:
Acceptance criteria: `FinishWorkloads` uses the fetched conditions; a regression test confirms that server-added conditions remain and the caller's conditions do not change.
