## Description

**What happened**:
In `test/util/behavioral/objects.go`, `SetNodeCondition` appends a missing node condition but leaves the local `condition` pointer nil. Subsequent field accesses can panic.

**What you expected to happen**:
The helper should add and update a missing condition without a panic. After appending, set `condition` to the appended entry and preserve the existing changed-state behavior.

**How to reproduce it (as minimally and precisely as possible)**:
Call `SetNodeCondition` for a node whose status does not contain `newCondition.Type`.

**Anything else we need to know?**:
Acceptance criteria: add regression coverage for an absent condition and confirm that existing-condition updates still work.
