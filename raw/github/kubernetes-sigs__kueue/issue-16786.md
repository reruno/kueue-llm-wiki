## Description

**What happened**:
In `test/integration/framework/framework.go`, `verifyLogs` checks only concurrent-modification errors and ignores other errors. It drains a filtered copy, leaving the shared observer unchanged.

**What you expected to happen**:
Drain the shared `observedLogs` with `TakeAll`, then reject error-level or higher entries except concurrent-modification errors.

**How to reproduce it (as minimally and precisely as possible)**:
Pass an observer containing a concurrent-modification error to `verifyLogs`: it fails. Pass one containing another error: it passes. The original observer retains both kinds of entries.

**Anything else we need to know?**:
Acceptance criteria:
- Concurrent-modification errors and logs below error level pass verification.
- Other error-level or higher entries fail verification.
- Verification drains the shared observer, so later teardowns do not recheck old entries.
