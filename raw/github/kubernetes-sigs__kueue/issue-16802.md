## Description

**What would you like to be cleaned**:

Improve unit-test runtime by balancing test packages between shards based on measured runtime rather than package-count round-robin assignment.

- Measure package runtimes and identify the main sources of shard imbalance.
- Update unit-test shard assignment in `hack/testing/shard-unit-tests.sh` and, if needed, `hack/testing/shard_test_packages.sh` and `hack/make/test.mk`. Preserve integration-test behavior because the package-sharding helper is shared.
- Verify that each unit-test package runs exactly once across shards.
- Compare repeated CI runs with comparable resources. Show a smaller runtime gap between shards and a lower maximum shard runtime.

**Why is this needed**:

In #16794, shard 0 reportedly ran for roughly 14 minutes while shard 1 ran for roughly 7 minutes, both with a 3400m CPU request. Shard 0 also exceeded the 14-minute CI runtime threshold. Better balancing should reduce unit-test completion time. This cleanup is separate from the immediate CPU increase discussed there.
