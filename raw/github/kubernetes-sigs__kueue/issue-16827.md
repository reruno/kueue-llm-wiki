## Description

**What would you like to be cleaned**:

Investigate splitting `hack/releasing/milestone_pull.sh` into explicit, independent phases:
- `--create-milestone v0.21.0`: create only the next minor milestone.
- `--create-pr v0.21.0`: create only the test-infra mapping PR.
- `v0.21.0` without flags: retain the PR-only default.

Acceptance criteria:
- Each phase checks only its own prerequisites. Milestone-only mode does not require a test-infra checkout.
- PR-only mode makes no milestones API calls. Preserve dry-run behavior and milestone idempotency.
- Update usage and tests in `hack/testing/milestone_pull_test.sh`. Document how the flags interact with `CREATE_MILESTONE` and `SKIP_PR`.
- Update `.github/ISSUE_TEMPLATE/NEW_RELEASE.md` with the local milestone command as an alternative to `/create-milestone`.
- Evaluate sharing milestone logic with `.github/workflows/release-utils.yml` and its create-milestone action without changing ChatOps authorization.

**Why is this needed**:

Explicit phases make the release checklist clearer and reduce coupling and duplicate logic. This is a non-blocking follow-up to [PR #16714](https://github.com/kubernetes-sigs/kueue/pull/16714), not a prerequisite for that PR.
