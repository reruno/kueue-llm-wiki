## Description

Several CQ/LQ lifecycle paths can leave metrics out of sync with the current queue state. I'd like to track the remaining gaps here and address them in separate, focused PRs. These cases do not necessarily share the same root cause.

### Reproduced on main

Verified locally against `9b87bcc03b2e67f547046a46b3721e8ab0d24bab`:

- [ ] **CQ/LQ custom-label updates can miss a metric refresh.** If `Reconcile` stores the new labels before the corresponding `Update` handler runs, `CQStore`/`LQStore` reports no change. The handler then skips cleanup/resync, leaving the old label series. Deterministic tests reproduce this for both queue types; the opposite event order passes.
- [ ] **Deleting a CQ leaves its remaining LQs' pending metrics inconsistent with a resync.** With one pending Workload, deleting its CQ leaves the LQ reporting `inadmissible=1`, while the existing resync path computes zero. We should clarify the intended metric semantics when the referenced CQ is missing before choosing the fix.
- [ ] **Deleting and recreating a CQ can leave stale unadmitted series.** With a CQ-sourced custom label, a Workload becoming `Misconfigured` while the CQ is absent can create a series with an empty custom-label value. After recreation, cleanup uses the restored label value and misses that old series. One Workload then contributes both an old `Misconfigured` series and a current `PendingEvaluation` series, each with value 1.

The deletion/recreation cases also reproduce in envtest with the core controllers running. Local diagnostic patches make the corresponding tests pass with `-race`; they still need to be developed into reviewed fixes.

### Existing work

- #15576 — pending metric refresh across LQ lifecycle changes.
- #16833 — pending metric refresh when CQs stop or resume.
- #16670 — stale pending series with Workload-sourced custom labels after CQ stop/resume.

### Further coverage

Resource usage/quota metrics and replica-role transitions still need the same lifecycle checks. These are audit targets, not confirmed bugs. Follow-up issues and PRs can be linked here as each case is verified.
