## Description

**What would you like to be added**:

Add Prometheus metrics to track DRA (Dynamic Resource Allocation) device reservations and requests per ClusterQueue and LocalQueue, including:

1. `kueue_cluster_queue_dra_devices_reserved`: A gauge reporting the number of DRA devices currently reserved by admitted workloads, labeled by `cluster_queue`, `device_class`, and `flavor`.
2. `kueue_cluster_queue_dra_devices_pending`: A gauge reporting the number of DRA devices requested by pending workloads in the queue, labeled by `cluster_queue` and `device_class`.
3. Optionally `kueue_local_queue_dra_devices_reserved`: Analogous gauge at the LocalQueue level.

**Why is this needed**:

With the adoption of DRA for accelerators (GPUs, MIG, specialized hardware), operators need visibility into how many devices are allocated and how many are waiting in queues.

Currently, Kueue exposes `kueue_cluster_queue_resource_usage` and `kueue_cluster_queue_resource_reservation` for standard and mapped resources. However:
- Logical resource metrics aggregate counts under mapped quota names, masking which underlying `device_class` is consuming capacity.
- There is no direct visibility into pending DRA device demand when workloads are queued.
- Monitoring dashboards (Grafana) and cluster autoscaling alerts cannot distinguish between standard extended resources and DRA-managed devices.

Having dedicated gauges with `device_class` labels allows operators to set up alerts for device exhaustion and track device utilization over time.

**Completion requirements**:

- [ ] Define the Prometheus metrics in `pkg/metrics/metrics.go` with appropriate labels (`cluster_queue`, `device_class`, `flavor`, `replica_role`).
- [ ] Update the workload reconciler and queue manager to record/release DRA device reservations upon admission and finish/eviction.
- [ ] Update pending workload accounting to record requested DRA devices.
- [ ] Add unit and integration tests covering the new metrics under `pkg/metrics` and `test/integration`.
- [ ] Update metrics documentation (`site/content/en/docs/reference/metrics.md`).
