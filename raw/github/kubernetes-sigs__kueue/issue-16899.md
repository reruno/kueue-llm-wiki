## Description

**What would you like to be cleaned**:

Address the four remaining review comments from [PR #16690](https://github.com/kubernetes-sigs/kueue/pull/16690) in `hack/releasing/create_release_tag_test.py`:

- [ ] Select the action step by `id == "tag"` instead of `runs.steps[0]`. [Review comment](https://github.com/kubernetes-sigs/kueue/pull/16690#discussion_r4214562071)
- [ ] Guard `args[0]` with `args and` in the Git wrapper checks for [`ls-remote`](https://github.com/kubernetes-sigs/kueue/pull/16690#discussion_r4214579515), [`tag`](https://github.com/kubernetes-sigs/kueue/pull/16690#discussion_r4214581133), and [`push`](https://github.com/kubernetes-sigs/kueue/pull/16690#discussion_r4214582850).
- [ ] Verify that inserting a preceding action step still selects the tag script, empty Git arguments do not cause `IndexError`, and the existing release utility tests pass.

**Why is this needed**:

Step selection by position can silently select the wrong script after the action changes. Unguarded argument indexing can fail before Git handles an empty argument list. These changes make the test harness more robust without changing release-tag behavior.
