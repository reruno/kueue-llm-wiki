## Description

**What would you like to be added**:
I would like to add KEP for Preemption Limits - a new functionality limiting number of allowed preemptions in time window defined by the cluster admin.


**Why is this needed**:
In new Configurable Preemptions - currently in Alpha -  mis-configurations can lead to cascading preemptions of workloads in the cluster.  It would be good to have guardrails in place to make the new rules & configs graduation safer.

In the first version it will work just with configurable preemptions, but in future it may be also extended to regular classic ones or fair sharing ones, as the concept itself is orthogonal. (E.g. If we have representation of existing preemption rules as configurable preemptions it may be supported out of the box)

**Completion requirements**:
There is a KEP for Preemption Limits in the repository.
