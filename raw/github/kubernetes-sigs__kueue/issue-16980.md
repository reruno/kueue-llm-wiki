## Description

**What happened**:

When creating a ClusterQueue using `kueuectl create clusterqueue` with extended or vendor resource names that contain hyphens (e.g. `example.com/v100-gpu`, `intel.com/sriov-net`, `habana.ai/gaudi-2`), the command fails immediately with:

```text
error: invalid resources specification
```

**What you expected to happen**:

`kueuectl create clusterqueue` should accept valid Kubernetes resource names where the name segment contains hyphens.

**How to reproduce it (as minimally and precisely as possible)**:

Run:
```bash
kueuectl create clusterqueue test-cq --nominal-quota "default:example.com/v100-gpu=1"
```

Result:
```text
error: invalid resources specification
```

**Anything else we need to know?**:

The validation regex in `cmd/kueuectl/app/create/create_clusterqueue.go` line 319 is:
```go
regex := regexp.MustCompile(`^([a-z0-9][a-z0-9\-\.]{0,252}):((\w+[\.-]?)*\/?\w+=[\w.]+;)*(\w+[\.-]?)*\/?\w+=[\w.]+;?$`)
```

The resource name segment uses `\/?\w+`. In Go's regexp package, `\w` only matches `[a-zA-Z0-9_]`, so any resource with a hyphen in the name part fails validation.

Changing `\/?\w+` to `\/?[\w\.-]+` fixes it while keeping existing validation for quantities and separators intact.

**Environment**:
- Kubernetes version: v1.33+
- Kueue version: main (also affects 0.18.x, 0.19.x, 0.20.x)
- OS: Linux
