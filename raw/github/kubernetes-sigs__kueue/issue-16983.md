## Description

**What would you like to be added**:

   Make `hack/migrate-to-v1beta2.sh` cheap to rerun and able to finish on large or busy clusters:

   1. **Skip objects that are already migrated.** The script writes `kueue.x-k8s.io/storage-version=<version>` but never
      reads it back, so every rerun patches every object again. It could read the annotation in the same LIST call and
      patch only objects without the target value, with a flag to force a full pass.
   2. **Patch in batches.** Pass many names to one `kubectl annotate` call instead of starting one kubectl process per
      object. Keep the calls sequential, so the API server sees no more concurrent load than today.
   3. **Keep going on per-object errors.** Today the first failed patch ends that kind (or that namespace). Instead, count
      each object as migrated, gone (`NotFound`: deleted after the list) or failed, continue, print the failed names, and
      exit non-zero at the end.
   4. **Check the CRD storage version before patching.** If a kind's CRD doesn't store the target version yet, annotating
      marks objects as migrated that aren't, and with (1) later runs would skip them. Skip such a kind with an error.

   **Why is this needed**:

   From running the current script (`--kubectl-get-api-version=v1beta2`) on dev clusters with a few thousand Kueue objects
   each (managed Kubernetes with an exec credential plugin):

   - Each kubectl process costs about 1 s (start, discovery, auth); the GET and PATCH themselves take about 50 ms each. One
     `kubectl annotate` call with 50 names took about 9 s, roughly 0.2 s per object, paced by kubectl's client-side rate
     limiter rather than API Priority and Fairness.
   - Where tests create and delete queues all the time, an object deleted mid-run (`NotFound`) stopped its namespace on
     most runs. Each rerun re-annotated everything already done and stopped again; over five runs each object was patched
     about five times.
   - Two ClusterQueues whose existing spec fails the validating webhook on any update
     (`lendingLimit ... must be less than or equal to the nominalQuota`) stop `clusterqueues` at the same object on every
     run, so the rest of that kind is never migrated.

   This matters more now that v1beta1 is unserved (v0.20, #14558) and removed on main (#16485): before upgrading, users need
   every object rewritten at v1beta2 before they can trim `storedVersions`, and on busy clusters the script often can't get
   there. Related: #9094.

   I have a patch for all four (one file, about +110/-20; existing flags, dry-run modes and the per-namespace listing from
   #9340 unchanged) and can open a PR.
