## Description

**What happened**:

In `apis/kueue/v1beta2/clusterqueue_types.go`, `ConcurrentAdmissionPolicy.Migration.Mode` is documented with default value `TryPreferredFlavors`:

```go
// - `TryPreferredFlavors` (default): a Workload will try to migrate to the preferred flavor after it's admitted and running.
// - `RetainFirstAdmission`: a Workload, once admitted to a flavor, will stick to a flavor and will not be migrated.
```

Both the webhook (`pkg/webhooks/clusterqueue_webhook.go:251`) and controller (`pkg/controller/concurrentadmission/controller.go:853`) treat an empty `mode` as `TryPreferredFlavors`.

However, the field in `clusterqueue_types.go` has `// +required` and lacks `// +kubebuilder:default=TryPreferredFlavors`. As a result, the generated CRD requires `mode` under `migration`:

```yaml
required:
- mode
```

When a user defines `migration` without explicitly specifying `mode` (e.g. relying on the documented default), the API server rejects the object with a validation error.

**What you expected to happen**:

`spec.concurrentAdmissionPolicy.migration.mode` should be optional with `default: TryPreferredFlavors` in the CRD schema, matching the documentation and controller implementation.

**How to reproduce it (as minimally and precisely as possible)**:

Create a ClusterQueue with `concurrentAdmissionPolicy.migration` omitting `mode`:

```yaml
apiVersion: kueue.x-k8s.io/v1beta2
kind: ClusterQueue
metadata:
  name: test-cq
spec:
  queueingStrategy: BestEffortFIFO
  concurrentAdmissionPolicy:
    migration:
      constraints:
        lastAcceptableFlavorName: default-flavor
  resourceGroups:
  - coveredResources: ["cpu"]
    flavors:
    - name: default-flavor
      resources:
      - name: cpu
        nominalQuota: 10
```

Apply fails with:
```text
ValidationError(ClusterQueue.spec.concurrentAdmissionPolicy.migration): missing required field "mode"
```

**Anything else we need to know?**:

Marking the field `// +optional` and adding `// +kubebuilder:default=TryPreferredFlavors` aligns the CRD schema with the controller and webhook behavior.

**Environment**:
- Kubernetes version: v1.33+
- Kueue version: main (v0.20.0-rc.1+)
- OS: Linux
