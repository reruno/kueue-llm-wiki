**What happened**:

A Job using DRA through a ResourceClaimTemplate and Topology-Aware Scheduling remained suspended. Kueue did not admit the Workload, and no Pods were created.

The ClusterQueue had enough device quota, and matching devices were available on the nodes.

The scheduler repeatedly logged:

```
Re-computing the assignment as it doesn't fit for TAS
```

The Workload was repeatedly requeued with FailedAfterNomination.

Adding explicit zero-valued CPU and memory requests to the Job allowed it to be admitted and its Pod to run:

```yaml
resources:
  requests:
    cpu: "0"
    memory: "0"
  claims:
  - name: devices
```

The ClusterQueue still covered only the DRA resources. No CPU or memory quota was added.

**What you expected to happen**:

A Workload using DRA ResourceClaimTemplates should be admitted when device quota, device availability, and topology constraints allow it, even if the Pod has no ordinary resource requests.

Omitting CPU and memory requests should not cause an admission loop that disappears when both requests are explicitly set to zero.

**How to reproduce it (as minimally and precisely as possible)**:

1. Deploy Kueue v0.20.0 with a working DRA driver.

2. Enable KueueDRADeviceFeasibility. Keep TAS and DRA integration enabled.

3. Configure:
- DeviceClasses and corresponding `deviceClassMappings`.
- A Topology with `kubernetes.io/hostname` as its lowest level.
- A ResourceFlavor referencing that Topology and selecting nodes with matching devices.
- A ClusterQueue covering only the mapped DRA resources, with sufficient quota + LocalQueue.
- A ResourceClaimTemplate requesting devices that fit on a single selected node.

4. Submit a suspended Job using that LocalQueue and ResourceClaimTemplate. Set the Pod annotation:

```yaml
kueue.x-k8s.io/podset-required-topology: kubernetes.io/hostname
```

The relevant Pod configuration should contain claims but no ordinary requests:

```yaml
spec:
  restartPolicy: Never
  containers:
  - name: pause
    image: registry.k8s.io/pause:3.10.2
    resources:
      claims:
      - name: devices
  resourceClaims:
  - name: devices
    resourceClaimTemplateName: test-devices
```

5. Observe that the Job remains suspended and the scheduler repeatedly recomputes its TAS assignment.

6. Submit an otherwise identical Job under a new name, adding:

```yaml
requests:
  cpu: "0"
  memory: "0"
```

7. Observe that the second Job is admitted and its Pod runs with allocated DRA devices, without adding CPU or memory quota to the ClusterQueue.

**Environment**:
- Kubernetes version: v1.37
- Kueue version: v0.20.0
- Others: ResourceClaimTemplate path, TAS, and KueueDRADeviceFeasibility enabled; ClusterQueue quota configured only for DRA resources
