## Description

**What happened**:

When running `kueuectl create localqueue` with `--dry-run=client` (for example, to generate manifests offline or in GitOps CI pipelines), the command attempts to query the cluster API to verify that the specified ClusterQueue exists.

If there is no active cluster connection, or if the ClusterQueue does not yet exist in the cluster, the command fails with:

```text
Error: clusterqueues.kueue.x-k8s.io "my-cq" not found
```

or with network dial errors when run offline.

**What you expected to happen**:

`--dry-run=client` should run locally on the client without making remote API calls to the cluster.

**How to reproduce it (as minimally and precisely as possible)**:

Run:
```bash
kueuectl create localqueue my-lq -c unknown-cq --dry-run=client -o yaml
```

Result:
```text
Error: clusterqueues.kueue.x-k8s.io "unknown-cq" not found
```

**Anything else we need to know?**:

In `cmd/kueuectl/app/create/create_localqueue.go`, `Validate(ctx)` checks:

```go
if !o.IgnoreUnknownCq {
	_, err := o.Client.ClusterQueues().Get(ctx, o.UserSpecifiedClusterQueue, metav1.GetOptions{})
	if err != nil {
		return err
	}
}
```

This validation runs before `Run()`. In `Run()`, client dry-run is skipped (`if o.DryRunStrategy != dryrun.Client`), but `Validate` unconditionally makes the network call unless `--ignore-unknown-cq` is also passed.

Updating `Validate` to only verify the ClusterQueue when `o.DryRunStrategy != dryrun.Client && !o.IgnoreUnknownCq` aligns it with kubectl dry-run conventions.

**Environment**:
- Kubernetes version: v1.33+
- Kueue version: main (v0.20.0-rc.1+)
- OS: Linux
