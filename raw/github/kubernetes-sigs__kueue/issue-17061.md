## Description

**What happened**:

In `test/integration/singlecluster/controller/admissionchecks/provisioning/provisioning_test.go:654`, the test case `"Should ignore the change if Workload is Admitted and the ProvisioningRequest's condition is set to BookingExpired"` uses a hardcoded sleep:

```go
// wait a bit to make it almost certain that the provisioning controller already sees the workload as admitted.
time.Sleep(100 * time.Millisecond)
```

Relying on a static 100ms sleep introduces a timing race on loaded CI runners. If the controller's reconciliation takes longer than 100ms, `BookingExpired` is processed before the workload admission state is observed, causing the test to flake.

**What you expected to happen**:

Tests should not rely on fixed duration sleeps to synchronize asynchronous controller events. The test should wait for the controller's admission check condition update using `gomega.Eventually`.

**How to reproduce it (as minimally and precisely as possible)**:

Run the integration test under resource-constrained / high-load CI runner conditions:

```bash
go test -v ./test/integration/singlecluster/controller/admissionchecks/provisioning -run TestProvisioning
```

**Anything else we need to know?**:

Before this step, the test sets the ProvisioningRequest to `Provisioned`. Waiting for the controller to update the admission check state to `Ready` via `behavioral.ExpectAdmissionCheckState(ctx, k8sClient, wlKey, ac.Name, kueue.CheckStateReady)` provides deterministic synchronization and removes the need for `time.Sleep`.

**Environment**:
- Kubernetes version: v1.33+
- Kueue version: main
- OS: Linux
