## Description

**What happened**:

In `test/util/behavioral/queues.go`, several test assertion helper functions lack `ginkgo.GinkgoHelper()`:
- `UnholdClusterQueue`
- `UnholdLocalQueue`
- `ExpectClusterQueuesToBeActive`
- `ExpectLocalQueuesToBeActive`

When assertions fail in these helpers, Ginkgo v2 attributes the failure inside the helper function instead of pointing directly to the calling test step in the test suite.

**What you expected to happen**:

All assertion helpers in `test/util/behavioral/queues.go` should call `ginkgo.GinkgoHelper()` so failure reports correctly attribute failures to the caller test line.

**How to reproduce it (as minimally and precisely as possible)**:

If a test assertion fails in `ExpectClusterQueuesToBeActive`, the failure location reported points to `queues.go` lines instead of the test spec line (`ginkgo.It`).

**Anything else we need to know?**:

Adding `ginkgo.GinkgoHelper()` brings these functions in line with other helpers in `test/util/behavioral/` (such as `CreateClusterQueuesAndWaitForActive`, `ExpectLocalQueueFairSharingUsageToBe`, etc.).

**Environment**:
- Kubernetes version: v1.33+
- Kueue version: main
- OS: Linux
