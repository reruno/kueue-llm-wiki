## Description

**What happened**:
`/set-release-note` includes all subsequent comment text in the release note, including other commands such as `/remove-kind cleanup` and `/kind bug`.

**What you expected to happen**:
Parse the release-note text separately from other commands in the same comment. Keep standalone and multiline release notes working.

**How to reproduce it (as minimally and precisely as possible)**:
Post this comment on a pull request:
```text
/set-release-note
CLI: Example release note.
/remove-kind cleanup
/kind bug
```
The release note includes the trailing commands.

**Anything else we need to know?**:
Investigate the `/set-release-note` ChatOps handler and its command-boundary parsing. Add regression tests for combined commands and standalone multiline notes. The release note must exclude other commands, and those commands must still run.

Reported in [PR #16850](https://github.com/kubernetes-sigs/kueue/pull/16850).
