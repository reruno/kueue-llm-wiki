**What would you like to be cleaned**:

The kueueviz backend currently calls `srv.Shutdown(context.Background())` when handling SIGTERM/SIGINT.

Because the shutdown context has no deadline, graceful shutdown has no upper bound if an active HTTP request handler does not return. Consider using a bounded shutdown context, for example `context.WithTimeout(context.Background(), 30*time.Second)`, so process termination is deterministic.

**Why is this needed**:

This is a low-risk reliability improvement. A bounded shutdown avoids waiting indefinitely during graceful termination, especially when running under Kubernetes termination grace periods.

Upgraded WebSocket connections are typically not waited on by `net/http.Server.Shutdown`, so this cleanup mainly protects ordinary active HTTP handlers. Graceful WebSocket termination can be considered separately if needed.
