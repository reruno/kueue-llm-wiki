**What happened**:

`kueueviz` only enables authentication when `KUEUEVIZ_AUTH_MODE` is exactly `TokenReview`.

If the value is misspelled or otherwise unknown, for example `tokenreview`, `TokenReveiw`, or `Enabled`, the backend still starts successfully but does not install the authentication or authorization middleware. As a result, protected API and WebSocket routes behave as unauthenticated routes.

**What you expected to happen**:

Unknown `KUEUEVIZ_AUTH_MODE` values should fail fast during startup with a clear error message.

Only explicitly supported values should be accepted, for example:

- `Disabled`
- `TokenReview`

This would prevent accidental fail-open behavior caused by configuration typos.

**How to reproduce it (as minimally and precisely as possible)**:

1. Start `kueueviz` backend with an invalid auth mode, for example:

   ```sh
   KUEUEVIZ_AUTH_MODE=tokenreview
   ```

2. Observe that the backend starts successfully.

3. Access protected routes without a bearer token, such as kueueviz API or WebSocket endpoints.

4. Observe that authentication is not enforced because the auth middleware is only configured when the value is exactly `TokenReview`.

**Anything else we need to know?**:

The relevant behavior appears to be in `cmd/kueueviz/backend/main.go`, where authentication is enabled only when:

```go
if serverConfig.AuthMode == "TokenReview" {
```

The configured value is read from `KUEUEVIZ_AUTH_MODE` in `cmd/kueueviz/backend/config/server.go`.
