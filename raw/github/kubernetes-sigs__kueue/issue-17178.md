## Description

**What happened**:

In `cmd/kueueviz/backend/handlers/cohorts.go`, `fetchCohorts` lists all ClusterQueues with the backend client and includes their names in each cohort's `clusterQueues` field. It does not check the requesting user's `list clusterqueues` permission.

Users who can view cohorts can therefore receive ClusterQueue names without permission to list ClusterQueues. The cohort details handler already checks this permission and reports `omittedPanels`.

**What you expected to happen**:

Pass the requesting identity to `fetchCohorts`. Before listing ClusterQueues, check `authorizer.Authorize(ctx, identity, middleware.ResourceAccess("list", ClusterQueuesGVR(), "", ""))`.

Acceptance criteria:
- If access is denied, do not list ClusterQueues or include the `clusterQueues` field in the response.
- If access is allowed, preserve the existing ClusterQueue names.
- Authorization errors do not expose ClusterQueue names.
- Preserve behavior when no authorizer is configured.
- Add tests for allowed, denied, and error cases.

**How to reproduce it (as minimally and precisely as possible)**:

Connect to `/ws/cohorts` as a user allowed to view cohorts but denied `list` access to ClusterQueues. Inspect the initial payload for ClusterQueue names.
