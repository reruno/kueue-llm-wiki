## Description

**What would you like to be cleaned**:

The recommended [cherry-pick script](https://github.com/kubernetes-sigs/kueue/blob/03c1e5458cda22f16c726ec6590aa1470b0abfaa/hack/cherry_pick_pull.sh) deals with a given PR on a per-commit basis.

For a larger PR, especially if it went through a chain of larger edits (e.g. for better visibility of review iterations, which we BTW recommend), this can lead to large & unnecessary overhead of manually resolving conflicts.

The script should use a single squashed commit representing the whole PR, and cherry-pick that one.

**Why is this needed**:

To speed up manual cherry-picking process when necessary. (In some cases, by many times).

**Note**:

While I'm not sure how the automated cherry-picker (after PR merging) works, AI tells me that it suffers from an analogous problem - working per commit.
If so, this means that by using squashed commits there, we could increase the chances for the automated cherry-picker to succeed, decreasing the need to use the `cherry_pick_pull.sh` script.
However, that change would need to happen in `kubernetes-sigs/prow`, not in the Kueue repo.
