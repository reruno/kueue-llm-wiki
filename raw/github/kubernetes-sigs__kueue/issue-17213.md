## Description

**What happened**:

The JobSet integration reports succeeded child Jobs as reclaimable. A restart can recreate those Jobs, so their new pods run without quota accounting. The job reconciler also stops before its `WaitForPodsReady` and eviction checks.

**What you expected to happen**:

JobSet restarts must preserve correct quota accounting for recreated pods. Reclaimable-pod handling must not block readiness or eviction processing.

**How to reproduce it (as minimally and precisely as possible)**:

Reported sequence; a minimal reproducer is still needed:
1. Run a JobSet until succeeded child Jobs are reported as reclaimable.
2. Trigger a restart that recreates those Jobs.
3. Check quota accounting for recreated pods and whether reconciliation reaches readiness and eviction checks.

**Anything else we need to know?**:

Follow-up to https://github.com/kubernetes-sigs/kueue/pull/17147 and related to https://github.com/kubernetes-sigs/kueue/issues/14811.

Required changes:
- Review reclaimable-pod reporting in the JobSet integration and reconcile it with restart semantics.
- Review reclaimable-pod processing in `pkg/controller/jobframework/reconciler.go` so readiness and eviction processing can proceed.
- Add regression coverage for completed child Jobs recreated during a restart.

Acceptance criteria:
- Recreated pods do not run against quota that has already been reclaimed.
- Reconciliation reaches `WaitForPodsReady` and eviction checks.
- Regression tests cover restart accounting and eviction completion, including quota release.
