## Description

**What would you like to be cleaned**:

Add an envtest integration regression test for the eviction fix in [PR #17147](https://github.com/kubernetes-sigs/kueue/pull/17147). Cover `pkg/controller/jobframework/reconciler.go` together with the Workload validating webhook using the shared Ginkgo/Gomega integration suite.

Acceptance criteria:
- Enable reclaimable-pod processing and run the job reconciler with the real webhook.
- Model a JobSet restart with stale `.status.reclaimablePods`, a lower current reclaimable count, and an evicted Workload that still holds quota.
- Trigger reconciliation through API updates and event handlers, not direct `Reconcile` calls. Simulate JobSet status changes as needed in envtest.
- Verify that eviction suspends the JobSet and, after active pods stop, clears `.status.admission`, releases quota, and removes stale reclaimable-pod entries.
- Demonstrate that the test fails without the fix in PR #17147 and passes with it. Use retry-safe assertions and explicit cleanup.

**Why is this needed**:

A fake-client unit test does not exercise the webhook rejection that blocks eviction when reclaimable-pod counts decrease while quota is reserved. This regression depends on interaction between the job reconciler and the webhook.

Requested by @mimowo in [this review comment](https://github.com/kubernetes-sigs/kueue/pull/17147#discussion_r4275317819). Related bug: [#14811](https://github.com/kubernetes-sigs/kueue/issues/14811).
