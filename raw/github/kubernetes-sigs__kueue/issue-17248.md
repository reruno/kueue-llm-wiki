## Description


**What happened**:

KueueViz builds the SubjectAccessReview cache key by joining identity groups with commas. It also formats extra attributes with `=`, `,`, and `;` delimiters.

This can produce the same cache key for structurally different identities. For example:

```text
Groups: ["group-a,group-b"]
Groups: ["group-a", "group-b"]
```

Both are encoded as:

```text
group-a,group-b
```

Extra attributes have the same problem:

```text
{"scope": ["read,write"]}
{"scope": ["read", "write"]}
```

Both are encoded as:

```text
scope=read,write;
```

When the username, UID, and resource attributes are also the same, the second authorization request can reuse the first request's cached result instead of creating a new SubjectAccessReview.

**What you expected to happen**:

Structurally different identity attributes should always produce different cache keys.

The order of groups, extra map keys, and extra values should not affect the key when they represent the same identity.

**How to reproduce it (as minimally and precisely as possible)**:

1. Create a SAR authorizer with a non-zero cache TTL.
2. Authorize this identity and have the fake SubjectAccessReview return `Allowed: true`:

   ```go
   Identity{
       Username: "alice",
       UID:      "alice-uid",
       Groups:   []string{"group-a,group-b"},
   }
   ```

3. Authorize the same resource attributes using this identity:

   ```go
   Identity{
       Username: "alice",
       UID:      "alice-uid",
       Groups:   []string{"group-a", "group-b"},
   }
   ```

4. Have a second SubjectAccessReview return `Allowed: false`.

The second SubjectAccessReview is not created. The second call instead returns the cached `true` result from the first identity.

**Anything else we need to know?**:

A possible fix is to sort copies of the group and extra-attribute slices, encode all identity fields with an unambiguous structured or length-prefixed representation, and use a fixed-size digest as the cache key.

Regression coverage should include group and extra-value delimiter collisions, as well as different map and slice orderings.

No real-world exploitation has been observed. The known trigger requires the username, UID, and requested resource attributes to match, while distinct groups or extra attributes produce the same encoded value.

AI tools were used to assist with analyzing the code, preparing the regression tests, and drafting this report.
