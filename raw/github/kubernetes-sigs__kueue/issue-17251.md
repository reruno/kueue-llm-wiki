## Description

**What happened**:

When no `LeaderWorkerSet` replica is Ready, the webhook allows changing `kueue.x-k8s.io/queue-name`. 
It does not check if the Workload already reserves quota. If it does, the reconciler fails on every retry, because `spec.queueName` can't change while quota is reserved:

```
Reconciler error ... queueName is immutable while workload quota reserved
```

The Workload stays in the old queue.

**What you expected to happen**:

The webhook rejects the change, like the StatefulSet webhook does after #16320.

**How to reproduce it (as minimally and precisely as possible)**:

1. Create a LeaderWorkerSet with queue `lq`.
2. Wait for its Workload to get `QuotaReserved=True`.
3. Change the queue-name label to `lq2` before any replica is Ready. The update succeeds.
4. The reconciler keeps logging the error above.

I ran this as an integration test on main, where Pods never become Ready.

**Anything else we need to know?**:

LeaderWorkerSet has one Workload per group, so the webhook needs to check all of them. I'd like to work on this.
