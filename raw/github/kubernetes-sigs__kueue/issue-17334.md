## Description

**What happened**:

PR #16884 makes Ray worker PodSet counts respect `MinReplicas`, `MaxReplicas`, and `NumOfHosts`, but two paths remain inconsistent:
- TAS: `buildWorkerTopologyRequest` in `pkg/controller/jobs/raycluster/common.go` still uses raw `Replicas` for subgroup counts and topology index-label selection.
- MultiKueue: `syncWorkerReplicas` in `pkg/controller/jobs/raycluster/raycluster_multikueue_adapter.go` copies only `Replicas` and `NumOfHosts`. Changes to replica bounds can leave the worker copy with a different effective count.

**What you expected to happen**:

- Derive TAS subgroup counts and index labels from the bounded replica count, keeping replica counts distinct from pod counts for multi-host groups.
- Synchronize `MinReplicas` and `MaxReplicas` with the other worker sizing fields.
- Add regression tests for lower/upper bounds, missing replicas, multi-host topology, and bound-only MultiKueue updates.

**How to reproduce it (as minimally and precisely as possible)**:

1. For TAS, use a multi-host worker group with `Replicas=1`, `MinReplicas=MaxReplicas=2`, and `NumOfHosts=2`. PodSet count becomes four, but topology metadata still derives from one replica.
2. For non-autoscaling MultiKueue, start with matching manager and worker groups at `Replicas=1`, `MinReplicas=1`, `MaxReplicas=3`. Change only the manager's `MinReplicas` to two. Replica synchronization does not propagate the changed bound.

These cases follow from source inspection; no runtime reproduction was performed for this issue.
