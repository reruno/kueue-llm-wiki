**What would you like to be added**:

We have a huge inflow of PRs and some of them get forgotten, because there are no reviews. At this point many PRs skip maintainer attention.

This is Idea 2 from the deck: https://docs.google.com/presentation/d/1AJ-rl8bUbcRyJgJfXS50Wb5tX51HlnXDYiLZGv9j_KQ

The policy will motivate contributors to engage reviewers and other community members in reviews before reaching out to maintainers.

I propose 30 days for stale and 60 days for closing, but the exact numbers could be adjusted.

**Why is this needed**:

To make contributors engage reviewers and contributors into reviewing before it can catch maintainer attention. This way we can better load balance reviews.

### Comment by [@mbobrovskyi](https://github.com/mbobrovskyi) — 2026-10-16T12:20:44Z

Actually, there is already a triage bot (k8s-triage-robot) that does this for PRs across the whole kubernetes-sigs org, including Kueue:

- After 90d of inactivity, lifecycle/stale is applied
- After 30d of inactivity since lifecycle/stale was applied, lifecycle/rotten is applied
- After 30d of inactivity since lifecycle/rotten was applied, the PR is closed

The configuration lives in https://github.com/kubernetes/test-infra/tree/master/config/jobs/kubernetes/sig-k8s-infra/trusted/sig-contribex-k8s-triage-robot.yaml in kubernetes/test-infra. See the ci-k8s-triage-robot-stale-prs, ci-k8s-triage-robot-rotten-prs and ci-k8s-triage-robot-close-prs jobs.

Examples of Kueue PRs closed by the bot:
 - #8922
 - #8354
 - #7422
 - #7058

Since the bot already applies these labels, a separate GitHub Action would add a second bot with different timing on the same labels.

I'm curious whether we can create our own Kueue-specific periodic job with shorter timings instead. It looks like there is a precedent: kubernetes-sigs/agent-sandbox is excluded from the org-wide stale-prs and rotten-prs jobs and has its own ci-k8s-triage-robot-stale-prs-agent-sandbox and ci-k8s-triage-robot-close-prs-agent-sandbox jobs (15d stale + 15d close), added in kubernetes/test-infra#36592 and kubernetes/test-infra#38076.
