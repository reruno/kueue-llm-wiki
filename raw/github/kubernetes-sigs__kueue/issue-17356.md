## Description

**What happened**:

When one update of a LocalQueue changes a custom metric label value and also sets `spec.stopPolicy`, `kueue_local_queue_admitted_active_workloads` for that LocalQueue is cleared and not reported again. When the admitted Workloads finish, the gauge goes to -1. `kueue_local_queue_reserving_active_workloads` is also missing until the next Workload change in that LocalQueue, even though the Workload is still running.

**What you expected to happen**:

Both gauges keep counting the admitted Workloads under the new label value.

**How to reproduce it (as minimally and precisely as possible)**:

1. Enable `CustomMetricLabels` and `LocalQueueMetrics`, with a custom label from the LocalQueue label `team`.
2. Create a ClusterQueue, and a LocalQueue with `team: alpha`.
3. Create a Workload in that LocalQueue and wait until it is admitted.
4. In one update, change the LocalQueue label to `team: beta` and set `spec.stopPolicy: Hold`.
5. The admitted active gauge for the LocalQueue is gone.
6. Finish the Workload. The gauge with `team="beta"` is -1.

**Anything else we need to know?**:

On a label change, the LocalQueue controller clears the LocalQueue gauges, but it skips the gauge resync for a queue being stopped (`!stoppingQueue` in `LocalQueueReconciler.Update`). So nothing reports them again. This was found while working on #17336 and #17260. It still happens with both PRs applied.
