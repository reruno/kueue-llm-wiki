## Description


Labels: kind/bug

**What happened**:

When a TAS Workload already has succeeded Pods (`status.reclaimablePods`), replacing a failed node never completes.
The scheduler finds a free node, but the Workload webhook rejects the update on every retry:

```
admission webhook "vworkload.kb.io" denied the request: status.admission: Invalid value: {..."count":1,"resourceUsage":{"cpu":"10m","example.com/slot":"1","memory":"16Mi"},"topologyAssignment":{...}}: field is immutable
```

| Field | Admitted | Sent by the second pass |
|---|---|---|
| `podSetAssignments[0].count` | 3 | 1 (3 minus 2 reclaimable Pods) |
| `podSetAssignments[0].resourceUsage` | cpu 30m, slot 3 | cpu 10m, slot 1 |
| `podSetAssignments[0].topologyAssignment` | worker (2 Pods), worker2 (1 Pod) | worker3 replaces worker2 (allowed to change) |

The failed node stays in `status.unhealthyNodes`, and the recreated Pod stays `SchedulingGated` even though free nodes exist.

**What you expected to happen**:

The failed node is replaced, and the recreated Pod is scheduled on a free node.

**How to reproduce it (as minimally and precisely as possible)**:

```shell
# 0. Install Kueue with default settings on a kind cluster with 3 workers.
#    Give each worker the label pool=repro and the extended resource example.com/slot: 2.
#    Create Topology "hostname-only" (kubernetes.io/hostname), ResourceFlavor "tas-flavor"
#    (nodeLabels pool=repro), ClusterQueue "cq", and LocalQueue "default/lq".

# 1. Create an Indexed Job: indexes 0 and 1 finish after 20s, index 2 keeps running
$ cat <<EOF | kubectl create -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: train
  namespace: default
  labels:
    kueue.x-k8s.io/queue-name: lq
spec:
  completionMode: Indexed
  completions: 3
  parallelism: 3
  template:
    metadata:
      annotations:
        kueue.x-k8s.io/podset-unconstrained-topology: "true"
    spec:
      restartPolicy: Never
      containers:
      - name: main
        image: busybox:1.36
        command: ["sh", "-c", "if [ \"$JOB_COMPLETION_INDEX\" -lt 2 ]; then sleep 20; else sleep 1800; fi"]
        resources:
          requests:
            cpu: 10m
            memory: 16Mi
            example.com/slot: "1"
          limits:
            example.com/slot: "1"
EOF

# 2. Wait until indexes 0 and 1 succeed. worker3 is free.
$ kubectl get pods -o wide
train-0-p6tl6   Completed   kueue-succ-repro-worker
train-1-26t9g   Completed   kueue-succ-repro-worker
train-2-62njl   Running     kueue-succ-repro-worker2
$ kubectl get workload -o jsonpath='{.items[0].status.reclaimablePods}'
[{"count":2,"name":"main"}]

# 3. Stop the node that runs index 2, wait until it is NotReady, and force-delete the Pod
$ docker stop kueue-succ-repro-worker2
$ kubectl delete pod train-2-62njl --force --grace-period=0

# 4. Check the Workload and the Pods after 2 minutes
# OUTPUT: the node is not replaced, and the recreated Pod stays gated although worker3 is free
$ kubectl get workload -o jsonpath='{.items[0].status.unhealthyNodes}'
[{"name":"kueue-succ-repro-worker2"}]
$ kubectl get pods
train-0-p6tl6   Completed
train-1-26t9g   Completed
train-2-x7pxp   SchedulingGated
$ kubectl -n kueue-system logs deploy/kueue-controller-manager | grep -c 'field is immutable'
8
```

**Anything else we need to know?**:

- If there is no free node, `TASFailedNodeReplacementFailFast` evicts the Workload instead (`no replacement for unhealthy node(s)`).
- All feature gates involved (`TopologyAwareScheduling`, `TASFailedNodeReplacement`, `TASReplaceNodeOnPodTermination`, `ReclaimablePods`) are Beta and enabled by default.
- KEP-2724 lists "support reclaimable pods" as a Stable goal for TAS, but nothing rejects this combination, so the Workload gets stuck silently. If the combination is not in scope yet, failing fast may be better than retrying forever.
- Related: #15223 (TAS topology release for reclaimable Pods).
