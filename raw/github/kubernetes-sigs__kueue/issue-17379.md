## Description


Labels: kind/bug

**What happened**:

A node gets an untolerated `NoSchedule` taint (for example `karpenter.sh/disrupted`, which Karpenter adds to a node it is about to remove), and all Pods of the TAS Workload on that node have already succeeded.
Kueue marks the node unhealthy. With no free node, it evicts the whole Workload and deletes the Pod that is still running on a healthy node:

```
Workload was evicted as there was no replacement for unhealthy node(s): kueue-succ-repro-worker
```

`hasProgressingPods` in the TAS node controller counts Succeeded Pods as not progressing, the same as Failed ones.
Nothing on that node needs to run again, so the node does not need a replacement.

**What you expected to happen**:

The node stays healthy for this Workload, and the running Pod on the other node keeps running.

**How to reproduce it (as minimally and precisely as possible)**:

```shell
# 0. Install Kueue with default settings on a kind cluster with 3 workers.
#    Give each worker the label pool=repro and the extended resource example.com/slot: 1.
#    Create Topology "hostname-only" (kubernetes.io/hostname), ResourceFlavor "tas-flavor"
#    (nodeLabels pool=repro), ClusterQueue "cq", and LocalQueue "default/lq".

# 1. Create an Indexed Job: indexes 0 and 1 finish after 20s, index 2 keeps running
$ cat <<EOF | kubectl create -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: train
  namespace: default
  labels:
    kueue.x-k8s.io/queue-name: lq
spec:
  completionMode: Indexed
  completions: 3
  parallelism: 3
  template:
    metadata:
      annotations:
        kueue.x-k8s.io/podset-unconstrained-topology: "true"
    spec:
      restartPolicy: Never
      containers:
      - name: main
        image: busybox:1.36
        command: ["sh", "-c", "if [ \"$JOB_COMPLETION_INDEX\" -lt 2 ]; then sleep 20; else sleep 1800; fi"]
        resources:
          requests:
            cpu: 10m
            memory: 16Mi
            example.com/slot: "1"
          limits:
            example.com/slot: "1"
EOF

# 2. Wait until indexes 0 and 1 succeed
$ kubectl get pods -o wide
train-0-vj6rs   Completed   kueue-succ-repro-worker
train-1-c7cmr   Completed   kueue-succ-repro-worker2
train-2-mckgg   Running     kueue-succ-repro-worker3

# 3. Taint the node that only has a succeeded Pod, as Karpenter does before removing a node
$ kubectl taint node kueue-succ-repro-worker karpenter.sh/disrupted=:NoSchedule

# 4. Check the Job events and the Pods after 15s
# OUTPUT: the Workload is evicted, and index 2 on the healthy worker3 is deleted and restarted
$ kubectl get events --field-selector involvedObject.kind=Job
Suspended          Job suspended
Resumed            Job resumed
SuccessfulDelete   Deleted pod: train-2-mckgg
Stopped            Workload was evicted as there was no replacement for unhealthy node(s): kueue-succ-repro-worker
$ kubectl get pods -o wide
train-0-vj6rs   Completed     kueue-succ-repro-worker
train-1-c7cmr   Completed     kueue-succ-repro-worker2
train-2-57245   Running       kueue-succ-repro-worker2
train-2-mckgg   Terminating   kueue-succ-repro-worker3
```
