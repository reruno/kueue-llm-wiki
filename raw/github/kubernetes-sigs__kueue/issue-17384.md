## Description

**What happened**:

Follow-up from #14562. When the workload controller pushes a DRA workload with a recomputed charge while it is inflight, `ClusterQueue.PushOrUpdate` drops the push ([cluster_queue.go#L385-L389](https://github.com/kubernetes-sigs/kueue/blob/bb201e17bd1cf47909aad100b0f6aaaa92bd3efd/pkg/cache/queue/cluster_queue.go#L385-L389)) and only the LocalQueue copy gets the new charge ([manager.go#L741-L746](https://github.com/kubernetes-sigs/kueue/blob/bb201e17bd1cf47909aad100b0f6aaaa92bd3efd/pkg/cache/queue/manager.go#L741-L746)). If the generation did not change and the workload needs DRA processing at requeue, `requeueWorkloadLocked` keeps the charge the workload had when it was popped and overwrites that copy ([manager.go#L819-L841](https://github.com/kubernetes-sigs/kueue/blob/bb201e17bd1cf47909aad100b0f6aaaa92bd3efd/pkg/cache/queue/manager.go#L819-L841)). The queued entry then keeps the old charge until the workload controller pushes it again, and the scheduler can reserve quota with it in the meantime.

Creating a DeviceClass that declares an extended resource the workload requests takes this path when `deviceClassMappings` lists that DeviceClass, since the charge then moves to the mapped name while the generation stays the same. The comment in `requeueWorkloadLocked` expects the reconcile that follows such a change to push the current charge. A LimitRange `defaultRequest` change takes the same path for a DRA workload without any mapping: after the requeue, the queued CPU charge is still the old default.

Under StrictFIFO, a head that doesn't fit goes straight back to the heap, and the scheduler waits at most 10 ms before the next cycle pops it again. A push that arrives between the pop and the requeue is lost.

**What you expected to happen**:

The requeued workload carries the charge pushed while it was inflight.

**How to reproduce it (as minimally and precisely as possible)**:

The test below queues a DRA workload charged `gpu: 1`, pops it, pushes it again with `gpu: 12`, and requeues it. It fails on main (bb201e17b) and on v0.20.2 with `gpu charge after requeue = 1, want 12`. On v0.19.9 it fails the same way after replacing `m.PopFrom("cq")` with `&m.Heads(ctx)[0]` and dropping `ctx` from the `AddOrUpdateWorkload` calls.

import (

	utiltestingapi "sigs.k8s.io/kueue/pkg/util/testing/v1beta2"
	"sigs.k8s.io/kueue/pkg/workload"
)

func TestChargePushedWhileInflight(t *testing.T) {
	features.SetFeatureGateDuringTest(t, features.KueueDRAIntegration, true)
	ctx, log := utiltesting.ContextWithLog(t)
	tmpl := "tmpl"
	wl := utiltestingapi.MakeWorkload("wl", "default").Queue("lq").Generation(1).PodSets(
		*utiltestingapi.MakePodSet(kueue.DefaultPodSetName, 1).PodSpec(corev1.PodSpec{
			ResourceClaims: []corev1.PodResourceClaim{{Name: "rc", ResourceClaimTemplateName: &tmpl}},
		}).Obj()).Obj()
	lq := utiltestingapi.MakeLocalQueue("lq", "default").ClusterQueue("cq").Obj()
	cl := utiltesting.NewClientBuilder().WithObjects(wl.DeepCopy(), lq).
		WithIndex(&corev1.LimitRange{}, indexer.LimitRangeHasContainerOrPodType, indexer.IndexLimitRangeHasContainerOrPodType).
		Build()
	m := NewManagerForUnitTests(cl, nil, WithPreemptionExpectations(preemptexpectations.New()))
	m.SetDRAReconcileChannel(make(chan event.TypedGenericEvent[*kueue.Workload], 2))
	if err := m.AddClusterQueue(ctx, utiltestingapi.MakeClusterQueue("cq").Obj()); err != nil {
		t.Fatal(err)
	}
	if err := m.AddLocalQueue(ctx, lq); err != nil {
		t.Fatal(err)
	}
	gpu := func(n int64) workload.InfoOption {
		return workload.WithPreprocessedDRAResources(map[kueue.PodSetReference]corev1.ResourceList{
			kueue.DefaultPodSetName: {"gpu": *resource.NewQuantity(n, resource.DecimalSI)},
		}, nil)
	}
	if err := m.AddOrUpdateWorkload(ctx, log, wl, gpu(1)); err != nil {
		t.Fatal(err)
	}
	head := m.PopFrom("cq")
	// The workload controller pushes a recomputed charge while the workload is inflight.
	if err := m.AddOrUpdateWorkload(ctx, log, wl.DeepCopy(), gpu(12)); err != nil {
		t.Fatal(err)
	}
	m.RequeueWorkload(ctx, &head.Info, RequeueReasonGeneric, "")
	if got := m.hm.ClusterQueue("cq").trackedInfo(workload.Key(wl)).TotalRequests[0].Requests.ResourceValue("gpu"); got.CmpInt64(12) != 0 {
		t.Errorf("gpu charge after requeue = %s, want 12", got)
	}
}

**Anything else we need to know?**:

mimowo's [suggestion on #14562](https://github.com/kubernetes-sigs/kueue/pull/14562#discussion_r4230719722) to read `q.items[wlKey]` at requeue, in place of the inflight capture that revision had, would cover it. `takePopped` deletes the LocalQueue copy when the workload is popped ([manager.go#L1023-L1024](https://github.com/kubernetes-sigs/kueue/blob/bb201e17bd1cf47909aad100b0f6aaaa92bd3efd/pkg/cache/queue/manager.go#L1023-L1024)), so a copy that is there at requeue was pushed while the workload was inflight. Taking its `TotalRequests` when its generation matches the current one makes the test pass, and `pkg/cache/queue` and `pkg/scheduler` still pass.
