**What would you like to be cleaned**:
`reportLQPendingWorkloads` scans every pending workload of the ClusterQueue to count one LocalQueue. It runs under the queue manager lock on every add, delete, pop and requeue, so draining N workloads costs O(N²). I'd keep the per-LocalQueue counts in PendingWorkloads, the same way #10485 made pendingResourcesTotal O(1).

**Why is this needed**:
In make run-performance-scheduler on main, it takes 9.0% of Kueue CPU, more than schedule (6.1%). In the TAS run, it takes 8.4% vs 11.5%. LocalQueue metrics are on by default. Those runs have only 500 workloads per ClusterQueue, so bigger queues cost more.

 |                                 | Kueue CPU (pprof samples) | schedule | reportLQPendingWorkloads |
 |---------------------------------|---------------------------|----------|--------------------------|
 | baseline                        | 103.6s                    | 6.1%     | 9.0%                     |
 | baseline, LocalQueueMetrics off | 83.8s                     | 5.0%     | –                        |
 | TAS                             | 118.1s                    | 11.5%    | 8.4%                     |
