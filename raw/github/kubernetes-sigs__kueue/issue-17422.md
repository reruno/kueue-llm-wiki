## Description

**What happened**:

Since #15284, two per-event paths cost more than they need:
- `needsDRAReconcile` builds a full Info (LimitRange/RuntimeClass reads, effective specs, total requests, scheduling hash) on every Workload event when the DRA extended-resource gates are on. `NeedsDRAReconcile` only reads the PodSpecs, and returns false anyway when no DeviceClass backs an extended resource.
- `effectivePodSpecs` deep-copies each PodSpec and compares the whole PodSpec with `equality.Semantic.DeepEqual`, but the adjustments only change `Overhead` and the container and pod `Resources`.

In `make run-performance-scheduler` on main (3ab60ecf5), with a prototype that skips the Info when the DRA cache is empty and compares only the adjusted fields:

| | main | prototype |
|---|---|---|
| Kueue CPU (pprof samples) | 115.1s | 108.8s (-5.5%) |
| `needsDRAReconcile` | 3.03s | 0.07s |
| `effectivePodSpecs` | 2.54s | 0.62s |

The perf pods have one container. On a pod with an init container, a sidecar, env and volumes, the narrow compare is 5.7x faster in a micro-benchmark.

**What you expected to happen**:

The DRA check and the effective-spec compare do only the work their result needs.

**How to reproduce it (as minimally and precisely as possible)**:

`make run-performance-scheduler SCALABILITY_EXTRA_ARGS=--withCPUProfile=true`, then `go tool pprof -top -cum` on `minimalkueue.cpu.prof`.

**Anything else we need to know?**:

Both came with #15284, so they affect release-0.20 and release-0.19 (#17354).

**Environment**:
- Kueue version: main 3ab60ecf5
