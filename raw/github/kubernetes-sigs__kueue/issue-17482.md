**What would you like to be cleaned**:

After #16483, `wantSimulatorPreemptions` no longer implicitly enables `SchedulerLibraryIntegration`. The test harness now installs the recording simulator only when the case enables the gate, and the simulator assertions are skipped otherwise.

Three existing cases in `pkg/scheduler/scheduler_tas_schedlib_test.go` still set simulator expectations without enabling the gate:

- `a simulator that will not release the victim does not stop the cycle`
- `only low priority workload is preempted`
- `the overlap recompute takes the other preemption's victim out of the simulator`

The first case also sets `failSimulatorPreemption`, so that path is not exercised either. The third case sets both `wantSimulatorReleasedTogether` and `wantSimulatorPreemptions`.

**Why is this needed**:

These cases currently pass, but only the non-simulator path runs. Regressions in pod removal, host-port or device release, or simulator preemption bookkeeping can go unnoticed. The new deferral case in #15263 already enables the gate explicitly; this issue tracks the older cases.

Proposed cleanup:
- Add `SchedulerLibraryIntegration: true` to the three cases, merged with their existing feature gates.
- Add a harness check that fails when simulator expectations are set while the gate is off.
- Update the stale comment in the `overlap recompute` case that says `wantSimulatorPreemptions` enables the gate.

Related: #15263, #16483, #14969, #15457. #15457 does not touch this file.

Acceptance:
- `go test ./pkg/scheduler/...`
- The three cases install the recording simulator and execute their simulator assertions.
