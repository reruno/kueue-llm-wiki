**What happened**:

With the Pod integration and MultiKueue, the manager cluster copies the worker Pod status onto the gated manager Pods. When the workload of a Pod group is evicted on the worker cluster (for example, preempted), the manager workload gets `Evicted=True`, but it never releases its quota reservation and is never requeued.

The job reconciler releases the quota only once `IsActive()` returns false. For a Pod group, `Stop` leaves the gated manager Pods in place, and `IsActive()` counts every Pod in the group whose phase is `Running`, including the gated manager Pods whose `Running` phase was copied from the worker. The worker Pods are deleted, so nothing updates the copied phase again. The workload keeps `QuotaReserved=True`, holds its ClusterQueue usage, and is not dispatched again.

Single Pods are not affected: `IsActive()` only checks the Pods of a group, so the quota of an evicted single Pod is released regardless of its phase.

**What you expected to happen**:

After the eviction, the manager workload should release its quota and be requeued, and the manager Pods should go back to gated `Pending`.

**How to reproduce it (as minimally and precisely as possible)**:

1. Set up a MultiKueue manager with one worker cluster and the Pod integration enabled.
2. Create a Pod group on the manager. For example, create 2 Pods with the same `kueue.x-k8s.io/pod-group-name` label, the `kueue.x-k8s.io/pod-group-total-count: "2"` annotation, and a `kueue.x-k8s.io/queue-name` label. Wait until the group runs on the worker. The manager Pods then show Running.
3. Evict the workload on the worker, for example by having a higher-priority workload preempt it.
4. Check the manager workload. It has `Evicted=True` but keeps `QuotaReserved=True`, and the ClusterQueue usage is not released.
5. Check the manager Pods. They are still gated but report `phase: Running`, and they stay that way.

**Anything else we need to know?**:

Related to #17418, which covers the stale status of single Pods and is fixed in #17420. That fix resets the manager Pod status after the quota is released, so it never runs for Pod groups.

Possible approaches:

1. Don't count gated Pods as active in `IsActive()`. A gated Pod can't run in the cluster where it is gated, so a `Running` phase on it can only be copied from a worker. The status reset from #17420 could then also cover Pod groups.
2. Reset the manager Pod status when the workload is evicted, before the quota is released, after the remote objects are deleted, so the status sync doesn't copy `Running` back.

**Environment**:
Kueue version: `main` (also `v0.20.1`)
Install tools: `Helm`

### Comment by [@vic-comm](https://github.com/vic-comm) — 2026-10-24T22:12:32Z

I investigated this issue and validated the fix locally on top of #17420, including live verification across multi-cluster Kind environments.

There are two distinct parts to resolving this cleanly:

### 1. Breaking the Deadlock in `IsActive()`
In `pkg/controller/jobs/pod/pod_controller.go`, `PodActivity` (invoked by `(*Pod).IsActive()`) counts any Pod in `Phase == Running` as active. Because a scheduling-gated Pod cannot execute locally on the manager cluster, any `Running` phase on it is mirrored from MultiKueue and must not block quota release.

Adding a gate check allows the generic reconciler to clear admission and release quota (`QuotaReserved=False, Requeued=True`):

```go
func PodActivity(pod *corev1.Pod, now time.Time) (active bool, recheckAfter time.Duration) {
	if pod.Status.Phase != corev1.PodRunning {
		return false, 0
	}
	// A gated Pod cannot run on this cluster. Any Running phase on a gated
	// Pod is copied from a remote cluster by MultiKueue and must not be counted as active.
	if isGated(pod) {
		return false, 0
	}
	...
```

### 2. Enabling Pod Group Status Reset & Handling Eviction Failures in #17420
Once quota is released and the workload is requeued, #17420's `ResetLocalStatus` is reached. To support Pod groups:
1. Query member pods with `listLocalPods` and reset each one instead of skipping groups.
2. In `resetPodStatus`, do not skip `Phase == PodFailed`. When a worker terminates an evicted pod (e.g., `SIGKILL`, exitCode 137), `PodFailed` is copied onto the manager pod. Skipping `utilpod.IsTerminated` leaves the manager pods permanently dead in `Failed / Error` state and wedges the workload in `WaitingForReplacementPods=True`. Only `PodSucceeded` (a completed job) should be preserved:

```go
func (b *multiKueueAdapter) resetPodStatus(ctx context.Context, localClient client.Client, localPod *corev1.Pod) error {
	// Preserve completed jobs (PodSucceeded), but reset PodFailed or Running phases mirrored from remote eviction.
	if !isGated(localPod) || localPod.Status.Phase == corev1.PodSucceeded || !localPod.DeletionTimestamp.IsZero() || !hasRemoteStatus(localPod) {
		return nil
	}

	return clientutil.PatchStatus(ctx, localClient, localPod, func() (bool, error) {
		localPod.Status = corev1.PodStatus{
			Phase:      corev1.PodPending,
			Conditions: []corev1.PodCondition{b.schedulingGatedCondition(localPod)},
			QOSClass:   localPod.Status.QOSClass,
		}
		return true, nil
	})
}

func (b *multiKueueAdapter) ResetLocalStatus(ctx context.Context, localClient client.Client, key types.NamespacedName) error {
	localPod := corev1.Pod{}
	if err := localClient.Get(ctx, key, &localPod); err != nil {
		return client.IgnoreNotFound(err)
	}

	if groupName := utilpod.GetPodGroupName(&localPod); groupName != "" {
		localPodGroup, err := listLocalPods(ctx, localClient, key.Namespace, groupName)
		if err != nil {
			return err
		}
		var errs []error
		for i := range localPodGroup.Items {
			if err := b.resetPodStatus(ctx, localClient, &localPodGroup.Items[i]); err != nil {
				errs = append(errs, err)
			}
		}
		return errors.Join(errs...)
	}

	return b.resetPodStatus(ctx, localClient, &localPod)
}
```
