## Description

**What happened**:

When a KueueViz page switches to another object, it shows the previous object until the new WebSocket sends its first message. For example, going from one workload detail page to another, or changing the namespace filter on the dashboard, briefly shows the old data under the new title.

`useWebSocket` in `cmd/kueueviz/frontend/src/useWebSocket.js` opens a new socket when the URL changes, but keeps the `data` and `error` state of the previous URL. Events from the previous socket are also not ignored after cleanup.

**What you expected to happen**:

The hook starts empty for the new URL and only shows data from the new socket.

**How to reproduce it (as minimally and precisely as possible)**:

1. Open the detail page of one workload.
2. Navigate to the detail page of another workload in the same tab, for example through a link.
3. Until the first message arrives, the page shows the fields of the first workload.

I have a fix with tests ready.
