## Description

**What would you like to be added**:

Emit user-visible events with dedicated reasons when `ensureOneWorkload` in `pkg/controller/jobframework/reconciler.go` refuses a prebuilt Workload because it:
- Is finished and not owned by the current Job.
- Is controlled by another object.

Include an actionable message that identifies the Workload and explains that the user must delete or replace it, or select a suitable prebuilt Workload.

**Why is this needed**:

An already suspended Job produces no `Stopped` event because `stopJob` makes no change. Both rejection paths currently provide only V(2) logs, so users cannot see why the Job remains suspended.

Non-blocking follow-up to https://github.com/kubernetes-sigs/kueue/pull/16994.
Requested by @mbobrovskyi: https://github.com/kubernetes-sigs/kueue/pull/16994#discussion_r4324435358.
Filed with CodeRabbit AI.

**Completion requirements**:

- [ ] Emit a diagnostic event for each rejection case, including when the Job is already suspended.
- [ ] Add controller tests for both event reasons and messages.
- [ ] Preserve suspension behavior and leave the rejected Workload unchanged.

This enhancement requires the following artifacts:
