## Description

**What happened**:

`backoffLimitCount`, `backoffBaseSeconds` and `backoffMaxSeconds` in
`ProvisioningRequestRetryStrategy` carry `+kubebuilder:default` markers
but no `+kubebuilder:validation:Minimum` marker. The generated CRD has
no `minimum:` constraint on any of them.

A negative `backoffBaseSeconds` reaches the controller and is used by
`UpdateAdmissionCheckRequeueState` to compute the exponential backoff,
which yields a negative `RequeueAfterSeconds`. A negative
`backoffMaxSeconds` removes the cap, so the requeue delay keeps doubling
with every retry.

**What you expected to happen**:

All three fields should reject negative values at CRD admission,
consistent with how the equivalent fields are validated for the
`waitForPodsReady.requeuingStrategy` in the Kueue `Configuration` API
(`pkg/config/validation.go`, lines 325-336).

**How to reproduce it (as minimally and precisely as possible)**:

Create a `ProvisioningRequestConfig` with
`spec.retryStrategy.backoffBaseSeconds: -60`. The CRD accepts it. With
a retry count of 2, `UpdateAdmissionCheckRequeueState` then produces
`RequeueAfterSeconds: -240`.

**Anything else we need to know?**:

No test exercised `UpdateAdmissionCheckRequeueState` with negative
inputs, and no CRD validation test covered these fields, so the gap was
not caught.
