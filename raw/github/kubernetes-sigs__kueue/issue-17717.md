## Description

**What happened**:

When migrating to structured overrides with `--reuse-values`, setting `managerConfig.controllerManagerConfigYaml: null` to drop the YAML kept from an earlier chart release works once. The `null` is then saved in the release values, and every later upgrade (with `--reuse-values`, `--reset-then-reuse-values` or no flags) fails schema validation because `controllerManagerConfigYaml` must be a string. Only `--reset-values`, or setting a string, recovers.

**What you expected to happen**:

`null` to mean the key is absent, as it does elsewhere in Helm values, so structured overrides apply on this and every later upgrade. The same should hold for `mode` and `structuredOverrides`. `controllerManagerConfigYaml: ""` keeps its meaning, an explicitly empty YAML configuration.

**How to reproduce it (as minimally and precisely as possible)**:

1. Install a chart release from before structured overrides:
   `helm install kueue <earlier chart> -n kueue-system`
2. Upgrade to the current chart with this values file:
   ```yaml
   managerConfig:
     controllerManagerConfigYaml: null
     structuredOverrides:
       clientConnection:
         qps: 600
   ```
   `helm upgrade kueue ./charts/kueue -n kueue-system --reuse-values -f values.yaml` succeeds and renders `qps: 600`.
3. `helm upgrade kueue ./charts/kueue -n kueue-system --reuse-values` fails: `managerConfig.controllerManagerConfigYaml` got null, want string.

Reproduced with Helm v4.3.1's install and upgrade actions, with the earlier release simulated as the current chart plus the old YAML default in its values.

**Anything else we need to know?**:

Proposed fix:
- Accept `null` for `mode`, `controllerManagerConfigYaml` and `structuredOverrides` in `values.schema.json`, and treat `null` as a missing key in `kueue.managerConfig` and the Populator's copy of the selection.
- README: document `null` as a way to drop the YAML key, and change "the first `--reuse-values` upgrade can carry the old chart's default YAML" to "any", since each reuse upgrade carries it forward until `mode: structured` is set.
- Upgrade cases in `test/helm`.

#16312 is not released yet, and `null` currently fails validation, so no working configuration changes behavior.
