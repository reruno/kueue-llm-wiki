**What happened**:

The `Dependabot Version Sync` workflow (`.github/workflows/sync-dependabot.yaml`) is skipped on the first run of every Dependabot PR. The `run-sync-hugo-version` job runs only when `github.event.pull_request.labels` contains `ok-to-test`. Dependabot opens the PR first and adds the labels in separate API calls, so the payload of the `opened` event has no labels.                                                                                   
                                                                                                                                                            
The workflow does not set `types:`, so it runs only on the default `opened`, `synchronize` and `reopened` events. Adding a label does not trigger it again. The sync step runs only if Dependabot later pushes to the PR branch, for example after a rebase.                                                   
                                                                                                                                                            
Example: #17695 (controller-tools 0.21.0 → 0.23.0):

```
| Time (UTC) | Event |                                                                                                                                    
|---|---|                                                                                                                                                 
| 19:03:27 | Dependabot pushes the commit and opens the PR |                                                                                              
| 19:03:31–32 | Dependabot adds `area/dependency`, `dependencies`, `ok-to-test`, `release-note-none` |                                                    
| 19:03:33 | [Run 40008374175](https://github.com/kubernetes-sigs/kueue/actions/runs/40008374175) starts with the `opened` payload, which has no labels. The job is `skipped` |                                                                                                                                    
| 20:55:59 | The PR is closed. No further push happened, so `make manifests update-helm` never ran |
```

The CRDs were then regenerated manually in #17699.

In comparison, the sync for #17696 (hugo) worked only because Dependabot rebased the PR at 19:36. The rebase triggered `synchronize`, and by then the labels were set ([run 40012714028] (https://github.com/kubernetes-sigs/kueue/actions/runs/40012714028)). The first run ([40008400991](https://github.com/kubernetes-sigs/kueue/actions/runs/40008400991)) was skipped.

**What you expected to happen**:

The workflow runs the sync step on every Dependabot PR that bumps hugo or `sigs.k8s.io/controller-tools`, and pushes the regenerated files to the PR. This should not depend on Dependabot rebasing the PR later.
