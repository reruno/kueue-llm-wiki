**What happened**:

The `Dependabot Version Sync` workflow (`.github/workflows/sync-dependabot.yaml`) is triggered by `pull_request_target`. GitHub now reports this warning for the file:

```
On December 2, 2026, GitHub will restrict `pull_request_target` on public repositories by default. To continue allowing the event trigger, configure an Actions policy.

GitHub has added a default Actions policy that blocks workflows triggered by `pull_request_target` in public repositories that have no applicable event policy. The policy runs in evaluate mode now, so runs still succeed. On December 2, 2026 it will be enforced. See [Securely using pull_request_target](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target#default-policy-for-pull_request_target).
```

The policy blocks the event, whatever the source branch or actor. After enforcement, the workflow will no longer run on Dependabot PRs. `make sync-hugo-version` and `make manifests update-helm` will not be committed to hugo and controller-tools bump PRs, so those PRs will need manual fixes again.

**What you expected to happen**:

The workflow keeps syncing hugo and controller-tools versions on Dependabot PRs after December 2, 2026, without a repository or organization policy exception for `pull_request_target`.

Proposed fix: trigger the workflow on `pull_request` instead of `pull_request_target`. Dependabot opens its PRs from branches in this repository, not from forks (for example #17696 has `isCrossRepository: false`), so `pull_request` runs for them. For Dependabot-triggered runs, `GITHUB_TOKEN` is read-only by default. The existing `permissions: contents: write` should raise it enough for the `git push` step. This must be verified on a real Dependabot PR.

`pull_request` is also the trigger GitHub recommends when a workflow does not need to process fork PRs. Here the job checks out the PR head and runs `make` with a write token.
