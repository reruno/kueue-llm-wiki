### Comment by [@ekam-walia](https://github.com/ekam-walia) — 2026-10-26T12:14:11Z

The test sets BlockAdmission: true. It creates prod-wl and dev-wl back to back, then expects prod-wl to be admitted and dev-wl to wait.

When both workloads are in the same scheduling cycle, makeClassicalIterator (`pkg/scheduler/scheduler.go:1202`) orders them. The last tie-break is FIFO on creation timestamp.
Timestamps only have 1-second resolution. If both workloads are created in the same second, the sort returns 0 and the order is arbitrary.
If dev-wl is processed first, it is admitted. waitForPodsReadyIfNeeded (`scheduler.go:682`) then sees an admitted workload without PodsReady and unsets prod-wl’s reservation. That writes exactly the message in failure: QuotaReserved=False, reason=Waiting … waiting for all admitted workloads to be in PodsReady condition.
The failure happens at the first check, before the test touches PodsReady, which matches “fails before the test updates PodsReady” in the issue.
