**What would you like to investigate**:

Whether any changes to Kueue's CRD or Configuration API (`apis/kueue/`, `apis/config/`) are required to support SLSA attestation generation as part of the release process (tracking issue kubernetes-sigs/kueue#1466).

Initial assessment suggests this is likely **not applicable**: SLSA attestation is a CI/release tooling change (Cloud Build, GitHub Actions, Makefile targets) and does not require changes to Kueue's Kubernetes APIs or the controller-manager configuration. However, this should be confirmed before the implementation PR is opened.

Questions to answer:
- Does any Kueue API surface need to expose provenance information (e.g., in workload status or operator metadata)?
- Does the Kueue Configuration API need a field to reference or configure attestation endpoints?
- Can the enhancement template's "API change" checklist item be marked N/A?

**Why is this needed**:

The enhancement issue template for kubernetes-sigs/kueue#1466 requires an explicit "API change" artifact. This investigation confirms whether that item applies or can be closed as N/A, preventing unnecessary scope in the implementation PR.
