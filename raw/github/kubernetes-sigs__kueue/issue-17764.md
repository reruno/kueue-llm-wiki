## Description


**What would you like to be documented or improved**:

Follow-up from the review of #16578. The KEP and the TAS docs differ from the code in three places.

1. Spreading counts only Workloads in the same ClusterQueue and flavor.
The KEP's accounting key and spreading group name only the namespace, and the docs say "evaluated per namespace".
The count looks only at Workloads admitted to the same ClusterQueue ([L115](https://github.com/kubernetes-sigs/kueue/blob/fb59c5c2af5aa07a6098d21e3a86379fb4d533e6/pkg/cache/scheduler/tas_spread_tree_count.go#L115)) and skips other flavors ([L151](https://github.com/kubernetes-sigs/kueue/blob/fb59c5c2af5aa07a6098d21e3a86379fb4d533e6/pkg/cache/scheduler/tas_spread_tree_count.go#L151)).
Other matching Workloads are skipped with no error, event or condition, so a rack can end up with more than `maxShareAllowingPlacement` of the groups.
This matters for `workloadLabelSelectors` that match Workloads in other ClusterQueues, and for a ClusterQueue with several TAS flavors whose nodes share racks.

2. A workload blocked only by spreading gets `WaitingForQuota`, not `TopologyPlacementFailed`.
The `WithSimulateEmpty(true)` pass ([L545-L548](https://github.com/kubernetes-sigs/kueue/blob/fb59c5c2af5aa07a6098d21e3a86379fb4d533e6/pkg/scheduler/flavorassigner/flavorassigner.go#L545-L548)) gets empty PodSet group counts ([L102-L104](https://github.com/kubernetes-sigs/kueue/blob/fb59c5c2af5aa07a6098d21e3a86379fb4d533e6/pkg/cache/scheduler/tas_spread_tree_count.go#L102-L104)), so the PodSet fits, and with no preemption targets the reason is `WaitingForQuota` ([L530-L533](https://github.com/kubernetes-sigs/kueue/blob/fb59c5c2af5aa07a6098d21e3a86379fb4d533e6/pkg/scheduler/scheduler.go#L530-L533)).
The Visibility section gives `TopologyPlacementFailed` as the example, and the Beta item about the `TopologyPlacementFailed` reason suffix assumes the same.

3. The "Example with two rules" Workload has no `topologyRequest.required`, so the Workload webhook rejects it.
With `required` set to zone, the partition rule is below the requested level and the workload stays pending.
Setting `required` to the partition level makes the example valid.
