## Description


**What happened**:

When Kueue replaces a failed node of a TAS Workload, the replacement fails if another node of the topology assignment is cordoned, even though free nodes exist and the Pods on the cordoned node are still running.

Cordoned nodes are removed from the TAS snapshot. Before replacing a node, `findReplacementAssignment` checks that every other node of the assignment is in the snapshot (`isTopologyAssignmentStaleIgnoringNodes`), so the cordoned node makes the assignment look stale.

**What you expected to happen**:

The drained node is replaced on a free node, and the Pods on the other nodes keep running.

**How to reproduce it (as minimally and precisely as possible)**:

```shell
# 1. Create a Job with 3 Pods
$ cat <<EOF | kubectl create -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: roll
  labels:
    kueue.x-k8s.io/queue-name: lq
spec:
  parallelism: 3
  completions: 3
  suspend: true
  template:
    spec:
      restartPolicy: Never
      containers:
      - name: c
        image: busybox:1.36
        command: ["sleep", "3600"]
        resources:
          requests:
            cpu: 10m
            example.com/slot: "1"
          limits:
            example.com/slot: "1"
EOF

# 2. Cordon worker2. Its Pod keeps running and the node is not reported unhealthy.
$ kubectl cordon kueue-h1-repro-worker2

# 3. Drain worker (wait ~40s). worker4 is free.
$ kubectl drain kueue-h1-repro-worker --ignore-daemonsets

# 4. Check the Workload
# OUTPUT: the Workload was evicted and cannot be admitted again while worker and worker2 are cordoned
$ kubectl get events --field-selector involvedObject.name=job-roll-6edf6 -o custom-columns=REASON:.reason,MSG:.message
REASON                     MSG
QuotaReserved              Quota reserved in ClusterQueue cq, wait time since queued was 0s
Admitted                   Admitted by ClusterQueue cq, wait time since reservation was 0s
EvictedDueToNodeFailures   Workload was evicted as there was no replacement for unhealthy node(s): kueue-h1-repro-worker
TopologyPlacementFailed    couldn't assign flavors to pod set main: topology "host" allows to fit only 2 out of 3 pod(s)

```
