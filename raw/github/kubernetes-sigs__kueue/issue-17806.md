**What happened**:

On the manager cluster, MultiKueue emits the `Normal` `MultiKueue` event `The workload was admitted on "<worker>"` on every reconcile of a Workload whose remote Workload is admitted, not only when the admission check becomes `Ready`.

`syncAdmittingRemoteState` (`pkg/controller/admissionchecks/multikueue/workload.go`) sets `needsACUpdate` to `acs.State != Retry && acs.State != Rejected`, which is also true when the admission check is already `Ready`. In that case it patches the admission check with the same state and message and emits the event again. 

The Workload is reconciled at least every `workerLostTimeout` (15 minutes by default) and on every change of the local or remote Workload, so the event repeats for the whole lifetime of the Workload.

**What you expected to happen**:

The event is emitted once, when the admission check transitions to `Ready`, in the same way as `kueue_multikueue_workload_admitted` is reported only when "the sync actually flips the admission check to Ready in this reconcile".

**How to reproduce it (as minimally and precisely as possible)**:

1. Set up a MultiKueue manager and a worker cluster.
2. Create a Job that is admitted on the worker.
3. Run `kubectl describe workload <name>` on the manager cluster several times.
4. The `The workload was admitted on "<worker>"` event is repeated (`xN`) while the Job runs.

Unit tests already expect this behavior: in `TestWlReconcile`, cases that start with the admission check in the `Ready` state, such as "admitting remote is kept when another worker's remote is out of sync", expect the event.

**Anything else we need to know?**:

The repeated patch of the admission check was originally intentional: a comment says that `LastTransitionTime` "is used to detect the lost worker state". The lost worker is now detected from the connection state (`admittingWorkerLostSince`), so the fix needs to confirm whether the repeated patch is still needed. Independently of that, the event can be emitted only when the admission check was not `Ready` before the patch.
