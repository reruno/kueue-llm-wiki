## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

When the API server rejects Workload creation due to validation, surface the reason on the owning Job (e.g. a Warning event), rather than only in controller logs.

**Why is this needed**:

In #17427, the Job remained suspended with no Workload or Warning event. The rejection appeared only in controller logs because `handleJobWithNoWorkload` returns the Workload `Create` error without emitting an event.

#17436 addresses this particular case through earlier admission validation, but other Workload validation failures can still reach this path.

Reproduced on kind v1.37 with #17419 applied (Oct 19). See #17427 for reproduction steps.

Related: #17419, #17436. #13775 provides a Warning event precedent for a different, pre-Create failure.


**Completion requirements**:

- Surface the validation rejection reason on the affected Job.
- Avoid excessive duplicate events on repeated reconciliation.
- Add regression coverage for a rejected Workload `Create`.
