**What would you like to be cleaned**:

Remove the `behavioral.SetLocalQueueStopPolicyWithTimeout` helper (`test/util/behavioral/queues.go`). It has only two callers, and both use it with `behavioral.MediumTimeout` to wait for something else:

- `test/e2e/sequential/baseline/ha_test.go`, in the step `verify the localQueue can be fetched and mutated`
- `test/e2e/sequential/baseline/default_config_test.go`, in the same step

In both tests the step runs after the caBundle has been cleared and restored on the LocalQueue CRD conversion webhook and the mutating webhooks. The long timeout isn't there to test the stop policy. It's there to wait until the apiserver accepts webhook requests with the restored caBundle.

**Why is this needed**:

- The tests should say what they wait for. Right now the webhook-readiness wait is hidden inside a stop-policy helper, so the tests are harder to read and the helper's purpose is misleading.
- This prepares #17758, which merges the ClusterQueue and LocalQueue stop-policy helpers into generic `SetQueueStopPolicy` and `UnsetQueueStopPolicy`. Without this change, that PR has to keep a `WithTimeout` variant for these two callers. It also switches the poll interval to `ShortInterval` (10ms), so the retry loop would poll every 10ms for up to `MediumTimeout`.

Related: #17758 (review comment: https://github.com/kubernetes-sigs/kueue/pull/17758#discussion_r4379721210), #17634, #17602
