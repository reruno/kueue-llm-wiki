## Description

<!-- Filed from the bug-report template (.github/ISSUE_TEMPLATE/BUG_REPORT.md, labels: kind/bug) -->

**What happened**:

The pod integration's MultiKueue adapter builds the remote Pod by deep-copying the whole live manager-side `Pod.Spec`:

https://github.com/kubernetes-sigs/kueue/blob/3c68ccf53b92dd438ee1b18fcba9474dd1ec1749/pkg/controller/jobs/pod/pod_multikueue_adapter.go#L235-L238

```go
remotePod = corev1.Pod{
    ObjectMeta: api.CloneObjectMetaForCreation(&localPod.ObjectMeta),
    Spec:       *localPod.Spec.DeepCopy(),
}
```

This includes `spec.ephemeralContainers`. The API server rejects `ephemeralContainers` on Pod create (they can only be added through the `ephemeralcontainers` subresource). So if a manager-side Pod was debugged (for example with `kubectl debug`) while it was waiting for MultiKueue dispatch, the `remoteClient.Create` call should fail on the worker with a `spec.ephemeralContainers: Forbidden` validation error, and the Pod never syncs to the worker. The error is logged ("Failed to create remote pod") and returned, so it is retried and keeps failing.

Note: this was found by reading the code during review of #17855. I have not reproduced it end-to-end yet.

**What you expected to happen**:

The remote Pod is created on the worker cluster even when the manager-side Pod has ephemeral containers. Ephemeral containers are a debugging aid of the manager-side object and should not be propagated to the remote create.

**How to reproduce it (as minimally and precisely as possible)**:

1. Set up MultiKueue (manager plus at least one worker cluster) with the `pod` integration enabled and a ClusterQueue with a MultiKueue AdmissionCheck.
2. On the manager, create a Pod with the `kueue.x-k8s.io/queue-name` label and the Kueue scheduling gate, while the workload is not yet dispatched (for example the quota is not yet available, or the AdmissionCheck is pending).
3. Add an ephemeral container to it: `kubectl debug <pod> -it --image=busybox --target=<container>`.
4. Let the workload be admitted and dispatched to a worker.
5. Observe the remote create failing in the Kueue manager logs (`Failed to create remote pod`) with `spec.ephemeralContainers: Forbidden`, and no Pod on the worker.

**Anything else we need to know?**:

Suggested minimal fix (not yet tested): clear `EphemeralContainers` on the remote copy before create, e.g.

```go
spec := localPod.Spec.DeepCopy()
spec.EphemeralContainers = nil
remotePod = corev1.Pod{
    ObjectMeta: api.CloneObjectMetaForCreation(&localPod.ObjectMeta),
    Spec:       *spec,
}
```

plus a unit test in the pod MultiKueue adapter tests. There may be other live-Pod-only fields worth reviewing at the same time.

I checked the other MultiKueue adapters at the same SHA: they copy the `Spec` of their own CRs (Job, JobSet, MPIJob, Kubeflow, Ray, StatefulSet, LeaderWorkerSet, ...), whose pod templates cannot carry `ephemeralContainers`. The pod adapter appears to be the only one that builds the remote object from a live Pod spec.

Related: #17601, #17855.
