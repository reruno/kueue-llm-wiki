## Description

**What would you like to be cleaned**:

Cache auxiliary data for one `kueuectl list workload` invocation.

The command currently resolves LocalQueues, ClusterQueue pending workload summaries, and owner API discovery data separately for every Workload-list page. Reuse values already resolved on an earlier page, including NotFound results, without changing CLI output or public APIs.

**Why is this needed**:

Workload listing is paginated with a default page size of 100. When Workloads on multiple pages refer to the same LocalQueue, ClusterQueue, or API version, the command repeats the same Kubernetes API requests on every page. This increases command latency and unnecessary API server and visibility API load for large lists.
