## Description

**What would you like to be cleaned**:

Enforce non-Kueue feature-gate prerequisites for `SchedulerLibraryDeepIntegration` through imperative validation in `LoadAndValidateFeatureGates` (`pkg/config/validation.go`), not the declarative Kueue feature-gate dependency system.

- Validate the supported prerequisite combinations, starting with `TopologyAwareWorkloadScheduling` and `CompositePodGroup`. The reported required-topology case works with either gate enabled; do not require both without establishing that requirement.
- Reject unsupported combinations with an actionable configuration error.
- Add coverage in `pkg/config/validation_test.go` for invalid and valid combinations, including deep integration disabled and feature gates supplied through CLI or configuration.

**Why is this needed**:

In #17878, testing the #17678 placement change showed that required topology can still be violated when deep integration is enabled and both prerequisite gates are disabled. Validation should reject unsupported configurations instead of allowing incorrect topology assignments. These prerequisites are non-Kueue feature gates.
