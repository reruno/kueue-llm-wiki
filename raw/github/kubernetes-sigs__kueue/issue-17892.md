## Description

**What would you like to be added**:

Report the `multikueue_cluster_status` metric independently of MultiKueue quota automation and of the MultiKueue CapacityProvider, behind a new alpha feature gate `MultiKueueMetricForClusterByStatus`.

The metric reports the `Active` status of each MultiKueue worker cluster, per manager ClusterQueue that refers to it (it mirrors the `Active` condition of the `MultiKueueCluster`). It was added in #13798 as part 1 of #11132.

Today only the KEP-9988 Alpha1 ClusterQueue reconciler reports it, so Kueue emits the metric only when the `MultiKueueManagerQuotaAutomation` alpha feature gate (off by default) is enabled. This coupling was not intended: the metric is about worker cluster connectivity, not quota automation. KEP-17401 (#17560) removes the Alpha1 code, and with it the metric.

Possible places to report the metric (from the discussion in https://github.com/kubernetes-sigs/kueue/pull/17560#discussion_r4387989626):
1. Keep `pkg/controller/admissionchecks/multikueue/clusterqueue.go` to only report the metric, and register it independently of the quota automation feature gates.
2. Move the reporting to `pkg/controller/admissionchecks/multikueue/multikueuecluster.go`.
3. Move the reporting to the MultiKueue AdmissionCheck reconciler (`admissioncheck.go`), which already reads the `Active` condition of each worker cluster in the `MultiKueueConfig`.

**Why is this needed**:

MultiKueue users need a metric to alert on worker clusters that are not connected. Without it, the only signal is the `Active` condition on the `MultiKueueCluster` object, which cannot be graphed or alerted on. After KEP-17401, the metric is not available at all until this issue is done.
