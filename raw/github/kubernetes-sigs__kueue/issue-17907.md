## Description

**What happened**:

The API server accepts a suspended Job whose `spec.template.metadata.annotations` total 262,144 bytes, the limit.
When its Workload is admitted, Kueue adds `kueue.x-k8s.io/workload: <workload name>` to the template ([reconciler.go#L2202](https://github.com/kubernetes-sigs/kueue/blob/358f92f1ad692c84a86171131da4bbffd9c2cd33/pkg/controller/jobframework/reconciler.go#L2202)), and the patch that unsuspends the Job is rejected:

```
Job.batch "test-job" is invalid: spec.template.annotations: Too long: may not be more than 262144 bytes
```

For the two errors that [`podset.IsPermanent`](https://github.com/kubernetes-sigs/kueue/blob/358f92f1ad692c84a86171131da4bbffd9c2cd33/pkg/podset/podset.go#L272-L274) recognizes, Kueue finishes the Workload with reason `FailedToStart` ([reconciler.go#L652-L664](https://github.com/kubernetes-sigs/kueue/blob/358f92f1ad692c84a86171131da4bbffd9c2cd33/pkg/controller/jobframework/reconciler.go#L652-L664)).
This error is not one of them and goes back to the requeue, so the controller logs it on every retry, and nothing records it on the Job or the Workload.
The Job stays suspended, and the Workload stays admitted with its quota reserved.

waitForPodsReady, on by default since v0.19, evicts the Workload after its timeout, 30 minutes by default ([defaults.go#L108-L116](https://github.com/kubernetes-sigs/kueue/blob/358f92f1ad692c84a86171131da4bbffd9c2cd33/apis/config/v1beta2/defaults.go#L108-L116)).
The Workload is then requeued, admitted again, and the start fails the same way.
`backoffLimitCount` defaults to null, which requeues without limit ([configuration_types.go#L460-L462](https://github.com/kubernetes-sigs/kueue/blob/358f92f1ad692c84a86171131da4bbffd9c2cd33/apis/config/v1beta2/configuration_types.go#L460-L462)).

**What you expected to happen**:

The start failure shows up on the Job or the Workload, and the Workload does not keep quota for a Job that cannot start.

**How to reproduce it (as minimally and precisely as possible)**:

Add this table to the "Job controller" Describe in `test/integration/singlecluster/controller/jobs/job/job_controller_test.go`, with a `strings` import:

```go
ginkgo.DescribeTable("starting a job whose template annotations are near the size limit",
	func(templateBytes int, wantSuspend bool) {
		const key = "example.com/data"
		job := testingjob.MakeJob(jobName, ns.Name).Queue("queue").Obj()
		job.Spec.Template.Annotations = map[string]string{key: strings.Repeat("x", templateBytes-len(key))}
		behavioral.MustCreate(ctx, k8sClient, job)
		wlKey := types.NamespacedName{Name: workloadjob.GetWorkloadNameForJob(job.Name, job.UID), Namespace: ns.Name}
		wl := &kueue.Workload{}
		gomega.Eventually(func(g gomega.Gomega) {
			g.Expect(k8sClient.Get(ctx, wlKey, wl)).Should(gomega.Succeed())
		}, behavioral.Timeout, behavioral.Interval).Should(gomega.Succeed())
		integration.SetQuotaReservation(ctx, k8sClient, wlKey, utiltestingapi.MakeAdmission("cq").Obj())
		integration.SyncAdmittedConditionForWorkloads(ctx, k8sClient, wl)
		suspendIs := func(g gomega.Gomega) {
			createdJob := &batchv1.Job{}
			g.Expect(k8sClient.Get(ctx, client.ObjectKeyFromObject(job), createdJob)).Should(gomega.Succeed())
			g.Expect(ptr.Deref(createdJob.Spec.Suspend, false)).Should(gomega.Equal(wantSuspend))
		}
		gomega.Eventually(suspendIs, behavioral.Timeout, behavioral.Interval).Should(gomega.Succeed())
		gomega.Consistently(suspendIs, behavioral.ConsistentDuration, behavioral.Interval).Should(gomega.Succeed())
	},
	// Kueue adds kueue.x-k8s.io/workload with the 18-byte Workload name, 41 bytes in all.
	ginkgo.Entry("stays suspended at the limit before Kueue adds its annotation", 262144, true),
	ginkgo.Entry("starts at the limit after Kueue adds its annotation", 262144-41, false),
)
```

**Anything else we need to know?**:

- AdmissionCheck `podSetUpdates` annotations are merged into the same template ([reconciler.go#L2217-L2226](https://github.com/kubernetes-sigs/kueue/blob/358f92f1ad692c84a86171131da4bbffd9c2cd33/pkg/controller/jobframework/reconciler.go#L2217-L2226)).
  The ProvisioningRequest check adds two of them ([controller.go#L841-L842](https://github.com/kubernetes-sigs/kueue/blob/358f92f1ad692c84a86171131da4bbffd9c2cd33/pkg/controller/admissionchecks/provisioning/controller.go#L841-L842)), which leaves less room.
- The Workload webhook checks the template annotations ([workload_webhook.go#L186-L189](https://github.com/kubernetes-sigs/kueue/blob/358f92f1ad692c84a86171131da4bbffd9c2cd33/pkg/webhooks/workload_webhook.go#L186-L189)) and each `podSetUpdates` entry ([workload_webhook.go#L266-L285](https://github.com/kubernetes-sigs/kueue/blob/358f92f1ad692c84a86171131da4bbffd9c2cd33/pkg/webhooks/workload_webhook.go#L266-L285)) on their own.
  Kueue does not check the total it writes to the Job before the patch.
- release-0.20 and release-0.19 add `kueue.x-k8s.io/workload` when TopologyAwareScheduling is enabled ([0.20](https://github.com/kubernetes-sigs/kueue/blob/303438cbae84b442adbb178678bc5f351f6c7cda/pkg/controller/jobframework/reconciler.go#L2203-L2205), [0.19](https://github.com/kubernetes-sigs/kueue/blob/9ab47e02138216a16bf1de4bc82b329c80a69b93/pkg/controller/jobframework/reconciler.go#L1945-L1946)), which it is by default since v0.14.
  I ran the tests only on main.
