## Description

**What happened**:

`generateVariant` in the ConcurrentAdmission controller uses the parent Workload's `Labels` and `Annotations` maps directly when constructing each variant, then mutates both of those maps. Since Go maps have reference semantics, this changes the passed-in **parent** Workload and allows separately generated **variants** to mutate each other's metadata.

**Affected code:** [`pkg/controller/concurrentadmission/controller.go:363–377`](https://github.com/kubernetes-sigs/kueue/blob/fc33bbe85dfdbb481819696f75f3f56cfe2296a1/pkg/controller/concurrentadmission/controller.go#L363-L377)

```go
variant := &kueue.Workload{
    Name:          jobframework.GetWorkloadNameForVariant(parent.Name, parent.UID, parent.GroupVersionKind(), string(flavor)),
    Namespace:     parent.Namespace,
    Labels:        parent.Labels,      // map alias, not a copy
    Annotations:   parent.Annotations, // map alias, not a copy
    ManagedFields: parent.ManagedFields,
    Spec:          parent.Spec,
    Status:        parent.Status,
}
variant.Spec.PreemptionGates = slices.Clone(variant.Spec.PreemptionGates)
workload.EnsurePreemptionGateOnSpec(variant, controllerconsts.ConcurrentAdmissionPreemptionGate)
delete(variant.Labels, controllerconsts.ConcurrentAdmissionParentLabelKey)
metav1.SetMetaDataAnnotation(&variant.ObjectMeta, controllerconsts.WorkloadAllowedResourceFlavorAnnotation, string(flavor))
```

This has three **deterministic, in-memory** consequences:

1. **Parent classification is invalidated.** Removing `ConcurrentAdmissionParentLabelKey` from a variant also removes it from the passed-in parent. After the call, `concurrentadmission.IsParent(parent)` returns `false` instead of `true`.
2. **Variant-only flavor metadata leaks into the parent.** When `parent.Annotations` is non-nil, setting the variant's allowed-flavor annotation also adds it to or overwrites it in the parent.
3. **Sibling variants can overwrite one another.** Generating `spot := generateVariant(parent, "spot")` followed by `onDemand := generateVariant(parent, "on-demand")` changes `spot`'s in-memory allowed-flavor annotation to `on-demand` when the parent starts with a non-nil annotations map. The returned variants are not independent objects with respect to their metadata.

The label mutation occurs whenever the parent carries its parent marker. The annotation aliasing requires a non-nil annotations map: `SetMetaDataAnnotation` allocates a new map for the variant if it starts nil.

**Impact and limits of the finding:** This is a demonstrable aliasing/correctness defect at the Go object level. I am **not** claiming that the Kubernetes API server necessarily persists the parent's modified label or that quota is already double-counted in production; those would require separate end-to-end evidence. The normal controller immediately creates each variant, which can mask the sibling-alias symptom in API-server state. Nevertheless, the helper violates parent/child isolation and may cause surprising behavior for callers retaining objects. It also makes test setup unreliable: [`controller_test.go:2747–2753`](https://github.com/kubernetes-sigs/kueue/blob/fc33bbe85dfdbb481819696f75f3f56cfe2296a1/pkg/controller/concurrentadmission/controller_test.go#L2747-L2753) invokes `generateVariant(parent, "spot")` before constructing a fake client with `parent`, so that fixture is created after the parent's identifying label has already been removed.

**What you expected to happen**:

- Constructing any variant does not change the parent Workload's `ObjectMeta`.
- The parent retains `ConcurrentAdmissionParentLabelKey: "true"` and remains recognizable by `concurrentadmission.IsParent`.
- Each variant excludes the parent label and has its own correct `WorkloadAllowedResourceFlavorAnnotation`.
- The metadata of one variant, its siblings and the parent is independent; modifying one must not modify the others.
- Existing preemption-gate, admission, and resource-flavor behavior is preserved.

func TestGenerateVariantPreservesParentMetadataAndSiblingIsolation(t *testing.T) {
    parent := &kueue.Workload{
        TypeMeta: metav1.TypeMeta{
            APIVersion: kueue.SchemeGroupVersion.String(),
            Kind:       "Workload",
        },
        ObjectMeta: metav1.ObjectMeta{
            Name:      "training",
            Namespace: "default",
            UID:       types.UID("parent-uid"),
            Labels: map[string]string{
                constants.ConcurrentAdmissionParentLabelKey: "true",
                "example.com/team": "ml",
            },
            Annotations: map[string]string{
                "example.com/request-id": "abc123",
            },
        },
    }
    original := parent.DeepCopy()

    spot := generateVariant(parent, "spot")
    onDemand := generateVariant(parent, "on-demand")

    if diff := cmp.Diff(original.ObjectMeta, parent.ObjectMeta); diff != "" {
        t.Errorf("generateVariant mutated parent metadata (-want +got):\n%s", diff)
    }
    if got := parent.Labels[constants.ConcurrentAdmissionParentLabelKey]; got != "true" {
        t.Errorf("parent marker lost: got %q", got)
    }
    if _, found := spot.Labels[constants.ConcurrentAdmissionParentLabelKey]; found {
        t.Error("variant unexpectedly carries the parent marker")
    }
    if got := spot.Annotations[constants.WorkloadAllowedResourceFlavorAnnotation]; got != "spot" {
        t.Errorf("first variant flavor unexpectedly changed: got %q, want spot", got)
    }
    if got := onDemand.Annotations[constants.WorkloadAllowedResourceFlavorAnnotation]; got != "on-demand" {
        t.Errorf("second variant flavor wrong: got %q, want on-demand", got)
    }
    spot.Labels["example.com/variant-only"] = "yes"
    if _, exists := parent.Labels["example.com/variant-only"]; exists {
        t.Error("changing the variant label modified the parent")
    }
    if _, exists := onDemand.Labels["example.com/variant-only"]; exists {
        t.Error("changing the first variant label modified the sibling")
    }
}

**Anything else we need to know?**:

**Root cause:** `Labels` and `Annotations` reuse the mutable parent maps, followed by `delete` and `SetMetaDataAnnotation`. Notably, the function already clones `Spec.PreemptionGates` to avoid a similar ownership problem for that slice; the same isolation is missing for metadata maps.

**Minimal proposed fix (illustrative):**

```go
import "maps"

// Within generateVariant's Workload literal:
Labels:      maps.Clone(parent.Labels),
Annotations: maps.Clone(parent.Annotations),
```

Keep the subsequent variant-specific `delete` and `SetMetaDataAnnotation` operations. `maps.Clone(nil)` returns nil, and the annotation helper allocates a map on the variant when necessary. This leaves other struct-field copy semantics unchanged, avoids an unnecessary refactor, and requires no CRD/API/configuration changes.

**Regression / acceptance criteria:**

- [ ] Generating one or multiple variants leaves the parent's metadata unchanged.
- [ ] Generating a second variant never rewrites the first one's flavor or labels.
- [ ] Parent-marker removal only affects the variant.
- [ ] Nil and non-nil parent annotation maps are both covered.
- [ ] Reconciliation tests still pass for multi-flavor and admitted-parent scenarios.
- [ ] The existing fake-client fixture that invokes `generateVariant` before registering the parent is reviewed for accidental parent mutation.
