## Description

**What would you like to be added**:

Allow adding or changing the `kueue.x-k8s.io/queue-name` and `kueue.x-k8s.io/priority-class` labels on a Deployment that has ready replicas.

Currently the Deployment validating webhook rejects such an update when `status.readyReplicas > 0`:

```
admission webhook "vdeployment.kb.io" denied the request: metadata.labels[kueue.x-k8s.io/queue-name]: 
Invalid value: "queue-name": field is immutable
```

The same applies to `kueue.x-k8s.io/priority-class`: it cannot be added to a Deployment with ready replicas, and the default WorkloadPriorityClass is not applied in that case either.

Removing either label stays forbidden and is out of scope of this issue.

**Why is this needed**:
Users who adopt Kueue for an existing service cannot put a running Deployment under Kueue management without downtime. Today the only options are to scale the Deployment to 0 replicas, force-replace it, or create a second Deployment behind the same Service, and some Helm charts or deployment policies do not allow the last one.

The restriction does not protect anything for Deployments:

- Kueue does not create a Workload for a Deployment. The webhook only propagates the labels to the Pod template, and every Pod gets its own Workload.
- Changing a label on the Deployment changes the Pod template, so the Deployment controller starts a regular rolling update. New Pods are gated until Kueue admits them. Running Pods keep their labels and their Workloads.
- Users can already get almost the same result by setting the labels directly on `spec.template.metadata.labels`, which the Deployment webhook does not validate.

The immutability check for running Deployments was carried over from Job semantics when queue-name mutation was allowed for Deployments with no ready replicas (#3552, #3528).

Note for users: while the new Pods wait for admission, the default `maxUnavailable: 25%` lets the Deployment controller terminate some old Pods. To keep full capacity during the rollout, set `maxUnavailable: 0`.

Reported on Slack by a user on Kueue v0.20.3: https://kubernetes.slack.com/archives/C032ZE66A2X/p1793264052075399
