## Description

<!-- Please only use this template for submitting clean up requests -->

**What would you like to be cleaned**:

Issues that CodeRabbit opens on request often have no `kind/*` label, although every template in `.github/ISSUE_TEMPLATE/` defines one in its `labels` field. A maintainer then has to add it with `/kind ...`.

GitHub applies template labels only when an issue is created through the web form. CodeRabbit creates issues with `gh issue create`, so it must pass each label explicitly with `--label`. It does this only sometimes:

  - Labeled by `coderabbitai[bot]`: #17761, #17905.
  - No label at creation: #17897, #17922, #17898, #17762, #17980, #17982.

For example, for #17980 CodeRabbit read `.github/ISSUE_TEMPLATE/CLEANUP.md` and `cmd/experimental/skills/kueue-pr-issue-workflow/SKILL.md`, then ran `gh issue create` without `--label` ([command](https://github.com/kubernetes-sigs/kueue/pull/17970#issuecomment-<CodeRabbit-reply-id>)).

The skill says "Apply all labels specified in the selected template's `labels` field", but it does not say that the labels must be passed explicitly when the issue is created from the CLI or API. `.coderabbit.yaml` only points to `AGENTS.md`, which links to the skill.

Proposed change:
  - In `kueue-pr-issue-workflow/SKILL.md`, state that template labels are applied only through the web form, and that `gh issue create` or the API must pass each label with `--label`.
  - In `tone_instructions` in `.coderabbit.yaml`, add a short instruction to pass every template label with `gh issue create --label`.

**Why is this needed**:

Unlabeled issues are harder to triage and filter, and each one needs a manual `/kind` command.
