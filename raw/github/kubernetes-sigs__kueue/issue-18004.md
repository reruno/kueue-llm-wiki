## Description

**What happened**

On Kubernetes v1.36.3 (k3s) with Kueue v0.20.3, every eviction (cohort reclaim preemption) of a batch/Job logs a few `Reconciler error`s, sometimes many:

```
restore info: Job.batch "<name>" is invalid: spec.template: Invalid value: {<entire pod template>}: field is immutable
```

The error eventually clears once the job controller reconciles, but each retry logs the whole pod template. In our case that is ~47 KB per line and ~5-8 lines per preemption. With a frequently preempted borrowing workload, this made up 99% of our cluster's error-log bytes.

**Why**

Kubernetes 1.36 promotes `MutableSchedulingDirectivesForSuspendedJobs` to beta (default on). `pkg/registry/batch/job/strategy.go` now permits scheduling-directive changes only when:

```go
suspended && (notStarted || hasSuspendedCondition) && job.Status.Active == 0
```

`Job.Stop()` in `pkg/controller/jobs/job/job_controller.go` suspends the Job, resets `status.startTime`, and then immediately patches `RestorePodSetsInfo` (removing the ResourceFlavor `nodeLabels` it injected at admission). At that moment `status.active` is still non-zero, because the job controller has not yet deleted the pods and synced status. So the restore patch is rejected and retried with backoff until `active == 0`. The same code is on `main`.

**What you expected**

No error: `Stop()` should wait for the Job to actually be suspended before restoring.

**Suggested fix**

In `Stop()`, when `j.Status.Active > 0` after suspending (or when the `JobSuspended` condition is not yet true), skip the restore and requeue without returning an error. The next reconcile, after the job controller sets `active: 0` and `JobSuspended=True`, performs the restore.

**Workaround**

Setting `feature-gates=MutableSchedulingDirectivesForSuspendedJobs=false` on kube-apiserver and kube-controller-manager restores the pre-1.36 rule (suspended and no `startTime`), which `Stop()` already satisfies.

**Environment**
- Kubernetes v1.36.3+k3s1; `kubernetes_feature_enabled{name="MutableSchedulingDirectivesForSuspendedJobs"} 1`
- Kueue v0.20.3; ResourceFlavors with `nodeLabels` (`kubernetes.io/hostname`); cohort with `reclaimWithinCohort: Any`
- Job has `podFailurePolicy`, so `podReplacementPolicy: Failed`
