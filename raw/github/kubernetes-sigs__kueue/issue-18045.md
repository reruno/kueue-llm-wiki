## Description

**What happened**:

Kueue computes PodGroup roles from a shape of the pod spec (`SpecShape` in `pkg/util/pod/pod.go`). For containers, the shape only records resource requests and ports (`ContainersShape`), so `restartPolicy` is invisible to the hash. As a result, a pod with a restartable init container (sidecar, `restartPolicy: Always`) gets the same role hash as an otherwise identical pod with a regular init container.

In a PodGroup containing both, the pods collapse into a single PodSet with a single count, even though their runtime resource footprints differ: a regular init container runs to completion before the main containers start, while a sidecar keeps consuming resources alongside them.

**What you expected to happen**:

Pods whose init containers differ in `restartPolicy` should get different role hashes and be accounted as separate roles in the PodGroup, since their peak co-running resource usage differs.

**How to reproduce it (as minimally and precisely as possible)**:

1. Create two pods with identical specs except for the init container: pod A has a regular init container requesting `cpu: 500m`; pod B has the same init container with `restartPolicy: Always`. Both have a main container requesting `cpu: 1`.
2. Put both pods in the same PodGroup (PodGroup name and scheduling gate).
3. Observe the generated Workload: both pods are aggregated into one PodSet with count 2, instead of two PodSets with count 1 each.

**Anything else we need to know?**:

- The fix should include `restartPolicy` in the init container shape only when it is set, so that role hashes of pods without restartable init containers stay stable across upgrades and existing PodGroups keep their roles.
- Users can already work around this by supplying distinct `kueue.x-k8s.io/role-hash` annotations, but the automatically computed hash should not need this workaround.

**Environment**:
- Kueue version: main (`80da74587` at the time of reporting)
- Others: found by source inspection; no specific cluster needed to reproduce.
