**What happened**:

With `CustomMetricLabels` on, this gauge has one series per ClusterQueue label value. But each series holds the whole Cohort count, and only the series of the ClusterQueue that just changed gets updated. So the series for one Cohort disagree with each other, and summing them over-counts.

Cohort `a` has `cq1` (`team=alpha`) and `cq2` (`team=beta`), with one admitted Workload each:

```
kueue_cohort_subtree_admitted_active_workloads{cohort="a",custom_team="alpha"} 1
kueue_cohort_subtree_admitted_active_workloads{cohort="a",custom_team="beta"}  2
```

The Cohort has 2 Workloads, but `sum by (cohort)` says 3. After I delete the `cq2` Workload, both series say 1, so the sum is 2 for one Workload.

**What you expected to happen**:

Summing over a Cohort gives its real count. Without custom labels you get one series with 2, then 1, which is right.

**How to reproduce it (as minimally and precisely as possible)**:

Take `TestCohortAdmittedWorkloadsDropsSeriesOfMovedClusterQueueCustomLabels` in `pkg/cache/scheduler`, skip the move, and read the series for `cohort="a"`.

**Anything else we need to know?**:

This has been there since #10013 (v0.17.0). I think each series should count only the ClusterQueues with that label value, so the sum works. #14186 touches the same labels.

**Environment**:
- Kubernetes version (use `kubectl version`): n/a (unit test)
- Kueue version (use `git describe --tags --dirty --always`): main at 8705516bb, same code in v0.17.0 through v0.20.0
