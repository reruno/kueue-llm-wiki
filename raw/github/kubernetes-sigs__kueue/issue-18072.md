### Comment by [@ekam-walia](https://github.com/ekam-walia) — 2026-11-01T21:04:45Z

Hi all, I think the root is in its setup, not in Kueue's code

In the `PodsReady timeout while a scale-up slice waits for quota` , the config has no requeuing strategy:

https://github.com/kubernetes-sigs/kueue/blob/4a2bb59f9b3ce4474dc79280bcf3ab381951d57c/test/integration/singlecluster/controller/jobs/raycluster/raycluster_controller_test.go#L1321-L1323

With no backoff, a workload evicted for PodsReadyTimeout is requeued and re admitted almost immediately. Evicted=True/PodsReadyTimeout therefore exists for only a very short window.

Then Evicted flips to False with the message Previously: Exceeded the PodsReady timeout …, and Requeued becomes BackoffFinished. The failure dump shows exactly this: QuotaReserved, Admitted, Requeued and Evicted=False. The eviction happened, but the Eventually polling initialSlice missed the transient state. It passes whenever a poll lands inside that window, which explains the roughly 1 in 20 failure rate.

I am happy to open a PR to fix this Issue which can I think include making the eviction state persistent in the test setup . It will fix the real cause, which is a race between the test’s polling and a very short lived condition. It doesn’t touch production code, and the `It `stays as it is.
