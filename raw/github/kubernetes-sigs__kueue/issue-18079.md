**What happened**:

`Reconcile` calls [`createVariants`](https://github.com/kubernetes-sigs/kueue/blob/3cdda2dc1de7ad40cc51e45a206469f8c2aa8e07/pkg/controller/concurrentadmission/controller.go#L218-L221) for every Parent it loads. It does not check whether the Parent is finished or has a `deletionTimestamp`. Adding a flavor to a ClusterQueue [enqueues every Parent](https://github.com/kubernetes-sigs/kueue/blob/3cdda2dc1de7ad40cc51e45a206469f8c2aa8e07/pkg/controller/concurrentadmission/controller.go#L157-L181) in it, finished ones included, so each finished Parent gets a new Variant for the new flavor. The new Variant has no `Finished` condition, and in envtest the scheduler admitted it in every run. `Reconcile` then deactivated it, since the old Variant of the finished Parent is still `Admitted`.

On the next reconcile, [`syncVariantEvictionStatus`](https://github.com/kubernetes-sigs/kueue/blob/3cdda2dc1de7ad40cc51e45a206469f8c2aa8e07/pkg/controller/concurrentadmission/controller.go#L401-L431) sees the evicted Variant that still holds quota and sets `Evicted` on the finished Parent. `Reconcile` then [returns early](https://github.com/kubernetes-sigs/kueue/blob/3cdda2dc1de7ad40cc51e45a206469f8c2aa8e07/pkg/controller/concurrentadmission/controller.go#L229-L236) and never reaches [`syncFinished`](https://github.com/kubernetes-sigs/kueue/blob/3cdda2dc1de7ad40cc51e45a206469f8c2aa8e07/pkg/controller/concurrentadmission/controller.go#L680-L684). The repro below does not cover this step. The fix PR will add a `TestReconcile` case for it, with a finished, admitted Parent and an evicted Variant that holds quota. Without the fix, the Parent gets `Evicted` with reason `VariantEvicted`, and the Variant never gets `Finished`.

The same happens for a Parent that is being deleted. If its Variants are deleted first, `Reconcile` creates them again with an owner reference to the deleting Parent, and the garbage collector deletes them again. This showed up in the e2e flake [#17518](https://github.com/kubernetes-sigs/kueue/issues/17518).

**What you expected to happen**:

No Variant is created for a finished Parent or for a Parent with a `deletionTimestamp`. The existing Variants of a finished Parent still get the `Finished` condition.

**Anything else we need to know?**:

The [KEP](https://github.com/kubernetes-sigs/kueue/blob/3cdda2dc1de7ad40cc51e45a206469f8c2aa8e07/keps/8691-concurrent-admission/README.md?plain=1#L523-L524) covers only propagation, not creation:

> 6. If the Parent Workload finishes, the `Finished` condition is propagated to all Variants.
> 7. If the Parent Workload is deleted, all Variants get deleted.

A possible fix is to handle a finished Parent first in `Reconcile`. Run `syncFinished` on its existing Variants and return, before `createVariants` and `syncVariantEvictionStatus`. Then return early for a Parent with a `deletionTimestamp`. The order matters, because a Parent that is both finished and being deleted (the #17518 shape) still has to mark its Variants `Finished`. Both returns go after the `ConcurrentAdmissionPolicy` check that [#14954](https://github.com/kubernetes-sigs/kueue/pull/14954) added, so its cleanup still runs for a ClusterQueue without the policy.

The repro diff above still applies and reproduces the bug at `879d77f73` (main on 2026-10-30), after #14954 merged. [#12501](https://github.com/kubernetes-sigs/kueue/pull/12501) added the ClusterQueue flavor watch that enqueues finished Parents.

E2E evidence from [this Prow build](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/17515/pull-kueue-test-e2e-baseline-main-1-37/2112633364736380928), namespace `e2e-concurrent-hlglc`, Parent `job-job-5898f`:
- 20:01:01.798, kueue finishes the Parent ("Workload is orphaned; finishing to release quota"), and at .803 the garbage collector deletes it, held by the kueue finalizer;
- .812 and .815, both Variants are deleted while the Parent still exists;
- .819 to .829, kueue reconciles the Parent and logs `Creating variant for flavor` and `Variant created` for both Variants again, same names;
- .825, the scheduler assumes the new `job-job-variant-reservation-e2e-concurrent-hlglc-3730c`;
- .827 and .834, kube-controller-manager logs `Deleting item` for both new Variants, since their owner is gone.

Other ways to delete Variants while the Parent still exists, not tested: foreground deletion of the Job (`kubectl delete job --cascade=foreground`, or the Job TTL controller), or `kubectl delete workloads --all`.
