## Description

## Goal

Test teardown deletes the LocalQueue and the ClusterQueue while Workloads can still race admission.
This class of flake was patched spec by spec in #14196, #13493, #15927 and #17629.
While fixing #17518 in #17629, two product bugs showed up on the same path.

This umbrella tracks both product fixes and the shared test cleanup.
The cleanup covers the shared teardown helpers and the specs that carry the wait-for-admission workaround, not every test that deletes the LocalQueue first.
The product fixes go first, since the cleanup in #15932 is easier to scope once they land.
It can be closed when all tasks are done.

### Comment by [@ivnovakov](https://github.com/ivnovakov) — 2026-11-20T19:23:00Z

I checked the `handleUpdate` side of #17637 too. When an assumed Workload is deactivated or finished after its LocalQueue is deleted, that update does not request the ClusterQueue.
The next event fixes it. A deactivated Workload is evicted once the admission write lands, and a finished one requests the ClusterQueue when it is deleted. It stays stuck only if the Workload is also deleted before the admission write lands.
Nothing like that showed up in CI, so I'm not planning a fix unless we see it.
