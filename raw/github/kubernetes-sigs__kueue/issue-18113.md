## Description

**What would you like to be added**:

Follow-up to #17515, requested by @pajakd in https://github.com/kubernetes-sigs/kueue/pull/17515#issuecomment-6463028321.

When TAS replaces a failed node of a PodSet group (for example a LeaderWorkerSet) that uses a preferred topology, first try to place the replacement Pods in the domain of the group members that are still healthy. Only if that domain has no capacity, fall back to the current preferred-topology placement.

Today, #17515 anchors the replacement to the healthy members only for required topology. For preferred topology the replacement can go to any domain, even when the original domain still has free capacity, so the group can be split across domains after a node failure.

**Why is this needed**:

A preferred topology asks Kueue to keep the Pods together when possible. After a node replacement, the group should stay in its original domain when it fits there, instead of being split for no reason. A hard anchor is not acceptable for preferred topology, because it would evict Workloads that can still run in another domain, so the anchor needs to be soft.

The same problem is more visible with `TASBalancedPlacement`, which tends to pick the emptiest domain for the replacement Pods.

**Completion requirements**:

- The replacement uses the anchor domain when it has capacity.
- The replacement falls back to another domain when only another domain has capacity, without eviction.
- Required-topology behavior from #17515 stays the same.

### Comment by [@bolubo](https://github.com/bolubo) — 2026-10-31T06:15:03Z

Hi, I'd like to take this.

As I understand it, #17515 computes `groupAnchor` (the domains the rest of the group keeps on healthy nodes), but its only consumer is `requiredReplacementDomain`, and that returns "" for preferred topology, unless a PodSet slice is only partially placed. So the replacement goes through the regular path and can move to another domain even when the original one still has room.

The piece we need for that is already there: `findTopologyAssignment` takes a required domain and skips every leaf outside it ("" means no restriction). So I would try the anchor first when it resolves to a single domain at the PodSet's constraint level, and if it does not fit, run the same placement again without it - which is exactly what happens today, so nothing gets evicted. If the healthy members of the group are spread over several domains, I would leave the placement alone rather than pick one of them arbitrarily.

No API change, and the usage accounting happens in the caller, so the second attempt does not count anything twice. Required topology and the partially placed slice path stay as they are.

Tests: the replacement stays in the anchor domain when it has room (also with TASBalancedPlacement), falls back when it does not, plus the multi-domain case and the existing required-topology cases.

One thing I am not sure about: does this need its own gate, or is it fine as part of the node replacement path?
