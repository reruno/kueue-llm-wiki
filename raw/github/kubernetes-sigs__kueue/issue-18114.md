## Description


**What happened**:

Follow-up to #17515, requested by @pajakd in https://github.com/kubernetes-sigs/kueue/pull/17515#issuecomment-6463028321.

With `TASReplaceMultipleFailedNodes` enabled, a PodSet group whose members use two unhealthy nodes is re-placed as a whole in one scheduling pass, so neither unhealthy node is used anymore. But `updateUnhealthyNodesAfterTASReplacement` removes only the head of `status.unhealthyNodes`, so the second node stays in the list:

```
unhealthyNodes=[{x2}] assignment=[leader=x3 worker=x4 worker=x5]
```

**What you expected to happen**:

After the group is re-placed, every unhealthy node that the new topology assignment no longer uses is removed from `status.unhealthyNodes`.

**How to reproduce it (as minimally and precisely as possible)**:

Found with a temporary unit test in `pkg/scheduler`:

1. Enable `TopologyAwareScheduling` and `TASReplaceMultipleFailedNodes`.
2. Admit a Workload with a PodSet group (a leader PodSet and a worker PodSet) with a required topology, using nodes x1 and x2.
3. Set `status.unhealthyNodes` to `[x1, x2]`, so no healthy member is left to anchor the group.
4. Run the scheduler. The whole group is placed on x3, x4 and x5, but `status.unhealthyNodes` is still `[x2]`.

**Anything else we need to know?**:

- Pods are not affected: the topology ungater only holds Pods assigned to nodes in the list, and the new assignment does not use x2.
- The stale entry uses one of the 8 slots, so the Workload can be evicted earlier than it should be when more nodes fail, and `HasUnhealthyNodes` stays true.
- Not tested: whether a later unhealthy node waits an extra pass, and whether x2 is removed when it recovers (the node controller only looks at Workloads that use the node in their assignment or still have Pods on it).
- With the gate off (default), `status.unhealthyNodes` has at most one node and is cleared after the replacement, so this does not happen.
- Feature gates: `TASReplaceMultipleFailedNodes` (Alpha, off by default).
- History: the whole-group re-placement was added in #17515; during its review the gap was left for a follow-up.
- AI assistance was used to investigate and prepare the issue.
