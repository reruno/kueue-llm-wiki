**What would you like to be added**:

A single combined unit coverage figure for a PR, aggregated across both unit test shards. Follow-up to https://github.com/kubernetes-sigs/kueue/pull/17039#issuecomment-6528474423.

Since #17039, `pull-kueue-test-unit-shard-0-main` and `pull-kueue-test-unit-shard-1-main` each publish their own `filtered.cov`, and the Prow coverage view shows each one separately. Each shard runs only part of the packages, so neither number is the real total.

A possible approach, which avoids rerunning the tests and avoids adding a Codecov token to Prow:

- Add a GitHub Actions workflow triggered by the commit `status` events that Prow posts for the two shard jobs. It would only download artifacts and would never check out or run PR code.
- Get the build IDs from the status `target_url`. Download both shard profiles from the public `kubernetes-ci-logs` bucket, and check that each build's `finished.json` revision matches the PR head SHA.
- Merge the two profiles by summing hit counts per block, then upload the merged profile to Codecov (enabled in kubernetes/org#6182) with OIDC, so no secret is needed.
- Use the periodic `periodic-kueue-test-unit-shard-{0,1}-main` jobs for main's baseline coverage.

**Why is this needed**:

The per-shard numbers understate coverage. On #17039's head commit:

| Profile | Shard 0 | Shard 1 | Merged |
| --- | --- | --- | --- |
| `filtered.cov` | 59.5% | 71.5% | 81.5% |

This would also cover part of #11173.
