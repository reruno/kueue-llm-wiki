**What would you like to be added**:

Part of #18141

A skill in `cmd/experimental/skills/kueue-pr-evidence-state-diff/` that runs one scenario on the merge base and on the PR head and adds the fields that differ to the PR description: Workload conditions and admission, ClusterQueue usage and counts, requeue state, and events.

A scenario is a short YAML file with objects to apply, waits, and named checkpoints. The skill turns it into a temporary integration test in throwaway worktrees for both SHAs and waits for the state to settle before each capture. The generated test is never committed. Captures are saved as JSON so the timeline skill (#18145) can reuse them.

Illustrative block:

```text
**kueue-pr-evidence-state-diff** base 1a2b3c4d5e6f -> head 9f8e7d6c5b4a
Head differs at checkpoint `after-eviction` (2 fields). Runner: envtest, default gates.
| object | field | base | head |
| wl/low | status.requeueState.count | 1 | 2 |
| wl/low | condition Requeued | False | True |
Unchanged: admission, ClusterQueue usage, events.
Repro: state-diff run --scenario requeue-no-priority-class
```

Non-goals: replacing integration tests, more than one scenario per block, automating kind in the first version.

**Why is this needed**:

For scheduler and controller PRs, a reviewer has to check out the branch or read the tests to see which state changes. The block puts the difference in one table and lists what stayed the same on an `Unchanged:` line, so a reviewer can spot side effects that no test asserts.

Test PR: #17991. The block should show only the requeue change for a Workload without a WorkloadPriorityClass.

**Completion requirements**:

Acceptance criteria:

- Both sides are generated at pinned SHAs. A head failure publishes nothing; a base failure is reported as evidence.
- envtest by default; kind only for the umbrella's listed cases, and the block names the runner.
- The block fits the umbrella budget, and a re-run replaces it in place.
- The capture format is documented for #18145.
