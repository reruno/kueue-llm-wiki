**What would you like to be added**:

Part of #18141

A skill in `cmd/experimental/skills/kueue-pr-evidence-red-green/` that finds the tests a PR adds or changes (Go test functions, table cases, Ginkgo `It`/`Entry`), applies only the test and testdata hunks to the merge base, and runs those tests on base and head. Unit tests run with `go test -run`, integration tests with `make test-integration` and a focus filter. The base side runs up to three times, and a test that fails only sometimes is reported as flaky. The block links the Prow junit results for the head SHA.

Fallback: if the test hunks do not apply or do not build on the merge base because they need new code, the verdict is "not applicable: tests depend on new code" with the first compiler error. The existing tests of the same functions then run unpatched on the base.

Illustrative block:

```text
**kueue-pr-evidence-red-green** base 1a2b3c4d5e6f -> head 9f8e7d6c5b4a
Red-green: 1 of 1 test fails on base, passes on head. Runner: unit.
| test | base | head |
| TestReconcile/gated_workload | FAIL 3/3 | PASS |
Prow: pull-kueue-test-unit-shard-0-main #<build>, 1 matching testcase passed
Base failure: unexpected PreemptionGate state "Closed"
Repro: red-green all --pr 17157
```

Non-goals: e2e tests on kind (listed as "not run"), copying non-test code to the base, re-running CI.

**Why is this needed**:

Reviewers ask whether a new test catches the bug, and often check by reverting the fix locally. A test that passes on both sides proves nothing about the fix, and the block shows it before review starts.

Test PR: #17157.

**Completion requirements**:

Acceptance criteria:

- The base side is the merge base plus the PR's test and testdata hunks only, and the block says so.
- Red only when the test fails on every base run; otherwise flaky.
- The not-applicable fallback and infra errors are reported separately, never as red.
- The Prow line names the job and build for the head SHA, or says CI has not finished.
