**What would you like to be added**:

Part of #18141

A skill in `cmd/experimental/skills/kueue-pr-evidence-perf-delta/` that runs `make test-performance-scheduler` (or the TAS variant) on the merge base and on head, three interleaved runs per side, and reports the median and min-max range of time to admission per class, ClusterQueue usage, evictions, and minimalkueue wall time, CPU, and max RSS.

A delta below the noise threshold (default 5%) shows as `~`. The block marks a delta weak when its ranges overlap.

If `pull-kueue-test-scheduling-perf-main` (or `pull-kueue-test-tas-scheduling-perf-main`) has finished for the head SHA, the skill uses its Prow artifacts instead. The base is then recent main periodic runs, not the merge base, and the block says so. Local and CI numbers are never mixed in one table.

The skill runs only when the diff touches hot-path code (`pkg/scheduler/`, `pkg/cache/`, `pkg/resources/`, `pkg/workload/`, `pkg/controller/core/`, `test/performance/scheduler/`). Otherwise it reports not applicable.

Illustrative block:

```text
**kueue-pr-evidence-perf-delta** base 1a2b3c4d5e6f -> head 9f8e7d6c5b4a
Local, config baseline, 3 runs per side, interleaved
Verdict: minimalkueue wall -12%; 4 metrics ~
| metric | base median (range) | head median (range) | delta |
| minimalkueue wall | 412s (405-420) | 362s (358-366) | -12% |
| time to admission, large | 31.0s (30.1-31.8) | 30.6s (29.9-31.5) | ~ |
```

Non-goals: changing the harness, configs, or thresholds; kind; PRs outside the hot path.

**Why is this needed**:

Performance PRs claim speedups. Reviewers either trust the claim or rerun the harness, which takes tens of minutes per run. One local run per side cannot separate a small gain from noise. Medians, ranges, and `~` show whether a gain is outside the noise. The same block would flag hot-path regressions in PRs that are not labeled as performance work.

Test PRs: #16340, #17461.

**Completion requirements**:

Acceptance criteria:

- Both sides use the same config; builds happen outside measured runs.
- Failed runs are listed in the block, never silently retried or dropped.
- Runs end to end on #16340 and #17461 and reports medians and ranges for both.
