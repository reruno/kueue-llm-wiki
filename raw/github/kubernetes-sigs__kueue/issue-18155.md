## Description

**What happened**:

The `kubectl-kueue` release binaries are built with the `.0` patch release of the Go minor version, not with the latest patch.

`.github/workflows/release-utils.yml` runs `actions/setup-go` with `go-version-file: 'go.mod'` before `make release-artifacts`. go.mod declares `go 1.27.0` (`go 1.26.0` on release-0.19) and has no `toolchain` line, so setup-go installs exactly that `.0` version. The `generate-sbom` composite action does the same. It already sets `check-latest: true`, but that has no effect when the version spec is an exact patch.

- v0.20.4 ([job log](https://github.com/kubernetes-sigs/kueue/actions/runs/40870032781/job/123434608760)): `Setup go version spec 1.27.0`, `go version go1.27.0 linux/amd64`. The latest 1.27 patch is 1.27.3.
- v0.19.11 ([job log](https://github.com/kubernetes-sigs/kueue/actions/runs/40868720324/job/123430127192)): `Setup go version spec 1.26.0`, `go version go1.26.0 linux/amd64`. The latest 1.26 patch is 1.26.10.

As a result, the published binaries miss every Go standard-library and toolchain fix released after `.0`.

**What you expected to happen**:

Release binaries are built with the latest patch release of the Go minor version declared in the release branch's go.mod.

**How to reproduce it (as minimally and precisely as possible)**:

Open the `Setup Go` step of any `create-draft-release` job in the release-utils workflow, or run `go version -m kubectl-kueue-linux-amd64` on a downloaded release binary.

**Anything else we need to know?**:

I have a fix ready, but GitHub currently refuses to let my account open pull requests against this repository. `gh pr create` fails with `GraphQL: vladikkuzn does not have the correct permissions to execute CreatePullRequest`, and the REST API returns 404.

- Compare link: https://github.com/kubernetes-sigs/kueue/compare/main...vladikkuzn:kueue:release-go-latest-patch?expand=1
- Branch `vladikkuzn:release-go-latest-patch`, head `1564df487ed166b022657df95268c8a938c2e94c`

The fix adds a step that reads the Go minor version from the checked-out go.mod. The two setup-go steps in `release-utils.yml` and the one in `.github/actions/generate-sbom/action.yml` then use `go-version: '<minor>.x'` with `check-latest: true`. Each release builds with the latest patch of its own branch's Go minor, and go.mod stays unchanged. #18137 touches the same setup-go blocks, so whichever merges second needs a small rebase.

A maintainer is welcome to open the PR from that branch. Otherwise I will open it as soon as GitHub allows.

**Environment**:
- Kueue version: v0.20.4, v0.19.11 release binaries
- Others: GitHub Actions release-utils workflow
