## Description

<!-- Please only use this template for submitting clean up requests -->

**What would you like to be cleaned**:

Make Kueue's Prow jobs run the Go version we intend, and make it visible when they don't. Today this depends on `GOTOOLCHAIN=auto`, which silently downloads a toolchain when the job image is older than `go.mod`.

**What happens today**

- test-infra sets `GOTOOLCHAIN=auto` as a preset for every prow.k8s.io job ([config.yaml#L1229-L1234](https://github.com/kubernetes/test-infra/blob/7f9e9939488536a268c445bf1094c20a7aabfe0a/config/prow/config.yaml#L1229-L1234), added in March 2026 following kubernetes/test-infra#36080). This overrides the `ENV GOTOOLCHAIN=local` set by the official `golang` images.
- Kueue's unit, integration, fuzz and perf jobs run on `public.ecr.aws/docker/library/golang:<minor>`. The verify and e2e jobs run on `kubekins-e2e`, which gets its Go version from kubernetes/kubernetes `.go-version`.
- With `auto`, if the `go` line in `go.mod` is newer than the local toolchain, cmd/go switches to exactly `go<go line>` (no `toolchain` line → `go1.27.0`, not the latest patch). See [go.dev/doc/toolchain#select](https://go.dev/doc/toolchain#select) and [select.go#L215-L224](https://github.com/golang/go/blob/251c4ee2e80806692f68c54321dcdf37842ad8d1/src/cmd/go/internal/toolchain/select.go#L215-L224).
- #15814 moved main's `go.mod` files to `go 1.27.0` on 2026-09-22 (release-0.20 branched from main afterwards). The golang-image jobs for `main` and `release-0.20` (56 job definitions) stayed on `golang:1.26` until kubernetes/test-infra#38224 merged on 2026-11-02. In that window, runs of those jobs began with this line:

  ```
  go: downloading go1.27.0 (linux/amd64)
  ```

  On main this lasted about six weeks: every `periodic-kueue-test-unit-shard-0-main` run from 2026-09-22 to 2026-11-01 has it. On release-0.20 it lasted since its jobs were added on 2026-09-30. Examples: [periodic-kueue-test-unit-shard-0-main, 2026-11-01](https://prow.k8s.io/view/gs/kubernetes-ci-logs/logs/periodic-kueue-test-unit-shard-0-main/2116772631825879040) and [periodic-kueue-test-integration-shard-0-release-0-20, 2026-11-01](https://prow.k8s.io/view/gs/kubernetes-ci-logs/logs/periodic-kueue-test-integration-shard-0-release-0-20/2116994339400847360). The [first unit run after kubernetes/test-infra#38224 merged](https://prow.k8s.io/view/gs/kubernetes-ci-logs/logs/periodic-kueue-test-unit-shard-0-main/2117135269994958848) no longer downloads.

**Why is this needed**:

- **An older patch than the images provide, with nothing flagging it.** In that window, unit and integration tests ran on go1.27.0. go1.27.1 was already out when the bump merged, and go1.27.2 (security fixes in the go command, crypto/tls, net/http and others) and go1.27.3 shipped during that window ([release history](https://go.dev/doc/devel/release#go1.27.minor)). Nothing in Kueue reports the version, so we only noticed by reading raw logs.
- **Different patches across jobs.** In the same window, verify (on kubekins) followed kubernetes `.go-version` (go1.27.2 by mid-October), while unit and integration stayed on go1.27.0. #17148 fixed a verify breakage that appeared when kubekins moved to go1.27.2; the unit jobs were still on go1.27.0 at the time. `auto` switching also bites tool builds outside Prow: #17377 fixed the API linter being built with an installed Go 1.26.3 while Kueue itself selected go1.27.0.
- **Network download in every run.** Each job fetched a full toolchain from proxy.golang.org before it started. That is an extra external dependency and an extra failure point.
- **The behaviour lives outside this repo.** If test-infra drops or changes the preset, the same lagging image fails with `go.mod requires go >= 1.27.0 (running go 1.26.x; GOTOOLCHAIN=local)` instead. Either way, Kueue's CI depends on a global setting we don't control.
- **It will happen again.** The next Go minor bump will repeat this unless the test-infra image bump is part of the Go bump process.

**Options**

| | Option | Pros | Cons |
|---|---|---|---|
| a | Set `GOTOOLCHAIN=local` on Kueue's golang-image jobs in test-infra | A lagging image fails loudly; no downloads | Goes against the project-wide default from kubernetes/test-infra#36080 (CI should behave like local development, and a PR can test a Go update); config is spread over ~80 job entries in another repo; doesn't help local runs |
| b | Add `toolchain go1.27.x` to `go.mod` | Pins an exact patch in-repo; only applies when Kueue is the main module, so downstream consumers are unaffected; `actions/setup-go` prefers the `toolchain` directive, so it would also cover #18155; consistent with KEP-3744's goal of not raising the `go` line on release branches | Under `auto`, still downloads whenever the image is older; every Go patch becomes a `go.mod` change on every supported branch; doesn't detect image lag |
| c | Add a cheap `make` check, run first by the golang-image Prow targets: print `go version` / `go env GOVERSION GOTOOLCHAIN GOROOT`, and fail when `CI` is set and `GOROOT` is under `$(go env GOMODCACHE)/golang.org/toolchain@*` (that is, auto-downloaded). It could also compare the minor against `go.mod` | Small, in-repo, reproducible locally; makes image lag fail loudly without changing the test-infra default; the version shows up in every log | Doesn't prevent the download, only fails after it; a PR that bumps the `go` line ahead of the images has red presubmits until test-infra catches up, so it needs (d) |
| d | Make "bump test-infra golang images first" part of the Go bump process (checklist/PR template), so the image always moves before `go.mod` | Prevents the gap; a newer image builds an older `go` line fine | Process only, so it is easy to miss without (c) |

**Proposal**: (c) + (d). The `make` check turns the next image lag into a red job instead of a silent download, and the checklist ordering (images first, then `go.mod`) keeps Go-bump PRs green. Compared with (a), (c) gives the same loud failure but stays in this repo, can be run locally, and leaves the global default alone. The cost is the same: a Go bump can't land ahead of the images. I'd skip (b) unless we decide to pin exact patches on release branches.

A side observation that (c)'s version line would also surface: `release-0.19` (`go 1.26.0`) runs unit/integration on `golang:1.26`, but verify/e2e on kubekins with Go 1.27.x (`auto` never downgrades), see #17152. Whether release branches should test on their own Go minor is a separate question.

Related: kubernetes/test-infra#36080, kubernetes/test-infra#38224 (merged), #15814, #17148, #17377, #18155, #6724. Out of scope, but these are also sources of Go versions: release GitHub Actions use `actions/setup-go` with `go-version-file: go.mod`, which resolves to the `go` line's exact patch (tracked in #18155), and image builds use the pinned `hack/images/golang/Dockerfile` digest inside Docker, where the image's `GOTOOLCHAIN=local` applies.
