## Description

**What happened**:

When `ConcurrentAdmission` is enabled with `SchedulerLibraryIntegration` or `SchedulerLibraryDeepIntegration`, the scheduler cache and preemption logic operate exclusively on Variant `Workload` keys (`<variant-wl>`), while real Pods are stamped with `kueue.x-k8s.io/workload: <parent-wl>` and indexed in `PodTracker` under `<parent-wl>`. On non-hostname-TAS flavors, `PodsForWorkload(<variant-wl>)` returns empty, so `wasSimulator` (`potentialVictims`, `committedVictims`, `PreemptWorkload`) skips or no-ops on `<variant-wl>` and fails to free `<parent-wl>`'s real Pods during preemption simulation. On hostname-leaf TAS flavors, `wasSimulatorFactory.NewSimulator` calls `tracker.RemoveWorkload(<variant-wl>)` instead of removing `<parent-wl>`, double-counting real and virtual Pods on simulated nodes and leaving `<parent-wl>`'s real Pods blocking placement even when `<variant-wl>` is preempted.

**What you expected to happen**:

`wasSimulatorFactory` and `wasSimulator` should resolve the mapping between `<variant-wl>` and `<parent-wl>` (via `kueue.x-k8s.io/parent-workload`) so `NewSimulator` deduplicates `<parent-wl>`'s real Pods when injecting virtual Pods. Preemption simulation (`potentialVictims`, `committedVictims`, and `PreemptWorkload`) should likewise free the real or virtual Pods associated with `<variant-wl>` from the simulated snapshot while reporting `<variant-wl>` as the `Workload` preemption target.

**How to reproduce it (as minimally and precisely as possible)**:

Enable `ConcurrentAdmission=true`, `TopologyAwareScheduling=true`, and `SchedulerLibraryIntegration=true` (or `SchedulerLibraryDeepIntegration=true`) on a single 4-CPU node with `ClusterQueue`s using `concurrentAdmissionPolicy`. Submit a low-priority Job so `ConcurrentAdmission` admits Variant `job-low-<hash>` while its real Pod binds to the node with `kueue.x-k8s.io/workload: job-low`. Submit either a second Job (with hostname-leaf TAS) to observe double-counted node usage, or a higher-priority 4-CPU Job to observe WAS preemption failing to free `job-low`'s real Pod from the simulated node.

**Anything else we need to know?**:

Affected code paths are `Cache.AddOrUpdateWorkload` (`pkg/cache/scheduler/cache.go`), `getPodSetsInfoFromStatus` (`pkg/controller/jobframework/reconciler.go`), `podtracker.Tracker` (`pkg/cache/scheduler/podtracker/pod_tracker.go`), `wasSimulatorFactory.NewSimulator` (`pkg/cache/scheduler/was/simulator_factory.go`), and `wasSimulator` (`pkg/cache/scheduler/was/preemptions.go`, `scheduler_simulator.go`). Neither feature-gate validation nor `ClusterQueue` webhook validation currently restricts combining `ConcurrentAdmission` with `SchedulerLibraryIntegration` or `SchedulerLibraryDeepIntegration` (and a similar key mismatch transiently affects `ElasticJobsViaWorkloadSlices` scale-up).

### Comment by [@NasitSony](https://github.com/NasitSony) — 2026-11-03T02:37:52Z

Verified the key mismatch holds. `startJob` calls `getPodSetsInfoFromStatus` with the Workload from `ensureOneWorkload`, which is the job's own Workload — the Parent. Variants are created by the concurrentadmission controller and own no job, so no reconcile resolves to one, and the annotation stamped on pods is always `<parent-wl>`. `podtracker.Tracker.savePod` indexes by that annotation, so `PodsForWorkload(<variant-wl>)` is empty by construction.
