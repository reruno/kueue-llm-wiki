## Description

Would a measured-heat admission check fit Kueue, so that hot nodes don't get admitted workloads?

Earthenware is an out-of-tree scheduler plugin ([earthenware-k8s](https://github.com/fitzyracing1/earthenware-k8s)), pinned to k8s v1.31.4. It does two things. It bin-packs pods into fixed slots per node group, and it filters out nodes whose measured temperature (annotation `earthenware.io/temp-c`) is over a limit. A node with no reading is never filtered, and nothing is estimated.

We ran a kind benchmark with 4 workers and pause pods:
- 11 pods: default-scheduler used 4 nodes and earthenware used 4.
- 6 pods: default-scheduler used 4 nodes and earthenware used 2.
- Pending time was 0s for both, at 1s resolution.

We know NodeResourcesFit MostAllocated already bin-packs. The new part is the measured-heat filter. Is there interest in this as a plugin, or is there a better place for it?
