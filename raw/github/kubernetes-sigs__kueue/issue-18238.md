**What would you like to be added**:

Optional OpenTelemetry tracing for the Workload controller: reconcile spans plus the time a Workload spends in each high-level status (pending, quota reserved, admitted, finished), exported over OTLP/gRPC to a backend such as Jaeger. It would be opt-in through the Kueue `Configuration` and a no-op when disabled.

**Why is this needed**:

Today the timing of Workload status transitions has to be inferred from logs and metrics. Traces would show where a Workload spends its time between submission and admission. This issue tracks the experimental prototype; the final design (API shape, annotation semantics, sampling defaults) is expected to come out of review.
