## Description

**What happened**:

The pod integration copies the whole Pod spec, including `ephemeralContainers`, into the Workload PodSet. With a ProvisioningRequest admission check, the PodTemplate built from that PodSet is rejected (`template.spec.ephemeralContainers: Forbidden: ephemeral containers not allowed in pod template`), no ProvisioningRequest is created, and the workload stays pending.

**What you expected to happen**:

Ephemeral containers do not block provisioning. They cannot set resources, so they can be left out of the PodTemplate without changing the requested capacity.

**How to reproduce it (as minimally and precisely as possible)**:

Either:
- add an ephemeral container (for example with `kubectl debug`) to a pod group member before the group is complete and its Workload is created; or
- add an ephemeral container to a gated single Pod whose Workload has no quota reservation, then change the Pod (for example a container image) so the Workload is rebuilt.

Use a ClusterQueue with a ProvisioningRequest admission check. The ProvisioningRequest is never created.
