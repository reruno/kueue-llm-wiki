**What would you like to be cleaned**:

Small follow-ups for the elastic SparkApplication support added in #17127:

- [ ] **Test the executor count after the driver finishes.** `driverStarted` in `pkg/controller/jobs/sparkapplication/sparkapplication_controller.go` includes the `SUCCEEDING`, `FAILING` and `FAILED` application states, but no test covers them: removing them from the switch still passes the unit and integration tests. Add `TestPodSetsExecutorCount` cases for these states next to "elastic, completed: does not fall back to initial executors". Origin comment by @ivnovakov: https://github.com/kubernetes-sigs/kueue/pull/17127#discussion_r4468984043
- [ ] **Use the shared usage helper.** `test/integration/singlecluster/controller/jobs/sparkapplication/sparkapplication_elastic_test.go` defines `expectPodsUsage`, which does the same check as `behavioral.ExpectClusterQueueResourceUsage`. Use the shared helper and remove `expectPodsUsage`. Origin comment by @ivnovakov: https://github.com/kubernetes-sigs/kueue/pull/17127#discussion_r4468984052
- [ ] **Fix the UNKNOWN state comment.** The `driverStarted` comment gives "an unreachable node" as an example of an unknown driver pod phase. Kubernetes no longer sets the `Unknown` pod phase: a driver on an unreachable node stays `Running`. Remove the example. Origin comment by @ivnovakov: https://github.com/kubernetes-sigs/kueue/pull/17127#discussion_r4468984061

**Why is this needed**:

- The test protects the behavior the code comment describes: falling back to the initial executors after the driver finishes would look like a scale-up, and the job reconciler would then not find the active workload slice to finish it.
- The helper change removes a duplicate test helper.
- The comment change removes an example that is wrong for current Kubernetes.
