**What happened**:

The SparkApplication reconciler registers the executor Pod watch only when `ElasticJobsViaWorkloadSlicesForSparkApplication` is enabled. With that gate off, existing elastic SparkApplications still count their executors from pods, because `isAnElasticJob` follows only `ElasticJobsViaWorkloadSlices`. Without the watch, a new executor above the Spark Operator's tracking limit does not trigger a reconcile until another event comes in.

**What you expected to happen**:

The executor Pod watch is registered whenever `ElasticJobsViaWorkloadSlices` is enabled, matching `isAnElasticJob`.

**How to reproduce it (as minimally and precisely as possible)**:

Found by reading the code; not reproduced. With `ElasticJobsViaWorkloadSlices` on and `ElasticJobsViaWorkloadSlicesForSparkApplication` off, run an existing elastic SparkApplication whose driver adds executors above the Spark Operator's executor tracking limit. The workload slice is not updated until another event reconciles the SparkApplication.

**Anything else we need to know?**:

Code: `NewReconciler` in `pkg/controller/jobs/sparkapplication/sparkapplication_controller.go`.
