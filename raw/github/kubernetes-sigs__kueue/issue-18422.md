## Description

**What would you like to be cleaned**:

Follow up on the review comments in https://github.com/kubernetes-sigs/kueue/pull/16080:

- Enqueue only affected local-capacity providers for Node changes. Account for old and new labels and cross-provider overlaps, and add tests. [Review](https://github.com/kubernetes-sigs/kueue/pull/16080#discussion_r4401462370)
- Split `computeCapacity` into smaller phases without changing its behavior. [Review](https://github.com/kubernetes-sigs/kueue/pull/16080#discussion_r4490953654)
- Add a shared behavioral helper that collects effective-quota resources for clearer CPU and GPU assertions. Extract worker-node selection into a helper. [CPU](https://github.com/kubernetes-sigs/kueue/pull/16080#discussion_r4490940973), [GPU](https://github.com/kubernetes-sigs/kueue/pull/16080#discussion_r4490998056), [worker](https://github.com/kubernetes-sigs/kueue/pull/16080#discussion_r4491527719)
- Use Ginkgo cleanup hooks for the integration test while preserving resource-deletion order. [Review](https://github.com/kubernetes-sigs/kueue/pull/16080#discussion_r4491001123)
- Investigate the e2e test's possible scheduler-cache timing race after quota reaches zero. Confirm cache propagation, for example with a suitable metric, or move the case to a test level with controlled timing. [Review](https://github.com/kubernetes-sigs/kueue/pull/16080#discussion_r4491642341)

**Why is this needed**:

Reduce unnecessary reconciles, improve maintainability and test diagnostics, and address the reported risk of a flaky test.
