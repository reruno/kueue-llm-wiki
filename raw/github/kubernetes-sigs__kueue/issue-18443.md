## Description

**What happened**:

This issue is found by a clanker, I'm not sure if this is a real business problem, but it seems reasonable to fix.

Kueue treats a missing node label as matching a ResourceFlavor that requires that label with an empty value.

For example:

```yaml
spec:
  nodeLabels:
    example.com/pool: ""
```

This should select nodes that have `example.com/pool` set to `""`. Instead, Kueue also includes nodes without that label.

**This is a pre-existing bug.** The faulty comparison already exists in the [shared label-matching helper before the LocalCapacity PR](https://github.com/kubernetes-sigs/kueue/blob/d378be4bd4f5e90dfb5310222b8e9495853332fd/pkg/util/tas/node.go#L35-L40), and the [existing TAS cache uses it](https://github.com/kubernetes-sigs/kueue/blob/d378be4bd4f5e90dfb5310222b8e9495853332fd/pkg/cache/scheduler/tas_nodes_cache.go#L118). The LocalCapacity provider in #16080 adds another caller affected by the same bug.

**What you expected to happen**:

A node should match only when the required label is present and its value matches. An empty value is valid; it should not mean that the label is optional.

/kind bug
