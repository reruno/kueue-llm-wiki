## Description

**What would you like to investigate**:

With `TASRespectNodeAffinityPreferred` enabled and no DRA, should a topology domain include the affinity scores of nodes that cannot fit at least one Pod?

In a rack-level placement, suppose rack A contains a1 with no CPU remaining and score 100, and a2 with score 0. Rack B contains b1 with score 75. If a2 and b1 can each fit the Pod, the reported behavior selects a2 because a1 raises rack A's score.

Check the intended behavior against KEP-2724. If nodes without capacity should not contribute, update the affinity aggregation in `pkg/cache/scheduler/tas_flavor_snapshot.go` and add regression coverage for this case.

**Why is this needed**:

An unavailable node's score can cause TAS to select a less preferred usable node. KEP-2724 specifies that child scores are summed but does not resolve this capacity question.
