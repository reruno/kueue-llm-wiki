## Description

**What would you like to be cleaned**:

Divide `wlReconciler.reconcileGroup` in `pkg/controller/admissionchecks/multikueue/workload.go` into helper functions. Use the same method as #17811 for the workload controller and #18419 for JobFramework.

The function has eight numbered steps. Each step can become one helper function:

1. Ignore an elastic Workload after a replacement or during a scale-up.
2. Delete the remote Workloads when the local Workload is finished or has no quota reservation.
3. Finish the local Workload when a remote Workload is finished. Reset the admission check when the remote Workload has a sync failure.
4. Process the eviction of a Workload on the manager cluster or on a worker cluster.
5. Update or delete the remote Workloads that are not in sync with the local Workload.
6. Sync the local Workload with the admitting remote Workload. Retry the admission when the admitting worker is not available.
7. Open the preemption gate.
8. Nominate and synchronize the worker clusters.

Since step 5 touches work assigned to @mykysha in #17952, I'll leave that to them and coordinate if needed

Many open pull requests change this file. I will send small pull requests with one or two steps each to make conflicts easier to handle

**Why is this needed**:

`reconcileGroup` has 340 lines and up to five levels of nesting. `ReconcileGenericJob` has 315 lines. It is difficult to see the sequence of steps in `reconcileGroup`. The function also increases in size when new MultiKueue features merge. With helper functions, the top-level function shows only the sequence of steps.

@mimowo approved this work in #17811.
