**What happened**:
`/create-draft-release` posted `✅ Draft release has been successfully created.` on the release issue even though the job failed at `Generate SBOM`:
  - Comment: https://github.com/kubernetes-sigs/kueue/issues/17978#issuecomment-6657441992
  - Job: https://github.com/kubernetes-sigs/kueue/actions/runs/42024365229/job/127234913402

The only sign of the failure was the GitHub notification email about the failed job. The draft release had no SBOM attached.

The cause is in the `Report Failure` step of the `create-draft-release` job in `.github/workflows/release-utils.yml`:

```
 message: ${{ steps.draft.outputs.message || '❌ Failed to create draft release.' }}
```

When `Create Draft Release` succeeds, `steps.draft.outputs.message` is the success message. If `Generate OpenVEX` or `Generate SBOM` fails afterwards, `Report Failure` runs and posts that success message instead of an error.

**What you expected to happen**:

If OpenVEX or SBOM generation or upload fails, the comment on the release issue says which step failed and links to the workflow run. It must not report success.

**How to reproduce it (as minimally and precisely as possible)**:

1. Run `/create-draft-release` on a release issue.
2. Let `Generate OpenVEX` or `Generate SBOM` fail (in the run above, `setup-bom` failed with `Error: compiling policy: unable to parse a policy, group or policySet from data`).
3. The bot comments `✅ Draft release has been successfully created.`, and the job is marked failed.

**Anything else we need to know?**:

Possible fix:
  - Add `id`s to the OpenVEX and SBOM steps, and build the failure message from the step that failed, for example `❌ Failed to generate or upload SBOM for <version>.`, with a link to the run.
  - Optionally, post a short comment after each step (draft created, OpenVEX uploaded, SBOM uploaded), so the release manager can see progress and where it stopped.

`create-release-candidate` has the same pattern. Its failure message is `steps.tag.outputs.message || steps.draft.outputs.message || steps.publish.outputs.message || ...`, so a failure in `Publish Release` posts the success message from `tag`.

The SBOM failure itself (`setup-bom` policy verification) is a separate problem and is not tracked here.

## Discussion

### Comment by [@mvanhorn](https://github.com/mvanhorn) — 2026-11-07T09:29:13Z

The failure comment is the first non-empty step output message. Creating the draft stores a success message in that output, and the value is still set when OpenVEX or SBOM fails afterward, so the failure report posts it.

Generate OpenVEX and Generate SBOM now have step ids. The draft-release failure message checks the SBOM outcome, then OpenVEX, then the draft step, and the comment names the failed step, the version, and links to the workflow run.

https://github.com/kubernetes-sigs/kueue/pull/18481
