## Description

**What happened**:

A Workload whose ResourceClaimTemplate uses a CEL selector is marked inadmissible when the cluster has fewer matching devices than the claim requests. The check counts devices in existing ResourceSlices, allocated or not ([claims.go#L597-L604](https://github.com/kubernetes-sigs/kueue/blob/v0.20.5/pkg/dra/claims.go#L597-L604)). It runs before the Workload is queued ([workload_controller.go#L181-L185](https://github.com/kubernetes-sigs/kueue/blob/v0.20.5/pkg/controller/core/workload_controller.go#L181-L185)), so the Workload never reserves quota and never gets a ProvisioningRequest. A node pool at zero nodes publishes no ResourceSlices, so the autoscaler never sees demand and never adds the nodes that would publish the devices.

**What you expected to happen**:

The Workload reserves quota and the ProvisioningRequest admission check provisions the capacity.

**How to reproduce it (as minimally and precisely as possible)**:

1. Create a ClusterQueue with a ProvisioningRequest admission check, whose flavor is backed by an autoscaled GPU node pool at 0 nodes.
2. Submit a Job whose ResourceClaimTemplate has a CEL selector, for example `device.attributes["gpu.nvidia.com"].productName == "NVIDIA H100 80GB HBM3"`.
3. The Workload stays inadmissible with "insufficient matching devices for CEL selector". No ProvisioningRequest is created.

**Anything else we need to know?**:

- The check was added in #9742 (v0.18.0).
- #17916 already skips it when the ClusterQueue has a MultiKueue admission check.
- Possible fix: skip it the same way when the ClusterQueue has a ProvisioningRequest admission check. TAS already keys its delay on the ProvisioningRequest controller ([tas_flavorassigner.go#L105](https://github.com/kubernetes-sigs/kueue/blob/v0.20.5/pkg/scheduler/flavorassigner/tas_flavorassigner.go#L105), [clusterqueue.go#L469-L470](https://github.com/kubernetes-sigs/kueue/blob/v0.20.5/pkg/cache/scheduler/clusterqueue.go#L469-L470)). The ProvisioningRequest then takes over failing fast: if no node pool can supply the devices, the check moves to Retry or Rejected.
- Claims without CEL selectors, and extended resources, are not checked and scale up normally.
