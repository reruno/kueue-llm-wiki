## Description


**What would you like to investigate**:

Introduce a cap (either hard or soft) on the number of issues assigned by contributors.

I would say 5 assigned issues should be cap, maybe 10 for reviewers and maintainers. Beyond that this is unrealistic.

**Why is this needed**:

Some contributors assign issues optimistically, which is fine, but when faced with complications they jump to another issue while the previous remains blocked for everyone.

Issue inspired by this discovery (13 assigned issues), but I saw in the past similar pattern too: https://github.com/kubernetes-sigs/kueue/issues/18535#issuecomment-6745470825
