## Description

**What happened**:
When `PartialAdmission` and `SchedulerLibraryDeepIntegration` are enabled, workloads needing reduced PodSet counts fail simulation and cannot be admitted.

`wasPlanner.Plan` derives virtual PodGroups and gang constraints (`MinCount` / `MinGroupCount`) from `wl.Spec.PodSets[i].Count`, while `CandidateVirtualPods` builds the reduced candidate count. During simulation, `GangScheduling.PlacementFeasible` fails because the candidate pods evaluated are fewer than the PodGroup's `MinCount`.

**What you expected to happen**:
Virtual PodGroups should be constructed using the candidate replica counts from `plan.Assignment` so partial admission probes can succeed in simulation.

**How to reproduce it (as minimally and precisely as possible)**:
Enable `SchedulerLibraryDeepIntegration` and `PartialAdmission`. Submit a workload with `count: 3`, `minCount: 1` into a ClusterQueue with capacity for only 1 replica. Full admission fails as expected, but the partial admission probe for `count: 1` also fails simulation because the virtual PodGroup still requires `minCount: 3`.

**Anything else we need to know?**:
Other planning helpers (`CandidateVirtualPods`, `WorkloadsTopologyRequests`, `TotalRequestsFor`) already source replica counts from `Assignment.PodSets`.
