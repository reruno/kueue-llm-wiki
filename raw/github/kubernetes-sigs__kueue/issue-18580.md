## Goal

#16478 was closed by #17013, but two pieces of the batch/v1 Job partial scale-up work are still open. Both wait for #16742, which lets a `partial` Job scale below its `minCount`. This issue can be closed when both tasks below are merged. Part of #12100.

## Tasks

- [ ] Website docs. The ElasticJob section in `site/content/en/docs/tasks/run/jobs.md` shows only atomic scale-up. Add a "Partial scale-up" subsection with the feature gate, the annotation, and what happens when the whole scale-up doesn't fit in the quota. PR ready, opens after this issue.
- [ ] Scale-down integration test in `test/integration/singlecluster/controller/jobs/job/job_controller_partial_scaleup_test.go`, from https://github.com/kubernetes-sigs/kueue/pull/17013#discussion_r4423341595. #16742 already covers a plain scale-down below `minCount` (`elastic_partial_scaleup_resize_test.go`). What's left is the case its KEP update describes, where a later scale-up doesn't restore the original minimum. A Job admitted at 4, scaled down to 1, then up to 5 keeps `minCount: 1`, so after an eviction it can be readmitted with only 1 of the 5 Pods. Add it in this file, which runs with `WaitForPodsReady` and covers Indexed Jobs.
