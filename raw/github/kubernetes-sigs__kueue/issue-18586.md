## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

A label on pods of admitted workloads with the workload's priority class, next to the queue labels
from #9156:

```yaml
kueue.x-k8s.io/workload-priority-class: high
```

Kueue could take the value from the Workload's `spec.priorityClassRef.name` and set it in the same
place it sets the queue labels today (`assignQueueLabels`), behind a new feature gate. I'd suggest a
new key rather than reusing `kueue.x-k8s.io/priority-class`, since that's already the label users set
on plain Pods to choose a priority. If a class name isn't a valid label value, Kueue could just skip
the label, the same way it does for ClusterQueue names.

**Why is this needed**:

- Group pod usage by priority tier (e.g. capacity held by preemptible work) without listing
  Workloads, as the queue labels allow per queue.
- See which running pods belong to workloads below a given priority.
- A pod's `spec.priority` is the kube-scheduler priority, which can differ from the Kueue workload
  priority.
- Only Kueue knows the resolved class (default WorkloadPriorityClass, PriorityClass fallback), so
  users can't reliably set it themselves.

Values are bounded by the number of priority classes, so the label adds no metric cardinality.
