**What would you like to be added**:

Allow `/set-release-note` to update the release note when the PR body contains more than one `release-note` block.

Currently `hack/releasing/set_release_note.py` stops with `❌ The pull request body contains multiple release-note blocks.` and the author has to edit the body by hand.

A common source of the second block is the CodeRabbit summary. It appends a `release-note` fence under "Suggested release note", between `<!-- This is an auto-generated comment: release notes by coderabbit.ai -->` and `<!-- end of auto-generated comment: release notes by coderabbit.ai -->`.

Possible approaches:

- Ignore `release-note` blocks inside the CodeRabbit auto-generated section, and update the remaining block.
- Or replace every `release-note` block with the new note.

The command should keep all other content of the body unchanged. `set_release_note_test.py` should cover the new cases.

**Why is this needed**:

On https://github.com/kubernetes-sigs/kueue/pull/18554, `/set-release-note NONE` failed ([command](https://github.com/kubernetes-sigs/kueue/pull/18554#issuecomment-6812779904), [result](https://github.com/kubernetes-sigs/kueue/pull/18554#issuecomment-6812786302)). The body had the author's block and the block from the CodeRabbit summary. Reviewers then have to ask the author to edit the body instead of fixing the note with one command.
