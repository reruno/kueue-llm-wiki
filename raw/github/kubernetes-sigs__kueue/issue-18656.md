Kueue now rejects such updates when the `WorkloadValidateUniquePodSetUpdates` feature gate (Beta, enabled by default) is enabled.
  
  If an external AdmissionCheck controller writes more than one `podSetUpdates` entry for the same PodSet in one admission check, change it to write one merged entry, or disable the `WorkloadValidateUniquePodSetUpdates` feature gate until it does. (#18021, @henry3260)

  If you create a borrow-only flavor with only `--borrowing-limit`, also pass a zero `--nominal-quota` for it, for example `--nominal-quota "alpha:cpu=0" --borrowing-limit "alpha:cpu=4"`. (#16651, @Eason09053360)

Keep mode in your values file; reuse retains it when omitted. To switch back, explicitly set `mode: yaml` and supply your YAML configuration. Without mode, migrate by removing the YAML key and using `--reset-values` with all desired customizations.

  - Your values use invalid inputs: mode must be `yaml` or `structured` when supplied; `structuredOverrides` must be a map and `controllerManagerConfigYaml` a string. Type validation applies even to unused inputs.
  - Your tools read the default YAML directly from `values.yaml`: update them to read the rendered manager ConfigMap. Defaults now live in `templates/manager/_config.tpl`.
  
  Existing users with valid YAML settings do not need to change their configuration or migrate.

Kueue does not support this mode: the leader Pods ran without admission while the worker Pods stayed gated.

## Changes by Kind

### Deprecation

- MultiKueue: Added a feature-gated capacity provider that sums quota from connected worker ClusterQueues for Dynamic Quota Orchestration. Use MultiKueueCapacityProviderConfig; MultiKueueConfig.spec.quotaManagement is deprecated and ignored. Removed the MultiKueueManagerQuotaAutomation feature gate, its ClusterQueue condition, and the multikueue_cluster_status metric.
  
  If you use MultiKueueManagerQuotaAutomation, remove it from your feature gates before upgrading. To keep the manager quota in sync, enable DynamicQuotaOrchestration and DQOMultiKueueCapacityProvider, then create a MultiKueueCapacityProviderConfig, a CapacityProvider, and a DynamicQuotaOrchestrator for the manager ClusterQueue. (#18382, @JanKaczmarski)

### API Change

- Added an alpha CapacityBuffer admission check (`kueue.x-k8s.io/capacity-buffer`) behind the `CapacityBufferACC` feature gate. It creates autoscaler CapacityBuffers for a workload's PodSets, admits the workload once the autoscaler, for example Karpenter, reports that the capacity fits, and holds the Pods with a scheduling gate until each PodSet's buffer is released. It is configured with the new alpha `CapacityBufferConfig` API, which requires the Kueue alpha APIs to be installed. (#17781, @jigisha620)
- ConfigAPI: Add `integrations.annotationKeysToCopy`, a list of annotation keys that Kueue copies from the job into the Workload at creation, for all integrations. It is guarded by the new AnnotationKeysToCopy feature gate (Beta, enabled by default), and Kueue ignores the field when the gate is disabled. Keys in the `kueue.x-k8s.io` domain and its subdomains are rejected at configuration validation. With CustomMetricLabels enabled, a key in that domain listed as a Workload-sourced `sourceAnnotationKey` is no longer copied from the job. Disable AnnotationKeysToCopy to restore the previous behavior. (#19088, @nsega)
- ConfigurablePreemptions: Added `preemptorPriorityClassSelector` and `priorityClassSelector` (`sourceRef` and `nameExpressions`) to `PreemptionConfig`, allowing administrators to filter preempting and candidate workloads by `WorkloadPriorityClass` or Pod `PriorityClass`. (#16684, @danylott)
- DQO: when the referenced CapacityProviders orchestrate more than 128 distinct flavors in total, the DQO now sets EffectiveCapacityComputed=False with reason AggregationFailed instead of failing to update its status. (#16767, @ekam-walia)
- DRA: Add `resources.excludeDeviceClassNames` to the Kueue Configuration, behind the alpha `KueueDRAExcludeDeviceClasses` feature gate. Kueue does not charge quota for DRA requests on the listed DeviceClasses, including extended resources they back, and does not reject them for `allocationMode: All` or a missing mapping. (#18632, @7xuanlu)
- DynamicQuotaOrchestration: Add opt-in expiration of effective quotas. When spec.capacityDistribution.effectiveQuotasTTLSeconds is set on a DynamicQuotaOrchestrator, its effective quotas expire if it stops renewing them, and Kueue uses spec.resourceGroups again. ClusterQueues and Cohorts report it with the EffectiveQuotaActive condition. (#18314, @7xuanlu)
- PriorityBoost: Moved the priority boost from the `kueue.x-k8s.io/priority-boost` annotation to the `spec.priorityBoost` field of the Workload. Kueue no longer reads the annotation, so a boost set only in the annotation stops applying after the upgrade. With MultiKueue, the manager cluster now sets the boost of the remote Workloads.

- CapacityBuffer admission check controller (#17781)

- Fixes for jobs outside `managedJobsNamespaceSelector` (#19270, #19306) and LimitRange `maxLimitRequestRatio` validation (#18931)
- MultiKueue fixes for removed and shared workers (#19173, #19393)
