## Description

**What happened**:

When an admitted elastic Workload with a TAS `TopologyAssignment` is scaled down in place, the TAS cache keeps charging all Pods of the original assignment.

`EnsureWorkloadSlices` calls `ApplyPodSetCounts` on the admitted slice ([manager.go#L112-L113](https://github.com/kubernetes-sigs/kueue/blob/74c0e6bcd5e6bf91716d4eec43f63d4a74440514/pkg/workloadslicing/manager.go#L112-L113), [manager.go#L142-L143](https://github.com/kubernetes-sigs/kueue/blob/74c0e6bcd5e6bf91716d4eec43f63d4a74440514/pkg/workloadslicing/manager.go#L142-L143)), which changes only `spec.podSets[].count`.
`totalRequestsFromAdmission` then lowers `Count` and `Requests` to the new count ([workload.go#L874-L879](https://github.com/kubernetes-sigs/kueue/blob/74c0e6bcd5e6bf91716d4eec43f63d4a74440514/pkg/workload/workload.go#L874-L879)), but it still builds `TopologyRequest.DomainRequests` from the admitted `TopologyAssignment` ([workload.go#L861](https://github.com/kubernetes-sigs/kueue/blob/74c0e6bcd5e6bf91716d4eec43f63d4a74440514/pkg/workload/workload.go#L861)).
`TASUsage` passes those domains to the TAS cache unchanged ([workload.go#L661](https://github.com/kubernetes-sigs/kueue/blob/74c0e6bcd5e6bf91716d4eec43f63d4a74440514/pkg/workload/workload.go#L661)).
Nothing rewrites the assignment on this path.

So a Workload admitted with 4 Pods as `node-a: 2, node-b: 2` and scaled down to 2 still holds TAS capacity for 4 Pods.
The charge is released only when the slice finishes, is evicted, or is replaced by a scale-up slice.
Until then, pending TAS Workloads can wait for, or preempt for, capacity that is free.

This happens with default feature gates.
`ElasticJobsViaWorkloadSlices` and `TopologyAwareScheduling` are both Beta, and the Job webhook rejects only required and preferred topology for elastic Jobs.
Unconstrained and implied TAS requests are admitted with a `TopologyAssignment`.

**What you expected to happen**:

After an in-place scale-down, the TAS cache charges only the Pods that remain, so pending Workloads can use the released domains.

**How to reproduce it (as minimally and precisely as possible)**:

Add the test below to `pkg/workload` and run `go test ./pkg/workload/ -run TestTASUsageAfterInPlaceScaleDown -count=1 -v`.
On main at `74c0e6bcd` it fails with `TASUsage charges 4 pods across domains after scale-down to 2`.

<summary>Test</summary>

```go
package workload

import (
	"testing"
	"time"

	corev1 "k8s.io/api/core/v1"

	"sigs.k8s.io/kueue/pkg/constants"
	"sigs.k8s.io/kueue/pkg/features"
	utiltesting "sigs.k8s.io/kueue/pkg/util/testing"
	utiltestingapi "sigs.k8s.io/kueue/pkg/util/testing/v1beta2"
)

func TestTASUsageAfterInPlaceScaleDown(t *testing.T) {
	features.SetFeatureGateDuringTest(t, features.TopologyAwareScheduling, true)
	features.SetFeatureGateDuringTest(t, features.ElasticJobsViaWorkloadSlices, true)

	wl := utiltestingapi.MakeWorkload("tas", "").
		Annotation(constants.ElasticJobAnnotation, "true").
		PodSets(
			*utiltestingapi.MakePodSet("workers", 4).
				SetMinimumCount(3).
				UnconstrainedTopologyRequest().
				Request(corev1.ResourceCPU, "1").
				Obj(),
		).
		ReserveQuotaAt(
			utiltestingapi.MakeAdmission("tas-cq").
				PodSets(
					utiltestingapi.MakePodSetAssignment("workers").
						Assignment(corev1.ResourceCPU, "tas", "4").
						Count(4).
						TopologyAssignment(utiltestingapi.MakeTopologyAssignment([]string{corev1.LabelHostname}).
							Domains(
								utiltestingapi.MakeTopologyDomainAssignment([]string{"node-a"}, 2).Obj(),
								utiltestingapi.MakeTopologyDomainAssignment([]string{"node-b"}, 2).Obj(),
							).
							Obj()).
						Obj(),
				).
				Obj(), time.Now(),
		).
		Obj()

	// In-place scale-down, as workloadslicing.Manager.EnsureWorkloadSlices does it.
	ApplyPodSetCounts(wl, PodSetsCounts{"workers": 2})

	_, log := utiltesting.ContextWithLog(t)
	if !IsElasticWorkload(wl) {
		t.Fatal("fixture must be an elastic Workload")
	}
	info := NewInfo(log, wl)
	if got := info.TotalRequests[0].Count; got != 2 {
		t.Fatalf("TotalRequests[workers].Count = %d, want 2", got)
	}
	var charged int32
	for _, dr := range info.TASUsage()["tas"] {
		charged += dr.Count
	}
	if charged != 2 {
		t.Errorf("TASUsage charges %d pods across domains after scale-down to 2 (TopologyAssignment still sums to 4)", charged)
	}
}
```

**Anything else we need to know?**:

- CodeRabbit first raised this on #16742 ([thread](https://github.com/kubernetes-sigs/kueue/pull/16742#discussion_r4419901629)). #16742 does not cause it. It does not touch `totalRequestsFromAdmission` or `TASUsage`, and the same test fails at its head. It only makes the path reachable for scale-downs below `minCount`.
- Truncating `DomainRequests` to `countAfterReclaim` in `totalRequestsFromAdmission` is not the fix. `countAfterReclaim` also subtracts `ReclaimablePods`, and #15219 keeps the domains charged until the whole PodSet is reclaimed. That change breaks two existing `TestNewInfo` cases.
- `utiltas.TruncateAssignment` already shrinks an assignment when the scheduler admits a smaller replacement slice ([tas_elastic_workloads.go#L151](https://github.com/kubernetes-sigs/kueue/blob/74c0e6bcd5e6bf91716d4eec43f63d4a74440514/pkg/cache/scheduler/tas_elastic_workloads.go#L151)). The fix can likely reuse it for the in-place scale-down, keyed on the spec count.
- Two questions stay open for the fix. Truncating assumes that the remaining Pods hold the lowest ranks, which fits Indexed Jobs but not every integration. The fix also has to decide whether to rewrite `status.admission.podSetAssignments[].topologyAssignment`.
- A fix needs a unit test in `pkg/workload` and an integration test where a pending TAS Workload is admitted into the released domains after an in-place scale-down.
