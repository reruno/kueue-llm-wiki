**What would you like to be added**:

Run the Kueue staging Cloud Build as the dedicated `kueue-sa` service account instead of the shared `gcb-builder` identity.
This is the "Build identity rollout" from KEP-1466 (#17754), part of umbrella #1466.

The rollout has three changes, which must land in this order.
After each one, a staging build of `main` must succeed before the next one starts.

1. kubernetes-sigs/kueue: `cloudbuild.yaml` sets
   `serviceAccount: projects/k8s-staging-images/serviceAccounts/kueue-sa@k8s-staging-images.iam.gserviceaccount.com`
   on `main` and on every supported release branch (cherry-picks).
   The job still runs as `gcb-builder`, which can act as `kueue-sa` through the `gcb-builder` migration shim.
2. kubernetes/test-infra: the Kueue staging build job sets `serviceAccountName: kueue` instead of `gcb-builder`.
3. kubernetes/k8s.io: add `kueue` to `skip_gcb_builder_shim`.

Landing step 3 before step 2, or step 2 before a branch carries step 1, stops the staging build of that branch.

The Security Profiles Operator staging build already does this: its `cloudbuild.yaml` sets only `serviceAccount:`, with no extra logging options.

**Why is this needed**:

KEP-1466 signs SLSA build provenance with Sigstore keyless signing.
The signing identity is the service account that runs the build.
`gcb-builder` is shared across projects in the staging organization, so provenance signed by it does not identify a Kueue build.
A Kueue-specific identity is needed before the attestation step can land.
Step 3 also stops other `gcb-builder` postsubmits from submitting builds as `kueue-sa`.

Step 1 on its own changes no build output: the same images and charts are pushed, and no attestations are produced yet.

**Completion requirements**:

- Step 1 merged on `main` and cherry-picked to every supported release branch, each followed by a successful staging build.
- Step 2 merged in kubernetes/test-infra, followed by a successful staging build of `main`.
- Step 3 merged in kubernetes/k8s.io, followed by a successful staging build of `main`.

Before step 1, confirm in kubernetes/k8s.io that `gcb-builder` can currently act as `kueue-sa`.
