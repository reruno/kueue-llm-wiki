## Description

**What would you like to be added**:

Add `kueue_oldest_pending_workload_age_seconds`, a gauge reporting the oldest current pending workload age per ClusterQueue.

The metric should follow the pending queue's membership, including active, inadmissible, and inflight workloads waiting for quota reservation. Workloads that already have quota and are waiting on admission checks are outside its scope.

The age should continue increasing without queue events, remain unaffected by admissions of other workloads, and start a new wait after requeue or quota release following eviction. Persisted workload timestamps should preserve the age across controller restarts. Empty queues should report zero, and deleted ClusterQueues should have their series removed. Labels and HA replica-role handling should follow existing ClusterQueue metric conventions.

**Why is this needed**:

`kueue_pending_workloads` exposes counts rather than individual waiting time. `kueue_admission_wait_time_seconds` is observed only after admission, so it cannot identify a workload that remains pending indefinitely.

A ClusterQueue can continue admitting smaller or higher-priority workloads while another workload waits for hours. We need to alert when any currently pending workload has waited more than four hours, even while other admissions continue. A current-age gauge supports this directly with a threshold of 14,400 seconds.

Related discussion: https://github.com/kubernetes-sigs/kueue/issues/10124 and the closed, unmerged https://github.com/kubernetes-sigs/kueue/pull/10633 proposed pending-wait quantiles. This request is limited to the oldest current pending age: unlike a mean or median, newly queued workloads cannot dilute it, and admission histograms cannot observe workloads that remain pending. The periodic scan cost remains a tradeoff for upstream review.

**Completion requirements**:

This enhancement requires the following artifacts:

- [ ] Design doc
- [ ] API change
- [ ] Docs update

The artifacts should be linked in subsequent comments.

A metrics reference update and alert example are required. No Kubernetes API change or separate design document is proposed. Tests should cover idle aging, selective starvation, queue ordering, requeue/eviction timestamps, empty queues, deletion, queue moves, custom labels, and replica-role transitions.
