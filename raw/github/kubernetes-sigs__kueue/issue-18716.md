## Description

**What happened**:

The SparkApplication integration reads the executor count and the dynamic allocation settings only from the typed fields (`spec.executor.instances`, `spec.dynamicAllocation`). The Kubeflow Spark Operator passes `spec.sparkConf` to spark-submit first and the typed fields after, so a typed field wins only when it is set, and anything it leaves unset comes from `spec.sparkConf`; spark-submit keeps the last `--conf` value. Its defaulting also leaves `spec.executor.instances` unset when `sparkConf` has `spark.executor.instances`. Kueue already follows this precedence for cores and memory (`typedOrSparkConf`), but not for these settings, so the same spec behaves differently once Kueue manages it:

- **Quota leak:** with `spark.executor.instances` in `sparkConf` and no `spec.executor.instances`, Kueue sizes the Workload with 0 executors while the driver starts the configured number. Nothing rejects it.
- **Missed bounds:** with `spec.dynamicAllocation.enabled: true` and `minExecutors`, `initialExecutors` or `maxExecutors` only in `sparkConf`, Kueue sizes and clamps the slices without the bounds Spark uses.
- **Rejected spec:** an elastic SparkApplication with dynamic allocation enabled only in `sparkConf` is rejected by the webhook, though the operator runs it as is.

This follows up on the discussion in #18289 (https://github.com/kubernetes-sigs/kueue/pull/18289#issuecomment-6722370034).

**What you expected to happen**:

Kueue resolves `spark.executor.instances` and `spark.dynamicAllocation.{enabled,minExecutors,initialExecutors,maxExecutors}` with the operator's precedence, for sizing and for the PodsReady expected count, so a spec that runs under the operator runs under Kueue without rewriting. Rejecting dynamic allocation on non-elastic jobs, from either source, stays as #18289 proposes.

**How to reproduce it (as minimally and precisely as possible)**:

With Kueue managing SparkApplications and the Kubeflow Spark Operator, create a SparkApplication with `sparkConf: {"spark.executor.instances": "3"}`, no `spec.executor.instances`, and a queue label. Its Workload's `executor` PodSet requests 0 Pods, while the application runs 3 executors.
