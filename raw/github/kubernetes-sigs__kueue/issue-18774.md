**What would you like to be added**:

Support KubeRay idle termination for Kueue-managed RayClusters: when the Ray autoscaler sets `spec.idleSuspend: true`, Kueue should release the Workload's quota, and admit the Workload again once the field is cleared.

KubeRay v1.8 adds `spec.idleSuspend` (kuberay-project/kuberay#5210, available in `v1.8.0-rc.0`). KubeRay treats it like `spec.suspend` and deletes all Pods, but Kueue only looks at `spec.suspend`.

Possible approaches, after bumping `ray-operator` to `v1.8.0-rc.0`:

- **Deactivate**: `IsWorkloadActive() = !spec.idleSuspend` via `JobWithCustomWorkloadActivation`. Concern (from reading the code, not tested yet): [`syncCustomWorkloadActivation`](https://github.com/kubernetes-sigs/kueue/blob/23cb2081d0820c3199d93b05534b7ee3968f75bc/pkg/controller/jobframework/reconciler.go#L620-L631) is a two-way sync, so it would also re-activate Workloads that were deactivated for other reasons, such as `kueuectl stop workload`.
- **OnHold**: `IsOnHold() = spec.idleSuspend` via `JobWithOnHold`. KubeRay has already deleted the Pods, so Kueue only needs to release the quota. Concern: `JobWithOnHold` was added for a terminal state (#13415), so the generic path never clears the hold. Resuming after `spec.idleSuspend` is cleared needs new code, similar to StatefulSet's `clearOnHold`.

Which one would the maintainers prefer?

**Why is this needed**:

Today an idle-suspended RayCluster has no Pods, but its Workload stays admitted and keeps its quota. Other workloads cannot use that quota until the user deletes the RayCluster.
