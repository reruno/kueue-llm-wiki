## Description

**What would you like to be cleaned**:

Remove `features.TopologyAwareScheduling: false` from unit-test cases under `pkg/` where it does not change the result. It looks copied from neighboring cases.

To find them, remove the entry and run the tests of the package. A failing subtest means the entry is needed. An entry in a passing subtest can go.

I did this for every entry under `pkg/` in a throwaway worktree. Roughly 89 of 204 entries are unneeded (the count is per package, not matched case by case):

| Package | Entries | Subtests that fail without them |
|---|---|---|
| `pkg/controller/jobs/job` | 86 | 35 |
| `pkg/controller/jobs/pod` | 32 | 20 |
| `pkg/controller/jobs/statefulset` | 21 | 9 |
| `pkg/controller/jobs/leaderworkerset` | 16 | 10 |
| `pkg/scheduler` (`scheduler_tas_test.go`, `scheduler_recompute_preemption_test.go`) | 3 | 0 |
| `pkg/controller/jobs/mpijob` | 6 | 5 |

In the other packages (`appwrapper`, `jobset`, `rayjob`, `rayservice`, `raycluster`, `kubeflow`, `sparkapplication`, `jobframework`, `podset`, `flavorassigner`, `cache`) every entry is needed.

Keep the entry where TAS changes the expected result, for example the `should create prebuilt workload*` cases in LeaderWorkerSet. `test/integration` was not checked.

**Why is this needed**:

`TopologyAwareScheduling` is enabled by default (Beta since 0.14). An override that does not change the result adds noise and hides which cases really depend on TAS being disabled.

Found while reviewing https://github.com/kubernetes-sigs/kueue/pull/18783.
