### Comment by [@vamsikrishna-siddu](https://github.com/vamsikrishna-siddu) — 2026-11-17T04:44:52Z

I looked into the CI failures on #18818.

**Root cause:** Kueue doesn't compile with spark-operator v2.6.0. (The bump is v2.5.2 → v2.6.0)

    vendor/github.com/kubeflow/spark-operator/v2/api/v1beta2/zz_generated.openapi.go:221:6: undefined: v1.PodStatusResult
    vendor/github.com/kubeflow/spark-operator/v2/api/v1beta2/zz_generated.openapi.go:298:6: undefined: v1.WorkloadReference

spark-operator v2.6.0 is built against `k8s.io/api` v0.35. Its generated OpenAPI file uses two `core/v1` types that were removed in v0.37, which Kueue uses. That's why almost every job failed. We can't fix this in Kueue without editing `vendor/` or adding a `replace` directive.

**Upstream fix:** kubeflow/spark-operator#3281 bumps spark-operator to `k8s.io` v0.37 and regenerates the OpenAPI file. It also unblocks #18107.

**Verification:** I opened draft PR #18940 (on hold, not for merge). It points Kueue at the head of kubeflow/spark-operator#3281 and keeps the v2.6.0 operator for e2e. Locally:
- `go build ./...` passes
- SparkApplication unit tests pass
- SparkApplication integration tests pass (19/19)


I'll post the full CI results once they finish.

**Next steps:**
1. Get kubeflow/spark-operator#3281 merged and included in a spark-operator release.
2. Bump Kueue to that release in a normal PR, and close the draft.
