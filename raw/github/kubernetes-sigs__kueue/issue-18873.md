## Description

**What happened**:

The ResourceFlavor webhook accepts a toleration whose operator is `Equal` (or empty, which means `Equal`) and whose `value` is not a valid label value, for example:

```yaml
apiVersion: kueue.x-k8s.io/v1beta2
kind: ResourceFlavor
metadata:
  name: gpu
spec:
  tolerations:
  - key: example.com/gpu
    operator: Equal
    value: "not a label value!"
    effect: NoSchedule
```

`validateTolerations` in `pkg/webhooks/workload_webhook.go` says it is extracted from the Kubernetes Pod validation, but it only checks the key. The upstream `ValidateTolerations` also requires the value of an `Equal` toleration to be a valid label value. The CEL rules on `spec.tolerations` cover the operator, the effect, the empty key and the `Exists` value, but not this.

Kueue adds the ResourceFlavor tolerations to the PodSet info of an admitted Workload (`FromAssignment` in `pkg/podset/podset.go`) and merges them into the Pod template of the Job when it starts it. kube-apiserver rejects that Pod template, so Jobs admitted with this flavor would not be able to start.

**What you expected to happen**:

The webhook should reject a ResourceFlavor toleration value that kube-apiserver would reject for a Pod, so the mistake is reported when the ResourceFlavor is created or changed.

**How to reproduce it (as minimally and precisely as possible)**:

Unit level, in `pkg/webhooks` on current main. This throwaway test compares the Kueue validators with the upstream Pod validation (`k8s.io/kubernetes/pkg/apis/core/validation`, which is vendored):

```go
func TestReproTolerationValue(t *testing.T) {
	bad := corev1.Toleration{Key: "example.com/gpu", Operator: corev1.TolerationOpEqual, Value: "not a label value!", Effect: corev1.TaintEffectNoSchedule}
	rf := &kueue.ResourceFlavor{}
	rf.Name = "rf"
	rf.Spec.Tolerations = []corev1.Toleration{bad}
	t.Logf("Kueue ValidateResourceFlavor -> errors: %v", ValidateResourceFlavor(rf))
	internal := []core.Toleration{{Key: bad.Key, Operator: core.TolerationOpEqual, Value: bad.Value, Effect: core.TaintEffectNoSchedule}}
	t.Logf("upstream ValidateTolerations -> errors: %v", corevalidation.ValidateTolerations(internal, field.NewPath("spec", "template", "spec", "tolerations"), corevalidation.PodValidationOptions{}))
}
```

Output:

```
Kueue ValidateResourceFlavor, toleration value "not a label value!" -> errors: []
upstream k8s ValidateTolerations (pod spec), same toleration -> errors: [spec.template.spec.tolerations[0].operator: Invalid value: "not a label value!": a valid label must be an empty string or consist of alphanumeric characters, '-', '_' or '.', and must start and end with an alphanumeric character (e.g. 'MyValue',  or 'my_value',  or '12345', regex used for validation is '(([A-Za-z0-9][-A-Za-z0-9_.]*)?[A-Za-z0-9])?')]
```

**Anything else we need to know?**:

- This was reproduced only at the unit level (the webhook validation function). The effect on Jobs follows from reading the code. It was not reproduced on a cluster or against a running webhook server.
- `validateTolerations` is also used for `status.admissionChecks[*].podSetUpdates[*].tolerations` on Workloads, which has the same gap. Those values are written by admission check controllers rather than by users, so this issue is about the ResourceFlavor.
