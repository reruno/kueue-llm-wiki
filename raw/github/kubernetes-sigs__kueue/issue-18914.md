## Description

**What happened**:

Duplicate `(driver, name)` counter or capacity sources in a DeviceClass mapping can charge quota twice. Cross-mapping validation checks only the first counter source, so later counter sources can bypass the duplicate check.

**What you expected to happen**:

- Reject duplicate `(driver, name)` tuples for counter and capacity sources.
- Check every counter source across mappings and share the disjointness helper where appropriate.
- Add regression tests for duplicate and distinct sources.
- Update KEP-2941 to reflect support for multiple counter sources.

**How to reproduce it (as minimally and precisely as possible)**:

Configure a DeviceClass mapping with the same counter or capacity `(driver, name)` twice, or repeat a non-first counter source across mappings. See `pkg/config/validation.go` and the DRA resource mapper.

**Anything else we need to know?**:

This validation change can reject configurations accepted by Kueue v0.19 and v0.20. See PR https://github.com/kubernetes-sigs/kueue/pull/17642 and the discussions:
- https://github.com/kubernetes-sigs/kueue/pull/17642#discussion_r4589466630
