**What would you like to be added**:

Upload the integration coverage profile to Codecov under its own flag, `integration`, next to the `unit` flag that #18136 adds. The proposal is to use [Codecov flags](https://docs.codecov.com/docs/flags), which report each test layer separately within one repository. This tracks the Codecov part of #18429 step 3 ("Publish"). Publishing depends on #18553 merging, on the coverage job producing a separate merged integration profile (#18429 step 2), and on #18136 landing.

1. **Profile.** Use the integration profile that the coverage job merges from `pull-kueue-test-integration-shard-{0..3}-main` and `pull-kueue-test-integration-multikueue-main` (#18429 step 2), as a separate artifact from the unit `filtered.cov`.
2. **Upload.** Extend `.github/workflows/codecov-prow.yaml` from #18136 to fetch that artifact and upload it with `flags: integration`. Keep the OIDC upload and the scripts from the default branch.
3. **Config.** Add `integration` under `flags:` in `codecov.yml`.

**Depends on:**

- #18553: the integration shards write `filtered.cov`.
- #18429 step 2: the coverage job merges the integration shards into a separate profile. No implementing PR found.
- #18136 (open): the Codecov workflow and the `unit` flag.

**Open questions:**

- **`after_n_builds`.** #18136 proposes `after_n_builds: 1`. Keep it, and let the integration upload update the report?

**Why is this needed**:

#11173 asks for a separate number per test layer. With only the `unit` flag, Codecov reports code that only envtest reaches as uncovered. An `integration` flag shows that coverage per PR. Codecov's commit total becomes unit ∪ integration; the `unit` flag view keeps the unit number.
