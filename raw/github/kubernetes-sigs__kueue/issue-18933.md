**What would you like to be added**:

Upload the e2e coverage profile to Codecov under its own flag, `e2e`, next to the `unit` flag that #18136 adds. The proposal is to use [Codecov flags](https://docs.codecov.com/docs/flags), which report each test layer separately within one repository. This tracks the Codecov part of #18430 step 4 ("Publish"). Publishing depends on the collection and the separate merged e2e profile from #18430 steps 1–3, and on #18136 landing.

1. **Profile.** Use the e2e profile that the coverage job merges from the coverage-built e2e jobs (#18430 step 3), as a separate artifact from the unit `filtered.cov`.
2. **Upload.** Extend `.github/workflows/codecov-prow.yaml` from #18136 to fetch that artifact and upload it with `flags: e2e`. Keep the OIDC upload and the scripts from the default branch.
3. **Config.** Add `e2e` under `flags:` in `codecov.yml`.

**Depends on:**

- #18430 steps 1–3: a coverage build of the manager, e2e jobs that write `filtered.cov`, and a separate merged e2e profile. No implementing PR found.
- #18136 (open): the Codecov workflow and the `unit` flag.

**Open questions:**

- **Which commits.** If e2e coverage runs only on a subset of jobs or only in periodics (#18430), most commits get no `e2e` upload. Should the `e2e` flag use `carryforward: true` so PRs show the last known number? Periodic jobs post no commit status, so the `on: status` workflow from #18136 would not run for them. A periodic-only e2e profile needs another trigger (for example `schedule:`), or a merge job that posts a status.
- **`after_n_builds`.** #18136 proposes `after_n_builds: 1` and `wait_for_ci: false`, so the report does not wait for e2e. Keep that, and let the `e2e` upload update the report later?

**Why is this needed**:

#11173 asks for a separate number per test layer. E2E tests exercise the manager in a real cluster. Publishing their coverage under a separate flag shows what those runs cover alongside unit and integration coverage. Codecov's commit total includes every uploaded flag; the `unit` flag view keeps the unit number.
