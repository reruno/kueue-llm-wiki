## Description

**What happened**:

Kueue builds the CEL input for a ResourceSlice device in two places: `buildDeviceListFromSlices` in `pkg/dra/claims.go` and `matchDevicesWithSelectors` in `pkg/dra/counters.go`. Both copy `Driver`, `Attributes` and `Capacity`, and leave `AllowMultipleAllocations` nil. The DRA CEL library reads nil as `false`.

So `device.allowMultipleAllocations == true` matches no device, even one whose ResourceSlice sets `allowMultipleAllocations: true`, and `!device.allowMultipleAllocations` matches every device.

KEP-2941 suggests the first selector in the `deviceSelector` of a capacity source, so that exclusive devices are not under-charged. With it, the source matches nothing, and every Workload charged through that source fails with `insufficient matching devices for capacity driver: 0 device(s) match`. In a ResourceClaimTemplate the same selector fails the device check. Both are internal errors, so the Workload is retried with backoff and stays pending.

**What you expected to happen**:

Both places copy `AllowMultipleAllocations` from the ResourceSlice device, as kube-scheduler does when `DRAConsumableCapacity` is on.

**How to reproduce it (as minimally and precisely as possible)**:

On main (6cd1d6931), one ResourceSlice device with `allowMultipleAllocations: true`:

```
ResourceClaimTemplate selector
  device.allowMultipleAllocations == true   insufficient matching devices for CEL selector in DeviceClass test-deviceclass-1: 0 device(s) match in the cluster but 1 requested
  !device.allowMultipleAllocations          charged res-1: 1

deviceSelector of a source
  device.allowMultipleAllocations == true   0 devices matched
  !device.allowMultipleAllocations          1 device matched
```

**Anything else we need to know?**:

Every release from v0.18.0, where #9742 added the device check, through v0.20.6 leaves the field unset. #14223 and #14372 were about the CEL environment that compiles the selector; this is the input it runs on. #18983 plans to extend the same device check to `firstAvailable` requests for Beta.
