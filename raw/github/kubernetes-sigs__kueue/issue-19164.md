## Description

**What happened**:

`hack/cherry_pick_pull.sh` skips the opening line of a `release-note` block. If that line also contains the closing fence, the script can collect a later block instead of the inline note. This behavior predates PR #19162.

**What you expected to happen**:

Handle an inline first block without collecting a later block as its release note. Keep the behavior for normal multiline blocks and large PR bodies.

**How to reproduce it (as minimally and precisely as possible)**:

Use a PR body with an inline `NONE` block followed by a multiline block:

````text
```release-note NONE```
```release-note
Later note
```
````

The extraction in `hack/cherry_pick_pull.sh` collects `Later note`.

**Anything else we need to know?**:

Prow recognizes the inline block. The release-notes tool's note-text extractor requires a multiline block; its separate exclusion filter can recognize inline `NONE`. Check these differences when choosing the handling and add regression tests for inline and multiline blocks.
