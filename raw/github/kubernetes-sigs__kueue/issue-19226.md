## Description

**What happened**:

With the partial scale-up strategy (`kueue.x-k8s.io/elastic-job-scale-up-strategy: partial`), an elastic SparkApplication whose initial executors do not fit is admitted partially, but it never starts.

The first Workload slice is admitted with fewer executors than it asks for (for example 1 of 3). Kueue then creates a scale-up probe slice for the full count. `normalizeActiveSlices` (`pkg/workloadslicing/workloadslicing.go`) selects the pending probe, not the admitted slice, so the job reconciler never unsuspends the SparkApplication. The app stays suspended, with no driver, while the admitted slice holds its quota. It starts only when the probe is admitted, that is, when the full initial count fits.

On a kind cluster this held 1 CPU for over 6 minutes with no pods running. If the initial count can never fit, for example `initialExecutors: 5` on a queue that holds driver + 3 executors, the app never starts and keeps holding the quota of the admitted slice.

Cause: the SparkApplication integration sets the executor PodSet's `minCount` to `minExecutors` on every slice, including the first one (`pkg/controller/jobs/sparkapplication/sparkapplication_controller.go`). KEP-12100 lists partial admission of the initial Workload as a non-goal, and says integrations set `minCount` to the initial count on the initial Workload. batch/Job (`podsCount()`) and Ray (`effectiveWorkerCount`) do that, so their first admission is all-or-nothing. With `minCount = minExecutors`, the first Spark slice can be admitted partially, which the probe lifecycle does not handle.

`minExecutors` was used so that an admitted Workload could scale down below its initial count (down to 0 when the executors exit) without failing the `minCount <= count` validation. #16742 now lowers `minCount` on in-place scale-down of admitted elastic Workloads, so that is no longer needed.

**What you expected to happen**:

The first slice is admitted all-or-nothing, as in batch/Job and Ray: the app waits without holding quota until the initial executors fit, then starts. Partial scale-up applies to later scale-ups of the running app.

**How to reproduce it (as minimally and precisely as possible)**:

1. Enable `SparkApplicationIntegration`, `ElasticJobsViaWorkloadSlices`, `ElasticJobsViaWorkloadSlicesForSparkApplication` and `ElasticJobsViaWorkloadSlicesWithPartialReplicaScaleUp`.
2. A ClusterQueue with 2 CPU; every Spark pod requests 500m (4 pods fit).
3. Fill 2 of the 4 pods with another workload (for example a SparkApplication with a driver and 1 executor).
4. Create an elastic SparkApplication with the partial strategy that starts with 3 executors:

```yaml
metadata:
  labels:
    kueue.x-k8s.io/queue-name: spark-lq
  annotations:
    kueue.x-k8s.io/elastic-job: "true"
    kueue.x-k8s.io/elastic-job-scale-up-strategy: partial
spec:
  dynamicAllocation:
    enabled: true
    initialExecutors: 3
    minExecutors: 1
    maxExecutors: 3
  driver:
    coreRequest: 500m
  executor:
    instances: 1
    coreRequest: 500m
```

5. The first slice is admitted with `executor: 1` of 3 and a probe slice for 3 stays pending, but the SparkApplication stays `SUSPENDED` with no driver pod until the first workload finishes and the probe is admitted.

**Anything else we need to know?**:

Proposed fix: set the executor PodSet's `minCount` to the executor count, as batch/Job and Ray do, so the first admission is all-or-nothing. Then:
- Change the integration test "Should partially admit the first workload and create a scale-up probe" (`test/integration/singlecluster/controller/jobs/sparkapplication/sparkapplication_controller_partial_scaleup_test.go`) to expect an all-or-nothing first admission, and check that the app starts.
- Check with a test that a pending probe whose executor count drops below its copied `minCount` (executors exit while the probe waits) can still be updated, since #16742 lowers `minCount` only for admitted Workloads.
- Update the SparkApplication docs that say the first admission can be partial.

Scale-ups of a running SparkApplication are not affected: a partially admitted scale-up slice and its probe work as expected.
