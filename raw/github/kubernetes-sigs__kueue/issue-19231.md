## Description

## Goal

Address @sohankunkerkar's CapacityBuffer AdmissionCheck review comments before Beta. These items cover readiness, resource holds, configuration, and feature interactions in the [KEP](https://github.com/kubernetes-sigs/kueue/pull/14700). Related: #5133.

Requested by @tenzen-y in [this comment](https://github.com/kubernetes-sigs/kueue/pull/14700#issuecomment-7044725235). Created with CodeRabbit AI.

## Tasks

- [ ] Clarify that `FitsExistingCapacity` can include launched NodeClaims whose Nodes are not ready, and define recovery if a Node fails to come up. [Review](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644408859)
- [ ] Clarify alpha autoscaler support and status reasons: Karpenter uses `FitsExistingCapacity`, while Cluster Autoscaler reports `FakePodsInjected`; check the proposed `InvalidPodTemplate` reason. [Review](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644456332)
- [ ] Bound resource and quota holds when Pod creation stalls after the check is Ready; evaluate a limit or requiring `waitForPodsReady`. [Review](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644478410)
- [ ] Correct or specify the desired behavior when a config in use is deleted, including whether admitted workloads are evicted. [Review](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644495484)
- [ ] Define how an existing AdmissionCheck becomes inactive when the feature gate is disabled, so workloads do not reserve quota indefinitely. [Review](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644506244)
- [ ] Specify support and safeguards for `ConcurrentAdmission` and sequential Pod creation, including the proposed inactive ClusterQueue behavior for unsupported cases. [Review](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644525671)
- [ ] Define a timeout that covers failed CapacityBuffer creation, including whether to start it at quota reservation. [Review](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644535059)
- [ ] Validate retry backoff settings to prevent a zero-delay requeue loop; evaluate a minimum of 1 and base less than or equal to maximum. [Reviews](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644541535) and [follow-up](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644545607)
- [ ] Clarify that capped buffers and infeasibility detection are Beta criteria, and serve the config CRD by default before enabling the gate by default. [Review](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644552911)
- [ ] Define whether Ready is final and whether it is re-evaluated after admission, considering that Retry can evict an admitted workload. [Review](https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644566694)
- [ ] Retain the `CapacityBuffer` after handoff for events and status conditions: shrink it to zero when all gated Pods exist, and delete it on eviction or Workload deletion. Target before Beta, preferably Alpha2 (or Alpha1 if feasible), before capped buffers. [Proposal](https://github.com/kubernetes-sigs/kueue/issues/19231#issuecomment-7111005521)
- [ ] Improve the CapacityBuffer end-to-end test stability by making eviction after timeout deterministic. See #19390. [Context](https://github.com/kubernetes-sigs/kueue/issues/19231#issuecomment-7111399786)

From my end it would be really good to support TopologyAwareScheduling (TAS) as soon as possible. Maybe not in Alpha1, but Alpha2. ### Comment by [@mimowo](https://github.com/mimowo) — 2026-11-23T19:02:21Z

One more idea we may want to do before Beta (even Alpha2) is to do not delete the buffer during handoff (when all gated pods exist) - we could just shrink its size to 0. 

This would keep the CapacityBuffer object as a container for events and other status updates ( conditions) which would greatly improve observability.

Then, similarly as ProvisioningRequest the object would be only deleted on eviction (or workload deletion). That would close another important gap before we have Capped Capacity Buffers.
