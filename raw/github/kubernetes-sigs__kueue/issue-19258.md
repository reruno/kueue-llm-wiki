## Description

**What would you like to be added**:

Follow-up to #19172, as [asked in its review](https://github.com/kubernetes-sigs/kueue/pull/19172#issuecomment-7050807413).

The DRA CEL device check matches only the requests of a claim that have a CEL selector (for `firstAvailable`, on every alternative). Requests without one take no part, so the check does not see the devices they need. Counting them would also change how the check lists ResourceSlices.

**Why is this needed**:

The check can admit a claim that no node can place. Take devices `a`, `b` and `c` on one node, and requests for `a` or `b`, for `a` only, and for two devices without a selector. With #19172 the check passes this claim, because the first request can take `b`. The claim needs four devices and the node has three, so none of the stable, incubating and experimental allocators of `k8s.io/dynamic-resource-allocation` v0.37.2 can place it. Main rejects the claim, but only because its first pass gives `a` to the first request.
