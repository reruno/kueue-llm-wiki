## Description

**What happened**:

Upgrading the Kueue chart to a new version with `helm upgrade --reuse-values` keeps the previous version's image tags. The upgrade applies the new chart's templates and CRDs, but the controller manager (and KueueViz, if enabled) keeps running the old image.

This happens because `hack/helm-chart-package.sh` writes the release tag into the packaged chart's `values.yaml` (`.image.tag = "${GIT_TAG}"`). `--reuse-values` uses the previous release's values, including its chart defaults, as the base for the upgrade, so the old tag is carried forward.

**What you expected to happen**:

The upgrade runs the new chart's images unless the user set an image tag themselves.

**How to reproduce it (as minimally and precisely as possible)**:

```sh
kind create cluster
helm install kueue oci://registry.k8s.io/kueue/charts/kueue --version 0.20.5 \
  --namespace kueue-system --create-namespace
helm upgrade kueue oci://registry.k8s.io/kueue/charts/kueue --version 0.20.6 \
  --namespace kueue-system --reuse-values
kubectl -n kueue-system get deployment kueue-controller-manager \
  -o jsonpath='{.spec.template.spec.containers[0].image}'
```

The image is still `registry.k8s.io/kueue/kueue:v0.20.5`. Helm's install and upgrade actions on the two published charts give the same result. With `--reset-then-reuse-values`, or with no flags, the upgrade runs `v0.20.6`.

The packaged chart shows the tag as a chart default:

```sh
helm show values oci://registry.k8s.io/kueue/charts/kueue --version 0.20.6 | grep -A1 "image tag"
```

**Anything else we need to know?**:

The chart templates already fall back to the chart's `appVersion` when no tag is set (`image.tag | default .Chart.AppVersion`), and the packaging script already runs `helm package --app-version "${GIT_TAG}"`. A possible fix:

1. In `hack/helm-chart-package.sh`, stop setting `.image.tag` for the Kueue, KueueViz, Populator and Priority Booster images, or set it to `""`. Keep setting the repository and pull policy. Fresh installs render the same images as today.
2. Add `| default .Chart.AppVersion` to the image tag in the Populator chart's `templates/manager.yaml`, which has no fallback today, and in the Priority Booster chart if it has none either.
3. Add a chart unit test that an empty tag renders `<repository>:<appVersion>`.

Things to check:
- Nothing in local development or e2e relies on the tag in the packaged `values.yaml`.
- Releases installed before the fix keep their saved tag on their first `--reuse-values` upgrade, because the chart can't tell it apart from a tag the user set. The docs should recommend `--reset-then-reuse-values` when changing chart versions. The chart README's migration example is being updated separately.
