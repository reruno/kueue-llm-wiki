**What happened**:

With Admission Fair Sharing, putting a ClusterQueue on `Hold` stops AFS usage sampling for its LocalQueues, even though their admitted Workloads keep running. If a Workload finishes during the hold, its usage can be missed after the ClusterQueue resumes, so the LocalQueue looks less active than it was when it competes for admission again.

This is the ClusterQueue-side counterpart of #15383. #19267 fixes stopped LocalQueues and leaves inactive ClusterQueues out of scope, as discussed in #15384.

**What you expected to happen**:

AFS keeps sampling the usage of admitted Workloads while their ClusterQueue is on `Hold`, as it does for a LocalQueue on `Hold` with #19267.

**How to reproduce it (as minimally and precisely as possible)**:


I reproduced this in the `singlecluster/scheduler/fairsharing` envtest integration suite, context "Using AdmissionFairSharing at ClusterQueue level" (sampling interval and half-life 1s):

1. Admit a 4-CPU Workload from `lq-a` on `cq1` (8 CPU, `UsageBasedAdmissionFairSharing`).
2. Set `cq1` to `Hold`, and wait for `lq-a` to become inactive. The Workload stays admitted.
3. Finish the Workload.

`lq-a`'s `status.fairSharing.admissionFairSharingStatus.lastUpdate` stays unchanged for 10s. The spec below passes 5/5 runs on main at 6317d9524 and 5/5 on #19267 at dcc59c75a. On #19267, the spec for a LocalQueue on `Hold` in the same context sees a sample within a few seconds.

```go
ginkgo.It("does not sample AFS usage while the ClusterQueue is held", func() {
	wl := createWorkload("lq-a", "4")
	behavioral.ExpectWorkloadsToBeAdmitted(ctx, k8sClient, wl)
	behavioral.ExpectLocalQueueFairSharingUsageToBe(ctx, k8sClient, client.ObjectKeyFromObject(lqA), ">", 0)
	behavioral.SetClusterQueueStopPolicy(ctx, k8sClient, cq1, kueue.Hold)
	gomega.Eventually(func(g gomega.Gomega) {
		g.Expect(k8sClient.Get(ctx, client.ObjectKeyFromObject(lqA), lqA)).To(gomega.Succeed())
		c := meta.FindStatusCondition(lqA.Status.Conditions, kueue.LocalQueueActive)
		g.Expect(c).NotTo(gomega.BeNil())
		g.Expect(c.Status).To(gomega.Equal(metav1.ConditionFalse))
	}, behavioral.Timeout, behavioral.Interval).Should(gomega.Succeed())
	behavioral.ExpectWorkloadsToBeAdmitted(ctx, k8sClient, wl)
	heldLq := &kueue.LocalQueue{}
	gomega.Expect(k8sClient.Get(ctx, client.ObjectKeyFromObject(lqA), heldLq)).To(gomega.Succeed())
	lastUpdateAtHold := heldLq.Status.FairSharing.AdmissionFairSharingStatus.LastUpdate.Time
	integration.FinishWorkloads(ctx, k8sClient, wl)
	gomega.Consistently(func(g gomega.Gomega) {
		u := &kueue.LocalQueue{}
		g.Expect(k8sClient.Get(ctx, client.ObjectKeyFromObject(lqA), u)).To(gomega.Succeed())
		g.Expect(u.Status.FairSharing.AdmissionFairSharingStatus.LastUpdate.Time).To(gomega.BeTemporally("==", lastUpdateAtHold))
	}, 10*time.Second, behavioral.Interval).Should(gomega.Succeed())
})
```

**Anything else we need to know?**:

In [`LocalQueueReconciler.Reconcile`](https://github.com/kubernetes-sigs/kueue/blob/6317d9524e9a71d3e16137eacaa765f5a377194d/pkg/controller/core/localqueue_controller.go#L209-L214), an inactive ClusterQueue causes an early return before the AFS sampling block. #19267 notes that this path has more semantics to settle than the LocalQueue one.
