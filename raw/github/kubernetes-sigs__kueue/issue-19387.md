## Description

**What happened**:

The KueueViz dashboard loads and renders every Workload, including associated pod details, without pagination. With many retained jobs/Workloads, the dashboard becomes slow to load. This was reported with KueueViz 0.19.5; the same unpaginated data flow is present in 0.20.7 and current main.

**What you expected to happen**:

Browse dashboard workloads in bounded pages while namespace filtering, live updates, summary totals, and pod expansion continue to work. The backend should attach pod details only for workloads in the requested page.

**How to reproduce it (as minimally and precisely as possible)**:

1. Populate a test namespace with thousands of Kueue Workloads, or retain a large history of managed jobs and their Workloads.
2. Open the KueueViz dashboard with that namespace selected, or with All namespaces selected.
3. Observe that the /ws/workloads/dashboard response includes every matching workload and its pod details, and the table renders every workload row without pagination controls.

**Anything else we need to know?**:

/kind bug
/area dashboard

The dashboard reads through a controller-runtime informer cache. The proposed fix is optional page/pageSize parameters on the dashboard WebSocket endpoint, with sorting and page selection before pod enrichment. Summary totals should cover the complete namespace scope. Requests without pagination parameters should retain their existing response for older frontends.

This reduces network payloads and browser rendering but still scans cached workloads for totals and ordering. Lazy pod loading and pagination on other pages can be handled separately.

Relevant implementation: https://github.com/kubernetes-sigs/kueue/blob/main/cmd/kueueviz/frontend/src/Dashboard.jsx and https://github.com/kubernetes-sigs/kueue/blob/main/cmd/kueueviz/backend/handlers/workloads_dashboard.go.
