## Description

## What happened

The CapacityBuffer AdmissionCheck reconciler computes a new `AdmissionCheckActive` condition using the current `AdmissionCheck.metadata.generation`, but it only writes that condition if its **Status** changes. Valid changes to `ObservedGeneration` or diagnostic `Message` are dropped whenever Status remains `True` or `False`.

Affected code (upstream `main`, commit `1fdd3769fbb920ce1e25452ddfd110b09421553d`): [`pkg/controller/admissionchecks/capacitybuffer/admissioncheck_reconciler.go`](https://github.com/kubernetes-sigs/kueue/blob/1fdd3769fbb920ce1e25452ddfd110b09421553d/pkg/controller/admissionchecks/capacitybuffer/admissioncheck_reconciler.go#L38-L63).

```go
if currentCondition.Status != newCondition.Status {
    apimeta.SetStatusCondition(&ac.Status.Conditions, newCondition)
    return reconcile.Result{}, client.IgnoreNotFound(a.client.Status().Update(ctx, ac))
}
```

This is a state-publication bug, not a timing-dependent race. Two transitions demonstrate it:

1. **Valid config A → valid config B.** An AdmissionCheck has `metadata.generation=1`, `Active=True`, and `Active.observedGeneration=1`. Updating `spec.parameters.name` to another existing `CapacityBufferConfig` increments the generation to 2. Reconciliation validates the new config and constructs `Active=True, observedGeneration=2`; because Status is still `True`, no status update is made. The API continues exposing `observedGeneration=1`.
2. **Invalid reference A → different invalid reference B.** An AdmissionCheck has `Active=False` with a `BadParametersRef` message describing reference A. Changing the parameters to a different invalid group, kind, or missing config makes the reconciler compute an error message for B, but since Status stays `False`, it keeps reporting the previous message and the previous observed generation.

This makes an updated `AdmissionCheck` appear unobserved despite being reconciled and can mislead operators troubleshooting a bad configuration. **No quota/admission failure is claimed** without an additional reproducer.

## What you expected to happen

After reconciliation:

- `status.conditions[type=Active].observedGeneration` reflects the `AdmissionCheck` generation just validated, including same-Status updates.
- `Reason` and `Message` reflect the latest validation result, rather than a previous invalid reference.
- `lastTransitionTime` changes only when Status actually transitions, not when just the generation or error text is updated.
- Fully unchanged conditions do not generate redundant API writes.

## How to reproduce it (as minimally and precisely as possible)

Add the following focused regression to `pkg/controller/admissionchecks/capacitybuffer/controller_test.go` (also add the `k8s.io/apimachinery/pkg/api/meta` import as `apimeta`). This reuses `newScheme()`, `NewController`, `utiltesting`, and the fake-client dependencies already in that file:

```go
func TestACReconcileRefreshesObservedGeneration(t *testing.T) {
    ctx, _ := utiltesting.ContextWithLog(t)

    ac := utiltestingapi.MakeAdmissionCheck("buffer-check").
        ControllerName(kueuealpha.CapacityBufferControllerName).
        Parameters(kueuealpha.SchemeGroupVersion.Group, "CapacityBufferConfig", "config").
        Generation(2).
        Condition(metav1.Condition{
            Type:               kueue.AdmissionCheckActive,
            Status:             metav1.ConditionTrue,
            Reason:             "Active",
            Message:            "The admission check is active",
            ObservedGeneration: 1,
        }).
        Obj()

    config := &kueuealpha.CapacityBufferConfig{
        ObjectMeta: metav1.ObjectMeta{Name: "config"},
    }

    k8sClient := fake.NewClientBuilder().
        WithScheme(newScheme()).
        WithObjects(ac, config).
        WithStatusSubresource(ac).
        Build()

    controller, err := NewController(k8sClient, &utiltesting.EventRecorder{}, nil)
    if err != nil {
        t.Fatal(err)
    }
    reconciler := &acReconciler{client: k8sClient, helper: controller.helper}

    if _, err := reconciler.Reconcile(
        ctx, reconcile.Request{NamespacedName: client.ObjectKeyFromObject(ac)},
    ); err != nil {
        t.Fatal(err)
    }

    got := &kueue.AdmissionCheck{}
    if err := k8sClient.Get(ctx, client.ObjectKeyFromObject(ac), got); err != nil {
        t.Fatal(err)
    }
    condition := apimeta.FindStatusCondition(got.Status.Conditions, kueue.AdmissionCheckActive)
    if condition == nil || condition.ObservedGeneration != ac.Generation {
        t.Fatalf("Active condition should observe generation %d, got %#v",
            ac.Generation, condition)
    }
}
```

**Expected:** `ObservedGeneration == 2` after reconcile.

**Predicted on the inspected main revision:** `ObservedGeneration == 1`; the `currentCondition.Status != newCondition.Status` test is false, so the reconciler does not call `SetStatusCondition`/`Status().Update`.

The included test is a **proposed deterministic regression, not a claim that the test or a live cluster was executed**. A second test case can seed `Active=False` with an error for config A, change the AdmissionCheck's reference to invalid config B, reconcile, and assert that the message now identifies B.

## Root cause / architectural context

The `CapacityBuffer` AdmissionCheck controller validates its `spec.parameters` reference through a typed config helper. It is responsible for publishing the `Active` status condition and is requeued through AdmissionCheck/config watches. The new condition is correctly constructed; the stale result comes entirely from the incomplete comparison before the status write.

Related implementation references:

- [CapacityBuffer AdmissionCheck reconciler](https://github.com/kubernetes-sigs/kueue/blob/1fdd3769fbb920ce1e25452ddfd110b09421553d/pkg/controller/admissionchecks/capacitybuffer/admissioncheck_reconciler.go).
- [CapacityBuffer config indexer and reference tracking](https://github.com/kubernetes-sigs/kueue/blob/1fdd3769fbb920ce1e25452ddfd110b09421553d/pkg/controller/admissionchecks/capacitybuffer/indexer.go).
- [ProvisioningRequest AdmissionCheck reconciler](https://github.com/kubernetes-sigs/kueue/blob/1fdd3769fbb920ce1e25452ddfd110b09421553d/pkg/controller/admissionchecks/provisioning/admissioncheck_reconciler.go) already checks `ObservedGeneration` as well as Status, and has a stale-generation regression test.
- [MultiKueue AdmissionCheck reconciler](https://github.com/kubernetes-sigs/kueue/blob/1fdd3769fbb920ce1e25452ddfd110b09421553d/pkg/controller/admissionchecks/multikueue/admissioncheck.go) also compares `Reason` and `Message`.

So the controllers currently expose different freshness semantics for the same `AdmissionCheckActive` condition.

## Suggested fix

Compare all relevant condition fields, while preserving the existing `Status().Update` behavior and `lastTransitionTime` semantics:

```go
old := apimeta.FindStatusCondition(ac.Status.Conditions, kueue.AdmissionCheckActive)
if old == nil ||
    old.Status != newCondition.Status ||
    old.Reason != newCondition.Reason ||
    old.Message != newCondition.Message ||
    old.ObservedGeneration != newCondition.ObservedGeneration {
    apimeta.SetStatusCondition(&ac.Status.Conditions, newCondition)
    return reconcile.Result{}, client.IgnoreNotFound(a.client.Status().Update(ctx, ac))
}
```

`apimeta.SetStatusCondition` already preserves `LastTransitionTime` for same-Status updates. A small predicate-only change plus targeted tests should suffice; no scheduler or API redesign is proposed.

## Acceptance criteria

- [ ] Initial valid reference publishes `Active=True` with the current observed generation.
- [ ] Valid config A → valid config B updates `ObservedGeneration` without changing `Active=True`.
- [ ] Invalid reference A → invalid reference B updates the diagnostic message and observed generation with `Active=False` unchanged.
- [ ] Existing `False → True` and `True → False` transitions still update normally.
- [ ] Same-Status metadata updates preserve `LastTransitionTime`.
- [ ] A completely unchanged condition causes no redundant status update.
- [ ] Regression tests run in CI alongside the existing CapacityBuffer controller tests.
