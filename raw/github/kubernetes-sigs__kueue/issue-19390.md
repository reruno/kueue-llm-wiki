**What would you like to be cleaned**:

I think the test here https://github.com/kubernetes-sigs/kueue/blob/main/test/e2e/singlecluster/baseline/capacitybuffer_test.go#L216-L231 is very tricky, because the workload is evicted, but it spends in the queue only 1s according to the configuration (BackoffBaseSeconds=1s). We may be unlucky and miss the Evicted=True observation, thus needed to wait another cycle.

I think it might be ok to end the e2e test on eviction after timeout, because what happens later should not have memory of the previous run. At least for the first iteration. So, I would suggest having timeout just 1s, and the requeueTime longer, like MediumTimeout, to make sure we will observe the eviction.

**Why is this needed**:

To make the test deterministic and easy to follow.
