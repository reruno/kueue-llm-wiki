**What happened**:

When a ClusterQueue custom label value changes, `ClusterQueueReconciler.resyncClusterQueueGaugeMetrics` clears the ClusterQueue gauges without holding the scheduler cache lock. `kueue_admitted_active_workloads` is dropped by `metrics.ClearCacheMetrics`. Then `Cache.ResyncClusterQueueGaugeMetrics` takes the cache read lock, and `clusterQueue.resyncAdmittedActiveWorkloads` adds 1 per admitted Workload without clearing the series first.

A Workload removed between the clear and the rebuild (`DeleteWorkload` or `ForgetWorkload`, under the cache write lock) writes -1 into the series for the new label value, since the label store already holds it. With two admitted Workloads, the series ends at 0 instead of 1, and goes to -1 when the other Workload is removed. A Workload admitted inside the same window is counted twice.

The LocalQueue series are not affected, because `resyncLocalQueueAdmittedActiveWorkloads` clears them inside the rebuild, under the cache read lock.

**What you expected to happen**:

After a relabel, `kueue_admitted_active_workloads` for the ClusterQueue matches the number of admitted active Workloads.

**How to reproduce it (as minimally and precisely as possible)**:

The window is too small to hit on purpose in a cluster, so a unit test in `pkg/cache/scheduler/cache_resync_metrics_test.go` replays the controller's steps in order:

1. Add a ClusterQueue labeled `team=alpha` and two admitted Workloads, with a `team` custom metric label configured.
2. Call `CQStore` and `UpdateClusterQueue` with `team=beta`.
3. Run the controller's clears, `metrics.ClearClusterQueueMetrics`, `metrics.ClearCacheMetrics` and `metrics.ClearClusterQueueResourceMetrics`.
4. Call `ForgetWorkload` on one Workload.
5. Call `Cache.ResyncClusterQueueGaugeMetrics`.

`kueue_admitted_active_workloads{cluster_queue="cq1",custom_team="beta"}` is 0 instead of 1.

**Anything else we need to know?**:

Found in review of #18770, which adds the same resync for terminating ClusterQueues. Main is affected through the relabel path of an active ClusterQueue, where `Update` calls `resyncClusterQueueGaugeMetrics` https://github.com/kubernetes-sigs/kueue/blob/243782aff9dc7de37023f593ec89b981dd89a65e/pkg/controller/core/clusterqueue_controller.go#L440.

Clearing the ClusterQueue series at the start of `clusterQueue.resyncAdmittedActiveWorkloads`, under the cache read lock, as the LocalQueue variant does, makes the test pass.
