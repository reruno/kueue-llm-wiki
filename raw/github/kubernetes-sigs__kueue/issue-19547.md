## Description

**What happened**:

`hack/issue_assignee_cap.py` applies the eight-issue limit to repository top-level owners and automatically unassigns them. This happened to @mimowo in #19545.

**What you expected to happen**:

Exclude repository top-level owners from the assignment limit. Continue to enforce the limit for other contributors.

**How to reproduce it (as minimally and precisely as possible)**:

Assign an open issue to a repository top-level owner who already has eight or more open issues. The assignment workflow unassigns the owner and posts a limit warning.

**Anything else we need to know?**:

Update the assignment check and add regression tests for exempt owners and non-exempt contributors. Requested by @tenzen-y in [this comment](https://github.com/kubernetes-sigs/kueue/issues/19545#issuecomment-7138676312).
