## Description

/kind feature

**What would you like to be added**:
Support for elastic scaling of Kubeflow Trainer v2 `TrainJob` workloads using Kueue's Workload Slices mechanism (`ElasticJobsViaWorkloadSlices`, [KEP-77](https://github.com/kubernetes-sigs/kueue/tree/main/keps/77-dynamically-sized-jobs)).

The Kubeflow Trainer project is introducing native elastic distributed training for `TrainJob` (such as PyTorch Elastic training via `torchrun`) as part of its upcoming release (tracked in [kubeflow/trainer#2903](https://github.com/kubeflow/trainer/issues/2903) and KEP [kubeflow/trainer#3654](https://github.com/kubeflow/trainer/pull/3654)).

We would like to open the discussion in Kueue to evaluate how to support such workloads and determine the exact scoping across the layered functionalities of `ElasticJobs`:

1. **Core Workload Slicing Integration**:
   - Opting into workload slicing via the `kueue.x-k8s.io/elastic-job: "true"` annotation.
   - Injecting the `kueue.x-k8s.io/elastic-job` scheduling gate into worker pod templates (via `trainJob.Spec.RuntimePatches`).
   - Evaluating whether TrainJob support should be guarded under the generic `ElasticJobsViaWorkloadSlices` gate or if a dedicated integration gate (e.g. `ElasticJobsViaWorkloadSlicesForTrainJob`, similar to SparkApplication) is preferred.

2. **Scoping Layered Capabilities & Cross-Cutting Feature Gates**:
   - **Partial Replica Scale-Up (`ElasticJobsViaWorkloadSlicesWithPartialReplicaScaleUp`)**: Evaluate whether TrainJobs can support partial scale-up (admitting intermediate worker counts within the runtime's `[minNodes, maxNodes]` range) or should strictly enforce atomic scale-up.
   - **Topology-Aware Scheduling (`ElasticJobsViaWorkloadSlicesWithTAS`)**: Determine initial topology constraints (e.g. restricting to unconstrained TAS placement as in early phases of other elastic integrations).
   - **MultiKueue Integration**: Assess requirements for dispatching elastic TrainJobs across management and worker clusters via the TrainJob MultiKueue adapter.
   - **ProvisioningRequests (`ElasticJobsViaWorkloadSlicesForProvisioningRequests`)**: Determine if dynamic slice scaling should integrate with autoscaler provisioning requests.

**Why is this needed**:
Currently, Kueue's TrainJob integration treats jobs as static. Resizing an active TrainJob either triggers webhook immutability rejections or causes Kueue to mark the Workload out-of-sync, forcing job suspension and Workload recreation.

Supporting Workload Slices for TrainJob will enable:
- **Disruption-free quota allocation on scale-up**: Requesting additional capacity via replacement workload slices without Kueue suspending the job, terminating already-running worker pods, or losing admitted cluster quota.
- **Immediate quota reclaim on scale-down**: Updating admitted workload pod counts in-place to release unused worker quota back to the ClusterQueue immediately.
- **Quota-controlled elasticity**: Ensuring newly spawned worker pods are held by scheduling gates until cluster capacity is admitted, preventing unmanaged pod spikes on congested clusters.
