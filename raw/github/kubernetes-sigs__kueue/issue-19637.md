## Description

/kind bug

**What happened**:

`kueuectl create clusterqueue` accepts arbitrary strings for `--queuing-strategy`, `--reclaim-within-cohort`, and `--preemption-within-cluster-queue`. The values are cast straight into the typed fields with no client-side check:

```go
o.QueueingStrategy = kueue.QueueingStrategy(o.UserSpecifiedQueueingStrategy)
o.ReclaimWithinCohort = kueue.PreemptionPolicy(o.UserSpecifiedReclaimWithinCohort)
o.PreemptionWithinClusterQueue = kueue.PreemptionPolicy(o.UserSpecifiedPreemptionWithinClusterQueue)
```

With `--dry-run=client`, kueuectl prints a ClusterQueue that the API would reject. Without dry-run, the request fails only after it hits the API (CRD `+kubebuilder:validation:Enum=...`).

**What you expected to happen**:

Invalid enum values should fail locally with a clear error before any API call, similar to how `--dry-run` already rejects unknown strategies. Allowed values:

- `--queuing-strategy`: `StrictFIFO`, `BestEffortFIFO`
- `--reclaim-within-cohort`: `Never`, `LowerPriority`, `Any`
- `--preemption-within-cluster-queue`: `Never`, `LowerPriority`, `LowerOrNewerEqualPriority`

**How to reproduce it (as minimally and precisely as possible)**:

```bash
kueuectl create clusterqueue bad-cq \
  --queuing-strategy=NotARealStrategy \
  --dry-run=client
```

Observed: prints a ClusterQueue with `queueingStrategy: NotARealStrategy` and exits 0.

Expected: non-zero exit and an error naming the allowed values.

Same for:

```bash
kueuectl create clusterqueue bad-cq \
  --reclaim-within-cohort=Bogus \
  --dry-run=client

kueuectl create clusterqueue bad-cq \
  --preemption-within-cluster-queue=Any \
  --dry-run=client
```

(`Any` is valid for reclaim-within-cohort but not for withinClusterQueue.)

**Anything else we need to know?**:

- Code: `cmd/kueuectl/app/create/create_clusterqueue.go` (`Complete` / `validate`)
- API enums: `apis/kueue/v1beta2/clusterqueue_types.go` (`QueueingStrategy`, `ClusterQueuePreemption`)
- Related but different: #19303 / #19304 add shell completion for some enum flags; this issue is about rejecting invalid values at runtime.
- Resource quota flags already validate client-side; these three enum flags do not.
