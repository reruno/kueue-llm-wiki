## Description

<!-- Please only use this template for submitting enhancement requests -->

**What would you like to be added**:

Make TAS topology domain selection priority-aware, so that pods of workloads with the same priority are consolidated into the same topology domains instead of being spread across domains regardless of priority.

For each topology domain, TAS would track the highest priority among the TAS-admitted pods in the domain (aggregated from its child domains). When TAS selects domains for a PodSet, it would prefer, among the candidate domains, in the following order:

1. Domains whose highest priority among TAS-admitted pods equals the incoming workload's effective priority (including priority boost).
2. Domains with no TAS-admitted pods.
3. Any other domain (today's behavior, as a fallback).

**Why is this needed**:

When small, higher-priority workloads are spread across many domains, each domain becomes "pinned".

It cannot be fully freed for a larger workload of the same priority, even if most of its capacity is used by lower-priority pods. This affects workloads that need a whole node, as well as workloads that need a whole rack or block (e.g., `required: rack`).

The incoming Configurable Preemption can mitigate this problem by defragmentation.
But it issues preemptions that enforce eviction priority to batch users.

Also, this Priority-aware TAS can help reduce the number of preemptions for Configurable Preemptions defragmentation.
