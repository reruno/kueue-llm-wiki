### Comment by [@mszadkow](https://github.com/mszadkow) — 2025-11-04T13:09:38Z

In my opinion in the test we lack Eventually wrapper on the:
```
		ginkgo.By("observe: job is no longer suspended in the manager cluster", func() {
			getJob(manager.ctx, manager.client, job)
			gomega.Expect(job.Spec.Suspend).To(gomega.BeEquivalentTo(ptr.To(false)))
		})
```

because it might be not enough to update `.spec.Suspend` to true at `09:46:41.105`:
```
  2025-11-03T09:46:41.105387587Z	LEVEL(-2)	jobframework/reconciler.go:571	Job admitted, unsuspending	{"controller": "job", "controllerGroup": "batch", "controllerKind": "Job", "Job": {"name":"job","namespace":"multikueue-w7lg5"}, "namespace": "multikueue-w7lg5", "name": "job", "reconcileID": "66c1b326-9b61-42b1-bd1f-6c5563035d60", "job": "multikueue-w7lg5/job", "gvk": "batch/v1, Kind=Job"}
```
and do a verification just once at `09:46:41.114` (9 milliseconds):
```
  [38;5;9m[FAILED][0m in [It] - /home/prow/go/src/sigs.k8s.io/kueue/test/integration/multikueue/jobs_test.go:1729 [38;5;243m@ 11/03/25 09:46:41.12[0m
```

### Comment by [@olekzabl](https://github.com/olekzabl) — 2026-05-28T23:06:17Z

/reopen

This flaked again, [here](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/11763/pull-kueue-test-integration-multikueue-release-0-16/2060125094218305536).

```
Operation cannot be fulfilled on jobs.batch "job": the object has been modified; please apply your changes to the latest version and try again
```

I think I see why. The improved test does this:

https://github.com/kubernetes-sigs/kueue/blob/1a88745244f31d920ef3c7f60f3f5b584ac9c7ef/test/integration/multikueue/jobs_test.go#L1792-L1796

so once we're unlucky enough to `getJob` in an outdated version, every subsequent attempt to update will fail the same way, no matter how many times we try.

The fix is to repeat `Get` in every attempt: #11769
