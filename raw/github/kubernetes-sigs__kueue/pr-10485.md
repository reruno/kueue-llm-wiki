#### What this PR does / why we need it:
Similar to kueue_cluster_queue_resource_reservation, but I want to track the resources pending in the CQ. Today we just count the number of pending workloads. Call it kueue_cluster_queue_resource_pending.

Helps with instrumenting Kueue to alert when something is broken. You can take the diff of Pending - Unallocated Nominal Quota to roughly gauge whether there's a scheduling issue and investigation needs to happen. (ex: fragmentation, scheduling gates not initiated by Kueue, bugs, etc.) If there's enough unallocated nominal quota to admit the pending workloads, but you see that diff for a prolonged period of time (ie not a spike shape), there's potentially an issue.

Hi all, I have a basic question about the metric and its usage/usefulness.

The PR defines "pendingResourcesTotal is the incremental sum of TotalRequests across workloads".
Let's take an example. Say the queue's nominal quota for a resource is 100, resource reservation is 20 and so the unallocated ("remaining nominal") amount is 80. Now, say there are 3 jobs A, B and C with resource needs of 50, 40 and 10, resp.

So, pendingResourcesTotal is 100 (A+B+C). It is more than the unallocated amount of 80. 

So, if we are monitoring the condition `if (pendingResourcesTotal <= remaining nominal) then /* some scheduling issue */`, that would not trigger, and things would seem normal.

However, job A can be admitted. If job A is not admitted for a while, that could be a scheduling problem, but that is not flagged because the metric is a sum across pending workloads rather than per workload.

IOW, is it useful to be looking only at the aggregated resource count?
