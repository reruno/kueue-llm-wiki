### Review by [@amy](https://github.com/amy) (commented) — 2026-05-13T13:49:43Z

- **cmd/experimental/skills/reviewer/extract-helpers/SKILL.md:1** by [@amy](https://github.com/amy) — 2026-05-13T13:49:43Z
  
  this isn't about unused parameters. This is about pulling out large chunks of code that can be summarized into a function name for readability.
  
  Sample:
  ```
  func Greeting(user User) string {
      name := strings.TrimSpace(user.FirstName)
      if name == "" {
          name = "friend"
      }
      name = strings.Title(name)
  
      return fmt.Sprintf("Hello, %s! You have %d new messages.", name, user.Unread)
  }
  ```
  name is built up over three lines, then used once. Its scope spans the whole function for no reason.
  There's more extreme examples in actual code.
  vs.
  ```
  func displayName(user User) string {
      name := strings.TrimSpace(user.FirstName)
      if name == "" {
          return "friend"
      }
      return strings.Title(name)
  }
  
  func Greeting(user User) string {
      return fmt.Sprintf("Hello, %s! You have %d new messages.", displayName(user), user.Unread)
  }
  ```
  name now lives only inside displayName, and Greeting is a single expressive line.
