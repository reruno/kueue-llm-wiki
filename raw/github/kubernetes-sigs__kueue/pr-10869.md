  I think in most cases the automated way will work well. Actually, it nicely skips  "v0.18.0-rc.0".
  
  However, I'm not sure it will work well in all cases. For example, when we are releasing 0.17.6 and 0.18.0 on the same day, then the automated selection for 0.17.6 may choose "true", because it is currently "latest", but we know that 30min later we will release 0.18.0. So probably we can just generate the changelog for 0.17.6.
  
  So, I'm wondering if we could use the automated way by default, but just have a param like `--force-latest y/n` true/false that would allow us to force which generation option to use.
  
  Then we don't need to even put the param in the "new release notes", but keep it as an option.
