  I think this value will not impact.
  
  The sample job in quick-start-job.yaml requests:
  ```yaml
  resources:
     requests:
        cpu: "1"
        memory: "200Mi"
  ```
  3 pods × 200Mi = 600 Mi total. That is well below both the 36Gi quota and what a KIND node can physically provide (~7.6 Gi). Kueue's nominalQuota is a logical accounting ceiling, not a physical reservation. Kueue admits the workload because 600Mi ≤ 36Gi, then the K8s scheduler places pods normally. The actual physical fit on KIND nodes is fine.
  
  But +1 to your comment, in order not to bring confuse here, I will update the value to `9Gi`, a value that fits a KIND node and still leaves headroom for multiple jobs.
