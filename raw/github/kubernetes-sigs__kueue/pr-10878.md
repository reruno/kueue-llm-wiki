## Description

#### What type of PR is this?

/kind feature
/area tas

#### What this PR does / why we need it:

When the LeastFreeCapacity places a single pod workload that fits inside one host, the existing sort keys operate only at the level being sorted without visibility into partially full nodes, so TAS may spread single pod workloads across domains based on least free capacity rather than stacking them on the same nodes, fragmenting capacity 

#### Which issue(s) this PR fixes:

Adds one new sort key minNonZeroLeafState which represents the smallest free node capacity among leaves in this subtree, such that TAS will pick the subtree containing the tightest non empty node

#### Does this PR introduce a user-facing change?
No

  > Is it just to illustrate the example, but your actual use case is different? 
  
  So the usecase is the same cluster is used for both training and inference workloads. Training workloads are mostly full-node and specify topology constraints at the NVSO domain layer. Inference workloads may be stackable or full-node but don't require topology constraints. To reduce fragmentation there are two goals:
  
  1. minimize NVSO domain fragmentation to keep as many free domains for training workloads 
  2. minimize node level fragmentation to avoid partially filled nodes 
  
  > Also, why do you actually use podset slices for single Pod workloads?
  
  There is not a single TAS constraint we can apply for the workloads without topology constraints to achieve objectives. Using podset slice will help with 1. but doesnt account for 2. While unconstrained topology would help with 2 but not 1. With this PR, using podset slice annotation will achieve both 1 and 2
