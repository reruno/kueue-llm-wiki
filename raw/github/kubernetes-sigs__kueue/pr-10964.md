#### What type of PR is this?

#### What this PR does / why we need it:

Adds a new `RejectDRAWhenDisabled` feature gate (default: enabled, Beta) that rejects
workloads using DRA resources (ResourceClaimTemplates or ResourceClaims) when the
`DynamicResourceAllocation` feature gate is disabled.

Without this, DRA workloads submitted while `DynamicResourceAllocation` is off are
silently admitted with zero device resource usage, bypassing quota enforcement entirely.
The Kubernetes DRA scheduler then allocates devices directly, allowing unlimited GPU
consumption outside Kueue's control.

The rejection is enforced at two levels:
- **Event handlers**: DRA workloads are not added to the scheduler queue
- **Reconcile loop**: workloads are marked `WorkloadInadmissible` with a clear message

#### Which issue(s) this PR fixes:

Fixes #10504

#### Special notes for your reviewer:

The guard is needed in multiple places in workload_controller.go because there are
several code paths that can add a workload to the scheduler queue (Create handler,
Update handler, resource updates handler, immediate requeue path). All must skip DRA
workloads to prevent the scheduler from admitting them before the reconciler can reject.

#### Does this PR introduce a user-facing change?

```release-note
Add RejectDRAWhenDisabled feature gate (default: enabled, Beta) that rejects workloads
using DRA resources when DynamicResourceAllocation is disabled, preventing silent quota bypass.
```
