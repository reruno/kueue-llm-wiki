  I just tested with an unknown `ReplicaType` and it worked properly. Let me explain de code flow:
  
  1. [The MPI job TAS validation](https://github.com/kaisoz/kueue/blob/c56c5a63c778f6ddcbb5c72c6613882df190afaa/pkg/controller/jobs/mpijob/mpijob_webhook.go#L177) is run on each validation webhook event
  2. The first thing the validator does is [call the ](https://github.com/kaisoz/kueue/blob/c56c5a63c778f6ddcbb5c72c6613882df190afaa/pkg/controller/jobs/mpijob/mpijob_webhook.go#L180)Podsets[ function of the controller](https://github.com/kaisoz/kueue/blob/c56c5a63c778f6ddcbb5c72c6613882df190afaa/pkg/controller/jobs/mpijob/mpijob_webhook.go#L180) to get the podsets
  3. The PodSets function implementation for MPI jobs [first extracts the available ReplicaTypes](https://github.com/kaisoz/kueue/blob/c56c5a63c778f6ddcbb5c72c6613882df190afaa/pkg/controller/jobs/mpijob/mpijob_controller.go#L113). A here's where the safety net is. Because the `MPIjob.Spec.MPIReplicaSpecs` is a map, the function  checks and returns only supported `ReplicaTypes`. This means that if you add a malicious `ReplicaType`, the controller just ignores it and doesn't create a `PodSet` for it (this is what I tested). The returned `PodSets` list will always be valid (in that sense)
  4. And coming back to the webhook. Since [it loops the returned `PodSets` list](https://github.com/kaisoz/kueue/blob/c56c5a63c778f6ddcbb5c72c6613882df190afaa/pkg/controller/jobs/mpijob/mpijob_webhook.go#L182) and they are already validated, it won't break
  
  I've added a test to confirm this 👍🏻
