  I have troubles understanding why this metrics is called goodput seconds and when it is actually useful. 
  
  Goodput should probably measure how much "good" the workload produced per unit of time when it was actually running or how much of the potential output was lost due to interruptions, preemptions, inefficient placements etc.  
  
  By including wait time the metric becomes randomly diluted. All the workloads may be having the best run ever with 100% hardware utilization and no preemptions, yet the metrics will be low because many of them were submitted at the same time.
  
  Similarly, the metric will be high when you have only couple workloads that can make literally zero progress because they are constantly interrupted and  rescheduled for no reason, but without any wait time.
  
  Moreover when we talk about ratio, seconds should not be there. 
  
  To improve it, I would rather measure something like the following ratio: 
  ```
  actual_execution_and_ready_time / (time_spent_on_scheduling + time_spent_on_preemptions + time_on_startup_before_ready + time_spent_on_stopping + actual_execution_and_ready_time)
  ```
