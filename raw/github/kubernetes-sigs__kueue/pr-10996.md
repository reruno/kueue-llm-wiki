### Comment by [@mimowo](https://github.com/mimowo) — 2026-05-22T13:28:58Z

> So, I merge this one first, then if we find any critical problem in DRA Extended Resource supports, we will revert this PR.

I have actually conerns about going Beta with "Extended Resource" for 0.18, because the currently implementation assumes that Extended Resource is any resource with "/". So, we start running new code paths for any users declaring nvidia.com/gpu. I proposed another solution when we first scrape the resources which are extended, not rely on strings. However, the new approach will only be provided now, so we don't have enough testing time to claim Beta. 

So, I would rather say that PD and ER stay Alpha in 0.18, and we move them both to Beta in 0.19 when we gain more confidence. I think this is perfectly valid approach to first graduate to Beta the "core" FG, and only later the secondary FGs. We took that approach with TAS where we graduated the main FG to Beta, while still keeping some FGs in Alpha for a while, incubating. The same approach is taken by the core k8s where the "core" FG is leading the graduation, while the secondary FGs graduate slower. 

In other words, I would like to still keep PD and ER in Alpha, while already move to Beta with the core FG. Let me know if this is ok for you.
