## Pull request overview

This PR graduates the `SchedulingEquivalenceHashing` feature gate to be enabled by default (Beta in 0.18), while narrowing equivalence hashing/bulk-move behavior to only trigger for true `NoFit` outcomes via explicit requeue reasons (avoiding incorrect bulk-moves for other inadmissibility causes like namespace selector mismatch or preemption gating).

**Changes:**
- Enable `SchedulingEquivalenceHashing` by default starting in version 0.18 (still Beta).
- Introduce explicit requeue reasons (`NoFit`, `PreemptionNoCandidates`) and gate equivalence hashing on the `NoFit` reason rather than a broad “non-immediate” condition.
- Add unit + integration coverage to ensure hashing triggers only for `NoFit` and does not interfere with namespace-mismatch scenarios.
