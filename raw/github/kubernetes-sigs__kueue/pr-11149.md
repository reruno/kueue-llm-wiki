## Description

## What this PR does

Adds a `/tmp` emptyDir volume mount to the manager deployment template so the visibility server can write its self-signed certificates when `readOnlyRootFilesystem: true` (the Helm chart default) and `enableCertManager: false`.

## Why

When `readOnlyRootFilesystem` is `true` (default since v0.17.2) and cert-manager is disabled, the visibility server tries to write `/tmp/apiserver.crt` but fails with:

```
error creating self-signed certificates: open /tmp/apiserver.crt: read-only file system
```

The chart already provides a `/visibility` emptyDir volume, but the server binary writes to `/tmp` which is on the read-only root filesystem.

## Changes

- Add `volumeMount` for `/tmp` → `tmp` volume in the manager container
- Add `tmp` emptyDir volume to the pod spec

```release-note
Fix visibility server crash with "read-only file system" error when readOnlyRootFilesystem is true and enableCertManager is false by adding a /tmp emptyDir volume mount.
```

### Comment by [@cixuuz](https://github.com/cixuuz) — 2026-05-13T00:15:04Z

@kannon92 Good question — I dug into this more.

**Why `/tmp` instead of `/visibility`?**

The error path depends on the `internalCertManagement` config:

1. **v0.11.0** used `o.SecureServing.ServerCert.CertDirectory = "/tmp"` unconditionally ([server.go:91 in v0.11.0](https://github.com/kubernetes-sigs/kueue/blob/v0.11.0/pkg/visibility/server.go#L91)), which meant `MaybeDefaultWithSelfSignedCerts` wrote to `/tmp/apiserver.crt`.

2. **v0.17.2** refactored this to use `certDir = "/visibility"` and branches on `InternalCertManagement.Enable`:
   - When `true` (default via Helm when `enableCertManager: false`): sets `CertDirectory = "/visibility"` → generates `/visibility/apiserver.crt` on the emptyDir ✓
   - When `false` (cert-manager provides certs): sets `CertFile`/`KeyFile` to `/visibility/tls.{crt,key}` and expects them to already exist

With default Helm values today, the path should indeed be `/visibility/apiserver.crt` (on the emptyDir), not `/tmp`. The `/tmp/apiserver.crt` error in the issue likely comes from an upgrade scenario where the old v0.11.0 binary was still running briefly against the new security context, or possibly a cached image.

**However**, a `/tmp` emptyDir is still good practice here because:
- Go's `os.TempDir()` returns `/tmp` — any transitive dependency writing temp files will fail with `readOnlyRootFilesystem: true`
- The k8s apiserver library itself uses `os.CreateTemp` in some code paths
- It's the standard pattern for hardened containers (distroless/nonroot images always mount `/tmp`)

**When did this start?** The `readOnlyRootFilesystem: true` default was introduced in v0.17.x (not present in v0.11.0). So anyone upgrading from ≤v0.16.x to v0.17.x with default values and without cert-manager would hit filesystem issues.

Happy to adjust the approach if you'd prefer a different fix — e.g., changing the Go code to use the already-mounted `/visibility` dir as a general temp dir, or gating the `/tmp` mount on `!enableCertManager`.
