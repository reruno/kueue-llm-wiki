  > Why Visibility API? 
  
  Because you advised so :)
  
  > What about, for example, providing the same object as regular CRD?
  
  Well, AFAIK (as mentioned e.g. [here](https://github.com/kubernetes-sigs/kueue/issues/10553#issuecomment-4343485978)) you recently proposed refactoring the whole Visibility API into a CRD-based "request in Spec, response in Status" communication protocol.
  If that proposal is accepted, this KEP will naturally fall into its scope.
  Is this what you mean?
