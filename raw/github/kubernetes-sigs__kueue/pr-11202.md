#### What this PR does / why we need it:

In `TestHeadsAsync`, each subtest creates a logger bound to the subtest's `*testing.T` via `utiltesting.ContextWithLog(t)`. The `tc.op(ctx, manager)` call then spawns goroutines that pass that context's logger deep into production code (`AddOrUpdateWorkload` → `AddOrUpdateWorkloadWithoutLock` → `expectations.Store.ObservedUID()`), where it calls `log.V(3).Info(...)` → `t.Log()`.

The race: after `manager.Heads(ctx)` returns (meaning the workload was added and the goroutine's work is logically done), the subtest goroutine can exit and finalize the subtest's `t`—but the spawned goroutine may still be executing the trailing `log.Info` call, which reads `t`'s internal state concurrently with `t`'s finalization write.
