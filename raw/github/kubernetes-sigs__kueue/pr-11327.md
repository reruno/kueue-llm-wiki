## Pull request overview

This PR targets a race condition in elastic Job workload-slicing where rapid scaling can produce duplicate replacement workload slices that remain admitted and leak quota. It updates the workload-slicing reconciliation logic to proactively finish one of the duplicates and adds an integration stress test to verify convergence and quota usage under rapid scaling.

**Changes:**
- Finish an “old” workload slice when two active slices both claim to replace the same prior slice.
- Add an integration stress test that rapidly cycles Job parallelism and asserts convergence to a single active admitted workload.
- Add a cluster-queue usage assertion to detect quota leaks after rapid scale cycles.

  `bothReplaceTheSameSlice` is added as a cleanup signal, but the later anomaly check still returns an error whenever `newWorkload` has quota and `newWorkloadAdmittedAsReplacement` is false.
