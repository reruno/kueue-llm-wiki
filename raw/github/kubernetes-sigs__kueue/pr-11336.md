### Comment by [@mimowo](https://github.com/mimowo) — 2026-05-20T11:21:53Z

The note for https://github.com/kubernetes-sigs/kueue/pull/11342  was generated with it. That was a simple case, but the reasoning was pretty good:

```
  1. Details

   1 ElasticJobsViaWorkloadSlices: Fixed a bug where a validation error for the `kueue.x-k8s.io/elastic-job` annotation incorrectly pointed to `metadata.labels[kueue.x-k8s.io/elastic-job]` instead of
     `metadata.annotations[kueue.x-k8s.io/elastic-job]`. This ensures that users receive the correct field path when the webhook rejects an attempt to modify this immutable annotation on an existing Job.

  2. Concise

   1 ElasticJobsViaWorkloadSlices: Fixed an incorrect field path in the validation error for the `kueue.x-k8s.io/elastic-job` annotation.

  3. Balanced

   1 ElasticJobsViaWorkloadSlices: Fixed a bug where updating the `kueue.x-k8s.io/elastic-job` annotation on a Job resulted in a validation error pointing to the incorrect path `metadata.labels` instead
     of `metadata.annotations`.

  ---

  Rationale:
   * Prefix: ElasticJobsViaWorkloadSlices: was chosen as the narrowest accurate prefix, as the kueue.x-k8s.io/elastic-job annotation is specific to this feature.
   * Wording: Framed as a bugfix using the recommended "Fixed a bug where <scenario> could <impact>" template.
   * User-Observable Change: The primary impact is the correction of the field path in the validation error message, which prevents user confusion when debugging rejected updates.
   * Formatting: Used code formatting (backticks) for the annotation key and field paths as per the engineering standards in the skill.
   * Consistency: Avoided broad prefixes like Kueue: and focused on the specific user-facing area.
```
