  `effectiveRequests` is only populated when `i < len(totalRequests)`; otherwise it stays as the zero value (likely `nil`). This can produce incorrect equivalence hashing: two workloads with different actual requests could hash the same if `totalRequests` is shorter than `wl.Spec.PodSets`, and `nil` vs `{}` can also change the hash depending on how `Requests` is constructed upstream. Consider either (a) deriving `effectiveRequests` from the podset template when `totalRequests` is missing, or (b) enforcing/validating that `totalRequests` always has one entry per podset and normalizing empty requests to a consistent representation before hashing.

  Good question! You are right about `SpecShape`, but DRA preprocessing changes `TotalRequests` without modifying the spec as  it replaces `example.com/gpu` with the DeviceClass-mapped logical resource (gpu). After translation, the spec still hashes the same but the workload's actual resource demands changed, so including `effectiveRequests` makes the hash reflect what the scheduler will actually evaluate.
