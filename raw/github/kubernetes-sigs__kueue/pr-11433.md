#### What this PR does / why we need it:
Adds integration tests for the fix in #10666, verifying that admitted workloads with `UnhealthyNodes` are properly evicted when:
- An AdmissionCheck enters `Retry` state
- The PodsReady recovery timeout is exceeded
These tests cover the regression where an early return in the workload controller skipped reconciliation for admitted workloads with unhealthy nodes, preventing eviction via these two paths.
Also introduces `managerSetupWithConfig` in the TAS test suite to allow tests that need custom `Configuration` (e.g., `WaitForPodsReady`).

#### Special notes for your reviewer:
This is the follow-up integration test requested in https://github.com/kubernetes-sigs/kueue/pull/10666#issuecomment-4294391572
The AdmissionCheck Retry test uses a fake controller name (`test-ac-controller`) so the check state can be manually controlled without interference from a real admission check controller.
The PodsReady test requires a separate top-level `ginkgo.Describe` block because `WaitForPodsReady` must be configured in the manager at startup.
