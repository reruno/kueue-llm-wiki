## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it:
This addresses a race condition, where a workload might be kept in `preemptionExpectations` despite being Admitted and not having the Evicted condition.

#### Which issue(s) this PR fixes:
Fixes #11480

#### Special notes for your reviewer:
The reproduction I linked in #11480 is itself flaky - the processing order of some events seems to be relevant. Without this fix, the reproduction succeeds within minutes. I ran it with this fix over the weekend and it did not fail once.

#### Does this PR introduce a user-facing change?
```release-note
Scheduling: Fix a race condition within the admission process that could cause workloads waiting indefinitely for a preemption, causing head-of-line blocking of the affected ClusterQueues.
```
