#### What this PR does / why we need it:

When a worker cluster is disconnected or reconnecting, `remoteClientsForAC` silently excludes it from the available clients map. If the local workload loses its quota reservation during this window, step 2 of `reconcileGroup` deletes remote workloads only on reachable clusters and returns with no `RequeueAfter`, leaving the unreachable cluster's remote workload orphaned.
This PR tracks whether any configured clusters were unavailable when building the workload group and, when so, returns `RequeueAfter` so cleanup is retried once the cluster is back.

**1. is the cleanup now immediate after reconnection, or how long the latency could be?**
Cleanup is not immediate. While a worker is unavailable, we requeue periodically (default workerLostTimeout = 5m). After reconnection, cleanup happens on the next retry, and in some cases earlier if reconnect/watch events trigger reconcile.

**2. before the change would there be the safety net of cleaning the workload by MK garbage collector?**
Before this change, GC was only a partial safety net: it cleans remotes when the local workload is missing or being deleted. If the local workload still exists but has lost quota reservation, GC treats the remote as still relevant and does not remove it. This PR covers that missing cleanup path.
