#### Which issue(s) this PR fixes:

Fixes #11496

#### Special notes for your reviewer:

```
cause: When a cluster connection is lost, `stopAndRemoveCluster()` completely removes the `remoteClient` from the map, causing the workload reconciler to be unable to detect the disconnected cluster, returning an `ErrNoActiveClusters` error and triggering the controller-runtime backoff instead of the `workerLostTimeout` delay mechanism.

Fix: Instead, mark disconnected clients as disconnected and retain them in the map, enabling the workload reconciler to:

	- Detect cluster disconnections
	- Apply the `workerLostTimeout` delay even if all clusters are disconnected
	- Properly handle cleanup when connections are restored
```

#### Does this PR introduce a user-facing change?

```release-note
MultiKueue: Fixed a bug where a lost connection to a worker cluster failed to trigger the "workerLostTimeout" delay mechanism for workload requeuing.
```
