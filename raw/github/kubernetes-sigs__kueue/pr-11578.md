I think the analysis is correct, my only doubt about this fix I have is that the problem remains that on even faster clusters the surge workloads are rotated so fast that the ShortInterval is not enough to catch their existence. 

The more robust approach would be to use watches. I know this brings complexity but if done correctly it actually makes the test code correct, without relying on interim polls.

Let me merge this one as it already improves the build stability, but I would suggest to follow up with the watches approach.
