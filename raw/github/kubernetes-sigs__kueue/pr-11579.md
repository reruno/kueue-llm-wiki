#### What this PR does / why we need it:
Instead of producing a single slice with the shortest common hostname prefix, domains are now grouped by their longest reusable `-` delimited prefixes and split into separate slices, enabling support for workloads up to 150k nodes.

### Comment by [@olekzabl](https://github.com/olekzabl) — 2026-06-12T08:38:16Z

I now recalled there's one more topic which we may wish to explore.

Your new algorithm is _asymmetric_ with respect to prefixes / suffixes - it's much smarter on the prefix side.
This fits very well the GKE naming scheme - though some community members (e.g. @mimowo) have earlier raised that ideally we should be possibly vendor-agnostic.

Now, treating prefixes & suffixes in your smart way _at the same time_ would be terribly complex, so let's not do this.
OTOH, in our earlier experimenting, we typically _force-symmetrized_ every approach, as follows:

1. Run the proposed algorithm A (like your new one) on the input.
2. Run the _mirrored version_ of A on the input.
   (Where the _semantics_ are like this: reverse all strings in the input, run A on them, reverse all strings in the result. Of course, also swap `prefixes` with `suffixes` in that output).
   But these are only the _semantics_. Doing this way is surprisingly slow; even reversing a large array of strings is a noticeable bottleneck.
   So, it can be noticeably faster to manually write "A mirrored" as separate piece of code.
   I mean, even that will be noticeably slower than A, because of some "string index dance" that results, which I guess confuses CPU optimizers etc. But it should be faster than "happy mirroring" as described above).
3. Compare results of both variants, pick the smaller one.

Of course, for GKE alone, A non-mirrored will almost always win.

---

Now, we're not sure if it makes sense to submit this PR in this symmetrized way. Possibly not.

Our only request would be if you could quickly & draftly mirror your A (either "happily" or more "manually") and check how it looks in benchmarks.
So that we get the knowledge "if any customer comes and complains about asymmetry, are we going to kill Kueue's performance by taking your A and symmetrizing it according to that request".

Does this request make sense to you?
(I imagine it could cost up to a few hours of work, so feel free to challenge if you think it's not worth the effort).
