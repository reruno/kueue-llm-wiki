#### Special notes for your reviewer:
I have changed skills.md slightly to cater to the new workflow.

usually when we are debugging, we have 2 ways of debugging:
1. checking the failed tests, and then checking the function it was testing to try to understand if there is an actual bug (either in the test or the method being tested) ← this helps the agent contextualize the problem and the process.
2. comparing failed run with successful run ← usually this is used as an esclation path if point 1 didnt yield any results (aka, test looks fine, method is doing what it is intended to do…etc)

this usually means the test could be flaky or racey, and its time to compare failed and successful runs to see what happens when the code is run in an actual cluster.
