## Description

#### What type of PR is this?

/kind cleanup
/area multikueue
/area testing

#### What this PR does / why we need it:

Splits the multikueue e2e test suite into two separate suites:

- `baseline` — tests using only core Kubernetes types (Job, Pod, Deployment, StatefulSet). No custom CRDs required.
- `extended` — tests using custom integration CRDs (JobSet, LeaderWorkerSet, AppWrapper, KubeFlow PyTorchJob/MPIJob/TrainJob, RayJob/RayCluster/RayService).

This follows the same model already used by the singlecluster e2e tests.

Two new Makefile targets are added:
- `make test-multikueue-e2e-baseline`
- `make test-multikueue-e2e-extended`

#### Which issue(s) this PR fixes:
Part of  #11603
Fixes #11603

#### Special notes for your reviewer:

- `baseline/suite_test.go` no longer waits for custom CRD operators to be available, which significantly reduces local first-run time.
- `extended/suite_test.go` keeps all operator availability checks unchanged.
- The existing `test-multikueue-e2e-main` target is preserved for backward compatibility.
