#### What this PR does / why we need it:

  Add a KEP proposing automatic `GOMEMLIMIT` tuning for the Kueue controller manager.                                                                                          
                                                                                                                                                                             
  When running inside a container with a memory limit, the Go runtime does not automatically respect the cgroup memory boundary. This can cause OOMKill events when the garbage
   collector is unaware of the container's memory limit.                                                                                                                     
                                                                                                                                                                               
  The KEP proposes a new optional `runtime.memlimitRatio` field (range `[0, 1]`) in the Kueue configuration API (`v1beta2`). When set, the controller manager automatically    
  sets `GOMEMLIMIT` to the specified fraction of the container's cgroup memory limit at startup, with a fallback to total system memory when cgroup detection is unavailable.
  The feature is disabled by default (ratio = 0 or unset) to preserve backward compatibility.

  @kannon92  @rphillips  Thanks for the feedback — fair point.
                                                                                                                                                                                 
    The main motivation for auto-detection was to reduce operational burden in                                                                                                   
    environments where the container memory limit may change over time (e.g.,                                                                                                    
    vertical pod autoscaling, GitOps-managed resource quotas, or multi-cluster                                                                                                   
    deployments with different limits). With the env var approach, operators                                                                                                     
    need to manually keep `GOMEMLIMIT` in sync with the container's memory                                                                                                       
    limit, which is error-prone — setting it too high risks OOMKill, and                                                                                                         
    setting it too low wastes memory or adds GC pressure.                                                                                                                        
                                                                                                                                                                                 
    That said, I understand the concern about taking on a new dependency.                                                                                                        
    Would a hybrid approach be acceptable?                                                                                                                                       
                                                                                                                                                                                 
    - **Helm chart**: Add `GOMEMLIMIT` as an environment variable (covers the                                                                                                    
      common case, zero code change).                                                                                                                                            
    - **Configuration API** (`runtime.memlimitRatio`): Keep as an optional                                                                                                       
      override for environments that need auto-adaptation. This could be                                                                                                         
      implemented without the `automemlimit` library — we'd just need to                                                                                                         
      read `/sys/fs/cgroup/memory.max` (cgroup v2) or the v1 equivalent                                                                                                          
      directly, which is ~30 lines of code.                                                                                                                                      
                                                                                                                                                                                 
    Happy to revise the KEP toward whichever direction the maintainers prefer.
