## Pull request overview

> [!NOTE]
> Copilot was unable to run its full agentic suite in this review.

Refactors the DRA (Dynamic Resource Allocation) `ResourceMapper` from a global singleton to a dependency-injected instance, threading it explicitly through `core.SetupControllers`, the `WorkloadReconciler`, and the DRA helper functions.

**Changes:**
- Removes the global `Mapper()` / `CreateMapperFromConfiguration` singleton and exports `NewResourceMapper`, `PopulateFromConfiguration`, and `Lookup` on `*ResourceMapper`.
- Adds a `draMapper *dra.ResourceMapper` parameter to `core.SetupControllers` and a new `WithDRAMapper` option for `WorkloadReconciler`; DRA helper functions (`GetResourceRequestsForResourceClaimTemplates`, `ResolveExtendedResourceQuota`, `resolveContainerExtendedResources`) now take the mapper as an explicit argument.
- Updates `cmd/kueue/main.go`, all integration test suites, and unit tests to construct/pass the mapper (or `nil` where DRA isn't exercised).

  `r.draMapper` may be `nil` here (e.g., if `WithDRAMapper` was not provided), and the downstream helpers dereference it via `mapper.Lookup(...)`, which will panic with a nil-pointer dereference. Since this DRA processing branch is reachable whenever the relevant feature gates are enabled, this is a real risk for any setup path (including tests) that enables the feature but doesn't construct a mapper. Consider either (a) guarding entry into this branch on `r.draMapper != nil` and logging/erroring clearly otherwise, or (b) defaulting `r.draMapper` to `dra.NewResourceMapper()` in `NewWorkloadReconciler` so the field is always safe to use. Option (b) is more robust and matches the pattern used in `cmd/kueue/main.go`.
