#### Special notes for your reviewer:
* syncAggregateFlavors currently implements support for a single resource flavor. The design was made with possible future expansion of a more granular resource aggregation (based on flavor). **Discussion on the matter will be covered separately as a follow-up in https://github.com/kubernetes-sigs/kueue/issues/11862.**

```release-note
MultiKueue Automation changes:
* when setting up automation, spec.ResourceGroups is now expected to be empty,
* automatically aggregated quota is now collected under "multikueue-aggregated-flavor"; the flavor is automatically generated and maintained; its spec can be specified via MultiKueue Config.

MultiKueue Config changes: 
* renamed QuotaManagement to QuotaManagementMode, 
* added AutomatedQuotaManagementConfig to specify the default aggregated flavor spec.

ClusterQueue changes: 
* added EffectiveResourceGroups status showing effective quota as interpreted by Kueue,
* ClusterQueue AdmissionCheck flavors (onFlavors) can now specify flavors not present in the ResourceGroup when EffectiveResourceQuota is enabled. This should not affect the logic since flavors not set in the ResourceGroups will not be assigned to workloads and thus the ACs will not utilize them.
```
