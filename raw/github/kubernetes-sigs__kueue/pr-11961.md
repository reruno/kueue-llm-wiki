<h2>v0.18.0</h2>
<p>Changes since <code>v0.17.0</code>:</p>
<h2>Actions Required Before Upgrading</h2>
<h3>(No, really, you MUST read this before you upgrade)</h3>
<ul>
<li>
<p><strong>Minor releases:</strong> Review the <code>.0</code> release notes for each new minor version you cross; see: <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.16.0"><code>v0.16.0</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.17.0"><code>v0.17.0</code></a>.</p>
</li>
<li>
<p>AdmissionChecks: Add the alpha <code>RejectUpdatesToCQWithInvalidOnFlavors</code> feature gate (disabled by default) to reject updates to existing ClusterQueues with invalid <code>AdmissionCheckStrategy.OnFlavors</code> references.
when enabling this feature gate, fix any existing invalid <code>OnFlavors</code> references before updating the affected ClusterQueues. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/10384">#10384</a>, <a href="https://github.com/ShaanveerS"><code>@​ShaanveerS</code></a>)</p>
</li>
<li>
<p>If you maintain an in-house integration you will need to modify the code
to pass the k8s client when calling the following functions: RunWithPodSetsInfo, PodSets, PodsReady,
ReclaimablePods. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/11310">#11310</a>, <a href="https://github.com/kaisoz"><code>@​kaisoz</code></a>)</p>
</li>
<li>
<p>Kueue integration webhooks now consistently exclude <code>kube-system</code> and the Kueue
installation namespace. For manifest-based installs this is <code>kueue-system</code>; for Helm
installs this is the Helm release namespace.</p>
</li>
</ul>
<p>Previously, Pod, Deployment, and StatefulSet integrations already excluded these
namespaces, while other workload integrations did not.</p>
<p>If you run Kueue-managed workloads in <code>kube-system</code> or in the namespace
where Kueue is installed, move them to another namespace before upgrading.</p>
<p>If this is not possible, update <code>managedJobsNamespaceSelector</code> and the relevant webhook
<code>namespaceSelector</code>s to include those namespaces. This setup is discouraged, as it may
affect system workloads and disrupt cluster upgrades. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/11192">#11192</a>, <a href="https://github.com/dkaluza"><code>@​dkaluza</code></a>)</p>
<ul>
<li>Observability: Migrate from the old event types <code>core/v1</code> to use <code>events.k8s.io/v1</code>, by replacing the
helper used in controller-runtime.</li>
</ul>
<p>if you compile your own &quot;in house&quot; integration then you need to adjust the code to replace
GetEventRecorderFor to GetEventRecorder when obtaining the event recorder. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/10971">#10971</a>, <a href="https://github.com/vladikkuzn"><code>@​vladikkuzn</code></a>)</p>
<ul>
<li>Observability: Replace the &quot;evicted_workloads_once_total&quot; metric &quot;detailed_reason&quot; label with &quot;underlying_cause&quot; label. This is a consistency fix as all other metrics name the label &quot;underlying_cause&quot;.</li>
</ul>
<p>If you use the &quot;detailed_reason&quot; label for the &quot;evicted_workloads_once_total&quot;, you can migrate to &quot;underlying_cause&quot; label. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/10637">#10637</a>, <a href="https://github.com/vamsikrishna-siddu"><code>@​vamsikrishna-siddu</code></a>)</p>
<ul>
<li>Removed the deprecated <code>--visibility-server-port</code> flag from the Kueue controller manager.</li>
</ul>
<p>If your installation passes <code>--visibility-server-port</code> to the
controller manager, remove the flag before upgrading and set the same port via
Kueue Configuration API in <code>visibilityServer.bindPort</code> instead. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/11309">#11309</a>, <a href="https://github.com/ekam-walia"><code>@​ekam-walia</code></a>)</p>
<h2>Changes by Kind</h2>
<h3>Feature</h3>
<ul>
<li>Add <code>WorkloadPriorityClassDefaulting</code> feature-gate to set a default WorkloadPriorityClass on Jobs if WorkloadPriorityClassLabel is not set and the <code>default</code> WorkloadPriorityClass exists (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/10798">#10798</a>, <a href="https://github.com/atosatto"><code>@​atosatto</code></a>)</li>
<li>Add a new configuration named <code>quotaCheckStrategy</code> to be able to restrict the quota check to only resources which are declared in the <code>ClusterQueue</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/9808">#9808</a>, <a href="https://github.com/MaysaMacedo"><code>@​MaysaMacedo</code></a>)</li>
<li>Add kubectl short names for AdmissionCheck (ac), Cohort (co), MultiKueueCluster (mkc), MultiKueueConfig (mkconf), ProvisioningRequestConfig (prc), Topology (topo), and WorkloadPriorityClass (wpc). (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/11540">#11540</a>, <a href="https://github.com/gyliu513"><code>@​gyliu513</code></a>)</li>
<li>Aggregate Kueue CRD read-only clusterRoles to k8s default view clusterRole (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/10482">#10482</a>, <a href="https://github.com/amy"><code>@​amy</code></a>)</li>

</ul>
