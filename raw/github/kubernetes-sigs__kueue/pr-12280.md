Adjusts the preemption integration test’s expectations around scheduler-generated events, likely to reduce flakiness or reflect updated event behavior.

**Changes:**
- Loosens event assertions from “one per low-priority workload” to “exactly one event”.
- Removes validation of `event.Count == 1`.
- Changes the polling timeout from `util.Timeout` to `util.MediumTimeout`.

  This change significantly weakens the test: previously it asserted one event per low-priority workload (and validated `event.Count == 1`), but now it only asserts a single event exists. Consider restoring the stronger invariant, or (if behavior has changed) updating the event query/predicate to target the specific single event you intend to validate (e.g., filter by reason/message/UID) and still assert `Count` to ensure it’s not a compressed/retried event.
