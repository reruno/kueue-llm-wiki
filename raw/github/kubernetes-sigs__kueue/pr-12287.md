### Comment by [@saschagrunert](https://github.com/saschagrunert) — 2026-06-17T05:33:07Z

The primary artifacts to attest here are the container images on `registry.k8s.io`, not the GitHub release binaries. The official Kubernetes image promotion tooling ([promo-tools/kpromo](https://github.com/kubernetes-sigs/promo-tools)) already handles signing and SLSA provenance attestation during promotion (staging -> registry.k8s.io), so that side is covered.

The gap is **build-time provenance** on the staging images. A couple of options:

1. **goreleaser**: what sig-release uses for artifact builds; has built-in SLSA and cosign support. Could replace the current GCB `make image-push` approach.
2. **cosign attest** added as a step in Kueue's `cloudbuild.yaml` to attest images right after they're pushed to staging.
3. **tejolote** (kubernetes-sigs): designed to wrap Kubernetes CI builds with SLSA provenance generation.

Once build-time attestations exist on the staging images, kpromo will automatically verify them during promotion (phase 3, verify-if-present semantics) before signing and attesting the promoted images.

So the recommended path would be: add provenance generation to the existing GCB build pipeline (option 1 or 2), and rely on kpromo for the promotion-side attestation. No changes needed in test-infra or k8s.io for that.
