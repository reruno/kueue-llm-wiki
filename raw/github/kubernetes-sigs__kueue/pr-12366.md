#### What this PR does / why we need it:

`MultiKueueAllowInsecureKubeconfigs` was deprecated in 0.17 but cannot be removed yet because it was never locked. This PR locks it to the default value (`false`) in 0.19, makes `validateKubeconfig` unconditional, and removes the now-unreachable insecure path and tests.

The gate remains registered as a locked no-op for 0.19 and can be removed in 0.20.

Follow-up to #12289, which moved the documented Kind dev setup to `certificate-authority-data`.
