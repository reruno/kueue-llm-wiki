## Description

#### What type of PR is this?

#### What this PR does / why we need it:

Enables the version dropdown in the Kueue docs site navbar and documents the process for maintaining it on future releases.

**`site/hugo.toml`:**
- Fixes `url_latest_version` (was pointing to the stale `sigs.k8s.io/kueue/docs` redirect; now points to `https://kueue.sigs.k8s.io`)
- Uncomments and populates `[[params.versions]]` with entries for `main`, v0.18, v0.17, and v0.16, each pointing to their respective subdomain (`v0-X.kueue.sigs.k8s.io`). The `main` entry uses the label `"main"` so it never goes stale across releases.

**`RELEASE.md`:**
- Adds a "Versioned docs" section documenting the four steps a release manager must follow when cutting a new minor release: update `hugo.toml` on both the new release branch and main, add a Netlify domain alias for the new branch deploy, and file a DNS CNAME request to kubernetes/k8s.io.

#### Which issue(s) this PR fixes:

Fixes #10781

#### Special notes for your reviewer:

This PR is one of four companion PRs that together enable versioned docs:
- This PR (main): activates the version dropdown, adds release checklist
- #12397 (release-0.18): marks docs as archived, adds version dropdown
- #12398 (release-0.17): marks docs as archived, adds version dropdown
- #12399 (release-0.16): marks docs as archived, adds version dropdown

The version dropdown entries for v0.18/v0.17/v0.16 will 404 until the Netlify domain aliases and DNS CNAMEs for `v0-X.kueue.sigs.k8s.io` are configured (manual infra step, not in this PR).
