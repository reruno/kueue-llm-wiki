- `TestSchedule`

TAS and AFS scheduling tests are left for follow-up PRs since their structures diverge more.

## Walkthrough

Extracts a shared test harness (`scheduleTestCase`, `scheduleTestConfig`, `runScheduleTestCases`) from the inlined per-case execution loop in `TestSchedule`, then migrates `TestScheduleForFairSharing` and `TestScheduleConcurrentAdmission` to use the same helper, removing ~320 lines of duplicated setup and assertion code across three files.

## Changes

**Scheduler test harness extraction**

| Layer / File(s) | Summary |
|---|---|
| **`scheduleTestCase`, `scheduleTestConfig`, and `runScheduleTestCases` helper** <br> `pkg/scheduler/scheduler_test.go` | Introduces `scheduleTestCase` and `scheduleTestConfig` structs and the `runScheduleTestCases` helper that runs each case twice (with `WorkloadRequestUseMergePatch` on/off), constructs the test client with a status-patch interceptor, executes the scheduler under a context timeout, and asserts cache admissions, workload lists, queue/inadmissible dumps, events, and preemption-skip metrics. Updates `TestSchedule` to use `scheduleTestCase` as the map value type and replaces its inline loop with a `runScheduleTestCases` call. |
| **Migrate `TestScheduleConcurrentAdmission` and `TestScheduleForFairSharing`** <br> `pkg/scheduler/scheduler_concurrent_admission_test.go`, `pkg/scheduler/scheduler_fs_test.go` | Updates imports to remove previously-inlined dependencies, switches both tests' `cases` map value type from anonymous structs to `scheduleTestCase`, and replaces each test's inlined scheduling/assertion loop with a single `runScheduleTestCases` call wired to the shared fixtures. |
