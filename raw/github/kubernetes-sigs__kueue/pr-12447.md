### Comment by [@zemin-piao](https://github.com/zemin-piao) — 2026-06-24T20:21:20Z

Thank you @everpeace @kannon92 @mimowo for replying! 

I think from the discussion of https://github.com/kubernetes-sigs/kueue/issues/4106 I can see why you folks have doubt on documenting this approach in the official doc. (e.g. such integration skips what the webhook should do about suspending the pods, adding labels + annotations).

To be clear about my motivation on this PR: I'm not trying to make manual usage of `kueue.x-k8s.io/pod-suspending-parent=pod ` and `kueue.x-k8s.io/managed=true` to be the official way on the kueue <-> spark non operator integration. 

The motivation of having such doc from me is about easily figuring out there is a way to do Kueue <-> spark (without spark operator) integration. For me as a new comer to Kueue, it took me quite some time to figure out how to do it (e.g. reading the source code, trial and error) until I found this thread https://github.com/kubernetes-sigs/kueue/issues/4106#issuecomment-3281251848 to actually make it work. Also there are many other organisations using spark-submit (non operator) way of doing spark on k8s hence there can be many others faced with the same puzzle. Within spark ecosystem, spark operator is optional and `spark-submit` (native spark script creating pods on k8s without an operator) is the spark "native" way of running spark applications. With such doc it can help folks quickly know there is an option of doing it. 

Given your your doubts that this is hacky, I'd like to propose **mentioning that this is not an officially supported way for Kueue <-> spark non operator integration but an option that community has tried and works**. WDYT? Happy to rework the PR so you folks are comfortable with it.
