#### What this PR does / why we need it:
Removes the rejection of device constraints (`matchAttribute`) and device config in `countDevicesPerClass`. These fields don't affect device counts as constraints filter which devices satisfy a request, config is pass-through to drivers. Rejecting them blocks valid workloads like GPU+NIC co-placement via `matchAttribute: resource.kubernetes.io/pcieRoot`.

Fixes #

#### Special notes for your reviewer:
Other rejections (FirstAvailable, AdminAccess, AllocationMode All) are kept. Those have real counting implications. Constraints and config don't. If a constraint is unsatisfiable, the workload holds quota until `PodsReadyTimeout`, same as any other scheduling constraint Kueue doesn't validate. I will work on the pre-admission feasibility via the scheduler-library integration.

## Pull request overview

This PR fixes DRA quota admission behavior so that `ResourceClaimSpec.devices.constraints` (matchAttribute) and `devices.config` are treated as pass-through fields rather than causing workloads to be rejected as unsupported. This aligns quota counting with the fact that these fields don’t change the requested device counts.

**Changes:**
- Removed rejection of device constraints and device config from `countDevicesPerClass`.
- Updated unit tests to expect correct resource counting (instead of field-validation errors) when constraints/config are present.
- Updated DRA integration tests to verify such workloads are admitted and charged quota correctly.
