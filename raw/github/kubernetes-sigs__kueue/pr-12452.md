#### What this PR does / why we need it:

This PR integrates the tracking and propagation of granular diagnostic reasons (encompassing `NoFit` failures, preemption/migration states, inactive queues, pods-readiness blocks, and configuration errors) into the core scheduling loop within scheduler under the `UnadmittedWorkloadsObservability` feature gate.

#### Which issue(s) this PR fixes:
Part of #10852

When the `UnadmittedWorkloadsObservability` feature gate is enabled, workloads that fail to obtain a quota reservation now receive detailed diagnostic reasons in their `QuotaReserved` status condition (such as `WaitingForQuota`, `ExceedsMaxQuota`, `TopologyPlacementFailed`, or `NoMatchingFlavor`) along with an explicit `Admitted: False` condition.
