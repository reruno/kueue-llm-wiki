## Description

#### What type of PR is this?

/kind bug
/area integrations

#### What this PR does / why we need it:

When a Kueue-managed `RayJob` uses `submissionMode: SidecarMode`, KubeRay injects the Ray job submitter as a **container in the head Pod** (rather than as a separate Kubernetes Job, as in `K8sJobMode`).

Kueue only accounted for the submitter in `K8sJobMode`, where it adds a dedicated `submitter` `PodSet`. For `SidecarMode` it added nothing, so the head `PodSet` was under-counted by the submitter's resources — KubeRay's default `500m` CPU / `200Mi` memory (`ray-operator/controllers/ray/common/job.go: GetDefaultSubmitterContainer`). A head Pod that actually runs `head + submitter` could be admitted against quota sized only for `head`, letting a ClusterQueue overcommit. The RayJob webhook does not reject `SidecarMode`, so this path is reachable.

This PR appends the submitter container to the **head** `PodSet` when `SubmissionMode == SidecarMode`, mirroring KubeRay's default submitter resources. KubeRay always uses those defaults for the sidecar submitter and ignores `SubmitterPodTemplate` (`ray-operator/controllers/ray/rayjob_controller.go: getSubmitterContainer`), so the defaults are mirrored rather than `SubmitterPodTemplate`.

#### Which issue(s) this PR fixes:

There is no existing tracked issue for this gap. Happy to file one if reviewers prefer.

#### Special notes for your reviewer:

- `K8sJobMode` behavior is unchanged: the submitter remains a separate `PodSet`. Only `SidecarMode` is affected, where the submitter is part of the head Pod.
- The default submitter resources are now shared via a `defaultSubmitterResources` helper used by both the `K8sJobMode` submitter template and the `SidecarMode` head container.
- `RunWithPodSetsInfo`/`RestorePodSetsInfo` need no change: the `SidecarMode` submitter is part of the head `PodSet` (not a separate one), so the expected `PodSet` count is unchanged.
- Unit test added in `TestPodSets`; a new e2e case (`feature:kuberay`) creates a `SidecarMode` RayJob and asserts the head `PodSet` includes the submitter and that Kueue's accounted resources match the submitter container KubeRay actually injects into the head Pod.

**AI usage disclosure:** This change was developed with the assistance of an AI coding tool (Claude Code). All code and tests were reviewed by the author before submission.

#### Does this PR introduce a user-facing change?

```release-note
RayJob: Fixed a bug where the Ray job submitter container's resources were not counted against quota when `submissionMode: SidecarMode` was used, causing the head PodSet to be under-counted. The head PodSet now includes the submitter sidecar (KubeRay's default `500m` CPU / `200Mi` memory).
```
