## Description

  #### What type of PR is this?

  /kind bug

  #### What this PR does / why we need it:

  `make verify` fails on macOS arm64 at the `verify-skills-lint` target because the container run command uses Linux only SELinux flags, ie: `:Z` volume suffix and label confinement.

This simple change extends the detection block in `Makefile-verify.mk` with two variables:
  - `VOLUME_FLAGS`: empty on macOS, `:Z` on Linux
  - `CONTAINER_SECURITY_OPTS`: `--security-opt label=disable` on macOS, empty on Linux

On Linux the container command expands to exactly what it was before.

  #### Which issue(s) this PR fixes:

See #12469.

  #### Special notes for your reviewer:

  Tested on macOS Darwin arm64 with podman 5.x. 

`make skills-lint` passes with 24 skills scanned, 34 rules run, all checks passed.

### Comment by [@amy](https://github.com/amy) — 2026-06-24T23:34:21Z

Works for me using docker. Here's what my agent said:

```
Why it works for you but fails for rflorenc
The difference isn't macOS vs. Linux — it's Docker vs. Podman, both on macOS.

Your machine uses Docker (/usr/local/bin/docker, daemon v29.3.1). The issue author tested with podman 5.x (stated in the PR). Both run containers inside a Linux VM, but the VMs differ in one critical way:

Docker Desktop's Linux VM does not enforce SELinux. So the :Z volume suffix in [Makefile-verify.mk:166](vscode-webview:///Makefile-verify.mk#L166) is silently ignored, and there's no label confinement to block the container writing to /out. Everything just works — which is exactly what you see.
Podman's VM (Fedora CoreOS) runs with SELinux enforcing. That triggers both failures in the issue
```
