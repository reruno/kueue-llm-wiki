  hi @mimowo 
  
  The PR I submitted removed `MiniJobController`, but that removal relies on `envtest` using a Kubernetes version that includes the upstream fix. **That is why I initially set `ENVTEST_K8S_VERSION` to `1.36.2`.**
  
  After reverting to `1.36`, the CI actually resolved to version `1.36.0`. Consequently, the PR's CI status reflects that the workaround has been removed, yet the test environment is still running the unfixed `1.36.0`. This causes the integration tests to lack both the `MiniJobController` and the `1.36.2` fix; as a result, the API server rejects the attempt to unsuspend the Job because the `spec.template` is being modified.
  
  and, I agree that the `envtest` minor version should align with the Kubernetes dependency in `go.mod`, so using 1.36 is reasonable.
  
  So, in that case, my understanding is that this cleanup should be deferred until `setup-envtest` in the CI actually selects a version that includes the Kubernetes fix.
