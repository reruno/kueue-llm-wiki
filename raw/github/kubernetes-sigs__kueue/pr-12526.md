<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/cert-manager/cert-manager/releases">github.com/cert-manager/cert-manager's releases</a>.</em></p>
<blockquote>
<h2>v1.20.3</h2>
<p>cert-manager is the easiest way to automatically manage certificates in Kubernetes and OpenShift clusters.</p>
<p>This patch release fixes a security issue (<a href="https://github.com/cert-manager/cert-manager/security/advisories/GHSA-8rvj-mm4h-c258"><code>GHSA-8rvj-mm4h-c258</code></a>, HIGH) where the default <code>cert-manager-edit</code> aggregate ClusterRole granted namespace users permission to create ACME <code>Challenge</code> and <code>Order</code> resources directly. A user who could create a <code>Challenge</code> referencing a <code>ClusterIssuer</code> could supply attacker-controlled solver configuration while cert-manager loaded credentials from the <code>ClusterIssuer</code>'s namespace, bypassing Issuer solver selectors (<code>dnsZones</code>, <code>dnsNames</code>, <code>matchLabels</code>). With the acme-dns provider specifically, this could disclose DNS credentials to an attacker-controlled endpoint.</p>
<p>This release also removes the issuer owner reference from Challenges which was blocking Challenge garbage collection, and updates Go to fix reported CVEs.</p>
<p>All users should upgrade.</p>
<blockquote>
<p>[!WARNING]
<strong>Potentially breaking change:</strong> The <code>cert-manager-edit</code> aggregate ClusterRole no longer grants <code>create</code> for <code>challenges.acme.cert-manager.io</code> or <code>create</code>, <code>patch</code>, <code>update</code> for <code>orders.acme.cert-manager.io</code>. These resources are internal to cert-manager's ACME workflow and are not intended to be created or modified directly by users. If you have tooling or workflows that create Challenge or Order resources directly (outside of the normal Certificate → CertificateRequest → Order → Challenge flow), you will need to grant those permissions explicitly.</p>
</blockquote>
