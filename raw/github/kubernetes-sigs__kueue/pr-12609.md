## Description

Synchronize waitForPodsReady integration tests with the Job controller before marking Jobs active. Kubernetes 1.36 rejects PodTemplate changes after status.active becomes nonzero, so the race caused repeated immutable field errors while the tests still passed

#### What this PR does / why we need it:

Kubernetes 1.36 only permits scheduling directive updates while a suspended
Job has no active pods. Several `waitForPodsReady` integration tests marked Jobs
active before Kueue had finished unsuspending them, causing `startJob` to
repeatedly attempt an immutable PodTemplate update even though the tests passed.

Wait for each Job to become unsuspended before simulating active and ready
status. This matches the real Job lifecycle and removes the hidden
reconciliation errors without changing controller behavior.
