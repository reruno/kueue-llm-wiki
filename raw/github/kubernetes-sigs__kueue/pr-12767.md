**Confirm 12m threshold is backed by historical build-time data.**

Tightening `second_longest` from 18m to 12m is a meaningful (33%) reduction. Per the upstream contract, this stat is skipped only when a job has fewer than the min-sample count, and any exceedance flips the CI exit code to non-zero. If any presubmit's second-longest runtime commonly falls between 12m and 18m, this will introduce new, potentially flaky CI failures.

Worth confirming against actual `prow_runtimes.py` historical output before merging that all currently tracked jobs consistently report `second_longest_seconds` under 12m.
