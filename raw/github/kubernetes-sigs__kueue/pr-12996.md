## Description

## Summary

Implements KEP-9876 cross-ClusterQueue preemption protection (upstream KEP: kubernetes-sigs/kueue#12791), replacing the earlier within-CQ variant on this branch (reverted — it protected a preemption path our production config never exercises).

New Configuration API (v1beta2, gated by `PreemptionProtection`, alpha, default off):

```yaml
preemptionProtection:
  fairSharing:
    minAdmitDuration: 1h    # protects InCohortFairSharing victims
  reclaimWithinCohort:
    minAdmitDuration: 10m   # protects InCohortReclamation / InCohortReclaimWhileBorrowing victims
```

A workload whose `Admitted` condition is younger than the applicable duration is skipped as a cross-CQ preemption victim (within-CQ preemption unaffected). Timing from `Admitted` (not `QuotaReserved`); already-evicted candidates never protected; protection is evaluated after policy/strategy checks so it is always the sole blocker. Includes `CanAlwaysReclaim` capacity-reservation accounting and a timer-based retry when protection windows expire (no cluster event otherwise re-queues the blocked preemptor).

## Testing

- Unit: protection window matrix (boundary, gate off, evicted, Admitted-missing), both preemption paths, oracle consistency, `CanAlwaysReclaim`, retry timer, config validation
- Integration (`test/integration/singlecluster/scheduler/preemptionprotection/`, 8 scenarios): FS + classical protection/expiry, reclaim-while-borrowing, rule independence, two-phase admission (timing from `Admitted`), retry-after-expiry with zero external events, capacity reservation
- End-to-end (WayveCode #116655, production-shaped cohort/CQ/priority config): fails against `0.17.3-phoenix-v1.0` (borrower evicted, `reason=InCohortReclamation`), **passes against the image built from this branch** (`pp-dev-michael-40c73a46`)

## Rollout notes

- Ship the controller image **before** adding `preemptionProtection` to helm values — older controllers strict-reject the unknown field and CrashLoop
- Post-0.17 builds require `TASProfileMixed=false` when `TopologyAwareScheduling=false` (new gate-dependency validation)
- Production delivery: backport these commits onto a `release/0.17.3-phoenix-v2` branch (this PR targets main)

The previous within-ClusterQueue protection API on ClusterQueue is removed.
