## Description

#### What type of PR is this?

/kind feature
/kind api-change

#### What this PR does / why we need it:

Introduces the `.scheduling.quotaReleaseStrategy` field to the Kueue
Configuration API (both `v1beta1` and `v1beta2`). This is the API foundation
for KEP-6143, which standardizes quota release behaviour across all
integrations to fix the TAS capacity accounting gap described in #10076.

Two strategies are defined:
- `OnTermination` (default): releases quota as soon as pods receive a
  `deletionTimestamp`. Preserves existing `batch/v1` Job integration behaviour.
- `OnTerminalBestEffort`: holds quota until pods fully reach a terminal
  phase (`Succeeded`/`Failed`). Required for TopologyAwareScheduling to prevent
  scheduling failures caused by new pods being assigned to nodes still
  physically occupied by terminating pods.

This PR adds the API types, defaults, and generated deep copy / conversion
functions only. Reconciler wiring and integration updates follow in subsequent
PRs.

#### Which issue(s) this PR fixes:

Part of #13163

#### Special notes for your reviewer:

This is the first PR in a series implementing KEP-6143. It is intentionally
scoped to the API schema only so each change can be reviewed independently.
The full implementation series is tracked on the KEP PR (#13163).

#### Does this PR introduce a user-facing change?

```release-note
Add `scheduling.quotaReleaseStrategy` to the Kueue Configuration API.
Administrators can set this field to `OnTermination` (default, releases quota
when pods begin terminating) or `OnTerminalBestEffort` (holds quota until pods
fully terminate, required for TopologyAwareScheduling).
```
