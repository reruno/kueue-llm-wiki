#### What this PR does / why we need it:
This PR cleans up the release automation scripts in `.github/workflows/release-utils.yml`. It removes the verbose `**Error details:**` sections (which often dumped unhelpful or redundant bash standard errors directly into issue comments) because the underlying GH Action workflows now provide direct links to the execution logs (as introduced in #13390). This prevents issue comment spam and focuses developers on the actual workflow logs.

### Comment by [@Singularity23x0](https://github.com/Singularity23x0) — 2026-07-24T11:39:11Z

Instead of redirecting the outputs into a file and then performing `cat` we could simply allow the command outputs to be logged in full.

### Comment by [@Vaishnav88sk](https://github.com/Vaishnav88sk) — 2026-07-24T17:15:05Z

> Instead of redirecting the outputs into a file and then performing `cat` we could simply allow the command outputs to be logged in full.

The goal of the original issue (#13397) is to reduce log clutter during successful runs. If we allow the commands to log in full, it will continue to spam the CI logs even when they succeed. Redirecting to a file and `cat`ting it only on failure ensures we keep the logs clean for successful executions while preserving debuggability when something actually breaks.
