#### What this PR does / why we need it:

**Experimental validation only: do not merge.**

This PR is a validation companion to #13496. It contains the same deep-admission implementation, with `FairSharingLookAhead` enabled by default so that the existing unit, integration, and e2e suites exercise the new scheduler path without individual opt-in.

The goals are to:

- catch regressions or unexpected interactions in tests unrelated to deep admission;
- identify tests that rely on the legacy depth-one behavior without requiring it.

Locally, `go test ./pkg/...` with the gate enabled surfaces one failure:

- `TestScheduleForAFS/admits one workload from each localqueue when quota is limited`

This appears to be a genuine interaction between deep admission and `UsageBasedAdmissionFairSharing`, rather than a test artifact. I will follow up with the analysis once CI reports the full picture.

The single experimental commit flips the gate's default to `true`. It also moves the gate from Alpha to Beta because `make generate-featuregates` rejects a default-on Alpha gate:

The commit then regenerates the two versioned feature lists accordingly.
