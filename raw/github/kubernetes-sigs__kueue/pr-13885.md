#### What this PR does / why we need it:

`Manager.Heads` pops one head from each active ClusterQueue, together with all ready second-pass workloads, before building the scheduling snapshot. If `cache.Snapshot()` fails, the cycle currently returns without restoring them, leaving those workloads out of scheduling until another event requeues them.

This PR restores them on the error path:

- regular heads are requeued with SnapshotFailed;
- second-pass workloads return through the existing retry and backoff path.

The inflight cleanup happens in `Manager.RequeueWorkload`, before info.Update clears the source ClusterQueue. This also fixes the existing `requeueAndUpdate` path and LocalQueue retargeting, where the previous ClusterQueue could continue counting the workload as pending.

The tests cover regular head recovery through a failing cycle, the second-pass requeue and its retry iteration directly, and the affected `RequeueWorkload` paths.

#### Special notes for your reviewer:

Split out of #13729, which touches the same path.

Restoring regular heads means a persistent snapshot failure can now cause a tight retry loop, since they are requeued immediately and the scheduling-cycle slowdown is capped at 10ms. A dedicated backoff for repeated snapshot failures is left for a follow-up.
