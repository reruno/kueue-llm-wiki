#### What this PR does / why we need it?

Adds a MultiKueue performance benchmark using one manager and three worker `envtest` control planes. It measures admission throughput and latency, quota-reservation latency, worker distribution, and watch gaps.

The baseline runs 1,000 Workloads with 1,000 QPS/burst for local clients and each worker cluster. It uses the worker-client configuration support already merged in #15280 and the updated defaults from #15206. Reports record the shared per-worker request-budget scope, so the checker rejects results from the earlier per-Kind limiter configuration.

`make test-performance-multikueue` runs the tests and baseline, then checks provisional performance ranges.

Part of #8564

#### Useful notes for your reviewer

Rebased onto main and removed the abandoned #15097 dependency commits. The remaining diff contains only the benchmark, documentation, and Make targets. The runner requires the default-enabled `MultiKueueReuseClientConnectionConfigForWorkers` feature gate.

Validation: runner/checker race tests, `go vet`, golangci-lint, formatting, and the full Make target passed. Five local calibration runs with Kubernetes 1.36.2 envtest on macOS arm64 admitted all 1,000 Workloads at 97.00–102.42 Workloads/s; four had zero watch gaps and one had a single gap. The README records the measurements and provisional thresholds.

A dedicated CI periodic and calibration on its worker remain follow-up work before enabling alerts. These local envtest measurements do not establish production or GPU workload performance.

AI tools were used to assist with implementation and review. The final diff was manually reviewed and validated.
