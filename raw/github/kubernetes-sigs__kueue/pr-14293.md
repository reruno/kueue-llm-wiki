### Comment by [@thc1006](https://github.com/thc1006) — 2026-08-12T10:25:26Z

The red checks here are the change itself rather than a flake. `apimeta` is not in this file's import block, so `verify-main` and `test-integration-shard-1-main` both stop at

```
test/integration/singlecluster/webhook/core/workload_test.go:600:5: undefined: apimeta (typecheck)
```

Adding `apimeta "k8s.io/apimachinery/pkg/api/meta"` is all it needs.

On the fix itself, `SetStatusCondition` does close the hole. The callback reuses `wl` across polls, and an empty `status.conditions` is omitted from the response, so the `Get` does not clear what the previous poll appended. A second attempt was therefore sending two `QuotaReserved` conditions and could never get back the Forbidden it was waiting for, which is why one unlucky first response turned into a hard failure rather than a retry.

The tests just below this one avoid that by declaring the object inside the closure instead, `var newWL kueue.Workload` at line 621 and again at 1089, 1130 and 1201. That covers the whole class rather than this one field, and would leave the two adjacent cases reading the same way. Both work, so it is entirely your call which you prefer.
