## Description

Cherry pick of #14200 on release-0.18, requested by @sohankunkerkar. The bot could not apply it on either release branch.

The branch carries the same shape the fix addresses: the quota key was resolved before each original extended resource name had been totalled, so two names that a `deviceClassMappings` entry sends to one key could collapse into each other's contribution. The tests come across with the change, and reverting the per-name aggregation on this branch turns them red, the same way it does on main.

Not a clean pick, so the differences are worth naming. This branch predates parts of 0.19, and three things differ from the merged commit:

- `keps/2941-DRA/README.md` is left out, as it was for #14152, which brought #14044 to this branch with the two Go files and no KEP.
- `resolveQuotaKey` keeps this branch's singular `mapper.getCounterConfig(...) != nil` rather than the plural accessor.
- The `KueueDRAIntegrationConsumableCapacity` branch is dropped. Neither the feature gate nor `getCapacityConfigs` nor `pkg/dra/capacity.go` exists here, so there is nothing for it to call.

The pick also carried the `erCache` nil guard along with it. That belongs to #13720 rather than to this change, so it is reverted here.

Nothing else differs. Diffed against the merged commit, those are the only changes, and `pkg/dra/extended_resources_test.go` is byte identical to it.

Verified on the branch rather than assumed. Applying only the new test file to this branch, without the production change, fails two cases: `two extended resource names sharing a quota key are not collapsed by cross-container aggregation` and `workload with per-container integer quantities that overflow int64 when summed`. release-0.19 fails only the first, so this branch carries both. With the change in place `go build ./...` and `go test ./pkg/dra/...` pass.

#### Does this PR introduce a user-facing change?

```release-note
DRA: Fixed quota undercount when two extended resource names sharing a deviceClassMappings key were requested by different containers in the same PodSet.
```
