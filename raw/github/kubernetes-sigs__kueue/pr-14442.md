#### What this PR does / why we need it?

When `clientConnection.qps` is zero or more, `cmd/kueue/main.go` builds one client-go token bucket from `qps` and `burst`, and the REST client waits on it before every request except watches:

```go
if *cfg.ClientConnection.QPS >= 0.0 {
    kubeConfig.RateLimiter = flowcontrol.NewTokenBucketRateLimiter(
        *cfg.ClientConnection.QPS,
        int(*cfg.ClientConnection.Burst),
    )
}
```

Nothing validated the two values. With `burst: 0`, every wait fails at once with `rate: Wait(n=1) exceeds limiter's burst 0`, so every request the manager's client sends, other than a watch, fails. With `qps: 0` and a positive `burst`, the first `burst` requests go through and the bucket never refills. Later requests fail with `would exceed context deadline` when the context has a deadline, and block until it is canceled when it has none. A negative `qps` turns client-side rate limiting off, and that stays allowed.

Both fields are pointers defaulted with `cmp.Or`, so an explicit `0` survives defaulting and reaches the limiter.

`validateClientConnection` now rejects `qps: 0`, and a `burst` of 0 or less unless a negative `qps` has turned the limiter off. It runs after defaulting, so omitted values keep their `1000`/`1000` defaults. The `qps` and `burst` godoc now says this, `clientConnection`, `qps` and `burst` get the `+optional` markers they were missing, and the regenerated v1beta2 reference no longer lists them as required.

No issue was filed for this. Before #2462, Kueue passed `qps` and `burst` to client-go, which replaces a zero with its own defaults. Since #2462 Kueue builds one shared token bucket itself, so a zero reaches the bucket as it is.

#### Useful notes for your reviewer

The client-go behaviour above was checked against `k8s.io/client-go/util/flowcontrol`: `NewTokenBucketRateLimiter(300, 0).Wait(ctx)` returns `exceeds limiter's burst 0`, and `NewTokenBucketRateLimiter(0, 3)` lets three `Wait` calls through and then behaves as described above.

The new `TestValidate` rows reach the rule through the exported `Validate`. A nil `burst` is ignored on purpose, since the defaulter fills it before `Validate` runs, and the v1beta2 defaults test pins that an explicit zero is kept. There is no integration case: the manager validates its configuration before any controller starts, and no integration suite goes through that path.

Other defaulted sections, such as `namespace` and `integrations`, are still listed as required in the reference. That is older than this change and left alone.
