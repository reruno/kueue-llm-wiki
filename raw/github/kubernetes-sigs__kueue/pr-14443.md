#### What this PR does / why we need it?

Nomination computes every TAS assignment against the snapshot taken when the scheduling cycle starts. Before it admits a Workload, the scheduler calls `TASFlavorSnapshot.Fits` to make sure the assignment still holds after the Workloads admitted earlier in the cycle. That check disagreed with the assignment in two ways.

It ignored Pod slots. The assignment counts one Pod slot for every Pod, but `Fits` only looked at what the Pod spec requests, so a node with no slot left still had room. For the same reason, a PodSet whose Pods request nothing could never pass it, so a ClusterQueue with a `pods` quota never admitted one.

It also measured each PodSet on its own. When two PodSets of one Workload landed in the same domain, each was compared with the full remaining capacity, as if the other were not there.

`Fits` now adds the Pod slot to every Pod and takes what each PodSet uses away from its domain before it looks at the next one. With `TASNodeFeasibilityForAllLevels` and no hostname level, this happens at the declared domain, and each PodSet is still checked against the domain's nodes on its own, because the assignment does not publish which nodes it picked.

Fixes #14437

#### Useful notes for your reviewer

Two new `TestScheduleForTASCohorts` cases run one scheduling cycle with two ClusterQueues. In the first, two Workloads are nominated onto a node with a single Pod slot. In the second, a Workload's two PodSets are nominated onto one node, and another Workload is admitted there first. A new `TestScheduleForTAS` case admits a PodSet whose Pods request nothing, in a ClusterQueue with a `pods` quota. All three fail on main.

This waited for #16625, which is now merged. Before it, with `KueueDRADeviceFeasibility`, the assignment did not count a device that a node publishes when it recorded the usage between PodSets, so it could put two PodSets on a node with one device, and the check as changed here would then have rejected the Workload in every cycle.

A node without a `pods` allocatable now fits nothing in this check, the same as in the assignment. The check still runs once per flavor, so PodSets that meet on one node through two different flavors are still measured separately.

_Disclosure: I used an AI coding assistant while preparing this PR. I reviewed and tested the change myself._
