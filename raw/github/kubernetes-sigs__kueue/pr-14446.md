## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

`TruncateAssignment` in `pkg/util/tas/tas_assignment.go` handles `ta == nil` and `newCount <= 0` in one branch, and that branch returns `&TopologyAssignment{Levels: ta.Levels}`, so a nil assignment panics in the check meant to catch it. The check is now split: a nil assignment returns nil, and `newCount <= 0` behaves as before.

The only caller outside tests, `handleScaleDown`, runs after `handleElasticWorkload` has returned early on a nil `PreviousAssignment`, so nothing reaches this path today.

#### Useful notes for your reviewer

The new `TestTruncateAssignment` case panics without the fix and passes with it.
