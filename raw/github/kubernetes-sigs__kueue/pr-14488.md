## Description

#### What type of PR is this?

/kind cleanup
/area observability

#### What this PR does / why we need it:

`kueue_pod_scheduling_gate_removal_seconds` was the only metric in the health metricsdoc group without the `replica_role` label, so observations from a leader, a follower, and a standalone replica were indistinguishable — unlike `WorkloadCreationLatency`, declared immediately above it in the same group.

This adds the label to the vector and its `+metricsdoc:labels=` annotation, threads the `RoleTracker` through the shared recording helper and all three emit paths (pod controller via a new `WithRoleTracker` PodOption; TAS topology ungater and elastic job ungater, which already carried a tracker), derives the value with the existing `roletracker.GetRole` helper (`standalone` when the tracker is nil), updates the test helper and unit tests, adds a role-threading unit test for the recording helper, and regenerates the metrics reference.

#### Which issue(s) this PR fixes:

Fixes #14457

#### Special notes for your reviewer:

- The label is placed before the configured ClusterQueue custom labels, matching every other role-labeled metric in `pkg/metrics/metrics.go`.
- The missing ClusterQueue custom-label values on this metric's record path are intentionally not addressed here — that is #14419, filed separately.
- Adding a label changes the series identity for existing queries on this metric; flagged in the issue as an accepted consequence of restoring parity with the rest of the health group.

#### Does this PR introduce a user-facing change?

```release-note
Observability: Fixed a bug where the `kueue_pod_scheduling_gate_removal_seconds` metric was missing the `replica_role` label (`leader`, `follower`, or `standalone`) carried by the other Kueue metrics.
```
