## Description

Documents which provisioningClassNames are verified-safe to combine with elastic Job scale-up/scale-down (queued-provisioning.gke.io, best-effort-atomic-scale-up.autoscaling.x-k8s.io, check-capacity.autoscaling.x-k8s.io) vs. out of scope, and the per-pod vs. per-template lifetime rule for ProvisioningRequest identity annotations that keeps elastic job templates free of stale per-request identity.

Raised during review of #14316.

Fixes #14615

#### What type of PR is this?

/kind kep

#### What this PR does / why we need it:

Adds a KEP formalizing two constraints for combining elastic Jobs `ElasticJobsViaWorkloadSlices` with Kueue's `ProvisioningRequest` admission-check integration, both raised during review of #14316:

1. A scope table of which `provisioningClassName`s have been verified against the elastic-job code path `queued-provisioning.gke.io`, `best-effort-atomic-scale-up.autoscaling.x-k8s.io`, `check-capacity.autoscaling.x-k8s.io` vs. which are explicitly out of scope/unverified today (TPU multi-host queued provisioning, non-GKE queued/reservation classes, elastic + MultiKueue, concurrent overlapping scale-ups).
2. The per-pod vs. per-template lifetime rule for `consume-provisioning-request` / `provisioning-class-name` annotations, which keeps the long-lived elastic job template free of stale per-request identity so GKE's nodeSelector-injection behavior for `queued-provisioning.gke.io` stays correctly scoped across every scale-up.

This documents existing, already-shipped behavior (implemented in #14316); it introduces no new API surface.

#### Which issue(s) this PR fixes:

Fixes #14615

#### Special notes for your reviewer:

This was requested by @yaroslava-serdiuk during review of #14316, specifically the concern that a pod admitted without the correct `consume-provisioning-request` annotation won't get GKE's nodeSelector injected and could schedule onto arbitrary capacity. The scope table and per-pod/per-template rule here were verified with a live end-to-end repro (real `queued-provisioning.gke.io` request against a GPU node), not just from code inspection.
