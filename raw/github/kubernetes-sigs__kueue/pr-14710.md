<blockquote>
<h2>v0.19.1</h2>
<p>Changes since <code>v0.19.0</code>:</p>
<h2>Actions Required Before Upgrading</h2>
<h3>(No, really, you MUST read this before you upgrade)</h3>
<ul>
<li>
<p><strong>Minor releases:</strong> Review the <code>.0</code> release notes for each new minor version you cross; see: <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.18.0"><code>v0.18.0</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.0"><code>v0.19.0</code></a>.</p>
</li>
<li>
<p>LeaderWorkerSet: Fixed a quota bypass where raising <code>spec.leaderWorkerTemplate.size</code> on an already-admitted, Kueue-managed LeaderWorkerSet ran more pods per group than the reserved quota covered. <code>spec.leaderWorkerTemplate.size</code> is now immutable while the LeaderWorkerSet is managed by Kueue, behind the new <code>LWSImmutableGroupSize</code> feature gate (Beta, enabled by default). <code>spec.replicas</code> stays mutable.</p>
<p>If you change <code>spec.leaderWorkerTemplate.size</code> on a Kueue-managed LeaderWorkerSet, recreate it at the new size instead, or disable the <code>LWSImmutableGroupSize</code> feature gate to keep the previous behavior, which also restores the quota bypass. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13809">#13809</a>, <a href="https://github.com/ivnovakov"><code>@​ivnovakov</code></a>)</p>
</li>
<li>
<p>TAS: Enforce stricter slice-size validation for Workloads. When podSetSliceRequiredTopology is specified, podSetSliceSize must also be specified and must be greater than 0. Non-positive slice sizes in topology constraints are also rejected.</p>
</li>
</ul>
<p>If you create Workload objects directly (or via custom controllers), update manifests before upgrade so that:</p>
<ul>
<li>podSetSliceRequiredTopology is never set without podSetSliceSize</li>
<li>podSetSliceSize is always greater than 0</li>
<li>podSetSliceSize is not set when podSetSliceRequiredTopology is absent</li>
<li>every podsetSliceRequiredTopologyConstraints entry has size greater than 0</li>
</ul>
<p>If you need a phased rollout, temporarily disable TASValidateWorkloadSliceSize, clean up invalid Workloads, then re-enable it. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13737">#13737</a>, <a href="https://github.com/mszadkow"><code>@​mszadkow</code></a>)</p>
<ul>
<li>TAS: Fix a bug where TASRecomputeAssignmentWithinSchedulingCycle can be enabled even if TopologyAwareScheduling is disabled.</li>
</ul>
<p>If you disable TopologyAwareScheduling, also set TASRecomputeAssignmentWithinSchedulingCycle=false before upgrading. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14257">#14257</a>, <a href="https://github.com/tenzen-y"><code>@​tenzen-y</code></a>)</p>
<h2>Changes by Kind</h2>
<h3>Feature</h3>
<ul>
<li>Helm: the controller-manager Deployment now supports optional <code>controllerManager.strategy</code>, <code>controllerManager.hostNetwork</code>, and <code>controllerManager.dnsPolicy</code> values. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13825">#13825</a>, <a href="https://github.com/dinhxuanvu"><code>@​dinhxuanvu</code></a>)</li>
<li>MultiKueue: Forwarded in-place <code>serveConfigV2</code> (Ray Serve application config) updates on a <code>RayService</code> from the manager to the worker cluster, so editing the Serve config on the manager now takes effect on the worker promptly. Changes to <code>rayClusterConfig</code>/<code>upgradeStrategy</code> (zero-downtime upgrade) are not yet propagated. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14036">#14036</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
</ul>
<h3>Bug or Regression</h3>
<ul>
<li>AFS: Fixed a bug that could modify cached Workload data while calculating LocalQueue fair-sharing usage, potentially producing inconsistent scheduling snapshots. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13568">#13568</a>, <a href="https://github.com/aburan28"><code>@​aburan28</code></a>)</li>
<li>AFS: Fixed a bug where a LocalQueue with <code>fairSharing.weight: 0</code> could be prioritized for admission instead of deprioritized when AdmissionFairSharing is enabled. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13559">#13559</a>, <a href="https://github.com/sumanthd032"><code>@​sumanthd032</code></a>)</li>
<li>AFS: Fixed pending Workload snapshot ordering when a referenced LocalQueue is missing. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13515">#13515</a>, <a href="https://github.com/YQ-Wang"><code>@​YQ-Wang</code></a>)</li>
<li>AdmissionFairSharing: Fixed a bug where resource usage smaller than one milli-unit was truncated to zero before it could accumulate, so with a long <code>usageHalfLifeTime</code> the <code>consumedResources</code> for CPU and extended resources such as GPUs stayed at <code>0</code> permanently and were ignored by fair sharing. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13761">#13761</a>, <a href="https://github.com/Shreesha001"><code>@​Shreesha001</code></a>)</li>
<li>AdmissionFairSharing: Fixed a bug where workloads admitted via AdmissionChecks could keep their entry penalty permanently, inflating LocalQueue fair-sharing usage and deprioritizing later workloads. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13795">#13795</a>, <a href="https://github.com/apullo777"><code>@​apullo777</code></a>)</li>
<li>AdmissionFairSharing: Fixed stale fair-sharing usage caused by entry penalties being applied to non-usage-based ClusterQueues or reapplied during second scheduling passes. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13851">#13851</a>, <a href="https://github.com/apullo777"><code>@​apullo777</code></a>)</li>
<li>AdmissionFairSharing: Fixed transient LocalQueue lookup errors causing a pending-Workload snapshot to mix
fair-sharing comparisons with standard queue ordering, resulting in a non-transitive comparator and inconsistent
admission order. When a lookup fails, the entire snapshot now falls back to standard queue ordering. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13546">#13546</a>, <a href="https://github.com/YQ-Wang"><code>@​YQ-Wang</code></a>)</li>
<li>ClusterQueue: Fixed a bug where a terminating ClusterQueue (one with a deletion timestamp still retained by the resource-in-use finalizer because workloads are reserving quota) stopped updating <code>status.pendingWorkloads</code>, <code>status.admittedWorkloads</code>, and <code>status.reservingWorkloads</code> and never set its <code>Active</code> condition to <code>Terminating</code>, leaving stale status. Kueue now keeps the status of a terminating ClusterQueue accurate. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13757">#13757</a>, <a href="https://github.com/kaushik229"><code>@​kaushik229</code></a>)</li>
<li>ConcurrentAdmission: Fix preemption ordering by waiting for more-preferred variants to be evaluated for admission before opening the preemption gate for a less-preferred variant. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14281">#14281</a>, <a href="https://github.com/yuluo-yx"><code>@​yuluo-yx</code></a>)</li>
<li>Corrected invalid PodSet info errors to report the expected and actual PodSet counts in the correct order. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13672">#13672</a>, <a href="https://github.com/cryo-zd"><code>@​cryo-zd</code></a>)</li>
<li>DRA: Fixed DeviceClass validation errors reporting a duplicated request field path with an incorrect request index in counter-based and capacity-based quota paths. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13899">#13899</a>, <a href="https://github.com/cryo-zd"><code>@​cryo-zd</code></a>)</li>
<li>DRA: Fixed a bug where extended resource quota could be charged against a DeviceClass the scheduler would not allocate from when multiple DeviceClasses share the same <code>extendedResourceName</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14124">#14124</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>DRA: Fixed a startup crash when <code>KueueDRAIntegrationPartitionableDevices</code> or <code>KueueDRAIntegrationConsumableCapacity</code> feature gates are enabled but the ResourceSlice API (<code>resource.k8s.io/v1</code>) is not available on the cluster. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13720">#13720</a>, <a href="https://github.com/MaysaMacedo"><code>@​MaysaMacedo</code></a>)</li>
</ul>
