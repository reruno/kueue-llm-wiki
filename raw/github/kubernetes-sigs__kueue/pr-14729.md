### Comment by [@cryo-zd](https://github.com/cryo-zd) — 2026-08-23T16:44:26Z

After tracing the supported elastic workload-slice path more carefully today, I found that I made a mistake before. Currently, batch/v1.Job has one PodSet, and the elastic Ray paths keep the head PodSet at count 1 while resizing worker groups. An already admitted grouped slice should therefore have assignments for both PodSets.

Let me withdraw this guard and the associated tests rather than retain an unproven fix. Sorry for the churn and wasted resources.
