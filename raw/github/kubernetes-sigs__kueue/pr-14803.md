#### What this PR does / why we need it:

Adds the Alpha `multiKueue.objectRetentionPolicies.remoteObjects.afterFinished` setting so completed remote Workloads and mirrored job objects can remain visible on worker clusters for a configured duration.

The existing immediate-cleanup behavior remains unchanged when the field is unset or zero, or when the feature gate is disabled. Retention applies after `Succeeded` or `Failed`; other cleanup paths remain immediate.

If a new run finds an older dedicated mirrored object with the same key, MultiKueue deletes it and retries reconciliation. Shared objects, including elastic slices, Pod groups, and multi-Workload adapters, are excluded from this collision cleanup.

This also adds unit tests, Job and JobSet integration coverage, and documentation.

#### Which issue(s) this PR fixes:

Fixes #13847
