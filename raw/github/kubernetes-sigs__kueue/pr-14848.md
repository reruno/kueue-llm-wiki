#### What this PR does / why we need it:

Stacked on #13885; the last 6 commits are part of this PR.

This is split out of #13729 to prepare the queue layer for fair-sharing refill and keep that PR focused on the refill scheduling logic itself.

Today each ClusterQueue keeps a single inflight workload: the head popped for the current scheduling cycle. That works while the scheduler pops at most one workload per ClusterQueue, but refill can pop additional workloads from the same queue during the cycle.

This PR prepares the queue layer for that:

* Tracks multiple inflight workloads by key and makes their lifecycle explicit: every popped workload must be requeued, deleted, or released.
* Adds the queue APIs refill needs to find and pop another workload during the same scheduling cycle.
* Exposes inflight claims in queue dumps and adds leak checks to the scheduler tests.

The only scheduler change releases the inflight claim for dropped nominations. The mid-cycle pop APIs are only used by #13729
