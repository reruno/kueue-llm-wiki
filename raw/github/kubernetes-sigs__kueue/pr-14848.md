#### What this PR does / why we need it:

A ClusterQueue's `Pop` advances the pop cycle, which consumes requeue signals from the previous scheduling attempt. Fair Sharing refill needs to take another Workload from the same ClusterQueue while an attempt is still running, without consuming those signals. Otherwise a cluster event that lands mid-cycle can stop reaching Workloads popped earlier in that cycle.

This PR adds the queue APIs for that: `PopMidCycle` on the ClusterQueue, plus `PopFrom` and `HasQueuedWorkloads` on the Manager. `Pop` and `PopMidCycle` share one body that differs only in whether it advances the pop cycle. `PopFrom` and `HasQueuedWorkloads` re-check the ClusterQueue status the way `heads()` does, since the scheduling snapshot froze that set at the start of the cycle.

Nothing calls these APIs yet; the caller is the refill loop in #13729. `Pop`'s behavior is unchanged.

The inflight bookkeeping prerequisite was split into #15844 and has merged. What is left here is the mid-cycle pop API that refill needs, which is intended to land with the Fair Sharing Refill KEP (#14605).
