<h2>Changes by Kind</h2>
<h3>Feature</h3>
<ul>
<li>TAS: Reduced CPU time and memory allocations for snapshot creation by reusing cached topology trees when scheduling-relevant Node data is unchanged. Controlled by the <code>TASCacheTopologyTree</code> feature gate, which is Alpha and disabled by default. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14639">#14639</a>, <a href="https://github.com/tenzen-y"><code>@​tenzen-y</code></a>)</li>
<li>WorkloadAwareScheduler: Delegated TAS node readiness and <code>spec.unschedulable</code> checks to the <code>scheduler-library</code> instead of applying them when building the TAS node cache. Controlled by the <code>SchedulerLibraryIntegration</code> feature gate, which is Alpha and disabled by default. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14613">#14613</a>, <a href="https://github.com/alien1403"><code>@​alien1403</code></a>)</li>
</ul>
<h3>Bug or Regression</h3>
<ul>
<li>AFS: Fixed entry-penalty accounting leaks that could inflate LocalQueue fair-sharing usage when a Workload was re-admitted or exited before settlement. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14153">#14153</a>, <a href="https://github.com/apullo777"><code>@​apullo777</code></a>)</li>
<li>DRA: Fixed a bug where a negative extended-resource request quantity (reachable only when the <code>WorkloadValidateResourcesAreNonNegative</code> validation is disabled, or on a Workload created before that validation existed) could be merged as a negative DRA quota charge, silently offsetting a legitimate charge on the same logical resource. Negative extended-resource requests are now dropped the same way zero-valued ones already are. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14655">#14655</a>, <a href="https://github.com/pujitha24"><code>@​pujitha24</code></a>)</li>
<li>DRA: Fixed quota undercount when two extended resource names sharing a deviceClassMappings key were requested by different containers in the same PodSet. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14200">#14200</a>, <a href="https://github.com/pujitha24"><code>@​pujitha24</code></a>)</li>
<li>FairSharing: Collapsed the per-candidate FairSharing preemption log into one entry per ClusterQueue and serialize its DominantResourceShare values, reducing scheduler log volume at verbosity 4. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14348">#14348</a>, <a href="https://github.com/venuchitta"><code>@​venuchitta</code></a>)</li>
<li>FairSharing: skip the FairSharing preemption tournament when the preemptor's dominant resource share is +Inf, since no candidate can be preempted, avoiding wasted per-candidate evaluation and its V(4) log volume. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14671">#14671</a>, <a href="https://github.com/venuchitta"><code>@​venuchitta</code></a>)</li>
<li>Importer: Fixed a bug where the Pod importer picked a single ResourceFlavor for the whole Pod, so Pods whose resources map to different flavors could be imported with a wrong flavor assignment. Flavors are now resolved per requested resource. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14579">#14579</a>, <a href="https://github.com/mszadkow"><code>@​mszadkow</code></a>)</li>
<li>JobFramework: Fixed ancestor resolution to verify that each controller ownerReference's UID matches the referenced object. Previously an object whose ownerReference named a Kueue-managed ancestor with a stale or mismatched UID was treated as managed by that ancestor and was skipped by Kueue (not suspended/gated and no Workload created). (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14658">#14658</a>, <a href="https://github.com/vladikkuzn"><code>@​vladikkuzn</code></a>)</li>
<li>LeaderWorkerSet: Fixed a bug where Pods of a LeaderWorkerSet admitted before the queue-name write moved into the LWS webhook could stay permanently SchedulingGated after an upgrade, eventually deactivating the Workload. Kueue now sets <code>kueue.x-k8s.io/queue-name</code> on LeaderWorkerSet Pods when adopting them and reconciles it on already-adopted gated Pods. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14602">#14602</a>, <a href="https://github.com/anguszzzz"><code>@​anguszzzz</code></a>)</li>
<li>MPIJob: Fixed TAS defaulting for runLauncherAsWorker jobs with missing or additional replica-spec entries, preventing a webhook panic and preserving rank-based topology placement. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14527">#14527</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>MultiKueue: Fixed a bug where a stale <code>status.nominatedClusterNames</code> could cause Server-Side Apply field manager conflicts with external dispatchers. Kueue now clears the field through a MutatingAdmissionPolicy when a Workload is admitted or evicted. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14643">#14643</a>, <a href="https://github.com/vic-comm"><code>@​vic-comm</code></a>)</li>
<li>MultiKueue: Fixed watch establishment to prevent timeouts from blocking indefinitely on delayed watch responses. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14550">#14550</a>, <a href="https://github.com/Dasmat13"><code>@​Dasmat13</code></a>)</li>
<li>Observability: Fixed a bug where the <code>kueue_pod_scheduling_gate_removal_seconds</code> metric was missing the <code>replica_role</code> label (<code>leader</code>, <code>follower</code>, or <code>standalone</code>) carried by the other Kueue metrics. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14488">#14488</a>, <a href="https://github.com/gangadhar-res"><code>@​gangadhar-res</code></a>)</li>
<li>PodGroup integration: Fixed a bug where a Pod could bypass ClusterQueue quota by setting <code>kueue.x-k8s.io/pod-group-name</code> to another Workload's name. Kueue now only adopts Workloads created by the pod-group framework (stamped with <code>kueue.x-k8s.io/is-group-workload</code>), and no longer finalizes a foreign Workload that merely shares the pod group name, which previously marked it Finished and released its quota while its pods were still running. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14630">#14630</a>, <a href="https://github.com/vladikkuzn"><code>@​vladikkuzn</code></a>)</li>
<li>RayJob, RayCluster, RayService, and SparkApplication: Fixed a bug where removing the <code>kueue.x-k8s.io/queue-name</code> label from an unsuspended job was accepted, so the job stopped being managed by Kueue while its pods kept running and its resources were no longer counted against quota. Removing the label is now rejected, both from an unsuspended job and from a suspended job in a namespace with a default LocalQueue. Controlled by the <code>ValidateRayAndSparkJobUpdates</code> feature gate, which is Beta and enabled by default. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14666">#14666</a>, <a href="https://github.com/ivnovakov"><code>@​ivnovakov</code></a>)</li>
<li>Scheduling: Fix preemption thrashing/loops caused by desynchronized eviction completion times by prioritizing preemptor workloads at the head of the scheduling queue. This is guarded by the PrioritizePreemptorWorkloads Alpha feature gate, disabled by default. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14682">#14682</a>, <a href="https://github.com/Nilsachy"><code>@​Nilsachy</code></a>)</li>
<li>TAS: Fixed a bug where cross-flavor TAS usage was matched against topology domains a ResourceFlavor does not hold, adding redundant per-node work and V(3) log lines to every scheduling cycle. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14174">#14174</a>, <a href="https://github.com/venuchitta"><code>@​venuchitta</code></a>)</li>
<li>TAS: Fixed a bug where node replacement treated sibling topology domains with a common string prefix as the same domain. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14452">#14452</a>, <a href="https://github.com/tomsen02"><code>@​tomsen02</code></a>)</li>
<li>TAS: Fixed a bug where replacing an unhealthy node could assign a workload to a node already claimed by another workload in the same scheduling cycle, leaving its pod permanently Unschedulable until the PodsReady timeout evicted it. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14647">#14647</a>, <a href="https://github.com/varunsyal"><code>@​varunsyal</code></a>)</li>
<li>VisibilityOnDemand: Fixed a bug where the <code>PositionInLocalQueue</code> on the ClusterQueue <code>pendingworkloads</code> was being inflated when two LocalQueues in different namespaces share the same name (for example, the auto-created <code>default</code> LocalQueue). (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14435">#14435</a>, <a href="https://github.com/pujitha24"><code>@​pujitha24</code></a>)</li>
<li>VisibilityOnDemand: Fixed a panic in the pending-workloads endpoints when prebuilt Workloads (BYOW) w/o priority are created (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14418">#14418</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>WaitForPodsReady: Fixed a bug where the <code>kueue_ready_wait_time_seconds</code>, <code>kueue_admitted_until_ready_wait_time</code>, <code>kueue_local_queue_ready_wait_time_seconds</code> and <code>kueue_local_queue_admitted_until_ready_wait_time_seconds</code> metrics were emitted after failure recovery, skewing the metric towards longer wait times. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14638">#14638</a>, <a href="https://github.com/kshalot"><code>@​kshalot</code></a>)</li>
</ul>
