#### What this PR does / why we need it:

`validateQualifiedName` (`pkg/config/validation.go`) is a port of upstream
Kubernetes' DRA resource validation. Its `switch` on the number of `/`-separated
parts only handled `len(parts) == 1` and `len(parts) == 2`; a name with more
than one slash (e.g. `"a/b/c"`) matched neither case, so `allErrs` stayed
empty and the value was silently accepted.

The only current caller validates `DeviceClassMapping.Sources[].Capacity.Name`
in Kueue's own `Configuration` file, re-validated fresh on every
controller-manager startup — not a live Kubernetes CRD field with persisted
cluster objects. So the ratcheting concern noted in the original TODO
(avoiding breaking existing non-compliant objects) doesn't apply here:
there's no persisted state to grandfather in, and failing fast on an invalid
config at startup is the correct behavior.

This adds a `default:` case rejecting names with more than one slash, mirroring
the existing `field.Invalid` style used for the empty-domain/empty-name cases
in the same function.

#### Special notes for your reviewer:

`k8s.io/apimachinery`'s declarative-validation utility
(`resourcesQualifiedName` in `staging/.../strfmt.go`) is left to be fixed
upstream separately — this PR only addresses Kueue's local copy.
