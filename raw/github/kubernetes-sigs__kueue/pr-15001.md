#### What this PR does / why we need it:
The manager already logs its gate settings at startup, but a log line is not something one can query or alert on. Checking a live deployment otherwise meant reading the ConfigMap, reading the --feature-gates argument, and working out the defaults by hand for anything neither of them set.

Export one gauge per gate instead, modeled on kubernetes_feature_enabled from component-base: 1 when the gate is enabled, 0 when it is disabled, labeled by name and stage. Disabled gates report 0 rather than being skipped. A gate with no series at all  would imply the binary does not declare that gate, which is a different thing from the gate being off.

Register() seeds the gauge, after the flag and the config file have been merged. Gates cannot change after startup, so one snapshot is enough.

## AI summary

This PR adds the `kueue_feature_enabled` gauge. It reports the state of each Kueue feature gate.

- Each series has a `name` label (gate name) and a `stage` label (`ALPHA`, `BETA`, `DEPRECATED`, or empty for generally available gates).
- The value is `1` when the gate is enabled and `0` when it is disabled. Disabled gates are reported, not omitted.
- `Register()` seeds the gauge after feature-gate flags and configuration are merged. The gauge is reset before each snapshot. It is not tracked for queue or role cleanup.
- `pkg/features/kube_features.go` adds `KueueFeatureGates()`. It returns the resolved specs for gates declared by Kueue. `LogFeatureGates` uses this list.
- Unit tests check that the metric reports all Kueue gates with the correct values. They exclude the `AllAlpha` and `AllBeta` meta gates. A test also checks that `Register` exposes the expected series.
- The Prometheus e2e test queries `kueue_feature_enabled`. It checks the metric name, stage values, and `0`/`1` values. It checks for at least one enabled and one disabled gate.
- The installation guide adds a section named "Check which feature gates are enabled". It includes PromQL examples. It states that the metric is per replica. It states that gate values change only after controller-manager pods restart.
- The generated metrics reference lists `kueue_feature_enabled`.

This change addresses the operator visibility request in `#14991`. It does not add feature-specific behavior for `DisableWaitForPodsReady`.

### Suggested release note

```release-note
Observability: Added the `kueue_feature_enabled` gauge metric. It reports each Kueue feature gate as `1` when enabled or `0` when disabled. The `name` label identifies the gate, and the `stage` label reports its maturity stage.
```
