#### What this PR does / why we need it:
Followup to #14557

Alpha CRDs such as `CapacityProvider` and `DynamicQuotaOrchestrator` are stored in `config/components/crd/alpha/bases/` as opt-in alpha APIs. Previously, the Kueue Helm chart did not provide an opt-in mechanism to conditionally include these alpha CRDs when installing or upgrading via Helm.
This PR introduces the `enableAlphaAPIs` flag in the Kueue Helm chart (as requested in https://github.com/kubernetes-sigs/kueue/pull/14557#discussion_r3912522957):
1. **Values & Docs**: Adds `enableAlphaAPIs: false` to `charts/kueue/values.yaml` and regenerates `charts/kueue/README.md`.
2. **Processing Plan**: Updates `hack/processing-plan.yaml` to process alpha CRD definitions from `./config/components/crd/alpha/bases/*.yaml` and output them into `charts/kueue/templates/crd/` wrapped in `{{- if .Values.enableAlphaAPIs }}` conditionals.
3. **CRD Templates**: Generates Helm CRD templates for `kueue.x-k8s.io_capacityproviders.yaml` and `kueue.x-k8s.io_dynamicquotaorchestrators.yaml` via `make update-helm`.
4. **Unit Tests**: Adds unit tests in `charts/kueue/tests/crd_test.yaml` verifying that:
   - By default (`enableAlphaAPIs: false`), alpha CRDs are not rendered while standard CRDs are rendered.
   - When enabled (`enableAlphaAPIs: true`), both standard and alpha CRDs are rendered.
5. **Verification**: Updates `hack/make/verify.mk` to validate Helm template rendering with `--set enableAlphaAPIs=true`.

Add Helm unit tests in charts/kueue/tests/crd_test.yaml and update Helm verify recipe.
