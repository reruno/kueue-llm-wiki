#### What this PR does / why we need it:
If a job names a `scheduling.k8s.io` `PriorityClass` that doesn't exist, it gets stuck in reconciliation. There's no priority, so no Workload gets created, the job stays suspended and unqueued, and nothing tells the user why. `ExtractPriority` now records a `Warning` event with reason `PriorityClassNotFound` on the object, the same way it already does for `WorkloadPriorityClassNotFound`. Since it's in `ExtractPriority`, every path that does the lookup gets it.

## AI summary

This change makes Kueue report a missing Kubernetes `PriorityClass` to users. Before this change, a suspended Job that named a missing `scheduling.k8s.io` `PriorityClass` gave no event on the Job. Kueue returned only a reconcile error.

- Adds the event reason constant `ReasonPriorityClassNotFound` with value `PriorityClassNotFound` in `pkg/controller/jobframework/events.go`.
- Changes `ExtractPriority` in `pkg/controller/jobframework/reconciler.go`. When a named Kubernetes `PriorityClass` lookup returns NotFound, it emits a `Warning` event with reason `PriorityClassNotFound` and still returns the lookup error. An empty class name emits no event.
- Resolves the class name from the integration-provided priority-class accessor when one exists. Otherwise, it uses the first PodSet template's class name.
- Adds a "Referencing a PriorityClass" section to `site/content/en/docs/concepts/workload_priority_class.md`. It states that the class must exist before Kueue creates the Workload. It also states that the Job remains suspended until then, and that CRDs such as `MPIJob` can name a class that no Pod spec contains.
- Adds unit tests in `workload_priority_test.go` for missing, existing, integration-provided, and forbidden class lookups. It also adds reconciler tests for the Job and MPIJob controllers, and integration tests for Job `PriorityClass` lookup.

### Suggested release note

```release-note
Observability: Kueue now emits a `PriorityClassNotFound` Warning event on a Job, or other workload object, that references a `scheduling.k8s.io` PriorityClass that does not exist. Kueue does not create the Workload until the PriorityClass exists. Previously, the failure was not reported on suspended Jobs.
```
