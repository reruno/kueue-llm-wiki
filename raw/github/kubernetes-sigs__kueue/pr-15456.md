Fixes #15455

With `SchedulerLibraryIntegration` enabled, the WAS simulator builds the pod it hands to the scheduler library from `PodRequirements.PodTemplate`, a plain deep copy of the PodSet template. The TAS snapshot merges `ResourceFlavor.spec.tolerations` and admission-check `PodSetUpdates` into the field form of the requirements only (`Tolerations`, `Selector`), which the default simulator reads and the WAS simulator does not. As a result:

- a workload whose only toleration for a node taint comes from the ResourceFlavor is never admitted.
- a workload with a ProvisioningRequest `nodeSelector` can be placed on a node the selector excludes.

Both behave correctly with the gate disabled.

The fix overwrites the template's `tolerations` and `nodeSelector` with the merged values right after the template is copied, so the pod form carries the same constraints as the field form.

Two gate-on cases are added to `TestScheduleForTAS`, one per symptom. Both fail without the fix and pass with it.

#### Useful notes for your reviewer

Verified locally with the gate default temporarily flipped to `true`: `pkg/scheduler` and `pkg/cache/scheduler` pass, and the full `tas` integration suite passes 132 of 132 once the WAS simulator is wired into that suite. That wiring is part of the item (2) work for #14969 and will follow in a separate PR that depends on this one.
