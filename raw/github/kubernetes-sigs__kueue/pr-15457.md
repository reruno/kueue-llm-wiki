#### What this PR does / why we need it?

Part of #14969 (item 2). Makes tests that fail with `SchedulerLibraryIntegration` enabled pass. Test-only, no product change.

With the gate on, the TAS cache keeps NotReady and unschedulable nodes and relies on the scheduler library to reject them. Several tests paired that gate-on cache with the default simulator, which production never does, so failed nodes stayed feasible.

- **Node-health tests** (`pkg/cache/scheduler`, `tas` and `pod` integration suites): use the WAS simulator when the gate is on, add the `node.kubernetes.io/not-ready` taint as the node lifecycle controller would (new `util.TaintNodeNotReady` helper), add gate-on twins, and pin cases specific to the gate-off path.
- **Residual TAS Pod tests** (#16339): use the WAS simulator too, so `SimulateResidualTASPodRelease` works with the gate on.

Rebased onto main. The earlier `TestReconciler` pins were dropped: the workload annotation is now always set (#15398), and the gate depends on `TopologyAwareScheduling` (#16362).

#### Useful notes for your reviewer

Verified locally:
- Unit tests in `pkg/controller/jobs/job`, `pkg/cache/scheduler` and `pkg/scheduler/...` pass with the gate on and off.
- `tas` and `pod` integration suites: 186/186 and 80/80 with the gate off.

Not addressed here: other integration suites still use the default simulator, and gate-on node replacement depends on the not-ready taint (excluding `status.unhealthyNodes` in `findReplacementAssignment` would remove that dependency).
