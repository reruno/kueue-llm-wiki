  This will be ran on a snapshot, so the candidates we pass here are considered to be valid in the snapshot.
  We also pass the `preemptedWorkloads []WorkloadKey,` parameter, which defines any workloads that are not preempted in the Snapshot, but that have been marked for preemption already by whatever logic happened between creating the Snapshot and running ScheduleSnapshot.
  
  Aside from that - the logic here gets the candidates, assumes they are all valid no matter which are preempted during the processing, excludes ones passed as already preempted, and return the result it calculated.
  The SchedulerLibrary logic does not take into account dynamically changing candidate lists as of this moment to my knowledge. I am also not aware of any plans to do so.
  
  If there are any additional operations we want to do on the result it returns - we will have to build them on top of that (including any reruns of the method with modified params and other tricks we can pull off). If and when we decide to implement those is not decided as of yet.
