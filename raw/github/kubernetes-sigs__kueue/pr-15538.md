## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it?

##### Problem
When `leaderElection.leaderElect` is true, the lease renewal client shares the client-side rate limiter with every controller client. A reconcile burst under a low `clientConnection.qps`/`burst` (for example the startup replay of retained finished Workloads) starves the Lease update past `renewDeadline`, the manager exits with `leader election lost`, and the deployment crash-loops while nothing is admitted.

Root cause: `cmd/kueue/main.go` sets one explicit `kubeConfig.RateLimiter` object so all controller clients share a bucket, and `ctrl.Options.LeaderElectionConfig` is never set. controller-runtime then falls back to `rest.CopyConfig(kubeConfig)` for the lease client (`pkg/manager/manager.go`, `LeaderElectionConfig == nil` branch), and `rest.CopyConfig` copies the `RateLimiter` pointer, so the lease client draws from the same bucket.

##### Fix
When leader election is enabled, `config.SetLeaderElectionConfig(&options, kubeConfig, &cfg)` sets `options.LeaderElectionConfig` to a `rest.CopyConfig` of the manager config with the shared `RateLimiter` dropped, so the lease client builds a token bucket of its own from the configured `clientConnection.qps`/`burst`. Lease renewals are bounded exactly like the controllers but can no longer be starved by them. The leader election loop is paced by `leaderElection.retryPeriod` and sends at most one get and one update per period per replica, so the bucket only comes into play while the API server is unhealthy. A negative `clientConnection.qps` disables client-side throttling for the lease client as it does for the manager. The manager config is left untouched; behaviour with leader election disabled is unchanged.

##### How tested
`TestSetLeaderElectionConfig` in `pkg/config/config_test.go` asserts the lease client gets a distinct `*rest.Config` with no shared `RateLimiter`, the configured QPS/Burst in the normal case and a negative QPS when throttling is disabled. After the fix:
