## Description

#### What type of PR is this?

/kind bug
/area tas

#### What this PR does / why we need it:

A workload replacing a failed node (`status.unhealthyNodes`) that needed preemption skipped topology assignment.
With `TASFailedNodeReplacementFailFast` off it then preempted other workloads and was committed flavors-only, so the
TAS cache stopped counting its Pods and their nodes got double-booked.

Now a failed-node replacement that would need preemption, because its quota or its placement doesn't fit, is NoFit.
It waits in the second pass for free capacity, or is evicted when `TASFailedNodeReplacementFailFast` is on.

This continues #15536 by @CodeBuildder: their commit is cherry-picked onto current main with them as author, and
their tests stay. The commits on top address the review comments left open there:

- A PodSet without a topology assignment no longer gets a fresh placement during a replacement, since that would
  not move Pods that already run. It is left as it is, as on main.
- The scheduler check that refused a TAS PodSet without an assignment is dropped. No known path creates one any
  more, and it would refuse every replacement of a Workload admitted that way.
- The NoFit decision lives in one place, and no unused flavor attempt reasons are recorded.

#### Which issue(s) this PR fixes:

Fixes #15337

#### Special notes for your reviewer:

- Production code: 8 lines in `AssignTopology`. The rule uses `HasTopologyAssignmentWithUnhealthyNode`, as
  `NeedsSecondPass` does, so a Workload with stale `unhealthyNodes` but no admission can still preempt (a test pins it).
- Coverage (`-coverpkg=./...`): 4/4 changed statement lines. With main's `AssignTopology`, the new
  `TestAssignTopology` replacement cases, the `TestScheduleForTAS` "no fit; does not preempt" case and the
  integration spec "stays on the failed node instead of preempting when no node is free" fail.
- Not changed: the whole-group path from #17515 still re-places a group that has no Pods left on healthy nodes,
  including a PodSet without a topology assignment.
- I used an AI coding assistant to help write and test these changes, and reviewed the result.

#### Does this PR introduce a user-facing change?

```release-note
TAS: Fixed a bug where a workload replacing a failed node that needed preemption could preempt other workloads and be admitted without a topology assignment. Such a workload now waits for free capacity, or is evicted when TASFailedNodeReplacementFailFast is enabled.
```
