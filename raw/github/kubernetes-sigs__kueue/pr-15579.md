## Description

#### What type of PR is this?
/kind bug
/area tas

#### What this PR does / why we need it?
An elastic TAS Workload growing from two to four one-CPU Pods on a four-CPU node is classified as requiring preemption, even when nothing else uses the node and quota is sufficient. The topology snapshot already charges the old slice, and elastic placement accounts for that assignment again.

Temporarily remove the replaced slice's TAS usage during placement, then restore the snapshot. Ordinary quota accounting and other workloads' topology usage are unchanged.

#### Useful notes for your reviewer
Reproduced on upstream `main` at `7fc7d417ec4fd8f899d7e51f6c0bc2719b5ebb0c`.

```sh
go test ./pkg/scheduler/flavorassigner -run '^TestElasticTASDoesNotDoubleCountReplacedSlice$' -count=1
```

With only the test added to unpatched `main`, the otherwise-empty node returns `Preempt` instead of `Fit`. With this fix, it returns `Fit`. A second case adds another workload's one-CPU usage and verifies the replacement still doesn't fit. Both cases check that assignment restores the snapshot's free capacity.

The existing scale-up integration test now grows from two to 24 one-CPU Pods across three eight-CPU nodes. This exercises an exact fit through the scheduler and cache; the replacement remains unadmitted on unpatched `main` and is admitted with the fix.

```sh
go test ./test/integration/singlecluster/tas -run TestAPIs \
  -ginkgo.focus='should grow an elastic workload to exactly fill topology capacity' -count=1
```

Validation: flavor assigner, scheduler cache, and scheduler package tests; the elastic/TAS integration group; `go vet` for the affected packages; golangci-lint v2.13.2 on the changed packages; formatting and whitespace checks. Integration tests used envtest Kubernetes 1.36.2. Full `make verify` has not been run.

AI assistance was used for drafting this PR.
