Bumps [github.com/cert-manager/cert-manager](https://github.com/cert-manager/cert-manager) from 1.21.1 to 1.21.2.
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/cert-manager/cert-manager/releases">github.com/cert-manager/cert-manager's releases</a>.</em></p>
<blockquote>
<h2>v1.21.2</h2>
<p>cert-manager is the easiest way to automatically manage certificates in Kubernetes and OpenShift clusters.</p>
<p>v1.21.2 fixes controller and webhook panics, data races, ACME renewal and HTTP-01 solver bugs, and a Gateway API dnsNames bug. It stops the ACME and Vault issuers copying untrusted HTTP response bodies into status conditions and Events, and tightens ambient AWS credential use for namespaced Vault Issuers. It also updates Go and several dependencies to fix reported security vulnerabilities.</p>
<p>All users should upgrade.</p>
<h2>Changes by Kind</h2>
<h3>Bug or Regression</h3>
<ul>
<li>ACME Issuer response bodies are no longer reflected into Issuer status conditions or Kubernetes Events. Only ACME problem documents are surfaced (bounded in length); other responses are reported by HTTP status code alone, with the full error available in the controller logs. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9239">#9239</a>, <a href="https://github.com/FelixPhipps"><code>@​FelixPhipps</code></a>)</li>
<li>Cap ACME server response bodies at 16 MiB to guard against unbounded-body denial-of-service. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9222">#9222</a>, <a href="https://github.com/FelixPhipps"><code>@​FelixPhipps</code></a>)</li>
<li>De-duplicate dnsNames when multiple Gateway/ListenerSet listeners share a Secret (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9234">#9234</a>, <a href="https://github.com/speer"><code>@​speer</code></a>)</li>
<li>Fix certificate renewal windows using February 29 cron schedules across non-leap century years. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9240">#9240</a>, <a href="https://github.com/wieghx"><code>@​wieghx</code></a>)</li>
<li>Fix validating webhook panics when AdmissionReview requests omit optional fields, by routing identity, approval, and resource validation on the always-present Resource/SubResource fields and denying (rather than silently allowing) requests with an unset or mismatched resource. As a side effect, validation is now also enforced for equivalent-converted requests on non-v1 API versions, which previously could skip validation. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9235">#9235</a>, <a href="https://github.com/lunarwhite"><code>@​lunarwhite</code></a>)</li>
<li>Fixed HTTP-01 solver cleanup so that a solver ingress, pod or service that has already been deleted no longer fails the cleanup with a NotFound error. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9278">#9278</a>, <a href="https://github.com/arpitjain099"><code>@​arpitjain099</code></a>)</li>
<li>Fixed a bug where <code>replaces</code> field was being populated for the wrong issuer on issuer changes (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9236">#9236</a>, <a href="https://github.com/hjoshi123"><code>@​hjoshi123</code></a>)</li>
<li>Fixed a data race in the ACME HTTP-01 self-check that could occur when custom DNS servers were configured. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9313">#9313</a>, <a href="https://github.com/shashankvarma499"><code>@​shashankvarma499</code></a>)</li>
<li>Fixed a panic in the certificates-issuing controller when a CertificateRequest has a failure time set but no Ready condition. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9238">#9238</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>Fixed a race in pkg/scheduler where the cleanup of a fired timer could cancel a newer timer scheduled for the same object, silently dropping a rescheduled poll. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9312">#9312</a>, <a href="https://github.com/shashankvarma499"><code>@​shashankvarma499</code></a>)</li>
<li>Fixed an issue where the body of a non-Vault HTTP response from <code>spec.vault.server</code> could be copied into the Vault Issuer's Ready condition and its Kubernetes Events. Such responses now report only the HTTP status code, and Vault's own error messages are truncated before being persisted. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9262">#9262</a>, <a href="https://github.com/FelixPhipps"><code>@​FelixPhipps</code></a>)</li>
<li>Ingress-shim no longer removes the applyset label from cached Ingress and Gateway objects (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9314">#9314</a>, <a href="https://github.com/KR-Ravindra"><code>@​KR-Ravindra</code></a>)</li>
<li>The ACME HTTP-01 self-check no longer reflects the fetched response body in <code>Challenge.status.reason</code>, preventing disclosure of internal response contents reachable via redirects. The response is still available in the controller's debug logs. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9232">#9232</a>, <a href="https://github.com/FelixPhipps"><code>@​FelixPhipps</code></a>)</li>
<li>The <code>vault</code> issuer no longer authenticates to Vault using the cert-manager controller's ambient AWS credentials for AWS IAM auth on a namespaced <code>Issuer</code>, unless ambient credentials are explicitly enabled via <code>--issuer-ambient-credentials</code>. <code>ClusterIssuer</code> and explicit <code>serviceAccountRef</code> (IRSA) configurations are unaffected. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9231">#9231</a>, <a href="https://github.com/FelixPhipps"><code>@​FelixPhipps</code></a>)</li>
</ul>
<h3>Other (Cleanup or Flake)</h3>
<ul>
<li>Upgrade Go to 1.26.6, which includes security fixes to the go command, and the crypto/tls, encoding/asn1, encoding/xml, html/template, net, net/http, and net/url packages. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9151">#9151</a>, <a href="https://github.com/wallrj"><code>@​wallrj</code></a>)</li>
<li>Upgrade Go to 1.26.8. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9323">#9323</a>, <a href="https://github.com/wallrj"><code>@​wallrj</code></a>)</li>
<li>Bump <code>google.golang.org/grpc</code> to v1.83.2 to fix reported security vulnerabilities (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9255">#9255</a>, <a href="https://redirect.github.com/cert-manager/cert-manager/issues/9317">#9317</a>)</li>
<li>Bump <code>golang.org/x/crypto</code> to v0.56.0 to fix reported security vulnerabilities (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9265">#9265</a>)</li>
</ul>
</blockquote>
