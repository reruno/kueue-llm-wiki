## Description

## Background

An elastic workload's new Pods can retain the original Workload annotation after a replacement slice is admitted. TAS then reconciles the original allocation on Pod events, leaving late-arriving workers gated despite available admitted capacity. Successful ungating can also leave pending expectations recorded under a replacement name but acknowledged under the original name.

## What's changing

Resolve the active admitted slice using the existing workload-slicing helper. Queue Pod and Workload events under the stable chain identity, and use that same identity for ungating expectations. Finished, evicted, or unadmitted allocations cannot release Pods.

## Validation/rollout

The failure was observed during worker growth and regrowth with Kueue v0.19.1. This draft targets current main and has not been deployed. Before rollout, validate repeated growth/shrink/regrowth with TAS placement and quota limits intact. A v0.19 backport would also need the shared slice-resolution helpers used here.

Prepared with OpenAI Codex assistance.
