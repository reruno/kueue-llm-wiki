#### What this PR does / why we need it?

Part of #14975. Replaces #15056, which was built against `statefulset_pod_reconciler.go` before #14597 removed it.

The StatefulSet integration suite never enabled the generic `pod` integration, even though StatefulSet requires it in any real deployment. That meant the suite exercised a configuration that cannot exist in production, and never covered the path that actually sets `WorkloadAnnotation` on StatefulSet pods — jobframework's shared `getPodSetsInfoFromStatus`, applied via the Pod job's `Run`.

This wires the pod integration into the suite, adds positive and negative cases for the annotation under the relevant feature gates, and adds an e2e assertion in `test/e2e/singlecluster/tasapi/baseline/statefulset_test.go`.

No production change.

#### Useful notes for your reviewer

The positive case fails without the pod-integration wiring and passes with it, which is what confirms the annotation comes from the shared jobframework path rather than from any StatefulSet-specific code. The negative case asserts the annotation is absent when both `TopologyAwareScheduling` and `SchedulerLibraryIntegration` are off, matching the gating in `getPodSetsInfoFromStatus`.
