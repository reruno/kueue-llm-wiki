#### What this PR does / why we need it?
This PR adds missing integration tests (s5 and s6) for capacity shrink scenarios from #13716.

**S5: Reparent lender subtree away**
- Before: root1 (0 CPU) with lender (2 CPU) and borrower (0 CPU) as children
- 3×500m workloads admitted by borrowing from lender sibling
- After: lender reparented to root2 (borrower loses capacity source)
- Verification: existing workloads remain admitted, new workloads stay pending

**S6: Reduce nominal quota below usage**
- Before: cq with 3 CPU nominal, 3×1 CPU workloads admitted
- After: quota reduced from 3 CPU → 1 CPU (quota < current usage)
- Verification: existing workloads remain admitted, new workloads stay pending

Both tests verify the fundamental invariant: capacity reduction never evicts already-admitted workloads.

**Explanation**

The reparenting test satisfies [`#13716`] S5. It confirms that all three admitted workloads retain admissions and that `wl-new` remains pending after the lender moves to another root. The quota-shrink test confirms that `wl-1`, `wl-2`, and `wl-3` are not evicted, but it does not confirm that their admissions remain present. It also submits `wl-reclaim` to `lender-cq`, where preemption admits it; it does not submit a new workload to the reduced `shrink-cq` and verify that the workload remains pending. Therefore, the quota-shrink objective is incomplete.

**Resolution**

After reducing `shrink-cq` nominal quota, assert that each existing workload still has a quota reservation. Submit a new workload to `shrink-cq` that cannot fit within the reduced quota and assert that it remains pending. Keep the preemption scenario as additional [`#13716`] S6 coverage if required.
