```release-note
Scheduling: Fixed a bug where a Workload whose usage reached `math.MaxInt64` in a resource was counted as unlimited, so removing it together with another Workload left the ClusterQueue, LocalQueue and Cohort usage below the real value until the controller restarted. Quota, `borrowingLimit` and `lendingLimit` values past that range are now accounted exactly rather than as unlimited, so an oversized lending limit keeps the difference local and an oversized borrowing limit still bounds borrowing; metrics still report `+Inf` at or past `math.MaxInt64`.
```

This backport was prepared with the assistance of generative AI. On this branch, whole-tree `go vet`, `go test -race` on `pkg/resources` and `pkg/cache/scheduler`, the `pkg/scheduler`, `pkg/controller/core` and `pkg/workload` unit tests, `make ci-lint` and the restart integration specs pass.

Not a clean pick. This branch has no `ResourceFormatter`, so `AmountQuantity` is a package-level function next to `ResourceQuantity` in `requests.go`, `FlavorResourceQuantities.ToResourceList` takes no formatter, the call sites in `cache.go` and `localqueue.go` follow, and the tests for it are in `requests_test.go` with the global registry reset. The `EffectiveQuotas` tests that `main` has are not on this branch and are left out; `workload.Usage` in `oversized_limits_test.go` takes the quantities directly here. `resources.Unlimited` and `Amount.Int64()` go away here as on `main`.
