#### What this PR does / why we need it?
An elastic Job with a pending scale-up slice can release its reservation when preempted while its Pods remain running. For example, a three-worker Job trying to grow to five in a four-GPU queue allows a higher-priority two-worker Job to be admitted before the victim stops. This happens with TAS enabled and disabled.

Return the evicted slice to the Job reconciler while it still holds quota, unless an admitted, non-evicted replacement has taken over. This lets the existing eviction path suspend the Job and wait for it to become inactive before clearing the reservation.

#### Useful notes for your reviewer
The integration regression holds the victim's Pods Running, verifies suspension while the urgent Job remains pending, then simulates termination and checks admission. It runs with TAS enabled and disabled. Unit coverage distinguishes a quota-reserved replacement waiting on admission checks from an admitted replacement.

Validation:
- `go test ./pkg/workloadslicing ./pkg/controller/jobframework`
- Job integration: `Elastic resize preemption retains occupied capacity|Job with elastic jobs via workload-slices support`
- `make ci-lint` and `git diff --check`

Integration tests use envtest Kubernetes 1.36.2. Pod creation, binding, and termination are simulated; envtest does not run the Kubernetes Job controller, kube-scheduler, or kubelet. Full `make verify` was previously blocked by Docker socket permissions and has not been rerun for this revision.
