## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it?
Cherry-pick of #15538 onto `release-0.18`, as requested by mimowo in the #15538 review (`/cherrypick release-0.18`). The cherry-pick robot only acts on `/cherrypick` issue comments, not review bodies, so it did not pick this one up.

Clean pick with `git cherry-pick -x d1b394d3c` — no conflicts, no adaptation needed. `cmd/kueue/main.go` on this branch already has the role tracker and the same `cfg.LeaderElection != nil && ptr.Deref(...)` guard as `main`, and `pkg/config/config.go` had not drifted in the touched area, so the applied diff is identical to the merged commit.

#### Problem
The manager `rest.Config` carries one shared `RateLimiter`, and controller-runtime copies it for the leader election lease client, so lease renewals compete for tokens with every reconcile and a burst can push a renewal past `renewDeadline` ("leader election lost").

#### Fix
Give the lease client its own `rest.Config` with a dedicated client-side limiter built from `clientConnection.qps`/`burst`.

#### How tested
On this branch, with `GOMAXPROCS=3`:

- `gofmt -l cmd/kueue/main.go pkg/config/config.go pkg/config/config_test.go` — clean (no output)
- `go vet ./pkg/config/ ./cmd/kueue/` — pass
- `go build ./cmd/kueue/` — pass
- `go test -count=1 ./pkg/config/` — pass, including the new `TestSetLeaderElectionConfig`

This backport was prepared with an AI agent operated by KR-Ravindra, who reviewed and tested it.

#### Which issue(s) this PR fixes
Backport of #15538 to `release-0.18`.

#### Release note

```release-note
HA: Fix the leader election lease client sharing the client-side rate limiter with the controllers, which could delay lease renewals under a low `clientConnection.qps` and restart the manager with "leader election lost".
```
