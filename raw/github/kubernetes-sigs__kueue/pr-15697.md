#### What this PR does / why we need it?

Improves the workload-slicing replacement test coverage in
`pkg/workloadslicing/workloadslicing_test.go`, as requested during review of #15686:

- Adds a new `TestEnsureWorkloadSlices` case,
  `EvictedOriginWithReservedReplacement_ReplacementAdmittedButEvicted`, covering an
  evicted, quota-reserved origin whose replacement is admitted but has itself since
  been evicted. `EnsureWorkloadSlices` must not treat such a replacement as having
  taken over the origin's Pods, so the origin is kept unfinished and returned as-is.
  This exercises the `!workloadevict.IsEvicted(&candidate)` half of the boolean guard
  in `EnsureWorkloadSlices` (`pkg/workloadslicing/workloadslicing.go`), a path not
  covered by the existing `ReplacementNotAdmitted` case (which only exercises the
  `workload.IsAdmitted(&candidate)` half being false).
- Adds a `finishedWorkloads map[string]string` field to the `TestEnsureWorkloadSlices`
  table's `want` struct. After the existing assertions, the test runner now lists all
  workloads and asserts which ones carry an active `Finished` condition and with what
  reason, instead of relying solely on a per-case `SubResourceApply` interceptor
  assertion. This is opt-in per case (`cmpopts.EquateEmpty()` treats "not set" the
  same as "nothing finished"), so it only applies to the three replacement-path cases
  touched here and leaves the ~25 other pre-existing table entries unchanged.
- Introduces a small `replacementPathClientBuilder()` helper (`testWorkloadClientBuilder()`
  plus `WithStatusSubresource(&kueue.Workload{})`), used by the three
  `EvictedOriginWithReservedReplacement_*` cases so `workloadfinish.Finish()`'s status
  apply actually persists to the fake client, instead of requiring the test to fake
  that assertion for each case. This is scoped rather than added to the shared
  `testWorkloadClientBuilder()`: doing it globally would silently flip three unrelated
  pre-existing cases' `error: true` expectation (they currently error only because the
  base builder doesn't register the Workload status subresource, not because of the
  production behavior under test), which is unrelated to this issue's scope.

No production code was changed.

#### Useful notes for your reviewer

- The new case's `want.workload` and `want.finishedWorkloads: map[string]string{}`
  were verified by tracing `EnsureWorkloadSlices` (lines ~255-267): the early-return
  loop returns the origin directly once it finds no non-evicted admitted replacement,
  so `normalizeActiveSlices`/`Finish` are never reached and nothing gets finished.
- Verified by hand (and by running the suite) that `testWorkloadClientBuilder()` itself
  is untouched, so the other ~25 `TestEnsureWorkloadSlices` cases and every other test
  function in the file are unaffected.
