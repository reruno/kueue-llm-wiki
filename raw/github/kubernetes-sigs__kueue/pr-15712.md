#### What this PR does / why we need it?

`image-pushing-postsubmit` runs `make -j5` over five targets. Four of them are buildx builds, and each fans out over the four entries in `PLATFORMS`. Every Dockerfile pins the builder stage to `--platform=${BUILDPLATFORM}` with `GOARCH=${TARGETARCH}`, so these are native amd64 cross-compiles rather than QEMU, which is why the s390x and ppc64le stages report `tool/linux_amd64/compile`. That leaves sixteen concurrent `go build` processes on a single `E2_HIGHCPU_32` machine, with nothing in the repo capping build parallelism.

Three runs since 2026-09-10 have died with `k8s.io/client-go/informers/...: /usr/local/go/pkg/tool/linux_amd64/compile: signal: killed`, twice taking down the root kueue image. This lowers the recipe to `-j3` so at most three image targets overlap. `-j4` would be a no-op, since `helm-chart-push` is not an image build and frees its slot to the fourth one as soon as it finishes. It gives back some of the merge-time win from #12322, but a failed push can leave the staging artifacts inconsistent, so the wall clock is the cheaper thing to spend.
