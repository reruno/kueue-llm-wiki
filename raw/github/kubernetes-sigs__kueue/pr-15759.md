#### What this PR does / why we need it?

Improves the replacement-path cases in `pkg/workloadslicing/workloadslicing_test.go` (`TestEnsureWorkloadSlices`) as requested in the follow-up to #15686:

- Register the Workload status subresource once in the shared `testWorkloadClientBuilder()` (`WithStatusSubresource(&kueue.Workload{})`), so `workloadfinish.Finish` status applies persist in the fake client.
- Add a `finishedWorkloads` expectation (workload name -> `Finished` reason). After `EnsureWorkloadSlices` runs, the test lists workloads and diffs the finished set against it. This replaces the `SubResourceApply` interceptors that only inspected the apply payload, and removes the now-unused `assertStatusConditionPatch`/`assertStatusConditionApply` helpers.
- Add `EvictedOriginWithReservedReplacement_ReplacementAdmittedAndEvicted`: the replacement is admitted but itself evicted, so it must not replace the evicted origin. The origin is returned and nothing is finished.

Fixes #15691

#### Useful notes for your reviewer

Registering the status subresource changed the outcome of three existing cases. Their previous expectations came from the fake client rejecting status applies with NotFound when the subresource is not registered, not from production behavior:

- `TwoWorkloads_BothWithReservedQuota`: previously `error: true`. Now `-1` is finished with `OutOfSync`, `-2` is kept, and the scale-up returns nil.
- `MoreThanTwoWorkloadSlices`: previously `error: true`. Now `-1` and `-2` are finished with `OutOfSync` and `-3` is returned. `-3` is also made strictly newer than `-2`; they shared a creation timestamp and had no UID, so the selection depended on sort tie-breaking.
- `TwoWorkloadSlices_NewIsUnreservedAndOutOfSync_UpdateFailure`: the `Update` interceptor was never reached because the status apply failed first. Added the `WorkloadSliceReplacementFor` annotation to `-2` so it becomes the pending replacement and `clnt.Update` is actually attempted.

`TwoWorkloads_OldWithReservedQuotaAndEvicted_NewWithoutQuotaReservation` drops its `TreatSSAAsStrategicMergeForApplyConfiguration` interceptor; it returns the evicted origin before any Finish call, and the shared builder now covers status applies.

Sanity check: flipping the expected reason in `EvictedOriginWithReservedReplacement_ReplacementAdmitted` to `OutOfSync` fails with a cmp diff, so the listing assertion is live.
