<h2>v0.166.0</h2>
<p>This release is mostly about hardening and bug fixes, but there are some notable changes:</p>
<ul>
<li><a href="https://gohugo.io/methods/page/render/"><code>.Render</code></a> now takes an optional context argument: <code>{{ .Render &quot;view&quot; $ctx }}</code>, mirroring the <code>partial</code> API. This makes it possible to pass e.g. a dict to a content view. See <a href="https://redirect.github.com/gohugoio/hugo/issues/15077">#15077</a>.</li>
<li>The <a href="https://gohugo.io/functions/go-template/return/"><code>return</code></a> keyword in templates has been reimplemented. It now works in any template (not just partials) and can be used anywhere, e.g. inside <code>if</code> or <code>range</code> blocks. See <a href="https://redirect.github.com/gohugoio/hugo/issues/15212">#15212</a>.</li>
<li>New <a href="https://gohugo.io/functions/resources/publish/"><code>resources.Publish</code></a> template function and <a href="https://gohugo.io/methods/pages/indexof/"><code>IndexOf</code></a> method on <code>Pages</code>.</li>
<li><a href="https://gohugo.io/configuration/related-content/"><code>related</code></a> config: new <code>tokenize</code> option for index values, and index creation is faster.</li>
<li>Several <a href="https://gohugo.io/configuration/security/">security</a> fixes; see the notes below.</li>
</ul>

<h3>Glob patterns</h3>
<p>The glob library used for e.g. module mounts (<code>includeFiles</code>, <code>excludeFiles</code>), <code>cascade</code> targets, <code>segments</code>, <code>deployment</code> matchers and <code>noVendor</code> has been upgraded to v1.0.0. This is a complete rewrite of the matching engine that fixes a long list of correctness bugs, but it also means that some patterns may behave differently:</p>
<ul>
<li>Malformed patterns (e.g. an unclosed <code>{</code>, an empty <code>[]</code> class) now fail with a syntax error instead of being silently accepted.</li>
<li><code>**</code> matches any sequence of characters including separators, but it is not the <code>**/</code> &quot;globstar&quot; of shells: <code>**/x</code> requires the literal <code>/</code> and does not match <code>x</code>, and <code>a/**/b</code> does not match <code>a/b</code>. Use <code>{**/,}x</code> if you need both.</li>
<li><code>\</code> is the escape character, so a literal backslash must be written as <code>\\</code>.</li>
</ul>
<p>If a pattern that used to match no longer does (or vice versa), it was most likely relying on a bug in the old engine.</p>
<h3>Security</h3>
<ul>
<li><code>text/org</code> content is now denied by default, as Org mode's export blocks and <code>@@html:...@@</code> snippets pass raw HTML through unescaped, making it the same XSS sink as <code>text/html</code>. Sites with Org content can opt back in via <code>security.allowContent</code>.</li>
<li>Remote fetches (<code>resources.GetRemote</code> etc.) now validate the resolved address at dial time and reject loopback, private, link-local, CGNAT and similar ranges. This only applies under the default <code>security.http.urls</code> allowlist; if you have customized it, you have opted into your own hosts and the check stands down. Proxies from <code>HTTP_PROXY</code>/<code>HTTPS_PROXY</code> hide the destination address from this check and are now ignored unless you set <code>security.http.proxyFromEnvironment = true</code>.</li>
<li>Node.js tools (PostCSS, Tailwind CSS etc.) now fail before invocation if a symlink inside the project resolves outside the allowed read/write roots. If you have a legitimate link, add its target to <code>security.node.permissions.allowRead</code>.</li>
<li>Mount roots that are themselves symlinks (e.g. <code>themes/mytheme/assets -&gt; /somewhere/else</code>) are now dropped. This closes a gap in the <code>themes/</code> confinement; absolute mount <code>source</code> values are still allowed.</li>
</ul>
<h3>Other</h3>
<ul>
<li><code>{{ return &lt;value&gt; }}</code> outside a partial is now an error; it was previously silently ignored.</li>
<li>A page without an explicit <code>slug</code> whose title contains a <code>/</code> (e.g. <code>Watch/listen to this</code>) now gets a single URL segment (<code>.../watch-listen-to-this/</code>) instead of a nested one (<code>.../watch/listen-to-this/</code>). Taxonomy and term pages are not affected.</li>
<li>Hugo is now built with Go 1.27.</li>
</ul>
<h3>KaTeX</h3>
<p>When upgrading to Hugo v0.166.0, sites using <code>transform.ToMath</code> with the <code>output</code> option set to <code>html</code> or <code>htmlAndMathml</code> must update the KaTeX stylesheet referenced in their template(s) to version 0.18.4 or higher. Using older CSS versions like 0.16.21 will cause certain mathematical or chemical expressions to render incorrectly.</p>
