#### What this PR does / why we need it?

Cherry-pick of #15649 to `release-0.18`.

`buildDriverPodTemplateSpec` and `buildExecutorPodTemplateSpec` ignored the SparkApplication-level `spec.nodeSelector`, so a SparkApplication that only set it lost the selector for good on the first eviction, and the selector was invisible to ResourceFlavor matching. This records it in the Workload PodSet templates, with the per-role selector taking precedence on conflict.

The only deviation from the original commit is dropping the `ctx` argument in the new `RestorePodSetsInfo` test call, since that method has no `ctx` parameter on this branch.

#### Useful notes for your reviewer


#### Release note

```release-note
SparkApplication: Fixed a bug where a SparkApplication that only set the SparkApplication-level `spec.nodeSelector` permanently lost it after the first eviction, letting the driver and executor pods be scheduled onto any node once re-admitted. The selector is now recorded in the Workload PodSets, so it also participates in ResourceFlavor matching.
```
