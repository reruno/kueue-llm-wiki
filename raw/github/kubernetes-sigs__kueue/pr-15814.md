### Comment by [@KR-Ravindra](https://github.com/KR-Ravindra) — 2026-09-18T11:47:59Z

The integration jobs all fail before any test runs, in `make generate-code`, and it is deterministic rather than flaky: kube_codegen.sh does its `go install` of the generators from inside the code-generator v0.37.0 module (its go.mod says `go 1.26.0`), so on the golang:1.26 job image with `GOTOOLCHAIN=auto` the binaries are built with the Go 1.26 go/parser. They then run from the repo root, where `go list` switches to the downloaded go1.27.0 toolchain, and that older parser rejects the new generic method in the 1.27 stdlib: `math/rand/v2/rand.go:213: method must have no type parameters`. Exporting `GOTOOLCHAIN=go1.27.0` (or the version read from go.mod) in hack/tools/code-generator/generate.sh before sourcing kube_codegen.sh should fix it; bumping the prow job image to golang:1.27 in test-infra would as well.

verify-main fails separately on 975 `modernize/embedlit` findings that the 1.27 language version unlocks; either run the fixer or exclude `embedlit` in .golangci.yaml.

#15290 is the same bump and already carries the embedlit exclusion and the regenerated client-go, but hits the same generate-code error.
