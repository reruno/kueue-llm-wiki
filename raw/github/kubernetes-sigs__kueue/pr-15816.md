#### What this PR does / why we need it?

The TAS annotations are read from the PodSet template
(`pkg/workload/workload.go:559`, `pkg/controller/jobframework/tas_validation.go:307`),
so for a `batch/Job` they must be set in `spec.template.metadata.annotations`.
An annotation placed in the Job's own `metadata.annotations` is silently
ignored — no error, event or condition.

Three places on the TAS concepts page did not make this clear:

- **Topology Spreading** said to add the annotations "on the Job" and showed a
  bare annotation map with no path context. This is the case the issue reports.
- **Multi-layer topology** showed `podset-slice-required-topology-constraints`
  as a bare annotation map with the same ambiguity.
- **Balanced placement** described `podset-preferred-topology` as set "on the Job".

All three now name the PodTemplate and, for the two examples, show the full
`spec.template.metadata.annotations` path — matching the convention already used
in the page's first example and stated explicitly in
`docs/tasks/run/topology_aware_scheduling.md`.

Fixes #15791
