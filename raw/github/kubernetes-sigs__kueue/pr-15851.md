## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

When `managedJobsNamespaceSelector` is configured, the defaulting webhook still adds `kueue.x-k8s.io/priority-class: default` to objects created in namespaces excluded by the selector.

Kueue does not manage objects in those namespaces, so the webhook should not mutate them either. `ManagedJobsNamespaceSelectorAlwaysRespected` has been GA since 0.19, but the WorkloadPriorityClass defaulting path did not follow this rule. The LocalQueue path was fixed earlier in #13375, while `WorkloadPriorityClassDefaulting` has been enabled by default since 0.20.

Unlike #13374, this does not cause workloads to hang because the label does not suspend anything. However, Kueue still mutates user objects in namespaces it was configured to ignore. If such a namespace is opted in later, the previously added label can then take effect.

This PR:

* Makes `ApplyDefaultWorkloadPriorityClass` check whether the object's namespace matches `managedJobsNamespaceSelector` before setting the default priority-class label.
* Passes the configured selector through every Job webhook. The Pod webhook passes `nil` because it has already enforced the selector earlier in the admission flow.
* Returns a Namespace read error from the admission webhook instead of swallowing it, matching the behavior of `ApplyDefaultLocalQueue`.

#### Useful notes for your reviewer

* The namespace check is performed after the existing eligibility checks, so objects that would return early do not incur an additional Namespace `Get`.
* When no `managedJobsNamespaceSelector` is configured, no Namespace read is performed and the existing behavior is preserved.
* `DefaultWorkloadPriorityClassExist` still logs at V(2) and continues when the default WorkloadPriorityClass cannot be found. This is intentionally unchanged; the two error-handling policies can be aligned separately if desired.
* Each new test verifies that the default label is added without the production change.

#### Release note

```release-note
WorkloadPriorityClassDefaulting: Fixed the defaulting webhook setting the `kueue.x-k8s.io/priority-class: default` label on jobs created in namespaces excluded by `managedJobsNamespaceSelector`.
```
