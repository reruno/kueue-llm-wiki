## Description

#### What type of PR is this?

#### What this PR does / why we need it?

Adds the `ConfigurablePreemptions` feature gate introduced by [KEP-13396: Configurable Preemptions](https://github.com/kubernetes-sigs/kueue/tree/main/keps/13396-configurable-preemptions), registered as Alpha and disabled by default in `0.20`, matching the `alpha: v0.20` milestone declared in the KEP's `kep.yaml`.

This is a gate-only change that unblocks the follow-up implementation PRs: the gate is declared in `pkg/features/kube_features.go` and the generated feature-gate lists are refreshed, but no product code reads it yet, so there is no behavior change.

- `pkg/features/kube_features.go`: new `ConfigurablePreemptions` key with the owner/KEP comment, plus its `VersionedSpecs` entry (`0.20`, `Alpha`, default `false`).
- `test/compatibility_lifecycle/reference/versioned_feature_list.yaml` and `site/data/featuregates/versioned_feature_list.yaml`: regenerated with `make generate-featuregates`.

Part of #13396

#### Useful notes for your reviewer

- No entry was added to `defaultFeatureGateDependencies`. The KEP does not require another gate to be enabled for configurable preemptions as a whole. Please flag if you would prefer a `{TopologyAwareScheduling}` dependency up front, given that the topology-defragmentation trigger relies on TAS. My assumption is that this is better expressed as a validation error on the `PreemptionConfig` trigger than as a gate dependency, since quota triggers work without TAS.
