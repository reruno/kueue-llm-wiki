<h3>Bug or Regression</h3>
<ul>
<li>CLI: Aggregate Matching Pods into One PodList for Structured Output (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15520">#15520</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>CLI: Fix kueuectl ClusterQueue resource-group validation to detect overlaps consistently and preserve distinct resource groups. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15522">#15522</a>, <a href="https://github.com/DevaanshPathak"><code>@​DevaanshPathak</code></a>)</li>
<li>CLI: Fixed a bug where <code>create clusterqueue</code> silently dropped a <code>--borrowing-limit</code> or <code>--lending-limit</code> entry for a resource not listed in <code>--nominal-quota</code>, and rejected omitting a limit for some nominal-quota resources. Limits are now optional per resource, and a limit for a resource without a nominal quota is reported as an error naming the flag and resource. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15513">#15513</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>CLI: Fixed a bug where <code>kueuectl create clusterqueue</code> accepted a resource listed more than once in the same <code>--nominal-quota</code>, <code>--borrowing-limit</code> or <code>--lending-limit</code> flag. The command now rejects the input with an error naming the resource and the flag. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15519">#15519</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>CLI: Fixed a bug where <code>kueuectl create clusterqueue</code> rejected a quota flag value with a trailing semicolon, such as <code>--nominal-quota &quot;alpha:cpu=1;&quot;</code>, with a misleading <code>invalid resource quota</code> error. The trailing semicolon is now accepted, as the flag's format validation already allowed it. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15517">#15517</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>CLI: Fixed shell completion for  <code>kueuectl stop workload</code>  and  <code>kueuectl resume workload</code> , which continued suggesting additional Workload names after the single required name was entered, potentially producing commands rejected for too many arguments (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15464">#15464</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>CLI: Fixed the <code>--status</code> flag help text and error message of <code>kueuectl list workload</code> to include the supported <code>quotareserved</code> value. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15486">#15486</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>ClusterQueue, Cohort &amp; LocalQueue: Fixed a bug where the status was written to the API server on every reconcile even when nothing changed. Kueue now skips the update when the status is unchanged. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15592">#15592</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>ConcurrentAdmission: Fixed a bug where the preemption gate could still be opened for a less favorable Workload Variant while a more favorable one was waiting to be evaluated, when that Variant already carried a <code>QuotaReserved</code> condition with reason <code>PendingEvaluation</code>. The more favorable Variant stayed blocked until the preemption timeout expired. This completes the fix released in 0.19, which only covered Variants carrying no <code>QuotaReserved</code> condition at all. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15639">#15639</a>, <a href="https://github.com/ivnovakov"><code>@​ivnovakov</code></a>)</li>
<li>DRA: Fixed a bug where a workload requeued after backoff lost its DRA-preprocessed resources, causing the queue to fall back to raw pod-spec requests. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15511">#15511</a>, <a href="https://github.com/vibhordubey333"><code>@​vibhordubey333</code></a>)</li>
<li>ElasticJobsViaWorkloadSlices: Wait for an evicted Job's active Pods to stop before releasing the reservation when a scale-up slice is pending. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15667">#15667</a>, <a href="https://github.com/garg02"><code>@​garg02</code></a>)</li>
<li>HA: Fix the leader election lease client sharing the client-side rate limiter with the controllers, which could delay lease renewals under a low <code>clientConnection.qps</code> and restart the manager with &quot;leader election lost&quot;. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15538">#15538</a>, <a href="https://github.com/KR-Ravindra"><code>@​KR-Ravindra</code></a>)</li>
<li>Helm: Fixed a bug where an empty <code>kueueViz.backend.ingress.host</code> generated an invalid WebSocket URL. The chart now uses the same <code>backend.kueueviz.local</code> default as the KueueViz Ingress. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15645">#15645</a>, <a href="https://github.com/HsiuChuanHsu"><code>@​HsiuChuanHsu</code></a>)</li>
<li>Importer: Fixed a bug where <code>importer import --concurrent-workers=0</code> could report success without checking or importing any pod. The importer now rejects the flag with an error asking for at least 1 worker. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15581">#15581</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>Importer: Fixed a bug where the importer reported success and exited 0 when listing Pods failed, for example due to insufficient RBAC or a wrong namespace. The importer now returns an error in that case. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15596">#15596</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>JAXJob x TrainJob: Fixed a bug where jobs deactivated by Kueue were not deleted after the <code>objectRetentionPolicies.workloads.afterDeactivatedByKueue</code> period because Kueue lacked the <code>delete</code> permission on these resources. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15567">#15567</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>JobFramework: Fix a nil pointer dereference and unauthorized deletion/modification of foreign Workloads in the job framework: FindMatchingWorkloads now only considers Workloads controlled by the reconciled job. Workloads with non-controller ownerReferences to a served job previously caused a permanent reconcile error-loop for that job, and Workloads controlled by other objects could be deleted or have their spec overwritten by kueue. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13573">#13573</a>, <a href="https://github.com/Mayveskii"><code>@​Mayveskii</code></a>)</li>
<li>KueueViz: Fixed a bug where the dashboard failed to load when no backend WebSocket URL was configured. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15646">#15646</a>, <a href="https://github.com/HsiuChuanHsu"><code>@​HsiuChuanHsu</code></a>)</li>
<li>Kueuectl: Fixed a bug where <code>kueuectl list workload --for TYPE/NAME</code> listed all workloads in the namespace when the referenced resource did not exist. It now prints only &quot;No resources found&quot;. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15583">#15583</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>Pod Integration: No Workload is (re)created for a pod group whose pods are all terminating once no Workload remains, and the pods' remaining Kueue finalizers are removed so stuck teardowns complete; previously such a pod could regain a permanently unschedulable Workload built from its admission-mutated spec. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15154">#15154</a>, <a href="https://github.com/anguszzzz"><code>@​anguszzzz</code></a>)</li>
<li>ProvisioningRequest: Fix an infinite ProvisioningRequest create/delete loop for workloads whose generated request name needed truncation. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15466">#15466</a>, <a href="https://github.com/vladikkuzn"><code>@​vladikkuzn</code></a>)</li>
<li>Scheduling: Fixed a bug where a Workload whose usage reached <code>math.MaxInt64</code> in a resource was counted as unlimited, so removing it together with another Workload left the ClusterQueue, LocalQueue and Cohort usage below the real value until the controller restarted. Quota, <code>borrowingLimit</code> and <code>lendingLimit</code> values past that range are now accounted exactly rather than as unlimited, so an oversized lending limit keeps the difference local and an oversized borrowing limit still bounds borrowing; metrics still report <code>+Inf</code> at or past <code>math.MaxInt64</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15653">#15653</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>TAS × ElasticJobsViaWorkloadSlices: Fix double-counting of a replaced elastic Workload slice's topology usage, which could incorrectly classify growth that fits as requiring preemption. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15586">#15586</a>, <a href="https://github.com/garg02"><code>@​garg02</code></a>)</li>
<li>TAS × ElasticJobsViaWorkloadSlices: Fix elastic replacement Pods remaining topology-gated because the ungater used stale slice admission or inconsistent expectation keys. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15693">#15693</a>, <a href="https://github.com/garg02"><code>@​garg02</code></a>)</li>
<li>TAS: Fix node replacement on clusters where a Node's <code>kubernetes.io/hostname</code> label differs from its object name. A Ready node is no longer reported in <code>status.unhealthyNodes</code>, and a failed node's workloads are now evicted. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15590">#15590</a>, <a href="https://github.com/rishabhsai"><code>@​rishabhsai</code></a>)</li>
<li>TAS: Fixed a bug where a PodSet group whose leader and workers use different Pod templates could be admitted to a domain the leader cannot run in, leaving it Pending while the Workload held quota. Gated by <code>TASLeaderPodSetFeasibility</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15690">#15690</a>, <a href="https://github.com/sohankunkerkar"><code>@​sohankunkerkar</code></a>)</li>
<li>TAS: The MPIJob and LeaderWorkerSet webhooks now reject a <code>kueue.x-k8s.io/pod-index-offset</code> annotation that is set together with <code>kueue.x-k8s.io/podset-group-name</code>, or whose value is not a non-negative integer. The MPIJob webhook additionally prevents the annotation from being removed or changed on update. This enforces the annotation contract that Topology-Aware Scheduling relies on for Pod rank ordering, preventing configurations that previously left Pods stuck gated. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14485">#14485</a>, <a href="https://github.com/adibmbrk"><code>@​adibmbrk</code></a>)</li>
</ul>
