#### What this PR does / why we need it?

Cherry-pick of #15734 to `release-0.19`.

The kubelet sets a pod's `PodReady` condition to `False` once the pod completes, so the pod integration reported `PodsReady=False` as soon as any member of a pod group finished. With `waitForPodsReady` and a `recoveryTimeout` configured, the workload was then evicted, deleting the pods that were still running. `PodsReady` can now treat a `Succeeded` pod as ready, except in serving pod groups.

The only deviation from the original commit is that the `PodIntegrationCountSucceededPodsAsReady` feature gate is Alpha and disabled by default (version `0.19`) on this branch, so patch upgrades keep the existing behavior.

#### Useful notes for your reviewer


#### Release note

```release-note
Pod: Added the `PodIntegrationCountSucceededPodsAsReady` feature gate (Alpha, disabled by default). When enabled, succeeded pods count as ready for `PodsReady`, which fixes a bug where a pod group could be evicted after `waitForPodsReady.recoveryTimeout` once one of its pods completed.
```
