#### What this PR does / why we need it?

When a local Workload is finished or has no quota reservation, MultiKueue checks every configured worker cluster for a remote controller object before deleting the remote Workload. Most pending Workloads have never been dispatched, so those controller-object lookups cannot find anything and add avoidable remote API traffic to the reconciliation path.

This change skips remote cleanup when the Workload has no evidence that remote objects could exist for that cluster. It preserves cleanup when a remote Workload is visible, the cluster was nominated or selected, or the Workload has ever been evicted. Treating both active and historical eviction conditions as dispatch evidence preserves orphaned controller-object cleanup after eviction and re-admission.
