#### What this PR does / why we need it?

Manual cherry-pick of #15886 to `release-0.18`.

The automated cherry-pick conflicted in `test/e2e/multikueue/extended/e2e_test.go` because the release branch still keeps the KubeRay tests in that file. The manual resolution preserves the release-branch-specific KubeRay imports and moves only the two existing LeaderWorkerSet specs and their integration-specific imports to `leaderworkerset_test.go`.

Test behavior, labels, Ginkgo hierarchy, shared fixtures, and cleanup scope remain unchanged.

This PR was prepared with assistance from OpenAI Codex.

Related: #15886

#### Useful notes for your reviewer

Validated with:

```
go test ./test/e2e/multikueue/extended -run '^$'
go test -v ./test/e2e/multikueue/extended -run TestAPIs -args -ginkgo.dry-run -ginkgo.label-filter=feature:leaderworkerset -ginkgo.v
```

The dry run registered both existing LeaderWorkerSet specs with the same names, labels, and Ginkgo hierarchy. The moved spec bodies compare identically with the release branch after excluding the context-provider assignments and indentation.
