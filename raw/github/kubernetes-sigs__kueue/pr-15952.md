#### What this PR does / why we need it?

The MultiKueue periodic consistently fails its provisional 75 workloads/s floor, which came from local macOS measurements. Seven CI jobs (14 attempts) measured 44.82–46.75 workloads/s, with all 1,000 workloads admitted and zero watch gaps.

Set the floor to 35 workloads/s, leaving about 22% below the slowest CI attempt, and document the CI measurements and benchmark limitations. The scenario and other performance bounds are unchanged.

Fixes #15891

#### Useful notes for your reviewer

Generation occupies 96–99% of the measured interval in CI. This change calibrates the current end-to-end benchmark; improving its sensitivity to controller regressions requires separate work on load generation. The README links the CI runs and explains the threshold rationale.

Validation:

- Replayed all 14 saved CI reports: the original expectations fail and the updated expectations pass.
- `make test-performance-multikueue` passed locally on Linux arm64 with 4 CPUs and 7 GiB, including race-enabled tests: 1,000 admissions, 45.35 workloads/s, zero watch gaps. This local run is validation, not calibration of the 7-CPU CI worker.

AI tools were used to assist with implementation and review. The final diff was manually reviewed and validated.
