#### What this PR does / why we need it?


Resource transformations can use one requested resource as a multiplier for another.

A vGPU device plugin is one example:

- `acme.io/vgpu-count` is the number of requested vGPUs.
- `acme.io/cores-per-vgpu` is the requested compute capacity per vGPU.
- Kueue should account for their product as total vGPU cores.

An administrator can configure this as follows:

```yaml
apiVersion: config.kueue.x-k8s.io/v1beta2
kind: Configuration
resources:
  # Do not account for the vGPU count directly.
  excludeResourcePrefixes:
    - acme.io/vgpu-count

  transformations:
    - input: acme.io/cores-per-vgpu
      strategy: Replace
      multiplyBy: acme.io/vgpu-count
      outputs:
        quota.acme.io/total-vgpu-cores: "1"
```

For a Pod requesting two vGPUs with 20 cores per vGPU:

```
resources: 
  requests:
    acme.io/vgpu-count: "2"
    acme.io/cores-per-vgpu: "20" 
  limits:
    acme.io/vgpu-count: "2"
    acme.io/cores-per-vgpu: "20"
```

Kueue should account for:

20 cores per vGPU × 2 vGPUs = 40 total vGPU cores

Before this change, Kueue removed excluded resources before applying transformations.
As a result, `acme.io/vgpu-count` was unavailable when resolving `multiplyBy`, and Kueue accounted for only 20 total vGPU cores.

This change keeps excluded resources out of direct ClusterQueue accounting while still making their requested quantities available to resource transformations.
