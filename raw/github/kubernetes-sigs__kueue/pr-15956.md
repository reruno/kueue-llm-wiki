#### What this PR does / why we need it?

When  `KUEUECTL_LIST_REQUEST_LIMIT`  enables pagination, LocalQueues are paginated before the client-side  `--active`  filter is applied.

For example, suppose the first page contains an inactive  `lq-inactive` , while the second page contains an active  `lq-active` :

```
$ KUEUECTL_LIST_REQUEST_LIMIT=1 kueuectl list localqueue --active=true
NAME   CLUSTERQUEUE   PENDING WORKLOADS   ADMITTED WORKLOADS   ACTIVE   AGE
NAME   CLUSTERQUEUE   PENDING WORKLOADS   ADMITTED WORKLOADS   ACTIVE   AGE
lq-active ...
```

The first page becomes empty after filtering, but the command still prints its table header. Because no matching LocalQueue has been counted, header output remains enabled for the second page, causing the header to be printed again before  lq-active .

The fix skips empty intermediate pages in the default table output, ensuring that the header is printed only once, with the first page containing matching results.
