#### What this PR does / why we need it:

`GenericJob.IsActive` is documented as reporting whether a job still has running Pods. The RayCluster integration currently uses readiness as a proxy, so a RayCluster becomes inactive as soon as it is no longer `Ready`, even while KubeRay is still deleting its Pods. This can release the Workload's quota before suspension has completed.

This PR changes RayCluster to remain active until KubeRay reports `status.state="suspended"`. KubeRay sets that state only after the RayCluster's Pods have been deleted. Like the other integrations, `IsActive` relies on the controller-reported runtime status rather than the desired spec or `observedGeneration`.

#### Which issue(s) this PR fixes:

NONE

#### Special notes for your reviewer:

The implementation uses `status.state` instead of the `RayClusterSuspended` condition because Kueue supports KubeRay v1.1+, while that condition is not reported by KubeRay v1.1 or v1.2.

RayService is intentionally out of scope. Its top-level and nested suspend fields participate in zero-downtime upgrade quota gating, which is being developed in [kueue#11264](https://github.com/kubernetes-sigs/kueue/pull/11264). Its `IsActive` semantics should be updated after that design lands.

Test:

- `go test ./pkg/controller/jobs/raycluster ./pkg/util/testingjobs/raycluster`

Kueue now waits for KubeRay to finish suspending a RayCluster before releasing its quota.
