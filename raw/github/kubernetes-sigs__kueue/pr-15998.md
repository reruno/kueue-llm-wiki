#### What this PR does / why we need it?

With `managedJobsNamespaceSelector` configured, the defaulting webhook stamps `kueue.x-k8s.io/priority-class: default` on objects created in namespaces the selector excludes, which the reconciler then ignores entirely. The LocalQueue half of the same webhook learned this rule in #13375; the WorkloadPriorityClass half was left behind.

`WorkloadPriorityClassDefaulting` is Alpha and off by default on this branch, so only clusters that enabled the gate are affected.

#### Useful notes for your reviewer

The pick is not clean because this branch predates the `IntegrationManager` refactor and because #13375 landed here as a second function rather than a signature change. This follows that shape:

- `ApplyDefaultWorkloadPriorityClassWithManagedJobsNamespaceSelector` carries the namespace check, and the webhooks call it.
- `ApplyDefaultWorkloadPriorityClass` stays for compatibility and now delegates with a nil selector, so the two cannot drift. A nil selector reads no Namespace, so its behaviour is unchanged.
- The Pod webhook passes `nil`: it enforces the selector before reaching the call.
