#### What this PR does / why we need it?
Five CRDs had no editor or viewer ClusterRole at all, so nothing carried that label
for them:

- `AdmissionCheck`
- `MultiKueueCluster`
- `MultiKueueConfig`
- `ProvisioningRequestConfig`
- `WorkloadPriorityClass`

**`/status` rules** are added only where the CRD actually has a status subresource, based on `subresources.status` in `config/components/crd/bases/*.yaml`:

| CRD | status subresource | `<resource>/status: [get]` rule |
|---|---|---|
| admissionchecks | yes | added |
| multikueueclusters | yes | added |
| multikueueconfigs | no | not added |
| provisioningrequestconfigs | no | not added |
| workloadpriorityclasses | no (`subresources: {}`) | not added |
