#### What this PR does / why we need it:

Kueue calculates Workload resource usage with `resourcehelpers.PodRequests`. For malformed Pod specs, an explicit pod-level request smaller than the aggregate container request replaces the container value. A directly created Workload can therefore reserve less quota than its containers request.

This PR introduces a shared `PodRequests` helper that:

- Calculates the effective pod-level requests without overhead.
- Keeps at least the Kubernetes aggregate container requests.
- Adds Pod overhead afterward.
- Preserves existing behavior for valid Pod specs.

The helper is used by Workload quota accounting and the other PodSpec request calculation paths.

Regression coverage includes:

- Valid pod-level requests.
- Pod-level requests smaller than container requests.
- Pod overhead.
- Init containers.
- Restartable init containers.
- Resources without corresponding pod-level requests.
- Workload-level request multiplication.

Fixes #14255

#### Useful notes for your reviewer

The calculation uses Kubernetes’ `AggregateContainerRequests`, preserving its regular-container, init-container, and restartable-init-container semantics.

Valid Kubernetes Pod specs are unaffected because Kubernetes already requires explicit pod-level requests to be greater than or equal to aggregate container requests.

Workloads that already hold quota continue using the resource usage recorded in `status.admission`; this PR does not rewrite existing reservations.
