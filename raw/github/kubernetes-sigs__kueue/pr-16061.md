#### What this PR does / why we need it?

When a workload requiring Topology Aware Scheduling (TAS) topology spreading attempts to preempt lower-priority workloads:
1. During flavor assignment feasibility checks (`RepresentativeMode() == Preempt`), `FindTopologyAssignmentsForWorkload` runs with `simulateEmpty = true` to check whether the incoming workload fits if lower-priority workloads are preempted. Previously, `topologySpreadCountsForFlavor` did not receive `simulateEmpty` and evaluated spread counts against existing snapshot workloads. This resulted in false domain bans from spreading constraints, marking the flavor as `NoFit` and aborting preemption before it could be attempted.
2. In `updateAssignmentForTAS`, when computing topology assignments after selecting preemption targets, `snapshot.SimulateWorkloadUsageRemoval` only subtracted quota usage but left target workloads in `cq.Workloads`. Spreading evaluations therefore still counted victim workloads against domain placement limits. Replacing this with `snapshot.SimulateWorkloadRemoval` removes the target workloads from `cq.Workloads` during assignment simulation and restores them afterwards, allowing the preempting workload to place onto domains vacated by victims.

Fixes #16021
