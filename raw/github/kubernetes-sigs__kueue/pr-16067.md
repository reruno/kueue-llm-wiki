#### What this PR does / why we need it:

Adds admission-time validation for the RayCluster head Pod container invariant while retaining the existing controller-side defensive checks.

The shared `raycluster.ValidateCreate` helper now rejects RayCluster specs whose head Pod has no containers. RayJob and RayService return those errors before topology validation can consume the invalid spec. The regression test uses `K8sJobMode` with TAS enabled to cover the real-cluster path that previously reached `PodSets()`.

This PR is intentionally limited to the head-container validation and is intended to merge after #16071, which makes the RayCluster webhook use the same shared helper. Together, the two PRs apply the invariant consistently to RayCluster, RayJob, and RayService without mixing the validation-path cleanup with this behavior change.

> The webhook can't cover every case. For example, RayJobs created before an upgrade never go through the new webhook check.

I understand your point, but this function is also called from other places, so we shouldn’t put this logic in this code path. In addition, from first principles, why should the validation depend on whether the TAS feature flag is enabled?
