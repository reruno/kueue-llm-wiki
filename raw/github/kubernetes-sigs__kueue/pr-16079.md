## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it?
Backports #15444 to release-0.18. Zero-count PodSets prefer a ResourceFlavor with sufficient per-pod capacity, so the initial flavor choice does not prevent later scale-up. Mixed-count groups include their actual requests plus one pod per zero-count PodSet in the probe. Quota accounting and fallback behavior are preserved.

Related: #15444

#### Useful notes for your reviewer
The automatic cherry-pick conflicted. Adapted quota accounting, scheduler call signatures, resource-formatting helpers, and the workload-finished test helper to the release branch's existing interfaces. The backport preserves the original warning wording and regression coverage. Integration cases set up and clean up the feature gate and manager individually for compatibility with the older test helpers.

Validation: workload and flavor-assignment unit tests passed three times with race detection; the affected controller requeue tests passed with race detection. Both zero-count elastic-job integration scenarios and lint passed. Full release-branch CI will run on this PR.

AI assistance: OpenAI Codex was used to prepare and test this backport.

#### Release note
```release-note
ElasticJobsViaWorkloadSlices: Fixed a bug that could assign an incompatible ResourceFlavor when an elastic Workload was re-admitted with zero pods. Kueue now selects a flavor that supports the Workload’s per-pod resource requirements.
```
