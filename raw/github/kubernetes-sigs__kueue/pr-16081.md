## AI summary

When `KueueDRADeviceFeasibility` is enabled, Kueue now applies matching `DeviceTaintRule` taints during DRA feasibility checks when the `DRADeviceTaintRules` API is served and its feature gate is enabled. This prevents Kueue from treating devices as feasible when kube-scheduler would reject them; claims that tolerate the taint can still use those devices.

### Suggested release note

DRA: Fixed a bug where Kueue could admit a Workload to a device that kube-scheduler rejects because of a matching `DeviceTaintRule`. When `DRADeviceTaintRules` is enabled and the API is served, Kueue now applies those taints during feasibility checks.
