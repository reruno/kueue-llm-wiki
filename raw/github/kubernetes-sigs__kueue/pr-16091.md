   #### What this PR does / why we need it?

   Adds KEP-15733, a provisional KEP for making the pod template of a queue-managed LeaderWorkerSet (LWS) mutable.

   Today the LWS webhook rejects any change to the part of the pod spec that Kueue compares, even edits that cannot change quota.
   Adding a toleration for a new taint, or an init container, means deleting and recreating the LWS.

   The KEP proposes two phases, each behind its own feature gate:

   - Phase 1 (`LWSMutablePodTemplate`) accepts edits to tolerations, container ports, and init containers that leave the pods' effective resource request unchanged. These edits need no
 re-admission.
   - Phase 2 (`LWSRollingReAdmission`) accepts the remaining edits and re-admits each group through a successor Workload that asks only for the delta. The old reservation stays until the
 successor is admitted, instead of being released first. It builds on the WorkloadSlice aggregation from KEP-77.

   #### Useful notes for your reviewer

   - The KEP is provisional. Both gates target alpha in v0.20, and I am glad to adjust the milestones to the release schedule.
   - The Phase 2 mechanism has not been reviewed by maintainers yet. The open questions under Graduation Criteria are where input would help most: keeping a successor on the group's current
 flavor, whether successors should preempt, and reusing versus generalizing the WorkloadSlice machinery.
   - Following the feedback on #15733, the KEP includes a graduation plan toward enabling both gates by default.
   - AI tools were used to help draft and review this KEP. I reviewed the content and checked its code references against the repository.
