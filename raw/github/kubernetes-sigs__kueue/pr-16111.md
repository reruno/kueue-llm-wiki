## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

For a batch/Job, `ReclaimablePods` measured the reclaimable count against `parallelism`, but the Workload PodSet only reserves `min(parallelism, completions)` Pods. With `parallelism: 10`, `completions: 5` and one succeeded Pod, the Job reported 6 reclaimable Pods, which was clamped to the PodSet count of 5, so the 4 Pods still running no longer held any quota. This PR measures the count against `podsCount()` instead, for both Indexed and NonIndexed Jobs.

#### Useful notes for your reviewer


#### Release note

```release-note
Job: Fixed a bug where a Job with `parallelism` greater than `completions` could release the quota of its still-running Pods once some Pods succeeded, allowing the ClusterQueue to admit Workloads beyond its quota.
```
