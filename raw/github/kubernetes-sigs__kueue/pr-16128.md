#### What this PR does / why we need it:

Cherry-picks the fix from #14578 to release-0.19. When all member Pods of a
PodGroup are gone but its Kueue-managed owner (for example, a StatefulSet or
LeaderWorkerSet) remains live, the PodGroup reconciler no longer finalizes the
Workload as orphaned. Instead, it completes an outstanding eviction by clearing
the quota reservation while retaining the Workload and its finalizer. This
prevents an empty, evicted PodGroup from holding quota indefinitely.

The backport adapts to the release branch's integration-manager and Workload
APIs. It covers the behavior with Pod and StatefulSet unit tests, a
LeaderWorkerSet unit regression test, and a StatefulSet integration test. The
StatefulSet integration suite now starts the Pod reconciler needed for that
test; the source branch's LeaderWorkerSet integration suite is not present on
release-0.19.

Related: #14574
Cherry-pick of #14578

#### Useful notes for your reviewer

This is a release-branch backport of the already-merged fix, with test-suite
adaptations required by release-0.19. No StatefulSet controller behavior is
changed by this backport.

Local verification:

- `go test ./pkg/controller/jobframework ./pkg/controller/jobs/pod ./pkg/controller/jobs/statefulset ./pkg/controller/jobs/leaderworkerset -count=1`
- `go test ./test/integration/singlecluster/controller/jobs/statefulset -run TestAPIs -count=1` (with KUBEBUILDER_ASSETS configured)

#### Release note

```release-note
LeaderWorkerSet & StatefulSet: Fixed a bug where evicted Workloads with no remaining Pods kept their quota reserved. Kueue now releases that quota.
```
