#### What this PR does / why we need it?

`E2E_NON_RETRIABLE_IMAGE_ERRORS` in `hack/testing/e2e-common.sh` matched a bare `unauthorized`, and `e2e_docker_pull_if_needed` hands that list to `retry.sh --continue-if`, so any 401 from a registry was read as a permanent denial and the remaining 6 attempts were dropped. In `pull-kueue-test-e2e-baseline-main-1-37` quay.io answered the `prometheus-operator` pull with a bare `unauthorized:`, printed after `Pulling from prometheus-operator/prometheus-operator`, so the failure came mid-pull rather than at manifest resolution. Cluster bring-up exited before any spec ran.

Only the phrasings that name a denial reason stay non-retriable now: `unauthorized: authentication required` and `unauthorized: access to the requested resource is not authorized`. A 401 with no reason falls through to the retry path, which is how `IMAGE_BUILD_RETRIABLE_ERRORS` in the `Makefile` already classifies a registry 401 during the image build.

#### Useful notes for your reviewer

- quay.io also answers an absent tag with a 401, so a genuinely missing image now takes the full backoff before it fails (188s measured locally) instead of failing immediately. That cost cannot land on the fallback probe in `prepare_docker_images`, where a failed lookup is the expected path: `docker manifest inspect` returns `no such manifest` for an absent tag on quay.io, Artifact Registry, gcr.io and Docker Hub, and all four still fail fast.
- The two new cases in `hack/testing/e2e-common_test.sh` use error strings captured from real registries, not invented ones. I checked they fail against the old pattern: with the bare `unauthorized` restored, `make e2e-common-test` exits 1 on the new pull case.
