#### What this PR does / why we need it?

#16148 removed a bare `unauthorized` from `E2E_NON_RETRIABLE_IMAGE_ERRORS` so that a 401 from a degraded registry no longer kills e2e cluster bring-up before any spec runs. That also gave up the fail-fast path for a tag that does not exist: `e2e_docker_pull_if_needed` now retries every 401 that names no reason, so a mistaken dependency version bump takes 188s to fail instead of failing on the first attempt.

The pull output alone cannot separate the two, since quay.io answers both a degraded token service and a missing tag with a bare `unauthorized`. A manifest lookup can: `docker manifest inspect` reports `no such manifest` for a missing tag on quay.io, Artifact Registry, gcr.io and Docker Hub. `e2e_image_pull_is_retriable` now classifies the failure, consulting the manifest once on a 401 that names no reason, and drops the remaining attempts only when that lookup gives a positive permanent answer. A lookup that is itself inconclusive, which is what a degraded token service produces, leaves all seven attempts in place.

#### Useful notes for your reviewer

- The extra lookup only runs on the 401 path, and aborts on the first attempt when the tag is gone, so it costs one manifest request rather than seven. It matches `E2E_MISSING_IMAGE_ERRORS`, a narrower set than the pull output is checked against, so only a missing manifest or missing repository stops the retries. `e2e_docker_manifest_available` is untouched: it is the discriminator here, not a caller of it.
- The three new cases in `hack/testing/e2e-common_test.sh` use error strings captured from real registries, and each fails against the behavior it guards: with the manifest lookup removed the missing-tag case burns all 7 attempts; with a bare `unauthorized` restored to `E2E_NON_RETRIABLE_IMAGE_ERRORS` the degraded-registry case fails; with the probe matching the full non-retriable list, a `404 page not found` from the lookup aborts the retries and the third case fails.
