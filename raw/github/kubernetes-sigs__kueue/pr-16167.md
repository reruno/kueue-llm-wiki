#### What this PR does / why we need it?

`GetTargets` now sizes the preemptor from the assignment being admitted: it uses the assigned PodSet counts instead of the spec counts and includes `pods` when the ClusterQueue has quota for them.

This fixes target selection for both pods-bound workloads and partially admitted workload-slice replacements.

<!--

-->
Fixes #16142

#### Useful notes for your reviewer

- `TotalRequestsFor` is only used by `GetTargets`, so this change is limited to preemption target selection.
- Workloads that already hold a quota reservation can already have `pods` in their requests, so that resource is not added twice. A `TestScheduleForTAS` second-pass case guards this.

The new `TestSchedule` cases (`pods` quota, and a partially admitted workload-slice replacement) and the `TestScheduleForTASPreemption` case fail on main and pass with this change. RayCluster, RayJob, and scheduler integration tests also pass with this PR alone and with #16125 stacked on top, including the RayCluster partial scale-up case that failed there.
