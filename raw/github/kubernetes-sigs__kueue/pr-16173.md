#### What this PR does / why we need it?
Adds WAS integration tests for scenario 1 of #13534. A Pod outside Kueue holds hostPort 8080 on the node TAS would pick. A Workload needing the same hostPort goes to the other node. A second spec with a free hostPort lands on the node TAS picks on its own, so the first can't pass by accident. The first spec fails with nodeports removed from the simulator profile.

  Creating this Pod only persists it in the API; `PodUsageReconciler` observes it asynchronously and calls `TASCache().TrackPod` later. The workload is created immediately afterward, so the workload controller can admit it to `was-n1` before the holder reaches the simulator; tracking the Pod afterward does not revoke that admission. Please synchronize on the holder being observed by the manager/TAS cache before creating the workload (or use another deterministic setup), otherwise this integration test can pass without exercising the conflict and is timing-dependent.
