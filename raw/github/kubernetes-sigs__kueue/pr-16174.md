#### What this PR does / why we need it?

Zero-count workers can steer a mixed-count TAS group toward a flavor that cannot admit its current pods.

Probe only groups where every effective count is zero. Mixed groups select flavors using actual requests again, while all-zero groups retain the original capacity check and zero quota usage.

Fixes #16083

#### Useful notes for your reviewer

- TAS checks placement after choosing a flavor. It does not retry a flavor skipped by the probe.
- All-zero groups have no pods to place, so keeping their probe cannot delay current pods.
- The scheduling hash already includes ordinary per-pod requests through the effective PodSpecs.
- DRA-derived requests may need separate hash handling. That is a follow-up question, not the fix for this admission failure.

Validation: the reproducer fails before the fix and passes afterward. Nine focused integration cases and the workload/flavor-assignment unit suites pass with the race detector. Lint and whitespace checks pass.

AI assistance: Codex helped implement, review, and validate this change.
