## Description

#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it?

`kueuectl delete workload --all` listed Workloads with empty `ListOptions` (no `Limit`). Against a real API server that never returns a continue token, so every Workload was already returned in one response.

This change pages `--all` the same way `kueuectl list` does: it uses `ListRequestLimit()` (default 100, overridable with `KUEUECTL_LIST_REQUEST_LIMIT`) and follows `list.Continue` until every page is collected, then deletes.

`listRequestLimit` moved from the `list` package into `cmd/kueuectl/app/util` so delete and list share it.

Fixes #16185

#### Useful notes for your reviewer

Without `Limit`, a real API server returns the full list in one response. With a shared list limit, pagination is real, so following `Continue` is required for `--all` when there is more than one page.

The paged-list test reactor requires the previous page's continue token on later requests. `TestWorkloadCmd` covers the two-page case.

#### Release note

```release-note
kueuectl delete workload --all now pages Workload lists with the same Limit as kueuectl list (KUEUECTL_LIST_REQUEST_LIMIT) and follows continue tokens.
```
