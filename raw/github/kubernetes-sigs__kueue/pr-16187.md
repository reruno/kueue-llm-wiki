## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

The StatefulSet reconciler creates the prebuilt Workload with `nil` label and annotation copy sets and never reads the `LabelKeysToCopy` / `AnnotationsToCopy` options, so labels listed in `integrations.labelKeysToCopy` and the `CustomMetricLabels` label and annotation sources were never copied for StatefulSets.

This threads the configured sets through the StatefulSet reconciler into `NewGroupWorkload`, as the LeaderWorkerSet reconciler already does, and adds unit and integration coverage for both `CustomMetricLabels` gate states.

Fixes #13277

#### Useful notes for your reviewer

- The gap dates from #9344, which moved Workload creation from the pod group path into the StatefulSet reconciler. Since then the pods carry the prebuilt-workload annotation, so the pod controller (which copies from pod labels) never constructs the Workload, and no code path copied anything.
- Source of the copied metadata: before #9344 the labels came from the pods, i.e. the pod template. With this change they come from the StatefulSet's own metadata, consistent with LeaderWorkerSet and Job. Happy to adjust if the pod template is the preferred source.
- CodeRabbit flagged this exact line during the #13146 review; that PR only added the second `nil`.
- Verified locally: the StatefulSet unit package, the full StatefulSet integration suite (10 specs, including the two new ones), and `golangci-lint` on the root module all pass.
- AI assistance (Claude Code) was used for the investigation, the implementation, and the tests. I reviewed and verified all of it locally.
