#### What this PR does / why we need it?

Removes the standalone `TestRecordWorkloadAdmissionEvents` test and relies on the existing scheduler test tables for admission-event coverage.

The existing `TestSchedule` coverage already verifies the zero reservation-wait event through the normal scheduling path, while `TestScheduleForTAS` verifies a non-zero reservation wait during a second scheduling pass.

The missing-`QuotaReserved` fallback cannot occur through the normal scheduler admission path, so its coverage is moved to a focused table-driven `TestQuotaReservedWaitTime` unit test in `pkg/workload`.

This keeps the scheduler tests focused on real scheduling behavior while preserving coverage of the defensive helper behavior.
