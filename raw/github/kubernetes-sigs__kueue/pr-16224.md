#### What this PR does / why we need it?

Extends the TAS topology spreading E2E coverage, which so far only exists for LeaderWorkerSet, to Deployments.

The new test creates a Deployment with 4 replicas that carries the `kueue.x-k8s.io/podset-topology-spreading` annotation (block level, `maxShareAllowingPlacement: "0.5"`, `Required`) together with `kueue.x-k8s.io/podset-required-topology`. It then verifies that:

- every replica's Workload is labelled with the Deployment's UID (`kueue.x-k8s.io/job-uid`, see #15641), so the annotation works without  `workloadLabelSelectors`, and each block holds exactly 2 of the 4 replicas, i.e. they are split 2/2 across
  the two blocks of the TAS kind cluster. The pods request only 10m CPU, so all  of them would otherwise fit on a single node.

Other changes:

- Enables the `TASTopologySpreading` feature gate in the default E2E config (`controller_manager_config.yaml` and `values.yaml`), which the baseline suite uses, the same way #11095 enabled `ConcurrentAdmission`. The gate only takes effect for workloads that carry the `podset-topology-spreading` annotation, so the other tests are not affected.
- Adds `blockOfNode` to the baseline `helpers_test.go`.


Part of: #15785

#### Useful notes for your reviewer

- The PodGroup case will follow in a separate PR, as discussed in the issue.
- Verified locally with `make test-tas-e2e-baseline` (18 passed, so the existing baseline tests are unaffected by the feature gate). As a sanity check, removing the spreading annotation makes the test fail with `block bX holds 4 of the 4 replicas`.

(Disclosure: I used an AI assistant (Claude) to generate part of the E2E test code in this PR. I reviewed the generated code and verified it by running the TAS E2E tests locally, including the negative check above, before submitting.)
