#### What this PR does / why we need it?

MultiKueue currently removes completed remote objects immediately, preventing users from inspecting completed runs on worker clusters. Extend KEP-693 with an optional global retention duration, behind the default-off Alpha `MultiKueueRemoteObjectRetention` gate targeting v0.21.

The proposal defines configuration defaults, completion and early-cleanup behavior, safe cleanup across same-name runs, restart and disable behavior, and the test plan. Retaining objects does not delay scheduler quota release. Manager-side Workload retention remains independent, and the proposal documents the cleanup limitation when worker configuration is removed or reassigned.

Part of #13847

#### Useful notes for your reviewer

Documentation only, following the request for a small KEP update: https://github.com/kubernetes-sigs/kueue/issues/13847#issuecomment-5810329424. The implementation is in #14803, which now targets v0.21 and matches the behavior described here, including gating same-name replacement and the ownership checks on deletion.
