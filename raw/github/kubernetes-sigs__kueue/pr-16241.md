## Description

#### What type of PR is this?
/kind cleanup

#### What this PR does / why we need it?
Updates `ClusterQueue.Snapshot()` and `buildSnapshotSort` to read `LocalQueue` fair-sharing weights from a point-in-time copy of the cached `c.lqWeights` map (cloned under `c.rwm.RLock()` alongside `c.workloads.DumpAll()`) via a shared `lookupLQWeight` helper instead of calling `afs.ResolveLQWeight` via `client.Get`.

This aligns the `Snapshot()` fair-sharing weight lookup path with the active heap comparator (`queueOrderingFunc`), avoids API reads during snapshot sorting, and eliminates the base-ordering fallback on transient `LocalQueue` client lookup errors.

Fixes #13602

#### Useful notes for your reviewer
- `c.lqWeights` is cloned via `maps.Clone(c.lqWeights)` under the same `c.rwm.RLock()` critical section that dumps the pending workloads in `Snapshot()`, ensuring race-free and transitive comparisons even when `UpdateLocalQueueWeight`, `addLocalQueue`, or `deleteLocalQueue` run concurrently.
- AI Disclosure: AI assistance was used to help draft the code changes, unit tests, and PR description, which were reviewed and verified locally with `go test -race ./pkg/cache/queue/...`.

```release-note

```

`756-756`: _🚀 Performance & Scalability_ | _🔵 Trivial_ | _⚡ Quick win_

**Skip the weight clone when fair-sharing sorting is not needed.**

`Snapshot()` copies `c.lqWeights` while holding `c.rwm.RLock()`. The non-fair-sharing sorter ignores the map, and the fair-sharing sorter performs no weight lookup when `elements` is empty. For a ClusterQueue with many LocalQueues, this can add unnecessary O(len(c.lqWeights)) work to reachable `PendingWorkloadsInfo` snapshots. Guard the clone with fair-sharing being enabled and `len(elements) > 0`. Preserve the point-in-time copy for enabled fair-sharing snapshots with pending workloads.
