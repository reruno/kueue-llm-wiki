#### What this PR does / why we need it?
**Why**

When `enableCertManager` is true, the Helm chart already creates a metrics certificate with cert-manager and mounts it into the manager. But the `ServiceMonitor` did not use it. It always used the chart default `tlsConfig: {insecureSkipVerify: true}`, so Prometheus scraped `/metrics` without checking the certificate.

The docs did not fix this either. Helm merges the chart default into the user's `tlsConfig`, and the example in `prometheus.md` did not set `insecureSkipVerify: false`. So users who followed the docs still got `insecureSkipVerify: true`, and Prometheus ignored their `ca`.

**What**

| Configuration | Before | After |
|---|---|---|
| `enableCertManager: true`, no `tlsConfig` | `insecureSkipVerify: true`. The cert-manager certificate is never checked. | `insecureSkipVerify: false`. `serverName` and `ca` are set from the chart's metrics Service and the `<fullname>-metrics-server-cert` Secret. |
| `enableCertManager: false` | `insecureSkipVerify: true` | No change. There is no cert-manager CA to check against. |
| Custom `metrics.serviceMonitor.tlsConfig` | Merged with the default `insecureSkipVerify: true`. Verification stays off unless the user sets `false`. | Used as it is. No default values are added. |

- The default of `metrics.serviceMonitor.tlsConfig` is now `{}`.
- The Helm section of the Prometheus docs is updated:
  - Users no longer need to turn off internal cert management by hand. The chart does this when `enableCertManager` is true, unless `internalCertManagement` is set in `managerConfig`.
  - Users no longer need to set `tlsConfig`.
  - If users set their own `tlsConfig`, it replaces the generated one, so they must set `serverName` and `ca` themselves.

### Security Architecture Review

**Security architecture risk:** _🔵 Low_ · up to `f1b11`

The default cert-manager configuration now verifies the metrics server certificate. An explicitly configured internal-certificate mode may instead leave Prometheus checking a different certificate, interrupting metrics collection. No new credential exposure was established.

**Retained concerns**
- **Low · reliability · inferred:** With cert-manager enabled but internal certificate management explicitly enabled, the ServiceMonitor selects the cert-manager CA while the manager does not install the external metrics certificate watcher. If the internally served certificate differs, verified metrics scrapes fail.

<details>

- _inferred_ — The changed trust decision applies to the metrics scrape configured by this Helm release's ServiceMonitor. The inspected change does not add a metrics endpoint or grant the scraper new authority.

**Security Findings and Attack Paths**
- _observed_ — A custom TLS configuration without insecureSkipVerify still renders insecureSkipVerify: true, even if other TLS fields are supplied. **Trust Boundaries and Controls**
- _observed_ — For the generated cert-manager branch, Prometheus is configured to check the Service DNS identity against the CA in the same named Secret that supplies the manager's mounted serving certificate.

**Resilience and Maintainability Implications**
