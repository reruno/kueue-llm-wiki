#### What this PR does / why we need it?

When the wait for pods ready annotation has changed the format, but remains having the same values for the fields, that is considered as an update valid and the annotation proceeds to be validated and handled. However, we could skip such update as is not necessary and validating the annotation again could cause issues if the `maxTimeoutOnWorkload` has been updated to a value that stopped being accepted by the existent timeouts.

With the change, the following annotations are considered the same:
```
    kueue.x-k8s.io/wait-for-pods-ready: |
      {
        "timeoutSeconds": 20,
        "recoveryTimeoutSeconds": 40
      }
```
and:
`kueue.x-k8s.io/wait-for-pods-ready: '{"timeoutSeconds": 20, "recoveryTimeoutSeconds":40}'`
