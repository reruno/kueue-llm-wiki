#### What this PR does / why we need it:

Assigns the three custom-metrics end-to-end specs in the sequential baseline suite to shard 0.

When these specs were moved into the sequential suite in https://github.com/kubernetes-sigs/kueue/pull/13294, they did not receive a shard label. CI runs this suite with either the `shard-0` or `shard-1` label filter, so none of the three specs were selected. Adding `shard-0` to their shared container makes all three specs run in the shard-0 presubmit while preserving their ordered execution.

Running the specs also exposed that their setup captured the currently installed configuration. This could inherit `managedJobsNamespaceSelector` from an earlier sequential container and leave the custom-metrics namespace unmanaged. The setup now starts from the suite-level default configuration before applying its custom metrics settings, matching the other configuration-changing containers and avoiding an additional controller restart.

AI assistance was used to audit the CI label filters, diagnose the failing presubmit, prepare the changes, and validate Ginkgo spec selection. The resulting diff and validation were reviewed by the contributor.
