#### What this PR does / why we need it?

Validates RayJob and RayService creation when MultiKueue in-tree autoscaling is requested.

MultiKueue-managed elastic Ray workloads that enable in-tree autoscaling are rejected unless the `MultiKueueRayInTreeAutoscaling` feature gate is enabled. This prevents users from creating workloads whose autoscaling behavior is not supported by the active feature-gate configuration.

This change includes webhook unit coverage for both the disabled and enabled feature-gate cases for RayJob and RayService.

AI usage disclosure: This PR was developed with assistance from an AI coding tool. The contributor reviewed and tested the resulting changes.

#### Useful notes for your reviewer

This PR intentionally contains only the webhook validation and its unit tests. The runtime MultiKueue RayService autoscaling changes are handled separately.

Tests:

`go test ./pkg/controller/jobs/rayjob ./pkg/controller/jobs/rayservice ./pkg/controller/jobs/raycluster -count=1`

<details>
<summary>Security review details</summary>

**Security Blast Radius**
- _inferred_ — The affected exposure is admission of Ray objects submitted through the Kueue-managed webhook paths, rather than a demonstrated change to cluster credentials or worker-cluster authority.

**Trust Boundaries and Controls**
- _observed_ — Queue routing determines whether the webhooks call shared Kueue validation, while managedBy defaulting requires a matching MultiKueue admission check. A queue-less request can skip that validation under the inspected settings; this pre-existing condition does not establish a bypass for an executing MultiKueue workload.

**Resilience and Maintainability Implications**
- _observed_ — Update validation is conditional on queue presence or webhook settings. When it runs, each inspected Ray update webhook reruns create validation; queue-less updates can return before the new rule, as they could before this PR.

**Hardening Proposals**
- _proposed_ — Define rollout handling for already-admitted autoscaling workloads when the feature gate is disabled, since admission-time rejection does not itself reconcile their persisted state.
