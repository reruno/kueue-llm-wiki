A couple of things I noticed from this run, in case useful :)

The remaining CI failure is still the re-admit spec. It looks like the old `1 / 400m` requests are still hitting the quota boundary: the two-worker shape needs `2.3 CPU`, matching the manager's `300m more needed`. Even past that, the one-worker shape next to the 750m preemptor would be `1.9 + 0.75 = 2.65 > 2`.

Also, the new `500m` head requests make worker2 eligible for autoscale/sequential. Both workers admitted them in this run, so the existing placement boundary may no longer hold. The elastic case can similarly land on worker2, where its 1→3 shape reaches `1.25 CPU > 1.2`.

Maybe keeping the requests at their main values and raising only the limits would preserve those quota/placement boundaries while still giving the Ray Pods more CPU headroom?
