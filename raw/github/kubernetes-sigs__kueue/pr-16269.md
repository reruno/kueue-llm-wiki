## Description

#### What type of PR is this?
/kind cleanup
#### What this PR does / why we need it?
Replaces the `rejectAll` boolean in `NewCandidateFilters` with an explicit error identifying which candidate filter failed to build, and updates `PreemptionEvaluator.Candidates` to fail-fast on build errors.
Previously, candidate filter compilation failures (such as an unsupported scope, invalid label selector operator, or invalid priority mode) returned `(CandidateFilters{}, true)` and silently skipped the selector during preemption evaluation. Returning an explicit error surfaces configuration issues immediately and prevents unintended candidate evaluations.
Fixes #16147
Part of #15892
#### Useful notes for your reviewer
- Updates `NewCandidateFilters` and sub-builders in `pkg/scheduler/preemption/config/filters/` to return descriptive errors identifying the failing filter.
- Adds build-time comparison operator validation for `Priority` and `NumericLabels` filters.
- Updates `PreemptionEvaluator.Candidates` in `pkg/scheduler/preemption/config/evaluator.go` to fail-fast and return `(nil, err)` when candidate filter compilation fails, consistent with `PreemptorSelector` error handling.
- Updates test suites (`factory_test.go`, `priority_filters_test.go`, `evaluator_test.go`, `cluster_queue_label_filters_test.go`, `label_filters_test.go`) with explicit error assertions.
- AI disclosure: Prepared with AI pair-programming assistance in accordance with the Kubernetes AI Tool Usage Policy.

### Security Architecture Review

**Security architecture risk:** _🟡 Moderate_ · up to `50b01`

A configuration error can now prevent valid configurable preemption candidates from being considered. Existing preemption strategies remain available, but the broader loss of candidates merits a design-level review.

**Retained concerns**
- **Medium · reliability · inferred:** A build error in one candidate selector now discards candidates gathered from valid selectors for the same trigger. For a referenced configuration containing a malformed operator, this can reduce preemption availability beyond the failing selector; the intended all-or-nothing policy is not documented.

<details>
<summary>Security review details</summary>

**Security Blast Radius**
- _inferred_ — The effective loss is confined to configurable candidates for the affected trigger of a referenced configuration. Later eligible triggers and baseline preemption paths can still supply candidates; the number of queues sharing a configuration was not established.

**Security Findings and Attack Paths**
- _inferred_ — No new privilege or data-access path was established. The supported availability path requires control over a referenced PreemptionConfig; the PR broadens the effect of a malformed candidate selector relative to the base behavior.

**Trust Boundaries and Controls**
- _observed_ — The editor role defines write authority over PreemptionConfigs, while the inspected candidate-selector CRD field documents valid operators without enforcing them by enum. Filter construction rejects invalid selectors at evaluation time.

**Resilience and Maintainability Implications**
- _observed_ — Filter errors carry configuration, rule, and selector context, but the strategy-facing caller logs the error and treats the affected trigger as having no candidates.

**Hardening Proposals**
- _proposed_ — Define the intended behavior for mixed valid and invalid selectors. If trigger-wide failure is required, consider rejecting malformed operators before configuration reaches scheduling; otherwise preserve valid selectors when reporting build errors.
