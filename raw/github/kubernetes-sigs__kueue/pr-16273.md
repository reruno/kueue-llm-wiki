#### What this PR does / why we need it?

Match PodSets by name in `TotalRequestsFor` and in the workload-slice replacement flavor check.

When a PodSet group's members are not adjacent, the flavor assignment and a replaced slice's admission are in group order, which differs from the Workload's order. These paths paired them by position and could use another PodSet's counts or flavors. In preemption this could panic the scheduler or leave the Workload pending; in slice replacement it could compare against and subtract another PodSet's flavors and requests.

### Security Architecture Review

**Security architecture risk:** _🔵 Low_ · up to `9ebf8`

Name-based matching fixes incorrect scheduling for reordered PodSets. A narrower question remains for unusually constructed replacement workloads: an unmatched PodSet no longer receives a replacement-flavor comparison. Normal slice creation requires matching PodSet names, and no quota bypass was established.

**Retained concerns**
- **Low · security · inferred:** An annotated replacement with a PodSet name absent from the replaced slice can skip that PodSet's replacement-flavor consistency check. This is conditional on a mismatched replacement reaching the scheduler; ordinary slice creation rejects mismatched name sets.

<details>
<summary>Security review details</summary>

**Security Blast Radius**
- _inferred_ — The identified conditional behavior is bounded to workload-slice replacement within the selected ClusterQueue snapshot and namespace. The change does not itself select replacements from another namespace or queue.

**Security Findings and Attack Paths**
- _inferred_ — If a mismatched annotated replacement reaches scheduling, an unmatched PodSet skips replacement-flavor comparison. The previous positional code attempted a comparison, although it could compare the wrong PodSet; admission or resource overuse from this path was not established.

**Trust Boundaries and Controls**
- _observed_ — The replacement reference comes from a workload annotation. The scheduler's lookup checks queue membership and namespace, while the normal slice producer separately requires matching PodSet-name sets.
- _observed_ — When an old PodSet name is absent, the changed preemption-sizing calculation does not subtract an unrelated old count. Flavor eligibility and resource-quota fitting still occur in flavor selection.

**Hardening Proposals**
- _proposed_ — Validate PodSet-name-set compatibility when resolving an annotated replacement, so replacement consistency does not depend on every workload having passed through the normal slice producer.
