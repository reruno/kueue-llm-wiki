## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it?
Caps a matched PodSet's copied-forward `minCount` at its own new `count` during elastic partial scale-up. Without this, a PodSet that shrinks while another grows in the same event could end up with `minCount > count`, which hands the scheduler's reducer a negative shrink budget and can leave the scale-up stuck pending.

Fixes #16285
Relates to: #12100

#### Useful notes for your reviewer
Added a unit test on `ConstructWorkload` and an integration test that shrinks one RayCluster worker group while growing another in the same update - reverting the fix reproduces the stuck-pending failure.
