#### What this PR does / why we need it?
The TAS perf generator set `kubernetes.io/hostname` to the node's index within its rack, so the 640 nodes in configs/tas shared 64 hostnames. TAS keys a hostname-lowest topology by hostname alone, so the test has been scheduling onto 64 leaves instead of 640. This uses the unique node name instead, as on a real cluster.
configs/tas results don't change (same wall time, usage and admission times with and without the fix), because CPU quota limits admission there. So rangespec.yaml stays as is. It does matter for per-node checks like DRA device feasibility.

  **Reject generated hostnames longer than 63 characters before creating Nodes.**
  
  A 16-level topology with `Name: "a-xxxxx"` and `Count: 1` is valid, and each topology label value is only `a-xxxxx-0`. However, `buildNodeName` appends `xxxxx` for every level and produces a 116-character name. The new `kubernetes.io/hostname` label copies this name. Kubernetes limits label values to 63 characters, so `CreateNodesWithStatus` can reject the generated Node.
  
  Return a configuration error before creating any Nodes. Do not truncate the name because truncation can cause collisions.
