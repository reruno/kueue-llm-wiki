## Description

#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it:

`CohortStats` computes the dominant resource share without checking for a Cohort cycle. `calculateLendable` walks to the root with `for root.HasParent()`, which does not terminate on a cycle, so the call spins while holding `c.RLock()`.

It is the only one of the four cache-side `dominantResourceShare` callers that does not guard. `reportWeightedShare` (`clusterqueue.go:612`), `ResyncCohortGaugeMetrics` (`cache.go:613`) and `ClusterQueueStats` (`cache.go:955`) all do. This mirrors them and leaves `WeightedShare` unset.

**Not currently reachable, and I should say so up front.** The only caller is `CohortReconciler.updateCohortStatusIfChanged`, and that reconcile returns early when `AddOrUpdateCohort` reports `ErrCohortHasCycle` (`cohort_controller.go:224-228`). Cohort reconciles are serial, since `controller_manager_config.yaml` sets `Cohort.kueue.x-k8s.io: 1`. So today the guard lives in the caller instead of in the function.

That is what this changes. Raising Cohort concurrency above 1 would open an interleaving where one reconcile passes `AddOrUpdateCohort` before another persists the cycle edge, and any new caller of `CohortStats` inherits an unstated requirement to guard. If it is reached, the cost is out of proportion to the likelihood: the spin holds `c.RLock()`, so the next `c.Lock()` never returns and the scheduler cache wedges.

Reaching the walk needs `len(borrowing) > 0`, so the Cohort has to be borrowing. `TestCohortCycleRequiredGuards` already builds that state, so the regression is one call added there. Without the fix that test hangs until the `go test` timeout rather than failing, the same tradeoff the stack-overflow assertion above it already makes.

#### Which issue(s) this PR fixes:

Fixes #16310

#### Special notes for your reviewer:

#15955 removes the walk from this path, so it stops the spin too. I would still take the guard, because after that change the only thing preventing the spin is that nothing walks the tree any more.

The two have no overlapping hunks, so either can merge first.

I have reproduced the spin in a unit test. I have not reproduced the cache wedge, and I have not seen this in production.
