## Description

#### What type of PR is this?

/kind bug
/area tas

#### What this PR does / why we need it:

With `TASReplaceMultipleFailedNodes` enabled, a remaining assigned node can be absent from the snapshot before it is added to `UnhealthyNodes`. If the required topology domain cannot be determined, node replacement currently treats the empty domain as unrestricted and can place replacement Pods outside the required rack.

Reject replacement when a required topology request still has a remaining assignment but its domain cannot be determined, following the [suggested validation](https://github.com/kubernetes-sigs/kueue/pull/12344#discussion_r4122993427). Preferred topology requests and replacement of the entire assignment remain allowed.

Update the existing unit and integration tests that allowed this fallback. The integration regression verifies that an unknown required domain emits a replacement failure and leaves the original assignment unchanged even when capacity is available in another block. Existing tests continue to cover replacement within a known domain and preferred topology requests.

#### Which issue(s) this PR fixes:

Fixes #16291

#### Special notes for your reviewer:

The regression cases fail against the unmodified code by producing a cross-rack assignment. The integration regression also fails without the guard. With the fix, all 162 TAS integration specs pass using Kubernetes 1.37 envtest and the race detector. Validation:

```sh
go test -race -ldflags=-linkmode=internal ./pkg/cache/scheduler ./pkg/scheduler -count=1
KUBEBUILDER_ASSETS=/path/to/kubernetes-1.37-envtest go test -race -ldflags=-linkmode=internal ./test/integration/singlecluster/tas -count=1 -timeout=20m
git diff --check
```
