`95-108`: _📐 Maintainability & Code Quality_ | _🔵 Trivial_ | _💤 Low value_

**Calling `WorkloadsTopologyRequests` here can change the `Assignment` it is checking.**

`WorkloadsTopologyRequests` calls `a.psError` on elastic-topology errors and on errors from `podSetTopologyRequest`. It can also set `psAssignment.DelayedTopologyRequest`. `MissingTopologyAssignment` is documented as a check, but these calls mean it can change PodSet status. The cached `representativeMode` is not reset afterwards.

In most cases, the same errors already happened during `AssignTopology`, so the risk is low. Still, a read-only helper should not change state. Consider one of these options:
- Collect the TAS-requested PodSet names without calling `psError`.
- State in the doc comment that the function can mark errors.
