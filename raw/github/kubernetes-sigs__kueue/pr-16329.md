#### What this PR does / why we need it?

During a rolling update, the StatefulSet and LeaderWorkerSet reconcilers removed both scheduling gates from Pods at the current revision without checking whether the Workload was admitted, so those Pods could run without quota. With `rollingUpdate.partition` the rollout never completes, so this lasts for as long as the partition is set. For StatefulSets, a Pod created during the rollout also stayed gated forever, because its defaulting and the ungating went into one patch that the Pod webhook rejects. This PR leaves the ungating of these Pods to the Workload admission, still ungates Pods whose StatefulSet is gone, and removes the LeaderWorkerSet StatefulSet watch that only served the rollout rule.
