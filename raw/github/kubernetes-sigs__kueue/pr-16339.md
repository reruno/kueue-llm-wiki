#### What this PR does / why we need it?

TAS releases a Workload's reservation when it becomes inactive or finishes, but a bound, nonterminal Pod can continue occupying node resources. Previously, TAS Pods were excluded from the existing non-TAS Pod usage cache, so a subsequent TAS snapshot could treat that node as free.

Track bound, nonterminal TAS Pods from Pod events and aggregate their node usage by Workload. On each scheduler snapshot, add that physical usage when the Workload no longer has an active TAS reservation. If the name has been reused and the old Pod has a distinguishable owner or PodGroup UID, count that Pod even while the new Workload has a reservation. The existing reservation continues to cover normally admitted Pods, avoiding double counting. Pod termination, deletion, resource-request reduction, and Workload-annotation or owner changes update the cache and requeue workloads when capacity may have been freed. The snapshot does not list Pods.

Regression coverage observes the old Workload's ClusterQueue reservation appear and then disappear, verifies the new Workload reaches a TAS no-fit result and stays Pending while the old Pod remains bound, and then verifies admission after the Pod is removed. Unit tests cover active-reservation exclusion, distinguishable same-name owner replacement, PodGroup UID replacement, residual aggregation across nodes and Workloads, deletion/termination, request-key removal, zero-request Pod slots, and changes in the Pod's Workload reference.

Fixes #16337

#### Useful notes for your reviewer

- Related: #10076 (Finished/Terminating case). This is a smaller new implementation, not a continuation of the closed draft #10820.
- The fix intentionally does not address excess or relocated Pods, fully reclaimed PodSets, or ambiguous ownership while a Workload still holds an active TAS reservation. It also does not delete Pods when a Workload becomes inactive or Finished.
- Local validation: scheduler-cache and TAS-controller package tests and focused race tests pass; `go vet` passes on both packages. Three focused single-cluster TAS integration specs pass using envtest Kubernetes 1.37.0. As a negative control, temporarily disabling residual TAS Pod usage made the inactive-Workload regression fail by admitting the second Workload; the code was restored and retested. A snapshot benchmark with 1,000 tracked Pods takes about 99 microseconds per operation on the local host; this is a benchmark observation, not a CI guarantee.
- AI assistance was used in the development and review of this change.

#### Release note

```release-note
TAS: Bound Pods whose Workload no longer has an active reservation continue to count against node capacity until the Pods terminate or are deleted.
```
