#### What this PR does / why we need it?
**Why**
The Helm e2e tests (`E2E_USE_HELM=true`, all `*-helm` make targets) do not test the same Kueue configuration as the kustomize e2e tests.

The Helm path has its own copy of the controller manager configuration inside test/e2e/config/{default,certmanager}/values.yaml. Nobody kept this copy in sync, and it is now wrong in 2 ways:

The kustomize e2e config enables the gates inside the configuration file:

- **No feature gates are enabled.**
  - **kustomize side**: `test/e2e/config/default/controller_manager_config.yaml`
https://github.com/kubernetes-sigs/kueue/blob/662c47d3653973f8e0648314f420eabf05c755b8/test/e2e/config/default/controller_manager_config.yaml#L39-L43
  - **Helm side**: `test/e2e/config/default/values.yaml`
https://github.com/kubernetes-sigs/kueue/blob/662c47d3653973f8e0648314f420eabf05c755b8/test/e2e/config/default/values.yaml#L30-L38

- **Some settings are missing:**
  - **kustomize side**: https://github.com/kubernetes-sigs/kueue/blob/662c47d3653973f8e0648314f420eabf05c755b8/test/e2e/config/default/controller_manager_config.yaml#L24-L26
  - *Helm side**: https://github.com/kubernetes-sigs/kueue/blob/662c47d3653973f8e0648314f420eabf05c755b8/test/e2e/config/default/values.yaml#L63-L64 

**What**

- Remove the copied configuration from `default/values.yaml` and `certmanager/values.yaml`. 
- Change `helm_install` to take the manager configuration from the kustomize e2e configuration. Now there is only one place to edit, and both install paths use it.

**How**
`helm_install` gets a third argument: the kustomization directory. This is the same directory the kustomize path uses: `test/e2e/config/${E2E_CONFIG_FOLDER:-default}`, or `test/e2e/config/certmanager`. The function:

1. runs `kustomize build` on that directory,
2. uses `yq` to take the `controller_manager_config.yaml` data from the `kueue-manager-config` ConfigMap,
3. passes it to the chart with `--set-file managerConfig.controllerManagerConfigYaml=<file>`.
