## Description

#### What type of PR is this?

/kind cleanup
/area tas

#### What this PR does / why we need it?

TAS stores whole-slice capacities for the ordinary, leader, tail, and leader-plus-tail cases in separate fields. As discussed in #15981, moving only the leader fields into a separate struct would not capture the combinations with a partial tail cleanly.

This PR consolidates the four slice capacities in `domainState.sliceCount [4]int32`, indexed by an `obligationMask`. It updates the calculation and placement paths to use the corresponding array entries without changing their existing behavior.

Fixes #15981

#### Useful notes for reviewer

This follows [pajakd's suggestion](https://github.com/kubernetes-sigs/kueue/issues/15981#issuecomment-5789737298) rather than introducing `leaderDomainState`. Unit tests cover all four mask combinations and the distinction between a tail that cannot fit and one that fits alongside zero whole slices.

Local checks: scheduler tests with `-race`, formatting verification, and scheduler lint passed.

**Explanation**

Issue [`#15981`] requires a dedicated `leaderDomainState` owned by `domainState`. The PR instead stores all capacities in `domainState.sliceCount [4]int32`. `podCountWithLeader` and `leaderCount` remain top-level fields in `domainState`, so the leader-only state is not isolated as requested. The mask-based lookups improve capacity separation, but they do not implement the issue's explicit state isolation requirement.

**Resolution**

Add a dedicated `leaderDomainState` to `domainState`. Move the leader-only fields, including `podCountWithLeader`, `leaderCount`, and leader-specific slice capacities, into that state. Update leader and leaderless placement paths and tests so leaderless placement does not depend on leader-only fields.
