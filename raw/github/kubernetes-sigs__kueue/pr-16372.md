#### What this PR does / why we need it?

The custom-label pending-workload integration tests manually pop and requeue a Workload to make it inadmissible while the queue manager's asynchronous requeuer is running. ClusterQueue creation schedules a retry with a 100ms batch period in integration tests. If that retry runs between the manual pop and requeue, or after the workload becomes inadmissible but before the metric assertion, the workload is active instead and the expected inadmissible count times out.

Move the manually constructed active/inadmissible metric coverage into table-driven queue unit tests with the existing synchronous requeuer. Drain initialization retries before creating inadmissible state, then cover separate active/inadmissible counts, merging workloads with the same labels while stopped, and requeue on resume. Keep the integration test for ClusterQueue stop/resume with initially active workloads so it no longer depends on a transient queue state. This also replaces the adjacent inadmissible-count integration test that has the same race.

Observed while testing https://github.com/kubernetes-sigs/kueue/pull/16370. The failure is independent of that PR's child-job lifecycle changes.

Closes #16559, which reports a flake in the adjacent `should track inadmissible pending workloads` integration test replaced by deterministic unit coverage in this PR.
