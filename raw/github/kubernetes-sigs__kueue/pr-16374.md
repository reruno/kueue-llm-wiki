#### What this PR does / why we need it?

For example, this `PreemptionConfig` has an invalid matchExpressions requirement: `operator: In` must have at least one value, but values is empty.

```
apiVersion: kueue.x-k8s.io/v1alpha1
kind: PreemptionConfig
metadata:
  name: empty-in-values
spec:
  rules:
    - name: select-preemptible
      activationPolicy:
        trigger: Always
      candidateSelectors:
        - scope: WithinClusterQueue
          labelSelector:
            matchExpressions:
              - key: preemptible
                operator: In
                values: []
```

The error is detected when the candidate filter is built. Previously, `orderedCandidates` funtion logged the error but returned `nil` candidates, so its caller could mistake the failure for “no Workloads matched” . Even if the cluster contains potentially preemptible Workloads, the failed rule appears to have found none, which may cause subsequent applicable rules to be evaluated under that mistaken assumption.


The fix propagates the error and stops this configurable-preemption evaluation.
