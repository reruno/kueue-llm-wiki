#### What this PR does / why we need it?

Adds an E2E test for TAS topology spreading with Pod groups, following the Deployment test in #16224 .

- Adds a test to `tasapi/baseline/pod_group_test.go` that creates 4 pod groups of 2 pods each, all in one spread group, with `maxShareAllowingPlacement: 0.5` at the block level. It checks that:
  - each pod group's Workload carries the `spread-group` label;
  - the pods of each group land in a single block;
  - each block holds exactly 2 of the 4 groups.
- Adds `spread-group` to `integrations.labelKeysToCopy` in `test/e2e/config/default/controller_manager_config.yaml`, the same setting the extended config already has.

Fixes #15785

#### Useful notes for your reviewer

- Pod group Workloads have no `job-uid` label, so the default spreading selector doesn't match any of them. The test sets `workloadLabelSelectors` on the `spread-group` label instead, and `labelKeysToCopy` copies that label from the pods onto each group's Workload.
- All groups use the same pod spec, so their PodSets share a name and are counted against each other.
- The pods request only 10m CPU, so all 4 groups would fit in one block. The 2 + 2 split can only come from the spreading rule.
- A CPU quota is added to the existing TAS ClusterQueue in this `When` block. The other tests there request only GPUs, so they are not affected.
- Negative check: without `workloadLabelSelectors`, all 4 groups landed in the same block and the test failed.
- AI disclosure: Part of the code was generated with the help of an AI assistant (Claude). I reviewed and tested all changes myself.
