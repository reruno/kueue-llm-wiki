#### What this PR does / why we need it?

This PR improves observability for TAS topology spreading.

When a Workload has a `Required` spreading rule, the rule can ban some
topology domains. If the remaining domains don't have enough capacity, the
Workload waits. Before this PR, the pending message only talked about
capacity, and nothing was logged about spreading. So it looked like the
Workload was only waiting for capacity, and users couldn't tell that
spreading was part of the reason.

This PR:
- Adds to the pending message how many domains topology spreading excluded,
  for example: `...; topology spreading excluded 1 topology domain(s) at level: cloud.com/topology-block`.
- Adds a `V(3)` log when placement fails and spreading banned some domains.
  The log includes the Workload, the PodSet, the searched level, the banned
  domains and the rules.

#### Useful notes for your reviewer

- `filterOutBannedDomains` now returns both the allowed and the banned
  domains. The banned ones are kept on the placement state, so the message
  and the log can use them.
- The log is at `V(3)`, which matches the "Balanced placement algorithm
  failed" log in the same function.
- `domainIDs` moved from a test file to production code, so the log can use it.

This PR was prepared with the help of an AI assistant (Claude Code) and
reviewed by me.
