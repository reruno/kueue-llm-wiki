#### What this PR does / why we need it?

When a Cohort update creates a cycle, the scheduler cache already applies the new parent, but the Cohort reconciler returns before updating the queue manager and, since #13774, no longer retries. If another Cohort then resolves the cycle, for example when swapping two Cohorts' parents, the queue manager's hierarchy no longer matches the cache, so freeing quota can skip requeueing ClusterQueues that are now in the same tree. Today a ClusterQueue status update re-enqueues the ancestor Cohorts and repairs this indirectly. This PR also updates the queue manager in the cycle branch, which already skips requeueing while the tree has a cycle, and adds an integration test for the swap.
