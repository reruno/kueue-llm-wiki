#### What this PR does / why we need it?

`QueueSecondPassIfNeeded` currently returns `false` when the Workload is already prequeued for another second pass. `requeueAndUpdate` interprets that as "not requeued"; since `RequeueWorkload` refuses a Workload that still holds a quota reservation, a `notNominated` or `skipped` entry can fall through and unset that reservation. For a failed-node replacement, this can also clear the Workload's admission.

Treat an already-prequeued second pass as handled by returning `true`: the pending pass re-reads the Workload and retries it. `prequeueIfAbsent` still prevents another timer from being armed, so this keeps #13745's single-pending-timer behavior.

This is the #16330 part of the split discussed in https://github.com/kubernetes-sigs/kueue/pull/14078#issuecomment-5905201360

#### Useful notes for your reviewer

- Return-value impact: the scheduler now keeps an already-prequeued Workload in the second-pass flow. The workload controller ignores the return value, and the snapshot-error path only skips a `RequeueWorkload` call that would reject the reserved Workload anyway.
- Coverage: the queue test checks both the `true` result and that no duplicate timer is armed. The scheduler regression test covers delayed topology assignment and failed-node replacement, including the FailFast-disabled and stopped-ClusterQueue paths.
