## Description

#### What type of PR is this?

/kind documentation
/area dra

#### What this PR does / why we need it?

Add setup instructions and a Job example for the `firstAvailable` support merged in #14130: the gate and DeviceClass mapping, how to read the alternative a Pod received from its generated ResourceClaim, how to clean up, and a short troubleshooting entry. The design and the limitations stay on the concept page, which the setup section links to.

The example DeviceClasses are mocks for the dra-example-driver; they select the same devices and show the charge, not an A100/MIG fallback.

Follow-up to #13601 (requested in https://github.com/kubernetes-sigs/kueue/pull/13601#issuecomment-5923924539) and #14130. Related: #16346, whose accounting and test cleanup stay separate.

#### Useful notes for your reviewer

Documentation and example manifests only; the supported request forms and the accounting are unchanged.

The pages were followed end to end on a kind cluster (Kubernetes v1.34.8, Kueue v0.20.0 release manifests, dra-example-driver v0.5.0): the example Job was charged `example.com/gpu: 1` and its claim read `gpu/a100`. A test-only template with an unsatisfiable first alternative was charged the same `1` and read `gpu/mig`; mismatched counts and an unmapped class were refused with `DRAResourcesUnresolved`; deleting the Jobs left no ResourceClaim.

For the `/v0.20/docs/` snapshot this also needs a `release-0.20` cherry-pick.

AI assistance (Claude Code) was used to draft the documentation and the validation scripts and to check the claims against the code.
