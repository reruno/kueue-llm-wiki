#### What this PR does / why we need it?
Requires `SkipChildJobSuspension` when `MultiKueueRayInTreeAutoscaling` is enabled. Kueue now rejects configurations that enable MultiKueue Ray autoscaling while leaving child job suspension enabled, including when the bypass gate is omitted and defaults to false.

The motivation is the child-job suspension race described in https://github.com/kubernetes-sigs/kueue/pull/16370. During MultiKueue workload-slice replacement for Ray autoscaling, the old remote Workload can be marked finished before the replacement is claimed by the remote parent job. The generic child-job reconciler can then find no unfinished Workload through the ancestor owner reference and suspend a running child, such as a RayJob's RayCluster, even when the replacement Workload already has admission.

Setting `SkipChildJobSuspension=true` bypasses this child suspension path and leaves the child lifecycle to the ancestor job's controller. Requiring it as a dependency of `MultiKueueRayInTreeAutoscaling` makes Kueue reject the unsafe gate combination at startup instead of allowing an unexpected child suspension during autoscaling.

Adds configuration and CLI regression coverage for invalid and valid gate combinations. The existing MultiKueue Ray autoscaling E2E configuration already enables the required gate on `main`.
