## Description

#### What type of PR is this?
/kind bug

/area release

#### What this PR does / why we need it?
`/merge-main-into-website` failed with `index.lock: File exists` when `git merge -X theirs` hit a rename/delete conflict. The resolution loop read unmerged paths with process substitution, so `git diff` could still hold the index lock while `git checkout --theirs` or `git add` ran.
The action now writes that path list to a temp file and resolves conflicts only after `git diff` exits. Content conflicts still prefer main via `-X theirs`. Rename/delete conflicts still prefer main via `git checkout --theirs`, or `git rm` when main deleted the path, then commit and push `website`.

Fixes #16455
Part of #12763
