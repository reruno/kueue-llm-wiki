#### What this PR does / why we need it?

When a worker cluster is removed from a MultiKueueConfig, the workload reconciler only reads the clusters left in the config. It no longer sees the remote Workload on the admitting cluster, so it retries the admission check right away and dispatches the job to another cluster, while the original remote Workload and Job keep running on the removed cluster.

This PR keeps reading the admitting cluster while its MultiKueueCluster exists, so the Workload keeps running there until it finishes and its remote objects are then cleaned up. Removing a cluster from the config now only stops new dispatches to it. A disconnected admitting cluster gets the usual `workerLostTimeout` grace, and a Workload whose admitting cluster has no MultiKueueCluster is still retried right away.

## AI summary

When a workload’s admitting `MultiKueueCluster` is removed from the config, Kueue now continues to track that cluster while its controller exists. This lets the workload finish there and allows Kueue to clean up its remote Workload and Job. The removed cluster receives no new dispatches. If it disconnects, Kueue applies the usual `workerLostTimeout`; if its `MultiKueueCluster` no longer exists, Kueue retries the workload immediately.
