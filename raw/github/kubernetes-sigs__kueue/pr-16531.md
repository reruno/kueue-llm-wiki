#### What this PR does / why we need it?

**Why:** `kueuectl create clusterqueue` merges flavors that cover the same set of resources into one resource group, but keeps each flavor's resources in the order the user typed them. The webhook matches `flavors[i].resources[j]` to `coveredResources[j]` by position, so `--nominal-quota "alpha:cpu=1;memory=1,beta:memory=2;cpu=2"` is rejected with `must match the name in coveredResources`, and `--dry-run=client` prints an invalid object.

**What:**
- `cmd/kueuectl/app/create/create_clusterqueue.go`: sort a merged flavor's resources into the group's `coveredResources` order; borrowing and lending limits move with their resource.
- The existing unit case for this scenario expected the invalid order; it now expects the fixed one, and a new case covers limits on the reordered flavor.
- A new integration test creates such a ClusterQueue through the real webhook; it failed before the fix.
