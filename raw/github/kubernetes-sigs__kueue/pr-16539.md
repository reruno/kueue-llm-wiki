## Description

DeletionGracePeriodSeconds is specified in seconds but the code passes it directly to time.Duration which treats the value as nanoseconds. A Pod with a 30s grace period would log terminated after 1m0.00000003s instead of the expected 1m30s.

The termination timing itself is unaffected because it uses deletionTimestamp + forcefulTerminationGracePeriod directly. Only the status message and event text are wrong.

Fix: multiply by time.Second so the conversion is correct per KEP-6757.

Closes #16497

release-notes: [BUGFIX] FailureRecovery pod termination message now reports correct grace period when pods have a non-zero deletionGracePeriodSeconds.
