<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/onsi/gomega/releases">github.com/onsi/gomega's releases</a>.</em></p>
<blockquote>
<h2>v1.44.0</h2>
<h3>Fixes</h3>
<ul>
<li><code>BeNumerically</code> compares signed and unsigned integers by value: <code>-1</code> no longer equals <code>uint64(math.MaxUint64)</code> and <code>uint(5)</code> is now greater than <code>-3</code> (<a href="https://redirect.github.com/onsi/gomega/issues/925">#925</a>) [26e3c6b]</li>
<li><code>BeNumerically(&quot;~&quot;)</code> no longer overflows when computing the distance between extreme integers (<a href="https://redirect.github.com/onsi/gomega/issues/928">#928</a>) [1955764]</li>
<li><code>BeNumerically(&quot;==&quot;, x, threshold)</code> now honors the threshold for floats, as it already did for integers (<a href="https://redirect.github.com/onsi/gomega/issues/927">#927</a>) [10e2aca]</li>
<li><code>HaveKeyWithValue</code> succeeds if any key accepted by the key matcher has a matching value, rather than depending on map iteration order (<a href="https://redirect.github.com/onsi/gomega/issues/929">#929</a>) [ffc577a]</li>
<li><code>HaveKey</code> and <code>HaveKeyWithValue</code> treat key and value matcher errors like <code>ContainElement</code> does: a match wins, and an error is only reported when nothing matches (<a href="https://redirect.github.com/onsi/gomega/issues/926">#926</a>) [dc91598]</li>
<li><code>MatchJSON</code> no longer treats numbers too large for a float64 as equal to one another (<a href="https://redirect.github.com/onsi/gomega/issues/930">#930</a>) [9d619a5]</li>
<li><code>MatchJSON</code> compares integers beyond ±2^53 exactly, so neighboring large integers (e.g. IDs) no longer match; all other numbers are still compared as float64s (<a href="https://redirect.github.com/onsi/gomega/issues/931">#931</a>) [8ef1aa7, 630fe12]</li>
<li><code>HaveExactElements</code> reports missing or extra elements that start at index 0, and reports the first extra element's index rather than the last (<a href="https://redirect.github.com/onsi/gomega/issues/934">#934</a>) [af1b777]</li>
<li><code>MatchYAML</code> compares every document in a multi-document stream rather than only the first; empty documents (e.g. a leading or trailing <code>---</code>) are ignored (<a href="https://redirect.github.com/onsi/gomega/issues/933">#933</a>) [2773796]</li>
<li><code>MatchXML</code> ignores namespace prefixes: elements and attributes are compared by namespace URI, and the URIs declared on each element must match whatever prefix they are bound to (<a href="https://redirect.github.com/onsi/gomega/issues/932">#932</a>) [c0dbd89, 2565350]</li>
</ul>
</blockquote>
