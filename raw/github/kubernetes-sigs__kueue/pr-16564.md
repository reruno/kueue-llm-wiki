<p><strong>Patch releases:</strong> Review the patch release notes leading up to this version, but <em>only</em> within this minor release line; see: <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.1"><code>v0.19.1</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.2"><code>v0.19.2</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.3"><code>v0.19.3</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.4"><code>v0.19.4</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.5"><code>v0.19.5</code></a>.</p>
</li>
<li>
<p>DRA: Fixed a bug where a chargeable Pod overhead or a resource-transformation output that shared a name with a DRA-backed extended resource was taken back along with the DRA charge and dropped from quota accounting. Only the containers' own request is subtracted now, so any such contribution left under the original <code>extendedResourceName</code> after <code>excludeResourcePrefixes</code> and transformations is preserved. Also fixed a restartable init (sidecar) container being maxed against the total instead of added to it, so its devices are counted alongside the regular containers'.</p>
<p>When a <code>deviceClassMappings</code> entry maps a DeviceClass to a different logical name, ClusterQueues must cover that logical name. A container-only request is fully translated and needs quota only on the logical name; cover the original <code>extendedResourceName</code> as well only if a Workload leaves chargeable Pod overhead or a resource-transformation output under it (normally in the same resource group). With such a residual uncovered, <code>BlockUndeclared</code> makes the Workload wait with the original name reported unavailable, while <code>IgnoreUndeclared</code> skips the residual and leaves it out of recorded usage. Where no mapping renames the DeviceClass, or the mapped name is the <code>extendedResourceName</code> itself, the device charge and the residual land on that one key, so its corrected usage can rise: a container asking for 1 with 1 of chargeable overhead now records 2 where it recorded 1. No second key is needed there, but the nominal quota has to cover the pair rather than a count of devices. The change applies as Workloads are evaluated, not to existing reservations at once. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15987">#15987</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</p>
</li>
<li>
<p>SparkApplication: Fixed a bug where Workloads reserved less CPU and memory than Spark requests for the driver and executor Pods, because <code>cores</code>, <code>memoryOverhead</code> and Spark's default memory overhead were ignored. Kueue now reserves the same CPU and memory that Spark requests. Memory values must use the Java format accepted by Spark (for example <code>512m</code> or <code>2g</code>); Kubernetes-style values such as <code>512Mi</code> are rejected.</p>
</li>
</ul>
<p>If SparkApplications rely on <code>cores</code> or on the default memory overhead, raise the ClusterQueue quotas accordingly: each Pod now reserves its <code>cores</code> as CPU and at least 384Mi of additional memory. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15923">#15923</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</p>

<li>Fixed a bug where an evicted Workload for a StatefulSet or LeaderWorkerSet that had no Pods (for example, scaled to zero) kept its quota reserved, which blocked other Workloads in the ClusterQueue. Kueue now releases the reservation. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16128">#16128</a>, <a href="https://github.com/gola"><code>@​gola</code></a>)</li>
<li>Job: Fixed a bug where a Job with <code>parallelism</code> greater than <code>completions</code> could release the quota of its still-running Pods once some Pods succeeded, allowing the ClusterQueue to admit Workloads beyond its quota. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16132">#16132</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>Job: Reject partial-admission minimum parallelism values outside the int32 range. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16002">#16002</a>, <a href="https://github.com/cryo-zd"><code>@​cryo-zd</code></a>)</li>
<li>MultiKueue: Fixed a bug that left <code>Active.ObservedGeneration</code> stale after a healthy configuration update. Kueue now records the latest evaluated generation. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15989">#15989</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>Pod: Added the <code>PodIntegrationCountSucceededPodsAsReady</code> feature gate (Alpha, disabled by default). When enabled, succeeded pods count as ready for <code>PodsReady</code>, which fixes a bug where a pod group could be evicted after <code>waitForPodsReady.recoveryTimeout</code> once one of its pods completed. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15910">#15910</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>ProvisioningRequest: Fixed a bug where a pre-existing <code>PodTemplate</code> at the deterministic name could be adopted verbatim, letting a user who can write <code>PodTemplate</code> objects decouple the capacity requested from Cluster Autoscaler from the quota-checked Workload PodSets. Kueue now replaces divergent specs with Kueue-derived contents. Gated by <code>EnforceProvisioningPodTemplateContents</code> (Alpha, disabled by default). (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16070">#16070</a>, <a href="https://github.com/vladikkuzn"><code>@​vladikkuzn</code></a>)</li>
<li>RBAC: Fixed a bug where a subject bound to <code>kueue-batch-admin-role</code> had no access to <code>AdmissionCheck</code>, <code>MultiKueueCluster</code>, <code>MultiKueueConfig</code>, <code>ProvisioningRequestConfig</code> and <code>WorkloadPriorityClass</code> (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16032">#16032</a>, <a href="https://github.com/HsiuChuanHsu"><code>@​HsiuChuanHsu</code></a>)</li>
<li>Ray integrations: Reject Kueue-managed jobs whose head Pod template has no containers during admission. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16084">#16084</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
<li>RayJob: Fixed a bug where a RayJob using the default submitter Job (<code>submissionMode: K8sJobMode</code> without <code>submitterPodTemplate</code>) and a head Pod template with no containers caused the Kueue webhook and reconciler to panic. Kueue now returns an error instead. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16065">#16065</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>ResourceTransformations: Fixed a bug where excluding a transformation input could let a Workload bypass ClusterQueue quota accounting. Kueue now accounts for the transformed output. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16053">#16053</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>SparkApplication: Fixed a bug where a SparkApplication that only set the SparkApplication-level <code>spec.nodeSelector</code> permanently lost it after the first eviction, letting the driver and executor pods be scheduled onto any node once re-admitted. The selector is now recorded in the Workload PodSets, so it also participates in ResourceFlavor matching. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15797">#15797</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>StatefulSet: Fixed a bug that allowed invalid TAS annotations in StatefulSet updates when TopologyAwareScheduling is enabled. Kueue now validates TAS metadata during updates. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16104">#16104</a>, <a href="https://github.com/thuongvu"><code>@​thuongvu</code></a>)</li>
<li>TAS: Fix a bug where StatefulSet integration didn't validate pod template metadata for topology annotations. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15881">#15881</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>TAS: Fixed a bug that could cause workload admission to fail with topology level not specified when the unconstrained topology annotation was set to &quot;false&quot;. Kueue now rejects this value when the TASRejectFalseUnconstrainedTopology feature gate is enabled. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15847">#15847</a>, <a href="https://github.com/cryo-zd"><code>@​cryo-zd</code></a>)</li>
<li>TAS: Fixed a bug where, with the <code>SchedulerLibraryIntegration</code> feature gate enabled, ResourceFlavor tolerations and admission-check PodSetUpdates (for example a ProvisioningRequest nodeSelector) were not applied to the simulated pod, so a workload could stay pending on a tainted node or be assigned to a node its nodeSelector excludes. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16121">#16121</a>, <a href="https://github.com/pajakd"><code>@​pajakd</code></a>)</li>
<li>TrainJob: Fixed a bug where an evicted or unadmitted TrainJob emitted a <code>Stopped</code> event and sent a redundant PATCH request on every reconcile. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15754">#15754</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>

<li>Workloads: Fixed a bug where a Workload with pod-level requests smaller than its aggregate container requests could reserve too little quota.
