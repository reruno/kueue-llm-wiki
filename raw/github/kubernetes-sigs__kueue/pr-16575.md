## Description

#### What type of PR is this?

/kind flake

#### What this PR does / why we need it:

`TestAmountFromQuantityAtAFarScale` compared allocation counts from a single run of each path, and that isn't stable under `-race` on Go 1.26. `(*big.Int).String` takes its scratch space from a `sync.Pool` there, and race builds drop one `Pool.Put` in four at random, so either run can count a few extra allocations. That's what failed the release-0.19 unit job on #16570.

Both paths are now measured over 100 runs, like `TestAmountFromQuantityInRangeDoesNotAllocate` does. The comparison stays strict. Without the float check in `AmountFromQuantity` the test still fails, with 42 vs 8 allocations for `10e999999` of CPU.

#### Which issue(s) this PR fixes:

Related: #16573

#### Special notes for your reviewer:

On the release-0.19 cherry-pick with go1.26.6, `go test -race -count=20` of this test failed 10 times before the change, and `-count=300` passed after it. Go 1.27, which main and release-0.20 use, no longer pools small scratch allocations in math/big (golang/go#73999), so the counts don't vary there and #16571 passed.

#16570 needs this as well. I can open a manual cherry-pick of both to release-0.19 once this merges.
