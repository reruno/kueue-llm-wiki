## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

When a `Cohort` has `spec.fairSharing.weight: 0` and is borrowing quota, `DRS.PreciseWeightedShare()` returns `math.Inf(1)` (`+Inf`).

In #7338 (`4d8832042`), both `ClusterQueueWeightedShare` and `CohortWeightedShare` help strings in `pkg/metrics/metrics.go` were updated to state:
> `If the Cohort has a weight of zero and is borrowing, this will return NaN.`

However, #7338 only added the `if weightedShare == math.Inf(1) { weightedShare = math.NaN() }` conversion in `ClusterQueueReconciler.updateCqStatusIfChanged` (`pkg/controller/core/clusterqueue_controller.go`), while `CohortReconciler.updateCohortStatusIfChanged` (`pkg/controller/core/cohort_controller.go`) and `Cache.ResyncGaugeMetrics` (`pkg/cache/scheduler/cache.go`) continued reporting the raw `Cohort` share (which #10552 (`b13b07c86`) later moved into `Cache.ResyncCohortGaugeMetrics`).

This PR:
- Converts `+Inf` (`math.Inf(1)`) to `math.NaN()` before calling `metrics.ReportCohortWeightedShare` in both `CohortReconciler.updateCohortStatusIfChanged` (`pkg/controller/core/cohort_controller.go`) and `Cache.ResyncCohortGaugeMetrics` (`pkg/cache/scheduler/cache.go`).
- Preserves `cohort.Status.FairSharing.WeightedShare = WeightedShare(stats.WeightedShare)` (`math.MaxInt64`) in the Kubernetes status subresource (which cannot serialize `NaN` or `+Inf` in `int64`).
- Adds unit tests in `pkg/cache/scheduler/cohort_metrics_test.go` and `pkg/controller/core/cohort_controller_test.go`, and an integration test in `test/integration/singlecluster/scheduler/fairsharing/fair_sharing_test.go`.

Fixes #16530

#### Useful notes for your reviewer

- Git history confirms `NaN` is the intended metric value: #7338 (`4d8832042`, *"report NaN instead of max_int when weight is 0"*) updated the metric help text for both `kueue_cluster_queue_weighted_share` and `kueue_cohort_weighted_share` to `NaN` when switching the gauges to `float64`.
- AI assistance (Gemini) was used for codebase history lookup and test drafting; all changes were reviewed and verified locally.
