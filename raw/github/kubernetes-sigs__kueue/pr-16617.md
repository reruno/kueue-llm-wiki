#### What this PR does / why we need it?

#16556 bumped `rayproject/ray` in `hack/testing/ray/Dockerfile` from `2.58.0` to `2.58.0.904890`. That tag is a Docker Hub build of a commit on Ray's `releases/2.58.0` branch, 9 commits before the `ray-2.58.0` git tag, and it is not a PyPI release. `RAY_VERSION` is cut from this tag, and `ray-project-mini-image-build` runs `pip install ray[default,serve]==${RAY_VERSION}`, so `periodic-kueue-push-images` fails with `No matching distribution found for ray==2.58.0.904890`. Only `image-pushing-periodic` builds that image, which is why #16556 merged green.

This PR reverts to `2.58.0` with the digest it had before #16556, and adds `verify-ray-version` to `verify-checks`. It requires `RAY_VERSION` to be a plain `X.Y.Z`, so the next Dependabot bump to a `X.Y.Z.<short-sha>` tag fails `pull-kueue-verify-main` instead of the periodic. Dependabot proposed this tag because its pre-release check ([`Tag#looks_like_prerelease?`](https://github.com/dependabot/dependabot-core/blob/2cf1d5e8cc9b2fbb2f6f0d6779ac80d3f1ab49b9/docker/lib/dependabot/docker/tag.rb#L43-L74)) only flags hex suffixes that mix digits and letters, so the all-digit `904890` passed as a normal version.

#### Useful notes for your reviewer

- `dependabot.yml` has no option to skip these tags: Dependabot sorts `2.58.0.904890` above `2.58.0`, and `ignore.versions` has no pattern form. So the check is the guard, and a red Dependabot PR just needs to be closed.
- `make ray-version-verify` fails on `2.58.0.904890`, `2.58.0-py312` and `v2.58.0`, and passes on `2.58.0`.
