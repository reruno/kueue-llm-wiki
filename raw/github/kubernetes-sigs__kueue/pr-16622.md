## Description

#### What type of PR is this?

/kind bug
/area multikueue

#### What this PR does / why we need it?

MultiKueue workload counter series were not removed when a ClusterQueue or MultiKueueCluster was deleted. This left stale metric series behind and caused recreated objects with the same names to continue from the old counter values.

This PR:

- clears dispatched, admitted, and evicted MultiKueue workload counters when a MultiKueueCluster is removed;
- clears the same counters when a ClusterQueue is deleted through the always-on core ClusterQueue delete handler;
- keeps `ClearMultiKueueClusterQueueMetrics` limited to status-gauge cleanup, since it is also used during normal reconciliation and must not reset counters;
- adds tests covering cleanup by worker cluster and ClusterQueue while preserving unrelated metric series.

Fixes #16615

#### Useful notes for your reviewer

The ClusterQueue counter cleanup is intentionally wired into the core ClusterQueue Delete handler rather than the feature-gated MultiKueue ClusterQueue reconciler, so it also works when `MultiKueueManagerQuotaAutomation` is disabled.
