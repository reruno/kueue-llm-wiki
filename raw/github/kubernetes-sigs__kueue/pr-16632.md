#### What this PR does / why we need it?

**Why:** When two flavors cover overlapping but different resources, `kueuectl create clusterqueue` fails with only `invalid resource group`. The check runs in kueuectl before any request is sent, so the user gets no hint of which flavors or resources conflict.

**What:**
- `cmd/kueuectl/app/create/create_clusterqueue.go`: the error now names both flavors and their resources, e.g. `flavor "beta" covers [memory cpu gpu] but flavor "alpha" covers [cpu memory]; flavors that share a resource must cover the same resources`. `mergeFlavorsByCoveredResources` finds the overlapping group in one pass instead of an equality scan plus a covered-resources set; merging is unchanged.
- The two existing overlap unit cases now assert the full message.
