#### What this PR does / why we need it?

**Why:** A flavor set only in `--borrowing-limit` or `--lending-limit` was added with `nominalQuota: 0`. So a misspelled flavor in a limit flag printed `created` but left the ClusterQueue inactive (`FlavorNotFound`), and a lending-only flavor failed on the server with a confusing `lendingLimit` error. #15433 already rejects this for a single resource, but not for a whole flavor.

**What:** `mergeResourcesByFlavor` in `cmd/kueuectl/app/create/create_clusterqueue.go` now rejects a flavor whose first entry comes from a limit flag. The two tests that expected the old behavior now expect the error, and new cases cover a mismatched flavor name and a flavor in both limit flags.

#### Useful notes for your reviewer

This is a behavior change: `--borrowing-limit alpha:cpu=4` alone no longer creates a borrow-only flavor; it now needs `--nominal-quota alpha:cpu=0` too. kueuectl can't tell that case apart from a typo, and the API marks `nominalQuota` as required, so I went with the explicit form.

```release-note
CLI: Fixed a bug where `kueuectl create clusterqueue` added a flavor set only in `--borrowing-limit` or `--lending-limit` with a zero nominal quota, so a misspelled flavor name could leave the ClusterQueue inactive. Such flavors are now rejected.

ACTION REQUIRED: If you create a borrow-only flavor with only `--borrowing-limit`, also pass a zero `--nominal-quota` for it, for example `--nominal-quota "alpha:cpu=0" --borrowing-limit "alpha:cpu=4"`.
```
