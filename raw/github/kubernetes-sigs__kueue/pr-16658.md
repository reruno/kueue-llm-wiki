#### What this PR does / why we need it?

Fix flavor-assignment paths that still paired PodSets by position when spec order and admission/group order differ for non-adjacent PodSet groups.

This could:

- resume flavor scan state for the wrong PodSet, leaving a workload pending although an assignment fits
- use the wrong PodSet data during the TAS second pass and reorder the admission, so the webhook rejects every retry

The fix maps reordered PodSets back to their spec indexes through podset.SpecIndexes.

It also switches grouping to `tas.GroupKeyForPodSet`, fixing the numeric group-name collision in #16661.
