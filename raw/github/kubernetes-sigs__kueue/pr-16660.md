#### What this PR does / why we need it?

Adds unit tests for `TASReplaceMultipleFailedNodes` when a workload has multiple PodSets, as suggested in https://github.com/kubernetes-sigs/kueue/pull/12344#discussion_r4108013684.

The new cases in `pkg/cache/scheduler/tas_cache_test.go` cover:
- the head unhealthy node is in the first PodSet: it is replaced within its own PodSet, and the other PodSet is kept unchanged.
- the head unhealthy node is in the second PodSet: it is replaced, and the first PodSet is kept unchanged.
- the head unhealthy node cannot be replaced: replacing a later unhealthy node in another PodSet is not attempted, even though a free node is available there.

The last case pins down the current behavior where only `UnhealthyNodes[0]` is processed, so a head node that cannot be replaced blocks later nodes.

Fixes #16283

#### Useful notes for your reviewer

- Test-only change; no production code is modified.
- Failed nodes (`node-1`, `node-4`) are simulated by leaving them out of the node list while the admission still references them, which follows the existing replacement cases in the same file.
- In the blocking case, `podset-b` is listed before `podset-a` because `FindTopologyAssignmentsForFlavor` returns early when a PodSet fails.
- AI disclosure: parts of the test code were generated with Claude. I reviewed all of it, adjusted it to follow the conventions in this file, and ran the tests locally.
