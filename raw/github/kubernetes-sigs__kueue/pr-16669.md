#### What this PR does / why we need it?

With `CustomMetricLabels` enabled and a `Workload`-sourced custom label configured, `kueue_pending_workloads` kept stale series for a ClusterQueue after it was stopped or resumed:

- On stop, active workloads are merged into the inadmissible tracker and the active tracker is replaced with an empty one, so the previously reported `status="active"` series were never deleted.
- On resume, `status="inadmissible"` series that only existed because of that merge were never deleted either, because the ClusterQueue's own inadmissible tracker never contained those label values.

As a result, `sum(kueue_pending_workloads)` double-counted pending workloads after a stop/resume.

This PR clears all pending workload series of the ClusterQueue before re-reporting, the same approach `reportLQPendingWorkloads` already uses via `ClearLocalQueuePendingWorkloadsSeries`. The zero-count popping mechanism (`clearZeroWorkloadCounts`, `metrics.ClearPendingWorkloads`, `LabelValsTracker.PopZeroCounts`) is no longer needed and is removed.

Related: #16372

#### Useful notes for your reviewer

- This branch is stacked on #16372, which adds `TestPendingWorkloadsMetricsWithCustomLabels`. Until #16372 merges, this diff includes its commits; the change for this PR is the last commit.
- The test now compares the full set of `kueue_pending_workloads` series for the ClusterQueue instead of only the expected positive ones. Without the fix, it fails on exactly the stale series (`active/kind1`, `active/kind2` when stopped; `inadmissible/kind1` when resumed).
- Validation:
  - `go test -race ./pkg/cache/queue ./pkg/metrics` passed.
  - `make ci-lint` passed.
  - Manually verified on a local kind cluster (Kubernetes v1.36.1): a StrictFIFO ClusterQueue with two pending Jobs labeled `workload-kind=kind1` / `kind2`, then stop (`Hold`) and resume, scraping `/metrics`:

    | Phase | Before (#16372 HEAD) | After |
    |---|---|---|
    | Active | `active` kind1=1, kind2=1 | same |
    | Stopped | `active` kind1=1, kind2=1 **and** `inadmissible` kind1=1, kind2=1 | `inadmissible` kind1=1, kind2=1 |
    | Resumed | all four series remain | `active` kind1=1, kind2=1 |
