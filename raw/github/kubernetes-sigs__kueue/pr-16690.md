#### What this PR does / why we need it?

Release lookup errors currently fall through as if no release exists, and replacing a tag deletes the remote tag before creating and pushing its replacement. A subsequent failure can leave a draft release without its tag.

Use a single GraphQL query for published and draft releases, and stop on lookup errors. Create the annotated replacement locally, then update the remote tag with an explicit `--force-with-lease` expectation instead of deleting it first. Preserve failure messages and protect concurrent tag creation or updates.

Fixes #13501

#### Useful notes for your reviewer

- Added 12 regression tests using real temporary Git repositories, simulated GitHub responses, and a rejecting Git hook. The unchanged action reproduces the tag-loss and lookup-error failures; all 23 release utility tests pass with the fix.
- Verified the new query with real `gh` against a published release, a missing release, and a repository lookup failure. ShellCheck, Bash syntax, and whitespace checks pass.
- Tests are discovered by the existing `release-utils-test` target. Full `make verify` was not run locally because Docker was unavailable.

AI-assisted implementation and tests.
