#### What this PR does / why we need it?

**Why:** `kueuectl create clusterqueue` checks `--nominal-quota`, `--borrowing-limit` and `--lending-limit` with a hand-written regex that still disagrees with the API server after #16981. It rejects valid values such as `1e-3` or `foo--bar.example.com/gpu`, but accepts names the server rejects, such as `example.com/gpu-`, `example.com/_gpu` or flavor `alpha-`, so `--dry-run=client` prints a ClusterQueue the server refuses. Errors are a bare `invalid resources specification`.

**What:** In `cmd/kueuectl/app/create/create_clusterqueue.go`, the regex now checks only the `FLAVOR:RESOURCE=QUANTITY` structure. Resource names use `content.IsLabelKey` like the ClusterQueue webhook, flavor names use `content.IsDNS1123Subdomain` like the CRD, and negative quantities are rejected like in the webhook. Errors name the spec, flavor, resource and flag. `TestParseResourceQuotas` covers these cases for all three flags.

#### Useful notes for your reviewer

This PR replaces the regex that #16981 widened. kueuectl now checks each value locally with the server's own functions, and leaves rules that span several fields (for example lendingLimit <= nominalQuota) to the server.
