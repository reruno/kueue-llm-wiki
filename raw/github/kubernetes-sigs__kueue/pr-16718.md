#### What this PR does / why we need it?

**Why:** `kueuectl create clusterqueue` checked `--nominal-quota`, `--borrowing-limit` and `--lending-limit` with a hand-written regex that disagreed with the API server. It rejected valid names and quantities such as `nvidia.com/mig-1g.5gb` (so MIG resources could not be used) and `1e-3`, but accepted names the server rejects, such as `example.com/_gpu` or flavor `alpha-`. Errors were a bare `invalid resources specification`.

**What:** In `cmd/kueuectl/app/create/create_clusterqueue.go`, the regex now checks only the `FLAVOR:RESOURCE=QUANTITY` structure. Resource names use `content.IsLabelKey` like the ClusterQueue webhook, flavor names use `content.IsDNS1123Subdomain` like the CRD, and negative quantities are rejected like in the webhook. Errors name the spec, flavor, resource and flag. `TestParseResourceQuotas` covers these cases for all three flags.
