#### What this PR does / why we need it?

`RUN npm install` in `cmd/kueueviz/frontend/Dockerfile` had no retry. In `pull-kueue-build-image-release-0-19` the npm registry answered one tarball with a transient `403 Forbidden`, and the same revision passed on retest. npm does not retry a 403, and `IMAGE_BUILD_RETRIABLE_ERRORS` in the `Makefile` has no 403 pattern, so `kueueviz-image-build` failed on the first attempt.

Both `npm install` calls in the frontend Dockerfile now run through `hack/testing/retry.sh`, with the same settings as the `npm install` retries in `hack/testing/e2e-kueueviz-frontend.sh`. The frontend image is built from `cmd/kueueviz/frontend`, where `retry.sh` is not reachable, so `kueueviz-image-build` passes `hack/testing` as a named `retry` build context and the Dockerfile copies `retry.sh` from it. Tested with `make kueueviz-image`, both installs ran under `retry [1/5]`.
