## Description

This purportedly fixes the issue in https://github.com/kubernetes-sigs/kueue/issues/16734.

This works by using the admission checks of the variant `Workload`, not the parent `Workload`, as the source of truth for admission checks.

~I have not tested this fix yet.~

I have verified that this patch works when backported to `v0.18.0`, the version of Kueue we are using in our deployment today.

## AI summary

For Concurrent Admission parents, Kueue now applies `PodSetUpdates` from the admitted variant whose admission matches the parent’s. This prevents the job integration from using admission checks from the parent or a different flavor attempt. For other workloads, Kueue continues to use that workload’s admission checks.

### Suggested release note

ConcurrentAdmission: Fixed a bug where a job could receive admission-check pod updates from the parent Workload or a different variant. Kueue now uses updates from the admitted variant that matches the parent’s admission.
