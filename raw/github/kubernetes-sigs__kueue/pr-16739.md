#### What this PR does / why we need it?

Several KueueViz resource lists remain stuck in the loading state when a query succeeds but returns no results, rather than displaying an empty state.

The backend returns `null` instead of an empty array (`[]`) when no resources are found. The frontend treats `null` as “not yet loaded,” so it keeps showing the loading spinner. This affects the Local Queues, Cluster Queues, Cohorts, and Resource Flavors pages.

For example, an administrator with permission to view Cohorts opens the KueueViz Cohorts page in a cluster with no Cohort resources:

• Expected: The page displays `No Cohorts found.` to indicate that no Cohort is configured.
• Actual: The backend query succeeds but returns `null`. The page keeps showing the loading spinner, which makes the administrator think the data has not loaded yet.

Before the fix, successful queries with no results returned a `nil` slice, which was serialized as JSON `null`. After the fix, they return a non-`nil` empty slice, which is serialized as JSON `[]`.

Non-empty results and error handling remain unchanged.
