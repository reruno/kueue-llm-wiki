#### What this PR does / why we need it?
Manual cherry-pick of #16611 for `release-0.19`, following the failed automated cherry-pick.

The existing test can submit a workload before the manager cache observes its LimitRange, allowing an initial 0-CPU admission instead of the expected 3-CPU request. Create the LimitRange before manager startup and wait for cache visibility before submitting workloads.

#### Useful notes for your reviewer
Adapted the backport to the existing test in 0.19. The second test and the `qManager` suite variable from the original branch are absent here and are not introduced.

Validation: the existing integration spec passed five consecutive runs with the race detector and Kubernetes 1.36.2 envtest. Formatting and `git diff --check` passed.
