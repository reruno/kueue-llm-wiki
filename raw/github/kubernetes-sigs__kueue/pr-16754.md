#### What this PR does / why we need it?

## AI summary

For a batch Job using elastic partial scale-up, `PodsReady` now uses the granted pod count from its latest active, admitted Workload slice when that count is below the Job’s target. This prevents `WaitForPodsReady` from treating a partially granted scale-up as not ready until the full target is ready. During a pending scale-up, the reconciler updates the `PodsReady` condition on the admitted slice.

### Suggested release note

**Balanced:** `ElasticJobsViaWorkloadSlices: Fixed a bug where WaitForPodsReady could treat a batch Job as not ready during elastic partial scale-up. Kueue now checks readiness against the granted pod count.`

This change is limited to the batch.Job integration and elastic partial scale-up. Tests were added for granted counts and `PodsReady` behavior; test execution results were not provided.

**Security architecture risk:** **🔵 Low** · up to `1dfa9`

The change remains behind existing feature controls and admission checks. The main concern is that a failed capacity lookup can be interpreted as pod loss and, if that state persists, cause an otherwise healthy workload to be evicted. No introduced security boundary bypass was established, but workload identity and deployment-policy coverage remain incomplete.

**Retained concerns**
- **Low · reliability · inferred:** During pending partial scale-up, readiness now updates the retained admitted slice. A subsequent grant lookup failure falls back to the full Job target instead of reporting an unknown readiness result. When healthy pods satisfy the granted count but not the full target, this can persist WaitForRecovery; if it remains unresolved until the configured recovery timeout, the workload controller can evict the healthy reserved slice. The base pending-probe path did not apply that readiness transition to the retained slice, so this introduces a dependency-failure path into its capacity lifecycle.

**Security Blast Radius**
- _observed_ — The selected status target is confined to the Job’s namespace and owner-reference API version, kind, and name.
