/kind cleanup

#### What this PR does / why we need it?

This is useful in some situations:
1. we don't know if the bug exists bug the code looks suspicious based on static code analysis. Confirming a bug would require substantial more time to repro on reviewer.

Examples: 
- https://github.com/kubernetes-sigs/kueue/issues/9139 (used cleanup but it was likely a bug)
- https://github.com/kubernetes-sigs/kueue/issues/15360

2. we have some vague cleanup idea but it requires substantial investigation. Using cleanup my suggest this is a log hanging fruit, but it is not. 

Examples: 
- https://github.com/kubernetes-sigs/kueue/issues/16265

### Comment by [@mimowo](https://github.com/mimowo) — 2026-10-06T17:32:06Z

> What is the output of this investigation ticket? Is it to write up a summary in the issue or would you want someone to file a PR once they did their investigation?

I wanted to keep it flexible. I assume in some cases this is a comment saying:'I checked there is no bug with the following unit test scenario". Or "I tried to refactor the code and I stumbled on this issues... What are next steps?". Sometimes the output is to create a bugfix issue if the bug is confirmed.

This happens already on the cleanup issues, so I can continue using them surely, but it does feel like a workaround.

As for the feature - again, my intention was to rather have the new issue type when:
1. I hesitate if a cleanup makes sense ( it requires a couple of hours of getting hands dirty)
2. I hesitate if there is a bug or not based on static code analysis ( again, I want to report my suspicions, not spend 6h building a repro)

My intention wasn't to use it for new features. If this was the confusion point then I'm happy to clarify.
