## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

When a ClusterQueue is deleted, the delete handler calls `ClearCohortMetrics` on its cohort, which computes the subtree metrics as if the whole cohort were removed, and nothing records them again afterwards. A cohort that still has other ClusterQueues or child cohorts therefore loses its `kueue_cohort_subtree_quota` and `kueue_cohort_subtree_resource_reservations` series; for a root cohort they stay missing until another member ClusterQueue is reconciled. This PR records the cohort metrics from the updated cache after the ClusterQueue is removed, as the cohort-change path in `Update` already does.
