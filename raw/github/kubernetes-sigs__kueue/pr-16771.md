#### What this PR does / why we need it?

`TopologyUngater` drops rank-based ordering for the whole PodSet as soon as one pod's rank has no domain in the `TopologyAssignment`, and falls back to greedy assignment. This happens after an elastic Job scale-down: the replacement slice gets the previous assignment truncated to the lowest ranks (`TruncateAssignment`), while the pods above the new count still exist until the Job controller deletes them. Greedy assignment can then ungate one of those pods into the domain of a pod at a lower rank, for example one that is being recreated.

With `ElasticJobsViaWorkloadSlicesWithTAS` enabled, the ungater now keeps rank-based ordering for an elastic workload whose pods have ranks without a domain, using the free capacity per domain. A gated pod goes to its own rank's domain while that domain has room. The capacity left is lent in ascending rank order, first to the pods whose rank's domain is full, then to the pods whose rank has no domain. Lending is what keeps an Indexed Job with completions above parallelism running: its pods at higher completion indexes have no domain and take the domains freed by the succeeded pods. Otherwise placement is unchanged. The KEP-77 graduation item for rank-based ordering on scale-downs is ticked.

#### Useful notes for your reviewer

- Scope: with the gate disabled, or for a non-elastic workload, placement is identical to `main`, and every existing `TestReconcile` case passes unmodified. The only change there is that a rank at or above the PodSet count now logs at V(3) instead of as an error. The domain-mismatch check also still falls back to greedy assignment for the whole PodSet there. With lending, an ungated pod can run outside its rank's domain, so the lending path skips that check and counts free capacity from where the pods run. The slice-size case from #13919 (`TASPartialSlices` disabled) is left for a follow-up.
