#### What this PR does / why we need it?

When an elastic Workload with a TAS PodSet group scales the workers up from 0, the running leader is placed again from scratch and can be assigned to a different domain than the one its Pod runs on.

Workers that had zero Pods have no previous assignment, so `handleElasticWorkload` returned early and the group went through fresh placement. The leader-preserving logic in `handleScaleUp` was never reached.

Now, when the workers have no previous assignment but the leader has one, the workers are treated as scaling up from zero Pods. The request goes through `handleScaleUp`, which keeps the leader's assignment and places only the new workers.

Fixes #16775

#### Useful notes for your reviewer

- Scaling from 0 to 1 also needs #16740, which fixes the leader and workers being swapped when their counts are equal.

AI assistance was used to prepare this PR.
