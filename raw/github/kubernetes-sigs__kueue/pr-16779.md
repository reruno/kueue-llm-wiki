#### What this PR does / why we need it?

Since #14227, Kueue does not copy its internal labels `kueue.x-k8s.io/multikueue-origin`, `kueue.x-k8s.io/concurrent-admission-parent` and `kueue.x-k8s.io/job-uid` from a Job or Pod to the Workload, even when `integrations.labelKeysToCopy` lists them. A configuration with such an entry is still accepted, and the entry has no effect.

The manager now logs these entries once at startup. The configuration still loads, since refusing it would break existing setups. The field comment, the generated config reference and the Workload concept page now say that these labels are never copied and that the manager logs them at startup.

Fixes #16322

#### Useful notes for your reviewer

The list of internal labels is unexported, so `NonInheritableLabelsIn` reports which keys `WithLabelKeysToCopy` drops. `main.go` logs them right after the feature gates, at Info level like the `metrics.customLabels` message. The filtering itself is unchanged.

Workload-scoped custom metric sources are not checked: a metric that names an internal label or annotation reports the value set on the Workload itself, so that entry has an effect.

`TestNonInheritableLabelsIn` covers the new function. I also started the manager with `team`, `kueue.x-k8s.io/multikueue-origin` and `kueue.x-k8s.io/job-uid` in `labelKeysToCopy`, and it logged the last two.

_Disclosure: I used an AI coding assistant while preparing this PR. I reviewed and tested the change myself._

#### Release note

```release-note
ConfigAPI: Kueue logs configured internal labels in integrations.labelKeysToCopy at startup. Kueue does not copy these labels to a Workload.
```
