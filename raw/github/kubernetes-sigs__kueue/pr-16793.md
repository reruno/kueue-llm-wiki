#### What this PR does / why we need it?

`IsLoggedEntryAConcurrentModification` in `test/util/behavioral/assertions.go` did an unchecked `.(string)` on the `"error"` value from `le.ContextMap()`. If an error-level log entry carries an `"error"` field that isn't a string (for example `zap.Bool("error", true)`), the integration-test log check panics instead of returning false.

This switches to a checked type assertion. Missing, nil and non-string values now return false, and string values are still matched with `utillogging.IsWriteConflictError`, so write-conflict detection works as before.

Fixes #16789

#### Useful notes for your reviewer

- Checked locally with a throwaway test (not included, per review): a `zap.Bool("error", true)` entry panics without the change (`interface conversion: interface {} is bool, not string`) and returns false with it. `go build` and `go vet` on `./test/util/behavioral/` pass.
- The two callers, `verifyLogs` in `test/integration/framework/framework.go` and the ClusterQueue controller integration test, both go through this helper, so nothing else needs changing.
- No production code is touched.

This PR was made with AI assistance, but every change has been reviewed line by line.
