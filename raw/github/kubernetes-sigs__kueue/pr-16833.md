/kind bug

#### What this PR does / why we need it?
Refresh pending-workload metrics after ClusterQueue updates even when no inadmissible Workloads are requeued. Stopping a CQ no longer relies on a later Workload update to publish the inadmissible count.

Fixes #16825

#### Useful notes for your reviewer
Adds a deterministic stop/resume regression with no subsequent Workload updates and no moved inadmissible Workloads, covering plain and custom-label metrics. The regression fails before the fix. The full queue package and the original CQ stop/resume integration test pass locally with the race detector enabled.

This change addresses the refresh trigger. Cleanup of stale zero-count custom-label series is handled separately by #16670.

#### Release note
```release-note
Observability: Refresh pending-workload metrics when ClusterQueues stop or resume, without relying on subsequent Workload updates.
```
