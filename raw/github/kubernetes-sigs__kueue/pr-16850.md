#### What type of PR is this?

#### What this PR does / why we need it?

**Refactor**

- `Run()` picks the search once: only when the first page of the job-uid search is empty and has no continuation does it fall back. The fallback has a single call site, so `enableOwnerReferenceFilter` and the in-loop changes to `opts` are gone.
- Pagination: `forEachWorkloadPage()`, `listWorkloadPage()`.
- Printing: `printWorkloadPage()`, `listAndPrint()`.
- `filterList()` and `filterByOwnerReference()` take `ownerUID *types.UID` instead of `(bool, uid)`; `nil` means no owner filter.

**Added test**

`should list each workload once when the job uid search spans pages`: when the `--for` job-uid search spans pages and the last page is empty, the owner-reference fallback must not start, and each Workload is listed once.

- This is the gap pointed out in the #16040 review: removing `opts.Continue == ""` made no existing test fail.
- `objs` holds the same wl1, so a wrongly started fallback lists it again.
- Verified: the test passes on the old code and fails once `opts.Continue == ""` is removed.

**Why existing behavior is unchanged**

- No existing test case was changed, and all pass. Both search phases and the user-supplied job-uid selector were already covered: the label search by the resource filter cases, the fallback by `composable jobs` and `job uid label is missing`, and the user-supplied selector by `selector already contains the job uid label`.
- The API server receives the same requests in the same order: the first page of the label search is reused, not listed again.
- Filtering and printing run in the same order for each page.


Fixes #16120

The issue is that `release-0.19` uses `-lang=go1.26` in `go.mod`, but the new test code uses promoted fields in composite literals (e.g. `WorkloadList{Continue: ...}, Job{Name: ..., Namespace: ..., UID: ...}`), which is a Go 1.27+ language feature.

```sh
// Instead of:
&kueue.WorkloadList{Continue: "page2", ...}

&kueue.WorkloadList{ListMeta: metav1.ListMeta{Continue: "page2"}, ...}

// Use:

```
