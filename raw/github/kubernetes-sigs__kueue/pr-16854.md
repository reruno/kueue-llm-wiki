#### What this PR does / why we need it?

Cherry pick #15677 to release 0.19.

* RayCluster: Populate hierarchical TopologyRequest info

- Use replicas as SubGroupCount
- Set pod index and subgroup index labels using KubeRay multi-host indexing labels
- Disabling feature gate KubeRayEvictOnInconsistentTopologyRequest allows existing to continue running with old topology requests
- Update topology fields when applying MultiKueue runtime counts



* Add TAS integration tests for RayCluster topology requests

- Add integration test verifying Workload PodSet TopologyRequest population (PodIndexLabel, SubGroupIndexLabel, SubGroupCount) and TAS admission for single-host and multi-host RayCluster worker groups.
- Add integration tests verifying that a pre-existing admitted RayCluster workload without topology index labels is preserved across a Kueue restart when KubeRayEvictOnInconsistentTopologyRequest is disabled (default), and replaced when the feature gate is enabled.


#### Relevant notes

The cherry pick was not clean.

Related changes I had to pull in dependencies from:

* #14585: Needed TopologyRequest equality comparisons, normalizedTopologyRequest, WithIgnoreTopologyRequest, and utiltas.HasTopologyConstraint required for EquivalentToWorkload to detect topology mismatches.
* #15331: Needed the base WorkerGroupWrapper test utility and its builder methods required by the new RayCluster integration tests.
* #15531: Needed the decomposed manager/scheduler setup helper structure in suite_test.go to support configuring TAS controllers in integration tests.
* #13435: omitted MultiKueue runtime count topology updates and fallback tests because MultiKueue Ray in-tree autoscaling does not exist in 0.19.
