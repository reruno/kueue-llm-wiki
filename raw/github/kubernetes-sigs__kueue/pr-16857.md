#### What this PR does / why we need it?

Fixes #16855

When a workload encounters an error during DRA preprocessing (e.g. referencing an unmapped DeviceClass in a ResourceClaimTemplate), `markDRAInadmissible` did not emit a Warning event. Consequently, users running `kubectl describe workload` saw no event explaining why the workload was inadmissible.

In addition, in `markDRAInadmissible` and `handleDRA`, `SetRequeuedCondition` was short-circuited behind `if updated && workload.SetRequeuedCondition(...)`. If `UnsetQuotaReservationWithCondition` returned false (for example when `QuotaReserved=False` was already present), `SetRequeuedCondition` was never called and the status patch was skipped.

This PR:
1. Emits a Warning event on the Workload object with the error details when `markDRAInadmissible` executes.
2. Ensures `SetRequeuedCondition` is evaluated independently of `updated` so status changes are recorded and patched properly.
3. Updates DRA workload controller unit tests and test runner helpers to verify the emitted events.

#### Useful notes for your reviewer

Unit tests in `pkg/controller/core` and `pkg/dra` pass.

#### Release note

```release-note
DRA: Emit a warning event on the Workload when DRA preprocessing fails, and fix SetRequeuedCondition evaluation when QuotaReserved was already False.
```
