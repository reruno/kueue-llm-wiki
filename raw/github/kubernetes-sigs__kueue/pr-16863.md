#### What this PR does / why we need it?

Adds JAXJob to `supportedPrebuiltWlJobGVKs` in `pkg/controller/jobframework/validation.go`, next to the other Kubeflow training jobs.

JAXJob has a MultiKueue adapter that sets the `kueue.x-k8s.io/prebuilt-workload-name` label on remote jobs through `SetMultiKueueMeta`. Because JAXJob was missing from the allowlist, `ValidateJobOnCreate` rejected such a job on the worker cluster with:

```
metadata.labels[kueue.x-k8s.io/prebuilt-workload-name]: Forbidden: Is not supported for "kubeflow.org/v1, Kind=JAXJob"
```

Fixes #16862

#### Useful notes for your reviewer

- Adds one case to `TestValidateJobOnCreate`: a JAXJob GVK with a prebuilt-workload label must pass `ValidateJobOnCreate`. Without the allowlist change the case fails with the error above; with it, it passes.
- Tests run: `go test ./pkg/controller/jobframework/... ./pkg/controller/jobs/kubeflow/...` passes.
- Not covered: I did not run an end-to-end MultiKueue flow with manager and worker clusters. The fix is verified at the `ValidateJobOnCreate` level.
- make verify: not run — Docker is not available in this environment; unit tests for the affected packages pass.
- Related but out of scope: the same MultiKueue integration has other open JAXJob-related work (for example worker-side cleanup policies). This PR only changes the prebuilt-workload allowlist.

#### Release note

```release-note
MultiKueue: Fixed a bug where a JAXJob dispatched by MultiKueue could be rejected on the worker cluster with `Is not supported for "kubeflow.org/v1, Kind=JAXJob"`, because JAXJob was missing from the allowlist of job kinds that accept a prebuilt Workload.
```

This change was developed with AI assistance (Claude), in accordance with the Kubernetes AI tool usage policy.
