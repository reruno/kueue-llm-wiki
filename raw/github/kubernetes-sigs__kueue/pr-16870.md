#### What this PR does / why we need it?

KubeRay uses the top-level `spec.suspend` field to suspend and resume a RayService. Kueue currently reads and writes `spec.rayClusterConfig.suspend` instead, which is the suspend setting for the RayCluster template.

This change updates the RayService integration to use top-level `spec.suspend` when checking, suspending, and starting a RayService. The behavior is controlled by the Beta `KubeRayServiceUsingTopLevelSuspend` feature gate, which is enabled by default. Disabling the gate retains the previous behavior for compatibility with KubeRay versions older than 1.7. It also aligns the test builder and existing webhook and e2e assertions with the default semantics.

This was split from the review feedback in:

- https://github.com/kubernetes-sigs/kueue/pull/11264#discussion_r4142156848
- https://github.com/kubernetes-sigs/kueue/pull/11264#discussion_r4142159478

AI disclosure: This pull request was developed with assistance from OpenAI Codex.

#### Useful notes for your reviewer

This PR contains only the standalone suspend-field fix. It does not include the workload-slicing changes from PR 11264. `KubeRayServiceUsingTopLevelSuspend` is planned to graduate to GA in Kueue 0.23.

#### Release note

```release-note
RayService: Fixed suspend and resume handling to use the top-level `spec.suspend` field when the Beta `KubeRayServiceUsingTopLevelSuspend` feature gate is enabled (default).

ACTION REQUIRED: If you use the RayService integration, upgrade KubeRay to v1.7.0 or newer before upgrading Kueue. To temporarily retain compatibility with older KubeRay versions, disable `KubeRayServiceUsingTopLevelSuspend`.
```
