#### What this PR does / why we need it?

Two follow-ups from the review of #16779.

The `labelKeysToCopy` field comment no longer mentions the startup log, and the config reference is regenerated from it. The Workload concept page still describes the log.

The comment above `nonInheritableLabels` and `nonInheritableAnnotations` now says where these keys are listed by name, so those places get updated when a key is added.
