#### What this PR does / why we need it?

This manually backports https://github.com/kubernetes-sigs/kueue/pull/16870 to `release-0.19`.

KubeRay uses the top-level `spec.suspend` field to suspend and resume a RayService. Kueue currently reads and writes `spec.rayClusterConfig.suspend`, which configures the RayCluster template instead.

This backport adds the Alpha `KubeRayServiceUsingTopLevelSuspend` feature gate. It is disabled by default so patch upgrades retain the existing behavior. When enabled, Kueue uses the top-level field for RayService suspension and resume.

AI disclosure: This pull request was prepared with assistance from OpenAI Codex.

#### Useful notes for your reviewer

The generated feature-gate conflicts from the automated cherry-pick were resolved and regenerated for v0.19. Because release-0.19 used KubeRay v1.6.2, which does not define the top-level RayService suspend field, this backport also carries the existing KubeRay v1.7.0 dependency bump.

Validation performed:

- `go test -race -count=3 ./pkg/features ./pkg/controller/jobs/rayservice`
- scoped `golangci-lint` for the changed Go packages
- compiled the single-cluster and MultiKueue extended e2e packages

#### Release note

```release-note
RayService: Added the Alpha `KubeRayServiceUsingTopLevelSuspend` feature gate, disabled by default, to opt in to top-level `spec.suspend` handling. This backport updates the KubeRay dependency to v1.7.0; upgrade the deployed KubeRay operator to v1.7.0 or newer before enabling the gate.
```
