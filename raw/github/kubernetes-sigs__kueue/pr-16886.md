## Description

Fixes #16666

Issue 16666: Infinite preemption/admission loop with fair-share and hierarchical cohorts

What this PR does:
- Updates findCandidates in preemption.go with borrowedFrsFromLCA to check intermediate cohorts up to the Least Common Ancestor, so workloads in sub-cohorts that stay within nominal quota on the contested flavor are not chosen as preemption candidates.
- Adds IsBorrowingOnAny to DRS in cache/scheduler to evaluate borrowing on specific contested flavor resources.
- Passes frsNeedPreemption to MakeClusterQueueOrdering so target queue and cohort pruning in ordering.go only evaluates contested flavors.
- Updates iterateWithFirstFsStrategy and iterateWithSecondFsStrategy to pass frsNeedPreemption to the ordering iterator.
- Adds unit tests in ordering_test.go and integration tests in preemption_fair_test.go covering internal sub-cohort borrowing and verifying that non-borrowing sub-cohorts are not preempted.

### Comment by [@akshat-lakhera](https://github.com/akshat-lakhera) — 2026-10-08T12:51:09Z

> @akshat-lakhera we recently merge this fix for the preemption loop, check if this fixes your issue too: #16343

Thanks @mimowo. I checked with PR #16343 on main, but issue #16666 is a different loop and still happens.

PR #16343 tackles the intra-queue case where fillBackWorkloads restores same-queue workloads and invalidates the target. 

Our issue is about hierarchical sub-cohorts borrowing internally. When a leaf queue borrows from a sibling, the sub-cohort as a whole is still within nominal quota on the contested flavor. But because the leaf itself has 0 nominal quota, findCandidates flags it as a borrowing candidate for outside queues. 

Even with the verifyFairSharingTargets check in PR #16343, if that victim sub-cohort borrows any other flavor, its dominant resource share stays high enough that the preemption still passes verification. It gets evicted, and then on the very next admission cycle, Kueue sees the sub-cohort is within nominal on the contested flavor and immediately re-admits it, continuing the loop.

That is why we still need borrowedFrsFromLCA to check intermediate cohorts up to the common ancestor before picking candidates.
