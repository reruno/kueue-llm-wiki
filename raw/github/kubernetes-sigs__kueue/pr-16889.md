## Description

/kind bug

Manual backport of #16833 to `release-0.19`, requested in https://github.com/kubernetes-sigs/kueue/pull/16833#issuecomment-6047423461.

Refresh pending-workload metrics after ClusterQueue updates, including stop/resume transitions where no inadmissible Workloads move and no subsequent Workload event triggers another report.

Backports the final merged change (`c4d66ab5af79c944bd4b76cba251fdd95e05e357`). The target branch has no `pending_workloads_metrics_test.go`, so this adds only the stop/resume regression and its status checker, using the target's `AddOrUpdateWorkload(log, wl)` signature. The custom-label case uses CQ-sourced labels: 0.19 does not support Workload-sourced labels for pending metrics. It checks both the positive and zero counts.

Validation:
- Both plain and custom-label regression cases fail before the production fix.
- Full `pkg/cache/queue` unit tests pass with `-race`.
- `gofmt` and `git diff --check` pass.

```release-note
Observability: Refresh pending-workload metrics when ClusterQueues stop or resume, without relying on subsequent Workload updates.
```
