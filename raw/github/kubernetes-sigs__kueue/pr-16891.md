## Description

/kind bug

Manual backport of #16833 to `release-0.20`, requested in https://github.com/kubernetes-sigs/kueue/pull/16833#issuecomment-6047423461.

Refresh pending-workload metrics after ClusterQueue updates, including stop/resume transitions where no inadmissible Workloads move and no subsequent Workload event triggers another report.

Uses the final merged diff (`c4d66ab5af79c944bd4b76cba251fdd95e05e357`). The target branch already includes custom-label series cleanup through #16871; this backport supplies the refresh trigger and its regression test.

Validation:
- Both plain and Workload custom-label regression cases fail before the production fix.
- Full `pkg/cache/queue` unit tests pass with `-race`.
- The existing CQ stop/resume custom-label integration scenario passes with `-race` on Kubernetes 1.37.0 envtest.
- `gofmt` and `git diff --check` pass.

```release-note
Observability: Refresh pending-workload metrics when ClusterQueues stop or resume, without relying on subsequent Workload updates.
```
