## Description

#### What type of PR is this?

#### What this PR does / why we need it?

Use zero worker replicas when a Ray worker group's `replicas` field is absent, matching the KubeRay CRD default of zero. Kueue's shared worker count helper previously used one for an absent value, so an object constructed before API defaulting could produce a different PodSet count from the persisted object.

Update the dedicated omitted-replicas test to expect zero workers. In the RayCluster, RayJob, and RayService tests for topology and other behavior, explicitly set replicas to one so those tests retain their original worker counts and purpose. Update the corresponding topology expectations to include the explicit subgroup count.

#### Useful notes for your reviewer

CRD default: KubeRay declares `replicas` optional with `+kubebuilder:default:=0`; see the [WorkerGroupSpec definition at this fixed commit](https://github.com/ray-project/kuberay/blob/a43952999b761269c5e7cac2f80d764288481038/ray-operator/apis/ray/v1/raycluster_types.go#L477-L480).

KubeRay reference: [`GetWorkerGroupDesiredReplicas`](https://github.com/ray-project/kuberay/blob/master/ray-operator/controllers/ray/utils/util.go#L389) uses `minReplicas` when `replicas` is absent; `minReplicas` defaults to zero.

This is the standalone correction to Kueue's absent-replicas fallback. Applying min/max replica bounds is tracked separately in draft PR https://github.com/kubernetes-sigs/kueue/pull/16884.

AI assistance: OpenAI Codex was used to implement the change, update tests, perform validation, and prepare this PR.

#### Release note

```release-note
Ray integrations: Use zero instead of one as the worker replica fallback when replicas is absent, matching the KubeRay CRD default.
```
