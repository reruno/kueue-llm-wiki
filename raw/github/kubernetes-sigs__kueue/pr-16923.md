#### What this PR does / why we need it?

`make verify` runs the MultiKueue performance-tool unit tests in a separate race-test invocation while module linting and four-platform CLI builds compete for CPU. Move these tooling tests into the existing unit-test package selection and shards, retaining race detection, JUnit reports, and coverage. Other integration, E2E, and performance suites under `./test/` remain excluded, and the focused runner-test target remains available.

Defer unsharded unit-test package discovery until the package list is used. Module linting now defaults to two concurrent processes. Standalone CLI platform concurrency remains configurable with a default of four; verification defaults to two concurrent CLI platform builds. `verify-checks` exports a configurable `GOMAXPROCS=2` to its Go generators, tool installation, builds, and linter subprocesses, also setting Go's default build `-p`. Unit/race jobs keep their existing settings. These are per-process and task limits, not a strict global CPU semaphore. No CLI platform or verification check is omitted. A lightweight verify target checks package-selection boundaries, exactly-once coverage across 1/2/3 shards, and custom target forwarding through the shard wrapper. Update the performance-tool README to describe its unit CI coverage.

Related: #16902

Module lint now waits for Go generation and module validation, while artifact builds wait for Go/module/Helm inputs. Both can overlap unrelated site generation; full generation and the final clean-tree checks remain required. Artifact builds also explicitly wait for `go mod tidy` and its diff check. A lightweight regression uses the real Make wrappers to check writer barriers, failure propagation, and independent site/check overlap.

Release preparation reuses the parent Make invocation's Helm-docs tool and shared rendering recipe, instead of recursively invoking Make. Verification removes the redundant pre-update Helm-doc generation; docs are still generated after chart versions and values are updated.

The CLI documentation generator now uses the same configurable CGO setting as the CLI build. On Linux, its previous default-enabled CGO setting selected different `net` and `os/user` sources from the default-disabled CLI build, preventing reuse of matching cache entries for affected dependencies. Aligning these inputs allows host-platform builds to reuse Go's existing build cache. The cache directory is unchanged; no Prow cache service or persistent volume is introduced.

Module lint workers also reuse the existing timed shell to report labeled per-module totals and command durations for package discovery and linter execution. The original aggregate timing remains. This follow-up measures wall time only, retaining the selected concurrency, package selection, linter rules, and timeout. `MAKE_TIMING=0` disables timing; within enabled module workers, command timing is explicitly enabled and the existing minimum-duration filtering applies. Internal per-rule profiling is not included.
