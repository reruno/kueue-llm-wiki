#### What this PR does / why we need it?

Document the KubeRay version used by the main branch's KubeRay-enabled extended E2E targets. Distinguish that tested version from historical requirements and feature-specific minimums, without claiming a guaranteed compatibility range or an N-3 support policy.

Add per-feature requirements for MultiKueue's managedBy workflow, RayService's top-level suspend field, and Ray History Server. Retain the previously documented RayService minimum for nested suspend and explain how to disable `KubeRayServiceUsingTopLevelSuspend` for KubeRay v1.3.0 through v1.6.x.

Link the RayJob, RayService, and MultiKueue guides to the shared compatibility guidance, and describe both RayService suspend paths.

Fixes #16906
