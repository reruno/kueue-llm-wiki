#### What this PR does / why we need it?

Fixes #

When creating a ClusterQueue using `kueuectl create clusterqueue`, resource names containing hyphens in the name part (e.g. `example.com/v100-gpu`, `intel.com/sriov-net`, `habana.ai/gaudi-2`) failed validation with:

```text
error: invalid resources specification
```

The regex in `parseUserSpecifiedResourceQuotas` used `\/?\w+` for the resource name segment. Because `\w` does not match hyphens, any valid Kubernetes resource with a hyphen after the slash was rejected.

This PR:
1. Updates the regex to allow hyphens in the resource name segment (`\/?[\w\.-]+=`).
2. Adds a unit test case in `create_clusterqueue_test.go` covering hyphenated extended resource names.
