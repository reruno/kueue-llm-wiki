#### What this PR does / why we need it?

When a job is reconciled and its Namespace is not yet in the manager's informer cache, `ReconcileGenericJob` logged `Namespace not found; skipping selector check` and returned `ctrl.Result{}, nil`. 

This can happen whenever the job informer observes a job before the Namespace informer observes its namespace, which is what the PaddleJob integration test hit in #16974:

```
Namespace not found; skipping selector check  namespace: core-sz2m5; job: core-sz2m5/test-job
Timed out after 10.000s.
workloads.kueue.x-k8s.io "paddlejob-test-job-9e6a3" not found
```

This PR returns the NotFound error so the job is requeued with backoff. The API server does not admit a job into a non-existent namespace, so a job that is in the cache while its namespace is not means the cache is behind, and the retry succeeds once it catches up. If the namespace is really being deleted, its jobs are deleted first, and the next reconcile takes the finalize path.

Fixes #16974
