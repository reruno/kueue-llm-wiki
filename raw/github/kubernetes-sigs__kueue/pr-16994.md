## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

Fixes #16736.

A Job referencing a prebuilt workload that was left in a finished state by a deleted predecessor adopted it and was finalized immediately: the workload finalizer was removed and the Job kept running unmanaged, without a quota reservation.

This refuses to adopt a prebuilt workload that is already finished and is not controlled by the Job being reconciled, so the Job is stopped and the leftover workload is left untouched, consistent with how the reconciler already treats a prebuilt workload that is missing or controlled by another object.

#### Useful notes for your reviewer

The new check sits in the shared prebuilt branch of `ensureOneWorkload`, right after the guard for workloads controlled by another object, so it covers every integration that supports prebuilt workloads.

A finished workload that is controlled by the Job itself is still returned, so the regular path is unchanged: the Job is finalized and the workload finalizer is removed as usual. The two added tests pin both cases: one for a finished workload with no controller, which is no longer adopted (the Job is stopped with a "missing workload" message and `ErrPrebuiltWorkloadNotFound`), and one for a finished workload controlled by the Job, which is still finalized.

#### Release note

```release-note
Jobs: Fixed a bug where a Job could adopt an unrelated, already finished prebuilt Workload and run without quota management. Kueue now stops the Job instead.
```
