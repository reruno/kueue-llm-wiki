<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/kubernetes-sigs/kueue/releases">sigs.k8s.io/kueue's releases</a>.</em></p>
<blockquote>
<h2>v0.20.0</h2>
<p>Changes since <code>v0.19.0</code>:</p>
<h2>Actions Required Before Upgrading</h2>
<h3>(No, really, you MUST read this before you upgrade)</h3>
<ul>
<li>
<p><strong>Minor releases:</strong> Review the <code>.0</code> release notes for each new minor version you cross; see: <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.18.0"><code>v0.18.0</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.0"><code>v0.19.0</code></a>.</p>
</li>
<li>
<p>AFS: LocalQueue usage is now accounted from quota reservation rather than admission for ClusterQueues using UsageBasedAdmissionFairSharing. AdmissionFairSharingAnchorAtQuotaReservation is Beta and enabled by default in v0.20.</p>
<p>If you explicitly disable AdmissionFairSharing, also disable AdmissionFairSharingAnchorAtQuotaReservation before upgrading to v0.20, or Kueue will reject the configuration at startup. Before rolling back to a release that does not recognize AdmissionFairSharingAnchorAtQuotaReservation, remove it from the configuration. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15000">#15000</a>, <a href="https://github.com/apullo777"><code>@​apullo777</code></a>)</p>
</li>
<li>
<p>API: Kueue no longer serves kueue.x-k8s.io/v1beta1.</p>
</li>
</ul>
<p>Update manifests and API clients to v1beta2 before upgrading. Run the <a href="https://raw.githubusercontent.com/kubernetes-sigs/kueue/main/hack/migrate-to-v1beta2.sh">migration script</a> before upgrading to rewrite existing objects in v1beta2 storage. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14558">#14558</a>, <a href="https://github.com/mbobrovskyi"><code>@​mbobrovskyi</code></a>)</p>
<ul>
<li>DRA &amp; ResourceTransformation: Fixed a bug where DRA device-class mapping or a resource transformation under the reserved resource name <code>pods</code> was silently discarded or left the Workload permanently pending.</li>
</ul>
<p>Remove or rename those entries before upgrading, or the kueue-controller-manager will fail to start. Renaming a mapping name or an <code>outputs</code> key also requires updating the matching ClusterQueue <code>nominalQuota</code> entries in the same change. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13989">#13989</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</p>
<ul>
<li>DRA: Fixed missing quota charges for Pod overhead and transformation outputs that share a DRA resource name. Restartable init-container requests are now counted alongside regular-container requests.</li>
</ul>
<p>Review ClusterQueue quotas for mapped logical resources and contributions still charged under original resource names. When both use one name, quota must cover their sum. With BlockUndeclared, uncovered contributions leave Workloads pending; with IgnoreUndeclared, they are not charged. Corrected accounting applies when Workloads are evaluated. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14154">#14154</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</p>
<ul>
<li>KueueViz: Added Kubernetes RBAC checks through SubjectAccessReview for API and WebSocket requests when authentication is enabled.</li>
</ul>
<p>Ensure users have the get, list, and watch permissions needed for their views. For non-Helm or custom RBAC installations, ensure the backend ServiceAccount can create subjectaccessreviews in the authorization.k8s.io API group. The Helm chart includes this permission. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13810">#13810</a>, <a href="https://github.com/mykysha"><code>@​mykysha</code></a>)</p>
<ul>
<li>LeaderWorkerSet: Fixed a quota bypass where raising <code>spec.leaderWorkerTemplate.size</code> on an already-admitted, Kueue-managed LeaderWorkerSet ran more pods per group than the reserved quota covered. <code>spec.leaderWorkerTemplate.size</code> is now immutable while the LeaderWorkerSet is managed by Kueue, behind the new <code>LWSImmutableGroupSize</code> feature gate (Beta, enabled by default). <code>spec.replicas</code> stays mutable.</li>
</ul>
<p>If you change <code>spec.leaderWorkerTemplate.size</code> on a Kueue-managed LeaderWorkerSet, recreate it at the new size instead, or disable the <code>LWSImmutableGroupSize</code> feature gate to keep the previous behavior, which also restores the quota bypass. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/13279">#13279</a>, <a href="https://github.com/ivnovakov"><code>@​ivnovakov</code></a>)</p>
<ul>
<li>Observability: Kueue now rejects invalid metrics.localQueueMetrics.localQueueSelector values at startup. Previously, enabled LocalQueue metrics included all queues when this selector was invalid.</li>
</ul>
<p>Correct invalid selectors before upgrading if metrics.localQueueMetrics.enable is true. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16379">#16379</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</p>
<ul>
<li>RayService: Starting in v0.20, the Beta <code>RayServiceValidateUpgradeStrategy</code> feature gate is enabled by default.</li>
</ul>
<p>Kueue-managed RayServices that use zero-downtime upgrades must enable the <code>ElasticJobsViaWorkloadSlices</code> feature gate and set the <code>kueue.x-k8s.io/elastic-job</code> annotation to <code>&quot;true&quot;</code>. To disable zero-downtime upgrades, explicitly set <code>spec.upgradeStrategy.type</code> to <code>None</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16094">#16094</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</p>
<ul>
<li>SparkApplication: Fixed a bug where Workloads reserved less CPU and memory than Spark requests for the driver and executor Pods, because <code>cores</code>, <code>memoryOverhead</code> and Spark's default memory overhead were ignored. Kueue now reserves the same CPU and memory that Spark requests. Memory values must use the Java format accepted by Spark (for example <code>512m</code> or <code>2g</code>); Kubernetes-style values such as <code>512Mi</code> are rejected.</li>
</ul>
<p>If SparkApplications rely on <code>cores</code> or on the default memory overhead, raise the ClusterQueue quotas accordingly: each Pod now reserves its <code>cores</code> as CPU and at least 384Mi of additional memory. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/15833">#15833</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</p>
<ul>
<li>TAS: Fix a bug where TASRecomputeAssignmentWithinSchedulingCycle can be enabled even if TopologyAwareScheduling is disabled.</li>
</ul>
<p>If you disable TopologyAwareScheduling, also set TASRecomputeAssignmentWithinSchedulingCycle=false before upgrading. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14237">#14237</a>, <a href="https://github.com/tenzen-y"><code>@​tenzen-y</code></a>)</p>
<ul>
<li>TAS: Workload slice sizes must be positive, and podSetSliceRequiredTopology and podSetSliceSize must be set together.</li>
</ul>
<p>Correct invalid manifests before upgrading. Disabling TASValidateWorkloadSliceSize disables only webhook checks; CRD minimum-size validation still applies. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/12728">#12728</a>, <a href="https://github.com/mszadkow"><code>@​mszadkow</code></a>)</p>
<ul>
<li>TrainJob: support Trainer v2.3.</li>
</ul>
<p>If you use Trainer v2.2, you have to update it to v2.3 since Trainer v2.2 and v2.3 don't have API compatibility. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/14504">#14504</a>, <a href="https://github.com/SatishChoudhary642"><code>@​SatishChoudhary642</code></a>)</p>
<ul>
<li>Workloads: Fixed a bug that caused Workloads to be finalized as orphaned while their owner Job was being deleted. Kueue now waits until the owner Job no longer exists before finalizing the Workload.</li>
</ul>
<p>If you implement the ComposableJob interface in a custom job integration, change your Load method to return (*jobframework.LoadResult, error) instead of (bool, error). Use jobframework.NewLoadResult(shouldFinalize, found) where found is false when the job is absent and true otherwise. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/12849">#12849</a>, <a href="https://github.com/mbobrovskyi"><code>@​mbobrovskyi</code></a>)</p>
