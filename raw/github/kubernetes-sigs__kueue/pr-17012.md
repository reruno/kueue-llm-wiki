#### What this PR does / why we need it?

Fixes #17011

In `apis/kueue/v1beta2/clusterqueue_types.go`, `ConcurrentAdmissionPolicy.Migration.Mode` is documented as defaulting to `TryPreferredFlavors`:

```go
// - `TryPreferredFlavors` (default): a Workload will try to migrate to the preferred flavor after it's admitted and running.
// - `RetainFirstAdmission`: a Workload, once admitted to a flavor, will stick to a flavor and will not be migrated.
```

Both the webhook (`pkg/webhooks/clusterqueue_webhook.go:251`) and controller (`pkg/controller/concurrentadmission/controller.go:853`) already treat an empty `Mode` as `TryPreferredFlavors`. However, the Go field had `// +required` and lacked `// +kubebuilder:default=TryPreferredFlavors`. This caused the generated CRD to require `mode`, rejecting manifests where `concurrentAdmissionPolicy.migration` was configured without explicitly setting `mode`.

This PR:
1. Changes `ConcurrentAdmissionPolicy.Migration.Mode` to a pointer (`*ConcurrentAdmissionMigrationMode`) with `// +optional` and `// +kubebuilder:default=TryPreferredFlavors`.
2. Drops `omitzero` from `ConcurrentAdmissionPolicy.Migration` (`json:"migration"`) to match bare tag conventions and prevent typed Go zero-values from dropping the field before CRD defaulting.
3. Regenerates CRD manifests in `config/components/crd/bases` and Helm chart templates.
4. Adds controller and webhook unit tests along with an envtest case verifying CRD defaulting on creation.

```

#### Release note

```release-note
ConcurrentAdmission: ClusterQueue manifests omitting `spec.concurrentAdmissionPolicy.migration.mode` now default to `TryPreferredFlavors`.

ACTION REQUIRED: In `apis/kueue/v1beta2`, the Go field `ConcurrentAdmissionMigration.Mode` changed from `ConcurrentAdmissionMigrationMode` to a pointer (`*ConcurrentAdmissionMigrationMode`). Downstream Go code constructing or manipulating `ConcurrentAdmissionMigration` must pass a pointer, and callers reading the field should handle nil pointers.
```
