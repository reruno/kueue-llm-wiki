#### What this PR does / why we need it?

Four-platform CLI builds and module linting currently run concurrently in the same `make verify` Pod. Add `make verify-cli-artifacts` so a separate required test-infra job can compile and package the CLI after Go code/mock generation, module verification, and Git-tag verification.

Both paths reuse the existing CLI recipe and preserve Linux/macOS amd64/arm64 coverage, version metadata, filenames, and archive contents. `VERIFY_CLI_ARTIFACTS` defaults to `1`, preserving complete verification until the companion job is deployed. Setting it to `0` skips only CLI compilation and packaging; Helm, manifests, generators, lint, and the final generated-file checks still run. `artifacts` and `release-artifacts` continue to build the CLI unconditionally.

Extend the existing generation-order regression to cover default CLI coverage, retained Helm/manifests when CLI builds are skipped, and prerequisite/build failure propagation for the standalone target. Each scenario explicitly sets the switch so inherited `MAKEFLAGS` cannot remove coverage.

Part of #16902: isolate CLI builds from the verify Pod. The companion test-infra change must also be deployed before evaluating the issue's remaining performance work.
