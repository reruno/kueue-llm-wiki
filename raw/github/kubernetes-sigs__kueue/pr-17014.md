#### What this PR does / why we need it?

Four-platform CLI builds currently compete with module linting for CPU in the same `make verify` Pod. Add `make verify-cli-artifacts` so test-infra can move CLI compilation and packaging into a separate required job. The new target waits for Go code and mock generation, module verification, and Git-tag verification before building.

Both paths reuse the existing CLI build recipe, retaining Linux/macOS amd64/arm64 coverage, version metadata, filenames, and archive contents. `VERIFY_CLI_ARTIFACTS` defaults to `1`, preserving the current behavior of local and CI `make verify`. Setting it to `0` skips only CLI compilation and packaging; Helm, release manifests, and other checks still run. `artifacts` and `release-artifacts` continue to build the CLI unconditionally.

Related: #16902

#### Useful notes for your reviewer

- Companion PR: https://github.com/kubernetes/test-infra/pull/38019. Merge this Kueue PR before deploying the new test-infra job and the verify skip setting. This PR alone preserves existing CI coverage.
- Extend the existing `verify-generation-order` regression to check default CLI coverage, retained Helm/manifests when CLI builds are skipped, and prerequisite/build failure propagation for the standalone target. Each scenario sets the switch explicitly to avoid inheriting the CI setting through `MAKEFLAGS`. The existing verify presubmit runs this regression target.
- Local validation passed shell syntax checks, `git diff --check`, the generation-order regression, the inherited `MAKEFLAGS=' -- VERIFY_CLI_ARTIFACTS=0'` scenario, and the actual `make verify-generation-order VERIFY_CLI_ARTIFACTS=0` entry point.
- Controlled checks using the real Makefile and multiplatform packaging script passed archive-content, skip-behavior, release-build, invalid-setting, and platform-failure checks. Go compilation and expensive tools were replaced with test doubles; these checks are not real Go builds or performance benchmarks.
- Full local verification, real four-platform Go compilation, and ShellCheck were not run. Normal presubmits must provide the remaining validation. Runtime savings have not been measured.
- No data migration is required. To roll back, first restore the original test-infra verify command and remove the standalone job, then revert this PR if needed.
