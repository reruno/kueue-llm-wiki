#### Useful notes for your reviewer

With `FairSharingPreemptWithinNominal` enabled, fair-sharing preemption could use the nominal-first shortcut when the preemptor was within nominal only for the resource needing preemption.

That allowed a Workload to reclaim CPU while still borrowing another requested resource, such as memory. Fair-sharing admission could then rank the evicted Workload ahead of the preemptor again, causing a preempt, re-admit, preempt loop.

This PR changes the shortcut to require the incoming Workload to be within nominal for all assigned requested resources before bypassing DRS. It also adds a regression test for the case where CPU is within nominal but memory is still borrowed.

AI assistance was used to draft and validate this change.

#### Release note

```release-note
Scheduling: Fixed a bug where fair-sharing preemption could repeatedly evict and re-admit Workloads when a preemptor was within nominal quota for one requested resource but still borrowing another.
```
