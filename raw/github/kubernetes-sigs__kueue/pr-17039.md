#### What this PR does / why we need it

Shows unit test coverage in Prow's coverage view. Prow's Spyglass coverage lens renders `artifacts/filtered.cov`, and `artifacts/filtered.html` when present. After the unit tests pass, `make test` now writes both files:

- `filtered.cov` is `cover.out` (or `cover-shard-N.out`) without generated code, client-go, mocks, and kueuectl test helpers: `zz_generated.*`, `client-go/`, `internal/mocks/`, and `cmd/kueuectl/app/testing/`. The `mode:` line is kept. Duplicate blocks that `-coverpkg` repeats per test binary are merged by summing their counts, so `filtered.cov` is about 2 MB instead of about 70 MB.
- `filtered.html` is rendered from `filtered.cov` with `go tool cover -html`.

The contributor guide explains where to find the coverage view on a pull request.

Part of: https://github.com/kubernetes-sigs/kueue/issues/11173

#### Useful notes for your reviewer

- The GitHub Actions workflow and `codecov.yml` from the earlier revision are removed. Prow already runs the unit tests (the `pull-kueue-test-unit-shard-*` jobs and the periodics) and archives the cover profiles to GCS. A second run in GitHub Actions took about 18 minutes and only repeated that work. This follows the "start with (b)" direction in #11173.
- Coverage is per shard. Each `pull-kueue-test-unit-shard-*` job shows the coverage reached by the tests in its shard, counted against all packages, so it is a lower bound on overall coverage. The shards are not merged.
- No test-infra change is needed. The coverage lens is already set up in Prow's `config.yaml` and matches `artifacts/filtered.cov`. Prow's decoration (`decorate: true`) sets `ARTIFACTS=/logs/artifacts` and uploads it under the job's `artifacts/`.
- The report is written only when the tests pass. When tests fail, `make test` fails at the test step, the same as before, and no filtered report is written. `cover.out` is still written in that case.
- Codecov upload from Prow will be a follow-up PR. It needs a `CODECOV_TOKEN` secret provisioned through kubernetes/k8s.io, as node-feature-discovery does. `codecov.yml` moves to that PR.
- Overlap with #17042: that PR rewrites `cover.out` in place to drop `test/` paths, on the line after the `gotestsum` call. This PR reads `cover.out` on that same spot, so whichever merges second has a small, mechanical rebase. If #17042 runs first, `filtered.cov` also leaves out `test/` paths. Folding these exclusions into #17042's `hack/coverprofile` Go filter can be a follow-up once that lands.
