## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it:
When ClusterQueue or LocalQueue custom labels or annotations are updated, the Update event handler triggers gauge metric re-synchronization to clear stale series and report the new values. However, if Reconcile executes before the Update event handler, Reconcile calls CQStore or LQStore on CustomLabels, which already swaps the new values into the in-memory cache. When the Update event handler subsequently runs, CQStore or LQStore returns false because the cache already contains the new values, causing the controller to skip gauge resync and leave stale metric series orphaned in Prometheus.

This patch adds ValuesChanged, CQValuesChanged, and LQValuesChanged to CustomLabels so the Update handlers compare old and new object metadata directly. If configured custom label values differ, gauge metrics are always resynchronized regardless of whether Reconcile or Update executed first.

#### Which issue(s) this PR fixes:
Part of #16840

#### Special notes for your reviewer:
Added TestValuesChanged in pkg/metrics/custom_labels_test.go covering all metadata comparison branches and nil safety.
Added TestClusterQueueCustomLabelUpdateMetricRefresh in pkg/controller/core/clusterqueue_controller_test.go covering both reconcile-before-update and update-before-reconcile interleavings.
Added TestLocalQueueCustomLabelUpdateMetricRefresh in pkg/controller/core/localqueue_controller_test.go covering both interleavings.
All unit and integration tests pass cleanly.

#### Does this PR introduce a user-facing change?
Observability: Fixed a bug where custom-label updates to a ClusterQueue or LocalQueue could leave stale metric gauge series in Prometheus.
