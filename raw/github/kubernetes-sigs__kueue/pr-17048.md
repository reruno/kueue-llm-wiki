#### What this PR does / why we need it?

A required-topology placement failure can look like a cluster-wide resource shortage even when enough resources are available across multiple domains. The current message does not explain that the whole PodSet must fit in a single domain.

This PR adds the required topology level and single-domain constraint to the existing failure message. Placement behavior, non-required diagnostics, and the dedicated multi-layer failure messages are unchanged.

Fixes #17045

#### Useful notes for reviewer

The regression test covers two hosts with enough total capacity but no single host able to fit both Pods. Existing tests cover the non-required paths, and affected message expectations are updated.

Local checks: cache and scheduler tests with `-race`, `make fmt-verify`, and `ci-lint` passed.

#### Release note

```release-note
TAS: Improved required-topology placement failure messages to identify the required level and explain that all Pods must fit in a single topology domain.
```
