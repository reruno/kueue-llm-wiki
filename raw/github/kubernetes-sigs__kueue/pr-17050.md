#### What this PR does / why we need it?
**WHY**
While I was testing #16348, I found this problem. That PR made the Helm e2e install use the same manager config and replica count as the kustomize install.
After that change, the Helm baseline suite could install Kueue again and run all 65 specs. 61 specs passed and 4 failed.

All 4 failures are PreemptionConfig RBAC specs, and the main reason is that the two install paths install different CRDs.
- `test/e2e/config/default/kustomization.yaml` includes `config/components/crd/alpha`, so the kustomize install creates the PreemptionConfig CRD.
- The Helm chart installs the alpha CRDs only when `enableAlphaAPIs` is `true`. The default is `fales`, and the e2e values files do not set it.

 **What**
 - `helm_install` in `hack/testing/e2e-common.sh` now sets `enableAlphaAPIs` from the kustomize config.
 - The value is `true` when the kustomize build contains any CRD from `config/components/crd/alpha`.
   Otherwise it is `false`.

 **How**
`helm_install` already runs `kustomize build` to read the manager config and the replica count. This PR adds the CRD names.
It compares them with the CRD names in `config/components/crd/alpha`. These are exactly the CRDs that the chart installs when `enableAlphaAPIs` is `true`.
