## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

`kueuectl create resourceflavor --tolerations key=:NoSchedule` currently creates an `Exists` toleration, which also matches nonempty taint values. The same problem affects `key=` without an effect.

Preserve explicit empty values as `Equal` tolerations while keeping the existing wildcard forms. Add command and API persistence regressions, plus a non-TAS Job E2E that verifies a nonempty node taint blocks scheduling and changing its value to empty allows the same Pod to complete. The E2E runs serially, targets one worker hostname, and removes only its own taint.

#### Useful notes for your reviewer

AI assistance was used in preparing this contribution.

Validation: ResourceFlavor command unit tests, `make fmt-verify`, and package-scoped golangci-lint pass. Both kueuectl E2Es pass in an isolated kind cluster running Kubernetes 1.36.4 and Kueue 0.20.1 with the repository's default agnhost image. The baseline CLI fails at the scheduling assertion because its Pod binds to the node despite the nonempty taint.

#### Release note

```release-note
CLI: Fixed kueuectl create resourceflavor so explicit empty values in --tolerations (for example key=:NoSchedule) match only empty taint values instead of any value.
```
