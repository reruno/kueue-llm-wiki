## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

`kueuectl create resourceflavor --tolerations key=:NoSchedule` currently creates an `Exists` toleration, which also matches nonempty taint values. The same problem affects `key=` without an effect.

Preserve explicit empty values as `Equal` tolerations while keeping the existing wildcard forms. Add command and API persistence regressions, plus a non-TAS Job E2E that verifies a nonempty node taint keeps an admitted Pod Pending and Unschedulable while the Job and Pod retain the explicit empty Equal toleration. The E2E runs serially, targets one worker hostname, and removes only its own taint.

#### Useful notes for your reviewer

AI assistance was used in preparing this contribution.

Validation: ResourceFlavor command unit and integration tests, `make fmt-verify`, and package-scoped golangci-lint pass. Both kueuectl E2Es pass in an isolated kind cluster running Kubernetes 1.36.4 and Kueue 0.20.1 with the repository's default agnhost image. The baseline CLI fails at the scheduling assertion because its Pod binds to the node despite the nonempty taint.

#### Release note

```release-note
CLI: Fixed a bug where `kueuectl create resourceflavor --tolerations key=:NoSchedule` created an `Exists` toleration that also matched taints with nonempty values. It now creates an `Equal` toleration with an empty value. To tolerate any value, omit the `=` (for example `key:NoSchedule`).
```

## AI summary

`kueuectl create resourceflavor --tolerations` now creates `Equal` tolerations when the input includes `=` with an empty value (for example, `key=` or `key=:NoSchedule`). Previously, these inputs created `Exists` tolerations that could match taints with nonempty values. Tolerations without `=` (for example, `key:NoSchedule`) remain `Exists` and still tolerate any value. A toleration with an empty key remains `Exists`.

The change is one line in `parseToleration` (`cmd/kueuectl/app/create/create_resourceflavor.go`). It replaces the value-length check with a check for `=` in the input string. Unit, integration, and E2E tests cover the new behavior.

### Suggested release note

CLI: Fixed a bug where `kueuectl create resourceflavor --tolerations` with an explicit empty value (for example, `key=` or `key=:NoSchedule`) created an `Exists` toleration that matched taints with nonempty values. Now Kueue creates an `Equal` toleration, so the ResourceFlavor matches only nodes whose taint value is empty. Omit `=` (for example, `key:NoSchedule`) to tolerate any taint value.

No action is required. The change applies to ResourceFlavors created by the CLI after upgrade. Existing ResourceFlavor objects are not modified.
