#### What this PR does / why we need it?

Follow-up from [this review thread](https://github.com/kubernetes-sigs/kueue/pull/16581#discussion_r4165952443).

The ClusterQueue and Cohort weighted share metrics report NaN when the weight is 0 and the ClusterQueue or Cohort borrows, as their help text says. The four places that report them checked for a `+Inf` share instead, which works only because nothing else makes the share `+Inf`. They now check `ZeroWeightBorrows()`, and the usage stats that the two controllers read carry that flag.

Related: #16581

#### Useful notes for your reviewer

The reported values don't change. With a weight above 1n, which the webhook requires when it isn't 0, the share would only overflow to `+Inf` after borrowing more than 1e296 (in millicores for CPU), far beyond any real usage.

`clusterQueue.reportWeightedShare` in the cache had no unit test for the NaN case. The integration test "should have NaN weighted share metric" covers the ClusterQueue controller, but it can't catch a mistake on the cache side, because the controller sets the gauge again right after. The new test is modelled on the Cohort one from #16581. Like that one, it checks that the metric goes back to 0 once the ClusterQueue stops borrowing, which a check on the weight alone would get wrong.
