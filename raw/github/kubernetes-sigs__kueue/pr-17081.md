#### What this PR does / why we need it?

https://github.com/kubernetes-sigs/kueue/issues/10824#issuecomment-6082576941

Adds unit and integration test coverage for the scenario reported in #10824:

When a ClusterQueue has multiple TAS-enabled ResourceFlavors and `flavorFungibility.whenCanPreempt: TryNextFlavor`, a workload requiring preemption on the first flavor defers to the second flavor. If the second flavor has free nominal quota but its TAS capacity is unreachable (e.g. cordoned node / "ghost quota"), TAS placement on the second flavor fails.
With the set-based flavor tracking introduced in #16766, the second flavor is tracked as tried in `FlavorScanState.TriedFlavors`, allowing subsequent cycles to skip it and fall back to preempting lower-priority workloads on the first flavor.
This PR adds:
1. **Unit tests in `pkg/scheduler/flavorassigner/flavorassigner_test.go`**:
   - `first flavor requires preemption and second flavor fits quota with WhenCanPreempt=TryNextFlavor: selects second flavor and records it as tried`
   - `first flavor requires preemption and second flavor with ghost quota was already tried with WhenCanPreempt=TryNextFlavor: falls back to first flavor with preemption`
2. **Integration test in `test/integration/singlecluster/tas/tas_preserve_flavor_scan_progress_test.go`**:
   - Verifies end-to-end that cordoning the node of the second flavor results in the scheduler falling back to the first flavor, preempting the lower-priority filler workload, and admitting the pending workload.
Fixes #10824
