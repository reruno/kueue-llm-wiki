## Description

Pod overhead contributes to the resource requests used for quota accounting, but `validatePodSet` did not validate it. Negative overhead could offset container requests, allowing a Workload to be admitted with insufficient quota charged.

Validate PodSet overhead under the existing `WorkloadValidateResourcesAreNonNegative` feature gate.

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

Validates each PodSet overhead resource quantity when `WorkloadValidateResourcesAreNonNegative` is enabled, preventing negative overhead from reducing the resources charged against quota.

Fixes #13991

#### Useful notes for your reviewer

- Adds tests for negative overhead, non-negative overhead, and behavior when the feature gate is disabled.
- Verified locally with `make test` and `make verify`.

#### Release note

```release-note
Workloads: Reject negative Pod overhead when WorkloadValidateResourcesAreNonNegative is enabled.
```

  This also runs on updates, status updates too, and until now nothing rejected a negative overhead. So every update to a Workload that already has one is refused while its overhead stays the same, including the one that removes Kueue's finalizer, and a deleted one can get stuck in Terminating. That's #14373 again, for overhead.
  
  Could we let an unchanged overhead entry through on update, matching the old PodSet by name like #15235 does for requests and limits, and add a few cases to `TestValidateWorkloadUpdate`?
