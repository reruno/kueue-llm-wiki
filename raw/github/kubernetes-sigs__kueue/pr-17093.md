```release-note
Observability: Fixed logging:
- Consistent logging and Event emission for successful Workload status transitions (Events are logged at verbosity 1 after the status update succeeds)
- Emit a Warning Event when a pending Workload is marked inadmissible because its LocalQueue or ClusterQueue is stopped, terminating or missing, or because its DRA usage is unsupported or invalid. The Event reason matches the `QuotaReserved` condition reason (`Inadmissible` when the `UnadmittedWorkloadsObservability` feature gate is disabled).
- Emit a Normal `DRAResourcesResolved` Event when an earlier DRA inadmissibility clears.
- Remove or move log records that announced a status transition before the status write succeeded; existing Events (`Deleted`, `Evicted`, `AdmissionCheckRejected`) report these transitions once persisted.
- DRA validation failures are no longer logged as errors on every reconcile. A single verbosity 3 record reports them when the Workload is marked inadmissible.
- A failure to queue a Workload after a DeviceClass change while its LocalQueue is missing or stopped, or its ClusterQueue is missing, is now logged at verbosity 3 instead of as an error, matching the other Workload event handlers.
- Internal DRA errors and failures to queue a Workload are logged once, in the "Reconciler error" record, which now names the failed operation.
- When the status update for a DRA-inadmissible Workload fails, the reconcile error reports both the DRA cause and the update failure.
- The error for an invalid `WaitForPodsReady` annotation now identifies the Workload by `namespace` and `name`, like other reconcile logs, instead of a `workload` key.

Logging cleanups:
- Per-Workload operational log records (reconcile start, informer observations, queueing decisions, AFS usage updates) moved from verbosity 2 to 3 or higher, so they no longer appear at the default verbosity while Events remain logged at verbosity 1.
- Renamed the log keys `queue` and `prevQueue` to `localQueue` and `prevLocalQueue`, and unified `localQueue` and `clusterQueue` references to use `klog.KRef`.
```

  I've discovered a problem: 👀
  
  the PR's release notes state that a Warning Event is generated when a Pending Workload cannot be admitted due to a missing, stopped, or terminated LocalQueue or ClusterQueue.
  
  but, I observed that the newly added `markUnadmitted` is invoked only via two queue status handler functions, and these invocations are referenced by the `HasQuotaReservation` condition within the `Reconcile` loop.
  
  Consequently, Pending Workloads for which quota has not yet been reserved do not trigger this new event path. Instead, they are updated via the `syncQuotaReservedFalseCondition` function, and no corresponding Warning Event is generated after the update is successfully persisted.
