#### What this PR does / why we need it:

Manual cherry-pick of #16738 to release-0.19, since the automated cherry-pick hit conflicts.

It fixes two FairSharing preemption bugs (#16665, #16666) where workloads running within their nominal quota could be preempted:

- Candidate ClusterQueues and non-ancestor Cohorts are now pruned when they only borrow on flavors that are not contested by the preemptor.
- Borrowing is now checked along the path from the candidate ClusterQueue up to its lowest common ancestor with the preemptor's queue, so borrowing inside an internal sub-cohort no longer makes a queue a target.

/assign mimowo

#### Special notes for your reviewer:

The fix logic applies unchanged: the fairsharing ordering, fair_sharing.go and cohort_snapshot.go on release-0.19 match the parent of the original commit. Only the call sites differ:

- fair_strategy.go does not exist on 0.19. The same loops live in preemption.go (runFirstFsStrategy and runSecondFsStrategy), so frsNeedPreemption is passed to MakeClusterQueueOrdering there.
- preemption_fair_test.go on 0.19 calls GetTargets directly, so the new test cases were adapted to that.
- ordering_test.go, the cache fair_sharing_test.go and the fairsharing integration test merged cleanly and match upstream.

Tested locally with go test ./pkg/scheduler/preemption/... ./pkg/cache/scheduler/... (all pass), the fairsharing integration suite (53 of 53 specs pass), and golangci-lint on the touched packages (0 issues).

#### Does this PR introduce a user-facing change?

```release-note
FairSharing: Fixed the preemption bug where workloads within nominal quota were preempted if the ClusterQueue borrowed on an uncontested flavor or within an internal sub-cohort.
```
