## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

`/set-release-note` put every line after the command into the release note, including other commands in the same comment such as `/remove-kind cleanup` and `/kind bug`.

`parse_release_note` now drops the trailing block of command and blank lines before using the note. Other commands are still handled by Prow as before. Only a trailing block is removed, so a note line that starts with `/` and is followed by more note text is kept.

Fixes #17085

#### Useful notes for your reviewer

- A command line is matched as `/` + lowercase word, optionally followed by arguments, for example `/kind bug` or `/lgtm`.
- Known limit: a note that is a single line starting with `/word text` is treated as a command and rejected as empty. A note with a following non-command line is not affected. I kept the rule simple instead of listing Prow commands; happy to change it if you prefer a fixed list.
- Added test cases for the example in the issue, a multiline note followed by `/lgtm` and `/approve`, a note line starting with `/`, and a comment with only commands. The new cases fail on main.
- Ran the release-utils suite the same way `make verify` does: 31 tests pass. Doctests in `set_release_note.py` pass.
