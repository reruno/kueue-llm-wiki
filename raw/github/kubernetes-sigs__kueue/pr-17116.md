## Description

#### What type of PR is this?

/kind bug
/area release

#### What this PR does / why we need it?

Stop `prepare_pull.sh`, `promote_pull.sh`, and `ci_pull.sh` when the user declines the push/PR confirmation. These scripts currently print `Aborting.` but continue to look up existing PRs and can edit the release issue even though submission was cancelled.

Exit with a failure status before any subsequent GitHub operation. Keep the existing confirmation, push, and PR creation behavior unchanged.

Split out at reviewer's request from #16935: https://github.com/kubernetes-sigs/kueue/pull/16935#discussion_r4256309754.

#### Useful notes for your reviewer

AI assistance: OpenAI Codex was used for implementation, review, and local validation.

This PR is independent of checklist marking. Its production changes are only the three missing `exit 1` statements, and it can merge independently of the dry-run fix and #16935.

The regression test executes each script's submission function and subsequent issue-update phases, with matching existing PRs supplied by a local GitHub double. It checks confirmation, cancellation, default/invalid input, and push/PR failures. Before the fix, 12 cancellation subcases failed; after the fix, all 24 subcases passed.

Validation:

- `python3 -m unittest discover -s hack/releasing -p '*_test.py'`: 32 tests passed with PyYAML 6.0.3.
- Bash syntax checks, ShellCheck v0.11.0 with `-x` for the three changed scripts, and `git diff --check` passed.
- The new `*_test.py` file is selected by the existing release-utils test discovery in `make verify`.

Full `make verify` and Kubernetes E2E were not run. The tests do not perform real branch preparation, Git pushes, PR creation, or issue edits.
