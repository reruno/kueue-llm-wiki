## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

Prevent `prepare_pull.sh` and `promote_pull.sh` from editing the release issue during a dry run. They already skip pushing and creating PRs, but still look up matching existing PRs and update the issue body.

Keep PR submission, existing-PR lookup, and issue updates together inside the non-dry-run block. Apply the guard independently to the release and main targets of `prepare_pull.sh`. `ci_pull.sh` already exits before those operations during a dry run and needs no production change.

Split out at reviewer's request from #16935: https://github.com/kubernetes-sigs/kueue/pull/16935#discussion_r4256322117.

#### Useful notes for your reviewer

AI assistance: OpenAI Codex was used for implementation, review, and local validation.

This PR is independent of checklist marking and the cancelled-submission fix. It can merge independently of #16935.

The regression coverage is now consolidated into the existing manual_release_submission_test.py table and shared harness; the duplicate manual_release_dry_run_test.py file has been removed. Five script/target combinations (prepare all/release/main, promote, and CI) run nine confirmation, cancellation, submission-failure, and dry-run cases: 45 subcases in total. Matching existing PRs are always available in the GitHub double. Exact exit status, real submission-helper entry, actual Git subcommand, call order, and skip-message counts are checked. Dry runs use closed stdin and may only prepare local branches.

Promote and prepare's final main phase use an early dry-run exit, with normal submission code unwrapped. Prepare's release phase deliberately retains its guard: exiting there would skip main preparation under --target all. Normal release submission still precedes main preparation. The help text explicitly includes skipping the release issue update.

Local in-memory mutations confirm the combined table detects premature exit before main preparation (one failing subcase), continued execution after cancellation (20), and git fetch replacing git push (20), without test-framework errors.

Validation:

- `python3 -m unittest discover -s hack/releasing -p '*_test.py'`: 32 tests passed with PyYAML 6.0.3.
- Bash syntax checks, ShellCheck v0.11.0 with `-x` for both changed scripts, and `git diff --check` passed.
- The new `*_test.py` file is selected by the existing release-utils test discovery in `make verify`.

Full `make verify` and Kubernetes E2E were not run. The tests do not perform real branch preparation, Git pushes, PR creation, or issue edits.
