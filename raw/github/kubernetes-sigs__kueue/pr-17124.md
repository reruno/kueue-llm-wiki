#### Useful notes for your reviewer

`PodIntegrationVerifyRoleRequests` is Alpha and disabled by default on release-0.19.

#### Release note

```release-note
ACTION REQUIRED: Pods: Fixed a bug where a Pod could bypass ClusterQueue quota by setting the `kueue.x-k8s.io/role-hash` annotation to another role's value and running an oversized Pod under that role's reservation. Kueue now verifies, before removing the scheduling gate, that each Pod of a group fits the effective spec (LimitRange and RuntimeClass adjustments applied) of the PodSet its role hash names; a Pod that does not fit is kept gated and a Warning event is emitted. The gated Pod does not fail the Workload or disturb running peers, but the group cannot become PodsReady until the Pod is replaced by one that fits; with `waitForPodsReady`, the Workload is evicted and requeued (up to the requeue limit). The check is controlled by the Alpha `PodIntegrationVerifyRoleRequests` feature gate, disabled by default on release-0.19. If you set the `kueue.x-k8s.io/role-hash` annotation yourself and replacement Pods of a group can request more than the Pods the Workload was built from, set `PodIntegrationVerifyRoleRequests=false`, or recreate the group (delete its Workload and re-create the Pods) so a new Workload is built from the larger Pods.
```
