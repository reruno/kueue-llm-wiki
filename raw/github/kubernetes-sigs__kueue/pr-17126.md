### Security Architecture Review

**Security architecture risk:** **🟡 Moderate** · up to `868db`
-->

The merged job preserves authorization before release operations. However, checking membership against the triggering commit can preserve removed release permissions on older queued executions. Successful commands can still create tags, publish releases, and update repository branches.

**Retained concerns**
- **Medium · security · inferred:** Authorization now evaluates OWNERS_ALIASES from the triggering snapshot rather than current main. If an authorized actor submits a command and is removed before that queued execution starts, the older policy can still authorize repository-write or publication operations. Base authorization would observe a removal merged before its main checkout. This is an inferred revocation weakness, not a demonstrated exploit; new events created after removal remain subject to the updated policy.


<details>
<summary><strong>Security review details</strong></summary>
<dl>
<dd>

**Security Blast Radius**
- _observed_ — Reachable privileged effects include tags, release publication, issue updates, and website-branch writes in the triggering repository. Inspected publication and website actions use github.token, not a newly added credential. A pre-existing third-party container handles the external Krew update; its internal authority was not inspected.

**Security Findings and Attack Paths**
- _inferred_ — The decision-changing path is a previously authorized account submitting a valid release command before removal, followed by execution after removal while retaining the earlier event SHA. The historical alias membership can pass the unchanged verifier and unlock release writes. This requires prior membership and a suitable release state; it is not a bypass available to arbitrary commenters. Runtime queue and rerun semantics remain unverified.

**Trust Boundaries and Controls**
- _observed_ — The verifier safely parses YAML, requires a valid aliases mapping and string-member lists, and authorizes exact actor membership. Missing policy, malformed policy, and denied membership propagate failure through the composite action. The merge does not remove this gate or introduce a comment-selected branch.

**Resilience and Maintainability Implications**
- _observed_ — Existing sink-level controls limit repeated writes: tag replacement uses a force-with-lease against the observed remote tag object, and publication rejects already published or missing releases. These controls contain some repetition and concurrency effects but do not refresh actor authorization.

**Hardening Proposals**
- _proposed_ — Separate reproducible tooling checkout from authorization freshness: evaluate membership against a current trusted policy before privileged execution, including queued or replayed runs. Define whether policy revocation must invalidate pending commands rather than relying on historical event membership.
