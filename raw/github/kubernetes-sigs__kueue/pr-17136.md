#### What this PR does / why we need it?

Manual cherry-pick of #16996 to `release-0.19`, requested in https://github.com/kubernetes-sigs/kueue/pull/16996#issuecomment-6139641279.

Adds `ginkgo.GinkgoHelper()` to test helpers and removes the explicit Gomega offsets replaced by helper annotations, so assertion failures are attributed to the calling test.

Original commit: `56dd7d0074b5063982d0e7f8d417fcecc3a7652b`.
Related: #16896.

#### Useful notes for your reviewer

Conflict resolution preserves the release branch's API versions, manager wiring, and helper signatures. Files and test scenarios that exist only on `main` are not introduced into `release-0.19`. No production code, dependencies, or CI configuration changes are included.

Local validation with Go 1.26.6:
- `gofmt -l` for all 86 changed files and `git diff --cached --check`: clean.
- A temporary normalized-AST comparison against the release base confirmed that the changes are limited to helper annotations and assertion offsets (including removing offset-only helper parameters).
- `go test -p 4 -run '^$' ./test/integration/... ./test/e2e/... ./test/util/behavioral/...`: passed; compilation only.
- `go test -p 4 ./test/integration/... ./test/e2e/... -args -ginkgo.dry-run`: passed; suite/spec registration only.
- `go test ./test/util/behavioral/...`: passed.
- `go test -p 4 -race -count=1 ./test/util/behavioral/...`: passed.
- `go vet -p 4 ./test/integration/... ./test/e2e/... ./test/util/behavioral/...`: passed.
- The populator and priority-booster integration components were separately compiled, dry-run, and vetted from their own directories with `./test/integration/...`; all passed. Both belong to the root Go module.
- A temporary fake-client/Ginkgo regression harness verified the primary failure location for a direct assertion, a nested asynchronous deletion helper, and a metrics-wrapper assertion. All three were attributed to the exact calling line. These intentional-failure fixtures are not part of the backport.

Actual cluster-backed integration and E2E tests were not run locally; those results remain pending upstream CI. Dry-run does not execute the test bodies. No full-suite coverage percentage is claimed. The WAS E2E lane is optional and will be explicitly requested. Full-Ray RayService scenarios are excluded from the ordinary raymini presubmits and remain a runtime-validation gap.
