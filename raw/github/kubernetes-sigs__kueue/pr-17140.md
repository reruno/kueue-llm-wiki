#### What this PR does / why we need it?
 **WHY**
Issue happens when Pods have no resource requests, for example Pods that use only DRA claims.
```
resources:
  claims:
  - name: devices
```

When the requests are empty, `CountIn` returns 0 in `Fits`. Consequently, Fits incorrectly determines that the workload cannot be accommodated.
https://github.com/kubernetes-sigs/kueue/blob/8922c563e3a690af453dedfa478bc7cb37029a7b/pkg/cache/scheduler/tas_flavor_snapshot.go#L668-L671

**WHAT**
- `Fits` now counts one Pod slot for each Pod, the same way the assignment does.
- Because of this, `Fits` now also checks the node's `pods` allocatable.
- Stored usage does not change.

**HOW**
- Clone `SinglePodRequests` and add `resources.OnePodRequest` to the copy.
- Clone the requests rather than modifying them directly, since SinglePodRequests is also used to track the workload's stored resource usage.
- Tests:
  - Added `TestFitsCountsPodSlot`. It covers Pods with no requests, Pods with zero requests, and Pods that fit by CPU but not by Pod slots.
  Each case runs with `VectorizedResourceRequests` on and off.
  - Added `pods` allocatable to the test nodes that call `Fits` directly, because `Fits` now checks it.
