#### What this PR does / why we need it?

A DeviceClass can be requested by its `spec.extendedResourceName` or by its implicit name `deviceclass.resource.kubernetes.io/<class>`, and KEP-2941 says Kueue supports both. The DeviceClass handler only registered `spec.extendedResourceName` in the DRA-backed resource cache, so a workload requesting the implicit name was treated as an ordinary extended resource and never reached `ResolveDeviceClass`, which already handles that name. This PR registers and removes the implicit name on DeviceClass create and delete, and requeues pending workloads that request it.
