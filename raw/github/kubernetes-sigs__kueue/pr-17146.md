## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

Cherry-pick of #16466 to `release-0.19`.

A zero-count PodSet can lose its suitable flavor when admission is retried, which can block later elastic scale-up. Restart both its capacity probe and fallback from the first configured flavor, and clear its retry progress so it does not trigger unnecessary retries.

#### Useful notes for your reviewer

- Adapted quota-usage references to the structure used in 0.19. The scheduling behavior and regression coverage match the merged fix.
- Groups containing non-zero PodSets retain their existing retry behavior. Zero-count PodSets still consume no quota.
- Validation passed: flavor-assigner, scheduler, and workload unit suites; five focused scheduler integration tests, including admission retry and elastic scale-up, with race detection; `ci-lint`.

AI disclosure: Codex helped prepare, resolve conflicts, test, and review this backport and draft.

#### Release note

```release-note
ElasticJobsViaWorkloadSlices: Fixed a bug where an admission retry could cause a zero-count PodSet to lose a suitable flavor and block later scale-up. Kueue now selects a suitable flavor across retries.
```
