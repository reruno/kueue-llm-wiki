#### What this PR does / why we need it?

#15952 set the MultiKueue performance throughput floor to 35 workloads/s based on CI runs and documented the calibration. #15982 (enabling the embedlit linter) unintentionally reverted those changes to `README.md`, `configuration.yaml`, and `expectations.yaml`. As a result, the periodic went back to the 75 workloads/s floor measured locally on macOS, which no CI run reaches.

This PR reapplies #15952's changes to those three files unchanged.

Part of: #15891

#### Useful notes for your reviewer

The changed lines are identical to #15952's. The later `README.md` change from #16923 is kept.

Replaying the checker with the restored expectations against every saved summary of `periodic-kueue-test-multikueue-perf-main` gave these results:

- All 42 attempts from runs before #16235 pass (44.25–46.87 workloads/s).
- All 60 attempts since #16235 fail (29.29–34.43 workloads/s).

So the restored floor catches the throughput regression introduced by #16235. #17157 addresses it; locally it brings throughput back to the gate-disabled level, so CI is expected to return to the calibrated range. Until #17157 merges, the periodic will keep failing.

`go test ./test/performance/multikueue/...` passes.

AI tools were used to assist with the investigation, implementation, and this description.
