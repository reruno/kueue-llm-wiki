#### What this PR does / why we need it?

Follow-up to #16984. `hack/migrate-to-v1beta2.sh` always walks all eleven Kueue resource kinds. On large cluster the Workloads pass dominates the run: one of our production clusters has about 24K Workloads and about 1K other Kueue objects. Workloads are often stored at v1beta2 already, because every write re-encodes them, so operators want to migrate the small kinds first, or rerun one kind, without walking all eleven.

This PR adds `--resources=LIST`, a comma-separated list of the plural resource names the script already knows (`cohorts`, `localqueues`, `clusterqueues`, ..., `workloads`):
- The selected kinds run in the script's usual order, whatever the order in the list; a repeated name runs once.
- An empty list, an empty item (`a,,b`) or an unknown name fails during flag parsing, before any kubectl call, with exit 1 and the allowed names. So does `--resources` without `=LIST` (e.g. `--resources cohorts`), which would otherwise be ignored like other unknown flags and migrate every kind.
- Unselected kinds make no kubectl call at all, so a wrong storage version on their CRDs doesn't fail the run. Selected kinds keep the storage-version guard and every existing flag.
- With the option, one line names the selected kinds. The help text warns that objects of unselected kinds are left as they are, so check them before removing v1beta1 from the CRDs' `storedVersions`.

Related: #9094

#### Useful notes for your reviewer

- Without the option, the script's kubectl calls and output are unchanged. A fake-kubectl harness (not included) compares the call log, stdout, stderr and exit code with today's script for 7 flag combinations; with the option's own cases that is 74 new checks. All 144 harness checks pass under bash 4.2, 4.4 and 5.3, and `make shell-lint` is clean.
- `kinds` moved above the flag parser so the parser can validate against it; its contents and order are unchanged.
- Server-side dry run on a dev cluster: `--resources=cohorts --reannotate --dry-run=server` patched only Cohorts (167 objects, 2 calls) and made no call for the other kinds.
- AI disclosure: written with AI assistance (Claude); I reviewed it and ran the tests above.

#### Release note

migrate-to-v1beta2.sh: add `--resources=LIST` to migrate only the listed resource kinds, for example
`--resources=cohorts,localqueues,clusterqueues`. Default: all kinds, as before.
