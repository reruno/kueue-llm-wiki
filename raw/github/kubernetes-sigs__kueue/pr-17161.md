## Description

#### What type of PR is this?

/kind bug
/area elastic-jobs

#### What this PR does / why we need it?

With `SchedulingEquivalenceHashing`, Workloads with the same scheduling shape share a hash, and a NoFit or PreemptionNoCandidates result of one Workload bulk-moves the others to inadmissible.

A replacement workload slice only needs the quota beyond what its replaced slice reserves, but the shape includes only its total requests. Two replacements with the same requests can therefore share a hash even when only one of them fits:

| Workload | Total request | Replaced slice reserves | Additional quota needed | Fits (2 CPUs free) |
|---|---|---|---|---|
| new-1 | 8 CPUs | 6 CPUs | 2 CPUs | yes |
| new-2 | 8 CPUs | 2 CPUs | 6 CPUs | no |

When ElasticJobsViaWorkloadSlices is enabled, this PR returns SchedulingHashUnknown for a Workload with the kueue.x-k8s.io/workload-slice-replacement-for annotation, so replacement slices are excluded from equivalence hashing and are never bulk-moved by another Workload's result.

Fixes #14230
