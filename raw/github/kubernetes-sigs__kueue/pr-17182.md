## Description

A resource no node publishes, like the memory of a virtual GPU managed by a scheduler extender, has zero capacity as far as TAS is concerned, so no node fit a Pod requesting it even though the scheduler would place it.

Zero the requested amounts of the resources no node of the topology publishes, both in the requests TAS counts and in the usage it records for a domain. A resource which some node publishes is still counted on every node.

#### What this PR does / why we need it?
TAS counted a Pod's request for a resource which no node of the topology
publishes against every node's allocatable, where its capacity is always zero,
so no node fit and the Workload stayed pending:

    topology "..." doesn't allow to fit any of 1 pod(s). Total nodes: 1;
    excluded: resource "nvidia.com/gpumem": 1

Such resources (e.g. the memory of a virtual GPU managed by a scheduler
extender such as HAMi) are accounted for and placed by the scheduler, not by
Kueue, so Kueue has no capacity to compare the request against.


Zero the amounts of the resources no node of the topology publishes, both in
the requests TAS counts and in the usage it records for a domain. Zeroing
rather than dropping the entry keeps the request's type, and a zero request is
treated as unbounded. A resource which some node publishes is still counted on
every node, so a Pod requesting it is not placed on a node which lacks it.


Fixes #17164
