#### What this PR does / why we need it?

Current ratio evaluation skips zero lendable and returns 0 if all cluster queues have zero lendable.
This behavior by-passes the dividing zero case. We should make it `+inf` and make ratio calculation include it.

Part of: #16529

#### Useful notes for your reviewer

The integration test follows case in #16488.
Make the weight postive and add resource recovering after withdrawling.

Code and tests are written by human.
Use AI to help understand and analyze the problem and draft release note.

#### Release note

```release-note
FairSharing: Fixed a bug where a ClusterQueue or Cohort with a positive weight ignored a borrowed resource that its parent Cohort had nothing lendable for, so its weighted share was 0 when that was its only borrowed resource. Kueue now reports the maximum weighted share in this case (9223372036854775807 in status, +Inf in the weighted share metrics), so fair sharing ranks its workloads after those of ClusterQueues with a finite share for admission, and before them for preemption.
```
