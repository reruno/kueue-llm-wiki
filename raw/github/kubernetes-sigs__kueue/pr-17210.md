## Description

#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it?

The checks that refuse the `pods` key in a resource transformation (its input, outputs and multiplyBy) and in a device class mapping each built the same `field.Invalid` error, apart from the field path. A helper that takes the path now builds it, so each check is one line. The errors themselves don't change, and `TestValidate` now checks their message.

Follow-up to #13989, as @sohankunkerkar suggested in https://github.com/kubernetes-sigs/kueue/pull/13989#discussion_r3788453900.

#### Useful notes for your reviewer

As before, the message repeats the Workload webhook's wording without sharing a constant with it.

`TestValidate` used to ignore the message of every error. It now compares it when a case's first error sets one, as `TestLoadAndValidateFeatureGates` already does. The reserved pods cases set it, and so did one existing quotaCheckStrategy case, which is now checked as well. `BadValue` is still ignored, so I compared the four errors before and after the change with a temporary test: their type, field path, value and message are the same.

_Disclosure: I used an AI coding assistant while preparing this PR. I reviewed and tested the change myself._
