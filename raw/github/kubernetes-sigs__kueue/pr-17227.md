## Description

#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it?

A workload waiting for preemption can be requeued on every scheduling cycle. Each retry emits eight scheduler progress messages at V(2). In one observed 35-second interval, a single workload was retried 3,273 times, producing 26,184 scheduler progress log entries.

The scheduler’s maximum backoff between unsuccessful scheduling cycles is 10ms. While waiting for preemption, it repeatedly retries the same workload and emits these eight V(2) log messages per cycle. In the observed case, the scheduler retried roughly 93 times per second, producing roughly 740 scheduler progress log lines per second, plus the separate Event logs.

Move these eight messages from V(2) to V(3): `Scheduling cycle starts`, `Obtained heads`, `Snapshot taken`, `Nomination done`, `Attempting to schedule workload`, `Workload re-queued`, `Workload processing done`, and `Scheduling cycle complete`.

At the default verbosity 2, these detailed cycle messages are hidden; verbosity 3 retains them for debugging. The change applies to these messages in all scheduling cycles. Event logs, Kubernetes Event recording, and scheduling/requeue behavior are unchanged.

#### Useful notes for your reviewer

This PR changes eight logging verbosity arguments in `pkg/scheduler/scheduler.go` and updates the logging policy to classify scheduler cycle progress, scheduling attempts, and workload requeue diagnostics at V(3).

AI disclosure: This change was developed with OpenAI Codex assistance.

#### Release note

```release-note
Logging: Scheduler cycle progress, scheduling attempts, and workload requeue messages require verbosity 3 or higher.

ACTION REQUIRED
If your observability dashboard (e.g., Grafana Dashboard) relies on those scheduling logs, you have to bump the logging level to v3 or higher.
```
