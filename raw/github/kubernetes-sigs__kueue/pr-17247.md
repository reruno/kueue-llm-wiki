## Description

#### What type of PR is this?

/kind bug
/area multikueue

#### What this PR does / why we need it?

When an autoscaled RayCluster slice is evicted and marked Finished/Replaced before MultiKueue processes its quota release, the replacement shortcut skips remote cleanup. A successor can reuse the suspended RayCluster with its stale replica count, leaving surplus worker pods scheduling-gated.

Complete eviction cleanup even when the slice has already finished. Delete the remote RayCluster with foreground propagation and UID/resourceVersion preconditions, remove the remote Workload so its finalizer cannot block that deletion, and retry until deletion completes. Keep a finalizer on the manager slice and persist an acknowledgement for the current eviction only after cleanup, including after controller restarts or temporarily unavailable workers.

For elastic RayCluster chains using a MultiKueue admission check, check pending evictions before planning and again when writing quota reservation, using a direct API reader. Wake pending workloads when cleanup is acknowledged. Keep the remote prebuilt-workload pointer synchronized during suspension so an evicted slice can still be drained by the worker job controller.

#### Useful notes for your reviewer

- Scope: elastic RayCluster workloads managed through MultiKueue. Worker queues without MultiKueue retain their existing admission policy.
- Adds controller-owned cleanup annotation and finalizer; no CRD schema changes. A cleanup token includes the eviction timestamp and count to distinguish repeated evictions in the same second.
- The barrier is a retryable controller protocol, not a cross-object or cross-cluster API transaction. Admission writes recheck the barrier, including status-patch retries.
- Unit coverage includes stale informer state, Finished/Replaced ancestors, deletion held by a finalizer, unavailable workers, repeated eviction, restart from persisted completion, and stale cleanup preserving a successor's RayCluster.
- Validation: affected MultiKueue, workload-slicing, scheduler, core-controller, and RayCluster unit packages passed. `make ci-lint` and `make verify` passed with Go 1.27 in an isolated checkout.
- Manual kind manager/worker validation used real KubeRay/in-tree autoscaling and CPU quotas to model the shortage: start with two workers, scale to 18, trigger cohort reclamation, hold remote deletion with a test finalizer, free quota, and restart the manager. Both chain slices remained without quota until deletion completed. Releasing the finalizer automatically restored admission with a new RayCluster UID, two ready workers, and zero scheduling-gated pods. Test scripts and captures are outside this PR.
- AI assistance: Codex assisted with implementation and validation.

#### Release note

```release-note
MultiKueue: Complete remote cleanup for evicted elastic RayCluster slices, including slices already marked Finished/Replaced, and defer quota reservation for their slice chain until cleanup is acknowledged. This prevents a successor from reusing stale worker replicas during eviction cleanup.
```
