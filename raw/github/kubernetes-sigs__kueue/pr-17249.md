#### What this PR does / why we need it?

##### Why

KueueViz joins user groups and extra attributes with delimiters when building SubjectAccessReview cache keys. Structurally different identities can therefore produce the same key and incorrectly share a cached authorization result.

##### What

Use a fixed-size digest of an unambiguous, length-prefixed identity representation. Sort copies of groups, extra keys, and extra values so equivalent identities produce the same key regardless of input order.

Add regression tests for delimiter collisions and reordered identity attributes.

Fixes #17248

The new encoding removes ambiguous identity serialization while retaining resource-specific authorization checks. One compatibility assumption remains unresolved: cached decisions now ignore identity-attribute ordering, but authorization requests preserve that ordering. No affected order-sensitive authorization policy or exploitable bypass was established.

**Retained concerns**
- **Low · security · inferred:** The cache newly treats reordered extra values and reordered or duplicated groups as equivalent, although the emitted SAR preserves those differences. Authorization correctness therefore depends on downstream policies ignoring them. An order-sensitive consumer could receive a cached decision for a differently ordered identity; no such deployed consumer was established.
