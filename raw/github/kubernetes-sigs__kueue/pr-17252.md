#### What this PR does / why we need it?

Adds the limitation from #17203 to the Concurrent Admission page: each Variant is pinned to one ResourceFlavor, and all pod sets of the Workload go to that flavor. So a Workload whose pod sets need different flavors at the same time (e.g. a RayJob with a CPU head and GPU workers) can't be admitted while Concurrent Admission is on.

Two small edits: one sentence in "Parent and Variant Workloads" and one bullet under "Constraints". Docs only, no behavior change.

Related: #17203

#### Useful notes for your reviewer

- The wording follows the code: `generateVariant` in `pkg/controller/concurrentadmission/controller.go` sets the allowed-flavor annotation to a single flavor, and `pkg/scheduler/flavorassigner/flavorassigner.go` skips every other flavor for every pod set.
- I left out the `default-flavor` workaround from the issue since the reporter says it isn't portable.
- I couldn't run Hugo locally, so I'm relying on the Netlify preview.
- Drafted with help from an AI assistant; I checked it against the files above.
