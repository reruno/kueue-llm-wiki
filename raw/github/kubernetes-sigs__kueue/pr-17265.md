## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

The `release-utils.yml` workflow runs on every issue comment and only checks whether the comment contains a release command. It does not check the issue label, so a release command mentioned on an unrelated issue triggers the workflow and posts an `❌ Invalid issue title` message.

This adds a label guard to the `authorize` job so the workflow only runs on issues labeled `area/release`. Every downstream job depends on `authorize`, so skipping it stops all release command handling and log updates on issues that are not release issues. Behavior on `area/release` issues is unchanged.

Fixes #17256

#### Useful notes for your reviewer

The guard uses `contains(github.event.issue.labels.*.name, 'area/release')` in the `authorize` job `if:`. The `issue_comment` event already carries the full issue object with labels, so no extra API call is needed.
