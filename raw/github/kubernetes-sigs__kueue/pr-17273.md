## Description

#### What type of PR is this?

/kind bug
/area dashboard

#### What this PR does / why we need it?

The dashboard tooltip of a preempted workload should link the preemptor's UID to its workload page, but no link was shown:

- The UID pattern expected `(UID: <uid>)`, while Kueue writes `(UID: <uid>, JobUID: <job-uid>)`.
- `workloads_by_uid` mapped each UID to the workload name only, so the link would miss the namespace.

The pattern now matches `(UID: <uid>`, and `workloads_by_uid` maps each UID to `<namespace>/<name>`.

Fixes #17271

#### Useful notes for your reviewer

- The link text is now `(UID: <uid>` so the rest of the message (`, JobUID: ...)`) reads as before.
- Added a backend test for `workloads_by_uid` with two workloads of the same name in different namespaces, and a vitest test for the pattern against the real message format.
- Ran `go test ./...`, `golangci-lint`, `npm test` (106 tests pass) and `npm run build`.
