### Comment by [@mykysha](https://github.com/mykysha) — 2026-10-19T08:58:02Z

Hello @mimowo @tenzen-y @amy @kannon92 @dkaluza @mbobrovskyi !

The proposal is to start using CodeRabbit for reviewer suggestions, utilizing not only the reviewer pool information, but also the context of the PR, file edit history, and specific reviewer areas of responsibility, as well as providing a way to edit the configuration independently of OWNERS files.

This PR, at the current stage, is rather a demonstration of how reviewer list could be configured. Current implementation is using OWNERS files as a base, so this is as up to date as those ones, as some of you have already noticed.

There are two distinct ways of how this could be configured:

1) Using the official configuration, like it is done in this PR. By using suggested_reviewers_instructions it is possible to configure areas of responsibility, and adding auto_assign_reviewers can assign that list of people automatically. However, there are some drawbacks to this approach. `suggested_reviewers` is enabled by default, which means that it is already enabled in kueue, and the way it works is that it suggests the reviewer in the walkthrough section, without an option to move it to the PR description section. The need to dive deeper into the walkthrough section could be mitigated by auto_assign_reviewers, but the issue is that as of my understanding there is no current way to limit the assignment to a number of people, lets say 2 per PR, the whole relevant list will be assigned by the CodeRabbit, which is not optimal.

2) A workaround using the `high_level_summary_instructions`. We can add a similar configuration to suggest reviewers in the PR description itself, relying on the prompt. This would potentially fix the majority of the issues highlighted in the previous approach, as the suggested reviewer section would be visible at the top of the PR, we can set the limit to the number of people suggested per PR, and we could integrate the existing OWNERS files, however this approach is not native and would potentially require more maintaining.

Please let me know what you think!
