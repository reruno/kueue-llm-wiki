#### What this PR does / why we need it?

The "should not temporarily admit a finished workload on restart manager" spec restarts the manager right after the workload is admitted and finished, then expects exactly one `QuotaReserved` event. The scheduler emits that event from a detached admission goroutine (`admissionRoutineWrapper.Run`), and stopping the manager does not wait for it. The manager stops the event recorder together with its caches, so an event emitted after that is dropped. In the failing build the scheduler logged "Workload successfully admitted" 9ms after the manager shutdown started, no event was ever recorded for the workload, and the first `Consistently` poll failed with `Expected <int>: 0 to equal <int>: 1`.

This PR waits for the first `QuotaReserved` event before finishing the workload, the same way the sibling spec in this `When` block does since #14334. The post-restart `Consistently(count == 1)` check stays, so a second reservation by the restarted manager still fails the test.
