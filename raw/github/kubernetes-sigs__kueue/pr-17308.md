#### What this PR does / why we need it?
`ResolveNoFitReason` now treats attempts that are not `NoFit` as carrying the PodSet's own `Status` reason, so stages that run after the quota pass (TAS, the WAS planner in #16483) no longer need to edit `FlavorAssignmentAttempts`. The TAS empty-cluster failure path now uses `ResolvePodSetFailure` with `TopologyPlacementFailed`, and `markFlavorAttempt` is removed. This also fixes workloads getting no reason when the failing PodSet had fit quota.

#### Useful notes for your reviewer
Capping non-`NoFit` attempts at the PodSet reason means they can never raise the final reason. It also can't hide a blocker in another resource group, which a new test case covers.
