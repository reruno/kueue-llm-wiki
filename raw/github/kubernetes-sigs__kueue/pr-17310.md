#### What this PR does / why we need it?

Cherry-pick of #17255 for `release-0.19`. The automatic cherry-pick failed to apply.

The LeaderWorkerSet webhook allows a queue-name change while no replica is Ready. A group's Workload can already hold a quota reservation then, so the reconciler fails to update the Workload on every retry. This PR rejects the change in that case, and shares the check with the StatefulSet webhook.

Changes from #17255:
- The StatefulSet lookup uses `findWorkloadName` and `client.Get`, as in #16710, so the legacy Workload name fallback stays.
- The LeaderWorkerSet controller integration test is not included. `release-0.19` has no LeaderWorkerSet controller integration suite. #16710 also has unit tests only.

#### Useful notes for your reviewer

The new LeaderWorkerSet webhook case fails against the unchanged `release-0.19` webhook and passes with this PR. These pass on this branch:

```shell
go test -race -count=1 ./pkg/controller/jobframework ./pkg/controller/jobs/leaderworkerset ./pkg/controller/jobs/statefulset
```

The webhook jobs and StatefulSet controller integration suites also pass.

LeaderWorkerSet: Fixed a bug where changing the `kueue.x-k8s.io/queue-name` label while no replica was Ready, but a Workload already held a quota reservation, made the LeaderWorkerSet reconciler fail on every retry and left the Workload in the old queue. Kueue now rejects the change in that case.
