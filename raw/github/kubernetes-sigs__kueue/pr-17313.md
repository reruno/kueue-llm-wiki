#### What this PR does / why we need it?

Cherry pick of #16474 on release-0.19. The automated cherry-pick failed to apply on this branch.

Manual adjustments:
- On release-0.19 the webhooks call `jobframework.ApplyDefaultWorkloadPriorityClassWithManagedJobsNamespaceSelector` and `jobframework.WorkloadShouldBeSuspended` instead of the `integrationManager` methods used on main.
- `WorkloadPriorityClassDefaulting` is Alpha and disabled by default on release-0.19, so the webhook `TestDefault` tests enable it.
- release-0.19 builds with Go 1.26, which does not allow promoted fields in struct literals, so the new test helpers set them through the embedded structs.

#### Useful notes for your reviewer


#### Release note

```release-note
Deployment, StatefulSet & LeaderWorkerSet: Fixed a bug where, with the `WorkloadPriorityClassDefaulting` feature gate enabled, updates to an object with ready replicas and no `kueue.x-k8s.io/priority-class` label were rejected once a WorkloadPriorityClass named `default` existed, even when Kueue did not manage the object. Kueue no longer adds the default WorkloadPriorityClass to such objects on update.
```
