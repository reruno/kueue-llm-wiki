<blockquote>
<h2>v0.2.0</h2>
<h1>Cluster Inventory API v0.2.0</h1>
<p>Cluster Inventory API <code>v0.2.0</code> adds <code>multicluster.x-k8s.io/v1alpha2</code> for <code>ClusterProfile</code> and <code>PlacementDecision</code>.</p>
<p><code>v1alpha1</code> is still served and remains the storage version for both, so stored objects stay on <code>v1alpha1</code>. Both CRDs are also now in the <code>multicluster</code> category.</p>
<h2>Highlights</h2>
<h3>ClusterProfile</h3>
<ul>
<li><code>status.credentialProviders</code> is removed in <code>v1alpha2</code>. Use <code>status.accessProviders</code> instead. <code>v1alpha1</code> keeps it, deprecated.</li>
<li><code>v1alpha2</code> validates <code>spec.clusterManager.name</code> and <code>status.accessProviders[].cluster</code> more strictly.</li>
<li><code>v1alpha2</code> adds <code>kubectl get</code> columns: display name, manager, version, healthy, age.</li>
<li>New <code>LabelInventoryMemberIDKey</code> constant for correlating ClusterProfiles that represent the same member cluster (<a href="https://redirect.github.com/kubernetes/enhancements/pull/6237">kubernetes/enhancements#6237</a>).</li>
</ul>
<h3>PlacementDecision</h3>
<ul>
<li><code>v1alpha2</code> validates <code>decisions[].clusterProfileRef</code> more strictly.</li>
<li><code>v1alpha2</code> adds <code>kubectl get</code> columns: scheduler, age.</li>
</ul>
<h3>Go packages</h3>
<ul>
<li><code>pkg/access</code> applies <code>tls-server-name</code>, <code>insecure-skip-tls-verify</code>, and <code>disable-compression</code> from <code>status.accessProviders[].cluster</code> to the <code>rest.Config</code>.</li>
</ul>
<h3>Docs and release process</h3>
<ul>
<li>Added a <a href="https://github.com/kubernetes-sigs/cluster-inventory-api/blob/v0.2.0/docs/compatibility.md">compatibility and deprecation policy</a>, and a faster patch release process that needs sign-off from two maintainers.</li>
</ul>
<h2>Upgrade Notes</h2>
<p><code>v1alpha1</code> objects and clients keep working. The full migration steps are in <a href="https://github.com/kubernetes-sigs/cluster-inventory-api/blob/v0.2.0/docs/api-versions.md">docs/api-versions.md</a>.</p>
<h3>ClusterProfile</h3>
<ul>
<li><code>v1alpha2</code> clients and <code>pkg/access</code> no longer read <code>status.credentialProviders</code>. Cluster managers that only fill it need to fill <code>status.accessProviders</code> first.</li>
<li><code>spec.clusterManager.name</code> must be a valid label value.</li>
<li>Every <code>status.accessProviders</code> entry needs a <code>cluster</code> whose <code>server</code> is an absolute URL, and <code>proxy-url</code>, if set, must be a valid URL. Leave the entry out until the endpoint is known.</li>
<li><code>BuildConfigFromCP</code> now takes a <code>*v1alpha2.ClusterProfile</code>.</li>
<li><code>AccessProvider.Cluster</code> and <code>NamedExtension</code> are now this API's own types instead of clientcmd's. The <code>certificate-authority</code> field (a file path) is not available; use <code>certificate-authority-data</code>.</li>
</ul>
