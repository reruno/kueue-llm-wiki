## Description

Cherry pick of #14443 on release-0.19.

#14443: TAS: Count Pod slots and earlier PodSets in the final fit check

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

The robot could not apply #14443 on this branch because `Fits` here still looks the leaf up by its domain ID, and this branch has no `usageDomain`, `leavesOf` or virtual hostname level. The change is the same: each entry adds the Pod slot, and what the earlier entries took from a leaf is subtracted before the next entry is checked there. `updateUsage` does not exist here, so that sum is kept inline. `TestFits` uses this branch's `newTASFlavorSnapshot` signature, and the changes to `TestFitsNonHostnameLowestLevel` and `TestFitsAfterPerWorkloadRemoval` are left out because those tests do not exist on this branch.

_Disclosure: I used an AI coding assistant while preparing this PR. I reviewed and tested the change myself._

TAS: Fixed a bug where a Workload could be admitted onto a node whose Pod slots had run out earlier in the same scheduling cycle, or onto a node or topology domain with room for only some of its PodSets, leaving Pods Pending. In a ClusterQueue with a `pods` quota, a PodSet whose Pods request no resources can now be admitted.
