## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it?
Cherry-pick of #17228 onto `release-0.20`.

MultiKueue registered the ClusterProfile watch whenever the `MultiKueueClusterProfile` feature gate was enabled, even when the ClusterProfile CRD was not installed. The watch then synced against a cache entry that was never configured and the manager exited, which broke kubeconfig-based MultiKueue on clusters lacking the optional CRD.

This splits the CRD presence pre-check (`ClusterProfileCRDPresent`) from the cache configuration (`ConfigureClusterProfileCache`) and only registers the ClusterProfile watch when both the feature gate is enabled and the CRD is present. An integration test covers the feature-gate-enabled-but-CRD-absent case to confirm kubeconfig loading still works.

Fixes #

#### Special notes for your reviewer
Manual cherry-pick: the automated cherry-pick robot could not apply #17228 on top of `release-0.20` due to conflicts in `pkg/config/config.go` and `pkg/config/config_test.go` (this branch does not have main's served-version check). Resolved by keeping the release-0.20 behavior (no served-version validation) while applying the watch-skip fix.

Fixed MultiKueue failing to start when the MultiKueueClusterProfile feature gate is enabled but the ClusterProfile CRD is not installed.
