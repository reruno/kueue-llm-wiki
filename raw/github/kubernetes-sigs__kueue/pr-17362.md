#### What type of PR is this?

#### What this PR does / why we need it?
Cherry-pick of #17228 onto `release-0.19`.

MultiKueue registered the ClusterProfile watch whenever the `MultiKueueClusterProfile` feature gate was enabled, even when the ClusterProfile CRD was not installed. The watch then synced against a cache entry that was never configured and the manager exited, which broke kubeconfig-based MultiKueue on clusters that lack the optional CRD.

This splits the CRD presence pre-check (`ClusterProfileCRDPresent`) from the cache configuration (`ConfigureClusterProfileCache`) and only registers the ClusterProfile watch when both the feature gate is enabled and the CRD is present (`shouldWatchClusterProfiles`). An integration test covers the feature-gate-enabled-but-CRD-absent case to confirm kubeconfig loading still works.

#### Special notes for your reviewer
Manual cherry-pick: the automated cherry-pick robot could not apply #17228 on top of `release-0.19`. Conflicts were resolved to match this branch's shape:

- `pkg/config/config.go` / `config_test.go`: `release-0.19` has no served-version check, so the split keeps the original behavior (no version validation) plus the watch-skip fix.
- `multikueuecluster.go` uses the positional `newClustersReconciler` constructor (not the functional-options refactor on `main`); `clusterProfileCRDPresent` is threaded as a constructor argument, and existing test callers were updated.
- `multikueuecluster_test.go`: kept the new `TestShouldWatchClusterProfiles` regression test.
- `suite_test.go`: `managerAndMultiKueueSetup` now accepts optional `multikueue.SetupOption`s so the integration test can set `WithClusterProfileCRDPresent`.
