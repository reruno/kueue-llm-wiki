#### What this PR does / why we need it?

Backport #17227 to `release-0.20` with the opt-in Alpha feature gate `LogLevelForSchedulerMainLoop`, as requested in https://github.com/kubernetes-sigs/kueue/pull/17227#issuecomment-6308746147.

The gate is disabled by default, preserving the existing verbosity 2 scheduler logs on patch upgrades. Enable it with `--feature-gates=LogLevelForSchedulerMainLoop=true` to move eight scheduler progress messages to verbosity 3 and reduce repeated output while workloads wait for preemption.

#### Useful notes for your reviewer

The level calculation is centralized in the `var` section of `pkg/scheduler/scheduler.go` and used inline at all eight logging calls. It reads the gate when called so command-line feature-gate configuration takes effect.

The logging-policy document from the original PR is omitted because it does not exist on this release branch. Generated feature-gate reference and site data are included.

Validation:
- Passed: `GOTOOLCHAIN=go1.27.0 go test ./pkg/scheduler ./pkg/features -count=1`.
- Passed: `make ci-lint` with the installed repository linter.
- Passed: `make generate-featuregates` and `bin/compatibility-lifecycle feature-gates verify`.
- `TestScheduleLogging` checks all eight emitted messages at the default, disabled, and enabled gate settings through the shared scheduling test runner.

AI disclosure: OpenAI Codex implemented the feature-gate adjustment, added tests, regenerated feature-gate data, and ran validation.

#### Release note

```release-note
Logging: Added the Alpha feature gate LogLevelForSchedulerMainLoop (disabled by default) to move eight scheduler progress messages from verbosity 2 to verbosity 3. Enable it with --feature-gates=LogLevelForSchedulerMainLoop=true to reduce scheduler log volume at verbosity 2. If you enable this gate and rely on these logs for observability dashboards, set logging verbosity to 3 or higher.
```
