#### What this PR does / why we need it?

Copies only `test/integration/multikueue/reconnect_test.go` from https://github.com/kubernetes-sigs/kueue/pull/16175 at commit `c9978a48894ebca2c59627da17b5391c0e01dae4` onto main. This draft checks whether the reconnect integration tests pass in CI without the reconnect-resync production changes.

Related: https://github.com/kubernetes-sigs/kueue/pull/16175

#### Useful notes for your reviewer

This is an experimental, test-only draft for CI validation. It adds the two reconnect scenarios without changing production code or adding the unit tests from the source PR. Please do not merge while this investigation is in progress.

Local validation on upstream main `0ad490c21b7f0116ae9b45383400ab30f9cbf675`, using Kubernetes 1.37 envtest: both reconnect integration scenarios passed (`2 Passed | 0 Failed`). Both also passed on the source PR head. The focused run used `go test ./test/integration/multikueue -run '^TestMultiKueue$' -count=1 -timeout=10m -ginkgo.focus='MultiKueue Reconnect'` with the envtest assets and project directory configured.

Repository verification (`make verify`) passed using an existing Go 1.27-compatible API linter via the `GOLANGCI_LINT_KAL` override and `-o golangci-lint-kal`. The initial default run failed because its custom API linter was built with Go 1.26 while main targets Go 1.27; rerunning with the compatible binary passed without source changes.
