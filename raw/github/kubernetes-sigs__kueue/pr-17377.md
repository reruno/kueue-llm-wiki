## Description

/kind bug

#### What this PR does / why we need it?

Build the custom API linter with the Go toolchain selected for Kueue by passing `GOTOOLCHAIN=$(go env GOVERSION)` to the custom builder.

When the installed Go binary is older than Kueue's required version, Go can select Go 1.27 for Kueue but fall back to Go 1.26 after the custom builder changes to golangci-lint's module. The resulting API linter refuses to analyze Kueue, reporting that its build version is lower than the target Go version. Inheriting Kueue's selected toolchain fixes this and follows future toolchain upgrades without a separate version pin.

#### Useful notes for your reviewer

Reproduced with an installed Go 1.26.3 toolchain and Kueue selecting Go 1.27.0. Before the change, the custom API linter reported `built with go1.26.3`; after rebuilding with this change, it reports `built with go1.27.0`.

Validation:
- `make golangci-lint-kal` rebuilt the custom linter with Go 1.27.0.
- `bin/golangci-lint-kube-api-linter run --config .golangci-kal.yaml ./apis/kueue/...` passed with zero issues.
- `make verify` passed without toolchain or linter overrides.

AI usage: OpenAI Codex assisted with investigating the toolchain mismatch, implementing the change, running validation, and preparing this PR description.
