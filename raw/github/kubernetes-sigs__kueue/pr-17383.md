#### What this PR does / why we need it?

The worker PodSet count clamps `replicas` to `minReplicas`/`maxReplicas`, but two paths still used the raw `replicas`:

- **TAS**: `subGroupCount` and the index labels came from `replicas`, so a group below `minReplicas` was described as one subgroup and the ungater fell back to greedy placement.
- **MultiKueue**: the remote RayCluster received only `replicas` and `numOfHosts`, so a bound change that altered the effective count was detected but never propagated.

Both now derive from the same clamped replica count, and the sync copies all four sizing fields when a count change triggers it.

Fixes #17334

#### Useful notes for your reviewer

- Unit: `TestBuildPodSets` now checks the TAS fields of its bound cases; the adapter table covers `minReplicas`-only, `maxReplicas`-only and cleared `minReplicas`. One existing `TestUpdatePodSets` expectation changed from `subGroupCount: 1` to 2.
- Integration: one new spec in the RayCluster TAS container (~18s) and one in the MultiKueue ElasticJob container (~7s).
- Already-admitted bounded workloads are evicted only with `KubeRayEvictOnInconsistentTopologyRequest` enabled (alpha, off by default).
- Verified locally: Ray unit packages, RayCluster and MultiKueue Ray integration specs, `make ci-lint`, `make verify`.
- AI disclosure: this PR was developed with the assistance of Claude Code (root cause analysis, fix, and tests). All changes were reviewed by the author.
- What's left: nothing, ready for review.

#### Release note

```release-note
Ray integrations: Fixed a bug where worker groups with `replicas` outside `minReplicas`/`maxReplicas` got a TAS topology request that did not match the PodSet count, and where MultiKueue did not propagate `minReplicas`/`maxReplicas` to the remote RayCluster. With the alpha `KubeRayEvictOnInconsistentTopologyRequest` gate enabled, already-admitted workloads whose worker groups have `replicas` unset (KubeRay defaults it to 0) or outside the bounds are evicted once after upgrade and re-admitted with the corrected topology request.
```
