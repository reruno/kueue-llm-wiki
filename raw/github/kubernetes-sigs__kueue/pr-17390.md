#### What type of PR is this?

#### What this PR does / why we need it?

Backports #17034 to `release-0.19`.

With `FairSharingPreemptWithinNominal` enabled, fair-sharing preemption could take the nominal-quota shortcut when a preemptor was within nominal CPU quota but still borrowing another requested resource, such as memory. This could repeatedly evict and re-admit Workloads.

Related: #17022

#### Useful notes for your reviewer

This backport adapts the fix to the v0.19 preemption layout, where the fair-sharing logic and unit tests are organized differently from `main`.

Tests:
- `go test ./pkg/scheduler/preemption/...`

AI assistance was used to implement this PR.

```release-note
Scheduling: Fixed a bug where fair-sharing preemption could repeatedly evict and re-admit Workloads when a preemptor was within nominal quota for one requested resource but still borrowing another.
```
