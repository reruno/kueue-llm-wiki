#### What this PR does / why we need it?

A ClusterQueue can reference several TAS flavors whose Topology does not exist. Its `Active` condition then has reason `TopologyNotFound`, and the message lists the flavors in a different order from one reconcile to the next. The cause is that `inactiveReason` ranges over the `tasFlavors` map ([clusterqueue.go#L376-L381](https://github.com/kubernetes-sigs/kueue/blob/1ca1a42ea20355c9aac871b825e5cd07842167cc/pkg/cache/scheduler/clusterqueue.go#L376-L381)).

A changed message makes the reconciler write the status ([clusterqueue_controller.go#L582-L583](https://github.com/kubernetes-sigs/kueue/blob/1ca1a42ea20355c9aac871b825e5cd07842167cc/pkg/controller/core/clusterqueue_controller.go#L582-L583)), and the ClusterQueue watch enqueues every update of a ClusterQueue ([clusterqueue_controller.go#L393-L436](https://github.com/kubernetes-sigs/kueue/blob/1ca1a42ea20355c9aac871b825e5cd07842167cc/pkg/controller/core/clusterqueue_controller.go#L393-L436), [clusterqueue_controller.go#L517-L522](https://github.com/kubernetes-sigs/kueue/blob/1ca1a42ea20355c9aac871b825e5cd07842167cc/pkg/controller/core/clusterqueue_controller.go#L517-L522)). So the same state can cause more than one status write.

The fix ranges over `slices.Sorted(maps.Keys(c.tasFlavors))`, so the same state always gives the same message.

The test is a new row in `TestClusterQueueReadinessWithTAS`: three flavors without a Topology, expected in name order. The row declares the flavors in reverse order. On main it failed in 3 of 3 runs, and in 20 of 20 runs with `-count=20`. With the fix it passes in 3 of 3 runs.

```
go test -count=1 ./pkg/cache/scheduler/ -run TestClusterQueueReadinessWithTAS
```

`go test ./pkg/cache/scheduler/...` passes.

#### Useful notes for your reviewer

The lists of admission checks in the same function are already sorted where they are built ([clusterqueue.go#L476-L481](https://github.com/kubernetes-sigs/kueue/blob/1ca1a42ea20355c9aac871b825e5cd07842167cc/pkg/cache/scheduler/clusterqueue.go#L476-L481)).

`release-0.18`, `release-0.19` and `release-0.20` have the same loop.

#### Release note

```release-note
TAS: Fixed a bug where the `Active` condition message of a ClusterQueue listed TAS flavors without a Topology in a random order, which could cause repeated status updates of the ClusterQueue. The flavors are now listed in name order.
```
