#### What this PR does / why we need it?
When a workload has multiple PodSets and one of them needs preemption for quota while another fails topology placement even on an empty cluster, AssignTopology only marked the flavor attempt and demoted the flavors of the failing PodSet. Its Status stayed empty, which reads as Fit, so RepresentativeMode stayed above NoFit and ResolveNoFitReason skipped that PodSet. The workload then reported an empty (Pending) QuotaReserved reason that only mentioned the quota problems of the other PodSet.

Record the failure on the PodSet Status with ResolvePodSetFailure, as the WAS planner already does for simulation failures, so the topology failure is reported as TopologyPlacementFailed.
