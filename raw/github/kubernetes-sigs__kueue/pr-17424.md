#### What this PR does / why we need it?

- `needsDRAReconcile` builds the full Info only when a DeviceClass backs an extended resource. Otherwise `NeedsDRAReconcile` returns false anyway.
- `effectivePodSpecs` compares only the fields the adjustments change, instead of the whole PodSpec.

The resource-comparison optimization appears behavior-preserving. However, the new cache shortcut creates a timing-dependent path that can skip DRA quota preprocessing for resources supplied only by namespace defaults. The concern requires concurrent configuration changes and does not establish an authentication bypass or broader cluster compromise.

**Retained concerns**
- **Medium · security · inferred:** The new empty-cache shortcut can miss a concurrently introduced DeviceClass backing for an extended-resource request supplied only by LimitRange defaults. If IsEmpty observes empty during pending reconciliation and backing appears before the subsequent DRA scan, head uses raw PodSpecs and skips preprocessing; base constructs effective PodSpecs and can detect that backing. DeviceClass recovery cannot select this workload through its explicit-resource index. A workload already queued through the ordinary path can therefore retain ordinary resource accounting rather than the mapped DRA charge, potentially admitting against the wrong quota shape. A later pending reconciliation can recover it, but recovery before reservation is not guaranteed. This adds a race interval to an existing eventual-consistency limitation rather than introducing an unrestricted quota bypass.
