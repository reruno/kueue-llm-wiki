#### What this PR does / why we need it?

We keep a standalone `X` target next to `verify-X` only when `verify-X` depends on `verify-tree-prereqs`. `verify-skills-lint` and `verify-ray-version` have no prerequisites, so they already work as the fast local run, the same way `verify-unit-test-selection` does. `skills-lint` and `ray-version-verify` run the same recipes and only duplicate them.

This PR removes the standalone `skills-lint` and `ray-version-verify` targets. Use `make verify-skills-lint` and `make verify-ray-version` to run these checks locally.

#### Useful notes for your reviewer

- Follow-up to #17352, as suggested in https://github.com/kubernetes-sigs/kueue/pull/17352#discussion_r4296164091. With `skills-lint` gone, the `-q` flag that #17352 adds affects only `verify-skills-lint`.
- The `ray-version-verify` / `verify-ray-version` pair came from #16617 and has the same duplication, so it is removed here too.
- `_skills_lint_recipe` and `_ray_version_verify_recipe` are kept as is. For skills, this lets this PR and #17352 merge cleanly in either order. For ray, it keeps the two removals consistent and the diff minimal. Both can be inlined into their verify-* targets later.
