#### What this PR does / why we need it?

Amends existing KEP-16029, following [Mimowo's request to align with the merged KEP](https://github.com/kubernetes-sigs/kueue/pull/17433#issuecomment-6274111153), rather than introducing a standalone KEP. The diff remains limited to the existing KEP README and metadata; the standalone `keps/17432-metrics-client-certificate-authentication` files are not included.

Adds a proposed authenticated follow-up mode, `ClientCertificateOrBearer`, and public `clientCAFile` bundle for remote collectors. Authentication uses either the existing bearer token or a trusted client certificate; a certificate-authenticated scraper does not need a bearer token. Either identity still needs Kubernetes RBAC/SubjectAccessReview permission for non-resource `GET /metrics`. An invalid or denied certificate cannot fall back to a more privileged token identity.

The accepted initial Alpha's `Delegated` and loopback-only `None` design, gate, and v0.21 milestone are preserved. This amendment does not expand the merged initial implementation in #16035. The new mode's name, gate staging, and delivery agreement remain subject to maintainer review; this documentation does not claim implemented support.

Related: #17432, #16029. Implementation prototype: #17459.
