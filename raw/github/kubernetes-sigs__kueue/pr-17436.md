#### What this PR does / why we need it?

With `SchedulerLibraryIntegration` and `SchedulerLibraryDeepIntegration` enabled, a Job carrying `kueue.x-k8s.io/podset-preferred-topology` is admitted, but the scheduler library has no placement support for a preferred topology request. The Job is left suspended and only the controller logs say why.

Reject a new or changed preferred topology request during Job admission when the deep integration gate is enabled, naming the gate in the message. Required and unconstrained requests are unaffected, and so is any request made with the gate disabled.

On update, an unchanged annotation is still accepted. Jobs that already carry it can therefore be suspended, resumed and cleaned up after the gate is turned on, matching the treatment of the wait-for-pods-ready annotation in `validateUpdate`.

Fixes #17427

#### Useful notes for your reviewer

- The guard is in `validateTopologyRequest`, which now receives `oldJob` (nil on create). The update path compares the preferred annotation value so unchanged requests are tolerated.
- The equivalent Workload-level guard is being added separately in #17419. This change is independent: it rejects earlier, at Job admission, so the user gets an error instead of an accepted Job whose Workload creation keeps failing.
- Covered by new cases in `TestValidateCreate` (rejected with the gate on, accepted with the gate off, and required/unconstrained accepted with the gate on) and `TestValidateUpdate` (unchanged accepted, added and changed rejected). The cases fail when the guard is removed.
- Ran `go test -count=1 ./pkg/controller/jobs/...` and `go vet ./pkg/controller/jobs/job/...`. `make verify` with the full lint toolset was not run locally.
- AI usage: this change was prepared with AI assistance (opencode) and reviewed by me before submission.

```release-note
Jobs with a preferred topology request are now rejected at admission when the SchedulerLibraryDeepIntegration feature gate is enabled, instead of being admitted and then staying suspended without an explanation.
```
