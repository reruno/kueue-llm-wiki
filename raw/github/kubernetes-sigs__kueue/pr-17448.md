## Description

#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it?

Follow-up to #17414 for the `CustomMetricLabels` path. `PendingBreakdownInLocalQueue` scanned every pending workload of the ClusterQueue on every queue change. `localQueueCounts` now keeps a `LabelValsTracker` per LocalQueue instead, like `PendingWorkloads` does for the ClusterQueue.

Part of #17412

#### Useful notes for your reviewer

With one Workload custom label in `make run-performance-scheduler`, `reportLQPendingWorkloads` went from 31.6% to 2.7% of Kueue CPU. This should land before `CustomMetricLabels` goes Beta.

#### Release note

```release-note
Observability: Improved the performance of LocalQueue pending-workload metrics with Workload custom metric labels by avoiding a scan of all pending workloads in the ClusterQueue on each queue change.
```

**Security Blast Radius**
- _inferred_ — The security-relevant resource effect is additional in-memory accounting in the shared scheduler process. Queue identity remains namespace/name scoped, and the changed breakdown feeds observability rather than granting workload admission or additional authority.

**Security Findings and Attack Paths**
- _inferred_ — Unbounded growth through arbitrary workload-label churn is not supported for the validated production path. At most two Workload labels, each with twelve configured values plus the untracked sentinel, bound the tracker to 169 combinations per status per LocalQueue. Retaining zero-count entries therefore adds bounded storage rather than a newly unbounded attack path.

**Trust Boundaries and Controls**
- _observed_ — The tracker derives LocalQueue identity from the workload namespace and queue name. Read results are newly allocated copies, so consumers cannot mutate queue-owned tracker state through the returned objects.

**Resilience and Maintainability Implications**
- _inferred_ — Tracker-level transitions are atomic, and empty per-status trackers are removed. The separate metrics lock can provide a snapshot that briefly lags a queue mutation, but the inspected consumer uses it for metric reporting; no persistent cross-queue accounting error or security-control dependency was identified.
