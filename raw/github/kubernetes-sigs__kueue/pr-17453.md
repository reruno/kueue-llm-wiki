## Description

#### What type of PR is this?

/kind bug
/area tas

#### What this PR does / why we need it?

When a node gets an untolerated `NoSchedule` taint or becomes NotReady, the TAS node controller treats Succeeded Pods as not progressing, the same as Failed ones.
If all Pods of the Workload on that node have succeeded, the node is still marked unhealthy. With no free node, Kueue evicts the whole Workload and deletes Pods that are still running on healthy nodes.

This PR keeps the node healthy for a Workload when every Pod that its `TopologyAssignment` places on the node has succeeded, since none of them needs to run again.

Fixes #17379

#### Useful notes for your reviewer

- The docs for node failure and untolerated taints in `topology_aware_scheduling.md` describe the new exception.

- This PR was prepared with AI assistance.

#### Release note

```release-note
TAS: Fixed a bug where a tainted or NotReady node whose Pods of a Workload had all succeeded was marked unhealthy, which could evict the Workload and restart its running Pods on other nodes.
```

## AI summary

When `TASReplaceNodeOnPodTermination` is enabled, TAS does not treat a node as failed for a Workload if all Pods assigned to that node have succeeded. This prevents unnecessary Workload eviction and restarts of Pods on healthy nodes. For multi-Pod PodSets without a Pod index label, Kueue cannot determine completion, so the exception does not apply. The documentation describes this behavior.

### Suggested release note

TAS: Fixed a bug where a node taint or failure could cause Kueue to evict a Workload after all Pods assigned to that node had succeeded. Kueue now keeps the node healthy for that Workload when `TASReplaceNodeOnPodTermination` is enabled.

  **Apply the completed-node rule to Workloads whose multi-Pod PodSets have no pod index label.**
  
  `podIndexKey` returns no index for a PodSet with `Count > 1` when its `TopologyRequest` is nil or has no `PodIndexLabel`. `allAssignedPodsSucceeded` then returns false, and `checkPodsOnNode` marks the node `workloadUnhealthy`, even when every Pod of the Workload on that node has succeeded.   Admission can produce this shape. Explicit `required`, `preferred`, or `unconstrained` topology annotations bypass the nil-request return in the default topology path. The topology ungater admits the shape with greedy assignment.
