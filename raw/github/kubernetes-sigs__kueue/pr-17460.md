#### What this PR does / why we need it?

Extracts the elastic replacement-accounting fix from #16339, following the
split proposed in https://github.com/kubernetes-sigs/kueue/issues/16354#issuecomment-6273950508.

With the alpha `ElasticJobsViaWorkloadSlicesWithTAS` feature enabled, preemption
evaluation can count the predecessor slice's TAS reservation twice: once in the
snapshot and again through the replacement's `PreviousAssignment`. A feasible
scale-up can consequently be rejected.

For example, on a four-CPU node, the predecessor uses two CPUs and a
lower-priority workload uses the remaining two. A four-CPU replacement should
be feasible after preempting the lower-priority workload.

The fix centralizes topology placement through
`Assignment.FindTopologyAssignments`, used by flavor assignment, preemption
feasibility evaluation and native assignment recomputation. It temporarily
removes the predecessor's cached TAS usage only when that exact Workload UID is
still accounted for in the owning ClusterQueue snapshot, and restores it after
the query. Quota usage is not removed by this helper. The cycle-local released
set belongs to the ClusterQueue snapshot so the helper can reject a second
deduction of already-released usage.

This PR does not add residual-Pod accounting, a Pod tracker or a scheduling-policy
change. Those remain separate work in #16339 and the shared tracker extraction.

Related: #16354, #16339, #16337. This is a focused accounting extraction, not a
complete fix for the residual-bound-Pod issue in #16337.
