## Description

#### What type of PR is this?

/kind cleanup
/area was

#### What this PR does / why we need it?

WAS failure reporting repeatedly scans PodSet assignments and flavor attempts. Batch these updates so processing takes linear time in the number of PodSets, assigned resources, and attempts.

Preserve existing failure reporting and feature-gate behavior. Add unit tests for multiple failed PodSets, disabled observability, and empty failures.

Fixes #17347

#### Useful notes for your reviewer

- recordSimulationFailures now builds failure statuses once, then calls Assignment.ResolvePodSetFailures.
- Batch method scans PodSets once. Failure lookup uses a map.
- Each failed PodSet scans assigned flavors and attempts once.
- Complexity changes from repeated PodSetAssignmentByName lookups to linear processing.
- Existing ResolvePodSetFailure behavior remains unchanged for other callers.
- Only assigned flavor attempts are updated. Other attempts keep their original result.
- UnadmittedWorkloadsObservability remains the gate for attempt updates.
- No API, scheduler flow, or user-facing behavior change.
