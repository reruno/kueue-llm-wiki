#### Useful notes for your reviewer
High level overview of the approach

Partial preemption consists from 2 steps: Picking victims, Scale down mechanism. Only Ray and Spark are supported in this POC

##### Picking victims
high wl - high priority workload 
wl - workload 
wls - array of wl sorted by priority (ascending) (all have minCount and part of partial preemption)
wl.minCount - minimum count of pods that we can have 
```
high wl comes -> 
evaluate lower prio wl from wls -> 

highWlRequest = high wl quota request
targets = [] # targets ie victims whom to evict to free space for high prio wl
for i in len(wls)
     # workload that could be partially evicted, 
     # we should be able to add to targets arr only a slice of this workload to not evict whole workload
    reclaimableSlice = wls[i].currCount - wls[i].minCount  
    1. if reclaimableSlice >= highWlRequest then we add to targets highWlRequest, 
    otherwise add to targets reclaimableSlice, highWlRequest -= reclaimableSlice
    if wls[i] is already reduced then we add whole wls[i] to targets ->
    after steps 1. quota is 
    enough -> break, we found quota for high wl
    not enough -> continue loop

if targets quota is not enough then high wl is pending
```
##### Scale down 
Kueue forcefully removes executor pods + lowers the workload's pod count (this reclaims quota) -> 
job runtime (spark driver) creates new pod -> 
kueue automatically gate it (here the state of workload is similar to pre state for partial scale up feature) -> 
partial scale up feature scales up the workload when quota is available
