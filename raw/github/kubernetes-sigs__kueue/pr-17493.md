## Description

#### What type of PR is this?

/kind bug
/area dashboard

#### What this PR does / why we need it?

Workload and LocalQueue names are only unique within a namespace. The dashboard tracked expanded rows by workload name, so expanding one workload also expanded any workload with the same name in another namespace, and both rows shared a React key. The ClusterQueue detail page keyed its LocalQueue rows by name too.

Rows are now keyed by namespace and name, via a small `workloadKey` helper on the dashboard.

Fixes #17492

#### Useful notes for your reviewer

- Added `DashboardRows.test.jsx`, which renders two workloads with the same name in different namespaces and checks that expanding one does not expand the other. It fails without the fix.
- The ClusterQueue detail change is only the React key, so it has no separate test.
- Ran `npm test` (114 tests pass) and `npm run build` in `cmd/kueueviz/frontend`.

#### Release note

```release-note
KueueViz: Fixed expanding a workload on the dashboard also expanding workloads with the same name in other namespaces.
```
