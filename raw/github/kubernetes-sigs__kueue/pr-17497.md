#### What this PR does / why we need it?

> [!IMPORTANT]
> **This PR is stacked on #14590** (KEP-975 partial preemption POC by @zhengchenyu, currently on hold).
> **Only the last commit, "Support partial preemption for RayCluster", is for review.** The first commit, "POC: support partial preemption (from upstream PR 14590, rebased)", is #14590 rebased onto main. It is included only so that CI can build, and it will be dropped once #14590 (or its successor) merges.

Stage 1 of partial preemption for KubeRay: a standalone, elastic RayCluster.

- **Opt-in.** Set the `kueue.x-k8s.io/partial-preemption: "true"` annotation on a RayCluster. This requires the `PartialPreemption` feature gate (alpha), an elastic workload (workload slicing enabled), the Ray autoscaler off, exactly one worker group, and `numOfHosts <= 1`.
- **Shrink instead of evict.** When the scheduler partially preempts the Workload, the job reconciler lowers the worker group `replicas` to the reclaim target, or to the admitted count after a partial admission, instead of suspending the whole RayCluster.
- **Partial admission floor.** The worker group `minReplicas` becomes the PodSet `minCount`, so it is also the floor for partial admission, and Kueue never shrinks below it.
- **Restore on stop.** Kueue records the original and the lowered worker replicas in the `kueue.x-k8s.io/raycluster-shrunk-worker-replicas` annotation, with the value `<orig>/<set>`. When the cluster is stopped (evicted or deactivated), Kueue restores the original replicas, unless the user changed them since, so the cluster is requeued at its original size.
- **Webhook.**
  - The RayCluster webhook validates the opt-in requirements on create.
  - On update, the validation is ratcheted, but only for objects that were already managed, so adding a queue name cannot bypass it.
  - The annotation and the worker group `minReplicas` are immutable.
  - When the gate is off, the gated validation is skipped, but the annotation stays immutable.
- **RayJob and RayService** reject the opt-in annotation on managed jobs. They are covered in later stages.

#### Useful notes for your reviewer

**Known limitations (Stage 1)**
- The Ray autoscaler must be off (`enableInTreeAutoscaling` unset or false).
- Only a single worker group is supported.
- `numOfHosts` must be 1 or less.
- Nothing is restored while the cluster is running. The original replicas come back only when the cluster is stopped.
- Kueue does not shrink the cluster while a scale-up slice is pending.
- KubeRay, not Kueue, picks which worker Pods to delete when replicas are lowered.
- If the Workload is deleted while the cluster is shrunk, nothing restores the original worker replicas.

Stages 2 (RayJob) and 3 (RayService) remain, so this PR does not close #17430.
