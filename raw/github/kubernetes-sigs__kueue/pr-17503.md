## Description


#### What type of PR is this?

/kind bug
/area tas

#### What this PR does / why we need it?

When a TAS Workload has reclaimable Pods, the second pass for a failed node builds the PodSet assignments from requests scaled down by those Pods (for example count 3 → 1).
The Workload webhook only allows `topologyAssignment` and `delayedTopologyRequest` to change on an admission, so the update is rejected with `field is immutable` and retried forever.
The recreated Pod stays `SchedulingGated` even though free nodes exist.

This PR keeps the admitted PodSet assignments in the second pass and takes only the topology fields from the new assignment.

Fixes #17372

#### Useful notes for your reviewer

- The first admission does not go through this path, so its behavior is unchanged.
- Tests:
  - New `TestScheduleForTAS` case; it fails without the fix (count 1) and passes with it.
  - `make test`, and the integration suites `singlecluster/tas`, `singlecluster/scheduler` and `singlecluster/controller/admissionchecks/provisioning` pass.

- This PR was prepared with AI assistance.

#### Release note

```release-note
TAS: Fixed a bug where replacing a failed node never completed for a Workload with some Pods already succeeded, leaving the recreated Pod gated. Kueue now keeps the admitted Pod count and resource usage when it updates the topology assignment.
```
