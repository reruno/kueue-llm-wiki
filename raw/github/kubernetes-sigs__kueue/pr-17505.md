## Description

This is a manual cherry-pick of #17454

Adjustments for this branch, which has diverged from main: the one conflicting hunk is in `pod_controller_test.go`. This branch's "deleted pods in group should not be finalized if the workload doesn't match" case still sets `WorkloadIdentifierAnnotations: false`, a gate that no longer exists on main, so that case became the gate-off twin and keeps the setting alongside `FinalizeTerminatingPodGroups: false`. On this branch the gate is Alpha and off by default, so the gate-on case enables it explicitly. Verified locally on the release-0.19 tree: build, unit tests with `-race`, the `FinalizeTerminatingPodGroups` integration specs, and lint.

I used AI tools to help prepare this cherry-pick; I reviewed and tested the result.

/assign mimowo

```release-note
Pod integration: Fixed a bug where a pod group's new Workload could be built from a pod still terminating on a node, pinning it there so it could not be admitted. On this branch the fix applies when the `FinalizeTerminatingPodGroups` feature gate is enabled (Alpha, off by default).
```
