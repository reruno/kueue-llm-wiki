## Description

#### What type of PR is this?

#### What this PR does / why we need it?

`requeueState.count` is only incremented by PodsReadyTimeout evictions and only cleared on deactivation. With a finite `waitForPodsReady.requeuingStrategy.backoffLimitCount`, long-lived Workloads (LeaderWorkerSet, StatefulSet, serving pod groups) are eventually deactivated by evictions from past, recovered incidents. In production, a serving LWS group Workload continuously PodsReady for 36.5 days was deactivated by ~69 timeouts from one incident weeks earlier.

This PR adds the Alpha feature gate `ResetRequeueStateOnPodsReady`. When enabled, once an admitted, non-evicted Workload has held `PodsReady=True` during its current admission for at least the resolved WaitForPodsReady timeout (including the per-workload override), the whole `requeueState` is cleared with a merge patch, as the deactivation path does, and a `RequeueStateReset` event records the previous count. If readiness drops earlier, the measurement restarts, so a flapping Workload still counts every timeout.

Fixes #17519

#### Useful notes for your reviewer

- No API, CRD, Helm or config changes. With the gate on, `backoffLimitCount` counts timeouts since the last sustained-ready period rather than over the Workload's lifetime. KEP-1282 and the website (Requeuing Strategy, Workload concepts) describe the reset and its risk of unbounded retries. Already-deactivated Workloads are not reactivated.
- Later commits fix the `pull-kueue-test-integration-shard-2-main` failure (merging three recheck delays with `min`/`max` picked the later one, even with the gate off), skip evicted Workloads, whose `PodsReady` can stay True while they drain, and start the window at the admission, so a `PodsReady=True` kept from an earlier admission does not count.
- Coverage: 47/47 changed statement lines (`go test -race -covermode=atomic -coverpkg=./...`, scoped to the diff). Breaking any guard of the reset or the recheck merge fails a unit test, and the integration spec fails when the merge ignores the reset timer. The `!IsAdmitted` guard is reachable (quota reserved, AdmissionCheck still Pending) and has a test.
- Known limitation: an admission SSA apply from a stale copy could restore a just-cleared count, as with the existing clear on deactivation.
- Committed with the help of an AI agent I operate; the design, review and testing decisions were made by me.
