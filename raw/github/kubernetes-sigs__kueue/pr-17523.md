## Description

Fixes #17522.

## Summary

Prevent DynamicQuotaOrchestrator from accepting CapacityProvider status synchronized for an older spec generation.

## Changes

- Validate `CapacitySynchronized.ObservedGeneration` against the current provider generation.
- Report `ProviderNotReady` with a diagnostic when the synchronization condition is stale.
- Add unit regression tests for stale and current generations.
- Add integration coverage for spec updates, delayed status synchronization, and automatic recovery.
- Update integration test fixtures and document the generation contract.

## Validation

Go unit and integration tests have not yet been executed successfully. GitHub CI validation is required.

## Review considerations

Please review the compatibility implications for external CapacityProvider implementations that do not populate `ObservedGeneration`.

The fix intentionally preserves previously applied effective quota retention behavior.

The change rejects stale capacity observations without expanding privileges or introducing a new external interface. The principal risk is upgrade compatibility: providers that omit ObservedGeneration will stop quota recalculation, while previously applied quotas remain in force. Compatibility with deployed providers has not been established.

**Retained concerns**
- **Low · reliability · inferred:** A previously accepted provider that publishes CapacitySynchronized=True without a matching ObservedGeneration will now keep referencing DQOs not ready. For distributing DQOs, this pauses quota updates while preserving last-applied ClusterQueue and Cohort quotas, creating a conditional upgrade-time quota-control drift risk until the publisher becomes compatible.

<details>
<summary><strong>Security review details</strong></summary>
<dl>
<dd>

**Security Blast Radius**
- _inferred_ — Influencing this gate requires control over a referenced provider's spec or status, not merely workload input. A shared provider can affect every referencing DQO; downstream quota scope can encompass a configured Cohort subtree and its ClusterQueues. CapacityProvider is cluster-scoped, but the review did not establish which deployed principals can modify it.

**Trust Boundaries and Controls**
- _inferred_ — Matching ObservedGeneration does not authenticate the publisher or independently verify reported capacity: DQO still trusts status obtained through the Kubernetes client. The PR strengthens snapshot acceptance without changing the controller's declared read-provider and write-quota authority. Actual deployment authorization remains outside the inspected evidence.

**Resilience and Maintainability Implications**
- _observed_ — The existing distribution path writes targets individually, skips unchanged quota values, and accumulates update errors without rolling back successful writes. It does not re-read provider generation before writing quotas, and DQO status is persisted afterward. These are pre-existing consistency limitations, not newly introduced findings; the added gate protects the discovery snapshot rather than providing a transaction-wide freshness guarantee.

**Hardening Proposals**
- _proposed_ — Coordinate rollout so external publishers report the current generation before upgraded discovery depends on them. Monitor ProviderNotReady together with last-applied target quotas, rather than interpreting nil DQO effective capacity as quota revocation.

  // providerNotReadyMessage returns why the CapacityProvider's capacity cannot be
  // trusted, or "" if CapacitySynchronized=True for the current generation.
  // A spec update increments Generation without clearing the previous condition
  // or reported capacity, so a True condition from an older generation is stale.
  func providerNotReadyMessage(cp *kueuealpha.CapacityProvider) string {
  	cond := apimeta.FindStatusCondition(cp.Status.Conditions, kueuealpha.CapacityProviderCapacitySynchronized)
  	switch {
  	case cond == nil || cond.Status != metav1.ConditionTrue:
  		return fmt.Sprintf("CapacityProvider %q is not synchronized", cp.Name)
  	case cond.ObservedGeneration != cp.Generation:
  		return fmt.Sprintf("CapacityProvider %q synchronization is stale (observedGeneration=%d, currentGeneration=%d)",
  			cp.Name, cond.ObservedGeneration, cp.Generation)
  	}
  	return ""
  }
