#### What this PR does / why we need it?
`runTASScheduleTestCases` installs the recording simulator only when a case enables
`SchedulerLibraryIntegration`. Three cases in `pkg/scheduler/scheduler_tas_schedlib_test.go`
set simulator expectations without the gate, so only the non-simulator path ran and their
simulator assertions were skipped.

- Enable `SchedulerLibraryIntegration` in the three cases, merged with existing feature gates.
- Fail fast in `runTASScheduleTestCases` when simulator expectations are set while the gate is off.
- Update the stale comment in the `overlap recompute` case.

Fixes #17482

#### Useful notes for your reviewer
- `go test ./pkg/scheduler/...` passes.
- Before this change, the `failSimulatorPreemption` case logged no "simulated failure"; it now runs that path in all six scenarios.
- Removing the gate from one of the cases makes the new harness check fail.
