## Description

#### What type of PR is this?

/kind bug
/area dashboard

#### What this PR does / why we need it?

The workload detail page and the Workloads page tooltip read `workload.ownerReferences`, but owner references are under `metadata.ownerReferences`, so they always showed "N/A". The events table used `event.name` as the row key, which is also under `metadata`.

Both now read from `metadata`. The event rows use `metadata.uid` as the key.

Fixes #17532

- Added `WorkloadDetailOwner.test.jsx`. It fails without the fix.
