#### What this PR does / why we need it?

Manual backport of #16044 to `release-0.19`, following the
[maintainer's request](https://github.com/kubernetes-sigs/kueue/pull/16044#issuecomment-6309012575).
The source is the actual main squash commit
`08958076ed65b96afb4d391a0401ee91373cba04`.

Retain a StatefulSet's Workload quota during scale-to-zero while a Pod owned by
that StatefulSet UID remains active. Once no owned Pod is active, transition
the Workload to `OnHold`; keep that condition stable against admission-gate
and queue-blocker reconciliation, including when
`UnadmittedWorkloadsObservability` is disabled (the release-0.19 default).

The backport retains Pod-event wakeups and the single activity-deadline
recheck from the original fix, without adding periodic polling or changing
the existing Pod activity semantics.

Related: #16043, #16044. The release-0.20 backport is #17540.

#### Useful notes for your reviewer

The automatic release-0.19 cherry-pick failed on three files. This manual
adaptation preserves the release's legacy Workload-name fallback and separate
StatefulSet PodReconciler. It uses the existing global integration helpers,
without importing main's IntegrationManager or workload-level PodsReady
annotation refactors.

The owner-indexed activity check also needs main's StatefulSet Pod-owner index,
which was absent on this branch. The backport includes that small index and
its five-case unit test, plus the existing main Pod wrapper helper for explicit
owner UIDs. Fake-client setup registers both owner and PodGroup indexes where
the release's Reconcile path needs them. Legacy condition expectations use
the existing normalizer without discarding the OnHold reason or message.

The backport is one commit, `7241917e1`, based on release-0.19 commit
`c72ab5e32`. Local validation passed with Go 1.26.3 and envtest Kubernetes 1.36.0:

- Complete core, Pod, StatefulSet, and testing-helper unit packages.
- Core OnHold and Pod activity race tests, and the complete StatefulSet unit
  package with the race detector, each repeated three times. The core matrix
  records 84 passes across the seven queue blockers and both observability/patch modes.
- Complete core (87 specs) and StatefulSet (17 specs) integration suites.
- Standard four-module `make ci-lint CI_LINT_NPROCS=1`, zero issues.
- `git diff --check`.

Negative Go-overlay checks confirm the regressions are meaningful: removing
the legacy guard fails 14 queue-blocker combinations, and bypassing the active
Pod wait fails three quota/deadline cases. The actual worktree was not modified
for either negative check. Upstream CI must be checked separately on this CP.

No new feature gate, Kubernetes API change, or Kubernetes StatefulSet-controller change
is introduced. Full `make verify` is not claimed.

#### Release note

```release-note
StatefulSet: Retain Workload quota during scale-to-zero while an owned Pod is active, and release it once the Pod is inactive.
```
