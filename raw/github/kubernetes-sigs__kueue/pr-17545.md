## Description

﻿#### What type of PR is this?

/kind bug
/kind api-change

#### What this PR does / why we need it?

Adds `+kubebuilder:validation:Minimum=0` to `backoffLimitCount`,
`backoffBaseSeconds` and `backoffMaxSeconds` in
`ProvisioningRequestRetryStrategy`, and regenerates the CRD manifest and
the Helm chart copy.

Without a lower bound, a negative `backoffBaseSeconds` produces a
negative requeue delay and a negative `backoffMaxSeconds` removes the
exponential cap. The same fields are already rejected when negative in
the `Configuration` API (`pkg/config/validation.go`).

Fixes #17544

#### Useful notes for your reviewer

- Changed files: the API types, the CRD under `config/components/crd/bases`,
  the Helm chart CRD copy, and `pkg/workload/admissionchecks_test.go`.
- Adds `TestUpdateAdmissionCheckRequeueState`, a table-driven unit test
  covering normal doubling, the cap, a negative base, a negative max,
  and a base larger than the max. The negative cases document the
  behavior the new CRD markers prevent.
- Objects already stored with negative values are not modified, but an
  update to them will be rejected until the values are corrected.

#### Release note

```release-note
ProvisioningRequestConfig: Added validation that rejects negative values for `retryStrategy.backoffLimitCount`, `retryStrategy.backoffBaseSeconds` and `retryStrategy.backoffMaxSeconds`. Previously a negative value was accepted and led to invalid requeue delays.
```
