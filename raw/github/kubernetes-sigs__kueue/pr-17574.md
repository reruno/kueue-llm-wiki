#### What this PR does / why we need it?
This is a manual cherry-pick of #17059 to `release-0.19`.

When a MultiKueue batch/Job is re-dispatched after eviction, the new worker Job starts with `status.failed=0`. The adapter was replacing the manager Job status wholesale, so the Kubernetes 1.35+ API server rejected the patch (`cannot decrease the failed counter`), preventing the Job and Workload from updating and causing them to stall.

This backports the `mergeJobStatus` fix which clamps `failed` to `max(local, remote)` while still copying all other active status fields from the worker.

Related: #17047
