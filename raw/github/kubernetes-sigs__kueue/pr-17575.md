#### What this PR does / why we need it?
Fixes #17521

Currently, Kueue's deployment webhook prevents updating `kueue.x-k8s.io/queue-name` if `ReadyReplicas > 0`. Because Deployments are handled through the plain Pod integration where each replica pod gets its own workload, changing the deployment queue label updates `spec.template`, triggering a rolling update. New pods queue under the new queue while active pods under the old ReplicaSet keep running until replaced.

This change relaxes the check to allow updating the queue name while `ReadyReplicas > 0`, while still preventing removing the queue name entirely (`newQueueName == ""`).

#### Useful notes for your reviewer
Updated unit tests in `pkg/controller/jobs/deployment` and integration tests in `test/integration/singlecluster/webhook/jobs` to verify that queue updates succeed on active Deployments and that clearing the queue label remains forbidden.

#### Release note
```release-note
Deployment: Allow adding or changing the `kueue.x-k8s.io/queue-name` label on Deployments with ready replicas. The change starts a rolling update, and new Pods wait for admission in the new LocalQueue.
```

### Comment by [@mbobrovskyi](https://github.com/mbobrovskyi) — 2026-10-30T12:22:39Z

Thanks for the PR! One interaction to sort out before merge:

Default() calls ApplyDefaultLocalQueue on UPDATE as well. Until now, an update to a running Deployment without queue-name, in a namespace with a default LocalQueue, was rejected (#17863). With this change the update is accepted, and the webhook silently adds queue-name: default and gates the pod template. So an unrelated update, like an image bump, an annotation change or kubectl rollout restart, moves a running service under Kueue and starts a gated rolling update.

#17865 fixes #17863 by applying the default only when the queue name can be set. Could we land #17865 first, or align the two? Then an explicit add is allowed but the default isn't applied on arbitrary updates. Also, please add a test: a running Deployment without a queue, a default LocalQueue, and an annotation update → no queue-name is added.
