#### What this PR does / why we need it?

Manual cherry-pick of #17041 to `release-0.19`. The automatic cherry-pick (#17476) failed its required unit-test and verify checks.

When the scheduler's admission write returns an error, it rolled back the assumed cache entry unconditionally. The apiserver can commit a write while the client sees an error, such as a timeout. If the Workload's update event arrived before the rollback, the rollback removed the admitted Workload from the cache, and nothing re-added it until its next update. The ClusterQueue then under-counted its usage.

The rollback now uses `Cache.DeleteWorkloadIfUnchanged`, which removes the entry only if the cache still holds the assumed version.

#### Useful notes for your reviewer
- The code matches #17041. The only differences are signature adaptations: release-0.19's `AddOrUpdateWorkload` and `addOrUpdateWorkloadWithoutLock` take `(log, wl)` with no `ctx` or `opts`, so the new helper and its tests use that form. The tests also needed the `runtime` import.
- Tests: `TestDeleteWorkloadIfUnchanged` (cache) and `TestSchedulerKeepsAdmittedWorkloadWhenCommittedAdmissionWriteReportsError` (scheduler, both `WorkloadRequestUseMergePatch` modes). The scheduler test fails without the `scheduler.go` change and passes with it.
- Verified locally: `go test ./pkg/...` and `make ci-lint` pass. 
- AI assistance: the backport and its verification were prepared with AI assistance, per the Kubernetes AI tool usage policy.
