#### What this PR does / why we need it?

`TASAssignmentsResult.Failure()` ranged over a map and returned the first failed PodSet it visited. When several PodSets fail at once, such as a leader and its workers or PodSets in different TAS flavors, the PodSet named in the Workload's `QuotaReserved` condition and event could change between scheduling cycles, and each change caused an extra status patch. This PR visits the PodSets in sorted order, as `FindTopologyAssignmentsForWorkload` already does for flavors.

None

#### Release note

```release-note
TAS: Fixed a bug where the pending message of a Workload with several PodSets that could not be placed could name a different PodSet in each scheduling cycle. Kueue now reports the first failed PodSet in alphabetical order.
```
