## Description

## Summary

Fixes #17583.

Scope ResourceSlice-triggered inadmissible Workload retries to the logical quota resources associated with the affected DRA driver, rather than the union of all configured drivers.

## Changes

- Maintain a driver-to-quota-resource mapping for both counter-based and capacity-based DRA sources.
- Enqueue reconciliation by driver identity, preserving the affected driver across ResourceSlice deletion.
- Handle create, update, and delete notifications without requiring deleted ResourceSlices to be fetched.
- Add regression coverage for driver isolation, unrelated-driver filtering, shared logical resources, and ClusterQueues covering multiple resources.

## Implementation details

The existing `ClusterQueuesForResources()` lookup is retained. The reconciler now supplies the quota resources associated with the changed driver.

Driver-keyed requests also coalesce multiple ResourceSlice changes from the same driver.

This builds on #13639 while keeping the separate DRA device-feasibility requirements discussed in #15769 in scope for review.

## Testing

Regression tests added in `pkg/controller/core/resourceslice_controller_test.go`.

Local tests have not yet run. CI validation is pending.

## Review notes

The change is intentionally limited to ResourceSlice retry targeting and does not modify quota accounting or public APIs.

Please review the event-to-driver mapping and deletion/recreation behavior carefully.
