#### What this PR does / why we need it?

An elastic RayCluster can scale up before its head first becomes ready. If the new workers wait for quota, the cluster-wide state never reaches `ready`, so the already admitted head-only Workload can hit `PodsReadyTimeout` and suspend a healthy head.

Use `HeadPodReady=True` for elastic RayCluster readiness. Missing, False, and Unknown conditions remain unready, even if the legacy cluster state retains an earlier `ready` value.

While a scale-up replacement waits for admission, update readiness on the retained admitted Workload. An optional jobframework selector limits this behavior to RayCluster; non-elastic RayClusters and the RayJob/RayService integrations keep their existing behavior. Prebuilt Workloads retain their assigned readiness target.

#### Useful notes for your reviewer

- The existing `ElasticJobsViaWorkloadSlices` gate and elastic-job annotation control this behavior. No API fields, dependency changes, or PodSet readiness counting are added.
- A healthy head is sufficient for elastic readiness even if workers remain unready. Worker recovery remains with KubeRay; head readiness loss still starts the existing recovery timeout.
- Unit tests cover the condition/state combinations, gate and annotation behavior, prebuilt Workloads, and reconciliation of a retained admitted Workload while its replacement waits for quota. The reconciliation regression tests fail when the new selector path is removed.
- Validation: `go test ./pkg/controller/jobs/raycluster ./pkg/controller/jobframework ./pkg/controller/core ./pkg/controller/jobs/rayjob ./pkg/controller/jobs/rayservice` passed on this upstream-based branch.
- Local kind validation with KubeRay v1.7.1 and Ray 2.56.0: a real Ray Client task caused a gated worker before head readiness; the admitted head-only Workload became ready and retained the same head for about 252 seconds without eviction. Separate cases confirmed the 120-second initial timeout and recovery timeout, including a stale cluster state of `ready`. These runtime checks preceded the rebase; this is a single-cluster CPU-only test, not a full MultiKueue replay.
- `make verify` passed in a clean temporary checkout whose source matched the final PR commit. The original workspace attempt encountered unrelated stale links and lint failures under existing `.claude/worktrees`.

AI assistance: OpenAI Codex assisted with the implementation, tests, and this PR description.

#### Release note

```release-note
RayCluster: Fixed erroneous PodsReadyTimeout evictions of elastic RayClusters whose heads are ready while scale-up workers wait for quota. Readiness and recovery checks now follow the head's readiness.
```
