#### What this PR does / why we need it?

Cherry-pick of #17591 onto `release-0.19`.

A RayCluster head can already be usable while workers are unready or waiting for scale-up quota. Using the legacy cluster state for readiness can leave its admitted Workload unready until a PodsReadyTimeout eviction interrupts the head.

This backport adds `RayClusterHeadPodReady` as an **Alpha feature gate, disabled by default**, introduced in `0.19`. Enabling it uses the `HeadPodReady` condition for RayCluster readiness. With the gate disabled, readiness continues to use `status.state == ready`.

#### Useful notes for your reviewer

- Unlike the Beta, enabled-by-default gate on main, this backport preserves existing behavior unless the operator explicitly enables the gate.
- Enabling the gate requires KubeRay v1.3.0 or later.
- The retained-Workload readiness update limitation described in #17591 remains; this backport does not change Workload selection or status synchronization.
- Readiness integration tests cover both gate states. The backport adapts the tests and generated lifecycle data to this release branch.

Validation: feature-gate and RayCluster package tests, readiness integration tests, and `make ci-lint` passed. `make verify` reported generated client-comment and API-reference differences; the same file diffs were reproduced by running the generators on unmodified `release-0.19` (59d498c7a1). Those unrelated generated differences are excluded from this backport.

AI assistance: OpenAI Codex assisted with the backport, validation, and this PR description.

#### Release note

```release-note
RayCluster: Added the Alpha RayClusterHeadPodReady feature gate, disabled by default. Enable it to use head readiness for PodsReady checks so unready workers do not block readiness of a usable head. Enabling this feature requires KubeRay v1.3.0 or later.
```
