## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

If the conflict resolution is committed in the other window before typing `y`, nothing is staged, so the script aborts. Without `DRY_RUN`, its cleanup then deletes the branch with that commit. Before #17200, [the prompt asked for `git am --continue`](https://github.com/kubernetes-sigs/kueue/blob/e7e6b63892cbed7e10a71c82c2c264a7ffbea3e4/hack/cherry_pick_pull.sh#L197), so committing there was the old workflow.

The script now records HEAD before the cherry-pick. If HEAD is still on the pick branch and descends from the recorded commit, `git reset --soft` moves it back there. The resolution is then staged again, and the script makes its usual commit under the PR author's name.

Fixes #17597

#### Useful notes for your reviewer

I picked #16022 with `DRY_RUN` onto [the base of #17599](https://github.com/kubernetes-sigs/kueue/commit/c9f47ac6c9e82f8840b09a1130a432906e7d963d) and resolved the conflicts as in #17599. Then I ran `git commit --no-edit` before typing `y`. On main the script aborts as in the issue. With this change it commits, and the tree matches #17599. A resolution that is only staged works as before, and a pick that adds nothing still aborts.
