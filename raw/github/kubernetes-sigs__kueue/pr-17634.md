#### What this PR does / why we need it?  

- Replaces `UnholdClusterQueue` with a more generic helper `SetClusterQueueStopPolicy` which updates ClusterQueue's `stopPolicy` to any given value.
- Implements `UnsetClusterQueueStopPolicy`, which sets the ClusterQueue's `stopPolicy` to nil, based on this comment: https://github.com/kubernetes-sigs/kueue/pull/17602#discussion_r4348826184.
- Updates all tests with ClusterQueue's `stopPolicy` get/update/retry blocks to use these helpers.

Related: #17494 and #16876
  
#### Useful notes for your reviewer  

- I added `setClusterQueueStopPolicy` with the actual logic because `SetClusterQueueStopPolicy` and `UnsetClusterQueueStopPolicy` do almost exactly the same. Therefore without a wrapper we would have a duplicated code.
- Two test cases, in `fair_sharing_test.go`, were updating ClusterQueue's `stopPolicy` with `behavioral.ShortInterval` (10ms) instead of `behavioral.Interval` (250ms). This interval only changes the delay between retries after an update conflict, so I updated them to use `SetClusterQueueStopPolicy` which has a normal (250ms) interval.
- Two places in `raycluster_controller_partial_scaleup_test.go` still manually update ClusterQueue's `stopPolicy` because, in the same block, they also update ClusterQueue's `NominalQuota`.

Also:
Both `SetClusterQueueStopPolicy` and `SetLocalQueueStopPolicy` do the same work (if #17602 gets merged) but with different Queue type. Maybe we could extract them into a single helper that treats `LocalQueue` and `ClusterQueue` uniformly?
