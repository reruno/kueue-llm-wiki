#### What this PR does / why we need it?

#17289 allowed `kueue.x-k8s.io/pod-index-offset` alongside `kueue.x-k8s.io/podset-group-name` at creation, but the MPIJob webhook still requires an empty offset on update for grouped Workers with `runLauncherAsWorker`. Such an MPIJob is created and admitted, then the update that starts it is rejected, so it stays suspended while holding quota.

This PR accepts `"1"` on grouped Workers, which matches the Worker offset inferred from the PodSet group, and rejects other values on create and update.

Related: #17289

```release-note
TAS: Fixed a bug where an MPIJob with `runLauncherAsWorker` that set `kueue.x-k8s.io/pod-index-offset` alongside `kueue.x-k8s.io/podset-group-name` was admitted but never started, while holding quota. Kueue now accepts `"1"`, which matches the offset implied by the PodSet group, and rejects other values; remove the annotation from existing MPIJobs that use another value.
```
