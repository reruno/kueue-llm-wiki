#### What this PR does / why we need it?

Adds the missing diagram of the admission cycle that involves a `ProvisioningRequest`
AdmissionCheck. The diagram covers the happy path as well as the retry loop: a `Failed`
or `BookingExpired` request leads to a requeue with the quota of the previous attempt
released, and a new `ProvisioningRequest` with an `-attempt<N>` suffix is created until
retries are exhausted and the Workload is deactivated. It also shows `CapacityRevoked`,
which marks the Workload `Inactive`.

The diagram is committed as an SVG next to the existing ProvisioningRequest state
diagram, so the page does not depend on a runtime diagram renderer.

The ProvisioningRequest states section in the troubleshooting page now links to the
admission cycle. While touching that section, I corrected the Workload field used to
reactivate a rejected Workload (`.spec.active`, not `.status.active`).

Part of #5172

#### Useful notes for your reviewer

The existing `/images/prov-req-states.svg` stays as the single-request state diagram.
This PR adds the cycle-level view (including retries) next to the two-phase admission
description added in #5677 rather than regenerating that SVG.

I used a committed SVG instead of a Mermaid code block because Docsy v0.11.0's Mermaid
partial uses `Resource.Err`, which was removed in Hugo 0.141.0, so the pinned Hugo
0.165.0 fails the site build for pages that contain Mermaid blocks.
