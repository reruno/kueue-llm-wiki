#### What this PR does / why we need it?

Three `make verify` checks list files with `find`, which descends into Git worktrees or clones nested under the repo (for example, worktrees that coding tools create in `.claude/worktrees/` or `.worktrees/`):

- `ci-lint` module discovery (`find . -name go.mod`)
- `fmt-verify` (`find . -name '*.go'`)
- shellcheck (`hack/testing/shellcheck/verify.sh`)

With such worktrees present, `make verify` lints and formats every nested checkout as well:

- `ci-lint` found 215 modules instead of 4, ran golangci-lint on each, and timed out.
- `fmt-verify` passed 207,189 files to gofmt instead of 1,392. That exceeds the argument limit, so gofmt never runs. With GNU Make 4.x (`.SHELLFLAGS = -ec`), the check fails with exit code 126. With GNU Make 3.81, the macOS default, `.SHELLFLAGS` is ignored, so the error goes to stderr, `out` stays empty, and the check **passes silently** without checking anything.

This PR lists files with `git -c core.quotePath=false ls-files --cached --others --exclude-standard` instead. It includes tracked and untracked, non-ignored files, does not descend into nested repositories, and skips tracked files deleted from the working tree.

The checks fail when `git ls-files` fails (for example, outside a Git checkout or on a repository with dubious ownership) or matches no file, so they never pass without checking anything. The Makefile helper exits explicitly instead of relying on `.SHELLFLAGS`, which GNU Make 3.81 ignores. `fmt-verify` now also prints the gofmt diff: `gofmt -d` exits with status 1 when it finds a diff, which made the `-ec` shell exit before printing it.

#### Useful notes for your reviewer

- On a clean checkout, the new lists are identical to the old ones for `go.mod`, `*.go` and `*.sh` files.
- Behavior change: gitignored files are no longer listed. On a clean checkout no gitignored file matched the old lists, and shellcheck already skipped ignored files.
- Git negative pathspecs override positive ones, so the `third_party/forked` exception in the shellcheck script is applied in the loop.
- `make verify` passes on a clean checkout.

Benchmark in a local checkout with 18 nested worktrees (macOS, Apple Silicon):

| Target | Before | After |
|---|---|---|
| `make ci-lint` | 76m54s, failed with `Timeout exceeded` | 1m33s, passed (0 issues) |
| Modules linted by `ci-lint` | 215 | 4 |
| `make fmt-verify` (GNU Make 3.81) | Exits immediately and passes without running gofmt (`Argument list too long`) | 2.6s, checks 1,392 files |

The "after" `ci-lint` run had a warm golangci-lint cache, so it is optimistic, but the order of magnitude holds. On a checkout without nested worktrees, the file lists are identical and the timing is unchanged.
