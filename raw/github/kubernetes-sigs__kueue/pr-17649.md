## Description

#### What type of PR is this?

/kind bug
/area dra

#### What this PR does / why we need it?

CEL availability validation currently counts devices from every listed ResourceSlice. During a pool update, stale devices and devices from an incomplete new generation can therefore satisfy a request that the DRA allocator cannot allocate.

Use the existing pool grouping and completeness checks to consider only complete pools at their highest observed generation, grouped by driver and pool name. Pools with the same name remain separate across drivers. Preserve the original slice and device order so overlapping requests retain the existing greedy matching behavior. When too few eligible devices remain, the existing internal-error path keeps the workload inadmissible and retries with backoff.

Fixes #14573

#### Useful notes for your reviewer

Eleven regression cases extend the existing resource-request tests: stale generations in both listing orders, an incomplete latest generation without fallback, an incomplete pool without older slices, a complete multi-slice generation, unrelated complete pools, identical pool names across drivers, slices without devices, driver-specific counter/capacity listings, and overlapping requests across pools.

Against the unchanged upstream source, six regression cases fail because invalid inventory passes validation; the five positive controls pass.

Validation on macOS arm64 with Go 1.27.0:
