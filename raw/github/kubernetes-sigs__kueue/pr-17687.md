## Description

#### What type of PR is this?

/kind cleanup
/area release

#### What this PR does / why we need it?

The "Promote images and Helm Charts to production" parent step in the release checklist was never checked automatically, so release managers had to check it by hand after `/wait-for-prod-images` succeeded.

This PR adds the `<!-- step:wait-for-prod-images -->` marker to the parent step. `/wait-for-prod-images` is the last sub-step of this group, so when it succeeds, `mark_step_done` now checks both the sub-step and the parent step. 

Fixes #17115

#### Useful notes for your reviewer

- **Test changes:** this is the first marker that is shared by more than one line, so the one-marker-one-line assumption in the test added by #16711 is relaxed:
  - `template_markers()` now deduplicates the markers.
  - `test_checks_only_the_items_of_the_command` now asserts that exactly the lines tagged with the command's marker are checked, instead of exactly one line.
  - The generic test no longer checks that the marker sits on the item that names the command. That is now covered by the new `test_wait_for_prod_images_also_checks_promote_step` for this case, and by review in general.
- **Tested end to end on my fork:** created a `📦 Release v0.20.0` issue from the updated template and commented `/wait-for-prod-images`. Both the parent step and the sub-step were checked, and no other item changed.

(**AI assistance:** parts of the test changes in `log_to_issue_test.py` were drafted with AI assistance (Claude). I reviewed and adjusted them, ran the unit tests locally, and verified the behavior end to end on my fork.)
