#### What this PR does / why we need it?

#17289 fixed rank-based ungating for PodSet groups whose Pod indexes start from 0, but only for JobSet and Ray. Kubeflow v1 Jobs (for example a PyTorchJob with a grouped Master and Worker) and MPIJobs without `runLauncherAsWorker` also number their workers from 0, so the first worker got rank -1: the topology ungater fell back to greedy ungating and logged an error on every reconcile. Kueue now sets `kueue.x-k8s.io/pod-index-offset: "0"` on their grouped Pod templates when it starts the job, as it does for JobSet and Ray. MPIJobs with `runLauncherAsWorker` are unchanged, because their worker indexes start from 1, which matches the PodSet group offset.

TAS: Fixed a bug where Pods of Kubeflow Jobs (v1), such as PyTorchJob, and of MPIJobs without `runLauncherAsWorker` in a `kueue.x-k8s.io/podset-group-name` PodSet group were ungated without rank ordering, and the topology ungater logged an error on every reconcile. Kueue now sets `kueue.x-k8s.io/pod-index-offset: "0"` on their grouped Pod templates when it starts the job. This applies to workloads admitted after the upgrade.
