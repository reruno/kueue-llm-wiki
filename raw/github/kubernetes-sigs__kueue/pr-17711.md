## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it?
A negative Pod request can cancel another charge under the same name before `FloorToZero`. For example, a PodSet asking for `example.com/gpu-quota: -3` beside a transformation that generates 8 was charged 5 instead of 8.

This treats negative requests as zero in `PodRequests`, before quota, TAS, and LimitRange accounting use them. Transformations that intentionally produce negative outputs are unchanged.

Fixes #14015

#### Useful notes for your reviewer
The webhook rejects negative requests while `WorkloadValidateResourcesAreNonNegative` is enabled. The remaining case is a cluster with the gate off, or a Workload written before the gate.

Tests cover the transformation cases, TAS net usage, and pod-level LimitRange validation.

Testing:
- `go test ./pkg/resources ./pkg/workload ./pkg/cache/scheduler ./pkg/scheduler/flavorassigner ./pkg/util/limitrange -count=1`
- `go build ./...`

- `golangci-lint` on the changed packages
