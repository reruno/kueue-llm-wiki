#### What this PR does / why we need it:
Expands docs and adds an integration test demonstrating how to configure shared license quotas across multiple compute flavors using dedicated ResourceGroups in a ClusterQueue.

Fixes #17684

This covers:
- An integration test showing a ClusterQueue with two ResourceGroups (`cpu` on on-demand/spot, and `example.com/license` on a headless flavor). It verifies that workloads on different compute flavors share the license pool, that jobs without license requests can still be admitted when licenses are full, and that pending jobs get admitted once a license is released.
- A new use-case section in the `share_quotas_across_flavors` doc with full YAML examples (ResourceFlavors, ClusterQueue, and sample Job).
- Clarification on pod schedulability when using extended resources in Kubernetes.

This change adds documentation for sharing a fixed software-license quota across compute flavors. The guide defines compute and headless license ResourceFlavors, a ClusterQueue with separate compute and license ResourceGroups, and a LocalQueue. The example Job requests an extended license resource in its container. The guide describes:

- Assigning compute and license flavors independently.
- Keeping the license reservation until the Job completes.
- Admitting license-free workloads on available compute quota when licenses are exhausted.
- Node schedulability requirements for the resulting Pods.
- Two ways to advertise license capacity.

The Cluster Queue concepts page adds a note. ResourceFlavors used only for software licenses or other non-node resources can omit `nodeLabels` and `tolerations`. The note links to the end-to-end example.

The change adds an integration test. It checks that:

- Workloads on on-demand and spot compute each reserve one license.
- A third license-requiring workload stays pending while both licenses are reserved.
- A compute-only workload is admitted while license quota is exhausted.
- After one license is released, the pending workload is admitted.

The guide does not state that license requirements can be declared only on the Workload. The Job's container still requests the license resource.
