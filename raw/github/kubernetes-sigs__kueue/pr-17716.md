#### What this PR does / why we need it?

Adds Helm upgrade tests for the manager configuration in `charts/kueue` and its use as a dependency of the experimental Kueue Populator chart. The tests run Helm's install and upgrade actions with in-memory release storage and a fake Kubernetes client, so no cluster is needed. They check the saved release values and the rendered manager configuration, which `helm unittest` cannot do because it renders a single release.

The 34 table cases cover:
- default upgrades, `--reuse-values`, `--reset-values` and `--reset-then-reuse-values`
- YAML as the complete configuration, including `""`
- unset settings following the target chart's defaults
- migration from YAML to `structuredOverrides`, optional `mode`, a saved mode, and switching back
- `null` removal as documented in the chart README
- Populator with the Kueue subchart enabled and disabled, and wrapper chart defaults versus customer YAML

The tests run as part of `make helm-unit-test` and `verify-helm-unit-test`. `test/helm/README.md` explains how to run them.

Fixes #17465

#### Useful notes for your reviewer

The upgrade-test command uses `-count=1` because chart files live outside the test module and chart-only edits do not invalidate Go’s test-result cache.

The tests run in `make helm-unit-test`. `verify-helm-unit-test` also runs them through the shared Helm unit-test recipe. `test/helm/` is a separate Go module, and `test/helm/README.md` documents how to run the tests. The test command uses `-count=1` because chart-only edits do not invalidate Go's test cache. The Dependabot configuration now also monitors `/test/helm`.

The PR changes two chart templates. `kueue.managerConfig` in `charts/kueue/templates/_helpers.tpl` and the Populator `manager.yaml` no longer call `hasKey` before checking `controllerManagerConfigYaml` and `structuredOverrides` for `nil`. Explicit `null` and an absent key now take the same path. The author reports that using `controllerManagerConfigYaml: null` to migrate to `structuredOverrides` with `--reuse-values` still breaks later upgrades. That issue is tracked in `#17717` and is not fixed in this PR.
