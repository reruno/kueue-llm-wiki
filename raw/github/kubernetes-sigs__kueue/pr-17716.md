#### What this PR does / why we need it?

Adds Helm upgrade tests for the manager configuration in `charts/kueue` and its use as a dependency of the experimental Kueue Populator chart. The tests run Helm's install and upgrade actions with in-memory release storage and a fake Kubernetes client, so no cluster is needed. They check the saved release values and the rendered manager configuration, which `helm unittest` cannot do because it renders a single release.

The 34 table cases cover:
- default upgrades, `--reuse-values`, `--reset-values` and `--reset-then-reuse-values`
- YAML as the complete configuration, including `""`
- unset settings following the target chart's defaults
- migration from YAML to `structuredOverrides`, optional `mode`, a saved mode, and switching back
- `null` removal as documented in the chart README
- Populator with the Kueue subchart enabled and disabled, and wrapper chart defaults versus customer YAML

The tests run as part of `make helm-unit-test` and `verify-helm-unit-test`. `test/helm/README.md` explains how to run them.

Fixes #17465

#### Useful notes for your reviewer

This PR adds Helm upgrade tests for manager configuration in `charts/kueue` and its use as a dependency of the Kueue Populator chart. The tests use in-memory Helm release storage and a fake Kubernetes client. They do not need a cluster.

The tests check saved values and rendered manager configuration. They cover default upgrades, `--reuse-values`, `--reset-values`, and `--reset-then-reuse-values`. They also cover YAML precedence, migration to `managerConfig.structuredOverrides`, target-chart defaults, and `null` removal.

`make helm-unit-test` and `verify-helm-unit-test` run the tests. `test/helm/README.md` documents them. The test command uses `-count=1` because chart-only edits do not invalidate the Go test cache.

`_helpers.tpl` and the Populator `manager.yaml` no longer require the `controllerManagerConfigYaml` and `structuredOverrides` keys to exist before the non-null check. An explicit `null` and an absent key now take the same path.

Using `controllerManagerConfigYaml: null` to migrate with `--reuse-values` still breaks later upgrades. This is tracked in `#17717` and is not fixed here.
