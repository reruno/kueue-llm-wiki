#### What this PR does / why we need it?

The test runs with `BlockAdmission: true`. It creates `prod-wl` and `dev-wl` back to back and expects `prod-wl` to be admitted first. Creation timestamps have 1-second resolution. If both workloads are created in the same second and land in the same scheduling cycle, the FIFO tie-break in `makeClassicalIterator` returns 0 and the order is arbitrary. When `dev-wl` is processed first, it is admitted and `prod-wl` is unset with `QuotaReserved=False, reason=Waiting` ("waiting for all admitted workloads to be in PodsReady condition"). The test then times out at the first `ExpectWorkloadsToHaveQuotaReservation` check.

Fixes #17732
