## Description

#### What type of PR is this?
/kind bug
/area multikueue

#### What this PR does / why we need it?
On a MultiKueue manager cluster, a scheduling-gated Pod group mirrored `Phase: Running` from the worker cluster. When the workload was evicted on the worker, the manager workload stayed deadlocked holding quota because `PodActivity` (invoked by `(*Pod).IsActive()`) counted the gated Running pods as active local processes.

Furthermore, `ResetLocalStatus` skipped Pod groups entirely, leaving member pods stuck with stale status (`Phase: Running` or `Phase: Failed` with exitCode 137), causing the requeued workload to wedge in `WaitingForReplacementPods=True`.

This PR fixes both issues:
1. Teaches `PodActivity` that scheduling-gated pods are inactive locally, allowing the generic reconciler to clear admission and release quota (`QuotaReserved=False, Requeued=True`).
2. Updates `ResetLocalStatus` to iterate over all member pods in the Pod group via `listLocalPods` and reset their status back to `Pending` with the `SchedulingGated` condition. It also ensures mirrored `PodFailed` phases from remote termination/SIGKILL are reset cleanly.

Fixes #17485

#### Useful notes for your reviewer
- Validated via unit tests in `pkg/controller/jobs/pod` and an integration test in `test/integration/multikueue/pod_test.go`.
- Tested end-to-end on live multi-cluster Kind setups verifying the full lifecycle: dispatch -> worker eviction -> quota release -> pod group reset to `SchedulingGated` -> re-dispatch and successful run.
- Prepared with the assistance of an AI tool (Google Antigravity), in accordance with the Kubernetes AI tool usage guidelines.
