## Description

#### What type of PR is this?

#### What this PR does / why we need it?

The Uninstall sections on the installation page give one command each. If Kueue objects
still exist, that command removes the controller together with the CRDs. Workloads,
ClusterQueues, ResourceFlavors, AdmissionChecks and Topologies carry the
`kueue.x-k8s.io/resource-in-use` finalizer, and managed Pods carry `kueue.x-k8s.io/managed`;
only the controller clears them, so the objects and their CRDs stay in `Terminating`.

This adds a "Before you uninstall" section to the installation page: why it happens, and
the order to delete Kueue objects while the controller still runs (as the quick start's
Clean up does): jobs, then any Workloads left (such as a prebuilt Workload no job
adopted), then queues, flavors and checks, then Topologies. The other two Uninstall sections link to it. Recovery from an uninstall
that is already stuck goes on the Troubleshooting delete ClusterQueue page, as "What if
Kueue was uninstalled first?", linked from the new section.

#### Useful notes for your reviewer

The finalizer list comes from the controllers that add it: clusterqueue, resourceflavor,
admissioncheck and tas/topology controllers, and jobframework for Workloads. LocalQueues
and Cohorts have no finalizer; they are in the order because of what references them.

Removing finalizers by hand is limited to a Kueue that is already uninstalled, where
nothing else can clear them, with a warning not to do it while the controller runs. It
removes only Kueue's own finalizer entry and keeps other controllers' finalizers. The
zh-CN copy of the troubleshooting page is left for translators.
