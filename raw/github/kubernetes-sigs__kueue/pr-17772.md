#### Useful notes for your reviewer

Adapted for release-0.19:

- `reconcilePodsReadyCondition` keeps the release-0.19 signature of `generatePodsReadyCondition`.
- release-0.19's `TestReconcileGenericJobWithWaitForPodsReady` only checks the reconcile error, so its table gets optional `wantPodCondition` and `extraWorkloads` fields for the new cases. The existing cases are unchanged.
- The integration test uses `ScaleFirstWorkerGroup(0)`, since release-0.19 doesn't have the `FirstWorkerGroupReplicas` wrapper.
- release-0.19's RayCluster integration suite passed an empty configuration to the core controllers, so the PodsReady timeout never applied there. The suite now passes the test configuration, as main does. Before this PR, no spec in the suite passed a configuration, so the other specs are unaffected (the full RayCluster suite passes).

Verified on release-0.19: the new integration specs pass, and without the fix the spec where the head becomes ready fails. `make verify` passes.

ElasticJobsViaWorkloadSlices: Fixed a bug where an admitted elastic Workload could be evicted with `PodsReadyTimeout` while its scale-up Workload slice waited for quota, even after its Pods became ready. Kueue now updates `PodsReady` on the admitted Workload slice.
