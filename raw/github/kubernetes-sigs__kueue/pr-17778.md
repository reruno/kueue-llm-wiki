## Description

#### What type of PR is this?

/kind bug
/area dashboard

#### What this PR does / why we need it?

Kueue treats a Cohort that a ClusterQueue or another Cohort references, but that has no Cohort object, as implicit. KueueViz listed only Cohort objects, so implicit Cohorts were missing from the Cohorts page and their detail page returned an error.

- `fetchCohorts` now also lists implicit Cohorts, sorted, after the Cohort objects. Names that come from ClusterQueues are only listed when the caller may list ClusterQueues.
- `fetchCohortDetails` serves an implicit Cohort when another Cohort names it as parent or, for callers who may list ClusterQueues, a ClusterQueue names it. Other unknown names still return an error.

Fixes #17775

#### Useful notes for your reviewer

- Added cases to `TestFetchCohorts` and `TestFetchCohortDetails`, including denied ClusterQueue access. Four of them fail without the change.
- Ran `go test ./...` and `golangci-lint` with the repo config in `cmd/kueueviz/backend`.

#### Release note

```release-note
KueueViz: Fixed implicit Cohorts, referenced by a ClusterQueue or another Cohort without a Cohort object, missing from the Cohorts page and failing to open.
```

That helper returns, sorted via sets.List, names that appear as keys in cohortQueues (from ClusterQueue spec.cohortName) or as Cohort spec.parentName values, when no Cohort object exists for them.
