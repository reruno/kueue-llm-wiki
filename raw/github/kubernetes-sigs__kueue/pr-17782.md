## Description

#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it?

The Kueue logging policy prefers full words in user-facing log keys. The Workload update event still abbreviated the previous state with `prevLocalQueue`, `prevStatus` and `prevClusterQueue`, so this renames the three keys to `previousLocalQueue`, `previousStatus` and `previousClusterQueue`.

Only the `WithValues` keys change: the `prevQueue` and `prevStatus` local variables keep their names and no controller behavior changes.

Fixes #17761

#### Useful notes for your reviewer

- On `main`, the only remaining `prev`-prefixed log keys are these three in `pkg/controller/core/workload_controller.go`; `pkg/controller/jobframework/reconciler.go` does not contain a `prevLocalQueue` key, so it is left alone. That also avoids conflicting with the open JobFramework logging PR.
- `grep -rn '"prev' --include='*.go' pkg/` now returns no log keys, and no test or documentation asserts on the old key names.
- Ran `go test -count=1 ./pkg/controller/core/...` and `go build ./pkg/controller/core/...`.
- AI usage: this change was prepared with AI assistance (opencode) and reviewed by me before submission.
