### Comment by [@mbobrovskyi](https://github.com/mbobrovskyi) — 2026-10-27T18:33:09Z

Thanks for working on this, @Dasmat13! Looking at the result, I think we can simplify it further. The new version still has the shape of a table: 12 It blocks calling one runner with seven positional arguments.

The aliases are plain cobra aliases on the same RunE, which passes the args to kubectl unchanged. A single get per alias already proves that both kueuectl and kubectl resolve the name, so repeating patch and delete for each alias adds nothing. Could we restructure it like this?

  - One It per resource (6 instead of 12). In each one, run get with every name from passThroughTypes, including kueueworkload and kueueworkloads, which are not covered today. Then run patch and delete once.
  - Replace testPassThrough with a small runKueuectl(args ...string) string helper.
  - Build the objects inline with the utiltestingapi wrappers and drop the makePassThrough* factories. With concrete types, the cleanup can use behavioral.ExpectObjectToBeDeleted.

```go
func runKueuectl(args ...string) string {                                                                                                               
    ginkgo.GinkgoHelper()                                                                                                                               
    cmd := exec.Command(kueuectlPath, args...)                                                                                                          
    setupEnv(cmd, kassetsPath, kubeconfigPath)                                                                                                          
    out, err := cmd.CombinedOutput()                                                                                                                    
    gomega.Expect(err).NotTo(gomega.HaveOccurred(), "%q", string(out))                                                                                  
    return string(out)                                                                                                                                  
} 

ginkgo.It("Should get, patch and delete a ClusterQueue", func() {                                                                                       
    cq := utiltestingapi.MakeClusterQueue("pass-through-cq").Obj()                                                                                      
    behavioral.MustCreate(ctx, k8sClient, cq)                                                                                                           
    ginkgo.DeferCleanup(func() { behavioral.ExpectObjectToBeDeleted(ctx, k8sClient, cq, true) })                                                        

    for _, name := range []string{"clusterqueue", "cq"} {                                                                                               
        gomega.Expect(runKueuectl("get", name, cq.Name, "-o=jsonpath={.spec.stopPolicy}")).To(gomega.Equal("None"))                                 
    }                                                                                                                                                   

    runKueuectl("patch", "clusterqueue", cq.Name, "--type=merge", "-p", `{"spec":{"stopPolicy":"Hold"}}`)                                               
    gomega.Expect(runKueuectl("get", "clusterqueue", cq.Name, "-o=jsonpath={.spec.stopPolicy}")).To(gomega.Equal("Hold"))                               
                           
    runKueuectl("delete", "clusterqueue", cq.Name)                                                                                                      
    behavioral.ExpectObjectToBeDeleted(ctx, k8sClient, cq, false)                                                                                       
})
```

Please keep framework.SlowSpec and `--yes` for Workload, since delete workload is kueuectl's own command, not a pass-through.
