## Description

Bumps [github.com/cert-manager/cert-manager](https://github.com/cert-manager/cert-manager) from 1.21.2 to 1.21.3.
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/cert-manager/cert-manager/releases">github.com/cert-manager/cert-manager's releases</a>.</em></p>
<blockquote>
<h2>v1.21.3</h2>
<p>cert-manager is the easiest way to automatically manage certificates in Kubernetes and OpenShift clusters.</p>
<p>v1.21.3 removes trust in the compromised eMudhra CA (see <a href="https://cert-manager.io/docs/trust/trust-manager/#emudhra-compromise">eMudhra Compromise</a>). The updated base images no longer include the &quot;emSign ECC Root CA - G3&quot; root certificate. Go 1.26.10 also makes <code>crypto/x509</code> reject certificate chains that pass through the compromised intermediates (<a href="https://pkg.go.dev/vuln/GO-2026-6809">CVE-2026-111943</a>).</p>
<p>It also fixes an ACME ARI renewal loop, stops the controller copying a private key from a Secret that the Certificate does not own, and quotes the proxy values in the Helm chart. It updates Go and several dependencies to fix reported security vulnerabilities.</p>
<p>All users should upgrade.</p>
<h2>Changes by Kind</h2>
<h3>Bug or Regression</h3>
<ul>
<li>Added <code>status.acme.ari.certID</code> to track issuance of new certs and re-fetch ARI from CA. This fixes a renewal loop where a stale ARI window from the previous certificate triggered repeated re-issuance until the CA rate limit was hit. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9292">#9292</a>, <a href="https://github.com/hjoshi123"><code>@​hjoshi123</code></a>)</li>
<li>Helm chart: quote the <code>http_proxy</code>, <code>https_proxy</code> and <code>no_proxy</code> values when rendering the controller Deployment env vars, so values like <code>*.example.com</code> no longer break the manifest. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9407">#9407</a>, <a href="https://github.com/pujitha24"><code>@​pujitha24</code></a>)</li>
<li>The <code>requestmanager</code> and <code>issuing</code> controllers now only consume the Secret named by <code>status.nextPrivateKeySecretName</code> when it carries the <code>cert-manager.io/next-private-key</code> label and is owned by the Certificate, matching the invariant the <code>keymanager</code> controller already enforces. Previously a principal able to write the <code>certificates/status</code> subresource, but not to read Secrets, could name any Secret in the namespace and have its private key copied into <code>spec.secretName</code>. The <code>keymanager</code> controller no longer creates the next private key Secret under the name in <code>status.nextPrivateKeySecretName</code>. It always uses a generated name, records a <code>NotOwned</code> Warning event when the field names a Secret it does not own, and repoints the field at the Secret it owns rather than deleting that Secret when the two disagree. The Secret named by <code>spec.secretName</code> is never treated as a next private key Secret, even if <code>spec.secretTemplate</code> labels it as one. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9368">#9368</a>, <a href="https://github.com/wallrj"><code>@​wallrj</code></a>)</li>
</ul>
<h3>Other (Cleanup or Flake)</h3>
<ul>
<li>Upgrade Go to 1.26.9, fixing CVEs in the crypto/tls, net/http, net/textproto and html/template packages. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9444">#9444</a>, <a href="https://github.com/wallrj-cyberark"><code>@​wallrj-cyberark</code></a>)</li>
<li>Upgrade Go to 1.26.10, fixing a CVE in the crypto/x509 package. (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9501">#9501</a>, <a href="https://github.com/wallrj-cyberark"><code>@​wallrj-cyberark</code></a>)</li>
<li>Bump <code>golang.org/x/net</code> to v0.60.0 to fix reported security vulnerabilities (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9451">#9451</a>)</li>
<li>Bump <code>go.opentelemetry.io/otel/exporters/otlp/otlptrace</code> and <code>otlptracegrpc</code> to v1.45.0 to fix a reported security vulnerability (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9374">#9374</a>, <a href="https://redirect.github.com/cert-manager/cert-manager/issues/9375">#9375</a>)</li>
<li>Update distroless base images, removing the compromised &quot;emSign ECC Root CA - G3&quot; root certificate (<a href="https://redirect.github.com/cert-manager/cert-manager/issues/9351">#9351</a>, <a href="https://redirect.github.com/cert-manager/cert-manager/issues/9414">#9414</a>, <a href="https://redirect.github.com/cert-manager/cert-manager/issues/9493">#9493</a>, <a href="https://redirect.github.com/cert-manager/cert-manager/issues/9495">#9495</a>)</li>
</ul>
</blockquote>
