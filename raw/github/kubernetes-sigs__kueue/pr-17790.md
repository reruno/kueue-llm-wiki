</ul>
<h2>Changes by Kind</h2>
<h3>Feature</h3>
<ul>
<li>MultiKueue: Added support for RayService in-tree autoscaling on worker clusters using elastic workload slices. Requires the MultiKueueRayInTreeAutoscaling feature gate. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17466">#17466</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
<li>Scheduling: Improved classical preemption performance by reusing candidate ordering and generating candidates on demand. Enable it with the alpha ClassicalPreemptionCandidateOrderCache feature gate (disabled by default). (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17296">#17296</a>, <a href="https://github.com/zhengchenyu"><code>@​zhengchenyu</code></a>)</li>
</ul>
<h3>Bug or Regression</h3>
<ul>
<li>
<p>ConcurrentAdmission: Fixed a bug where a parent <code>Workload</code> could remain admitted on a flavor removed from its <code>ClusterQueue</code> when a surviving variant was already admitted. The parent is now marked for eviction so it can be re-admitted on a remaining flavor. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17337">#17337</a>, <a href="https://github.com/yuluo-yx"><code>@​yuluo-yx</code></a>)</p>
</li>
<li>
<p>DRA: Fixed a bug where a workload requesting a DeviceClass by its implicit extended resource name <code>deviceclass.resource.kubernetes.io/&lt;class&gt;</code> was treated as an ordinary extended resource, so its quota was not charged to the <code>deviceClassMappings</code> logical resource and the workload could stay pending. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17434">#17434</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</p>
</li>
<li>
<p>Deployment, StatefulSet &amp; LeaderWorkerSet: Fixed a bug where, once a WorkloadPriorityClass named <code>default</code> existed, updates to an object with ready replicas and no <code>kueue.x-k8s.io/priority-class</code> label were rejected, even when Kueue did not manage the object. Kueue no longer adds the default WorkloadPriorityClass to such objects on update. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17309">#17309</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</p>
</li>
<li>
<p>Elastic workloads: Fixed Pods remaining Pending after scale-up when ElasticJobsViaWorkloadSlicesForProvisioningRequests is enabled. ProvisioningRequests belonging to a replaced workload slice are now retained while their capacity bookings remain valid. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17359">#17359</a>, <a href="https://github.com/neilb-dotcom"><code>@​neilb-dotcom</code></a>)</p>
</li>
<li>
<p>ElasticJobsViaWorkloadSlices: Fixed a bug where an elastic Workload replacement slice that grows one PodSet and shrinks another could remain pending when the growing PodSet appeared before the shrinking PodSet in <code>spec.podSets</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17561">#17561</a>, <a href="https://github.com/abhayjoshi201"><code>@​abhayjoshi201</code></a>)</p>
</li>
<li>
<p>Fixed a bug where setting a ClusterQueue's <code>stopPolicy</code> to <code>HoldAndDrain</code> did not evict admitted Workloads whose LocalQueue was held or deleted. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17480">#17480</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</p>
</li>
<li>
<p>Jobs: Fixed a bug where a Job could adopt an unrelated, already finished prebuilt Workload and run without quota management. Kueue now stops the Job instead. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/16994">#16994</a>, <a href="https://github.com/bolubo"><code>@​bolubo</code></a>)</p>
</li>
<li>
<p>KueueViz: Fix the workload details page failing when the Workload's LocalQueue was deleted. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17275">#17275</a>, <a href="https://github.com/onkar717"><code>@​onkar717</code></a>)</p>
</li>
<li>
<p>KueueViz: Fixed a bug where a backend component failure could prevent graceful HTTP server shutdown. KueueViz now shuts down the server and stops the components before reporting the failure. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17471">#17471</a>, <a href="https://github.com/fat-catTW"><code>@​fat-catTW</code></a>)</p>
</li>
<li>
<p>KueueViz: Fixed a bug where an unknown KUEUEVIZ_AUTH_MODE value could start the backend without authentication and authorization middleware. KueueViz now exits with an error unless the value is Disabled or TokenReview. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17311">#17311</a>, <a href="https://github.com/fat-catTW"><code>@​fat-catTW</code></a>)</p>
</li>
<li>
<p>KueueViz: Fixed a bug where distinct user group or extra attribute sets could incorrectly share a cached authorization result. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17408">#17408</a>, <a href="https://github.com/fat-catTW"><code>@​fat-catTW</code></a>)</p>
</li>
<li>
<p>KueueViz: Fixed a bug where the cohorts list exposed ClusterQueue names to users without permission to list ClusterQueues. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17300">#17300</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</p>
</li>
<li>
<p>KueueViz: Fixed links to missing ClusterQueues and Cohorts, such as &quot;N/A&quot; on the dashboard linking to <code>/cluster-queue/undefined</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17405">#17405</a>, <a href="https://github.com/onkar717"><code>@​onkar717</code></a>)</p>
</li>
<li>
<p>KueueViz: Fixed the ResourceFlavor detail page always showing &quot;None&quot; for node labels and node taints. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17329">#17329</a>, <a href="https://github.com/onkar717"><code>@​onkar717</code></a>)</p>
</li>
<li>
<p>KueueViz: Fixed the dashboard tooltip of a preempted workload not linking to the preemptor workload. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17428">#17428</a>, <a href="https://github.com/onkar717"><code>@​onkar717</code></a>)</p>
</li>
<li>
<p>LeaderWorkerSet: Fixed a bug where changing the <code>kueue.x-k8s.io/queue-name</code> label while no replica was Ready, but a Workload already held a quota reservation, made the LeaderWorkerSet reconciler fail on every retry and left the Workload in the old queue. Kueue now rejects the change in that case. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17307">#17307</a>, <a href="https://github.com/Andrushika"><code>@​Andrushika</code></a>)</p>
</li>
<li>
<p>MultiKueue: Fixed a bug where <code>serveConfigV2</code> updates to a RayService with in-tree autoscaling were not propagated to the worker cluster when <code>MultiKueueRayInTreeAutoscaling</code> was enabled. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17513">#17513</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</p>
</li>
<li>
<p>MultiKueue: Fixed a regression where <code>MultiKueueOrchestratedPreemption</code>, enabled by default since v0.20, added two status writes for every Workload replicated to a worker cluster, reducing MultiKueue admission throughput. <code>status.preemptionGates</code> no longer lists a <code>Closed</code> state for gates that have not been opened; such gates remain closed. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17468">#17468</a>, <a href="https://github.com/YQ-Wang"><code>@​YQ-Wang</code></a>)</p>
</li>
<li>
<p>MultiKueue: Fixed batch/Job re-dispatch eviction loop caused by status.failed counter rejection on Kubernetes 1.35+. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17569">#17569</a>, <a href="https://github.com/mishradwaterlaw"><code>@​mishradwaterlaw</code></a>)</p>
</li>
<li>
<p>MultiKueue: Fixed manager startup failure when the MultiKueueClusterProfile feature gate is enabled but the ClusterProfile CRD is not installed. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17228">#17228</a>, <a href="https://github.com/yindia"><code>@​yindia</code></a>)</p>
</li>
<li>
<p>Observability: Fixed <code>kueue_local_queue_admitted_active_workloads</code> doubling after a ClusterQueue custom label change, and going negative after a LocalQueue label change. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17435">#17435</a>, <a href="https://github.com/Andrushika"><code>@​Andrushika</code></a>)</p>
</li>
<li>
<p>Observability: Improved Workload controller logging:</p>
<ul>
<li>Log Workload inadmissibility and recovery from DRA validation errors at verbosity 3, after the corresponding status update succeeds. DRA validation failures no longer produce error logs on every reconcile.</li>
<li>Move routine per-Workload messages from verbosity 2 to 3 or higher to reduce log noise.</li>
<li>Rename the <code>queue</code> and <code>prevQueue</code> log keys to <code>localQueue</code> and <code>prevLocalQueue</code>, and include the namespace in LocalQueue references.</li>
<li>Identify the failed operation in reconciliation errors. If updating the Workload status after a DRA failure also fails, report both errors.</li>
</ul>
<p>DRA: Fixed a case where a Workload kept <code>Requeued=True</code> after DRA validation failed again. The controller now sets <code>Requeued=False</code> even if the same validation error is already recorded in the Workload status. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17332">#17332</a>, <a href="https://github.com/mimowo"><code>@​mimowo</code></a>)</p>
</li>
<li>
<p>Pod integration: Fixed a bug where a pod group's new Workload could be built from a pod still terminating on a node, pinning it there so it could not be admitted. The fix is on by default through the Beta <code>FinalizeTerminatingPodGroups</code> feature gate. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17501">#17501</a>, <a href="https://github.com/anguszzzz"><code>@​anguszzzz</code></a>)</p>
</li>
<li>
<p>RayCluster: Fixed a bug where worker PodSet counts could fall below KubeRay’s minimum replica count, leaving workers scheduling-gated when capacity became available. Kueue now respects worker replica bounds when calculating PodSet counts. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17366">#17366</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</p>
</li>
<li>
<p>Scheduling: Fixed a bug that could delay workload admission after leader failover when the new leader lacked Cohort quota. Kueue now keeps Cohorts in the scheduler cache on every replica. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17404">#17404</a>, <a href="https://github.com/dundysm"><code>@​dundysm</code></a>)</p>
</li>
</ul>
