#### What this PR does / why we need it?

Manual cherry-pick of #17460 into `release-0.19`, requested in
https://github.com/kubernetes-sigs/kueue/pull/17460#issuecomment-6439776443
after the automated cherry-pick encountered conflicts:
https://github.com/kubernetes-sigs/kueue/pull/17460#issuecomment-6439447556.

With `ElasticJobsViaWorkloadSlicesWithTAS` enabled, topology checks during
preemption can count the predecessor slice's reservation twice: once in the
snapshot and again through `PreviousAssignment`. This can reject a feasible
elastic replacement. For example, a two-CPU predecessor on a four-CPU node
should be able to grow to four CPUs after preempting a lower-priority workload
occupying the other two CPUs.

This backport centralizes the temporary, reversible TAS-only predecessor
deduction in `Assignment.FindTopologyAssignments`. It checks that the exact
Workload UID is still accounted for and has not already been released. The
helper does not deduct quota usage.

Related: #17460, #17792, #16354, #16339, #16337. This does not close the
residual-bound-Pod issue or add its physical-Pod tracking/policy changes.

#### Useful notes for your reviewer

`release-0.19` does not have the native assignment planner. Instead of bringing
that refactor into a patch release, this backport applies the same helper to
the existing `assignFlavors`, `workloadFits` and `updateAssignmentForTAS`
paths, using the release's `WithWorkload` interface.

The native-planner regression is adapted to the legacy preemption and
recomputation path. Coverage also includes predecessor UID/presence/released
state and feature-gate guards, restored TAS capacity and unchanged quota,
three scheduler pressure variants, and the four-CPU integration regression.

Validation done on this backport:

- `make generate-code generate-mocks`: clean; an unrelated comment-only drift
  in generated applyconfiguration files was excluded after inspection.
- Unit tests for the nine affected packages (`pkg/cache/scheduler`,
  `pkg/scheduler/flavorassigner`, `pkg/scheduler/preemption`, `pkg/scheduler`,
  `pkg/controller/core`, `pkg/controller/tas`, `pkg/util/tas`, `pkg/workload`,
  `pkg/workloadslicing`): passed.
- Focused race tests (snapshot, helper and legacy regression paths), three
  repeats: passed.
- Ablation checks: reverting only the preemption topology caller, or only
  `updateAssignmentForTAS`, makes both legacy regression cases fail as
  expected; both mutations were restored and re-verified.
- TAS integration suite (`test/integration/singlecluster/tas`) with `--race`:
  137 of 137 specs passed.

The `release-0.20` backport is already merged as #17792; this PR targets only
`release-0.19`.
