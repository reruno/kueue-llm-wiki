## Description

#### What type of PR is this?
/kind cleanup

#### What this PR does / why we need it:

Breaks the workload controller's `Reconcile` down into helpers, following the `handleDRA` extraction from #13549. `Reconcile` goes from ~440 to ~170 lines and now reads as a list of steps.

Each commit moves one block. Every commit passes `pkg/controller/core` unit tests and `golangci-lint`.

| Commit | Helper | What moved |
|---|---|---|
| 1 | `reconcileFinished` | Retention handling for finished workloads (requeue until expiry, then delete) |
| 2 | `reconcileRequeueAtUpdate` | Persisting the admission-check retry time |
| 3 | `rejectDRAWhenDisabled` | Rejecting DRA workloads while `KueueDRAIntegration` is off (the gate check stays at the call site, next to `handleDRA`) |
| 4 | `reconcileActive` | The active-workload branch: pending deactivation, backoff, Requeued=True after reactivation or finished backoff |
| 5 | `reconcileBackoff` | The backoff-elapsed requeue, pulled out of `reconcileActive` |
| 6 | `reconcileInactive` | The inactive-workload branch: evict, or consume DeactivationTarget and clear RequeueState |
| 7 | `reportAdmittedWorkload` | The Admitted event and admission metrics, next to `reportFinishedWorkload` |
| 8 | `reconcileQuotaReserved` | The checks for workloads holding a quota reservation and the recheck interval |

Helpers that can stop reconciliation return `(done bool, result ctrl.Result, err error)`, like `handleDRA`, so each call site is `if done { return result, err }`.

There is no behavior change.

#### Which issue(s) this PR fixes:
 #13424

#### Special notes for your reviewer:
Each commit is a move plus the `&wl` → `wl` change that comes with passing a pointer.

The LocalQueue and ClusterQueue lookups stay in `Reconcile`, because they produce `lq`, `lqExists`, `lqActive`, `cq` and `cqName` for the later steps. I can split those in a follow-up if you'd like.
