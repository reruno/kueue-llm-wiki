## Description

#### What type of PR is this?

/kind cleanup
/area testing

#### What this PR does / why we need it?

Exclude `.claude/worktrees/**` from skillsaw discovery. Claude Code stores isolated checkouts there, and scanning their instruction files can make local `make verify` fail on broken links or imports belonging to other branches.

Keep linting the main checkout's skills and instruction files with strict mode enabled.

Related: https://github.com/kubernetes-sigs/kueue/pull/17645, which excluded nested worktrees from Go module discovery, formatting, and shellcheck; skillsaw uses its own discovery.

Validation:
- `make verify-skills-lint` passed in a clean worktree.
- Ran the same skillsaw image against the original checkout containing existing `.claude/worktrees/`, with the updated configuration mounted read-only: passed. Before the change, that checkout reported 21 warnings and failed strict mode.
- `PATH="/opt/homebrew/opt/coreutils/libexec/gnubin:$PATH" make verify` passed (88.94 seconds). The first full run failed because macOS `/sbin/sha256sum` does not support the Helm unittest installer's checksum arguments; selecting the installed GNU coreutils resolved it without repository changes.
