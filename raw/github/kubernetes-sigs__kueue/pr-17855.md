#### What type of PR is this?

#### What this PR does / why we need it?

The pod integration copies the whole Pod spec, including `ephemeralContainers`, into the Workload PodSet. When the ClusterQueue has a ProvisioningRequest admission check, the provisioning controller builds a PodTemplate from that PodSet. The API server rejects it (`template.spec.ephemeralContainers: Forbidden: ephemeral containers not allowed in pod template`), no ProvisioningRequest is created, and the workload stays pending.

Two paths lead there:
- A pod group member gets an ephemeral container (for example with `kubectl debug`) before the group is complete and its Workload is created.
- A gated single Pod whose Workload has no quota reservation gets an ephemeral container, and a later change, such as a new container image, rebuilds the Workload from the Pod spec.

The provisioning controller now clears ephemeral containers on the PodTemplate it builds for the ProvisioningRequest. Ephemeral containers can't set resources, so the provisioned capacity does not change. The change is made on a deep copy, so the Workload is unchanged, and it is not feature gated because it only affects templates the API server would reject. Workloads that are already stuck get their ProvisioningRequest on the next reconcile.

Follow-up to #17601 / #17786.

#### Which issue(s) this PR fixes:
Fixes #18241

#### Useful notes for your reviewer

Why not stop copying ephemeral containers in the pod integration: that would not heal Workloads that already have them in their PodSets (`ComparePodTemplate` ignores ephemeral containers, so they are never rebuilt). It would also change the PodSets that other consumers see. The PodTemplate is where the restriction applies.

#17786 changes the same function (`buildPodTemplate`). The two changes are independent; whichever merges second needs a trivial rebase.

Out of scope: the Pod MultiKueue adapter copies the live Pod spec, including ephemeral containers, when it creates the remote Pod.

Tests:
- Unit: a new `TestReconcile` case. It fails without the fix (the PodTemplate keeps the ephemeral container) and passes with it.
- Integration: two new specs, one per path, in `test/integration/singlecluster/controller/admissionchecks/provisioning/`. Without the fix both fail with the Forbidden error (8/8 runs). With the fix they pass (3/3 runs).
