#### What this PR does / why we need it?
The scheduler records an admission's metrics after the status write returns. With `CustomMetricLabels` enabled and a custom label taken from Workloads, it also stored the Workload's label values again at that point, when LocalQueue metrics were exposed for the Workload. The cache adds and removes those entries, so a delete or a label update that the cache handled in between was undone.

A deleted Workload's values then stayed in memory; the failed run in #17796 shows that order. If the labels changed in that window, the ClusterQueue and LocalQueue admitted active gauges ended at -1 for the old value and +1 for the new one once the Workload was gone.

This takes the scheduler's LocalQueue change from #14577 by @Sidd-Prabhu: the values for `kueue_local_queue_admitted_workloads_total` and `kueue_local_queue_admission_wait_time_seconds` are derived from the admitted Workload, as @Singularity23x0 suggested there, and nothing is stored. The rest of #14577 stays there: the Workload labels on the ClusterQueue admission metrics for #13589, and the WorkloadReconciler's LocalQueue reporting, which it also moves to derived values.

Fixes #17796

#### Useful notes for your reviewer
The new unit test changes the cache right after the admission write, before the scheduler records the admission: it deletes the Workload in one case and changes its labels in the other, then deletes it. On main the first case leaves `default/wl` in the label store, and the second leaves both gauges at -1 and +1. Before the delete, the test also checks the stored values, so it fails if the relabel does not happen. If only the `Store` is dropped and the values are still read from the store, the LocalQueue admission counter is recorded without the admitted Workload's label value, and both cases fail.

The commit cherry-picks cleanly onto release-0.20, where the test also fails without the fix. release-0.19 does not have this `Store`.

I ran the race unit tests for pkg/scheduler, pkg/cache, pkg/metrics and pkg/controller/core, and the CustomMetricLabels integration specs.

_Disclosure: I used an AI coding assistant while preparing this PR. I reviewed and tested the change myself._
