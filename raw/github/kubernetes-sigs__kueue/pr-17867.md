#### What this PR does / why we need it?

Cherry-pick of kubernetes-sigs/kueue#17803 to `release-0.19`, as requested in https://github.com/kubernetes-sigs/kueue/pull/17803#issuecomment-6460157572.

Workloads whose device requests come from `LimitRange` defaults can stay pending after a matching `DeviceClass` is created. This backport includes those workloads in `DeviceClass` change notifications so Kueue reevaluates their quota requirements.

#### Useful notes for your reviewer

The automatic cherry-pick conflicted in `pkg/controller/core/workload_controller_dra_test.go`.

The production fix is unchanged from the original PR. The tests use configured extended resource names because the `release-0.19` DeviceClass handler does not track implicit resource names. The backport also uses this branch's `reconcile.Request` structure, queue inspection API, and default `Pending` status reason.

AI assistance was used to adapt the backport, resolve conflicts, and run local validation.

Local validation:
- Regression tests fail against the pre-fix controller, as expected.
- `GOMAXPROCS=4 go test -p 4 -race ./pkg/controller/core -run '^(TestDeviceClassHandler_.*|TestReconcileDRA|TestNeedsDRAReconcileReadsDefaultsOnlyWithBackedResources|TestWorkloadReconcilerPreservesDRAResourceSnapshotWhenQueueing)$' -count=1` passed.
- `GOMAXPROCS=4 make test-integration INTEGRATION_TARGET=./test/integration/singlecluster/controller/dra INTEGRATION_NPROCS=1 GINKGO_ARGS='--focus=DeviceClass'` passed with 13 specs and race detection.
- `GOMAXPROCS=4 make ci-lint` passed.
- `make verify` passed.
- Real-cluster E2E tests were not run. This backport changes controller event handling and is covered by envtest.

#### Release note

```release-note
DRA: Fixed a bug where Workloads whose device requests come from LimitRange defaults stayed pending after a matching DeviceClass was created.
```
