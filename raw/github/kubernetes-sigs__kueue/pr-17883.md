## Description

#### What type of PR is this?

/kind bug
/area multikueue

#### What this PR does / why we need it?

The pod MultiKueue adapter builds the remote Pod by deep-copying the manager Pod's spec, including `spec.ephemeralContainers`. The API server rejects ephemeral containers on create, so if someone ran `kubectl debug` on the manager Pod while it waited for dispatch, the remote create keeps failing and the Pod never reaches the worker.

This clears `EphemeralContainers` on the copy before creating the remote Pod, as suggested in the issue. The other adapters copy their own CRs' specs, so they aren't affected.

Fixes #17861

#### Useful notes for your reviewer

- Added a unit test case in `pod_multikueue_adapter_test.go`: the manager Pod has an ephemeral container, and the remote Pod must be created without it. The fake client doesn't enforce the create validation, so the test checks the created spec directly. Added a small `EphemeralContainer` helper to the pod test wrapper for it.
- Tests: the new case fails without the fix (worker Pod gets the ephemeral container) and passes with it. `go test ./pkg/controller/jobs/pod/...` passes, `go vet` and golangci-lint v2.15.0 (repo config) report 0 issues on the changed packages. I couldn't run `make verify` (no `make` on my Windows machine), so CI will cover the generated-files checks; nothing generated is touched.
- AI disclosure: written with Claude, working with @BhavayGoyal.
