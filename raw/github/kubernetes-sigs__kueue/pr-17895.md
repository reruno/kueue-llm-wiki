#### What this PR does / why we need it?

The pod integration's MultiKueue adapter builds the remote Pod by deep-copying the live manager Pod spec, including `spec.ephemeralContainers`. The API server rejects ephemeral containers on Pod create. So if a manager Pod is debugged (for example with `kubectl debug`) before it is dispatched, it is never created on the worker, and the sync is retried forever.

This PR:
- adds an integration test (`test/integration/multikueue/pod_test.go`) that adds an ephemeral container to a gated manager Pod through the `ephemeralcontainers` subresource, waits until the manager's cache observes it, reserves quota on the manager and on worker1, and expects the Pod on worker1. envtest runs a real API server, so it enforces the create validation that a fake client would skip.
- clears `EphemeralContainers` on the remote copy before `remoteClient.Create` in `pkg/controller/jobs/pod/pod_multikueue_adapter.go`.

It is an integration test rather than the unit test the issue suggested because the fake client does not enforce create validation, so a unit test would only check that the field is cleared, not that the create would fail.

Fixes #17861

With the change, the spec passes and the remote Pod has no ephemeral containers.

The other MultiKueue adapters copy the spec of their own CRs, whose pod templates cannot carry ephemeral containers. ProvisioningRequest PodTemplates are handled separately in #17855.
