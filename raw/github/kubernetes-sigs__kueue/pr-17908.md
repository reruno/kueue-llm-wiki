#### What this PR does / why we need it?


 Before this fix, a misspelled authentication mode did not block Helm deployment or backend startup. KueueViz still served requests without authentication or resource permission checks.

```
enableKueueViz: true
kueueViz:
  backend:
    ingress:
      # Enabled by default, but not necessarily publicly accessible
      enabled: true
    auth:
      # Intended to enable TokenReview, but capitalization is incorrect
      mode: "tokenreview"
```

The fix validates the authentication mode in the Helm chart's values schema. Only `Disabled` and `TokenReview` are accepted. Misspelled values, empty strings, `null`, and non-string values now fail Helm rendering instead of silently disabling authentication.

## AI summary

When KueueViz is enabled, the Helm chart schema now requires `kueueViz.backend.auth.mode` to be `Disabled` or `TokenReview`. Invalid, empty, null, and non-string values fail chart rendering. The schema also requires `enableKueueViz` to be a boolean. Chart documentation now directs users to set the authentication mode through this value, not `KUEUEVIZ_AUTH_MODE` in `kueueViz.backend.env`.

### Suggested release note

Helm: Fixed a bug where an invalid KueueViz authentication mode could pass chart validation and leave authentication disabled. The chart now rejects values other than `Disabled` and `TokenReview` when KueueViz is enabled.
