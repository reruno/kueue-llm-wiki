#### What this PR does / why we need it?

The Argo Workflows guide says that `suspend`, `http` and `resource` templates create no pods.
A `resource` template runs `argoexec resource` in a pod of its own ([operator.go#L4024-L4026](https://github.com/argoproj/argo-workflows/blob/v4.1.6/workflow/controller/operator.go#L4024-L4026)).
`http` and `plugin` templates run in one agent pod per Workflow ([http_template.go#L15](https://github.com/argoproj/argo-workflows/blob/v4.1.6/workflow/controller/http_template.go#L15), [agent.go#L26-L28](https://github.com/argoproj/argo-workflows/blob/v4.1.6/workflow/controller/agent.go#L26-L28)).
That pod gets the labels from `spec.podMetadata` and none from the templates ([agent.go#L233-L236](https://github.com/argoproj/argo-workflows/blob/v4.1.6/workflow/controller/agent.go#L233-L236), [workflowpod.go#L1318-L1327](https://github.com/argoproj/argo-workflows/blob/v4.1.6/workflow/controller/workflowpod.go#L1318-L1327)), so a queue set in `spec.podMetadata` also applies to it.

#### Useful notes for your reviewer

I checked this against the Argo Workflows v4.1.6 source.
The v0.19, v0.20 and zh-CN copies of the page make the same statement; this changes only the current English page.
