#### What this PR does / why we need it?

The TAS RayJob ranks-ordering e2e test can fail because it finds no worker pods ([Prow run](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/17875/pull-kueue-test-e2e-tas-extended-shard-0-main/2115475616806473728)).

KubeRay clears `status.rayClusterName` while a RayJob is suspended and sets it again a few reconciles after the RayJob is unsuspended. The test could read the RayJob in between and then list worker pods by an empty `ray.io/cluster` label. This PR makes the test also wait until `status.rayClusterName` is set.
