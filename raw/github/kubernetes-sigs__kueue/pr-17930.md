### Comment by [@mbobrovskyi](https://github.com/mbobrovskyi) — 2026-10-29T15:54:54Z

Thanks for the PR! I phrased the original request as "one scenario per command", but on reflection `edit` and `describe` should be covered for every pass-through type, the same way `get`/`patch`/`delete` already are. Each (command, type) pair is a separate cobra subcommand (`delete workload` already has its own implementation), so testing only ClusterQueue leaves the other pairs unverified.

Could you drop the two new `It`s and extend each existing test instead (renaming them to `Should get, describe, patch, edit and delete a <Type>`)? Flow: `get` → `describe` → `patch` (A→B) → `edit` (B→A) → `get` → `delete`. Keep your `runKueuectlWithEnv` helper for `edit`. For example, for ClusterQueue:

```go
ginkgo.It("Should get, describe, patch, edit and delete a ClusterQueue", func() {
	cq := utiltestingapi.MakeClusterQueue("pass-through-cq").Obj()
	behavioral.MustCreate(ctx, k8sClient, cq)
	ginkgo.DeferCleanup(func() {
		behavioral.ExpectObjectToBeDeleted(ctx, k8sClient, cq, true)
	})

	for _, name := range []string{"clusterqueue", "cq"} {
		gomega.Expect(runKueuectl("get", name, cq.Name, "-o=jsonpath={.spec.stopPolicy}")).To(gomega.Equal("None"))
	}
	gomega.Expect(runKueuectl("describe", "clusterqueue", cq.Name)).To(gomega.MatchRegexp(`Stop Policy:\s+None`))
	runKueuectl("patch", "clusterqueue", cq.Name, "--type=merge", "-p", `{"spec":{"stopPolicy":"Hold"}}`)
	gomega.Expect(runKueuectl("get", "clusterqueue", cq.Name, "-o=jsonpath={.spec.stopPolicy}")).To(gomega.Equal("Hold"))
	runKueuectlWithEnv([]string{`KUBE_EDITOR=sed -i -e 's/stopPolicy: Hold/stopPolicy: None/'`}, "edit", "clusterqueue", cq.Name)
	gomega.Expect(runKueuectl("get", "clusterqueue", cq.Name, "-o=jsonpath={.spec.stopPolicy}")).To(gomega.Equal("None"))
	runKueuectl("delete", "clusterqueue", cq.Name)
	behavioral.ExpectObjectToBeDeleted(ctx, k8sClient, cq, false)
})
```

Suggested values for the other types:

| Type | `describe` regexp | `KUBE_EDITOR` sed expression (reverts the patch) |
|---|---|---|
| Workload | `Active:\s+true` | `'s/active: false/active: true/'` |
| LocalQueue | `Stop Policy:\s+None` | `'s/stopPolicy: Hold/stopPolicy: None/'` |
| ResourceFlavor | `Type:\s+small` | `'s/type: large/type: small/'` |
| Cohort | `Parent Name:\s+parent-1` | `'s/parentName: parent-2/parentName: parent-1/'` |
| Topology | `Node Label:\s+cloud.provider.com/topology-block` | `-e 's/topology-rack/tmp/' -e 's/topology-block/topology-rack/' -e 's/tmp/topology-block/'` |

A few notes:
- Please use a regexp on a spec field instead of `"Name:         " + name`. The exact padding comes from kubectl's tabwriter, and a spec field shows that `describe` actually read the object.
- Please make the sed expression match the field. A bare `s/None/Hold/` replaces any `None` in the YAML. Quoting works because kubectl runs a `KUBE_EDITOR` that contains spaces through `sh -c`.

@coderabbitai please update the issue to match.
