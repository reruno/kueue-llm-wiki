#### What this PR does / why we need it?

This draft combines two changes on upstream main (`ce0f8786f2694e129314bea42c0d3e609c6ec2e4`) as two separate commits for combined CI validation:

- Add the alpha, disabled-by-default `MultiKueueClusterNames` feature gate and `kueue.x-k8s.io/multikueue-cluster-names` annotation. Copy the annotation from Jobs to Workloads and intersect requested clusters with the clusters authorized by their MultiKueueConfig.
- Include the fix and regression tests from https://github.com/kubernetes-sigs/kueue/pull/17774: prevent a remote autoscaling Ray job from being pointed back onto a replaced workload slice while the manager still observes the old slice as unfinished.

Related: https://github.com/kubernetes-sigs/kueue/pull/14539
Related: https://github.com/kubernetes-sigs/kueue/pull/17774

#### Useful notes for your reviewer

The annotation change is cherry-picked from the deployed `codex/rayservice-autoscaling-cluster-targeting` branch (commits `0560b0fe11`, `4e535cf596`, and `100c55b83e`) into `fd15af8ff9`. The Ray fix and integration test are cherry-picked from `0f72a9e0b` and `c83cb6d16` in PR 17774 into `78be29fef`. Each change has its own commit. The final tree is identical to the previously tested single-commit revision `06d89b7d1`.

This is a combined validation draft. The annotation patch retains its existing dispatcher behavior: it overrides nominations for annotated workloads. Compatibility with Incremental and External dispatchers needs follow-up before merging; the incremental controller independently owns the nomination field and an annotation can bypass its step size or external placement decisions. The annotation integration scenario covers the AllAtOnce dispatcher.
