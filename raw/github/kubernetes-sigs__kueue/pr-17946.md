#### What type of PR is this?

/kind bug

/area concurrent-admission

#### What this PR does / why we need it?

`generateVariant` assigned the parent's `Labels` and `Annotations` maps to the variant and then edited them. Removing `ConcurrentAdmissionParentLabelKey` from the variant also removed it from the parent, and setting the allowed-flavor annotation on one variant changed it on the parent and on every other variant built from the same parent.

This clones both maps, the same way the function already clones `Spec.PreemptionGates`.

Fixes #17944

#### Useful notes for your reviewer

Added `TestGenerateVariantDoesNotShareMetadata`. It fails on main (the parent loses its label and gains `workload-allowed-resource-flavors: on-demand`, and the spot variant's flavor reads `on-demand`) and passes with the fix.

Tested locally (go 1.27.2):
- `go test ./pkg/controller/concurrentadmission/... -count=1` (also with `-race`)
- `go test ./test/integration/singlecluster/controller/concurrentadmission/` against envtest 1.37 after `make compile-crd-manifests`
- `go vet` and `golangci-lint run` (repo config) on the package; gofmt clean

I didn't run the e2e suites or the full `make test`.

I don't have evidence that the mutated parent was ever written back to the API server, so the release note is NONE.

I used an AI assistant to help write the fix and the regression test; I reviewed and verified the change myself.

```release-note
ConcurrentAdmission: Fixed a bug where generating Workload variants could change the parent’s metadata or overwrite a sibling variant’s flavor annotation. Each variant now has independent labels and annotations.
```

Issue `#17944` requires that constructing a variant leaves the parent ObjectMeta unchanged, keeps the parent marker, gives each variant its own labels and flavor annotation, and keeps sibling metadata independent.

The diff at head changes generateVariant in pkg/controller/concurrentadmission/controller.go. Labels and Annotations are now set to maps.Clone(parent.Labels) and maps.Clone(parent.Annotations) instead of the parent's map references. The subsequent delete(variant.Labels, ConcurrentAdmissionParentLabelKey) and metav1.SetMetaDataAnnotation therefore act only on the variant's maps. This removes the three aliasing effects listed in the issue: parent marker removal, flavor annotation leakage into the parent, and sibling flavor overwrite.

The nil-annotations case is handled by code reasoning: maps.Clone(nil) returns nil, and SetMetaDataAnnotation allocates a new map for the variant. This matches the issue's note. The Spec.PreemptionGates clone and other struct-field copies are unchanged, as the issue requests.

Added test TestGenerateVariantDoesNotShareMetadata in controller_test.go checks that the parent metadata is unchanged after generating spot and on-demand variants, that each variant has its own flavor, and that the spot variant lacks the parent label.
