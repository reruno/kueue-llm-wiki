## Description

#### What type of PR is this?

/kind cleanup
/area testing

#### What this PR does / why we need it?

Allow independent integration scenarios to run across the existing Ginkgo processes:

- Remove `Ordered` from the Job `waitForPodsReady unscheduledTimeout` group, which already initializes its manager and resources per spec.
- Remove `Ordered` from the WAS Simulator group and scope its shared manager to each process's suite lifecycle.
- Remove `Ordered` from the two RayCluster workload-slice groups, give each spec its own manager and restored feature gates, and register manager cleanup before startup so readiness failures cannot leak a manager.
- Start the two longest remaining ordered Job groups earlier with `SpecPriority(1)` to avoid late stragglers.

Test scenarios, assertions, timeouts, race detection, package sharding, the default four single-cluster workers, and CI CPU/memory allocations are preserved. No product API, configuration schema, or data format changes are included.

Related: #17943

#### Useful notes for your reviewer

Rebased the test scheduling changes onto `main` at `86b2f3f51` and narrowed this PR in response to review:

- Removed all tool download changes. `gomod-download-tools` prerequisites and the `ginkgo-top` module download retain their existing retry behavior.
- Split the worker-count configuration and documentation into independent #18069, based directly on `main`.
- Removed the overlapping CLI build optimization, which is already merged in #17885. This PR leaves that implementation unchanged.
