## Description

#### What type of PR is this?

/kind bug
/area multikueue

#### What this PR does / why we need it?

With RetainFirstAdmission, once a variant is admitted the other variants get deactivated. If a losing variant still holds quota when the workload controller marks it `Evicted=True` (reason `Deactivated`), `syncVariantEvictionStatus` treats it like the admitted variant being evicted and evicts the parent with `VariantEvicted`. The running job gets suspended even though the variant it runs on is fine.

This change makes `syncVariantEvictionStatus` release the quota of an inactive variant and move on, so only an active variant's eviction is propagated to the parent. If the admitted variant itself gets deactivated, its quota is released here and `syncAdmissionStatus` still evicts the parent through the existing "no variant is running" path.

Fixes #17915

#### Useful notes for your reviewer

The new unit test fails on main with the parent evicted as `VariantEvicted`, and passes with the change.

We hit this on GKE with a ProvisioningRequest admission check on both flavors and ConcurrentAdmission on MultiKueue workers. The manager saw the worker workload evicted, retried the check and dispatched again, so the job never settled. Details are in #17915.

#### Release note

```release-note
ConcurrentAdmission: Fix a bug where deactivating a losing variant that still held quota evicted the parent workload, suspending a job that was running on the admitted variant.
```
