## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it?
When a `LocalQueue` was stopped (`spec.stopPolicy: Hold` or `HoldAndDrain`), the queue manager called `clearLQMetrics()`, which invoked `metrics.ClearLocalQueueMetrics()`. This prematurely purged all cumulative counters (`kueue_local_queue_admitted_workloads_total`, `finished_workloads_total`, `evicted_workloads_total`) and latency histograms simply because the queue was paused. Upon resumption, counters would reset to 1 instead of continuing monotonically.

Furthermore, because a stopped queue was already removed from the in-memory queue manager map, subsequent deletion via `kubectl delete localqueue` triggered an early return in `Manager.DeleteLocalQueue()`, leaving any counters recorded while stopped (such as `LocalQueueStopped` eviction counters or workloads that finished under Hold) permanently leaked in the Prometheus registry.

This PR fixes both issues by:
1. Introducing `metrics.ClearLocalQueueGaugeMetrics()` to clear only `gaugeCleanupScopeLocalQueue` gauges.
2. Updating `clearLQMetrics()` in `pkg/cache/queue/metrics.go` to call `ClearLocalQueueGaugeMetrics()` so that in-memory deletion (pause/stop) does not clear cumulative counters or histograms.
3. Adding an explicit call to `metrics.ClearLocalQueueMetrics()` in `LocalQueueReconciler.Delete()`, ensuring all metrics (gauges, counters, histograms) are purged unconditionally when the Kubernetes API object is deleted.
4. Adding unit and integration tests covering the stop/resume and deletion lifecycle matrix.

Fixes #17524

#### Useful notes for your reviewer
- Follows the design proposed by @thc1006 in #17524.
- Adds unit tests in `pkg/metrics/metrics_test.go` and integration tests in `test/integration/singlecluster/controller/core/localqueue_controller_test.go`.
