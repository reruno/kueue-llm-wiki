#### What this PR does / why we need it?

The `Should delete a standalone workload with --yes` scenario in `test/integration/singlecluster/kueuectl/delete_test.go` checked the result with `behavioral.ExpectObjectToBeDeleted(ctx, k8sClient, wl, true)`. With `deleteNow=true` the helper deletes the Workload itself before waiting for it to disappear, so the scenario passed even when `kueuectl delete workload` did not delete anything.

This PR passes `false` instead, so the helper only waits for the deletion done by the command. That matches the alias scenarios added in #17970. Namespace cleanup in `AfterEach` is unchanged.

Fixes #17982

#### Useful notes for your reviewer

- **Context:** this is the follow-up to #17970 requested in https://github.com/kubernetes-sigs/kueue/pull/17970#issuecomment-6500037663.
- **Masking demonstrated with a temporary local change (not committed):** I made `delete workload` skip its `Workloads().Delete` call for standalone Workloads, then ran the scenario on its own with `INTEGRATION_TARGET=./test/integration/singlecluster/kueuectl GINKGO_ARGS="--focus=standalone.workload.with" make test-integration-run`.
  - Before this change, the scenario passed (1 passed).
