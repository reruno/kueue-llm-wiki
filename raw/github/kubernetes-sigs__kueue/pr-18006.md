## Description

#### What type of PR is this?

/kind cleanup
/area testing

#### What this PR does / why we need it?

The provisioning controller tests build ProvisioningRequests as struct literals, and derive variants by copying a request and changing its name, UID or PodSets in place.
This adds `ProvisioningRequestWrapper` next to `ProvisioningRequestConfigWrapper` and builds those requests in `controller_test.go` with it.

Fixes #17998

#### Useful notes for your reviewer

The owner references now carry the Workload kind. The tests compare request metadata only by labels, and the owner index reads only the name, so no result changes; the package's unit tests give the same results as on main.
Status is still set as before, by `requestWithCondition(s)` and two closures for `ProvisioningClassDetails`.
The literals in `indexer_test.go` and `provisioning_test.go` stay, since they set only names and bare owner names, which is what those tests check.
