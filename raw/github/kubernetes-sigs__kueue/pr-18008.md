## Description

#### What type of PR is this?
/kind bug
/area dra

#### What this PR does / why we need it?
`extractCELRequests()` used to collect `adminAccess: true` requests as well, and
`countMatchingDevices()` reserves every matched device in a set shared by all
requests of one ResourceClaimTemplate. An admin request therefore took a device
away from the ordinary requests of the same claim.

As a result, a workload whose ordinary requests exactly fit the cluster was
marked inadmissible as soon as it also carried an admin claim:

    QuotaReserved=False reason=DRAResourcesUnresolved
    ... insufficient matching devices for CEL selector in DeviceClass mig.example.com:
    0 device(s) match in the cluster but 1 requested

while the same workload without the admin request was admitted, and the workload
with the admin request was admitted as soon as one more matching device existed.

AdminAccess requests consume no quota and the kube-scheduler does not treat
devices allocated with admin access as allocated; they are shared with other
claims. So they must not consume availability here. `chargesForClaimSpec()`,
`GetCounterResourcesForWorkload()` and `DetermineCapacityResourcesForWorkload()`
already skip them.

This PR:
- skips AdminAccess requests in `extractCELRequests()`;
- adds a unit case (one device; admin + ordinary request, both with CEL selectors)
  and an integration case (the workload is admitted and charged for the ordinary
  request only);
- updates KEP-2941 and the DRA concept page, whose limitations list still said
  admin requests are unsupported.

Related: #13642

#### Useful notes for your reviewer
Reproduced on a kind cluster with a synthetic partitionable-device ResourceSlice
and a counter-based `gpu.memory` mapping. Same claim, same selectors; only the
number of matching MIG devices changes:

| matching devices | admin-only | ordinary-only | admin (no selector) + ordinary | admin + ordinary | admin x2 |
|---|---|---|---|---|---|
| 1 | admitted, 0 | admitted, 4864Mi | admitted, 4864Mi | inadmissible | inadmissible |
| 2 | admitted, 0 | admitted, 4864Mi | admitted, 4864Mi | admitted, 4864Mi | admitted, 0 |

After the fix the 1-device column matches the 2-device column.

I considered keeping the admin requests in the check and matching them against a
private, non-shared device set. I went with skipping because the check exists to
keep quota from being held by workloads that cannot be scheduled, and admin
requests hold no quota. Happy to switch to the stricter variant instead.

AI assistance was used for analysis and test scaffolding; every result above was
reproduced on a real cluster and the change was reviewed by the author.

#### Release note
```release-note
DRA: An AdminAccess request no longer takes a device away from the other requests in the same ResourceClaimTemplate. Previously, a workload that exactly fit the cluster could be marked inadmissible with "insufficient matching devices" just because it also carried an admin request.
```
