## Description

This is an automated cherry-pick of #17786

```release-note
ProvisioningRequest: Fix a bug where workloads whose container or initContainer volumeMounts reference volumes added at runtime (StatefulSet and LeaderWorkerSet volumeClaimTemplates, JobSet volumeClaimPolicies) remained pending when the ClusterQueue had a ProvisioningRequest admission check, because the PodTemplate created for the ProvisioningRequest was rejected.
```

/kind bug

Adaptations for release-0.19: dropped the `sanitizeProvisioningRequestPodTemplate` context (not on this branch), spelled out embedded `VolumeSource`/`ObjectMeta` in struct literals (Go 1.26), and used `jobframework.EnableIntegration` plus `pod.SetupIndexes` in the integration suite.

Proven with `go build ./...`, `golangci-lint` on the touched packages, unit tests, and `make test-integration INTEGRATION_TARGET=./test/integration/singlecluster/controller/admissionchecks/provisioning/...` (23/23 passed; the new spec fails without the controller change).
