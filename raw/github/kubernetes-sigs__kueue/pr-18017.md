#### What this PR does / why we need it?

The garbage collector of kube-controller-manager picks up new CRDs only on its discovery resync, every 30 seconds. In the failed run it started watching Workloads at 17:16:11.928, 15ms after the Orphan spec deleted its Job, so it never removed the Job's owner reference from the Workload, and then deleted the Workload.

This PR makes `WaitForKueueAvailability` wait until the garbage collector watches Workloads: it deletes the owner ConfigMap of a probe Workload and waits for the garbage collector to delete the Workload. When the garbage collector already watches Workloads, this takes about 0.3s.

Fixes #17997

**Clean up probe objects when the probe fails.**

The probe creates a ConfigMap and a Workload in `default` and deletes them only on the success path. If `behavioral.MustCreate` for the Workload fails, or the deletion wait fails, the objects remain. Each failed run in a reused cluster (`E2E_MODE=dev`) can leave `gc-probe-` objects in the `default` namespace. Register cleanup for `owner` and `wl` right after they are created, so the cleanup runs on failure too.
