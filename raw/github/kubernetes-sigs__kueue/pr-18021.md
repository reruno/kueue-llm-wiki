## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

The Workload webhook accepted more than one `podSetUpdates` entry for the same PodSet in one admission check. Job start and the TAS node controller apply only the first entry, while TAS placement applies all of them, so TAS could place Pods on a node whose taint the started Pods do not tolerate. This PR rejects the repeated entries behind a new Beta feature gate, `WorkloadValidateUniquePodSetUpdates` (enabled by default). On update, a list unchanged from the old object is still allowed, so Workloads that already store repeats can be updated and finalized.

Fixes #17899

#### Useful notes for your reviewer


#### Release note

```release-note
AdmissionChecks: Fixed a bug where an admission check could set more than one `podSetUpdates` entry for the same PodSet, so TAS could place Pods on nodes whose taints the started Pods did not tolerate. Kueue now rejects such updates when the `WorkloadValidateUniquePodSetUpdates` feature gate (Beta, enabled by default) is enabled.

ACTION REQUIRED: If an external AdmissionCheck controller writes more than one `podSetUpdates` entry for the same PodSet in one admission check, change it to write one merged entry, or disable the `WorkloadValidateUniquePodSetUpdates` feature gate until it does.
```
