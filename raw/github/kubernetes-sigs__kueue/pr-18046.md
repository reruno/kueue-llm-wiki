## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

The PodGroup role hash shape only recorded resource requests and ports for containers, so `restartPolicy` was invisible to the hash. A restartable init container (sidecar) therefore shared a role with an otherwise identical regular init container, and a PodGroup containing both collapsed them into a single PodSet, under-accounting the resources the sidecar keeps consuming while the main containers run.

This PR includes the `restartPolicy` of each init container in the shape when it is set. The key is omitted for regular init containers, so role hashes of pods without restartable init containers are unchanged and existing PodGroups keep their roles across the upgrade.

Fixes #18045

#### Useful notes for your reviewer

- `initContainersShape` extends `ContainersShape` per init container; a compat test recomputes the pre-change hash and verifies it is preserved for pods without restartable init containers.
- Unit tests cover the shape (presence/absence of `restartPolicy`), the hash change for sidecars, hash stability for regular init containers, and `constructGroupPodSets` producing separate roles for mixed groups, independent of input pod order.

#### Release note

```release-note
PodGroup role hashes now distinguish restartable init containers (sidecars) from regular init containers, so groups mixing both are accounted as separate roles. Role hashes of pods without restartable init containers are unchanged.
```

## AI summary

PodGroup role hashes now include the `restartPolicy` of init containers when it is set. Pods with a regular init container and pods with a restartable init container (sidecar, `restartPolicy: Always`) no longer share a hash. Kueue counts them as separate PodSets instead of one combined PodSet.

- Unset `restartPolicy` values are omitted from the shape. Hashes for pods without restartable init containers do not change.
- Existing PodGroups keep their roles across upgrades. Compatibility logic restores legacy role annotations on eligible Pods that have not started.
- When a legacy mixed-group sidecar replacement has a different role hash, Kueue emits a `LegacyPodGroupRoleMismatch` warning event. The replacement stays gated, and the existing Workload is retained.
- The change adds unit and integration tests for role hashes, PodSet grouping, legacy compatibility, and the mismatch warning.

### Suggested release note

Pod: Fixed a bug that caused pods with a regular init container and pods with a restartable init container (sidecar) to be combined into one PodSet when their specs differed only in the init container `restartPolicy`. Now Kueue assigns separate roles to these pods. Existing PodGroup roles are preserved across upgrades. A mismatched legacy sidecar replacement emits a `LegacyPodGroupRoleMismatch` warning event.
