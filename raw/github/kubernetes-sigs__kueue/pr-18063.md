#### What this PR does / why we need it?

Replaces handwritten `ClusterQueue.Status.FlavorsUsage` checks with the shared `behavioral.ExpectClusterQueueResourceUsageWithTimeout` helper in:
- `test/integration/singlecluster/scheduler/scheduler_test.go`: 6 checks in the "Workload slicing with multiple podSets" specs.
- `test/integration/singlecluster/controller/jobs/raycluster/raycluster_controller_partial_scaleup_test.go`: the body of the `expectPodsUsage` closure. Its call sites are unchanged.

`ClusterQueueResourceUsage` now returns `(int64, bool)` to indicate whether the resource we're looking for was found. Without that, the helper treated a missing entry as `0` usage, so a check for `0` could pass when it shouldn't.
The handwritten checks prevented this with `HaveLen(1)` and `idx == -1`. The helper now does the same for every caller.
