#### What this PR does / why we need it?

Adds partial scale-up for elastic SparkApplication. With the `partial` strategy and dynamic allocation, a scale-up slice can be admitted with fewer executors than requested.

Part of partial scale-up for elastic jobs tracked in #12100.

#### Useful notes for your reviewer

- Same as RayJob: the executor `minCount` is the current executor count.
- Depends on #16742: when executors exit (at the latest when the app completes), the executor count drops below `minCount`. Without #16742 that update is rejected and the Workload never finishes. Covered by the spec "Should finish the workload when the executors exit".

## AI summary

SparkApplications that use dynamic allocation can partially admit scale-up Workload slices when quota cannot fit all requested executors. Kueue admits the executors that fit. It keeps the remaining executors gated. Initial admission stays atomic.

This behavior requires the `ElasticJobsViaWorkloadSlicesWithPartialReplicaScaleUp` feature gate and the `kueue.x-k8s.io/elastic-job-scale-up-strategy: "partial"` annotation. Without the annotation, scale-ups remain atomic.

The change does the following:
- Sets the executor PodSet `MinCount` to the full requested count when partial scale-up and dynamic allocation are enabled. Otherwise, it leaves `MinCount` unset.
- Adds controller unit tests for the `MinCount` behavior.
- Adds integration tests for partial admission and for workload completion when executors exit.
- Adds an end-to-end test for staged quota increases.
- Updates the English and Chinese dynamic allocation documentation.

### Suggested release note

SparkApplication: Added partial admission for dynamic-allocation scale-ups. Kueue admits the executors that fit available quota and keeps the remaining executors gated until more quota is available. This behavior is gated by the `ElasticJobsViaWorkloadSlicesWithPartialReplicaScaleUp` feature gate and requires the `kueue.x-k8s.io/elastic-job-scale-up-strategy: "partial"` annotation.
