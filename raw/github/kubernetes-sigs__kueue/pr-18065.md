#### What this PR does / why we need it?

When `hack/cherry_pick_pull.sh` cherry-picks several PRs, it copies each PR's `release-note` block into one block. If one PR has a real note and another has `NONE`, the `NONE` ends up as the last line of the real note. `/sync-release-notes` runs the `release-notes` tool, which skips a block only when the whole block is `none`, `n/a` or `na`. So the tool publishes the `NONE` line, and it also publishes a block of several `NONE` lines. #18061 had the first case and #9212 had the second, and someone edited both bodies by hand before merge.

The script now skips the notes that the `release-notes` tool ignores: empty, `NONE`, `N/A` and `NA`, in any case. If no note is left, it writes a single `NONE`.

#### Useful notes for your reviewer

- I ran the new filter with macOS `/bin/bash` 3.2 on the bodies of #14954 and #18058, and only the #14954 note was left. Notes that are all `NONE` give one `NONE`, also with CRLF line endings or in lowercase. The script skips a PR without a `release-note` block.
- The script sets the `NONE` fallback before the heredoc expands `RELEASE_NOTES`, because bash 3.2 fails on an empty array under `nounset`.
- This PR was written in part with the assistance of generative AI.
