#### What this PR does / why we need it?

Since #7772 the readyz check never reaches its `certificates are not ready` branch, so this PR removes that branch and the `certsReady` channel behind it. Readiness works the same way.

`cert.BootstrapCerts` writes the webhook certificates with a separate bootstrap manager before the main manager is created. `ManageCerts` then only adds the rotator and closes `certsReady` right away, and without internal cert management `main` closes it in the `else` branch. Both happen before `mgr.Start`, so the readyz check in `setupProbeEndpoints` never returns `certificates are not ready`, and the comment about calling `GetWebhookServer` lazily is stale.

This PR removes `certsReady` and the `setupFinished` parameter of `ManageCerts`, and registers `mgr.GetWebhookServer().StartedChecker()` as the readyz check directly. Readiness still waits until the webhook server is started and reachable.

### Comment by [@ivnovakov](https://github.com/ivnovakov) — 2026-11-02T09:20:33Z

Thanks for the review!

No, `cmd/kueue` has no unit tests, so readyz is covered only by e2e.
Every e2e suite calls `WaitForKueueAvailability` in `BeforeSuite`, which waits for `kueue-controller-manager` to be Available, and that needs the `/readyz` readinessProbe to pass.
If the webhook server does not start, `StartedChecker` keeps failing, the pods never become Ready, and every suite fails at setup.

The check itself does not change in this PR. readyz was already `StartedChecker` once `certsReady` was closed, and this PR only removes the wrapper around it.
