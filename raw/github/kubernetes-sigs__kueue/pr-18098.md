#### Useful notes for your reviewer

The automated cherry-pick failed with conflicts in `pkg/cache/scheduler/tas_flavor_snapshot.go`, because release-0.19 does not have several changes that #17515 builds on.
The test changes are the same as in #17515. The fix is adapted as follows:

- `groupDomainsOnHealthyNodes` takes the group name (`*string`) and matches `TopologyRequest.PodSetGroupName`, because release-0.19 does not have `utiltas.PodSetGroupKey`. A PodSet without a group returns no anchor, as in #17515.
- `assignPodSetGroup` uses the release-0.19 `findTopologyAssignment` and `addAssumedUsage`, without the topology spreading counts.
- `opts.workload` replaces `wlObj`, and the log uses `UnhealthyNodes[0]` instead of `workload.FirstUnhealthyNodeName`.
- `requiredReplacementDomain` keeps the release-0.19 lookup of the first domain and reads it from the group anchor when the PodSet has no domain left.
- The check that fails a required replacement when no domain can be determined is not included, because it was added by #16321, which is not in release-0.19.

Tests:
- `go test ./pkg/cache/scheduler/... ./pkg/scheduler/` passes.
- Without the fix, 5 of the 7 new `TestScheduleForTAS` cases fail on release-0.19; with it, all 7 pass.
- This PR was prepared with AI assistance.

#### Release note

```release-note
TAS: Fixed a bug where replacing a failed node could move a Pod of a PodSet group, such as a LeaderWorkerSet leader, to a different topology domain than the rest of its group. Kueue now keeps the group in its required domain, or evicts the Workload when the domain has no room for the replacement.
```
