## Description

#### What type of PR is this?

/kind bug
/area elastic-jobs

#### What this PR does / why we need it?

When a node becomes unreachable, its Pods are deleted but stay Terminating until the node comes back, because no kubelet confirms the deletion.
The elastic Job ungater still counts such a Pod toward the granted PodSet count, so the replacement Pod created by the Job stays behind the `kueue.x-k8s.io/elastic-job` scheduling gate, even when other nodes have room.

This PR makes the ungater skip a Pod that is being deleted on a node with the `node.kubernetes.io/unreachable` taint, so its slot can be used by the replacement Pod.

Fixes #17948

#### Useful notes for your reviewer
- The check matches the one used by the `FailureRecoveryPolicy` Pod termination controller (Terminating Pod plus the `node.kubernetes.io/unreachable` taint). If the Node object no longer exists, the Pod still counts.
- This PR was prepared with AI assistance.

#### Release note

```release-note
ElasticJobsViaWorkloadSlices: Fixed a bug where a replacement Pod stayed gated while the Pod it replaced was stuck terminating on an unreachable node.
```

Add an integration scenario that:
