## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

With `TASReplaceMultipleFailedNodes` enabled, a PodSet group is re-placed as a whole, so one admission can move away from more than the head of `status.unhealthyNodes`. `updateUnhealthyNodesAfterTASReplacement` removed only the head, so a node the new assignment no longer used stayed in the list:

```
unhealthyNodes=[{x2}] assignment=[leader=x3 worker=x4 worker=x5]
```

The stale entry occupies one of the eight slots and keeps `HasUnhealthyNodes` true, so the Workload is evicted earlier than it should be when more nodes fail.

The function now drops every unhealthy node that no hostname-scoped `PodSetAssignment` in the new admission uses. A node that is still assigned is kept for a later pass, which is what a partial replacement relies on. When the admission has no hostname-scoped assignment, only the head is dropped, exactly as before.

`assignedNodeNames` reads the node names from the last level of the topology domains, mirroring `utiltas.HasNodeInPodSetAssignment`, and ignores domains with `Count == 0`.

Fixes #18114

#### Useful notes for your reviewer

- `TestUpdateUnhealthyNodesAfterTASReplacement` covers the reported case (both `x1` and `x2` left by a group re-placement), a node that is still assigned (kept), the single-node replacement (field cleared), and the no-hostname-assignment fallback (head only). The first case fails before the fix and passes after it.
- I did not run the integration suite locally: `test/integration/singlecluster/tas` needs envtest binaries that are not installed here. The TAS integration scenarios around multi-node replacement should still hold, since a node that is still assigned is retained.
- `go test ./pkg/scheduler/` and `go vet ./pkg/scheduler/` pass.

#### Release note

```release-note
TAS: remove every node that a re-placed PodSet group no longer uses from `status.unhealthyNodes` when the `TASReplaceMultipleFailedNodes` feature gate is enabled, instead of removing only the first one.
```
