## Description

#### What type of PR is this?

/kind bug
/area tas

#### What this PR does / why we need it?

When a node of a TAS Workload fails, Kueue tries to replace it. If another node of the same assignment is cordoned (its Pods still running), that node is missing from the TAS snapshot, so the assignment looked stale and the replacement failed. With `TASFailedNodeReplacementFailFast`, the Workload was evicted.

Now nodes missing from the snapshot are ignored during replacement, with or without `TASReplaceMultipleFailedNodes`. This is the minimal fix (option 1 in the issue); the root-cause fix follows separately.

Fixes #17783

#### Useful notes for your reviewer

- Tests: unit cases in `tas_cache_test.go` and `scheduler_tas_test.go`, and an integration spec that follows the issue's repro.
- The kept cordoned node may appear out of topology order in the assignment. The gate-on path already does this, and it doesn't affect placement.
- Not covered here: required topology with all remaining nodes cordoned, and PodSet slices with a cordoned node. Left for the root-cause fix.
- Verified locally: unit tests, the full TAS integration suite (172/172), golangci-lint.
- AI disclosure: developed with the assistance of Claude Code. All changes were reviewed by the author.

#### Release note

```release-note
TAS: Fixed a bug where replacing a failed node failed, or evicted the Workload, when another node in its topology assignment was cordoned or NotReady while its Pods kept running. This affected clusters with the `TASReplaceMultipleFailedNodes` feature gate disabled (the default).
```

## AI summary

When replacing a failed node, TAS now ignores other missing node-level domains in the assignment, including when `TASReplaceMultipleFailedNodes` is disabled. This prevents a cordoned node with running Pods from making the assignment appear stale and causing failed replacement or Workload eviction. New unit, scheduler, and integration tests cover this scenario.

### Suggested release note

TAS: Fixed a bug where a cordoned node with running Pods could block replacement of another failed node and cause Workload eviction. Kueue now preserves the cordoned node’s assignment while replacing the failed node.
