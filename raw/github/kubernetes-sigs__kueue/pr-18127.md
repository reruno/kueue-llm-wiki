#### What this PR does / why we need it?


When `PriorityBoost` is enabled, external controllers can update a `Workload`'s `kueue.x-k8s.io/priority-boost` annotation to apply an offset to its base priority without changing Pod priority.
This adjustment applies to both `WorkloadPriorityClass` and Kubernetes `PriorityClass`, but before this fix, boost changes on admitted `Workload` objects were handled differently:

• With `WorkloadPriorityClass`, changing the boost triggered reevaluation of pending `Workload` objects.
• With Kubernetes `PriorityClass`, the annotation update succeeded and the effective priority changed, but pending `Workload` objects were not reevaluated.

Consequently, in the Kubernetes `PriorityClass` case, pending `Workload` objects still had to wait for another scheduling event, even if a decreased or removed boost made the admitted `Workload` eligible for preemption.

This fix detects `priority-boost` annotation changes for `Workload` objects backed by Kubernetes `PriorityClass` and triggers reevaluation of pending `Workload` objects. It preserves the existing behavior of ignoring changes to Pod priority itself.
