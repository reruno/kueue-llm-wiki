#### What this PR does / why we need it?

Kueue counted devices from ResourceSlice pools that the DRA allocator never allocates from. #17649 fixed this for stale and incomplete pools in the CEL availability check, but invalid pools were still counted, and the counter path kept its own copy of the pool checks.

This PR moves pool eligibility into one helper used by the CEL availability, counter, and capacity paths. A pool is eligible when it is complete and valid at its highest observed generation, grouped by driver and pool name. As in the allocator (`k8s.io/dynamic-resource-allocation/structured`), a pool is invalid when:

- two devices in the pool have the same name,
- two counter sets in the pool have the same name, or
- a device consumes a counter set or counter that the pool does not publish in `sharedCounters`.

Listing order is preserved, so overlapping CEL requests still reserve devices greedily in the same order. Skipped pools are logged at V(4) with the reason. When too few eligible devices remain, the existing internal-error path keeps the Workload inadmissible and retries with backoff.

Fixes #17705
Related: #17649

#### Useful notes for your reviewer

- The counter-set checks run regardless of the `DRAPartitionableDevices` gate; Kueue cannot see the scheduler's gates. With the gate off, the API server drops `sharedCounters` and `consumesCounters`, so the checks pass trivially.
- A ResourceSlice holds either devices or `sharedCounters`, not both. The partitionable-devices integration fixtures only set `consumesCounters`, so under the new checks their pools were invalid. Each of those pools now publishes its counter set in a second slice (`resourceSliceCount: 2`); a new `CounterSet` test wrapper builds it. The incomplete-pool spec is unchanged.
- `matchDevicesWithSelectors` now takes the eligible slices instead of a pool map, so device iteration order in the counter path is deterministic.
- Tests: a table test for the helper (`pools_test.go`) covers stale, incomplete, the three invalid cases, an invalid pool next to a valid one, identical pool names across drivers, and order. Five cases were added to `Test_GetResourceRequests`. Against unchanged upstream code, the three invalid-pool cases fail and the two positive controls pass.
- Docs: added a troubleshooting note to `setup_dra.md`.
