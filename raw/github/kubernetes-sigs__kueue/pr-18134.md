## Description


#### What type of PR is this?

#### What this PR does / why we need it?

Every queue change reports `kueue_pending_workloads` for the ClusterQueue.
`reportCQPendingWorkloads` copies the active and inadmissible `LabelValsTracker`s and merges them into a third tracker.
With `CustomMetricLabels` disabled (the default), it then reads only the two `.Total()` values.
`ClusterQueue.Pending()` and `PendingTotal()` also copy both trackers to return two integers.
`CustomLabels.Get` allocates a map before it checks whether custom labels are enabled.

This PR:

- Adds `PendingWorkloads.Pending()`, which returns the active count (including inflight workloads) and the inadmissible count without copying the trackers.
- Uses it in `ClusterQueue.Pending()` and `PendingTotal()`.
- In `reportCQPendingWorkloads`, reads the trackers only when Workload custom labels are configured. The default path reports the two integers, and moves the active count to inadmissible when the ClusterQueue is inactive. This matches the existing split in `reportLQPendingWorkloads`.
- Makes `CustomLabels.Get` return early when custom labels are disabled. This also covers `CQGet`, `LQGet` and `CohortGet`.

Fixes #18110
