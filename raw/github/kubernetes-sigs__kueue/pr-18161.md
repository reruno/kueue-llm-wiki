## Description

#### What type of PR is this?

/kind kep

#### What this PR does / why we need it?

KEP-3258 (delayed admission check retries) was implemented in #7620 and released in v0.15.0 without a feature gate. The KEP's `kep.yaml` already says `feature-gates: {}`, but the README's Graduation Criteria still list an `ACRequeueAfter` feature gate for Alpha, Beta and GA, so the KEP contradicts itself and the released code.

This PR:
- removes the feature gate items and explains why the feature has no gate: both fields are optional, and Kueue only delays a retry when an admission check controller sets `requeueAfterSeconds`
- marks the Alpha items and the ProvisioningRequest migration that shipped in v0.15 as done
- adds the KEP merge, implementation and release dates to the Implementation History
- sets `status: implementable` and moves the Beta milestone to `TBD`, because the Beta criteria (bugs, docs, metrics) are not met yet
- replaces the `kep.yaml` comment that said the feature can be disabled through the Configuration API; there is no such setting
- describes `requeueAfterSeconds` as it is in the API: an `int32` number of seconds counted from the check's `lastTransitionTime` (the KEP had `*metav1.Duration` and "based on eviction time")
