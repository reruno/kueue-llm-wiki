#### What this PR does / why we need it?

The `requeueAfterSeconds` and `retryCount` fields of the admission check state were added in v0.15 (KEP-3258, #7620), but the admission check concept page doesn't mention them; they only appear in the generated API reference. The KEP lists "first iteration of admission check documentation" as a graduation item.

This PR adds a "Delaying a retry" section to `site/content/en/docs/concepts/admission_check/_index.md` that explains:
- how a controller asks for a delay, and why `requeueAfterSeconds` has to be set in the same update as the `Retry` state
- how Kueue turns it into `.status.requeueState.requeueAt`, and how it combines with other backoffs that share that field (WaitForPodsReady)
- that Kueue keeps `requeueAfterSeconds` when it resets a check to `Pending`, so controllers should set it every time they set `Retry`
- how Kueue maintains `retryCount`
- that the ProvisioningRequest admission check uses these fields

Part of #3258

Related: #18161 (updates the KEP-3258 graduation criteria and metadata)
