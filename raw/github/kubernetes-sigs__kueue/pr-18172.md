## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it?
This PR ensures that restartable init containers (native sidecars with `restartPolicy: Always`) are differentiated from regular init containers during PodGroup role hash and shape computation.

Previously, `ContainersShape` in `pkg/util/pod/pod.go` only recorded container resource requests and ports, ignoring `restartPolicy`. As a result, a pod with a restartable init container received the same role hash as an otherwise identical pod with a regular init container. When grouped in a PodGroup, these pods would collapse into a single PodSet with a shared count, despite their runtime resource usage footprints differing significantly (a regular init container terminates before main containers start, while a sidecar runs concurrently for the life of the pod).

With this PR:
- `ContainersShape` records `c.RestartPolicy` in the container shape when set (`c.RestartPolicy != nil`).
- When `RestartPolicy` is unset (regular init containers and app containers), the key is omitted, keeping role hashes for existing pods without restartable init containers stable and backward-compatible.
- Unit tests added in `pkg/util/pod/pod_test.go` verifying shape inclusion/omission and role hash differentiation.

Fixes #18045

#### Useful notes for your reviewer
Unit tests added in `TestSpecShape` and `TestGenerateRoleHash`.

#### Release note
```release-note
Distinguish pods with restartable init containers from pods with regular init containers when computing PodGroup role hashes.
```
