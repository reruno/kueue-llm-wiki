#### What this PR does / why we need it?
When `kueuectl list pods --for pod/NAME` resolves a Pod group whose name is identified by the `kueue.x-k8s.io/pod-group-name` annotation, print an actionable warning to stderr before querying the API server.

Kubernetes supports server-side filtering on label selectors but not annotation selectors. As a result, listing Pods for an annotation-based Pod group can require scanning every Pod in the selected namespace (or across all namespaces when `--all-namespaces` is used). Previously, the command gave no indication of this potentially broad scan.

With this PR:
1. When resolving Pods for an annotation-based Pod group (`o.PodAnnotationSelector != nil`), `printAnnotationScanWarning()` is called before issuing the broad Pod list request to the API server.
2. The warning explains that Kubernetes cannot filter Pods by annotation on the server, identifies the effective scan scope (current namespace or across all namespaces), and advises how to narrow the scan using `--namespace` or `--selector` when applicable:
   - For all namespaces without selector: `warning: Kubernetes cannot select Pods by annotation on the server. Scanning all Pods across all namespaces; use --namespace or --selector to narrow the search.`
   - For all namespaces with selector: `warning: Kubernetes cannot select Pods by annotation on the server. Scanning Pods across all namespaces; use --namespace to narrow the search.`
   - For a single namespace without selector: `warning: Kubernetes cannot select Pods by annotation on the server. Scanning all Pods in the <namespace> namespace; use --selector to narrow the search.`
   - For a single namespace with selector: `warning: Kubernetes cannot select Pods by annotation on the server. Scanning Pods in the <namespace> namespace.`
3. Label-based Pod groups (`kueue.x-k8s.io/pod-group-name` label) and standalone Pods remain completely silent and unchanged.
4. Comprehensive unit tests added in `cmd/kueuectl/app/list/list_pods_test.go` covering all warning variations and ensuring existing label-based and standalone test cases remain unaffected.

Fixes #18162

## AI summary

`kueuectl list pods --for pod/NAME` now writes a warning to stderr before it lists Pods for an annotation-based Pod group. The warning states that Kubernetes cannot select Pods by annotation on the server. It names the scan scope and suggests a way to narrow the request. The command still returns the full group by filtering the listed Pods client-side. Label-based groups and standalone Pods produce no warning and keep their current output.

The warning text depends on the flags:

- With `--all-namespaces` and no label or field selector, the warning says all Pods across all namespaces are scanned. It suggests omitting `--all-namespaces` and using `--namespace` or `--selector`.
- With `--all-namespaces` and a label or field selector, the warning says Pods across all namespaces are scanned after the server-side selectors apply.
- Without `--all-namespaces` and no selector, the warning names the namespace and suggests `--selector`.
- Without `--all-namespaces` and with a selector, the warning names the namespace only.

### Suggested release note

CLI: Added a stderr warning for `kueuectl list pods --for pod/NAME` when the Pod group is identified only by the `kueue.x-k8s.io/pod-group-name` annotation. Kubernetes cannot select Pods by annotation, so the command lists Pods in the namespace or across all namespaces and filters them client-side. The warning names the scan scope and suggests `--namespace` or `--selector` to narrow the search.
