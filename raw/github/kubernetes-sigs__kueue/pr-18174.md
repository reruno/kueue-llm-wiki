#### What this PR does / why we need it?

## Why

Annotation-based Pod groups cannot be filtered by the Kubernetes API. `kueuectl list pods --for pod/NAME` therefore lists Pods in scope and filters them client-side, which can be unexpectedly expensive in large namespaces.

## What

Add a warning before the client-side scan. It reports the namespace scope and supplied label or field selectors, and suggests how to narrow the request further.

Related: #18162

#### Useful notes for your reviewer

- The selected Pods are unchanged.
- Label-based Pod groups and standalone Pods do not emit the warning.
- Tests cover namespace-scoped and all-namespaces scans, label selectors, field selectors, JSON output, and empty results.
- AI assistance was used to prepare the implementation, tests, and this PR description.

#### Release note

```release-note
CLI: `kueuectl list pods --for pod/NAME` now warns when the Pod group is identified by an annotation and the command must list Pods in the group's namespace and filter them client-side. With `--all-namespaces`, the command now lists only that namespace, so Pods of same-named groups in other namespaces are no longer included.
```
