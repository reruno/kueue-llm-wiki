#### What type of PR is this?

#### What this PR does / why we need it?
This PR fixes two installation and startup failures with `manifests-alpha-enabled.yaml`:

1. **Alpha CRDs missing**:
   `config/alpha-enabled/kustomization.yaml` only referenced `../default`, which builds the base (beta/stable) CRDs. The alpha-level CRDs (`DynamicQuotaOrchestrator`, `CapacityProvider`, `PreemptionConfig`) located in `config/components/crd/alpha` were omitted from `manifests-alpha-enabled.yaml`.
   Added `- ../components/crd/alpha` to `config/alpha-enabled/kustomization.yaml` so that alpha CRDs are rendered.

2. **Controller startup failure on conflicting feature gates**:
   In Kubernetes 1.37+, `GenericWorkload` graduated to Beta (`PreRelease: featuregate.Beta`, `Default: false`). However, its dependent features (`WorkloadWithJob`, `CompositePodGroup`, `TopologyAwareWorkloadScheduling`, and `PodGroupPreemptionPolicy`) remain Alpha.
   Because `AllAlpha=true` only enables gates with `PreRelease: featuregate.Alpha`, setting `--feature-gates=AllAlpha=true` in `config/alpha-enabled/manager_config_patch.yaml` enabled the dependent alpha features while leaving `GenericWorkload` disabled. This caused `kueue-controller-manager` to immediately crash on startup with:
   ```text
   featureGates: Invalid value: "AllAlpha=true": [WorkloadWithJob is enabled, but depends on features that are disabled: [GenericWorkload], CompositePodGroup is enabled, but depends on features that are disabled: [GenericWorkload], TopologyAwareWorkloadScheduling is enabled, but depends on features that are disabled: [GenericWorkload], PodGroupPreemptionPolicy is enabled, but depends on features that are disabled: [GenericWorkload]]
   ```
   Updated `manager_config_patch.yaml` to `--feature-gates=AllAlpha=true,GenericWorkload=true`.

3. **Unit Test**:
   Added `TestAllAlphaFeatureGates` in `pkg/config/validation_test.go` verifying that `AllAlpha=true,GenericWorkload=true` passes feature gate validation.

Fixes #18181

Hi @kannon92 and @mimowo, thanks for the reviews!

1. @kannon92 I have amended the commit message to remove `Fixes` and force-pushed to address the Prow check.

2. Regarding `GenericWorkload`:
In Kueue's controller manager, feature gates are registered in `utilfeature.DefaultMutableFeatureGate` which incorporates both Kueue-defined feature gates and imported Kubernetes scheduler feature gates (`k8s.io/kubernetes/pkg/features`).

In Kubernetes 1.37+, `GenericWorkload` graduated to **Beta** (`default: false`), while dependent features (`WorkloadWithJob`, `CompositePodGroup`, `TopologyAwareWorkloadScheduling`, and `PodGroupPreemptionPolicy`) remain **Alpha**.

When `manager_config_patch.yaml` specifies `--feature-gates=AllAlpha=true` alone:
- `AllAlpha=true` enables all Alpha gates, turning on `CompositePodGroup=true`, `TopologyAwareWorkloadScheduling=true`, etc.
- `AllAlpha=true` does **not** enable Beta gates, so `GenericWorkload` remains `false`.
- On startup, `LoadAndValidateFeatureGates` validates feature gate dependencies and fails with:
  `feature "CompositePodGroup" requires feature "GenericWorkload" to be enabled`
  crashing the controller-manager immediately on boot.

Setting `--feature-gates=AllAlpha=true,GenericWorkload=true` satisfies the prerequisite for those alpha features, enabling the alpha manifests to boot cleanly.

### Comment by [@pajakd](https://github.com/pajakd) — 2026-11-03T08:36:13Z

> I see, in that case what about enabling also AllBeta? The current enablement of GenericWorkload seems ad hoc

Yeah, I think `AllBeta=true` will protect us against any future breakage like this.

But still `AllBeta=true, AllAlpha=true` will not boot (I think) because some Alpha features of kueue conflict each other. 
We have `DisableWaitForPodsReady` and `WaitForPodsReadyUnscheduledTimeout` (both Alpha) and they cannot be both enabled see the validations here: https://github.com/kubernetes-sigs/kueue/blob/8d855b16e3d21d6765d094af5884fec8203e3bb8/pkg/config/validation.go#L281-L288

The `DisableWaitForPodsReady` will be removed in 0.21 but for now I think we have to disable it here. So, `--feature-gates=AllAlpha=true,AllBeta=true,DisableWaitForPodsReady=false` should work IMO.
