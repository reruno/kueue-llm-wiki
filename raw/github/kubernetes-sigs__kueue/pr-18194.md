#### What this PR does / why we need it?

Backports #16339 to `release-0.20` as an opt-in Alpha feature.

With `TASResidualPodAccounting` enabled, TAS continues accounting for bound Pods after their Workloads release quota. Scheduling waits for existing eviction/deactivation cleanup instead of preempting unrelated Workloads when releasing those Pods would make the assignment feasible. This includes staged and consecutive releases of multiple preemption victims, partial admission, and elastic predecessor accounting.

The feature is Alpha and **disabled by default** on this release branch, and requires `TopologyAwareScheduling`. Leaving the new gate disabled preserves reservation-only accounting.

Related: #16337. Backport of #16339.

#### Useful notes for your reviewer

This is a release-specific adaptation, not a mechanical cherry-pick:

- Uses the existing release-0.20 native planner and scheduler-library integration.
- Adapts the existing scheduler signatures, explicitly enables the Alpha gate in behavior tests, and retains gate-off regression coverage.
- Updates generated feature-gate references and documents the Alpha/default-off behavior.
- Does not backport the unrelated failed-node replacement changes from #15263.
