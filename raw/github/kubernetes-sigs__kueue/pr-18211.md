#### What this PR does / why we need it?

Adds the alpha, disabled-by-default `MultiKueueClusterNames` feature gate and the `kueue.x-k8s.io/multikueue-cluster-names` annotation. When enabled, the annotation is copied from Jobs to Workloads and restricts nomination to the intersection of the requested worker clusters and those authorized by the Workload's MultiKueueConfig. A request with no authorized clusters remains unscheduled.

This supports callers that know where their checkpoint data resides and need to dispatch a job to that cluster.

Related: #14539 and #14540.

#### Useful notes for your reviewer

This draft cherry-picks only annotation commit `fd15af8ff9c83c1b5ece73279edb46e9ade448bb` from the closed combined validation PR #17945 onto upstream main at `baa52c3c08aef0485c3d523ef743e29412d36944`, as one commit. The job-framework conflict was resolved by retaining main's WaitForPodsReady parsing alongside annotation propagation. The Ray slice repoint fix from the combined PR is excluded.

The earlier annotation port #16741 is closed without merging. This is a fresh draft for CI validation on current main; the design discussion remains in #14539.

The source patch's dispatcher behavior is retained: an annotation overrides nominations. Compatibility with Incremental and External dispatchers still needs follow-up before merging because those dispatchers independently own nomination decisions. The integration scenario covers AllAtOnce.
