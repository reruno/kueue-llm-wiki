#### What this PR does / why we need it?

validateCreateForMaxExecTime accepted any positive value of the kueue.x-k8s.io/max-exec-time-seconds label that fits in an int, while MaximumExecutionTimeSecondsForObject parses the label as a 32-bit value. A value above 2147483647 therefore passed the webhook and was then dropped by the reader, so the Workload got no maximumExecutionTimeSeconds.

Jobs created with such a label before this fix were silently running with no execution time limit.

This PR keeps strconv.Atoi and adds an explicit check that rejects values above math.MaxInt32, with a comment explaining why (the reader parses the label as 32-bit, and Workload.spec.maximumExecutionTimeSeconds is an int32).

Fixes #18217
