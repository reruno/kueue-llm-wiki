#### What this PR does / why we need it?

`issueMigration` evicts the migration victim on every scheduling cycle, even when the victim is already evicted. Each eviction is a loose SSA apply built from the scheduler snapshot, with no resourceVersion. It bumps `schedulingStats.evictions`, so the ConcurrentAdmission controller's "Parent has no quota, clearing variant admission" write fails with a conflict, and when that clear does land, the next eviction from a stale snapshot puts `status.admission` back. In the failing runs this repeats about 80 times per second until the spec times out, and the Parent is never admitted again.

`issueMigration` now returns before `Evict` when the victim is already evicted, the same way `IssuePreemptions` treats an evicted preemption target. The entry still gets `RequeueReasonPendingMigration` and the "Pending the migration" message, so it keeps waiting for the migration.

#### Useful notes for your reviewer

- The new `TestScheduleConcurrentAdmission` case fails without the change in `scheduler.go`, because the eviction count goes from 1 to 2. With a sleep injected in `issueMigration`, the flaking spec failed 10 of 10 runs before the change and passed 10 of 10 after. Without the injection it passed 20 of 20 runs after the change.
- Passing runs hit the same loop for a short time too, so the change also removes the repeated `EvictedDueToFlavorMigration` events and eviction metric increments.
