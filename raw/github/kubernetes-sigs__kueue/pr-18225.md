#### What this PR does / why we need it?

  I realized this `.mu` is actually out of scope of this PR:
  
  - it's orthogonal to its main goal (replacing non-recommended builders with recommended ones)
  - it's _essentially unnecessary_ for now (as currently `NewSimulator` is only called once per Kueue scheduling cycle, when building the snapshot)
  - yet, some risk exists already (e.g. `Dumper.DumpAll()` might snapshot concurrently after the user sends SIGUSR2), and more scenarios like this could appear
    (OTOH, in the `newDumper` scenario, an even better mitigation would be to skip building the WAS snapshot...)
  
  So for now I'm moving `.mu` and related test changes (including addressing your comment here) to a follow-up, #19657.
  This will allow us reconsidering if `.mu` is the good direction.
