#### What this PR does / why we need it?

A manager workload that reserves quota before any worker cluster is connected is never dispatched. It keeps the quota with the MultiKueue admission check `Pending` indefinitely. A common trigger is a manager restart where the scheduler admits workloads before the worker clients finish connecting.

1. The workload reconciler only sees connected clusters. With no connected cluster, the `AllAtOnce` dispatcher nominates nobody and returns without requeueing.
2. On the worker's first connection, the cluster reconciler does not resync. The resync after #16175 only runs on reconnects.
3. Even on a reconnect, the resync only requeues workloads whose `clusterName` or `nominatedClusterNames` contain the worker, and this workload has neither.

The workload only recovers when some unrelated event touches it.

This PR:
- resyncs on the first connection to a worker as well as on reconnects;
- also requeues workloads that hold quota, are not finished, have a pending admission check, and have no nominated or assigned cluster.

#### Useful notes for your reviewer

- The resync lists Workloads from the manager's cache once per connection and only enqueues matching workloads, so its cost at startup is small.
- Overlap: #18117 also calls `requeueWorkloadsForCluster` (when a single watch is re-opened in place); it doesn't change this path.
- Tests:
  - Unit: `TestResyncOnConnect` covers first connect and reconnect, plus the cases that must not be enqueued.
  - Integration (`reconnect_test.go`): a workload that reserved quota while every worker was disconnected is dispatched after a reconnect, and one that reserved quota before the worker's first connection is dispatched after that connection. Both specs fail without the fix.
- Reproduced on kind with upstream main 228b92a71 (manager + worker, worker reached through a proxy that delays every request; restart the manager while pending jobs get quota):
  - Without the fix: 4 workloads stayed `QuotaReserved=True`, admission check `Pending`, no nomination and no remote workload, for more than 20 minutes.
  - With the fix: all 4 were dispatched and admitted about 3 seconds after the worker connected.
- This PR was prepared with AI assistance (Claude Code). I reviewed the changes and the test results.

#### Release note

```release-note
MultiKueue: Fixed a bug where a workload that reserved quota before any worker cluster was connected, for example right after the manager restarted, was never dispatched and kept its quota with the admission check Pending.
```
