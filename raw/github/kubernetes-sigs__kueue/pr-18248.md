#### What this PR does / why we need it?

RayCluster, RayJob and RayService each implement `CustomEquivalenceOptions` and `CanDefaultManagedBy` with the same body copied three times:

- `CustomEquivalenceOptions` returns `equality.WithIgnoreTopologyIndexLabels()` unless `KubeRayEvictOnInconsistentTopologyRequest` is enabled.
- `CanDefaultManagedBy` returns true when MultiKueue is enabled and `spec.managedBy` is unset or set to the KubeRay controller.

This PR moves both bodies into the `raycluster` package, which RayJob and RayService already import for their shared RayCluster logic:

- `raycluster.EquivalenceOptions()`
- `raycluster.CanDefaultManagedBy(managedBy *string)`

Each job type's method now calls the shared helper. The three job types can no longer drift apart, for example when `KubeRayEvictOnInconsistentTopologyRequest` graduates and the relaxed comparison is removed.

No behavior change.

#### Useful notes for your reviewer

Existing tests already cover both helpers: `raycluster_controller_test.go` covers the equivalence option with the gate on and off, and the three Ray webhook tests cover `managedBy` defaulting.
