(<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17835">#17835</a>, <a href="https://github.com/mimowo"><code>@​mimowo</code></a>)</p>
</li>
</ul>
<h2>Changes by Kind</h2>
<h3>Bug or Regression</h3>
<ul>
<li>CLI: Fixed the usage line of <code>kueuectl delete workload</code> to show that it accepts multiple names, that names and <code>--all</code> are mutually exclusive, and that <code>--all-namespaces</code> works only with <code>--all</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17924">#17924</a>, <a href="https://github.com/mbobrovskyi"><code>@​mbobrovskyi</code></a>)</li>
<li>DRA: Fixed a bug where CEL device availability checks counted devices from stale or incomplete ResourceSlice pools, so a Workload could reserve quota for devices the DRA allocator cannot use. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17706">#17706</a>, <a href="https://github.com/junnhwan"><code>@​junnhwan</code></a>)</li>
<li>DRA: Fixed a bug where Workloads whose device requests come from LimitRange defaults stayed pending after a matching DeviceClass was created. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17864">#17864</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>DynamicQuotaOrchestrator: Prevent stale CapacityProvider synchronization status from driving effective-capacity computation after provider specification updates. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17709">#17709</a>, <a href="https://github.com/Om-Beast"><code>@​Om-Beast</code></a>)</li>
<li>ElasticJobsViaWorkloadSlices: Fixed a bug where <code>WaitForPodsReady</code> could treat an elastic batch Job as not ready while a replacement Workload slice was pending admission. Kueue now evaluates readiness against the granted replica count in the latest admitted slice. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17816">#17816</a>, <a href="https://github.com/mszadkow"><code>@​mszadkow</code></a>)</li>
<li>ElasticJobsViaWorkloadSlices: Fixed a bug where an admitted elastic Workload could be evicted with <code>PodsReadyTimeout</code> while its scale-up Workload slice waited for quota, even after its Pods became ready. Kueue now updates <code>PodsReady</code> on the admitted Workload slice. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17765">#17765</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
<li>ElasticJobsViaWorkloadSlices: Fixed a bug where, with <code>SchedulingEquivalenceHashing</code> enabled, a replacement workload slice that fits could be deferred because another replacement slice with the same requests did not fit. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17682">#17682</a>, <a href="https://github.com/Narwhal-fish"><code>@​Narwhal-fish</code></a>)</li>
<li>FairSharing: Fixed a bug where a workload could be blocked from reclaiming its parent Cohort's nominal quota when that Cohort's DominantResourceShare was inflated by borrowing on an unrelated flavor. The nominal-quota preemption claim is now evaluated at the level where the preemptor's and target's subtrees meet, so descendants of a Cohort get preferential access to the Cohort's own nominal quota, and a ClusterQueue within its own nominal quota no longer preempts across a borrowing parent Cohort. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17798">#17798</a>, <a href="https://github.com/amitaekbote"><code>@​amitaekbote</code></a>)</li>
<li>Job integrations: Fixed a bug where a job created right after its namespace could stay suspended without a Workload until the next informer resync. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17843">#17843</a>, <a href="https://github.com/Narwhal-fish"><code>@​Narwhal-fish</code></a>)</li>
<li>KueueViz: Fixed a bug where the workloads dashboard, cohort, ClusterQueue, and ResourceFlavor websockets could push live updates when a related resource changed, even if the caller lacked cluster-wide watch permission for that resource. Callers without that permission still receive the initial snapshot filtered by their list permissions. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17755">#17755</a>, <a href="https://github.com/HarshithaMS005"><code>@​HarshithaMS005</code></a>)</li>
<li>KueueViz: Fixed the workload owner reference always showing &quot;N/A&quot;. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17667">#17667</a>, <a href="https://github.com/onkar717"><code>@​onkar717</code></a>)</li>
<li>MultiKueue &amp; LeaderWorkerSet: Fixed a bug where finishing, preempting, or scaling down one group of a LeaderWorkerSet deleted the LeaderWorkerSet on the worker cluster, stopping and recreating the other groups still running there. Kueue now deletes the remote LeaderWorkerSet only after its last group is removed from the worker. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17644">#17644</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>MultiKueue: Fix a bug where a gated manager Pod kept the status copied from the worker Pod after its workload was evicted on the worker and requeued. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17738">#17738</a>, <a href="https://github.com/marina-gonzalez-alvarez"><code>@​marina-gonzalez-alvarez</code></a>)</li>
<li>MultiKueue: Immediately resynchronize workloads when a worker watch reconnects instead of waiting for the next polling interval. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17845">#17845</a>, <a href="https://github.com/Kunal241207"><code>@​Kunal241207</code></a>)</li>
<li>Observability: Fixed a bug where, with the <code>CustomMetricLabels</code> feature gate enabled and a custom label taken from Workloads, a Workload deleted or relabeled right after admission could keep its stored label values in memory, or leave <code>kueue_admitted_active_workloads</code> and <code>kueue_local_queue_admitted_active_workloads</code> at -1 for its old label values and +1 for the new ones. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17868">#17868</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>RayCluster: Added the Alpha RayClusterHeadPodReady feature gate, disabled by default. Enable it to use head readiness for PodsReady checks so unready workers do not block readiness of a usable head. Enabling this feature requires KubeRay v1.3.0 or later. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17603">#17603</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
<li>Scheduler: Fixed a bug where a PodSet total past the largest Quantity was stored in <code>resourceUsage</code> as MaxInt64. The cache then under-counted that usage, and an even Pod count made the admission webhook reject the Workload on every retry. Kueue now records a total that fits in a Quantity, and sets <code>QuotaReserved=False</code> with reason <code>UnrecordableResourceUsage</code> when the total cannot be stored. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17665">#17665</a>, <a href="https://github.com/HarshithaMS005"><code>@​HarshithaMS005</code></a>)</li>
<li>TAS: Fix feasible elastic Workload slice replacements being rejected during preemption because the predecessor's topology usage was counted twice. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17792">#17792</a>, <a href="https://github.com/gola"><code>@​gola</code></a>)</li>
<li>TAS: Fixed a bug that could prevent grouped PyTorchJob and JobSet pods submitted through AppWrapper from receiving index-based topology placement when no pod index offset was set. Kueue now applies the default offset. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17954">#17954</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>TAS: Fixed a bug where Pods of Kubeflow Jobs (v1), such as PyTorchJob, and of MPIJobs without <code>runLauncherAsWorker</code> in a <code>kueue.x-k8s.io/podset-group-name</code> PodSet group were ungated without rank ordering, and the topology ungater logged an error on every reconcile. Kueue now sets <code>kueue.x-k8s.io/pod-index-offset: &quot;0&quot;</code> on their grouped Pod templates when it starts the job. This applies to workloads admitted after the upgrade. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17730">#17730</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>TAS: Fixed a bug where Pods of a TrainJob in a <code>kueue.x-k8s.io/podset-group-name</code> PodSet group were ungated without rank ordering, and the topology ungater logged an error on every reconcile. Kueue now sets <code>kueue.x-k8s.io/pod-index-offset: &quot;0&quot;</code> on these Pods when it starts the TrainJob. This applies to workloads admitted after the upgrade. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17871">#17871</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>TAS: Fixed a bug where a Workload with multiple PodSets reported an empty (Pending) QuotaReserved reason when one PodSet needed preemption for quota and another failed topology placement even on an empty cluster. The topology failure is now reported as TopologyPlacementFailed. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17617">#17617</a>, <a href="https://github.com/mimowo"><code>@​mimowo</code></a>)</li>
<li>TAS: Fixed a bug where an MPIJob with <code>runLauncherAsWorker</code> that set <code>kueue.x-k8s.io/pod-index-offset</code> alongside <code>kueue.x-k8s.io/podset-group-name</code> was admitted but never started, while holding quota. Kueue now accepts <code>&quot;1&quot;</code>, which matches the offset implied by the PodSet group, and rejects other values; remove the annotation from existing MPIJobs that use another value. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17666">#17666</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>TAS: Fixed a bug where the <code>Active</code> condition message of a ClusterQueue listed TAS flavors without a Topology in a random order, which could cause repeated status updates of the ClusterQueue. The flavors are now listed in name order. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17913">#17913</a>, <a href="https://github.com/spicysharkco"><code>@​spicysharkco</code></a>)</li>
<li>TAS: Fixed a bug where the pending message of a Workload with several PodSets that could not be placed could name a different PodSet in each scheduling cycle. Kueue now reports the first failed PodSet in alphabetical order. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17624">#17624</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
</ul>
