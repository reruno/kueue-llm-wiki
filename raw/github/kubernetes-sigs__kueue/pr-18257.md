<blockquote>
<h2>v0.169.0</h2>
<p>The main motivation behind this release is to get out a build with <a href="https://github.com/golang/go/issues?q=milestone%3AGo1.27.3+label%3ACherryPickApproved">Go 1.27.3</a>, which blocks trust in a small set of intermediate certificates due to specific security concerns around their operation. See the <a href="https://go.dev/blog/emudhra-incident">eMudhra incident</a> for more information. This affects Hugo features that fetch remote resources over HTTPS, e.g. <code>resources.GetRemote</code>.</p>
<p>This release also contains some security hardening of the template functions and menu entries that can render content as HTML (see below), a deprecation of looking up reserved front matter fields via <code>.Params</code> (also below), a faster and more robust <code>plainify</code>, and a set of bug fixes.</p>
<h2>Security notes</h2>
<p>Templates are trusted in Hugo, but content (including front matter) is not necessarily. This release tightens a few places where values from content could end up rendered as unescaped HTML:</p>
<ul>
<li><code>pre</code> and <code>post</code> values in menu entries defined in <strong>front matter</strong> are now HTML escaped, unless <code>text/html</code> is allowed in <a href="https://gohugo.io/configuration/security/"><code>security.allowContent</code></a>, which already marks HTML in <code>/content</code> as trusted. A warning (<code>warning-menu-pre-post-html-escaped</code>) is logged when a value containing HTML markup is escaped. Menu entries defined in the project configuration are not affected. f63482bf</li>
<li><code>emojify</code> and <code>plainify</code> now return a <code>string</code> unless the input is <code>template.HTML</code>, in which case the result is also <code>template.HTML</code>. Previously both always returned <code>template.HTML</code>, so e.g. <code>{{ .Title | emojify }}</code> would mark a potentially unsafe title as safe HTML. If you relied on the old behavior with trusted input, pipe the result through <code>safeHTML</code>. Thanks to <a href="https://github.com/Reload3d"><code>@​Reload3d</code></a> for reporting this. <a href="https://redirect.github.com/gohugoio/hugo/issues/15452">#15452</a></li>
</ul>
<h2>Deprecations</h2>
<p>Reserved front matter fields such as <code>title</code>, <code>date</code> and <code>summary</code> are currently also stored in <code>.Params</code>. Lookups such as <code>.Params.title</code> (and <code>ByParam &quot;title&quot;</code>, <code>where .Pages &quot;Params.title&quot; ...</code> etc.) are now redirected to the corresponding <code>Page</code> method and logged as deprecated, unless the field was set in the <code>params</code> section of front matter. The content of <code>.Params</code> is unchanged for now. 53e1fef9</p>
