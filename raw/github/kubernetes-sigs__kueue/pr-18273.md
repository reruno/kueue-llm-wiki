#### What this PR does / why we need it?

Manual cherry-pick of #18248 to `release-0.19` (the `release-0.20` cherry-pick is #18262).

RayCluster, RayJob and RayService each had identical copies of the `CustomEquivalenceOptions` and `CanDefaultManagedBy` bodies. This moves them to `raycluster.EquivalenceOptions` and `raycluster.CanDefaultManagedBy`, so the three job types cannot drift apart. Keeping `release-0.19` aligned with `main` also makes future Ray backports apply cleanly.

No behavior change.

I resolved it by keeping only the two new helpers. The resulting diff matches #18248 (4 files, +25/−21).
