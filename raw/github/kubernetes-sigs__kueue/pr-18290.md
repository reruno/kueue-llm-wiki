#### What this PR does / why we need it?

Adapt PR #16035 for `release-0.19` so trusted sidecar scrapers can collect metrics without ServiceAccount bearer tokens. As suggested in https://github.com/kubernetes-sigs/kueue/pull/16035#issuecomment-6463550479, this backport omits the ConfigAPI changes and uses a disabled-by-default alpha feature gate to opt out directly:

```yaml
featureGates:
  DisableMetricsAccessControl: true
metrics:
  bindAddress: "127.0.0.1:8443"
```

HTTPS remains required. Enabling the gate requires a literal loopback IP and numeric port from 1 to 65535; wildcard addresses, hostnames, non-loopback IPs, and port zero fail validation. `metrics.bindAddress: "0"` still disables metrics. With the gate disabled, existing authentication and authorization remain in effect.

Related: #16029, #16035.

#### Useful notes for your reviewer

- Target branch: `release-0.19`. The latest published patch is v0.19.11; the intended next patch is v0.19.12, subject to merge and release timing.
- Adapted from commit `305afc31719f9b7b3fc637f149650201c9a56295`. This is a manual backport because the requested gate-only interface differs from main.
- No configuration API fields or dependencies change. The new alpha gate is registered for 0.19 and defaults to false.
- The startup warning and sidecar guide explain shared-network-namespace access. The guide includes external serving certificates, TLS verification, and upgrade instructions.
- Before upgrading to v0.21, remove `DisableMetricsAccessControl` and use `MetricsAccessControl: true` with `metrics.accessControlMode: None`. The old gate is not recognized by v0.21.

- Existing release-0.19 unit, integration, and cert-manager E2E presubmits select the new tests. Integration covers verified HTTPS responses 200/401/403; E2E covers anonymous sidecar scraping, Pod-IP connection refusal, and restoration of authenticated scraping.

#### Release note

```release-note
Observability: Added the alpha DisableMetricsAccessControl feature gate (disabled by default) to allow trusted sidecars to scrape HTTPS metrics without authentication or authorization on an explicit loopback IP and port. The default authenticated behavior is unchanged. Before upgrading to v0.21, remove this backport-only gate and use MetricsAccessControl with metrics.accessControlMode: None instead.
```
