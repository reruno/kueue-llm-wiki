#### What this PR does / why we need it?

`kind-k8s-main-image-build` builds the node image for `test-e2e-k8s-main-was` from the latest k/k CI build. `kind build node-image` downloads `kubernetes-server-linux-amd64.tar.gz` from `dl.k8s.io` once and does not retry. A dropped connection (`unexpected EOF`) then fails the job before any spec runs. The `curl -sL` that reads `ci/latest.txt` has no retry either. Without `-f`, it also returns an HTTP error body as the version string.

Wrap `kind build node-image` in `NETWORK_RETRY`, the helper the kubectl download in `hack/make/deps.mk` already uses. Fetch `latest.txt` through `hack/testing/retry.sh` with `curl -fsSL` and without `--stream`, because `$(shell ...)` needs the captured stdout. This is the same form as the envtest lookup at the top of `hack/make/test.mk`. `hack/testing/e2e-common.sh` already retries both steps the same way: `build_kind_node_image` wraps `kind build node-image` in `retry.sh --stream`, and `e2e_download_url` wraps `curl -fsSL` in `retry.sh`. This target was the one place that did not.

The new `verify-kind-k8s-main-image-build` check runs `hack/testing/kind-k8s-main-image-build_test.sh`. The test runs the real target with two fake commands. On its first call, `curl` returns a 503 page and `kind` fails with `unexpected EOF`. The test asserts that the target calls each command twice and passes the right tarball URL to `kind`.
