#### What this PR does / why we need it?

Adapt PR #16035 for `release-0.20` so trusted sidecar scrapers can collect metrics without ServiceAccount bearer tokens. As suggested in https://github.com/kubernetes-sigs/kueue/pull/16035#issuecomment-6463550479, this backport omits the ConfigAPI changes and uses a disabled-by-default alpha feature gate to opt out directly:

```yaml
featureGates:
  DisableMetricsAccessControl: true
metrics:
  bindAddress: "127.0.0.1:8443"
```

HTTPS remains required. Enabling the gate requires a literal loopback IP and numeric port from 1 to 65535; wildcard addresses, hostnames, non-loopback IPs, and port zero fail validation. `metrics.bindAddress: "0"` still disables metrics. With the gate disabled, existing authentication and authorization remain in effect.

Related: #16029, #16035. Companion release-0.19 backport: #18290.

#### Useful notes for your reviewer

- Target branch: `release-0.20`. The latest published patch is v0.20.4; the intended next patch is v0.20.5, subject to merge and release timing.
- Adapted from commit `305afc31719f9b7b3fc637f149650201c9a56295`. This is a manual backport because the requested gate-only interface differs from main.
- No configuration API fields or dependencies change. The new alpha gate retains its 0.19 introduction version from the companion backport and defaults to false.
- Planned removal: v0.22, recorded beside the feature-gate declaration/spec and in the migration guide. The gate is intentionally limited to the release-0.19 and release-0.20 backports; no v0.21 compatibility alias is planned, so v0.21 upgrades must migrate configuration.
- The startup warning and sidecar guide explain shared-network-namespace access. The guide includes external serving certificates, TLS verification, and upgrade instructions.
- Before upgrading to v0.21, remove `DisableMetricsAccessControl` and use `MetricsAccessControl: true` with `metrics.accessControlMode: None`. The old gate is not recognized by v0.21.

#### Release note

```release-note
Observability: Added the alpha DisableMetricsAccessControl feature gate (disabled by default) to allow trusted sidecars to scrape HTTPS metrics without authentication or authorization on an explicit loopback IP and port. The default authenticated behavior is unchanged. Removal of this temporary gate is planned for v0.22. Before upgrading to v0.21, remove this backport-only gate and use MetricsAccessControl with metrics.accessControlMode: None instead.
```
