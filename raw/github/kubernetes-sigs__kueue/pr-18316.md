#### What this PR does / why we need it?

`pkg/controller/jobs/raycluster/common.go` had two private helpers that check whether a Ray job's `spec.managedBy` is MultiKueue:

- `isRayObjectManagedByMultiKueue` handles RayCluster, RayJob and RayService. `ValidateCreate` uses it for the in-tree autoscaling check.
- `isManagedByMultiKueue` handles RayJob and RayService. `UpdatePodSets` uses it when the child RayCluster is NotFound.

This PR keeps the documented `isManagedByMultiKueue`, adds the RayCluster case to it, and removes `isRayObjectManagedByMultiKueue`.

No behavior change. In production, `UpdatePodSets` is only called from the RayJob and RayService controllers, so the new RayCluster case is unreachable there. `ValidateCreate` gets the same result as before.
