## Description

Cherry pick of #13904 on release-0.19.

#13904: Resolve the LeaderWorkerSet priority class once on the update path

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

On this branch `jobframework.UpdateWorkloadPriority` keeps the single-Workload signature that v0.19.0 shipped, and the batch form is unexported (#13876). This PR adds `jobframework.UpdateWorkloadPriorities`, which calls the batch form, and the LeaderWorkerSet reconciler uses it. `UpdateWorkloadPriority` does not change.

The unit test conflict came from two missing-class cases that this branch does not have, so I left them out. This branch does not emit a `WorkloadPriorityClassNotFound` event, so the new case for a missing class checks only the queue update and the error.

_Disclosure: I used an AI coding assistant while preparing this PR. I reviewed and tested the change myself._

```release-note
LeaderWorkerSet: Fixed a bug where changing the `kueue.x-k8s.io/priority-class` label could give a LeaderWorkerSet's Workloads different priorities. Kueue now resolves the WorkloadPriorityClass once and also updates Workloads that already use the class but have an old priority value.
```
