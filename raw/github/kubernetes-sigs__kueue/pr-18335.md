#### What this PR does / why we need it?

`nominateAndSynchronizeWorkers` and `syncToSingleCluster` in the MultiKueue workload reconciler returned a `reconcile.Result`, but every return path produced an empty `reconcile.Result{}`, so `RequeueAfter` was never set. The caller in `reconcileGroup` still merged that unused result with `requeueAfterSynchronize` (set by the `MultiKueueOrchestratedPreemption` preemption-gate logic), which made the code harder to follow.

This PR makes both functions return only `error`, and `reconcileGroup` now returns `reconcile.Result{RequeueAfter: requeueAfterSynchronize}` directly. The behavior is unchanged: on error the result is still empty, and on success the requeue is still `requeueAfterSynchronize`, with `resetErr` passed through as before.

Related: #18320 (that PR changes the nomination requeue behavior and will be rebased onto this cleanup).

- No behavior change. The only test change is dropping the unused `reconcile.Result` in `TestNominateAndSynchronizeWorkers_MoreCases`.
