#### What this PR does / why we need it?

In `pull-kueue-verify-main`, root-module lint finishes about 2m15s after every other check. It is still capped at `GOMAXPROCS=2`, a limit that let it share the Pod's 7 CPUs with the CLI builds, which now run in `pull-kueue-build-cli-main`.
This PR adds `VERIFY_CI_LINT_GOMAXPROCS`, defaulting to 3, and applies it only to module lint, so generators and other checks keep `VERIFY_GOMAXPROCS`. Most of root-module lint (about 4m13s) is compiling packages with a cold Go build cache, which is the part that gains from more CPU.

| | Before (`GOMAXPROCS=2`) | After (`GOMAXPROCS=3`) |
|---|---:|---:|
| Prow: whole job | 8m16s | 7m06s |
| Prow: `verify-checks` | 7m16s | 6m12s |
| Prow: root-module lint | 5m26s | 4m25s |
| Prow: root-module linter peak memory (sampled) | 6.6 GB | 6.6 GB |
| Local: root-module lint, empty Go build cache | 3m13s | 2m30s |

Prow "before" is the median of 6 recent runs with the CLI split active. Prow "after" is a single run, [this PR's presubmit](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/18348/pull-kueue-verify-main/2118270124552097792), where lint finished 42s after the next check. Locally, `GOMAXPROCS=4` saved only 6 more seconds while using 21% more CPU, so the default is 3.
