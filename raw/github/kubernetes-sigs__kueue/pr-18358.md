#### What this PR does / why we need it?

In `pull-kueue-verify-main`, module lint runs two modules at a time in `git ls-files` order. Root-module lint, the last check to finish, waits about 22s for `cmd/experimental/webhook-conversion-repro` before it can start.
This PR sorts the module list so the root module starts first.

| | Unsorted (3 runs) | Sorted (2 runs) |
|---|---:|---:|
| Prow: whole job | 7m06s, 7m15s, 7m20s | 7m05s, 7m17s |
| Prow: `verify-checks` | 6m12s, 6m21s, 6m27s | 6m12s, 6m23s |
| Prow: root-module lint start delay | 22s, 23s, 23s | 0s, 0s |
| Prow: root-module package loading | 3m35s, 3m39s, 3m42s | 3m54s, 4m01s |
| Prow: root-module lint duration | 4m25s, 4m31s, 4m38s | 4m46s, 4m55s |
| Prow: root-module lint finish, from lint start | 4m47s, 4m54s, 5m01s | 4m46s, 4m55s |

All runs include the previous lint change. The unsorted runs are from [18348](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/18348/pull-kueue-verify-main/2118270124552097792), [18357](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/18357/pull-kueue-verify-main/2118313048052600832) and [18304](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/18304/pull-kueue-verify-main/2118317746411278336). The sorted runs are this PR's presubmits, [first](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/18358/pull-kueue-verify-main/2118314948495937536) and [second](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/18358/pull-kueue-verify-main/2118318087215255552).
Root-module lint no longer waits, but its package loading takes about 20s longer, so the job is not measurably faster: the median finish moves about 4s earlier, less than the 14s spread between unsorted runs. The change does keep root-module lint from queueing behind modules whose paths sort before it, including any added later.
Starting root-module lint earlier makes it overlap other module lint for about 150s instead of 105s, so I also compared memory. Locally, with empty caches and two runs per order, the peak RSS of the lint process tree was 3.54 and 3.21 GiB unsorted and 3.45 and 3.14 GiB sorted, and each peak came after the other modules had finished. Total lint time was 186s and 186s unsorted and 175s and 177s sorted. These local numbers are for comparing the orders only. Whole-Pod memory on Prow was not measured because its Prometheus endpoint does not serve queries.

> **Start the root module first explicitly. The sort does not guarantee it.**
> 
> `LC_ALL=C sort` orders directory names by byte value. Names whose first byte is below `.` (`0x2E`), such as `!scratch` or `#tools`, sort before the root module. Untracked, non-ignored module directories are included in the list, so a local checkout can contain such a module. With the default `CI_LINT_NPROCS=2`, root lint waits only when two such modules occupy both workers. With `CI_LINT_NPROCS=1`, one such module is enough to delay it. The comment above the recipe says the sort starts root first, which does not hold for these names.
> 
> Place the root module first explicitly:
>
