#### What this PR does / why we need it?
The `Generate SBOM` step of the release workflow fails, which blocks the v0.19.12 release:
https://github.com/kubernetes-sigs/kueue/actions/runs/42024365229/job/127234913402

```
Error: compiling policy: unable to parse a policy, group or policySet from data
```

`setup-bom` v0.4.4 verifies the downloaded `bom` binary with ampel v1.3.3, using the unpinned policy
`git+https://github.com/carabiner-dev/policies#sigstore/sigstore-dual-signatures.json`.
On 2026-11-05 that policy gained a `meta.name` field (carabiner-dev/policies PR 42).
ampel v1.3.3 cannot parse that field.
The upstream follow-up (carabiner-dev/policies PR 43) removed the field only from `signature/signature.json`, not from this policy.

This PR pins `setup-bom` to the current `release-actions` main (`3f8e1eb`), which verifies with ampel v1.3.10 (`carabiner-dev/policy` v0.5.5, which knows `meta.name`).
The latest tag, v0.4.5, still uses ampel v1.3.6 and fails the same way, so the pin is a commit SHA.

`bom-release: '0.7.1'` keeps the SBOM generator unchanged, because the newer `setup-bom` defaults to bom 0.8.0.
