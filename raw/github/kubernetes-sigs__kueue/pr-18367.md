## Description

#### What type of PR is this?

  /kind feature

  /area multikueue

  #### What this PR does / why we need it?

  Promotes the `MultiKueueClusterProfile` feature gate to beta, enabled by default in v0.21, following the beta criteria in the KEP-693 update (#18131).

  - Flips the gate default to `true` and regenerates the feature gate lists.
  - Sets the gate explicitly in the gate-off unit and integration tests, which relied on the alpha default.
  - Updates the MultiKueue setup guide: the gate is enabled by default, and installing the CRD while Kueue runs needs a restart.

  Picking up a ClusterProfile CRD installed after startup, without a restart, is a Beta criterion in the KEP. It goes in a separate PR so it can be cherry-picked; this PR should merge after it. Until then the setup guide documents the restart.

  Fixes #17133

  #### Useful notes for your reviewer

  Depends on the KEP update in #18131.

  | Behavior | Level | Command and result | Not run and why |
  |---|---|---|---|
  | Gate off: `MultiKueueCluster` with `clusterProfile` reports `MultiKueueClusterProfileFeatureDisabled` | unit | `go test ./pkg/controller/admissionchecks/multikueue/` (`TestUpdateConfig/cluster_profile_feature_gate_disabled`, gate now set explicitly):
  pass | |
  | Gate off: reason is reported by the running controller | integration | `make test-multikueue-integration INTEGRATION_TARGET_MULTIKUEUE=./test/integration/multikueue GINKGO_ARGS='--focus=ClusterProfile'` (gate now set explicitly in `BeforeEach`): pass
  | |
  | Gate default on: features and config packages | unit | `go test ./pkg/features/... ./pkg/config/...`: pass | |
  | Connecting through a ClusterProfile and a credential plugin | e2e | | Not run locally. The sequential MultiKueue e2e suite already sets the gate explicitly and is unchanged. |

  ```text
  Gate: MultiKueueClusterProfile
  Default: true
  PreRelease: Beta
  Version: 0.21
  Off-path test: TestUpdateConfig/cluster_profile_feature_gate_disabled (unit); "MultiKueue with ClusterProfile / Feature gate disabled" (integration)
  ```

  With the gate on by default, every install now reads the ClusterProfile CRD at startup. RBAC already allows `get` on `clusterprofiles.multicluster.x-k8s.io`. As stated in the KEP, kueue-controller-manager exits at startup when that CRD is installed but
  does not serve `v1alpha2`; the release note covers this.


  #### Release note

  ```release-note
  MultiKueue: Promoted the `MultiKueueClusterProfile` feature gate to beta and enabled it by default.

  ACTION REQUIRED: If the `clusterprofiles.multicluster.x-k8s.io` CRD is installed but does not serve `v1alpha2`, upgrade it to cluster-inventory-api v0.2.0 or later, or disable the `MultiKueueClusterProfile` feature gate, before upgrading Kueue.
  Otherwise kueue-controller-manager fails to start.
  ```
