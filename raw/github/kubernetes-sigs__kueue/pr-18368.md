#### What this PR does / why we need it?

Manual cherry-pick of #17386 (`baa52c3c08aef0485c3d523ef743e29412d36944`) into `release-0.20`.

RuntimeClass events made Kueue process every pending Workload, not only the Workloads that use the changed RuntimeClass. `queueReconcileForPending` appended a second `client.MatchingFields` option, which replaced the RuntimeClass field selector. The fix merges both field selectors into one `MatchingFields` option.

The automated cherry-pick #18340 failed `pull-kueue-test-unit-shard-0-release-0-20` and `pull-kueue-verify-release-0-20` (`verify-ci-lint`, `typecheck`) with the same build error:

```
pkg/controller/core/workload_controller_dra_test.go:1550:28: undefined: context
```

The new regression test uses `context.Context`. On `main`, `workload_controller_dra_test.go` already imported `context` from an earlier change that is not on `release-0.20`. This PR is the same cherry-pick plus that one import, squashed into a single commit. The controller change is identical to #17386.

Related: #17385
