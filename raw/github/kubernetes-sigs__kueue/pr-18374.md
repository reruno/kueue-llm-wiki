#### What this PR does / why we need it?

Manual cherry-pick of #17386 (`baa52c3c08aef0485c3d523ef743e29412d36944`) into `release-0.19`.

RuntimeClass events made Kueue process every pending Workload, not only the Workloads that use the changed RuntimeClass. `queueReconcileForPending` appended a second `client.MatchingFields` option, which replaced the RuntimeClass field selector. The fix merges both field selectors into one `MatchingFields` option.

The automated cherry-pick #18339 failed `pull-kueue-test-unit-shard-0-release-0-19` because `pkg/controller/core` did not build:

```
pkg/controller/core/workload_controller_dra_test.go:1194:28: undefined: context
pkg/controller/core/workload_controller_dra_test.go:1213:6: unknown field Namespace in struct literal of type reconcile.Request
```

The other failed checks on #18339 were aborted when the PR was closed; they did not fail.

The controller change is identical to #17386. This PR changes only the test, in two ways, squashed into a single commit:
- It adds the missing `context` import. On `main`, `workload_controller_dra_test.go` already imported `context` from an earlier change that is not on `release-0.19`.
- It writes the expected `reconcile.Request` values as `{NamespacedName: types.NamespacedName{...}}`. `reconcile.Request` embeds `types.NamespacedName`. Setting the promoted `Namespace` and `Name` fields directly in a composite literal compiles with Go 1.27, which `main` uses, but not with Go 1.26, which `release-0.19` uses. The `reconcile.Request` type is the same in the controller-runtime versions of both branches.

Related: #17385
