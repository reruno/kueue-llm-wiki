## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

Append `DisableMetricsAccessControl=false` to the alpha-enabled manager manifest on `release-0.20`. `AllAlpha=true` otherwise enables the metrics-authentication opt-out, which rejects the default wildcard metrics binding and prevents startup. The explicit override preserves authenticated HTTPS metrics while enabling the other alpha features.

Related: #18352.

#### Useful notes for your reviewer

- One-line manifest change. Retains the existing AllBeta=true and DisableWaitForPodsReady=false settings.
- Built `config/alpha-enabled` using the pinned Kustomize v5.8.1.
- Checked the rendered Deployment arguments using this branch's feature-gate registry and `config.MetricsServerOptions`: the original arguments fail the gate-off assertion; the updated arguments leave the gate disabled and preserve HTTPS and its authentication/authorization filter.
- Passed focused race tests: `go test -race -timeout 420s ./pkg/config -run '^Test(MetricsServerOptions|LoadAndValidateFeatureGates)$' -count=1` (using the installed macOS 26.5 SDK).
- Passed `git diff --check`.
- AI disclosure: This change and PR description were prepared with assistance from OpenAI Codex.

#### Release note

```release-note
Manifests: Keep metrics authentication and authorization enabled in the alpha-enabled manifest by explicitly setting DisableMetricsAccessControl=false, preventing metrics bind-address validation failures with AllAlpha=true.
```
