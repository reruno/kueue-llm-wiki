## Description

#### What type of PR is this?

/kind bug
/kind regression

#### What this PR does / why we need it?

Restore CRD conversion in v0.20 by registering the `v1beta1` Kueue types in the manager scheme during `cmd/kueue` initialization, while keeping the `v1beta1` API unserved.

#14558 removed the `v1beta1` scheme registration, but the five conversion-enabled CRDs and the certificate rotator still reference `/convert`. controller-runtime registers that endpoint only when the scheme contains convertible versions, so the manager returned 404 and kube-apiserver could repeatedly fail while filling its `v1beta1` watch cache.

This change is intentionally scoped to `release-0.20`. It preserves the existing migration contract and does not backport the larger `v1beta1` API removal from #16485.

Fixes #18391

#### Useful notes for your reviewer

| --- | --- | --- |
| `cmd/kueue` initialization registers `v1beta1`, and `TestSchemeConvertibleTypes` verifies that the real manager scheme reports ClusterQueue, Cohort, LocalQueue, MultiKueueCluster, and Workload as convertible. | unit | `go test ./cmd/kueue -run '^TestSchemeConvertibleTypes$' -count=1` and `go test -race ./cmd/kueue -run '^TestSchemeConvertibleTypes$' -count=1` passed. |

The per-kind conversion functions remain covered by `apis/kueue/v1beta1/*_conversion_test.go`. All `make verify` checks passed. ShellCheck used the pinned image from the local cache because Docker Hub failed while attempting to pull it again.

AI assistance disclosure: AI was used to implement the fix, add tests, update this description, and run validation. Reviewed by me.

#### Release note

```release-note
API: Fixed a bug where, after upgrading to v0.20, kube-apiserver repeatedly failed to initialize its watch cache for the ClusterQueue, Cohort, LocalQueue, MultiKueueCluster and Workload CRDs, because the Kueue manager no longer served the `/convert` conversion webhook that these CRDs still configure for the unserved `kueue.x-k8s.io/v1beta1` version.
```
