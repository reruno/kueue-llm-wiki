## Description

#### What type of PR is this?

  /kind cleanup

  /area multikueue
  /area testing

  #### What this PR does / why we need it?

  Adds an integration test where the ClusterProfile CRD is installed while kueue-controller-manager is running, as requested in https://github.com/kubernetes-sigs/kueue/pull/18404#discussion_r4494597047.

  The existing spec in #18404 only simulates a missing CRD with `WithClusterProfileCRDPresent(false)`. The shared integration clusters always have the CRD installed, so the API is already served when the manager starts.

  The new spec starts a dedicated control plane without the ClusterProfile CRD, so the shared clusters are not affected:

  1. Starts the manager with the `MultiKueueClusterProfile` gate enabled.
  2. Creates a `MultiKueueCluster` that references a ClusterProfile, and expects `BadClusterProfile` with "the ClusterProfile API is not served".
  3. Installs the ClusterProfile CRD and creates the ClusterProfile.
  4. Expects the `MultiKueueCluster` to be reconciled without a restart (`no access provider configured`).

  `createCluster` in the suite now delegates to `createClusterWithDepCRDs`, so a spec can choose which dependency CRDs to install. Existing callers are unchanged.

  Part of #17133. Follow-up to #18404.

  #### Useful notes for your reviewer

  The spec is in `test/integration/multikueue`, which the MultiKueue integration presubmit already runs. It adds one short-lived envtest control plane for this spec only.
