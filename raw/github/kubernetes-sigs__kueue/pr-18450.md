## Description

#### What type of PR is this?

  /kind bug

  /area multikueue

  #### What this PR does / why we need it?

  Manual cherry-pick of #18404 to release-0.20. The automated cherry-pick failed with a merge conflict in `multikueuecluster.go`.

  When the `MultiKueueClusterProfile` feature gate is enabled and the ClusterProfile CRD is installed after kueue-controller-manager starts, Kueue now starts watching ClusterProfiles without a restart.

  Differences from #18404:
  - release-0.20 uses ClusterProfile `v1alpha1`, so the new code uses `inventoryv1alpha1` instead of `inventoryv1alpha2`.

  Part of #17133.

  #### Useful notes for your reviewer

  Apart from the differences above, the patch matches #18404 line for line. See #18404 for the original tests.


  #### Release note

```release-note
MultiKueue: Fixed a bug where Kueue ignored a ClusterProfile CRD installed after kueue-controller-manager started, so `MultiKueueCluster` objects that use clusterProfileRef (alpha MultiKueueClusterProfile feature gate) stayed inactive until a restart.
```
