#### What this PR does / why we need it?

`TestMatchingLeavesCacheIsInvisible` checked only which node the Pods were placed on. With `TASRespectNodeAffinityPreferred` enabled, `n4` wins the placement whether its preferred affinity score is 10 or 20, so a score that was doubled on a matching-leaves cache hit would not have been caught.

This adds a `wantAffinityScores map[string]int64` field to the test cases and asserts that `n4`'s leaf has `affinityScore == 10` after each evaluation, with the cache both enabled and disabled. This checks that the score is restored once, not lost and not doubled.

Fixes #18432
