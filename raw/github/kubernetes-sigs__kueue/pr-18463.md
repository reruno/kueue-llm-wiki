## Description

Cherry pick of #18078 on release-0.20.

Manual backport; prow cherry-pick conflicted in
test/integration/singlecluster/controller/core/custom_labels_test.go.
Kept the new admitted-active gauge integration test and the release-0.20
Empty customLabels case; did not bring the main-only "cohort and workload
custom labels" When.

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

With CustomMetricLabels enabled, every series of
kueue_cohort_subtree_admitted_active_workloads for a Cohort carried the
whole subtree count, so summing a Cohort's series over-counted. Each
series now counts only ClusterQueues whose custom label values match.

#### Useful notes for your reviewer

I used an AI assistant to prepare this cherry-pick; I reviewed the
conflict resolution and test results.

#### Does this PR introduce a user-facing change?

```release-note
Observability: Fixed a bug that caused `kueue_cohort_subtree_admitted_active_workloads` to over-count when CustomMetricLabels was enabled. Each series now counts workloads only from ClusterQueues with matching custom label values.
```
