#### What this PR does / why we need it?

The release workflow builds the `kubectl-kueue` binaries (`make release-artifacts` on the runner's Go) right after `actions/setup-go` runs with `go-version-file: go.mod`. go.mod declares `go 1.27.0` (`go 1.26.0` on release-0.19) and has no `toolchain` line, so setup-go installs exactly that `.0` release. As a result, the published binaries miss every Go patch release after `.0`:

- v0.20.4 ([job log](https://github.com/kubernetes-sigs/kueue/actions/runs/40870032781/job/123434608760)): `Setup go version spec 1.27.0`, `go version go1.27.0 linux/amd64`. The latest 1.27 patch is 1.27.3.
- v0.19.11 ([job log](https://github.com/kubernetes-sigs/kueue/actions/runs/40868720324/job/123430127192)): `Setup go version spec 1.26.0`, `go version go1.26.0 linux/amd64`. The latest 1.26 patch is 1.26.10.

`check-latest: true` alone doesn't help, because the version spec read from go.mod is an exact patch. The SBOM action already sets `check-latest: true` and still logs `Resolved as '1.27.0'` in the same jobs.

This PR adds a step that reads the Go minor version from the checked-out go.mod. setup-go then gets `go-version: '<minor>.x'` with `check-latest: true`. The [setup-go docs](https://github.com/actions/setup-go/blob/b7ad1dad31e06c5925ef5d2fc7ad053ef454303e/README.md#supported-version-syntax) document `1.25.x` wildcards, and `check-latest` resolves the latest matching patch from the `actions/go-versions` manifest. Each release then builds with the latest patch of its own branch's Go minor, while go.mod and its `go` directive stay unchanged:

- `create-draft-release` checks the release tag out at the workspace root, and main only into `.automation`, so 0.19.x picks up 1.26.x and 0.20.x picks up 1.27.x.
- `create-release-candidate` checks out main at the root, so it picks up 1.27.x.
- The `generate-sbom` composite action gets the same change. It runs at the workspace root, both from `release-utils.yml` and from `sbom.yaml`.

The workflows run from main, so this one change covers releases from every branch. No `toolchain` line is added: it would need a manual bump on every branch for each Go patch, and setup-go's exported `GOTOOLCHAIN=local` makes later steps ignore it anyway.

#### Useful notes for your reviewer
