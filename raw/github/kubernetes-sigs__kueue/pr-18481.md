## Description

#### What type of PR is this?

A draft release that fails while producing OpenVEX or the SBOM still receives a success comment on the release issue. The workflow run is failed and that artifact is missing, but the comment does not say which step failed. Release-candidate creation can report an earlier step's success text when a later step fails. The failure comment is the first non-empty step output message.

Creating the draft stores a success message in that output, and the value is still set when OpenVEX or SBOM fails afterward, so the failure report posts it. The release-candidate expression reads the tag message before draft and publish, so a publish failure still surfaces the tag success message.

Generate OpenVEX and Generate SBOM now have step ids. The draft-release failure message checks the SBOM outcome, then OpenVEX, then the draft step, and the comment names the failed step, the version, and links to the workflow run. The release-candidate failure message checks publish, then draft, then tag, and uses a step's message only when that step's outcome is failure. Workflow tests assert the new ids, that check order, and the failure wording.

pytest -q hack/releasing/log_to_issue_test.py completed with all tests passing.
The tests passed with the kueue change applied; a run with it reverted gave no clear result, so no test is shown to catch this bug.

Fixes #18477
