#### What this PR does / why we need it?

Fixes the flaky `TestDeviceTaintsMatchUpstreamTracker` (seen as `device_name_only` on `periodic-kueue-test-unit-shard-1-release-0-20`), where the upstream tracker occasionally returned `gpu-0` without the rule's taint while Kueue's `applyRulesToSlice` returned it.

The cause is in `k8s.io/dynamic-resource-allocation/resourceslice/tracker` (v0.37.1), not in Kueue. `syncSlice` reads the rules, computes the patched slice and stores it without a lock. It is called from both the ResourceSlice handler and the DeviceTaintRule handler, which run on separate goroutines. When the two run at once, a sync that read the rules before the rule arrived can overwrite the patched slice that a sync that saw the rule just stored. The taint is then lost, and nothing re-syncs, so the tracker stays wrong after `HasSynced()` returns true.

The test now feeds the tracker the slices first and the rules afterwards, using two informer factories, so only the rule handler touches the slices once they are processed. The comparison against `applyRulesToSlice` is unchanged.

Fixes #18472
