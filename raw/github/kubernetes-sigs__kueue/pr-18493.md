#### What this PR does / why we need it?

This fixes a DRA-backed extended-resource accounting bug where transformed resources and logical DRA quota keys could be counted twice, or where a transformation output could be dropped incorrectly after exclude-resource filtering.

The root cause was in the workload accounting flow: resource transformations, excluded-resource filtering, and DRA logical charges were merged in the wrong order. In practice, this allowed:
- a DRA-backed extended resource to remain counted under both its original name and its logical quota key
- a transformed output to be removed when it recreated an excluded name
- a logical quota name collision to be validated incorrectly when the reserved-name gate was disabled

This patch fixes the accounting order so that:
- transformed outputs are treated as the final effective result
- excluded prefixes continue to remove only the original retained request, not a valid generated output
- the DRA logical charge is suppressed when a transformation consumes the original request
- real DRA logical-name collisions are still rejected when the feature is active, while preserving the legacy `pods` escape hatch when the validation gate is off

This change is limited to the DRA/transform accounting path and the config validation path, with regression tests covering the affected cases.
