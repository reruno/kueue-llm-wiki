#### What this PR does / why we need it?

Fixes #18416

In elastic SparkApplications with dynamic allocation, kueue holds the initial executor quota until all initial executors have been created. When an executor fails during ramp-up, Spark requests a replacement with a new monotonically increasing executor ID.

Because the created count was calculated as `max(j.recordedMaxExecutorID(), maxID)`, a failed executor caused `created` to reach `initialExecutors` prematurely while active executors remained below the initial count. This caused kueue to release the initial quota hold and clamp to `minExecutors` or the running count.

This PR tracks failed executor IDs in annotations (`kueue.x-k8s.io/spark-failed-executor-ids`) and subtracts them from `maxCreated` to reflect the actual number of working executors created during ramp-up.

#### Useful notes for your reviewer

Added test cases in `sparkapplication_controller_test.go` covering executor failure during ramp-up, failure after pod deletion, replacement executor allocation, and annotation recording.

#### Release note

```release-note
SparkApplication: maintain initial executor quota when an executor fails during ramp-up.
```
