#### What this PR does / why we need it?

`NodeMatchesFlavor` compared `nodeLabels[k] != v`, so a ResourceFlavor `nodeLabels` entry with an empty value (`key: ""`) also matched nodes that do not have the label at all.
A node now matches only when the label is present and its value equals the required value, so `""` is a regular value and no longer means "optional".

The helper is shared by the TAS nodes cache, the TAS pod usage and ResourceFlavor controllers, and the local-capacity CapacityProvider, so all of them get the fix.

Fixes #18443

#### Useful notes for your reviewer

- Behavior change for a flavor that uses `key: ""` and relied on matching nodes without the label. This matches the Kubernetes `nodeSelector` semantics, where the label must be present.
- Tests: a table test for `NodeMatchesFlavor` (18 cases), a case in the TAS nodes cache test, and a case in the local-capacity reconciler test. They fail without the fix.
- AI disclosure: prepared with the help of an AI coding assistant and reviewed by me.

#### Release note

```release-note
TAS: Fixed a bug where a ResourceFlavor `nodeLabels` entry with an empty value (for example `key: ""`) also matched nodes that do not have the label. Nodes now match only if they have the label with exactly that value.
```
