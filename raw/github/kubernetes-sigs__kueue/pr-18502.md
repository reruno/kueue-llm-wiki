#### What this PR does / why we need it?

Addresses the remaining review feedback on the local-capacity CapacityProvider controller:
- Splits `computeCapacity` into smaller named phases without changing behavior. The checks run in the same order and every message is unchanged.
- Adds shared helpers in the behavioral test utilities that return the set of resources, and their quotas, in a flavor's `status.effectiveQuotas`. The e2e and integration tests use them, so a failure prints the whole set instead of a bool. The e2e worker-node selection moves into a helper.
- Converts the integration test cleanup to `DeferCleanup`, keeping the deletion order (LocalQueue and namespace before the ClusterQueue, and the Topology after its flavor).
- Removes the e2e check that a workload stays pending right after the quota drops to zero, because the scheduler cache may not have applied the quota yet. The integration suite now covers it and waits for the cache (`kueue_cohort_subtree_quota`) before asserting.

Fixes #18422

- Not covered here: the first item of the issue (enqueueing only the affected providers for Node changes), which is in #18501.
