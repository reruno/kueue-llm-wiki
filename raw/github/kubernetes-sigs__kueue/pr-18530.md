#### What this PR does / why we need it?

For example, a Job uses Kueue's Workload slices. Its PodSet has been granted four running slots, and all four Pods have been ungated.

One worker node's kubelet becomes unreachable. An existing Pod on that node is subsequently marked for deletion and receives a `deletionTimestamp`. Because the kubelet cannot complete termination, the Pod's phase may remain `Running`. If the Job allows replacements before the old Pod reaches a terminal phase, the Job controller creates a replacement Pod. The replacement Pod has an `ElasticJobSchedulingGate` and waits for Kueue to ungate it.

The original `ElasticJobUngater` excluded only Pods in the `Succeeded` or `Failed` phase. It did not exclude Pods being deleted. As a result, it still counted the three healthy Pods and the one deleting Pod as occupying all four slots. Kueue therefore calculated zero remaining slots and did not remove the replacement Pod's gate. The replacement Pod was created but could not be scheduled on a healthy node. The Job could not restore its intended parallelism.
