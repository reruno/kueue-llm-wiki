#### What this PR does / why we need it?

Follow-up of #18382 addressing the remaining code review comments:
- Splits `aggregateWorkerQuotas` into small helpers, so `continue` becomes `return` and the loops are flat ([`r4492083252`](https://github.com/kubernetes-sigs/kueue/pull/18382#discussion_r4492083252)).

- Queues the CapacityProvider when a `MultiKueueCluster` starts being deleted. Before, this update was ignored and the deleted worker's quota stayed in the capacity.

## AI summary

CapacityProvider now queues reconciliation when a `MultiKueueCluster` starts deletion and skips deleting workers during quota aggregation. This lets it remove a deleting worker’s quota from capacity. The change also factors quota aggregation into helpers and consolidates event handlers.

### Suggested release note

MultiKueue: Fixed a bug where a deleting worker’s quota could remain in CapacityProvider capacity. Kueue now queues reconciliation when a `MultiKueueCluster` starts deletion.
