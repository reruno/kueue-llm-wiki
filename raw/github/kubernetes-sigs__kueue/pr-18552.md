## Description

#### What type of PR is this?

#### What this PR does / why we need it

When DynamicQuotaOrchestrator quota redistribution encounters a participant status-update failure, the reconciliation returns an error but can retain the previous `Distributed=True` condition.

This is misleading because the persisted effective quotas may contain a mixture of old and new allocations.

This PR addresses the status-reporting and recovery behavior:

- Introduces the `DistributionIncomplete` condition reason.
- Sets `Distributed=Unknown` when a quota distribution operation fails.
- Preserves existing ownership semantics by using `Unknown` instead of `False`, avoiding unintended DQO ownership changes.
- Restores `Distributed=True` with reason `QuotasDistributed` after a successful reconciliation.
- Documents the new condition and its limitations.

**Regression coverage**

Adds `TestIncompleteRedistributionCondition` using deterministic Kubernetes Conflict injection to cover:

1. Receiver listed before the donor.
2. Donor listed before the receiver.
3. Failed redistribution after a previously successful distribution.
4. Correct incomplete-distribution condition.
5. Successful recovery after the injected conflict is removed.

**Scope and remaining work**

This is a focused improvement related to the broader capacity-conservation bug reported in #18548.

It does not change quota allocation calculations, coordinate participant updates, or prevent admission from observing partially applied allocations.

The original overcommit issue remains open and requires an admission-safe redistribution design that accounts for independent ClusterQueue and Cohort informer updates, retries, and controller restarts.

#### Which issue(s) this PR fixes

Related to #18548

#### Useful notes for your reviewer

The implementation is limited to the DQO condition handling, regression coverage, and documentation.

`Distributed=Unknown` is intentional: the existing ownership logic distinguishes `Distributed=False`, and a transient write failure should not imply that the orchestrator has relinquished ownership.

**Validation**

The regression test has been added but has not yet been executed in the authoring environment. It should be validated through CI and a local Go test run:

`go test -mod=vendor ./pkg/controller/core/dqo -run '^TestIncompleteRedistributionCondition$' -count=10 -v`

`go test -mod=vendor ./pkg/controller/core/dqo -count=1`

I would particularly appreciate feedback on whether the incomplete-distribution condition should remain a separate change or be incorporated into the complete redistribution safety fix.

AI assistance was used for code authoring and drafting.
