Bumps [github.com/onsi/ginkgo/v2](https://github.com/onsi/ginkgo) from 2.33.1 to 2.34.0.
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/onsi/ginkgo/releases">github.com/onsi/ginkgo/v2's releases</a>.</em></p>
<blockquote>
<h2>v2.34.0</h2>
<h3>Features</h3>
<ul>
<li><code>DeferOnFailure</code> registers a callback that runs only when a spec fails - as soon as the failing node returns and before any teardown (<code>JustAfterEach</code>, <code>AfterEach</code>, <code>AfterAll</code>, <code>DeferCleanup</code>) - so it can capture the state teardown is about to destroy.  It takes exactly what <code>DeferCleanup</code> takes and shares its scoping: called in <code>BeforeEach</code>/<code>JustBeforeEach</code>/<code>It</code> it covers the spec, in <code>BeforeAll</code> the ordered container, and in <code>BeforeSuite</code> the whole suite.  It is also available on <code>GinkgoT()</code>; note that this adds a method to <code>FullGinkgoTInterface</code>, so hand-written implementations of that interface need to add it.  See <a href="https://onsi.github.io/ginkgo/#capturing-failure-state-deferonfailure">https://onsi.github.io/ginkgo/#capturing-failure-state-deferonfailure</a></li>
</ul>
<h3>Fixes</h3>
<ul>
<li>Progress reporters (<code>AttachProgressReporter</code>) are no longer called while Ginkgo holds an internal lock, so a reporter that calls <code>CurrentSpecReport()</code> or <code>AddReportEntry()</code> no longer stalls for 5 seconds and has its output dropped.</li>
<li><code>--sleep-on-failure</code> now runs after any <code>DeferOnFailure</code> callbacks, also pauses when a spec times out, and no longer pauses if the suite has already been interrupted.</li>
</ul>
</blockquote>
</details>
