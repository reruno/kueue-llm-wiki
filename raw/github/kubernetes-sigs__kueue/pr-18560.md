</li>
<li>
<p><strong>Patch releases:</strong> Review the patch release notes leading up to this version, but <em>only</em> within this minor release line; see: <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.1"><code>v0.20.1</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.2"><code>v0.20.2</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.3"><code>v0.20.3</code></a>, <a href="https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.4"><code>v0.20.4</code></a>.</p>
</li>
<li>
<p>Observability: Reduced log noise from the job reconciler and job webhooks used by all job integrations:</p>
<ul>
<li>Most per-job log records now use verbosity 3 or higher, so they are no longer shown at the default verbosity 2.</li>
<li>Most errors are now logged once instead of twice, and reconciliation errors identify the failed operation.</li>
<li>Some log keys were renamed, for example <code>oldQueueName</code> and <code>newQueueName</code> to <code>prevLocalQueue</code> and <code>localQueue</code>.</li>
</ul>
<p>If your dashboards, alerts or log queries depend on Kueue log messages, keys or verbosity levels,
review them before upgrading. For the complete list of logging changes, see <a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17747">#17747</a>.
To keep the job reconciler's per-job messages, most of which moved from level 2 to 3, set the log level to 3 or higher. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18104">#18104</a>, <a href="https://github.com/mimowo"><code>@​mimowo</code></a>)</p>
</li>
</ul>
<h2>Changes by Kind</h2>
<h3>API Change</h3>
<ul>
<li>DQO: when the referenced CapacityProviders orchestrate more than 128 distinct flavors in total, the DQO now sets EffectiveCapacityComputed=False with reason AggregationFailed instead of failing to update its status. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18293">#18293</a>, <a href="https://github.com/ekam-walia"><code>@​ekam-walia</code></a>)</li>
</ul>
<h3>Feature</h3>
<ul>
<li>MultiKueue: Reduced the delay in dispatching Workloads after a worker cluster reconnects by no longer resyncing finished Workloads that are not being deleted. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18300">#18300</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
<li>Observability: Added the alpha DisableMetricsAccessControl feature gate (disabled by default) to allow trusted sidecars to scrape HTTPS metrics without authentication or authorization on an explicit loopback IP and port. The default authenticated behavior is unchanged. Removal of this temporary gate is planned for v0.22. Before upgrading to v0.21, remove this backport-only gate and use MetricsAccessControl with metrics.accessControlMode: None instead. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18310">#18310</a>, <a href="https://github.com/ankushbbbr"><code>@​ankushbbbr</code></a>)</li>
<li>Pod: Add DeclareWorkloadFailureOnUnretriablePodGroups FG (disabled by default on the release branch) for marking unretriable PodGroups as Failed. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18282">#18282</a>, <a href="https://github.com/tenzen-y"><code>@​tenzen-y</code></a>)</li>
</ul>
<h3>Bug or Regression</h3>
<ul>
<li>CLI: Fixed a bug where <code>kueuectl list</code> commands accepted negative <code>KUEUECTL_LIST_REQUEST_LIMIT</code> values. <code>kueuectl</code> now rejects them with an error; <code>0</code> is still accepted and disables pagination. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18087">#18087</a>, <a href="https://github.com/fat-catTW"><code>@​fat-catTW</code></a>)</li>
<li>Cohort: a ClusterQueue status write no longer reconciles every ClusterQueue in its Cohort tree. ClusterQueues are notified when a Cohort, or a ClusterQueue under it, is created, deleted or changes its spec or quotas. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18205">#18205</a>, <a href="https://github.com/aleksandr-inherent"><code>@​aleksandr-inherent</code></a>)</li>
<li>ConcurrentAdmission: Fixed a bug where Workloads were not cleaned up after <code>concurrentAdmissionPolicy</code> was removed from a ClusterQueue, leaving stale parent/variant Workloads and permanently held quota. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18036">#18036</a>, <a href="https://github.com/NasitSony"><code>@​NasitSony</code></a>)</li>
<li>ConcurrentAdmission: Fixed a bug where generating Workload variants could change the parent’s metadata or overwrite a sibling variant’s flavor annotation. Each variant now has independent labels and annotations. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18265">#18265</a>, <a href="https://github.com/vshalpnjabi"><code>@​vshalpnjabi</code></a>)</li>
<li>ConcurrentAdmission: Fixed a bug where, during migration to a more favorable ResourceFlavor, Kueue evicted the already evicted Variant Workload again on every scheduling cycle. This could keep the Parent Workload from being admitted, and it emitted repeated <code>EvictedDueToFlavorMigration</code> events and <code>kueue_evicted_workloads_total</code> increments. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18252">#18252</a>, <a href="https://github.com/ivnovakov"><code>@​ivnovakov</code></a>)</li>
<li>Deployment, StatefulSet, and LeaderWorkerSet: Fixed a bug where updates to running objects without a queue-name label were rejected after a default LocalQueue was created. Kueue now applies the default only when the queue-name label can be set. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18159">#18159</a>, <a href="https://github.com/tomsen02"><code>@​tomsen02</code></a>)</li>
<li>ElasticJobsViaWorkloadSlices: Added rank-based Pod ungating, prioritizing lower completion indexes for indexed Jobs when capacity is limited. This requires TopologyAwareScheduling to be enabled, but also applies to workloads using non-TAS flavors. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18269">#18269</a>, <a href="https://github.com/mykysha"><code>@​mykysha</code></a>)</li>
<li>FailureRecovery: Fixed a bug where the KueueFailureRecovery condition and Warning event reported an incorrect grace period for Pods with a non-zero DeletionGracePeriodSeconds. Kueue now reports the correct combined grace period. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18034">#18034</a>, <a href="https://github.com/kshalot"><code>@​kshalot</code></a>)</li>
<li>KueueViz: Fix &quot;undefined&quot; in taint and toleration labels on the ResourceFlavor page. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18029">#18029</a>, <a href="https://github.com/onkar717"><code>@​onkar717</code></a>)</li>
<li>KueueViz: Fix YAML dialogs switching resources across namespaces (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18028">#18028</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>KueueViz: Fixed ClusterQueue name disclosure in Workload details when users lack LocalQueue read permission. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18025">#18025</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>LeaderWorkerSet: Fixed a bug where changing the <code>kueue.x-k8s.io/priority-class</code> label could give a LeaderWorkerSet's Workloads different priorities. Kueue now resolves the WorkloadPriorityClass once and also updates Workloads that already use the class but have an old priority value. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18332">#18332</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>Manifests: Fixed a bug that prevented the alpha-enabled manifest from installing alpha CRDs and starting the controller manager. The manifest now installs the alpha CRDs and configures compatible feature gates. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18321">#18321</a>, <a href="https://github.com/Fazlul105"><code>@​Fazlul105</code></a>)</li>
<li>MultiKueue: Fixed a bug where an autoscaling elastic RayCluster that was preempted on the manager during a worker-side scale-up could keep its worker pods running indefinitely. The pods were no longer counted in the worker ClusterQueue usage, while the manager kept holding quota. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18210">#18210</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
<li>MultiKueue: Fixed a bug where the Workload and Job on a worker cluster removed from a MultiKueueConfig kept running after their Workload was evicted and dispatched to another cluster, so the same job could run twice. This fix does not cover a kueue-controller-manager restart before the cleanup completes. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17955">#17955</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>MultiKueue: Fixed a bug where the <code>The workload was admitted on &quot;&lt;worker&gt;&quot;</code> event was emitted on every reconcile of an admitted Workload. The event is now emitted once, when the MultiKueue admission check becomes <code>Ready</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18203">#18203</a>, <a href="https://github.com/unaimeds"><code>@​unaimeds</code></a>)</li>
<li>MultiKueue: Fixed a bug where the remote copy of an autoscaling elastic RayCluster could be pointed back at a replaced workload slice after a worker-side scale-up. If the job was then preempted on the manager, its worker pods could keep running while the manager kept holding quota. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17993">#17993</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
</ul>
