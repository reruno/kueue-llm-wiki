#### What this PR does / why we need it?

Adds the `LeaderWorkerSetRejectGroupIdentityHash` feature gate (Beta, enabled by default) for the `spec.groupIdentity: Hash` rejection from #18250, as requested in https://github.com/kubernetes-sigs/kueue/pull/18250#discussion_r4512379423. Users who accept that the leader Pods of a Hash LeaderWorkerSet run without admission can disable it and upgrade without changing their LeaderWorkerSets. With the gate disabled, the webhook neither rejects nor warns about Hash, and applies the default LocalQueue on updates as before.

Related: #18250

## AI summary

This PR adds the `LeaderWorkerSetRejectGroupIdentityHash` feature gate. The gate controls how the LeaderWorkerSet webhook handles `spec.groupIdentity: Hash`.

- When the gate is enabled, Kueue keeps the Hash rejection and warning checks for managed LeaderWorkerSets. On updates to Hash LeaderWorkerSets without a queue name, Kueue does not apply the default LocalQueue.
- When the gate is disabled, the webhook does not reject or warn about `spec.groupIdentity: Hash`. It applies the default LocalQueue on updates.

The change updates the webhook logic, feature gate declaration, versioned feature lists, Group identity documentation, and unit and integration tests.

### Suggested release note

LeaderWorkerSet: Added the `LeaderWorkerSetRejectGroupIdentityHash` feature gate. When this gate is enabled, Kueue rejects `spec.groupIdentity: Hash` for managed LeaderWorkerSets and warns on updates to already-managed Hash LeaderWorkerSets. When this gate is disabled, Kueue accepts `spec.groupIdentity: Hash` without rejection or warnings and applies the default LocalQueue on updates.
