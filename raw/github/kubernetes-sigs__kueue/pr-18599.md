#### What type of PR is this?

#### What this PR does / why we need it?

Since v0.19, Kueue rejects Workloads that use DRA for companion devices, like RDMA NICs with `allocationMode: All`. Right now the only fix is turning off the DRA gates.

This updates KEP-2941 with option B from #18171. Admins can list DeviceClasses in a new `excludeDeviceClassNames` config field. Kueue doesn't charge or reject requests for those classes. It's alpha, behind `KueueDRAExcludeDeviceClasses`, for v0.21.

Part of #18171

#### Useful notes for your reviewer

Follows the design in https://github.com/kubernetes-sigs/kueue/issues/18171#issuecomment-6581991641. One choice to check: if a listed class backs an extended resource, I treat that request as a plain extended resource. So `excludeResourcePrefixes` can still drop it.

@agrawalkhushi18 @shubpal07 does this work for your Cluster Toolkit setup?

I used Claude Code to help read the DRA code and draft the KEP text.

## AI summary

This PR changes two files in the KEP-2941 (DRA) design directory. It does not change Kueue code.

- `keps/2941-DRA/README.md`: Documents a proposed alpha `KueueDRAExcludeDeviceClasses` feature gate and an `excludeDeviceClassNames` configuration field. Listed DeviceClasses are not charged against quota and are not rejected for allocation mode or missing mappings. The KEP covers `exactly` and `firstAvailable` requests, extended resources, configuration validation, device feasibility, MultiKueue, risks, test scenarios, graduation criteria, and alternatives. It adds Story 7 and updates the `firstAvailable` rules so that requests whose alternatives all use excluded classes can be skipped.
- `keps/2941-DRA/kep.yaml`: Adds `KueueDRAExcludeDeviceClasses` to the `feature-gates` list.

If a listed DeviceClass backs an extended resource, the request is treated as a plain extended-resource request. Admins should check `extendedResourceName` first, because that resource stops being charged on every node. Such requests can still be dropped by `excludeResourcePrefixes`.
