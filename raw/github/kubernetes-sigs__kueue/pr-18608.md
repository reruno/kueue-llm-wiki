#### What this PR does / why we need it?

`kueue_local_queue_unadmitted_workloads` can be reported for a LocalQueue after it is deleted or stopped, and stay.

The unadmitted tracker reports the gauge of a LocalQueue without checking that the queue manager still holds it. A removal assumes that it does, and an update checks the LocalQueue that the Workload names now, not the one in its old status.

`DeleteLocalQueue`, which also runs when a LocalQueue is stopped, clears the metrics before it removes the queued Workloads from the tracker, so those removals can report the gauge again. The LocalQueue controller clears the metrics again after a deletion, but not after a stop. After a deletion, a later removal or move of a Workload still tracked under the LocalQueue can bring the gauge back. The update check also skips the gauge decrement for a Workload outside the queue, such as an inactive one, that moves to a LocalQueue that does not exist, so the old LocalQueue keeps counting it.

The queue manager now drops the LocalQueue before it removes the queued Workloads, and each status checks its own LocalQueue.

This is split out of #18325, which keeps the fix for the metrics recorded for a Workload.

Part of #18322

Moving the delete back after the removals, or assuming that the LocalQueue exists, makes a named case fail.

Not changed here, and older than this PR: a re-created LocalQueue does not report the gauge for Workloads that the tracker still holds, until their count changes or the gauges are resynced.

## AI summary

- Stops `kueue_local_queue_unadmitted_workloads` from reporting for a deleted LocalQueue. `DeleteLocalQueue` now removes the LocalQueue from the queue manager before it removes that LocalQueue's Workloads from unadmitted-workload tracking.
- Fixes the gauge when a Workload moves to a nonexistent LocalQueue. The LocalQueue gauge for the old LocalQueue is decremented.
- Each unadmitted-workload update now checks LocalQueue existence at update time, through `LocalQueueExistsWithoutLock`. The caller no longer passes an existence flag. ClusterQueue metric handling is unchanged.
- Adds `TestLocalQueueUnadmittedWorkloadsMetric`. The table-driven test covers removal and movement of inactive and queued Workloads, popped queue heads, moves to an existing or missing LocalQueue, and `DeleteLocalQueue`.
- Known limitation, not changed by this PR: a recreated LocalQueue does not report the gauge for Workloads still held by the tracker. The gauge updates after those Workload counts change, or after the gauges are resynced.

### Suggested release note

Observability: Fixed a bug that caused stale `kueue_local_queue_unadmitted_workloads` values when a LocalQueue was deleted or a Workload moved to a nonexistent LocalQueue. Kueue now reports this metric only for existing LocalQueues.
