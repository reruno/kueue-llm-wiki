#### What this PR does / why we need it?

With `podSetMergePolicy: IdenticalWorkloadSchedulingRequirements`, PodSets merge when their containers have equal requests and their other scheduling fields match; limits are not compared. A container can ask for a resource only through its limits, as is common for GPUs, and the API server copies those limits into the requests when the Pods are created. So a PodSet with a GPU only in its limits could merge with a PodSet without a GPU, and the ProvisioningRequest then used the PodTemplate of the first of them for the Pods of both.

The requests are now also compared after the limits are copied into them, as they are in the PodTemplate built for the request. They still have to match as written, so this only keeps PodSets apart and merges none that were kept apart before.

#14408 gives every merged PodSet the update of the request, so it needs this first. Otherwise a PodSet merged this way would be pointed at capacity provisioned for the other one.

Related: #14408
