#### What this PR does / why we need it?

While a ClusterQueue is being deleted and admitted workloads still hold its `kueue.x-k8s.io/resource-in-use` finalizer, its resource metrics stop updating. The ClusterQueue `Update` event handler returns early for an object with a deletion timestamp, so it never reaches `updateResourceMetrics`. `Reconcile` still runs and refreshes the status, but it calls `RecordCohortMetrics` only for ClusterQueues that are not being deleted. As the workloads finish, `kueue_cluster_queue_resource_reservation`, `kueue_cluster_queue_resource_usage` and `kueue_cohort_subtree_resource_reservations` keep the values from before the deletion until the ClusterQueue is gone.

`Reconcile` now records the ClusterQueue resource metrics in its deletion branch when `metrics.enableClusterQueueResources` is set, and records the cohort metrics for every ClusterQueue it reconciles.
