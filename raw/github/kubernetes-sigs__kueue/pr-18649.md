#### What this PR does / why we need it?
CodeRabbit sometimes refuses to open an issue when the requester has no repository write access, and sometimes opens one. The repository gave it no rule for that choice.
This adds a rule under "Opening issues" in `cmd/experimental/skills/kueue-pr-issue-workflow/SKILL.md`. CodeRabbit already reads that skill through `AGENTS.md`. `tone_instructions` in `.coderabbit.yaml` is limited to 250 characters, so the rule is not placed there.
CodeRabbit opens an issue when `gh api orgs/kubernetes-sigs/members/<user>` returns 204, including when the member has no repository write permission. A 204 means the requester is a member of the `kubernetes-sigs` organization.
After this merges, a `kubernetes-sigs` member without write access should ask CodeRabbit to open an issue. If it still refuses, the restriction is enforced by CodeRabbit, and the next step is the CodeRabbit organization settings or CodeRabbit support.

Membership is checked with `gh api -i orgs/kubernetes-sigs/members/<user>`. Only `HTTP 204` confirms membership. For any other status, including `404` after a `302` redirect, CodeRabbit reports the status and asks a maintainer to open the issue.
