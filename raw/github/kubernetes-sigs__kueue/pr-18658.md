#### What this PR does / why we need it?

When an admitted partial Job scales below its minimum, Kueue lowers the Workload's `minCount` to the new count (#16742). A later scale-up builds a new Workload slice that copies the lowered `minCount` forward. No test covers that path for a `batch/v1` Job.

This adds a spec to `elastic_partial_scaleup_resize_test.go`. It admits a Job at 4, scales it to 1, then to 5, and checks that the new slice is admitted with count 5 and keeps `minCount: 1`.

## AI summary

This change lets an elastic Job scale down when its PodSet `minCount` is higher than the new count. Kueue now lowers the stored `minCount` to the new count. Before this change, the Workload webhook rejected such a scale-down.

Main changes:

- **Webhook validation** (`pkg/webhooks/workload_webhook.go`): `validateImmutablePodSet` accepts a scale-down that reduces `MinCount`. The new value must equal the smaller of the old `MinCount` and the new PodSet count. The helper temporarily restores the old `MinCount` before immutable-field checks.
- **Count and minimum updates** (`pkg/workload/podsetscounts.go`): `ApplyPodSetCounts` caps an existing `MinCount` at the updated PodSet count when the minimum is higher. The function signature is unchanged.
- **Workload slicing** (`pkg/workloadslicing/manager.go`): `EnsureWorkloadSlices` updates each matching PodSet's `MinCount` during initial admission. It keeps the existing minimum when the Workload has a quota reservation, accumulated past execution time, or is scaled up. Otherwise, it uses the job minimum, or the lesser of the job minimum and the current count.
- **Scale-up behavior** (KEP 12100 README): A later scale-up keeps a lowered minimum. For example, after scaling from 4 to 1 and then to 5, the new slice keeps `minCount: 1`. Scaling down to 0 can allow readmission with zero workers.
- **Tests**: Unit tests cover webhook scale-down rules, `ApplyPodSetCounts`, and workload-slice scale-down. Integration and e2e tests cover Job and RayCluster scale-down and scale-up, pending Job admission, and webhook metadata-only updates.

The PR objectives describe only the Job integration spec. The diff also changes webhook validation, count handling, and workload-slice logic in 11 files, with 843 lines added and 9 removed. This summary follows the diff.

Test results were not available in the supplied context.
