#### What this PR does / why we need it?

Moves the MultiKueue CapacityProvider controller (#17401) out of `pkg/controller/admissionchecks/multikueue` into its own sub-package, `pkg/controller/admissionchecks/multikueue/capacityprovider`, with `reconciler.go` as the main file, as requested in https://github.com/kubernetes-sigs/kueue/pull/18382#discussion_r4492085426.

This is a structural refactor with no behavior change: the controller name (`multikueue_capacityprovider`), logger name, conditions and messages, watches, RBAC markers, and feature gating are unchanged. `multikueue.SetupIndexer` and `multikueue.SetupControllers` keep their signatures, so `cmd/kueue` and the integration and performance suites need no changes.

#### Useful notes for your reviewer

Most of the changes are renames. The things you should focus on is:
- `capacityprovider/reconciler.go`: the new `WorkerClients` interface, `NewReconciler` (options + the `cqUpdateCh` argument), and `connectedWorkerClient`, which now calls `WorkerClients.ConnectedClient`.
- `multikueuecluster.go`: `clustersReconciler.ConnectedClient`, which implements `WorkerClients` (the remote-client part of the old `connectedWorkerClient`).
- `controllers.go`: wiring of `capacityprovider.NewReconciler`, and `SetupIndexer`, now a wrapper around `mkindexer.Setup`.
- `indexer/indexer.go`: all MultiKueue and CapacityProvider indexes in one package (moved from `indexer.go`), with the same feature gates.

## AI summary

This refactor moves the MultiKueue CapacityProvider controller into a new `capacityprovider` sub-package and moves MultiKueue field-index setup into a new `indexer` package. The controller name, logger name, conditions, messages, watches, RBAC markers, and feature gating remain unchanged according to the PR objectives.

Main changes:
- **capacityprovider/reconciler.go**: The former `cpReconciler` is now the exported `Reconciler`, built with `NewReconciler` and the `WithRoleTracker` and `WithEventsBatchPeriod` options. Worker access goes through a new `WorkerClients` interface. The event-handler constructor is renamed to `newEventHandler`. A new `activeConditionChanged` helper compares the Active condition's status, reason, message, and observed generation for MultiKueueCluster updates.
- **capacityprovider/reconciler_test.go**: Moved to the new package. Tests are renamed to `TestReconcile` and `TestReconcilerEventHandlers`. Fixtures use a `fakeWorkerClients` map.
- **indexer/indexer.go**: Moved to the new `indexer` package. `SetupIndexer` is renamed to `Setup`. The capacity-provider index now checks the controller name, non-nil parameters, and the parameter API group and kind.
- **indexer/indexer_test.go**: New `TestSetup` table test covering the indexes. The old `multikueue/indexer_test.go` is deleted.
- **controllers.go**: Adds `SetupIndexer`, which delegates to the indexer package. `SetupControllers` builds the capacity-provider reconciler through the new package.
- **multikueuecluster.go**: Implements `capacityprovider.WorkerClients` through a new `ConnectedClient` method. Uses the indexer package's index constants.
- **multikueuecluster_test.go**: Adds a shared client builder and a `TestClustersReconcilerConnectedClient` test.
- **admissioncheck.go** and **workload.go**: Use the indexer package's index keys. `multiKueueConfigName` compares a `GroupKind` instead of a `GroupVersionKind`.

The PR objectives state that `multikueue.SetupIndexer` and `multikueue.SetupControllers` keep their signatures. The objectives also report no required changes to `cmd/kueue` or the integration and performance suites. Reviewers should confirm two points that the diff summary describes as narrower or stricter behavior: the MultiKueueCluster update-event comparison and the capacity-provider index filtering.
