#### What this PR does / why we need it?

Ensures `behavioral.DeleteNamespace` deletes all custom job types (`RayService`, `RayCluster`, `TrainJob`, `LeaderWorkerSet`, `CronJob`, `SparkApplication`, and Kubeflow training jobs) before deleting workloads and the namespace itself.

In `envtest`, namespaces do not garbage-collect child resources upon deletion. Previously, `DeleteNamespace` deleted the `Workload` and put the namespace into `Terminating` without calling several existing `DeleteAll*InNamespace` helpers from `test/util/behavioral/jobs.go` (such as `DeleteAllRayServicesInNamespace`, `DeleteAllTrainJobsInNamespace`, and `DeleteAllLeaderWorkerSetsInNamespace`). Consequently, leftover job CRs remained alive in terminating namespaces across subsequent test specs, causing controllers to repeatedly fail recreating missing workloads and enter tight reconcile/requeue loops—driving memory usage up until the parallel Ginkgo workers were OOM-killed.

Part of #18623
Fixes #18688

#### Useful notes for your reviewer
- Added `DeleteAllRayClustersInNamespace`, `DeleteAllTFJobsInNamespace`, `DeleteAllPaddleJobsInNamespace`, and `DeleteAllXGBoostJobsInNamespace` to `test/util/behavioral/jobs.go`.
- Wired all missing `DeleteAll*InNamespace` helpers into `behavioral.DeleteNamespace` in `test/util/behavioral/namespace.go` prior to `deleteWorkloadsInNamespace`.
