#### What type of PR is this?

#### What this PR does / why we need it?

An elastic `SparkApplication` that is preempted stays suspended for good. The first admission writes the Workload and workload-slice names into `spec.{driver,executor}.annotations`. A later admission under another Workload, either a replacement slice or the first slice of a new chain, made `PodSetInfo.Merge` report the two names as a permanent conflict, so the job reconciler finished the Workload as `FailedToStart` instead of starting the job:

```
invalid admission check PodSetUpdate: conflict for annotations: conflict for key=kueue.x-k8s.io/workload, value1=sparkapplication-als-2-3d1ae, value2=sparkapplication-als-2-9211c
```

`RunWithPodSetsInfo` now merges through `podset.Merge`, as the other integrations do, which replaces the stale Kueue-managed annotations for elastic admissions.

Fixes #18606

#### Useful notes for reviewers

Tests:

- **Admission again under a new slice** (unit, `TestRunWithPodsetsInfo`): an application that still carries the previous Workload's annotations is admitted under a replacement slice of the same chain and under the first slice of a new chain; the annotations follow the current Workload and the user's annotations are kept. Without the fix both cases fail with the error above. A non-elastic admission with a stale `workload` annotation still fails.
- **No regressions** (unit): `go test ./pkg/controller/jobs/sparkapplication/ ./pkg/podset/` passes.
- **Reproduction** (e2e): #18606 has a script that runs the preemption scenario on a cluster.

Other notes:

- The change is a field-for-field substitution: the Spark pod spec is wrapped in an `ObjectMeta` and `PodSpec` for `podset.Merge`, and the result is written back as before. Conflicts on user annotations, labels and node selectors are still reported.
- **Not run locally:** `make verify` (it requires GNU sed, and its tool installer cannot download the pinned tools from this network) and the integration suites. `gofmt` and `go vet` are clean.
- This PR was prepared with AI assistance (Claude).

Merge errors are returned. The `metav1` import was added.

They assert that re-admission replaces stale Workload annotations on driver and executor PodSets, both when the slice name is retained and when a new slice chain starts. A non-elastic case expects an error for stale Workload annotations. Test cases now set their feature gates before running.

Linked issue `#18606` describes an elastic SparkApplication that stays `SUSPENDED` after preemption. Its Workload finishes as `FailedToStart` because of the annotation conflict. This change targets that scenario. The author reports that `go test ./pkg/controller/jobs/sparkapplication/ ./pkg/podset/` passed, and that `gofmt` and `go vet` were clean. The author did not run `make verify` or the integration suites. This summary did not run any tests.
