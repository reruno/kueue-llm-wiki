## AI summary

This PR graduates the `CustomMetricLabels` feature gate from Alpha to Beta. It adds a v0.21 feature-gate entry that defaults to enabled. Custom Prometheus labels for ClusterQueue, LocalQueue, Cohort, and Workload metrics are available without setting the gate.

Main changes:

- `pkg/features/kube_features.go` adds a `0.21` entry with `Default: true` and `PreRelease: featuregate.Beta`. The `0.17` Alpha entry is unchanged.
- `keps/7066-custom-metric-labels/kep.yaml` moves the target stage to beta. It sets `latest-milestone` to `v0.21` and adds the beta milestone `v0.21`. The alpha milestone `v0.17` is kept.
- `site/data/featuregates/versioned_feature_list.yaml` and `test/compatibility_lifecycle/reference/versioned_feature_list.yaml` add a `0.21` entry for the gate.
- `site/content/en/docs/tasks/manage/observability/configure_custom_metric_labels.md` states that the gate has been enabled by default since v0.21. The example no longer sets `featureGates.CustomMetricLabels`.
- Unit, integration, and e2e tests remove the explicit `CustomMetricLabels` gate setup. Their other setup and assertions are unchanged.
- `pkg/metrics/custom_labels_test.go` adds deletion-semantics tests for the custom-label stores. These tests cover selective deletion, unknown-reference deletion, typed CQ, LQ, and Cohort delete wrappers, and re-adding a deleted reference.

Runtime behavior change: custom metric labels are active without a feature-gate setting. The test changes do not change runtime logic.

## Suggested release note

```text
Observability: Custom Prometheus labels for ClusterQueue, LocalQueue, Cohort, and Workload metrics graduated to Beta. This behavior is gated by the CustomMetricLabels feature gate.
```
