#### What this PR does / why we need it?

#18545 added `StartManagerForSpec` and used it where specs paired `StartManager` with a `DeferCleanup` stop. Many singlecluster specs still start the manager in `BeforeEach` or `JustBeforeEach` and stop it with `fwk.StopManager(ctx)` in `AfterEach`. Each of those specs has to remember the stop. If one drops it, the next `StartManager` replaces the stored cancel function and the old manager keeps reconciling objects from later specs.

This PR converts those pairs to `StartManagerForSpec` and removes the `StopManager` calls. `AfterEach` blocks that only stopped the manager are removed.

Some `AfterEach` blocks ran cleanup after `StopManager` that needs the manager to be stopped: `metrics.InitMetricVectors(nil)` replaces the global metric vectors that controllers read, and `fwk.Teardown()` stops envtest. Since the helper stops the manager after `AfterEach`, that cleanup now goes into a `ginkgo.DeferCleanup` registered before `StartManagerForSpec`. Ginkgo runs cleanups in reverse order, so it still runs right after the manager stops.

Manager pairs in `BeforeSuite`/`AfterSuite` and stop/restart inside a spec, keep using `StartManager`.

## AI summary

This change updates 81 singlecluster integration test files (+181/-492 lines). It switches per-spec manager startup from `StartManager` to `StartManagerForSpec`. It also removes the matching `StopManager` calls from `AfterEach`, `AfterAll`, and `JustAfterEach` hooks.

- **Webhook tests:** Most webhook suites under `test/integration/singlecluster/webhook/` only change the start call and remove the stop call.
- **Job and framework tests:** Job-integration suites (AppWrapper, JAXJob, MPIJob, PaddleJob, PyTorchJob, RayCluster, RayJob, RayService, SparkApplication, TFJob, TrainJob, XGBoostJob) and core controller suites change the same way.
- **Metric cleanup:** Suites that reset metric vectors register that reset with `ginkgo.DeferCleanup` before starting the manager. The reset then runs after the helper stops the manager.
- **Retained behavior:** Suite-level `StartManager` calls are not changed. Namespace cleanup, resource-flavor checks, and tracker cancellation remain in their existing hooks.

The diff summaries show no changes to exported declarations. This PR does not report test results. The linked issue's requested verification of cleanup ordering on setup failure and of explicit stop and restart within a spec is not reported as completed.
