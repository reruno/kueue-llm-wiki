#### What type of PR is this?

#### What this PR does / why we need it?

Breaks down `wlReconciler.reconcileGroup` in the MultiKueue workload controller into helpers, following #17811, #18520 and #18536. `reconcileGroup` goes from 344 to 142 lines. Each numbered step of the function moves into its own helper, one commit per helper:

| Commit | Helper | Step |
|---|---|---|
| 1 | `isElasticReplacedOrScalingUp` | 1: skip an elastic workload that a new slice replaced or that is scaling up |
| 2 | `deleteRemoteWorkloads` | 2: delete the remote workloads when the local workload is finished or has no quota reservation |
| 3 | `reconcileRemoteFinished` | 3: finish the local workload when a remote workload is finished, or reset the check on a sync failure |
| 4 | `reconcileRemoteEviction` | 4: handle a workload whose remote workload is evicted |
| 5 | `reconcileAdmittingRemoteLost` | 6a: handle a Ready check when no remote workload is admitted |
| 6 | `reconcileAdmittingRemote` | 6b: converge onto the admitting remote workload |
| 7 | `openNextPreemptionGate` | 7: open the next preemption gate |

Step 5 is not changed, because #17952 covers it. Steps 6c and 8 stay inline because they are short, and step 9 is already a helper.

Part of: #18462

#### Useful notes for your reviewer

No behavior change. Each commit moves one block. Error messages, log lines and values, events, metrics, and return values do not change.

- Helpers that can stop reconciliation return `(done, result, err)`, like #17811. Steps that always return when they run keep their condition at the call site and return `(reconcile.Result, error)`.
- Helpers take the `reconcileGroup` logger, like `syncToSingleCluster`, so `op=reconcileGroup` stays on the log lines.
- Step 4 can continue to the later steps. In that case, it first adds the `remote` and `remoteWorkload` values to `log` and `ctx`. These two lines stay in `reconcileGroup`, so the later steps log the same values. `reconcileRemoteEviction` returns `done=false` only on that path.
- In step 7, the feature gate check moves into `openNextPreemptionGate`, which returns a zero requeue time when the gate is off. This is the same value as before.
- The issue planned several small PRs. Following #18520, this PR does all the steps except step 5, with one commit per helper.
