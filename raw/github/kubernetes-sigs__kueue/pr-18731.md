#### What this PR does / why we need it?

`periodic-kueue-test-e2e-k8s-main-was` has failed since the Kubeflow Trainer bump to v2.4.0. It fails during cluster setup, before any WAS spec runs:

```
Error from server (Invalid): CustomResourceDefinition "clustertrainingruntimes.trainer.kubeflow.org" is invalid:
  ...properties[replicatedJobs].items.properties[job].properties[resourceClaims].x-kubernetes-validations[0].rule:
  Forbidden: estimated rule cost exceeds budget by factor of 1.006651x
```

The lane installs every external operator (AppWrapper, JobSet, Kubeflow, MPI, Trainer, LWS, KubeRay, Prometheus), but the WAS suite (`test/e2e/singlecluster/wasapi`) only uses batch `Job`. This PR stops passing those operator versions, so the lane installs only Kueue. That matches the released-Kubernetes WAS lane (`run-test-e2e-was-api-%`).

Fixes #18724

#### Useful notes for your reviewer

- The failure is deterministic, not a flake. The lane passed through `9f223b614` and has failed since `70fe03248`, which includes the Trainer v2.4.0 bump (#18563).
- It only affects Kubernetes `main`. On #18563, the extended e2e lanes, which install Trainer, passed on 1.35, 1.36 and 1.37.
- Reproduced locally: on a kind cluster built from Kubernetes `v1.38.0-beta.0.386+02814b43b6e007`, applying the Trainer v2.4.0 CRDs gives the same error with the same `1.006651x` factor.
- Verified locally: `make run-test-e2e-k8s-main-was` on a kind cluster from Kubernetes `v1.38.0-beta.0.386+02814b43b6e007` installs no external operators and passes (Ran 1 of 1 Specs, SUCCESS).
- `make -n` shows that after this change, `run-test-e2e-k8s-main-was` and `run-test-e2e-was-api-%` differ only in the node image and the artifacts directory.
- Trainer v2.4.0 will probably fail the same way on other lanes once Kubernetes 1.38 is released. That's out of scope here and should be raised with kubeflow/trainer.
- AI disclosure: I used Claude Code to investigate the failure, reproduce it and draft this change. I reviewed and verified the result.
