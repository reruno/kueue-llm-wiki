#### What this PR does / why we need it?

Fixes three places in the TAS concept page that disagree with the code:

- `TASFailedNodeReplacementFailFast` has been enabled by default since v0.14, but the paragraph about it said Kueue retries by default and that the gate must be enabled to stop retrying. The alert right above that paragraph already says the gate is enabled by default.
- The Feature Gate Interaction Matrix labeled the `FNFF=false` row as "Default Hot Swap". It is now "Hot Swap", and the `FNFF=true` row is marked "(default)".
- The matrix listed the Pod-termination trigger for any value of `TASReplaceNodeOnPodTermination`. With that gate disabled, a node is treated as failed after 30 seconds of `NotReady`, regardless of Pod state, as the paragraph below the table already says. The Trigger cells now mention this case.

The wording of the existing sentences is kept; only the incorrect parts are changed.

## AI summary

This PR changes one file: `site/content/en/docs/concepts/topology_aware_scheduling.md` (5 lines added, 3 removed). It is a documentation-only change. It does not change controller behavior.

- **Fast Hot Swap text:** The paragraph now starts with the disabled-gate case. If `TASFailedNodeReplacementFailFast` is disabled, Kueue retries replacement until it succeeds or the workload is evicted. The paragraph states that this gate is enabled by default. When the gate is enabled, Kueue attempts replacement once. If replacement fails, Kueue evicts and requeues the workload. A new paragraph states that when `TASNodeReplacementDeferFailFastWhenUsefulInflightEvictions` is enabled, Kueue does not evict the workload if evictions already in progress are expected to free a suitable placement.
- **Feature-gate matrix:** The `FNFF=false` row label changes from "Default Hot Swap" to "Hot Swap". The `FNFF=true` row label changes from "Fast Hot Swap" to "Fast Hot Swap (default)".
- **Trigger cells:** Both rows add a parenthetical. When `TASReplaceNodeOnPodTermination` (`RNO`) is disabled, a node is treated as failed after it stays `NotReady` for 30 seconds, regardless of Pod state.
- **Behavior cell in the `FNFF=true` row:** The cell adds the deferral exception for in-progress evictions.
