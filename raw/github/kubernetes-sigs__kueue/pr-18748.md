## Description


#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

With ConcurrentAdmission, the Parent Workload is not queued, while each of its Variants is. The ClusterQueue pending counts counted the queued Workloads, so a Workload was counted once per flavor in the ClusterQueue's `status.pendingWorkloads` and in `kueue_pending_workloads`. KEP-8691 says that the existing metrics track Parent Workloads and skip Variants.

This PR adds `variantParentCounts`, which counts the pending Variants of each Parent per status (active, inadmissible, inflight). It follows `schedulingHashCounts` and is updated next to it at every mutation of the pending Workloads. `Pending()` subtracts the Variants beyond the first one of each Parent. A Parent counts as active when any of its Variants is active or inflight, and as inadmissible otherwise.

Not changed in this PR:

- LocalQueue counts (`status.pendingWorkloads` and `kueue_local_queue_pending_workloads`). I'll follow up separately; after a Kueue restart, the LocalQueue status also counts the Parent itself, because `addLocalQueueLocked` adds it to the LocalQueue items.
- The pending counts reported when custom metric labels are configured (`PendingBreakdown()`).
- The Visibility API, which lists Variants.

Part of #18747

## AI summary

This change counts each ConcurrentAdmission Parent once in ClusterQueue pending counts. Before this change, each pending Variant counted separately. The change applies only when the ConcurrentAdmission feature gate is enabled.

- `pkg/cache/queue/variant_parent_counts.go` (new): adds `variantParentCounts`. It tracks pending Variants per Parent UID in three maps: active, inadmissible, and inflight. Its `excess()` method returns the active and inadmissible counts above one per Parent. A Parent is active if any Variant is active or inflight. Otherwise it is inadmissible.
- `pkg/cache/queue/pending_workloads.go`: updates the tracker on each add, update, delete, move, and inflight transition. `Pending()` subtracts the excess values from the active and inadmissible totals.
- `pkg/cache/queue/cluster_queue.go`: initializes the tracker in `newClusterQueueImpl`.
- `pkg/cache/queue/variant_parent_counts_test.go` (new): adds `TestVariantParentCountsExcess` and `TestPendingCountsEachParentOnce`. The tests cover gate-enabled and gate-disabled cases.

The change does not alter LocalQueue counts, `PendingBreakdown()` label counts, or Visibility API results. Those paths still list Variants.

Review point: `excess()` does not subtract inadmissible Variants for a Parent that also has active or inflight Variants. Such a Parent counts once as active and again for each inadmissible Variant. Confirm this matches the intended behavior.

The author reports that the targeted tests pass, that the package tests pass, and that a manual kind check shows the pending count drop from 3 to 1 for one Job across three flavors. No integration test was run. This summary did not run the tests.
