## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

When a pending Workload is deleted while a scheduling cycle holds it (for example, its Pod is deleted while still scheduling-gated), the scheduler's status update fails with NotFound. `requeueAndUpdate` logged this as `Could not update Workload status` at error level and then recorded a Warning event for the Workload that no longer exists. `waitForPodsReadyIfNeeded` (used with `waitForPodsReady.blockAdmission`) makes the same status update and logged the same error.

The deletion is an ordinary lifecycle event. This PR handles NotFound the way the admission path in the same file already does:
- `requeueAndUpdate`: log at V(3) and return, so no event is recorded for the deleted Workload.
- `waitForPodsReadyIfNeeded`: log at V(3). The wait and the rest of the cycle are unchanged; the admission write that follows already handles NotFound.

Other errors are still logged at error level. Queue and quota handling are unchanged: `RequeueWorkload` already drops a Workload that is gone from the informer cache.

The NotFound in the preemption path (#10874) is out of scope.

Fixes #18732

### Comment by [@bodyhedia44](https://github.com/bodyhedia44) — 2026-11-14T13:55:21Z

Thanks for the review

Yes, keeping WaitForPodsReady there is intentional. waitForPodsReadyIfNeeded doesn't return anything, so an early return there would only skip the wait not the rest of the cycle. The caller then normally goes on to admit() which assumes the Workload in the cache and starts the admission write in the background. That write fails with NotFound and the existing handling there removes the assumed Workload from the cache and logs at V(3)

What an early return would save is the wait itself with blockAdmission the scheduler can block for a while until all admitted Workloads are PodsReady here on behalf of a Workload that no longer exists
That wait already happens today so this PR doesn't change it

If you think it's worth avoiding that wait I'm happy to do it in a follow-up.
