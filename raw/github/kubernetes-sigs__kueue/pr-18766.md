## Description

Cherry pick of #16459 #18758 #18761 on release-0.20.

#16459: Align Workload priorities with their WorkloadPriorityClass on Workload events
#18758: WorkloadPriorityClass: Add a feature gate for the Workload watch
#18761: Wait for the manager cache in the gate-off WorkloadPriorityClass spec

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

#16459 and #18761 apply as is. #18758 conflicts only in `kube_features.go`, because main lists gates that this branch does not have. The gate is Beta and on by default here with version 0.20, the way `WorkloadValidateResourcesAreNonNegative` is on this branch.

_Disclosure: I used an AI coding assistant while preparing this PR._

#### What type of PR is this?
/kind bug

```release-note
WorkloadPriorityClass: Fixed a bug where changing a WorkloadPriorityClass value and quickly changing it back could leave Workloads that reference it at the intermediate priority. Kueue now also sets the class value back when the `priority` of such a Workload is changed directly.
WorkloadPriorityClass: Added the `WorkloadPriorityClassWatchesWorkloads` feature gate, Beta and enabled by default. Disable it to keep a `priority` changed directly on a Workload until its WorkloadPriorityClass is reconciled again.
```
