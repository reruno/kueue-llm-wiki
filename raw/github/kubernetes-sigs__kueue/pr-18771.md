#### What this PR does / why we need it?

`RecordCohortMetrics` and `ClearCohortMetrics` collect the subtree values of a Cohort and its ancestors in `collectCohortMetricPoints` under the scheduler cache read lock, release it, and then write the gauges. A cache update can land between the two steps. When two calls for the same Cohort overlap, the one that collected before the update can write last, so `kueue_cohort_subtree_quota` or `kueue_cohort_subtree_resource_reservations` keeps the older value until the next call for that Cohort or a Cohort below it. Calls do overlap. The shipped configuration runs 5 ClusterQueue reconciler workers, and the Cohort reconciler and the ClusterQueue event handlers call these functions too.

Both functions now go through `reportCohortMetrics`, which takes the read lock before collecting and releases it after the last gauge write. A cache update needs the write lock, so it can't land in between. Calls that overlap now read the same cache state, so an older read can no longer be written after a newer one. None of the callers already holds the cache lock, so it is never taken twice. The ClusterQueue and LocalQueue resync functions already write gauges under the read lock.

## AI summary

This PR makes Cohort gauge writes run under the scheduler cache read lock. Before this change, `RecordCohortMetrics` and `ClearCohortMetrics` released the lock after collecting metric points and then wrote the gauges. A cache update could land between those steps. An older call could then overwrite newer gauge values.

Changes in `pkg/cache/scheduler/cohort_metrics.go`:

- `RecordCohortMetrics` and `ClearCohortMetrics` now call a shared `reportCohortMetrics` method. The method takes the cache read lock with `RLock` and releases it after all gauge writes.
- `reportCohortMetrics` skips empty Cohort names. It logs whether it is recording or clearing. It collects points and applies each one while holding the lock.
- `collectCohortMetricPoints` no longer takes its own read lock. Its callers must hold the cache lock. The doc comment states this.

Changes in `pkg/cache/scheduler/cohort_metrics_test.go`:

- Adds `TestCohortMetricsWrittenUnderCacheLock`. The test checks that each Cohort gauge write happens while the cache lock is held.

The change does not address the Cohort deletion gap in `removeCohortInMemory`. That gap is tracked in `#18769`.

### Suggested release note

```text
Observability: Fixed a bug where concurrent ClusterQueue reconciliation could leave `kueue_cohort_subtree_quota` and `kueue_cohort_subtree_resource_reservations` with stale values for a Cohort. Kueue now writes Cohort gauges under the same cache lock used to collect their values, so older values no longer overwrite newer ones.
```
