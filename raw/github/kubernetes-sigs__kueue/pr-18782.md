#### What this PR does / why we need it?
When a queued parent Job is updated before admission, the parent Workload updates in place, but existing unadmitted variants keep their initial spec from creation. If a variant is later admitted, the parent can revert to that stale spec.

This change adds `syncVariantSpecs` to the concurrent admission reconciler to copy updated parent spec, labels, and annotations to unadmitted variants before admission evaluation, while preserving each variant's `Active` state, preemption gates, and flavor annotation. Parents and variants that already hold quota reservations are skipped, and an `UpdatedVariant` event is emitted only when a variant changes.

`firstCandidateVariant` also checks `ObservedGeneration` against `Generation` when picking a preemption gate candidate. It waits while `QuotaReserved` is stale, and treats a stale `BlockedOnPreemptionGates` condition as absent once `QuotaReserved` has been refreshed to a non-`PendingEvaluation`, non-`PreemptionGated` reason. In `pkg/controller/core/workload_controller.go`, `resolveGranularUnadmittedQuotaReservedCondition` now preserves `schedulerSetReasons` only when `wl.Generation == 0 || cond.ObservedGeneration >= wl.Generation`, so a spec update resets stale scheduler reasons such as `WaitingForQuota` or `PreemptionGated` back to `PendingEvaluation` rather than re-stamping them with the new generation before the scheduler runs.

Existing preemption test fixtures in `controller_test.go` were updated with `.Request(corev1.ResourceCPU, "1")` on the parent workload so their initial podsets match the variant fixtures. Unit tests cover metadata sync, reserved parent and variant skips, spec detachment, generation checks across gate selection, core condition resets and matching-generation preservation, and an intervening `WorkloadReconciler` run between a variant spec update and preemption gate selection. Integration tests cover syncing updated parent specs to variants under envtest.

Fixes #18745

AI summary

This PR makes unadmitted ConcurrentAdmission variants follow their parent Workload. Before admission evaluation, the variant reconciler copies the parent spec, labels, and annotations to each unadmitted variant. It keeps each variant's `Active` state and flavor annotation. It skips the sync when the parent or the variant has a quota reservation. It emits `UpdatedVariant` when a variant changes, and it stops reconciliation when an update fails.

The PR also changes two generation checks:
- Preemption-gate candidate selection compares condition `ObservedGeneration` with the variant `Generation`. A stale `QuotaReserved` condition makes the variant wait. A stale `BlockedOnPreemptionGates` condition is treated as absent.
- `resolveGranularUnadmittedQuotaReservedCondition` keeps a scheduler-set reason only when `ObservedGeneration` is at least the Workload `Generation`, or when the generation is zero. Otherwise the condition resets to `PendingEvaluation`.

`generateVariant` now deep-copies the parent spec. Unit tests cover sync, reservation skips, and generation checks. An integration test covers a parent pod-set count, label, and annotation change reaching unadmitted variants.

Suggested release note

ConcurrentAdmission: Fixed a bug where unadmitted variants kept a stale spec after a queued Job was updated, which could cause quota to be reserved for the old Pod count or block admission when the PodSet list changed. Now Kueue syncs the spec, labels, and annotations of unadmitted variants with the parent Workload before admission evaluation.

This behavior is gated by the `ConcurrentAdmission` feature gate.
