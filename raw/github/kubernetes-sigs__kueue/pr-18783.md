#### What this PR does / why we need it?

When a reconcile runs before the Workload cache sees a Workload that an earlier reconcile created, the LeaderWorkerSet reconciler creates it again. The reconciler logged the `AlreadyExists` error as `Failed to create Workload` and returned it, so the LeaderWorkerSet was requeued with backoff. This PR treats `AlreadyExists` as created, as the StatefulSet reconciler already does.

## AI summary

The LeaderWorkerSet reconciler now treats an `AlreadyExists` error from Workload creation as success. A reconcile can run before the Workload cache observes a Workload that an earlier reconcile created. The create call then returns `AlreadyExists`. Before this change, the reconciler logged that error as `Failed to create Workload`, returned it, and requeued the LeaderWorkerSet with backoff. Now `createWorkload` logs at V(3) that the Workload already exists but is not in the cache yet, and returns `nil`. Other create errors keep the existing error log and return path.

The change touches two files:
- `pkg/controller/jobs/leaderworkerset/leaderworkerset_reconciler.go`: adds the `apierrors` import and the `AlreadyExists` check in `createWorkload` (+5 lines).
- `pkg/controller/jobs/leaderworkerset/leaderworkerset_reconciler_test.go`: adds a `staleWorkloadCache` test field. When set, the test client's `List` for `WorkloadList` returns no results. The new case "should not fail when the workload cache has not seen an earlier create" seeds a Workload with the expected name, owned by the LeaderWorkerSet through an owner reference. It expects reconciliation to succeed and leaves that Workload unchanged. The test clears the flag before it reads stored Workloads.

Test results for this head are not available.

### Suggested release note

```text
LeaderWorkerSet: Fixed a bug that caused an error log and a requeue with backoff when the reconciler tried to create a Workload that already existed while the Workload cache had not yet observed it. Now Kueue treats the existing Workload as created. The reconciler logs the condition at verbosity 3 and does not requeue the LeaderWorkerSet.
```

No feature gate applies to this change.
