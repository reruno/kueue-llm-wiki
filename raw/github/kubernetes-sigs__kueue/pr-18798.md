#### What this PR does / why we need it?
Validates `deviceClassMappings[].deviceClassNames` as DeviceClass names (DNS subdomain, up to 253 characters) instead of label keys, so valid names longer than 63 characters no longer stop Kueue from starting. The check is one helper, `validateDeviceClassName`. `excludeDeviceClassNames` (#18632) can reuse it.

Part of #18780

## AI summary

This PR changes how Kueue validates `deviceClassMappings[].deviceClassNames` in the configuration API.

- Validation now uses DNS-subdomain rules instead of label-key rules.
- Valid DeviceClass names can be up to 253 characters. The DNS-subdomain check enforces this limit, so a separate length check is removed.
- The validation logic is in a new `validateDeviceClassName` helper. The helper returns an invalid-field error for each DNS-subdomain validation message.
- Names with uppercase letters, underscores, or the `prefix/name` form now fail validation at startup.
- `DeviceClassNames` documentation in the API types and the `kueue-config.v1beta2` reference now describe each entry as a DNS subdomain.
- Unit tests in `TestValidateDeviceClassMappings` use the `name.domain` format. They add cases for these results:
  - A name whose first DNS label exceeds 63 characters is accepted.
  - Uppercase names, underscores, `example.com/gpu`, and names with leading or trailing dots or dashes are rejected.
- `excludeDeviceClassNames` is not changed. It is not on `main`.

Review findings and CI results were not supplied. Their counts and status are not available.

### Suggested release note

ACTION REQUIRED: ConfigAPI: Fixed a bug that caused Kueue to fail at startup when `deviceClassMappings[].deviceClassNames` contained a DeviceClass name longer than 63 characters. Now Kueue accepts DeviceClass names up to 253 characters that follow DNS-subdomain rules. Names that use uppercase letters, underscores, or the `prefix/name` form now fail validation at startup. Remove or correct these names before upgrading, because they cannot match a DeviceClass.
