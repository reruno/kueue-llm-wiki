#### What this PR does / why we need it?

Follow-up to #18750, as requested in https://github.com/kubernetes-sigs/kueue/pull/18750 ("Let's handle the blockAdmission configuration for a follow up").

With `waitForPodsReady.blockAdmission` enabled, the scheduler sets the `WaitingForPodsReady` condition on the head Workload and then blocks until all admitted Workloads are PodsReady. When that status write fails with NotFound, the Workload was deleted, yet the scheduler still waited for PodsReady on its behalf and then attempted an admission that could only fail and be rolled back.

The scheduler now skips both the wait and the admission when the Workload was deleted, and requeues the entry without a status update. The requeue drops the deleted Workload.

Related: #18732

## AI summary

This PR changes how the scheduler handles a head Workload that is deleted while `waitForPodsReady.blockAdmission` is enabled.

- `waitForPodsReadyIfNeeded` now returns `deleted bool`.
- When the quota reservation status update returns NotFound, the function logs at V(3) "Workload not admitted because it was deleted" and returns `true`. It does not wait for PodsReady.
- When no update is made, the function performs a follow-up lookup. If the Workload is missing, it reports deletion in the same way.
- Other update errors are logged with `log.Error`. The function then calls `s.waitForPodsReady(ctx)` and returns `false`.
- The `Scheduler` struct has a new `waitForPodsReady func(context.Context)` field. `New` sets it to `cache.WaitForPodsReady`. Tests can replace it.
- `processEntry` sets `e.inadmissibleMsg` to "Workload was deleted" and `e.skipStatusUpdate` to true, then returns before admission.
- `TestSchedulerSkipsPodsReadyWaitForDeletedWorkload` runs with `WorkloadRequestUseMergePatch` disabled and enabled. It replaces the PodsReady wait with a hook and counts admission attempts. It fails if the hook is called, if an admission attempt occurs, if an error log is recorded, or if an event is recorded.
- The cancellation comment in `TestStatusUpdateWhenWorkloadDeleted` now states that cancellation prevents a hang if `WaitForPodsReady` is called.
