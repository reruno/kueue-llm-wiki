## Description

#### What type of PR is this?

/kind bug
/area concurrent-admission

#### What this PR does / why we need it?

With ConcurrentAdmission, the Parent Workload is not queued, while each of its Variants is. #18748 made the ClusterQueue pending counts count each Parent once. The LocalQueue counts still counted every Variant, so one Job in a ClusterQueue with three flavors reported 3.

The LocalQueue status also counted the Parent itself, because the Parent could still enter the LocalQueue items through three paths that the existing Parent check did not cover:

1. After a Kueue restart, the LocalQueue is added after its Workloads, and `addLocalQueueLocked` added the Parent. It now skips Workloads with the Parent label, as `ClusterQueue.AddFromLocalQueue` already does.
2. After a Kueue restart, a Parent event can arrive before its ClusterQueue is added to the queue manager. The Parent check looked up the ClusterQueue policy, so it missed the Parent. It now checks the Parent label first and falls back to the ClusterQueue policy for a new Parent that is not labeled yet.
3. When an admitted Variant is evicted, the Parent is evicted too and is requeued immediately through `AddOrUpdateWorkloadWithoutLock`, which had no Parent check. The check moved from `AddOrUpdateWorkload` into `AddOrUpdateWorkloadWithoutLock`, so both paths use it.


Part of #18747

## AI summary

This change fixes LocalQueue pending counts when ConcurrentAdmission is enabled. Each Parent Workload is now counted once. Before this change, a Parent with several Variants was counted once per Variant. The LocalQueue status could also count the Parent itself after a restart or eviction.

Changes by file (7 files, +348/-65):

- `pkg/cache/queue/variant_parent_counts.go`: Indexes Variant counts by the Parent's namespaced `workload.Reference`. The code previously used the Parent UID. `variantParentKey` returns an empty key when the gate is disabled or the Variant has no Parent name. The excess calculation moves into a new `variantExcess` helper. Nil maps count as empty.
- `pkg/cache/queue/local_queue.go`: Adds a `delete` method and a `pendingCount` method. Per the raw summary, `AddOrUpdate` removes the old Variant count before it adds the new one. `pendingCount` subtracts excess Variants.
- `pkg/cache/queue/local_queue_counts.go`: Maintains active and inadmissible Variant counts per LocalQueue. Updates run on add, remove, update, and status moves. `pendingInLocalQueue` subtracts the Variant excess from each status total.
- `pkg/cache/queue/manager.go`:
  - `IsConcurrentAdmissionParentWithoutLock` treats a Workload with the Parent label as a Parent. This check runs only when the ConcurrentAdmission gate is enabled. It does not depend on the ClusterQueue being present.
  - `addLocalQueueLocked` skips Parent Workloads.
  - The Parent check moves from `AddOrUpdateWorkload` into `AddOrUpdateWorkloadWithoutLock`, so both update paths use it.
  - `PendingWorkloads` returns `pendingCount()` instead of the number of stored items.
  - Deletion and checkout call `q.delete`.
- `pkg/cache/queue/manager_test.go`: Adds tests for LocalQueue pending counts with the gate enabled and disabled.
- `pkg/cache/queue/variant_parent_counts_test.go`: Updates fixtures for the new key. Checks that `PendingInLocalQueue` returns the same active and inadmissible counts as `Pending`.
- `test/integration/singlecluster/controller/concurrentadmission/concurrent_admission_test.go`: Adds an integration test. It checks that the LocalQueue pending status and pending-workloads metric count a Parent once when two flavor Variants exist.

The author reports that the new unit tests and a `-race` run pass. I did not run them. No CI result is available for this review.
