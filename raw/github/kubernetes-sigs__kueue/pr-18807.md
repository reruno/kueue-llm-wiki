#### What this PR does / why we need it?

Manual cherry-pick of #17588 into `release-0.20`, requested after the automated cherry-picks encountered conflicts:
https://github.com/kubernetes-sigs/kueue/pull/17588#issuecomment-6897313485

Workloads can undercount Pod overhead when a PodSet already records overhead and also references a RuntimeClass. The fix merges PodSet and RuntimeClass overhead per resource using the larger value, checks RuntimeClass names when comparing suspended Jobs with prebuilt Workloads, and preserves the existing comparison for reserved Jobs that may still have running Pods.

The Pod-group role check keeps the recorded PodSet overhead bound across RuntimeClass updates so an oversized replacement cannot be ungated.

Related: #17588, #14274.

#### Release note

```release-note
Workloads now account for the higher of their declared Pod overhead and the RuntimeClass overhead. A RuntimeClass mismatch between a suspended Job and its prebuilt Workload is treated as out of sync; already admitted Jobs that may still have running Pods are not stopped by this new comparison during an upgrade.
```
