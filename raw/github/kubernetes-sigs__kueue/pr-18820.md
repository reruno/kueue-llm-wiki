<h2>Changes by Kind</h2>
<h3>Bug or Regression</h3>
<ul>
<li>API: Fixed a bug where, after upgrading to v0.20, kube-apiserver repeatedly failed to initialize its watch cache for the ClusterQueue, Cohort, LocalQueue, MultiKueueCluster and Workload CRDs, because the Kueue manager no longer served the <code>/convert</code> conversion webhook that these CRDs still configure for the unserved <code>kueue.x-k8s.io/v1beta1</code> version. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18411">#18411</a>, <a href="https://github.com/alanhuangch"><code>@​alanhuangch</code></a>)</li>
<li>CLI: Fixed a bug where <code>kueuectl create clusterqueue</code> rejected valid quota values, such as <code>cpu=1e-3</code> or the resource name <code>foo--bar.example.com/gpu</code>, and accepted flavor or resource names that the API server rejects. Errors now name the invalid spec and flag. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18540">#18540</a>, <a href="https://github.com/Eason09053360"><code>@​Eason09053360</code></a>)</li>
<li>DQO: Fixed a bug where CapacityProviders that together reported more than 64 distinct resources for a flavor could leave stale effective capacity marked as computed. Kueue now sets <code>EffectiveCapacityComputed=False</code> with reason <code>AggregationFailed</code> and clears <code>status.effectiveCapacity</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17698">#17698</a>, <a href="https://github.com/7xuanlu"><code>@​7xuanlu</code></a>)</li>
<li>DQO: Fixed a bug where a long Distributed condition message (over 32 KiB) caused the API server to reject the DynamicQuotaOrchestrator status update. Kueue now truncates the message. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18644">#18644</a>, <a href="https://github.com/vshalpnjabi"><code>@​vshalpnjabi</code></a>)</li>
<li>DynamicQuotaOrchestrator: Report Distributed=Unknown with reason DistributionIncomplete when quota redistribution fails instead of retaining a stale success condition. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18675">#18675</a>, <a href="https://github.com/mbobrovskyi"><code>@​mbobrovskyi</code></a>)</li>
<li>ElasticJobsViaWorkloadSlices: Fixed a bug where a ClusterQueue charged both a workload slice and its replacement during an elastic scale-up, so its usage could briefly exceed the quota and block or preempt other workloads. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18648">#18648</a>, <a href="https://github.com/Pradeep39"><code>@​Pradeep39</code></a>)</li>
<li>FairSharing: Fix a bug where workloads waiting for their second pass of scheduling (for example a delayed topology assignment) were skipped and requeued with backoff when their ClusterQueue also nominated a pending workload in the same cycle. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18674">#18674</a>, <a href="https://github.com/mbobrovskyi"><code>@​mbobrovskyi</code></a>)</li>
<li>Fixed a bug where any RuntimeClass create, update, or delete requeued every pending Workload in the cluster. Kueue now reconciles only pending Workloads that use that RuntimeClass. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/17386">#17386</a>, <a href="https://github.com/dlanov"><code>@​dlanov</code></a>)</li>
<li>Job integrations: Fixed a race where changing a suspended job's queue and workload priority together could expose the new priority in the old queue before the queue change was applied. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18468">#18468</a>, <a href="https://github.com/guming-learning"><code>@​guming-learning</code></a>)</li>
<li>KueueViz: Fixed &quot;Pod Sets Count&quot; on workload pages showing the first pod set's pod count instead of the number of pod sets. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18678">#18678</a>, <a href="https://github.com/mbobrovskyi"><code>@​mbobrovskyi</code></a>)</li>
<li>LocalQueue: Fix an issue where stopping a LocalQueue wiped its cumulative counters and histograms, and deleting a stopped LocalQueue failed to remove its metric series. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18361">#18361</a>, <a href="https://github.com/vic-comm"><code>@​vic-comm</code></a>)</li>
<li>Manifests: Keep metrics authentication and authorization enabled in the alpha-enabled manifest by explicitly setting DisableMetricsAccessControl=false, preventing metrics bind-address validation failures with AllAlpha=true. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18399">#18399</a>, <a href="https://github.com/ankushbbbr"><code>@​ankushbbbr</code></a>)</li>
<li>MultiKueue: Fixed a bug where Kueue ignored a ClusterProfile CRD installed after kueue-controller-manager started, so <code>MultiKueueCluster</code> objects that use clusterProfileRef (alpha MultiKueueClusterProfile feature gate) stayed inactive until a restart. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18450">#18450</a>, <a href="https://github.com/yindia"><code>@​yindia</code></a>)</li>
<li>MultiKueue: Fixed a bug where a Workload could stay pending forever when no worker cluster was connected at its first nomination, for example while the only worker was reconnecting. Kueue now retries the Workload until a worker cluster is connected. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18428">#18428</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
<li>MultiKueue: Fixed a bug where the MultiKueue admission check on the manager stayed <code>Pending</code> with an empty message when no worker could reserve quota. The message now lists the <code>QuotaReserved</code> reason and message reported by each worker cluster, such as <code>DRAResourcesUnresolved</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18605">#18605</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>Observability: Changing a custom metric label value on a ClusterQueue, LocalQueue, or Cohort now keeps the object's counter and histogram series under the old value only when every custom label of that kind sets <code>trackedValues</code>. Previously ClusterQueue and LocalQueue always reset them, and Cohort always kept them. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18519">#18519</a>, <a href="https://github.com/Andrushika"><code>@​Andrushika</code></a>)</li>
<li>Observability: Fixed a bug that caused <code>kueue_cohort_subtree_admitted_active_workloads</code> to over-count when CustomMetricLabels was enabled. Each series now counts workloads only from ClusterQueues with matching custom label values. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18078">#18078</a>, <a href="https://github.com/vshalpnjabi"><code>@​vshalpnjabi</code></a>)</li>
<li>Observability: Fixed a bug where a Workload status change while its LocalQueue referenced a deleted ClusterQueue could leave stale unadmitted-workload metric series. Kueue now reports the retained metrics with the recreated ClusterQueue’s labels. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18455">#18455</a>, <a href="https://github.com/akshat-lakhera"><code>@​akshat-lakhera</code></a>)</li>
<li>Preemption: Fixed a bug where the capacity reservation made when a preempting Workload finds no candidates could go negative for a ClusterQueue already using more than its nominal quota plus borrowing limit, which could keep another Workload from preempting that ClusterQueue's workloads in the same scheduling cycle. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18618">#18618</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>ProvisioningRequest: Fixed a bug where <code>podSetMergePolicy</code> merged PodSets admitted to different ResourceFlavors, so the ProvisioningRequest requested all their capacity on the first PodSet's flavor. Kueue now merges only PodSets assigned to the same flavors. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18676">#18676</a>, <a href="https://github.com/mbobrovskyi"><code>@​mbobrovskyi</code></a>)</li>
<li>Scheduling: Fixed a bug where Kueue could set Pod node selectors nondeterministically when assigned ResourceFlavors specified conflicting values for the same node label. Kueue now keeps the value from the first flavor in sorted resource-name order. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18369">#18369</a>, <a href="https://github.com/bolubo"><code>@​bolubo</code></a>)</li>
<li>TAS: Fixed a bug where Jobs that request a topology, and whose Workloads were admitted while the <code>TopologyAwareScheduling</code> feature gate was disabled, were stopped and requeued after the gate was enabled. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18575">#18575</a>, <a href="https://github.com/kshalot"><code>@​kshalot</code></a>)</li>
<li>TAS: Fixed a bug where equal-capacity topology domains broke ties alphabetically instead of packing smaller or partially-occupied ancestor domains first, which could unnecessarily fragment larger intact ancestor blocks. This behavior is controlled by the <code>TASAncestorCapacityTieBreak</code> feature gate (Beta, enabled by default). (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18537">#18537</a>, <a href="https://github.com/HristoMohamed"><code>@​HristoMohamed</code></a>)</li>
<li>TAS: Fixed a bug where preferred node affinity could be ignored, placing Pods on a less preferred domain, when <code>TASCacheNodeMatchResults</code> reused cached node matches. This affects users who enabled <code>TASRespectNodeAffinityPreferred</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18436">#18436</a>, <a href="https://github.com/adibmbrk"><code>@​adibmbrk</code></a>)</li>
<li>TAS: Fixed a bug where, with TASRespectNodeAffinityPreferred enabled, a node that could not run the Pod still added its preferred-affinity score to its topology domain, so TAS could choose a less preferred node. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18459">#18459</a>, <a href="https://github.com/sohankunkerkar"><code>@​sohankunkerkar</code></a>)</li>
</ul>
