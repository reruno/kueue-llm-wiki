## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

When a ClusterQueue's `cohortName` changes, `Manager.UpdateClusterQueue` moved it to its new cohort first and then requeued inadmissible Workloads by the ClusterQueue's root, which by then is the new root. The cohort it left gets back the quota the ClusterQueue was borrowing there, but its inadmissible Workloads stayed pending until some unrelated event in that cohort. The cohort controller doesn't cover this when the old parent is a root (a flat cohort, explicit or implicit), since `ClusterQueueAncestors` leaves the root out. `AddOrUpdateCohort` had the same order, so a Cohort whose `parentName` changes left its old tree without a requeue too.

Both now read the old root before the edge moves, and requeue it as well when it differs from the new one.

Fixes #18833

#### Useful notes for your reviewer

Tests, all of which fail on main and pass with the fix:
- `TestQueueInadmissibleWorkloads`: a ClusterQueue moving to another cohort, a ClusterQueue leaving its cohort, and a Cohort moving to another parent. The runner gets `updatedClusterQueues` and `updatedCohorts`, applied after the setup requeues are processed, so only the update can move the Workloads.
- Integration, `scheduler` suite: a borrowing ClusterQueue moves to another cohort, and the pending Workload in the cohort it left is admitted.

#18522 edits the same lines of `UpdateClusterQueue` for StrictFIFO retries, so whichever lands second needs a small rebase.

I used an AI assistant while preparing this PR.

## AI summary

This PR fixes missed retries of inadmissible Workloads when a ClusterQueue changes Cohorts or a Cohort changes parents.

Before this change, `Manager.UpdateClusterQueue` and `Manager.AddOrUpdateCohort` moved the node first. They then requeued inadmissible Workloads by the new root only. The old tree was not requeued, so its Workloads could stay pending after the moved node freed borrowed quota.

Changes:
- `pkg/cache/queue/manager.go`:
  - `AddOrUpdateCohort` reads the old root before it updates the edge. It requeues the new root. It also requeues the old root when the root changed.
  - `UpdateClusterQueue` reads the old root before it updates the edge. When `requeueInadmissibleWorkloads` is set and the root changed, it also requeues the old root.
  - A new helper, `rootOfTree`, returns the root of a non-nil Cohort tree that has no cycle.
- `pkg/cache/queue/manager_test.go`: `TestQueueInadmissibleWorkloads` adds cases for a ClusterQueue moving to another Cohort, a ClusterQueue leaving its Cohort, and a Cohort changing parents. Each case checks the moved Workloads and the active Workloads.
- `test/integration/singlecluster/scheduler/scheduler_test.go`: adds an integration test. A 5-CPU Workload in `move-cq-1` stays pending while `move-cq-2` borrows its quota. After `move-cq-2` moves to `move-new`, the pending Workload is admitted.
