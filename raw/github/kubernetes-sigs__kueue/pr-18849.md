### Comment by [@ivnovakov](https://github.com/ivnovakov) — 2026-11-16T12:09:56Z

The root `OWNERS` filters are new for this repo. Today the root filters cover file types at any depth (`_test.go`, `go.mod`, `Dockerfile`) and a few root and `hack/make` files. Area rules live next to the code. `pkg/controller/jobframework/OWNERS` already has filters for `jobframework-implementation-approvers`. #15119 moved the `site/` rules from the root `OWNERS` into `site/OWNERS`.

So these two could move next to the code. In `pkg/controller/jobframework/OWNERS`:
```yaml
  "^tas[^/]*\\.go$":
    reviewers:
    - tas-reviewers
```
In `site/OWNERS`:
```yaml
  "^content/en/docs/(concepts|tasks)/.*topology[^/]*\\.md$":
    reviewers:
      - tas-reviewers
```
I checked this locally with Prow's owners parser. You are suggested on the same 4 `tas*.go` files and the same 4 topology docs, and the approvers don't change. The other root filters stay, since `pkg/scheduler/`, `pkg/cache/scheduler/` and `apis/` have no `OWNERS` file.

Should we move these two, so they match how the other areas are set up?
