#### What this PR does / why we need it?

Follow-up to #18830, as suggested in https://github.com/kubernetes-sigs/kueue/pull/18830#issuecomment-6913530556.

The eight remaining cases in the StatefulSet `TestReconciler` set `TopologyAwareScheduling` to `false` only to avoid the pod index label that TAS adds to the PodSet. This PR removes the override and expects the label, so these cases run with the default feature gates.

The webhook case "conflicting TAS annotations are accepted when TAS is disabled" keeps the override.

Part of #18804

## AI summary

This PR changes one test file: `pkg/controller/jobs/statefulset/statefulset_reconciler_test.go` (+35/-18). No production code changed.

- Eight `TestReconciler` cases drop their `features.TopologyAwareScheduling: false` override. These cases now run with the default TAS feature gate.
- Seven of those cases gain an expected `TopologyRequest` with `PodIndexLabel` on their created Workload's PodSet. These are the replicas > 0 case, the two CustomMetricLabels cases, the legacy-fallback-disabled case, the two AdmissionGatedBy propagation cases, and the AdmissionGatedBy gate-disabled case. The WaitForPodsReady gate-disabled case also gains the expectation, which makes eight cases with the new expectation.
- The "should create workload with TAS topology request when TAS enabled" case drops its `TopologyAwareScheduling: true` override. It does not gain a new expectation in this diff.
- Other feature-gate settings in these cases stay unchanged.
- No `TestReconciler` case covers the TAS-disabled branch in `constructWorkload` after this change. A counterpart test is not part of this diff.
