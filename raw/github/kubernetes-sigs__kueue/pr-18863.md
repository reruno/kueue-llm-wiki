#### What this PR does / why we need it?

The Pod webhook accepted any `kueue.x-k8s.io/pod-group-total-count` value that parses as an int and is at least 1. With the fast-admission annotation, `constructGroupPodSetsFast` converts that value to the int32 PodSet count, so a value above 2147483647 wrapped around (for example `4294967297` became `1`) and the group Workload would be built with the wrong count.

This adds an explicit, commented check in `validatePodGroupMetadata` that rejects values above `math.MaxInt32`, in the same style as the existing `max-exec-time-seconds` upper-bound check.

**Behavior change**
- Now: a Pod whose `kueue.x-k8s.io/pod-group-total-count` is above 2147483647 is rejected by the webhook with an `Invalid` error on that annotation (`should be less than or equal to 2147483647`).
- Unchanged: values from 1 to 2147483647 are accepted as before; `0`, empty and non-numeric values are rejected as before. The controller's own parsing of the annotation is not changed.
- Existing objects: Pods already created with such a value are not revalidated until they are updated.

Fixes #18862
