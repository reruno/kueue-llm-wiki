#### What this PR does / why we need it?

The Pod webhook accepted any `kueue.x-k8s.io/pod-group-total-count` value that parses as an int and is at least 1. With the fast-admission annotation, `constructGroupPodSetsFast` converts that value to the int32 PodSet count, so a value above 2147483647 wrapped around (for example `4294967297` became `1`) and the group Workload was built with the wrong count.

This PR adds the int32 bound to `groupTotalCount()`, next to the existing `gtc < 1` check. The Pod webhook (create and update, through `validatePodGroupMetadata`) and the Pod controller (including `constructGroupPodSetsFast`) all read the count through this function, so one check covers all of them. The check is behind a new Beta feature gate, `PodGroupValidateTotalCountAnnotation`, enabled by default.

**Behavior change**
- Gate: `PodGroupValidateTotalCountAnnotation`, Beta, enabled by default.
- With the gate on, a count above 2147483647 is an error on create, on update, and in the controller. The webhook returns an `Invalid` error on `metadata.annotations[kueue.x-k8s.io/pod-group-total-count]`, and the controller does not build a Workload for such a group.
- Existing Pods with an oversized count cannot be updated while the gate is on.
- Turning the gate off restores the old behaviour: such values are accepted again.
- Unchanged: values from 1 to 2147483647 are accepted as before. Missing, empty (`""`) and malformed values on a Pod group member are rejected as before, regardless of the gate.

Fixes #18862
