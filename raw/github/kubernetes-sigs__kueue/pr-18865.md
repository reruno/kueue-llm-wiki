#### What this PR does / why we need it?

Follow-up to #18832, as suggested in https://github.com/kubernetes-sigs/kueue/pull/18832#issuecomment-6913954011.

Seventeen cases in the Pod integration unit tests set `TopologyAwareScheduling` to `false` only to avoid what TAS adds to the expected result. This PR removes the override and expects it, so these cases run with the default feature gates:

- `TestDefault`: sixteen cases now expect the topology scheduling gate on the Pod.
- `TestPodSets`: "no annotations" now expects the pod index label on the PodSet.

The two "... if TAS is disabled" cases in `TestPodSets` and "index-label annotation naming an absent label, TAS disabled" in `TestValidateCreate` keep the override.

It also adds the `TestDefault` case "pod with PodGroupPodIndexLabelAnnotation when TAS disabled", so the gate-off branch of the webhook stays covered.

It also removes the explicit `TopologyAwareScheduling: true` from the eight "pod with TAS ..." cases in `TestDefault`, because TAS is enabled by default.

Part of #18804
