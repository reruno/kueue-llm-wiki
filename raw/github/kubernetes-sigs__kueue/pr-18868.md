#### What this PR does / why we need it?

A StatefulSet scaled to zero retains its Workload in OnHold. On resume, the controller resynchronizes the PodSet count, while the topology request still reflects the template used for initial Workload creation. A valid topology annotation update can therefore be accepted on the StatefulSet and omitted from the next Workload admission.

Refresh the retained PodSet topology request before releasing OnHold. Reuse the existing topology-request builder for creation and resume, including its Pod index metadata and existing feature-gate behavior. Persist the updated Workload spec before allowing it to compete for admission.

This extends the retained-Workload lifecycle and replica-count synchronization. StatefulSet update validation already accepts legal topology changes that this fix propagates. [#12233](https://github.com/kubernetes-sigs/kueue/pull/12233), [#15279](https://github.com/kubernetes-sigs/kueue/pull/15279), [#16039](https://github.com/kubernetes-sigs/kueue/pull/16039)

Fixes #18867

## AI summary

This PR fixes a StatefulSet resume case in TAS. When a retained Workload leaves `OnHold` after a scale-up from zero, Kueue now refreshes its topology request from the current Pod template. Before this change, the Workload kept the topology request from its initial creation. The Workload then could admit Pods under an outdated topology constraint.

Changes:

- `pkg/controller/jobs/statefulset/statefulset_reconciler.go`: When `reconcileWorkload` releases a Workload from hold, it also derives the topology request from the StatefulSet when TopologyAwareScheduling is enabled. It returns any derivation error. It updates the Workload only when the request differs. `constructWorkload` uses the same topology-request helper.
- `pkg/controller/jobs/statefulset/statefulset_topology_test.go`: Adds `TestReconcilerResumeTopology`. The test covers topology changes, replica-count refresh, TAS-disabled and already-resumed cases, failed updates, and invalid topology construction.
- `test/integration/singlecluster/controller/jobs/statefulset/statefulset_controller_test.go`: Adds a TAS integration test. A two-replica StatefulSet scales to zero, then resumes with a required hostname topology. The test checks that the Workload keeps its UID, stays blocked until one hostname fits both Pods, and is admitted after capacity is added.
- `test/integration/singlecluster/controller/jobs/statefulset/suite_test.go`: Registers TAS indexes and starts TAS controllers in the test manager, checking each setup error.

Validation: The author reports passing unit tests, the StatefulSet integration suite (26/26), a focused regression run with `--repeat=4`, and `make verify`. These results were not re-run for this summary. Physical Pod execution with kube-scheduler and kubelets is not tested.

## Suggested release note

```release-note
StatefulSet: Fixed a bug that caused a resumed StatefulSet to keep a stale TAS topology request when its Pod template changed while the Workload was on hold after scale-to-zero. Now Kueue refreshes the Workload topology request from the Pod template before it releases the Workload from hold. This behavior is gated by the TopologyAwareScheduling feature gate.
```
