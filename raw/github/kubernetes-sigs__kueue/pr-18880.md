## Description

#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it?

Builds the manifests with `kubectl kustomize` and removes the pinned standalone kustomize binary.

#18919 already replaced `kustomize edit` with yq, so this PR finishes the removal.

- `kustomize build` is now `$(KUBECTL) kustomize`. `$(KUBECTL)` is the kubectl that `make kubectl` installs, so kustomize is the version that kubectl includes: v5.8.1 for the current kubectl v1.36.4. It now changes when the e2e Kubernetes version is bumped.
- `make kubectl` now skips the download when the right version is already installed, like `make helm`.
- The kustomize pin is removed from `hack/tools`, `hack/make/deps.mk`, the tools installer and the docs.

Fixes #11075

#### Useful notes for your reviewer

| Behavior | Command and result |
|---|---|
| Built manifests do not change | All 40 kustomizations build the same with kustomize v5.8.3 and with `kubectl kustomize` |
| Release manifests do not change | The 12 release files are identical to `main` |
| `make kubectl` skips when installed | Skips with no network, downloads into an empty `bin/`, downloads again when `KUBECTL_VERSION` changes |
| Works offline | `make compile-crd-manifests` passes with no network when kubectl is installed |
| Verify | `make kustomize-build-verify`, `make verify-ci-tools` and `hack/testing/verify-generation-order_test.sh` pass. `go mod tidy` in `hack/tools` is clean |

## AI summary

This change removes the standalone kustomize binary from Kueue's build and tooling. Manifest builds now use `$(KUBECTL) kustomize`, so the kustomize version comes from the installed kubectl.

### Changes

- **Build and manifest rendering:** `Makefile`, `hack/make/verify.mk`, and `hack/testing/e2e-common.sh` render CRDs, manifests, and alpha-CRD comparisons with `kubectl kustomize`. The exported `KUSTOMIZE` variable is removed from `hack/testing/e2e-common.sh`.
- **Tool dependencies:** `hack/make/deps.mk` removes the Kustomize version variable, binary variable, and install target. `hack/tools/go.mod` and `hack/tools/pinversion.go` drop the `sigs.k8s.io/kustomize/kustomize/v5` dependency. `hack/tools-installer/data.json` and `install_test.py` drop the `kustomize` entry.
- **kubectl target:** The `kubectl` target in `hack/make/deps.mk` skips the download when the installed client version matches `KUBECTL_VERSION`.
- **E2E and test prerequisites:** `hack/make/test.mk` and `hack/testing/verify-generation-order_test.sh` replace the `kustomize` prerequisite with `kubectl`. The `kueue-populator` scripts build `kubectl` and pipe `kubectl kustomize` output to `kubectl apply`.
- **Documentation:** `ENVIRONMENT_DEPENDENCIES_POLICY.md` and the development guide no longer list `kustomize`.

### Scope and behavior

- Apply, delete, artifact path, and `ignore-not-found` behavior is unchanged.
- Kustomize output depends on the kubectl version. The kustomize version changes when `KUBECTL_VERSION` changes.
- The PR description reports that the rendered output matches the previous kustomize build for all 40 kustomizations. The author reports these checks as passing: `make kustomize-build-verify`, `make verify-ci-tools`, `hack/testing/verify-generation-order_test.sh`, and `go mod tidy` in `hack/tools`. These results are author-reported. CI results were not available for this summary.

### Linked issue

This PR addresses `#11075`, which asks to remove the kustomize dependency and use the built-in kubectl kustomize plugin.
