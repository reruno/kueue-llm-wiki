#### What type of PR is this?

#### What this PR does / why we need it?

Follow-up to #18865.

`TopologyAwareScheduling` is enabled by default, so setting it to `true` changes nothing. This PR removes that override from the ten Pod cases that have it: five in `TestValidateCreate`, four in `TestPodSets` and one in `TestReconciler`.

The four cases that set it to `false` stay, because they cover TAS disabled.

Part of #18804

## AI summary

This PR removes redundant `TopologyAwareScheduling: true` feature gate overrides from Pod unit tests. The tests do not change behavior. The overrides are removed from 10 test cases:

- `pkg/controller/jobs/pod/pod_webhook_test.go`: 5 cases in `TestValidateCreate`, covering invalid pod-group index-label annotations.
- `pkg/controller/jobs/pod/pod_controller_test.go`: 4 cases in `TestPodSets` and 1 case in `TestReconciler`, covering required/preferred topology, topology spreading, and implicit TAS for prebuilt workloads.

The `TASTopologySpreading` settings remain in the spreading tests. Four cases that set `TopologyAwareScheduling` to `false` remain, so the TAS-disabled paths stay covered.
