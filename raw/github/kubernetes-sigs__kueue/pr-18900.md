#### What this PR does / why we need it?

Same cleanup as #18890.

`TopologyAwareScheduling` is enabled by default, so setting it to `true` changes nothing. This PR removes that override from the 33 cases that have it: 17 for RayJob, 14 for RayCluster and 2 for RayService.

The cases that set it to `false` stay, because they cover TAS disabled.

Part of #18804

## AI summary

This change removes redundant `TopologyAwareScheduling: true` feature-gate overrides from unit tests for the RayJob, RayCluster, and RayService integrations. It touches 6 test files and removes 33 lines. No production code changes.

- `raycluster_controller_test.go`: removes 4 overrides from `TestPodSets`.
- `raycluster_webhook_test.go`: removes 10 overrides from `TestValidateCreate`.
- `rayjob_controller_test.go`: removes 6 overrides from `TestPodSets`.
- `rayjob_webhook_test.go`: removes 11 overrides from `TestValidateCreate`.
- `rayservice_controller_test.go`: removes 1 override from the topology-annotation PodSet test.
- `rayservice_webhook_test.go`: removes 1 override from the elastic-job required-topology test.

The tests keep their expected results. Cases that set `TopologyAwareScheduling` to `false` remain. These cases still cover the TAS-disabled behavior. The `TopologyAwareScheduling` gate is enabled by default, so the removed overrides do not change test behavior.
