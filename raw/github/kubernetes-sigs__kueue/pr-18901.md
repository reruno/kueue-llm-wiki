#### What this PR does / why we need it?

Same cleanup as #18890.

`TopologyAwareScheduling` is enabled by default, so setting it to `true` changes nothing. This PR removes that override from the 30 places that have it: 13 for JobSet, 13 for AppWrapper and 4 for SparkApplication.

The cases that set it to `false` stay, because they cover TAS disabled.

Part of #18804

## AI summary

This PR removes redundant `features.TopologyAwareScheduling: true` test setup from five unit-test files:

- `appwrapper_controller_test.go`: removes gate overrides from pod-set and `RunWithPodSetsInfo` cases. Adds an empty-configuration case for ungrouped PyTorchJob.
- `jobset_controller_test.go`: removes gate overrides from the required- and preferred-topology annotation cases.
- `jobset_webhook_test.go`: removes gate overrides from topology-related create and update cases.
- `sparkapplication_controller_test.go`: removes the gate override from the "with TopologyAwareScheduling" case.
- `sparkapplication_webhook_test.go`: removes the legacy gate from the elastic-job and base TAS `TestValidateCreate` cases.

Test inputs and expected results stay the same. Overrides set to `false` remain. The diff touches only test files: 2 insertions and 34 deletions across 5 files.

The PR author states that TopologyAwareScheduling is enabled by default, so the removed `true` overrides do not change test behavior.
