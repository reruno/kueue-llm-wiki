#### What this PR does / why we need it?

After a leader change, Kueue could evict a healthy TAS Workload from a stale second-pass copy. Every replica queues second passes, but only the leader takes them. When an update shows that a Workload no longer needs one, `QueueSecondPassIfNeeded` removes the entry only at `iteration > 0`, which the update handler never passes. A new leader then replays the old copy, and the fail-fast eviction (a loose apply, retried on conflict) lands on a Workload whose node was already replaced or had recovered.

This PR:

1. lets only the Workload update handler drop the ready copy once it isn't needed (finishes #8357): updates arrive in order, so the newest version decides. A pending backoff stays;
2. makes the fail-fast eviction strict, like the second-pass admission write (#15761). On Conflict the eviction is skipped with `OutdatedScheduleCycle`, and the requeue re-reads the Workload.

Fixes #18920
