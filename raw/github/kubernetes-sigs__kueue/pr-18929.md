#### What this PR does / why we need it?

Cherry-pick of #17374 to `release-0.19`, as [requested](https://github.com/kubernetes-sigs/kueue/pull/17374#issuecomment-6929689051). Releases unused topology reservations after elastic Jobs shrink so waiting Jobs can use the freed capacity.

#### Useful notes for your reviewer

Retains the original fix and regressions, with compatibility adjustments for 0.19: read reclaimable counts directly from status, retain the older reconcile request syntax, and use hostname topology in the Job fixture. This release only applies the fixture's Pod node selectors at hostname level.

| Behavior | Level | Command and result | Not run and why |
| --- | --- | --- | --- |
| Shrink validation, reclaimable counts, and queue wakeup | unit | `go test -race -count=1 ./pkg/controller/tas ./pkg/controller/core ./pkg/cache/queue` — passed | — |
| Capacity reuse, zero/regrowth, grouped reservations, and node recovery | integration | Ginkgo focus `Job controller with TAS and ElasticJobsViaWorkloadSlices\|should defer elastic shrink until an unhealthy node recovers` — all seven cases passed with race detection and envtest Kubernetes 1.36.2 | — |

The two capacity-release integration regressions also fail as expected when the shrink fix is removed.

`make verify` passed.

AI assistance was used to prepare this cherry-pick.

#### Release note

```release-note
TAS × ElasticJobsViaWorkloadSlices: Fixed a bug where an elastic Job kept unused topology capacity reserved after scaling down, preventing waiting Workloads from using it. Kueue now releases that capacity once the removed Pods terminate.
```
