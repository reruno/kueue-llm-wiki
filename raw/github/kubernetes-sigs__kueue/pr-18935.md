#### What this PR does / why we need it?

Combines three changes on upstream main at `72af8ddd1` for combined CI validation. Not meant to be merged. It replaces #18927 (closed) and adds one commit.

- `a1e7266be`: the cluster-targeting annotation commit from #18288 (originally `31bd887b194fab9bee6dac33601e32c08384a49b`): the alpha, disabled-by-default `MultiKueueClusterNames` feature gate and the `kueue.x-k8s.io/multikueue-cluster-names` annotation.
- `c208cde74`: #18407 at `9cff6b2c5`, squashed. After a worker reconnects, MultiKueue requeues its Workloads, and the replayed remote ADDED watch events, at low priority.
- `c0d478500`: the new #18407 commit `91ef04cd7`. The periodic sync of an admitted Workload is requeued at low priority. Before, the priority queue kept the default priority of that pending sync when a reconnect enqueued the Workload again, so every admitted Workload of the worker was processed at the default priority and new Workloads waited behind them.

Related: #18407, #18927, #18288
