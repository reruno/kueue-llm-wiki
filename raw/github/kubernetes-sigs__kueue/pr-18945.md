#### What this PR does / why we need it?

Follow-up to #18899, as suggested in https://github.com/kubernetes-sigs/kueue/pull/18899#issuecomment-6938201194.

The MPIJob webhook checks the Worker pod index offset only when `TopologyAwareScheduling` is enabled, in `ValidateCreate` and in `ValidateUpdate`. No unit test failed when those two checks ignored the gate.

- `TestValidateUpdate`: the TAS-disabled case had no `runLauncherAsWorker`, so the offset was not managed and the case passed with TAS enabled too. It now sets `runLauncherAsWorker` and a wrong offset.
- `TestValidateCreate`: adds the same scenario as a pair, rejected with TAS enabled and accepted with TAS disabled.

With both checks replaced by `true`, these two cases fail and the rest of the package passes.

Fixes #18804
