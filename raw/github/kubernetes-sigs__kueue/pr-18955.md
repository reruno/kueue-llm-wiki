#### What this PR does / why we need it?

Same cleanup as #18890, for the integration tests.

`TopologyAwareScheduling` is enabled by default, so setting it to `true` changes nothing. This PR removes that override from the five places that have it under `test/integration`: two AppWrapper specs, the ConfigurablePreemptions suite setup, one TAS elastic accounting spec and one StatefulSet webhook spec.

Part of #18804

## AI summary

This change removes explicit `TopologyAwareScheduling` feature gate overrides from four integration test files under `test/integration`. It changes 6 lines and removes no assertions or setup other than those overrides.

- `singlecluster/controller/jobs/appwrapper/appwrapper_controller_test.go`: removes the gate enablement from two topology-placement specs (PyTorchJob and JobSet).
- `singlecluster/scheduler/configurablepreemptions/suite_test.go`: removes the gate enablement from `BeforeSuite`. The suite still enables `ConfigurablePreemptions` and `PrioritizePreemptorWorkloads`.
- `singlecluster/tas/elastic_accounting_test.go`: removes the gate enablement from the elastic replacement topology-accounting test. The two elastic workload-slice gates remain.
- `singlecluster/webhook/jobs/statefulset_webhook_test.go`: removes the gate enablement from the test that rejects conflicting topology annotations.

No controller, API, or user-facing code changes.
