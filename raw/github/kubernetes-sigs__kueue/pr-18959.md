## Description

Cherry pick of #18803 on release-0.20.

#18803: Drop a trailing dot when truncating generated object names

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

The cherry-pick robot failed on the import blocks of `pkg/cache/scheduler/was/virtual_pods.go` and `virtual_pods_test.go`, which differ on release-0.20 (`pkg/util/podset`, `k8s.io/utils/ptr`). I kept the branch's imports and added only `utilstrings` and `validation`. The rest of the change applies unchanged.

#### What type of PR is this?
/kind bug

#### Useful notes for your reviewer

`go build ./...`, `go vet` and `go test` pass for `pkg/util/strings`, `pkg/controller/jobframework`, `pkg/controller/admissionchecks/provisioning` and `pkg/cache/scheduler/was`. With release-0.20's original `workload_names.go`, `controller.go` and `virtual_pods.go`, the 5 new "truncated at a dot" cases fail. With this PR, they pass.

AI tools (Claude Code) assisted with this backport; the conflicts were resolved and the tests run as described above.

```release-note
Workloads: Fixed a bug that caused generated Workload and ProvisioningRequest names to contain `.-` after truncation. The API server rejected these names. Now Kueue removes trailing dots from the truncated name before it appends the hash suffix.
```
