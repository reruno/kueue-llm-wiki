## Description

Cherry pick of #18803 on release-0.19.

#18803: Drop a trailing dot when truncating generated object names

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

`pkg/cache/scheduler/was/virtual_pods.go` is not on release-0.19, so this PR leaves out the `virtualPodName` change and its test. The Workload and ProvisioningRequest name fixes apply unchanged. The two test-file conflicts are resolved as follows:
- The provisioning test keeps the branch's `metav1` import.
- `pkg/util/strings/strings_test.go` gets `TestTruncateNamePrefix` only. `TestJoinMap` came from main's context, and `JoinMap` is not on this branch.

#### What type of PR is this?
/kind bug

#### Useful notes for your reviewer

`go build ./...`, `go vet` and `go test` pass for `pkg/util/strings`, `pkg/controller/jobframework` and `pkg/controller/admissionchecks/provisioning`. With release-0.19's original `workload_names.go` and `controller.go`, the 4 new "truncated at a dot" cases fail. With this PR, they pass.

AI tools (Claude Code) assisted with this backport; the conflicts were resolved and the tests run as described above.

```release-note
Workloads: Fixed a bug that caused generated Workload and ProvisioningRequest names to contain `.-` after truncation. The API server rejected these names. Now Kueue removes trailing dots from the truncated name before it appends the hash suffix.
```
