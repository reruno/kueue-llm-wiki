<summary>Release notes</summary>

<blockquote>
<h2>v0.170.0</h2>
<p>The big change in this release is that <strong>the <em>extended</em> edition of Hugo is gone</strong>. LibSass has been deprecated for a long time, and it was the only remaining reason we needed a CGO-enabled extended build. There is now only one Hugo binary, and apart from LibSass it has all the features the extended build had.</p>
<h2>Notes</h2>
<ul>
<li>Setting <code>transpiler</code> to <code>libsass</code> in <a href="https://gohugo.io/functions/css/sass/"><code>css.Sass</code></a> now returns an error. <a href="https://gohugo.io/functions/css/sass/#dart-sass">Dart Sass</a> is now the default and the only transpiler, so you need to <a href="https://gohugo.io/functions/css/sass/#installation-overview">install it</a> if you use Sass.</li>
<li>We no longer publish <code>hugo_extended_*</code> archives. To avoid breaking existing CI setups, we publish aliases for the most downloaded extended archives (e.g. <code>hugo_extended_&lt;version&gt;_linux-amd64.tar.gz</code>, <code>hugo_extended_&lt;version&gt;_Linux-64bit.tar.gz</code>, the <code>linux-amd64.deb</code>, <code>linux-arm64.tar.gz</code> and <code>windows-amd64.zip</code>), but you should update your scripts to use the standard archives. The <code>extended_withdeploy</code> builds are also removed. See <a href="https://gohugo.io/installation/">Installation</a>.</li>
<li><a href="https://gohugo.io/functions/hugo/isextended/"><code>hugo.IsExtended</code></a> now always returns <code>false</code>, and the module config setting <code>hugoVersion.extended</code> is deprecated and has no effect.</li>
<li>Command-line flags (e.g. <code>--buildDrafts</code>) now override OS <a href="https://gohugo.io/configuration/introduction/#environment-variables">environment variables</a> (e.g. <code>HUGO_BUILDDRAFTS</code>). This also fixes <code>HUGO_ENVIRONMENT=qa hugo build -e staging</code> loading the <code>staging</code> config but reporting <code>qa</code> in <code>hugo.Environment</code>.</li>
<li><a href="https://gohugo.io/functions/strings/truncate/"><code>strings.Truncate</code></a> has been rewritten on top of a proper HTML scanner. It now handles comments, void elements, quoted attributes with <code>&gt;</code> and raw text elements such as <code>script</code> correctly, and it's faster and allocates less. On a curious note, the old version was implemented by <a href="https://github.com/biilmann">Mathias Biilmann</a>, the Netlify CEO.</li>
<li><code>time.Time</code> values now keep their named time zone, and <a href="https://gohugo.io/functions/compare/eq/"><code>eq</code></a>, <code>ne</code>, <code>in</code> and <code>uniq</code> compare <code>time.Time</code> values by instant.</li>
<li><a href="https://gohugo.io/functions/resources/match/"><code>resources.Match</code></a> and friends now preserve the directory casing in the matched paths, so e.g. <code>resources.Match &quot;gallery/Travel/Iceland/*&quot;</code> now works on case-sensitive file systems.</li>
<li>Syncing of static files is much faster for big unchanged files, as we now skip the content check for files with the same size and modification time.</li>
<li>Several fixes and hardening of the WASM based image codecs (AVIF crash at <code>encoderSpeed</code> 6 and lower, recovering from broken WASM instances in the server).</li>
</ul>
<h2>Security</h2>
<h3>Hugo</h3>
<ul>
<li><a href="https://gohugo.io/configuration/markup/#passthrough">Passthrough</a> content is now HTML escaped when no passthrough render hook is set, unless <code>markup.goldmark.renderer.unsafe</code> is enabled. Before this, e.g. <code>\(&lt;img src=x onerror=alert(1)&gt;\)</code> in a content file emitted raw HTML.</li>
<li>The <code>wrapperClass</code> option, settable from the <a href="https://gohugo.io/shortcodes/highlight/"><code>highlight</code></a> shortcode and <a href="https://gohugo.io/functions/transform/highlight/"><code>transform.Highlight</code></a>, is now escaped.</li>
<li><a href="https://gohugo.io/hugo-modules/use-modules/#vendor">Vendored</a> module paths are now restricted to the <code>_vendor</code> directory (symlinks pointing outside are rejected).</li>
</ul>
<p>Thanks to <a href="https://github.com/R0X4R"><code>@​R0X4R</code></a> for finding and reporting the last two issues.</p>
<h3>Go</h3>
<p>This release is built with Go 1.27.4, which <a href="https://groups.google.com/g/golang-announce/c/iY8TY0wWgbM/m/KsU1KfWgAQAJ">includes 12 security fixes</a>. The one most relevant for Hugo is a crash in the <code>net/http</code> HTTP/1 server (used by <code>hugo server</code>) caused by a race in <code>MaxBytesReader</code>. The other 11 are in the <code>cmd/go</code> toolchain (cgo flag and linker injection at build time) and mainly matter if you build Hugo from source with untrusted dependencies.</p>
<h3>Dependencies</h3>
<ul>
<li><code>golang.org/x/net</code> v0.62.0 <a href="https://seclists.org/oss-sec/2026/q4/407">fixes two issues in the <code>html</code> package</a>: quadratic complexity when coalescing text nodes, and a namespace issue when rendering raw text. Hugo uses this package when collecting HTML elements for <code>hugo_stats.json</code> and in the AsciiDoc integration.</li>
<li><code>github.com/go-jose/go-jose/v4</code> v4.1.6 (indirect dependency) contains a number of <a href="https://github.com/go-jose/go-jose/releases">security fixes</a>, among them GHSA-mgcc-cww5-fp2q (RSA modulus size limit when parsing JWKs) and a stack depth limit in the JSON decoder.</li>
</ul>
