#### What this PR does / why we need it?
Logs from `scheduler-library` currently use `"scheduler"`, making them hard to separate from Kueue's own scheduler logs.

This PR adds `.WithName("was")` to `ctx` for WAS deep-integration `scheduler-library` calls (`NewFrameworkComponents`, `NewFrameworkMap`, `ScheduleWorkload`), so those logs appear under `scheduler.was` (or `was` at startup). Basic-integration calls (e.g. `FindFeasibleNodes`) are not covered.

## AI summary

This PR changes the logger name for `scheduler-library` (WAS) logs. Before this change, those logs used the `scheduler` logger name, the same name as Kueue's scheduler logs. Now they use `scheduler.was`, so the two sources are easier to tell apart.

- `pkg/cache/scheduler/was/simulator_factory.go`: Adds a `withWASLogger` helper. It appends the `was` name to the controller-runtime logger in the context. The helper is applied to the context passed to `upstreamsync.NewFrameworkComponents` and `upstreamsync.NewFrameworkMap`.
- `pkg/cache/scheduler/was/scheduler_simulator.go`: `ScheduleWorkload` wraps its context with `withWASLogger` before it calls `cluster.ScheduleWorkload`. The workload Pods and scheduling options are unchanged.
- `pkg/cache/scheduler/was/scheduler_simulator_test.go`: Adds `TestWASLoggerName`. The test captures JSON logs from the simulator factory and from `ScheduleWorkload`. It checks that each entry has a `scheduler/was` logger name and no `scheduler/was/was` name. It also checks that both paths produce logs.
