#### What this PR does / why we need it?

`pull-kueue-test-unit-coverage-main` could keep waiting for up to an hour after both unit shards had finished.

The job polls each shard's `prowjob.json` to see whether the shard is done. Prow writes that file as `pending` and overwrites it when the job ends, but the bucket serves public objects with `cache-control: public, max-age=3600`. Once the job had read the `pending` copy, it could keep getting it from the cache.

This PR reads the object's `generation` from the JSON API metadata, which is not cached (`cache-control: private, max-age=0`), and downloads `prowjob.json?generation=<n>`. Each overwrite gets a new generation, so a cached `pending` copy cannot be returned. If Prow overwrites the file between the two requests, the old generation returns 404 and the read is retried.

The issue suggests reading through the JSON API with `alt=media`. That response is also served with `cache-control: public, max-age=3600, must-revalidate`, and in the check below it returned a stale `pending`, so this PR does not use it.

It also adds `--max-time` to the listing, metadata and `prowjob.json` requests, so a stalled connection cannot hold the job until its Prow timeout.

Fixes #18957

## AI summary

This PR changes how `hack/testing/merge-unit-coverage.sh` reads shard state from GCS. A plain read could return a cached `pending` `prowjob.json` for up to an hour. The script now reads the current object generation and requests that exact generation.

- Adds a `get` helper. It runs `curl` with `--retry 3` and `--max-time "${CURL_MAX_TIME}"`. It returns 2 on HTTP 404 and 1 on other errors.
- Adds a `read_prowjob` helper:
  - Reads the generation from the JSON API (`fields=generation`).
  - Requests `prowjob.json?generation=<n>`.
  - Retries up to three times if the object is overwritten between the two requests (HTTP 404).
- `check_shard_count` and `scan` use `read_prowjob`. `list_builds` uses `get`.
- `scan` skips older builds that have no `prowjob.json` (404). It prints the newest such build as `unknown`. It stops on other read errors.
- Adds `CURL_MAX_TIME` (default 30 seconds). It applies to the metadata, object, build-listing, and coverage-download requests.
- `hack/testing/merge-unit-coverage_test.sh` extends the `curl` stub to model generation metadata and generation-checked reads. New cases cover a shard that completes after a pending read, a retry when `prowjob.json` changes between requests, and a failed generation read.
