#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it?

Moves the TAS helpers out of the flat `jobframework` package into `pkg/controller/jobframework/tas/`:

- `tas.go` (`NewPodSetTopologyRequest`, pod index offset defaulting)
- `tas_validation.go` (TAS annotation and pod set grouping validation)
- their unit tests

The files only depend on `apis`, `features` and `pkg/util`, so there is no import cycle. Callers in the job integrations now import the package as `jobframeworktas`. No behavior change.

This lets TAS ownership be set with a directory `OWNERS` file instead of filename filters, as suggested in https://github.com/kubernetes-sigs/kueue/pull/18849#discussion_r4597954177.

#### Special notes for your reviewer

Pure move plus import updates.

## AI summary

This PR moves the topology-aware scheduling (TAS) helpers from the `jobframework` package into a new `jobframework/tas` package. The package name is `tas`, and job integrations import it under the alias `jobframeworktas`.

- **Moved files:** `tas.go`, `tas_validation.go`, and their unit tests move to `pkg/controller/jobframework/tas/`. The package declaration changes from `jobframework` to `tas`.
- **Moved helpers:** `NewPodSetTopologyRequest`, pod-index offset defaulting (including `NeedsDefaultPodIndexOffset`), TAS annotation validation, and pod-set grouping validation.
- **Callers updated:** Integration controllers and webhooks import `jobframework/tas` and call the moved helpers. These include AppWrapper, Job, JobSet, KubeflowJob, LeaderWorkerSet, MPIJob, Pod, RayCluster, RayJob, SparkApplication, StatefulSet, and TrainJob.
- **OWNERS:** The `filters` pattern in `pkg/controller/jobframework/OWNERS` changes to match Go files under `tas/` and one directory level below it. It no longer matches the exact `tas.go` and `tas_validation.go` filenames. This supports directory-based ownership of TAS code.
- **Behavior:** The author reports no behavior change. The files depend only on `apis`, `features`, and `pkg/util`, so the move does not create an import cycle.
