#### What this PR does / why we need it?

All production callers of `dominantResourceShare` pass `wlReq = nil`. Admission and preemption evaluate a Workload by changing the snapshot usage with `SimulateUsageAddition` and `SimulateWorkloadRemoval`, and then read the DRS. Only `TestDominantResourceShare` still passed a non-nil `wlReq`: its shared loop passed `tc.flvResQ` at 4 call sites, and 3 cases set that field.

This PR removes the `wlReq` parameter. Without it, a flavor-resource that has quota but no usage can never be borrowed, so `dominantResourceShare` now uses a single loop over `Usage` and treats a missing `SubtreeQuota` entry as 0. This replaces the two loops added in #18827 and gives the same result.

## AI summary

This change removes the unused `wlReq` parameter from `dominantResourceShare` in `pkg/cache/scheduler/fair_sharing.go`. The function no longer adds prospective workload requests to usage. It computes the share from current usage only.

- `dominantResourceShare` now uses one loop over `Usage`. A missing `SubtreeQuota` entry counts as zero. Borrowing is `usage - SubtreeQuota`, and only positive values count.
- Callers in `cache.go`, `clusterqueue.go`, `clusterqueue_snapshot.go`, and `cohort_snapshot.go` no longer pass the `nil` argument.
- `TestDominantResourceShare` drops the per-case `flvResQ` input. Test cases record amounts as Workload usage. Expected values are unchanged.
- Exported declarations are unchanged.
- Diff size: 6 files, +32 and -52 lines.

Admission and preemption already simulate workload changes in snapshot usage before they read the share. This change does not alter that behavior.
