#### What this PR does / why we need it?

Cherry-pick of #16509 to release-0.20; the cherry-pick robot failed to apply it.
The production change is the same as on main. One unit test case differs: the workload that keeps running on a removed cluster is requeued without a priority, because release-0.20 does not have the low priority requeue from #18407.

#### Useful notes for your reviewer

#### Release note

```release-note
MultiKueue: Fixed a bug where removing a worker cluster from a MultiKueueConfig re-dispatched the Workloads admitted on that cluster to another cluster without deleting their remote objects, so the same job could run twice. Workloads already admitted on the removed cluster now keep running there until they finish.
```
