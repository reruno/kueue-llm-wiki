#### What this PR does / why we need it?

Cherry-pick of #18407 to release-0.19.

Conflicts were resolved for code that is not on release-0.19:
- `queueWorkloadEvent` keeps the release-0.19 lookup of the local Workload (main also resolves workload slice chains) and passes the event priority.
- `setupWithManager` uses the new `workloadEventHandler`, without the `AdmissionCheck` watch that only exists on main.
- `multikueuecluster_test.go` keeps the `cluster-inventory-api` `v1alpha1` import of release-0.19.
- The "local workload keeps running on its admitting cluster after the cluster is removed from the config" case (backported in #18985) now expects the low priority requeue, as it does on main.

Related: #18115
