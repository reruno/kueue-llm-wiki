## Description

#### What type of PR is this?
/kind bug

#### What this PR does / why we need it?
When a ClusterQueue is deleted or does not exist, workloads remaining in its associated LocalQueues cannot be admitted and are effectively inadmissible. Previously, reportLQPendingWorkloads only counted inadmissible workloads when the ClusterQueue existed, resulting in zero reported workloads upon queue resync while the LocalQueue still held pending items.

This change:
1. Updates reportLQPendingWorkloads to report all pending workloads in the LocalQueue as inadmissible when the ClusterQueue is missing.
2. Ensures LocalQueue pending workload metrics are immediately refreshed upon ClusterQueue deletion in DeleteClusterQueue.
3. Keeps LocalQueue pending metrics consistent across ClusterQueue deletion, workload updates, and resync cycles.

Part of #16840

## AI summary

This PR fixes LocalQueue pending workload metrics when the associated ClusterQueue is missing or deleted. Before this change, `reportLQPendingWorkloads` counted inadmissible workloads only when the ClusterQueue existed. A resync could therefore report zero while the LocalQueue still had pending workloads.

### Changes

- `pkg/cache/queue/metrics.go`: When a LocalQueue's ClusterQueue is unavailable, `reportLQPendingWorkloads` reports the LocalQueue's queued items as inadmissible. With custom workload labels enabled, each item is tracked in the inadmissible label tracker. Otherwise, the item count is used. Previously, these fallback branches left the pending counts empty.
- `pkg/cache/queue/manager.go`:
  - `DeleteClusterQueue` reports pending workload metrics for each LocalQueue assigned to the deleted ClusterQueue. This reporting runs before the unadmitted-workload observability update, which remains conditional on that feature.
  - `AddOrUpdateWorkloadWithoutLock` and `requeueWorkloadLocked` report the LocalQueue's pending workload metrics when the ClusterQueue is missing. They then return their existing error or failure result.
- `pkg/cache/queue/manager_metrics_test.go`: Adds three tests:
  - `TestLocalQueuePendingMetrics_DeletedClusterQueueAndResyncConsistency`: checks metrics after ClusterQueue deletion and recreation, and after LocalQueue and global resyncs.
  - `TestLocalQueuePendingMetrics_DeletedClusterQueueWithCustomLabels`: checks custom-label series across the same transitions.
  - `TestLocalQueuePendingMetrics_RequeueAfterClusterQueueDeleted`: checks metrics after requeueing an in-flight workload when its ClusterQueue is deleted.
  - Updates the existing LocalQueue metrics test to expect an inadmissible metric when the destination ClusterQueue is missing.

No exported or public declarations changed.

### Suggested release note

```text
Observability: Fixed a bug that caused LocalQueue pending workload metrics to report zero when the associated ClusterQueue did not exist or was deleted. Now Kueue reports these pending workloads as inadmissible and refreshes the metrics when a ClusterQueue is deleted.
