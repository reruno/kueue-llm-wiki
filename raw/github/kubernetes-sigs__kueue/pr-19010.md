## Description


Cherry pick of #18600 on release-0.19.

#18600: TAS: Fix repeated suspension of AppWrappers without explicit TAS annotations

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

#### What type of PR is this?
/kind bug
/kind regression

The automated cherry-pick conflicted in `pkg/util/tas/tas_test.go` because #14820 is not on release-0.19. On this branch, that file does not have the test that `TestIsUnconstrainedByDefault` follows on main, and it does not import `kueue`, which the new test needs. I added the test at the end of the file and added the import. The changes to the other files are the same as in #18600.

On release-0.19 (02f9cd7e0), the 2 new AppWrapper integration specs fail without this change and pass with it. With the change, the AppWrapper integration suite, the MultiKueue AppWrapper spec and the unit tests under `pkg/controller/...`, `pkg/podset` and `pkg/util/tas` pass. I did not run `make verify` or e2e on this branch.

This PR was written in part with the assistance of Claude Code.

```release-note
TAS: Fixed a bug where an AppWrapper without explicit TAS annotations, admitted to a TAS-only ClusterQueue, was suspended and started again repeatedly. With MultiKueue, the Workload on the worker cluster was finished as `OutOfSync` and the AppWrapper did not keep running.
```
