Aligns logging in the `Job`, `Pod`, and `StatefulSet` integrations (including their MultiKueue adapters) with the [Kueue logging policy](https://github.com/kubernetes-sigs/kueue/blob/main/site/content/en/community/contribution_guidelines/logging_policy.md).

#### Release note

```release-note
Observability: Updated logging for the `Job`, `Pod`, and `StatefulSet` integrations. Routine per-object logs moved from level 2 to 3, setup logs moved to level 1, pod transition logs now run after writes succeed, duplicate and `V(2).Error` logs were removed, and some log keys were renamed (`statefulset`, `podName`, `workloadName`, `oldStatus`, `old.parallelism`, `APIVersion`, `ControllerReference`).

ACTION REQUIRED: If your dashboards, alerts, or log queries depend on Kueue log messages, keys, or levels for these integrations, review them before upgrading. Set the log level to 3 or higher to keep per-object reconcile and event logs.
```

## AI summary

This change aligns logging in the Job, Pod, and StatefulSet integrations, including their MultiKueue adapters, with the Kueue logging policy. It does not change Events, conditions, or API writes.

- **Job controller:** Workload and child-job identities are logged when queueing child jobs. The indexed-job terminal-count diagnostic moves from V(3) to V(5). The reclaimable-pod diagnostic moves from V(3) to V(4).
- **Job MultiKueue adapter:** Local Job lookup errors are logged with a `klog.KRef` and returned wrapped with the Job key. Job objects in the status-update log use `klog.KObj` at V(5). The finished-Job log moves from V(2) to V(3). The suspended-Job workaround log moves to V(4) and uses `previousStatus` and `status`. The stale elastic workload sync log moves to V(3) and uses revised field names.
- **Pod event handlers:** The pod identity moves from the logger's values to the individual log calls. The "Queueing reconcile for pod" log runs only when V(5) is enabled, and it includes the pod identity. Workload child-pod reconciliation returns early when the Workload has no owner references. Parse failures still stop processing. The error log now uses structured fields and the original `apiVersion`.
- **Pod controller:** Setup logs through the manager's logger with the controller name at V(1). Several messages change verbosity. Some error logs drop their V(2) level. Excess-pod deletion logs after `Delete` succeeds. The owner-reference addition log runs only at V(4) and includes the Workload identity. A new V(3) log reports each ungated pod in a group. Errors from related-Workload lookups in `ListChildWorkloads` and `FindMatchingWorkloads` are returned with operation context using `%w`. They are no longer logged before they are returned.
- **Pod MultiKueue adapter:** The terminating-local-Pod log moves from V(2) to V(3) and uses `klog.KObj` instead of `podName`. A remote Pod creation failure logs with `klog.KObj`. The returned error wraps the create error with Pod identity.
- **StatefulSet reconciler:** The startup log moves from V(2) to V(3). Setup logs move to V(1) and use the reconciler name. Pod patching happens only when defaulting, ungating, or queue-label sync changed the Pod. The StatefulSet log field changes from `statefulset` to `statefulSet`.

Operators who use dashboards, alerts, or queries on these messages, keys, or levels must review them before upgrading. Set the log level to 3 or higher to keep per-object reconcile and event logs.

Observability: Moved routine per-object logs in the Job, Pod, and StatefulSet integrations, including their MultiKueue adapters, from log level 2 to level 3, moved setup logs to level 1, removed duplicate logs, and renamed some log keys. Review dashboards, alerts, and queries that depend on these messages, keys, or levels. Set the log level to 3 or higher to keep per-object reconcile and event logs.
