#### What this PR does / why we need it?

`PartialAdmission` is Beta and enabled by default since v0.5, but some tests still turn it on explicitly. The calls don't change the result, and they make it hard to tell which tests depend on the gate.

This PR removes those calls:
- 10 `featureGates` entries in `TestSchedule` (`pkg/scheduler`),
- 1 entry in `TestWorkloadWebhookDefault` (`pkg/webhooks`),
- 3 `SetFeatureGateDuringTest(..., true)` calls in the workload webhook integration suite (`elastic_partial_scaleup_test.go`).

Kept on purpose:
- every case that turns the gate off;
- the table-driven cases that set the gate from a `bool` field;
- the explicit `true` in the RayCluster webhook integration suite. A sibling `Describe` there sets the gate to `false` through `SetFromMap` and never restores it, and Ginkgo randomizes the order of top-level containers, so this call turns the gate back on.

This PR removes test-only enables of the `PartialAdmission` feature gate. The gate is enabled by default, so these enables are redundant.

- `pkg/scheduler/scheduler_test.go`: removes 10 `PartialAdmission: true` entries from `featureGates` in `TestSchedule`.

- Cases that disable the gate.
- Table-driven cases that set the gate from a boolean field.
