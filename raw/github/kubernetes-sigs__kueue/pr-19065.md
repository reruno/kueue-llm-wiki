#### What this PR does / why we need it?

`PrioritySortingWithinCohort` is Beta and enabled by default since v0.6, but `TestEntryOrdering` still turns it on explicitly. The entries don't change the result, and they make it hard to tell which tests depend on the gate.

This PR removes those entries from `TestEntryOrdering` (`pkg/scheduler`):
- 2 entries in the "Priority sorting is enabled (default)" cases,
- 1 entry in "Some workloads are preempted; Priority sorting is enabled",
- the gate from the 2 `PrioritizePreemptorWorkloads` cases, which keep setting `PrioritizePreemptorWorkloads` itself.

## AI summary

This change removes redundant test setup in `pkg/scheduler/scheduler_test.go`. It does not change product code.

- `TestEntryOrdering` no longer explicitly enables the `PrioritySortingWithinCohort` feature gate. This applies to the default priority sorting cases and to one case where some workloads are preempted.
- The `PrioritizePreemptorWorkloads` cases no longer explicitly enable `PrioritySortingWithinCohort`. They still enable `PrioritizePreemptorWorkloads`.
