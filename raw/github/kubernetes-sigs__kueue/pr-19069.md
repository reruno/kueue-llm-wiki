## Description

Cherry pick of #18338 on release-0.19.

#18338: Skip evicting a Workload that has no quota reservation on retry

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

The [`/cherrypick release-0.19` run](https://github.com/kubernetes-sigs/kueue/pull/18338#issuecomment-6979911035) conflicted in `preemption_test.go`. On release-0.19, Kueue sends the server-side apply status write through `Status().Patch`, not `Status().Apply`. So the new test handles that write in its `SubResourcePatch` interceptor with `TreatSSAAsStrategicMerge`, as the test it replaces did. The production code is the same as in #18338.

_Disclosure: I used an AI coding assistant while preparing this PR._

/kind bug

```release-note
Scheduling: Fixed a panic in the scheduler when `WorkloadRequestUseMergePatch` was enabled and a Workload released its quota while Kueue was evicting it, for example for preemption.
```
