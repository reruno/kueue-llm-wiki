#### What this PR does / why we need it?

`FairSharingPreemptWithinNominal` is Beta and enabled by default since v0.17, but two test cases still turn it on explicitly. The calls don't change the result, and they make it hard to tell which tests depend on the gate.

This PR removes those calls and one leftover:
- 2 `featureGates` entries in `TestFairSharingPreemptionStrategy` (`pkg/scheduler/preemption`):
  - "preemptor within nominal reclaims every candidate",
  - "preemptor borrowing on another requested resource follows the strategy path",
- the `featureGates` field and its `features.SetFeatureGatesDuringTest` call in `TestClassicalPreemptionStrategy`. No case in that table sets the field, so both were dead code.
