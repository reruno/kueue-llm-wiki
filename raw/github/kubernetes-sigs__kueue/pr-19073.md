#### What this PR does / why we need it?

`ElasticJobsViaWorkloadSlices` has been Beta and enabled by default since v0.18, but many tests still turn it on explicitly. The calls don't change the result, and they make it hard to tell which tests depend on the gate.

This PR removes those calls:
- about 220 `ElasticJobsViaWorkloadSlices: true` entries in table-driven `featureGates` maps in `pkg/` unit tests,
- 22 `SetFeatureGateDuringTest(..., true)` calls in `pkg/` unit tests,
- 38 `SetFeatureGateDuringTest(..., true)` calls, 5 `featureGates` map entries and 3 `SetFromMap` entries in `test/integration`.

`TestFindActiveWorkload` (`pkg/workloadslicing`) decided whether to register the workload slice name index by reading the gate from the test case map. It now checks `features.Enabled`, as the indexer does in production.

#### Useful notes for your reviewer

I kept:
- The per-case `true` entries in `TestValidateCreate` (`pkg/controller/jobs/rayservice`). The test disables the gate for every case, so these entries turn it back on,
- The gate values in `pkg/config/validation_test.go`. They are inputs to the configuration validation, not test setup.

Tests only, no product code changes. Following the one-gate-per-PR approach discussed in #18993. The gate is on by default in every supported release, so this can be cherry-picked to release-0.19 and release-0.20.

## AI summary

This PR removes explicit enabling of the `ElasticJobsViaWorkloadSlices` feature gate from test setup. The change touches 62 files, with 48 lines added and 417 removed. The change affects tests only. It does not change production code.

The author reports that this gate is Beta and enabled by default. Because of that, the removed settings do not change test results. The explicit settings also hid which tests depend on the gate.

- **Unit tests in `pkg/`:** Removes `true` entries from per-case `featureGates` maps and removes `SetFeatureGateDuringTest(..., true)` calls. Tests that need other gates, such as `ElasticJobsViaWorkloadSlicesWithTAS`, `ElasticJobsViaWorkloadSlicesWithPartialReplicaScaleUp`, or `ElasticJobsViaWorkloadSlicesForProvisioningRequests`, keep those settings.
- **`TestFindActiveWorkload` (`pkg/workloadslicing`):** The check for whether the workload slice name index is registered now reads `features.Enabled`. It no longer reads the test-case map.
- **Integration tests in `test/integration`:** Removes gate setup from `BeforeEach` blocks, test bodies, and `SetFromMap` entries. Tests keep their other gate settings.
- **Unchanged by design:**
  - `TestValidateCreate` in `pkg/controller/jobs/rayservice`. Each case disables the gate, so the per-case entries stay.
  - Gate values in `pkg/config/validation_test.go`. These values are configuration-validation inputs.

Test inputs and expected results are unchanged in the reviewed summaries.
