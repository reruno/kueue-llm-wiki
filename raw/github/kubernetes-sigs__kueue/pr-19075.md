#### What this PR does / why we need it?

This is a manual cherry-pick of #18748 and #18806 to release-0.20.

#### Useful notes for your reviewer

The automated cherry-picks failed: #18748 conflicted in `pkg/cache/queue/pending_workloads.go`, and #18806 depends on #18748. This PR has one commit for each, in the same order.

#18806 applies cleanly on top of #18748. #18748 is adapted as follows, because release-0.20 does not have #18134, which added `PendingWorkloads.Pending()` on main:

- `PendingWorkloads.Pending()` is added as in #18748, so it subtracts the extra Variants.
- `ClusterQueue.Pending()` and `PendingTotal()` call `PendingWorkloads.Pending()` instead of summing the label trackers.
- `reportCQPendingWorkloads` reports `cq.Pending()` when no Workload custom label is configured, so the `kueue_pending_workloads` metric counts each Parent once, as on main.

Tests:
- The unit tests of #18748 and #18806 are the same. `go test ./pkg/cache/queue/... ./pkg/controller/core/... ./pkg/controller/concurrentadmission/...` passes.
- `INTEGRATION_TARGET='test/integration/singlecluster/controller/concurrentadmission' make test-integration`: 14/14 pass. With the release-0.20 queue code, the new LocalQueue test fails with `Expected 2 to equal 1`.
- `make ci-lint` passes.
- This PR was prepared with AI assistance.

#### Release note

```release-note
ConcurrentAdmission: Fixed the ClusterQueue `status.pendingWorkloads` and the `kueue_pending_workloads` metric counting a pending Workload once per Variant. A Workload is now counted once.
ConcurrentAdmission: Fixed the LocalQueue `status.pendingWorkloads` and the `kueue_local_queue_pending_workloads` metric counting a pending Workload once per Variant. The LocalQueue status also no longer counts the Parent Workload after a Kueue restart or an eviction. A Workload is now counted once.
```
