#### What this PR does / why we need it?

This is a manual cherry-pick of #18748 and #18806 to release-0.19.

#### Useful notes for your reviewer

The automated cherry-picks failed: release-0.19 does not have `pkg/cache/queue/pending_workloads.go`, and #18806 depends on #18748. This PR has one commit for each, in the same order. `variant_parent_counts.go` and the tests are the same as in #18748 and #18806, except as noted below. The fix is adapted as follows:

- In release-0.19, the heap, `inadmissibleWorkloads` and the inflight workload are fields of `ClusterQueue`, not of `PendingWorkloads`. The `variantParentCounts` updates sit next to the `localQueueCounts` updates in the `ClusterQueue` helpers that move a pending workload (`pushToHeapIfNotTracked`, `pushOrUpdateHeap`, `removeFromHeap`, `insertInadmissible`, `removeFromInadmissible`, `moveInadmissibleToHeap`, `moveHeapToInadmissible`, and the inadmissible update in `PushOrUpdate`), and in `Pop` and `forgetInflightByKey`. `ClusterQueue.Pending()` subtracts the extra Variants.
- `localQueueCounts` keeps plain counts in release-0.19, without the custom label trackers. The per-LocalQueue Variant counts of #18806 are added next to those counts, and `pendingBreakdownInLocalQueue` is not included.
- `heads()` has no `takePopped` in release-0.19, so it removes the popped workload from its LocalQueue with the new `LocalQueue.delete`.
- `TestPendingCountsEachParentOnce` requeues one Variant before it pops another, because the release-0.19 `ClusterQueue` keeps a single inflight workload. The end state and the expected counts are the same as in #18748. The test also calls `newClusterQueueImpl` without the custom labels argument, and the comments in `variant_parent_counts.go` name the release-0.19 fields.

Tests:
- `go test ./pkg/cache/queue/... ./pkg/controller/core/... ./pkg/controller/concurrentadmission/...` passes. Without the change to `ClusterQueue.Pending()`, `TestPendingCountsEachParentOnce` fails with `Pending() = (3, 1), want (2, 0)`.
- `INTEGRATION_TARGET='test/integration/singlecluster/controller/concurrentadmission' make test-integration`: 12/12 pass. With the release-0.19 queue code, the new LocalQueue test fails with `Expected 2 to equal 1`.
- `make ci-lint` passes.
- This PR was prepared with AI assistance.

#### Release note

```release-note
ConcurrentAdmission: Fixed the ClusterQueue `status.pendingWorkloads` and the `kueue_pending_workloads` metric counting a pending Workload once per Variant. A Workload is now counted once.
ConcurrentAdmission: Fixed the LocalQueue `status.pendingWorkloads` and the `kueue_local_queue_pending_workloads` metric counting a pending Workload once per Variant. The LocalQueue status also no longer counts the Parent Workload after a Kueue restart or an eviction. A Workload is now counted once.
```
