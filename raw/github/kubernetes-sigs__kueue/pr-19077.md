#### What this PR does / why we need it?

CodeRabbit still refuses to open issues for `kubernetes-sigs` members after #18649, for example in https://github.com/kubernetes-sigs/kueue/pull/18934#discussion_r4611174227.

The skill checks membership with `gh api -i orgs/kubernetes-sigs/members/<user>`. CodeRabbit's token is not an organization member, so this endpoint returns 404 for members with private membership, and the skill then asks a maintainer to open the issue. The comment's `author_association` has the same problem: an unauthenticated or non-member caller sees `CONTRIBUTOR` instead of `MEMBER`.

This PR checks the requester against `config/kubernetes-sigs/org.yaml` in `kubernetes/org` instead. Peribolos manages the organization from that file, and it lists every member regardless of membership visibility.

Part of #18124

#### Useful notes for your reviewer

No Kueue behavior change; this only changes an agent skill.

Checked the new command manually: it reports `member` for `mbobrovskyi`, `MBobrovskyi` and `HarshithaMS005`, and nothing for a non-existent login. Team member lists in `org.yaml` are indented, so the full-line `- <user>` match only hits the top-level `admins` and `members` lists.

`make verify-skills-lint` passes. As with #18649, this can only be validated after merge. If CodeRabbit still refuses after it confirms membership, the remaining restriction is its own write-permission check.

The `kueue-pr-issue-workflow` agent skill changes how it checks whether a requester belongs to the `kubernetes-sigs` organization before opening an issue.

- The skill no longer calls `orgs/kubernetes-sigs/members/<user>`. That call can return 404 for members with private membership.
- The skill now checks `config/kubernetes-sigs/org.yaml` in `kubernetes/org` with `gh api`, using a `grep` for the requester's login.
- When the requester is listed, the skill opens the issue even without repository write permission.
- When the requester is not listed, the skill asks a maintainer to open the issue.
- The skill no longer relies on the comment's `author_association`.
