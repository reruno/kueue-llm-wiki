#### What this PR does / why we need it?

Propagate caller contexts through controller event handlers, scheduler candidate-cache warming and classical preemption iteration. Preserve context values, cancellation, deadlines and the caller's logger instead of replacing them with background contexts.

Keep the existing logging behavior: reconciliation reuses its injected logger; event paths retain controller/replica-role decoration, existing verbosity levels, messages and structured object keys.

Fixes #19079.

## AI summary

This change passes caller contexts through controller event handling, the scheduler candidate order cache, and classical preemption candidate iteration. It replaces `context.Background()` in these paths. It addresses `#19079`.

- **Scheduler cache:** `CandidateOrderCache.Warm` takes a `ctx`. If cancellation leaves entries unbuilt, `Warm` skips them. `Get` builds missing entries on demand.
- **Controllers:** LocalQueue, ClusterQueue, Cohort, StatefulSet, and LeaderWorkerSet event logic moves into context-aware `handle*` methods. New typed event handlers call these methods and enqueue reconcile requests when they return true.
- **Logs:** The ClusterQueue delete log now adds a `clusterQueue` key. Its verbosity stays at 3. The diff does not show level changes for ClusterQueue create or update logs, or for Cohort delete logs.

**Public API changes:**
- `CandidateOrderCache.Warm` and `classical.NewCandidateIterator` gain a leading `ctx context.Context` parameter.
- The exported `Create`, `Update`, `Delete`, and `Generic` predicate methods on the LocalQueue, ClusterQueue, and Cohort reconcilers are removed.
