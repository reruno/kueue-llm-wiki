#### What this PR does / why we need it?

This PR replaces the hand-written MultiKueueConfig event handler of the MultiKueue workload controller with controller-runtime's `handler.EnqueueRequestsFromMapFunc`, as #18949 did for the AdmissionCheck event handler. The handler keeps its event filter: it queues the Workloads of the MultiKueue AdmissionChecks that use a MultiKueueConfig only when the config's clusters change or the config is deleted.

The Workloads are now queued immediately instead of after `eventsBatchPeriod`. MultiKueueConfigs rarely change, so batching their events has no practical effect. The priority does not change: the filter drops resync updates, and the remaining update and delete events are queued at the default priority, as before.

Part of #18466

## AI summary

The MultiKueue workload controller now handles `MultiKueueConfig` events through a function-based `configHandler(c client.Client) handler.EventHandler`.

- The update handler enqueues workloads only when both objects are `MultiKueueConfig` values and their `Spec.Clusters` differ. Updates that leave `Spec.Clusters` unchanged return early, so resync updates are dropped.
- The delete handler enqueues workloads only when the deleted object is a `MultiKueueConfig`.
- Both handlers delegate to `handler.EnqueueRequestsFromMapFunc`. The map function calls `workloadRequestsForConfig`, which lists the AdmissionChecks that use the config and collects their workload requests. It returns the requests with any joined errors. Errors are logged.
- The removed handler used `q.AddAfter(req, eventsBatchPeriod)`. The map-based path enqueues requests without that delay.
- Create and Generic events are not handled, so they do nothing.
- The watch registration calls `configHandler(w.client)`.
- The tests `TestConfigHandlerUpdate` and `TestConfigHandlerDelete` construct the handler with `configHandler(fakeClient)`.
- The diff changes 2 files, with 43 lines added and 57 removed.

## Suggested release note

```text
MultiKueue: Fixed a bug that delayed workload requeuing when a MultiKueueConfig changed its clusters or was deleted. Now Kueue queues the affected workloads immediately, without waiting for the events batch period.
```
