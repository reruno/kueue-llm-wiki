#### What this PR does / why we need it?

Two Ray autoscaler defaults work poorly with elastic Ray workloads (`kueue.x-k8s.io/elastic-job: "true"` + `enableInTreeAutoscaling: true`) under Kueue quota:

- `AUTOSCALER_MAX_CONCURRENT_LAUNCHES` (default 10) splits a large scale-up into several steps, each creating a Workload slice. Kueue can admit the first slices while later ones wait for quota, so the Ray application runs with only part of the capacity it asked for.
- `RAY_AUTOSCALER_PENDING_NODE_IDLE_TIMEOUT_S` (default disabled) means gated pending workers that no demand needs anymore stay until the one-hour allocate timeout, and their Workload slice keeps waiting for quota.

This PR adds a "Recommended autoscaler settings" section to the RayCluster page with both settings and links to the related Ray issues (ray-project/ray#67124, ray-project/ray#67102, kuberay-project/kuberay#5434), and links it from the RayJob and RayService autoscaling sections.

These recommendations come from running elastic Ray workloads with Kueue in production.

+## Autoscaling
+
+{{< feature-state state="alpha" for_version="v0.20" >}}
+
+With MultiKueue, the [Ray autoscaler](https://docs.ray.io/en/latest/cluster/kubernetes/user-guides/configuring-autoscaling.html)
+runs on the worker cluster and resizes the mirror copy of the Ray workload.
+Kueue reflects each resize back to the management cluster as a new
+[Workload slice](/docs/concepts/elastic_workload), so quota follows the number of
+running workers.
+This works for RayCluster, RayJob, and RayService.
+
+### Enable the feature gates
+
+Enable these feature gates on the management cluster and on every worker cluster:
+
+```yaml
+ElasticJobsViaWorkloadSlices: true   # beta, enabled by default
+MultiKueueRayInTreeAutoscaling: true # alpha, disabled by default
+SkipChildJobSuspension: true         # alpha, disabled by default
+```
+
+`MultiKueueRayInTreeAutoscaling` depends on `MultiKueue`, `ElasticJobsViaWorkloadSlices`,
+and `SkipChildJobSuspension`.
+Without `MultiKueueRayInTreeAutoscaling`, the admission webhook rejects a
+MultiKueue-managed elastic Ray object that sets `enableInTreeAutoscaling: true`.
+
+### Configure the Ray workload
+
+Configure the Ray workload on the management cluster as for a
