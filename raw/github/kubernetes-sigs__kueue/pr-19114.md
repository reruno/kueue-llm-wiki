## Description

#### What type of PR is this?

/kind bug
/area concurrent-admission

#### What this PR does / why we need it?

With ConcurrentAdmission, the Parent Workload is not queued, while each of its Variants is. #18748 and #18806 made the pending Workload counts count each Parent once, but the pending resources still added the requests of every Variant. For one Job with a 100 CPU request in a ClusterQueue with two flavors, `kueue_pending_workloads` reported 1 while `kueue_cluster_queue_resource_pending` reported 200 CPU.

The Variants copy the spec of their Parent, so the pending resources now hold the requests of each Parent once:

- The total holds the requests of the Parent's pending Variant that was added last. When another Variant of the Parent is added or updated, its requests replace the previous ones, so an update of the requests is reflected. When the last pending Variant leaves, the same requests are subtracted.
- An inflight Variant is added only when its Parent has no other pending Variant and no other inflight Variant was added for it.

An admitted Parent whose Variants still wait for a migration to a preferred flavor is counted once, as in the pending Workload counts. Whether such a Parent should count as pending at all is discussed separately in #18747.

## AI summary

This PR changes how `PendingWorkloads` counts pending resources for ConcurrentAdmission Variants. Each Parent Workload counts once.

- `pkg/cache/queue/pending_workloads.go` adds a `variantResources` map keyed by Parent reference. Each entry stores the Parent's pending Variant count, its inflight Variant count, and the latest Variant requests.
- Adding or updating a pending Variant replaces the Parent's recorded requests with that Variant's requests. It then updates the Variant count.
- Removing a pending Variant decrements the count. The Parent's requests are subtracted only when its last pending Variant leaves.
- An inflight Variant is counted only when its Parent has no other pending Variant and no other inflight Variant is already counted.
- Workloads that are not Variants keep the previous per-workload accounting.
- `pkg/cache/queue/cluster_queue.go` initializes `variantResources`.
- The PR adds a unit test, `TestPendingResourcesCountEachParentOnce`, in `pkg/cache/queue/variant_parent_counts_test.go`. It covers ConcurrentAdmission enabled and disabled.
