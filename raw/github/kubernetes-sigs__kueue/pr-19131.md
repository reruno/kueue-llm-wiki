## Description

Cherry pick of #18325 on release-0.20.

#18325: Do not recreate the metrics of a deleted LocalQueue

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

The [`/cherrypick release-0.20` run](https://github.com/kubernetes-sigs/kueue/pull/18325#issuecomment-7004554857) conflicted in four files. This branch does not have `kueue_local_queue_workload_creation_latency_seconds` from #18295, so the queue manager part of #18325 is left out: `RecordLocalQueueMetrics`, its caller, its test, and the delete handler comment about it. In `recordWorkloadAdmissionEvents` the ClusterQueue metrics keep this branch's custom labels. The rest is the same as in #18325.

_Disclosure: I used an AI coding assistant while preparing this PR._

```release-note
Observability: Fixed a bug where the metrics of a deleted LocalQueue, such as `kueue_local_queue_evicted_workloads_total`, could reappear after the deletion and stay, if Kueue recorded them for a Workload while the LocalQueue was being deleted.
```
