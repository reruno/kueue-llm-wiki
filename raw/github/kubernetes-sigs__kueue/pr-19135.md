#### What this PR does / why we need it?

Aligns logging across the MultiKueue Workload reconciler, MultiKueueCluster reconciler, remote client, kubeconfig FS watcher, Secret/ClusterProfile handlers, and MultiKueue job adapters (external frameworks, Ray, LeaderWorkerSet) with the [Kueue logging policy](https://github.com/kubernetes-sigs/kueue/blob/main/site/content/en/community/contribution_guidelines/logging_policy.md).

Part of #9801

#### Useful notes for your reviewer

Non-logging changes:
- Workload reconciler: returned errors are wrapped with the operation and the worker cluster, e.g. "updating remote workload on worker cluster %q: %w". No control flow or error aggregation changes.

Notes:
- Errors whose structured keys would be lost by wrapping (`workerCluster`, remote objects, `watchKind`) keep an `Error` log at the point of failure and are also returned. These logs stay until #18101 lands.
- The logger scoped in steps 4 and 6b of `reconcileGroup` keeps the `remote` key. Renaming it would duplicate `workerCluster` in records that already add that key.
- The "component workloads assigned to different clusters" log now carries the error it returns; it used to pass a nil error.
- Errors from `setRemoteClientConfig` and the watcher are not wrapped, because their text goes into the MultiKueueCluster condition message.
- "Lost the watch on the worker cluster, queueing a reconcile to reconnect" moves to level 1 as a connection-health transition.
- The Secret update handler logs the Secret it queued; it used to log the old object.

Cherry-pick: release-0.19 and release-0.20, without a feature gate.

AI assisted.

#### Release note

```release-note
Observability: Aligned MultiKueue controller and adapter logs with the logging policy. Watch loss and GC lifecycle logs moved to level 1, per-object logs moved from level 2 to level 3, handler failures are logged as errors, duplicate error logs were removed, and log keys were renamed (`cluster`/`remoteCluster` and per-call `remote` to `workerCluster`; `cluster1`/`cluster2` to `workerCluster`/`otherWorkerCluster`; `member` to `componentWorkload`; `leaderworkerset` to `leaderWorkerSet`; `observedWorkloadName`/`currentWorkloadName` to `observedWorkload`/`currentWorkload`; `name`/`namespace` of external-framework objects to `remoteObject` and `job`; `remoteCQ`/`remoteLQ`/`remoteWl` to `remoteClusterQueue`/`remoteLocalQueue`/`remoteWorkload`; `clusterName` to `multiKueueCluster`; `kind` to `watchKind`; `clusterprofile` to `clusterProfile`; `ownerKey` to `owner`; `adapterKey` to `ownerGVK`; FS watcher `name` to `path`).

ACTION REQUIRED: If your dashboards, alerts or log queries depend on Kueue log messages, keys or verbosity levels, review them before upgrading. For the complete list of logging changes, see #19135. To keep the per-object logs, set the log level to 3 or higher.
```

## AI summary

This change aligns logging in the MultiKueue controller with the Kueue logging policy. It changes log levels, messages, and structured keys. It does not change control flow, error aggregation, or watch, retry, and garbage-collection behavior.

- **Workload reconciler (`workload.go`):** Reconciliation failures log at error level. Remote operation errors are wrapped with the operation and worker cluster name. Errors whose structured keys would be lost when wrapped still log at the failure point and are returned. Quota-reservation sync errors are wrapped before they are joined with other reconciliation errors. `workloadToOpenPreemptionGate` checks for a nil remote workload before it creates its logger.
- **Remote object handling (`externalframeworks/adapter.go`):** Creation and status-sync errors are returned directly. Successful creation and sync log at level 3 with the remote object key or the local job key. The earlier level 2 pre-operation logs are removed.
- **Cluster and handlers (`multikueuecluster.go`):** Messages, structured cluster and object identifiers, and verbosity levels are updated across remote-client watch handling, queue events, garbage collection, reconciliation, and Secret and ClusterProfile handlers. Reconciliation logs when a client configuration is missing.
- **Kubeconfig watcher (`fswatch.go`):** Events and errors use `path` and `op` fields. Ignored events move to level 5. Shutdown moves to level 1.
- **Remote client (`remote_client.go`):** The cache-sync message changes to "Remote cache synced" and moves to level 1.
- **Job adapters:** The LeaderWorkerSet adapter uses the `leaderWorkerSet` key for Forbidden-error logs. The Ray adapter formats workload names with `klog.KRef`, and its stale-sync log moves to level 3.

Errors from `setRemoteClientConfig` and the watcher are not wrapped. Their text appears in the MultiKueueCluster condition message.

Log levels, message text, and key names change. Dashboards, alerts, and queries that depend on them can need updates. To keep per-object logs, set the log level to 3 or higher.

Update dashboards, alerts, and queries that depend on log messages, keys, or verbosity levels.
