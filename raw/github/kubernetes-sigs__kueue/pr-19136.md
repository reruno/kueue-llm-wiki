#### What this PR does / why we need it?

Aligns logging in the ConcurrentAdmission variant controller with the [Kueue logging policy](https://github.com/kubernetes-sigs/kueue/blob/main/site/content/en/community/contribution_guidelines/logging_policy.md).

Part of #9801

#### Useful notes for your reviewer

Non-logging changes:
- Errors returned from `Reconcile` and `createVariants` are wrapped with the operation, e.g. "deactivating variants: %w". No control flow changes.

Notes:
- Eviction and admission records moved after the confirmed patch; the `evicted` flags only decide whether to log.
- The `parent` key was removed: the parent is the reconciled Workload, which controller-runtime already logs.
- Variant creation failures keep a log with the `variant` key, now as `Error` (they were level 3 info), until #18101 lands.
- The `variants` key printed a klog type-error string, because `klog.KObjSlice` needs pointers. It now logs object references.

Cherry-pick: release-0.19 and release-0.20, without a feature gate.

AI assisted.

#### Release note

```release-note
Observability: Aligned ConcurrentAdmission controller logs with the logging policy. Per-object logs moved from level 2 to level 3, evictions are logged after they are saved, variant creation failures are logged as errors, and log keys were renamed (`flavor` to `resourceFlavor`, `Variant` to `admittedVariant`).

ACTION REQUIRED: If your dashboards, alerts or log queries depend on Kueue log messages, keys or verbosity levels, review them before upgrading. For the complete list of logging changes, see #19136. To keep the per-object logs, set the log level to 3 or higher.
```

## AI summary

This change updates logging in the ConcurrentAdmission variant controller (`pkg/controller/concurrentadmission/controller.go`). It also changes how some errors are returned. The change is limited to this one file.

- **Log levels:** Per-object records move from V(2) to V(3). Plan and decision records move to V(4). Search steps and "if needed" records move to V(5). Event handler logs (Create, Update, Delete) and the "neither parent nor variant" log move to V(5).
- **Eviction logs:** Parent eviction logs run after the patch succeeds. They run only when `SetEvictedCondition` reports a change. Those logs are at V(3).
- **Key changes:** `flavor` becomes `resourceFlavor`. The `Variant` key becomes `admittedVariant` in the admission sync path. The `parent` key is removed from several logs. `clusterQueue` is logged as an object reference. Variants are logged as object references at V(4).
- **Error handling:** `Reconcile` and helper functions wrap errors with the operation name and return them. They no longer log the error before returning it. In `createVariants`, owner-reference and create failures are logged at Error level with the `variant` key before the wrapped error is returned.
- **Removed logs:** Logs for deleting variants in `cleanupParentAndVariants` and `deleteStaleVariants` are removed. The `workload` key is removed from the "Workload not found" log.
- **Unchanged:** Variant selection, activation, deactivation logic, and preemption-gate behavior are not changed. The declared API surface is not changed.

Users who depend on the previous log levels, key names, or message text in dashboards, alerts, or queries must update them. Per-object logs appear only at log level 3 or higher.

### Suggested release note

```text
ConcurrentAdmission Observability: Changed the verbosity levels, key names, and messages of ConcurrentAdmission controller logs. Per-object logs now appear at log level 3 or higher. Plan and search logs now appear at levels 4 and 5. Review dashboards, alerts, and queries that depend on these logs before upgrading.
```
