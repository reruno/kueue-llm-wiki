## Description

#### What type of PR is this?

#### What this PR does / why we need it?

Aligns logging in the LeaderWorkerSet reconciler and the ProvisioningRequest admission check controller with the [Kueue logging policy](https://github.com/kubernetes-sigs/kueue/blob/main/site/content/en/community/contribution_guidelines/logging_policy.md).

Part of #9801

#### Useful notes for your reviewer

Non-logging changes:
- Returned errors are wrapped with the operation and the object, e.g. "creating Workload %s: %w". No control flow or error aggregation changes.

Notes:
- Per-Pod, per-Workload and per-ProvisioningRequest failures keep an `Error` log with their key and are also returned, until #18101 lands.
- The LeaderWorkerSet fan-out still returns one error per branch, so the per-item logs are what identifies every failed object.
- ProvisioningRequest: the logs inside the status patch keep their place; only their levels, keys and messages change. A missing ProvisioningClassDetail is logged at level 1 (it was unleveled).

Cherry-pick: release-0.19 and release-0.20, without a feature gate.

AI assisted.

#### Release note

```release-note
Observability: Aligned LeaderWorkerSet and ProvisioningRequest controller logs with the logging policy. Per-object logs moved from level 2 to level 3, LeaderWorkerSet results are logged after they are saved, and log keys were renamed (`leaderworkerset` to `leaderWorkerSet`, `statefulset` to `statefulSet`, `req`/`requestName`/`prName` to `provisioningRequest`, `check` to `admissionCheck`).

ACTION REQUIRED: If your dashboards, alerts or log queries depend on Kueue log messages, keys or verbosity levels, review them before upgrading. For the complete list of logging changes, see #19137. To keep the per-object logs, set the log level to 3 or higher.
```

## AI summary

This change updates log levels, messages, and log keys in the LeaderWorkerSet reconciler and the ProvisioningRequest admission check controller. It aligns them with the Kueue logging policy. Control flow and error aggregation do not change.

- Per-object logs move from level 2 to level 3. Logs written before a write move to level 4. Per-Pod and handler-step logs move to level 5.
- LeaderWorkerSet results are logged after they are saved.
- Several log keys are renamed.
- Returned errors are wrapped with the operation and object. Errors are still returned.
- Per-Pod, per-Workload, and per-ProvisioningRequest failures still produce an `Error` log.
- A missing ProvisioningClassDetail is logged at level 1.
- A missing attempt suffix on a ProvisioningRequest name is logged at level 1. The code assumes attempt `1`.
