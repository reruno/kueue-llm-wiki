## Description

#### What type of PR is this?

#### What this PR does / why we need it?

Aligns logging in the DynamicQuotaOrchestrator, LocalCapacity, MultiKueue CapacityProvider, failure recovery, unscheduled Pods tracker and ResourceSlice controllers, the AppWrapper, SparkApplication, JobSet, Kubeflow, MPIJob, RayJob and RayCluster integrations, and the noop reconciler with the [Kueue logging policy](https://github.com/kubernetes-sigs/kueue/blob/main/site/content/en/community/contribution_guidelines/logging_policy.md).

Part of #9801

#### Useful notes for your reviewer

Non-logging changes:
- AppWrapper: the component pod spec error is returned wrapped ("getting AppWrapper component pod specs: %w") and no longer logged with the whole AppWrapper object.

Notes:
- SparkApplication: a failure to count the ready executors is logged as `Error`; it was a level 2 info record with an `error` key.
- LocalCapacity: enqueue-all fallbacks without an error are logged at level 1 instead of `Error(nil, ...)`.
- `jobframework/utils.go` (`ctrl.Log` in `NewWorkload`) is left for a later PR. Fixing it needs a context parameter that reaches several job integrations.

Cherry-pick: release-0.19 and release-0.20, by hand. `capacityprovider`, `localcapacity` and the SparkApplication executor-count code are not on either branch. `dqo`, `unscheduledpods` and the RayCluster runtime-counts annotation are not on release-0.19.

AI assisted.

ACTION REQUIRED: If your dashboards, alerts or log queries depend on Kueue log messages, keys or verbosity levels, review them before upgrading. For the complete list of logging changes, see #19138. To keep the per-object logs, set the log level to 3 or higher.

This change aligns log levels, keys, and object references with the Kueue logging policy. It touches 14 files across DQO, capacity, failure recovery, unscheduled Pods, ResourceSlice, job integrations, and the noop reconciler. Diff size: 48 lines added, 41 removed.

- **Verbosity:**
  - The DQO reconcile-start log moves from level 2 to level 3.
  - The ResourceSlice reconcile log stays at level 3. Its namespaced name is removed.
  - The unscheduled-Pods reconcile-start and "PodsScheduled condition updated" logs move from level 4 to level 3.
  - PodSet-count mismatch logs in `RestorePodSetsInfo` move to level 1 in JobSet, KubeflowJob, MPIJob, RayJob, and RayCluster (`common.go`). SparkApplication moves its mismatch log from level 2 to level 1.
  - LocalCapacity logs nil-error fallbacks at level 1. Non-nil errors log as errors.
  - The noop reconciler logs its skipped setup at level 1 through the manager logger, not `ctrl.Log`.
- **Errors:** The SparkApplication ready-executor count failure logs as `Error`, not as a level 2 info record.
- **Keys and references:**
  - RayCluster renames `oldCount`/`newCount` to `previousCount`/`count`.
  - Failure recovery renames `pod_count` to `podCount`.
  - The forceful-termination log no longer includes the pod object.
  - Several logs use `klog.KObj` or `klog.KRef` for object references. These cover the CapacityProvider, the DynamicQuotaOrchestrator, the MultiKueue capacity provider, RayCluster fields, and the unscheduled-Pods workload reference.
- **Error handling:**
  - `AppWrapper.PodSets` returns the error from `awutils.GetComponentPodSpecs` wrapped as `getting AppWrapper component pod specs: %w`. It no longer logs the error first.
  - The unscheduled-Pods tracker logs the `PodsScheduled` update after `PatchStatus` succeeds. A patch error returns before that log.
- **API signature:** `NoopReconciler.SetupWithManager` takes a named parameter, `mgr ctrl.Manager`. Its signature otherwise matches the previous one.
- **Not changed:** `jobframework/utils.go` still uses `ctrl.Log` in `NewWorkload`. This change defers that fix because it needs a context parameter in several job integrations.
