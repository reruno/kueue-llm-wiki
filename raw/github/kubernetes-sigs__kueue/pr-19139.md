## Description

Cherry pick of #18325 on release-0.19.

#18325: Do not recreate the metrics of a deleted LocalQueue

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

The [`/cherrypick release-0.19` run](https://github.com/kubernetes-sigs/kueue/pull/18325#issuecomment-7004541764) conflicted in seven files. Three of them are the queue manager part of #18325, `RecordLocalQueueMetrics`, its caller and its test. It is left out, with the delete handler comment about it, because this branch does not have `kueue_local_queue_workload_creation_latency_seconds` from #18295. The other four come from code that is not on this branch: the execution time and recovery wait time metrics, the Workload custom labels on admission, and the eviction cause of configurable preemptions. There the pick keeps this branch's code and only records its LocalQueue metrics through `RecordLocalQueueMetricsForWorkload`, as #18325 does. The new `Evict` test watches the status write in `SubResourcePatch`, because this branch sends the server-side apply through `Status().Patch`.

_Disclosure: I used an AI coding assistant while preparing this PR._

```release-note
Observability: Fixed a bug where the metrics of a deleted LocalQueue, such as `kueue_local_queue_evicted_workloads_total`, could reappear after the deletion and stay, if Kueue recorded them for a Workload while the LocalQueue was being deleted.
```
