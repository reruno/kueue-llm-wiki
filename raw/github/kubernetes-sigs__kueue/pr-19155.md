/kind bug

#### What this PR does / why we need it?

When delete/create events for a non-TAS Pod coalesce, reconciliation can observe a replacement Pod with the same name but fewer resource requests. The previous comparison missed resources omitted entirely from the replacement, so the old node was not marked for requeue despite its newly available capacity.

Use the existing resource-decrease comparison to detect omitted requests as well as reduced values. Regression tests cover both request representations, unchanged and increased requests, and repeated reconciliation.

Replaces #18497 after recreating the fork, with the change reapplied to current main.

Reverting only the production fix through a Go overlay makes the omitted-request regressions fail in both request representations. | Full `make verify`, integration and E2E are left to presubmit CI; local lint and envtest tools were not installed. |

The existing unit-test targets select both packages. No API, configuration, or feature-gate changes.

## AI summary

This PR fixes TAS handling of non-TAS Pods. Kueue now detects freed capacity when a replacement Pod omits a resource request that the old Pod had.

- `pkg/cache/scheduler/tas_non_tas_pod_cache.go`: `updatePodUsage` now calls `requestsDecreased(oldUsage, requests)` instead of checking only `GreaterKeys`. A previously requested resource that is now omitted counts as a decrease. The node-migration check is unchanged. Lines changed: +3/-1.
- `pkg/cache/scheduler/tas_non_tas_pod_cache_test.go`: adds a case where a same-name replacement Pod with a different UID drops its CPU request. The test expects `cache.update` to return the old node. Lines changed: +14/-0.
- `pkg/controller/tas/pod_usage_controller_test.go`: adds `TestPodUsageReconcilerRecreatedNonTASPod`. It covers map and vectorized request forms, unchanged, reduced, omitted, and increased requests, and repeated reconciliation. Lines changed: +72/-0.

API changes: none.
