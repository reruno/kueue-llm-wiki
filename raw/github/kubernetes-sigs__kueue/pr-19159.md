#### What this PR does / why we need it?

Adds the `kueue_tas_node_replacement_total` counter, per ClusterQueue with a
`result` label, reporting the outcome of TAS failed node replacement (hot swap).

The `result` label has three values:
- `replaced`: a scheduling cycle re-admitted the workload, and the new topology assignment no longer uses the unhealthy node that was next in line for replacement.
- `no_replacement`: fail-fast eviction (`TASFailedNodeReplacementFailFast`) evicted the workload because no replacement node fit.
- `multiple_node_failures`: the TAS node controller evicted the workload because another node failed while replacement was already in progress.

Previously, a successful replacement was only logged at `V(3)`, and both eviction
cases were counted as the same `kueue_evicted_workloads_total{reason="NodeFailures"}`
series, so operators could not tell how often replacement avoids an eviction.

This PR also fixes a crash: the TAS node controller passed `nil` custom labels to
the eviction, so evicting a workload after multiple node failures panicked with
`inconsistent label cardinality` when `CustomMetricLabels` was enabled with
ClusterQueue labels configured. The node controller now receives the configured
custom labels, as the topology ungater already does.

Fixes #16729

#### Useful notes for your reviewer

- When a conflict retry in fail-fast eviction reads the workload without a quota
  reservation, `workloadevict.Evict` writes and reports nothing. The
  `no_replacement` counter is skipped in that case too.
- A re-admission is counted as `replaced` only when the previous assignment used
  the unhealthy node and the new one does not.

- `replaced`: a workload moves off the unhealthy node. The prior assignment used that node, and the new assignment does not.
