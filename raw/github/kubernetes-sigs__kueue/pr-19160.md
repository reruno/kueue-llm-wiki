#### What type of PR is this?
/kind bug


```release-note
ClusterQueue: Fixed a bug where deleting a ClusterQueue could stay blocked by its `resource-in-use` finalizer when its LocalQueue was deleted before a Workload that the scheduler was admitting. Kueue now rechecks the ClusterQueue when such a Workload is deleted.
```

The change is the same as #18662. The conflict came only from `ForgetWorkload`, which release-0.19 got through #18196 and keeps after `deleteWorkloadWithoutLock` with its own doc comment.
