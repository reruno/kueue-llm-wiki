#### What this PR does / why we need it?

`hack/cherry_pick_pull.sh` builds the cherry-pick release note with an `awk` program that collects the lines of every `release-note` block in the original PR body. CodeRabbit now adds its own `release-note` block inside its auto-generated summary, so #19160, the script-made pick of #18662, got the author's note and CodeRabbit's note in one block, until its body was fixed by hand. The robot-made pick #18975 got only the author's note. When the author block is `NONE` and the bot block has text, the script gets `NONE` plus the bot text, which slips past the `NONE` check from #18065.

The `awk` program now ignores everything after the closing fence of the first `release-note` block. That is the block [Prow's release-note plugin](https://github.com/kubernetes-sigs/prow/blob/9c8eff7c98cc979e833369aefe5d1e86afcf063f/pkg/plugins/releasenote/releasenote.go#L382-L383) and the [release-notes tool](https://github.com/kubernetes/release/blob/a70473d6dc31bbca171ff9c0f35b2fecd28fd43e/pkg/notes/notes.go#L424-L434) take the note from, and `hack/releasing/set_release_note.py` already relies on that.

#### Useful notes for your reviewer

- I ran the changed lines on the #18662 body, which gave two notes before and only the author's note after. A body with a single `NONE` block, with LF and CRLF line endings, is skipped before and after. An author `NONE` followed by a bot note gave `NONE` plus the bot note before and is skipped after.
- The `awk` program reads the whole body instead of calling `exit` after the first block. With `exit`, `jq` got SIGPIPE on a 120 KB test body, and `pipefail` aborted the script.
- `hack/legacy_cherry_pick_pull.sh` has the same `awk` program. I left it alone since it's deprecated and kept only as a fallback.
- AI usage disclosure: drafted with AI assistance, reviewed and edited by me.
