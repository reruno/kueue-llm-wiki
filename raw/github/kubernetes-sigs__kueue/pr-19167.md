#### What this PR does / why we need it?
Fixes #

During nomination, FlavorAssigner can probe a flavor whose preemption candidates are not yet eligible and learn a retryAt deadline before selecting an alternate flavor with spare quota. When TAS placement fails on that nominated flavor, updateAssignmentIfNeeded recomputes the assignment with NominationMapping pinned to the nominated flavor. That pinned pass skips the earlier flavor and returns retryAt = nil, and recordAssignment previously overwrote the stored retryAt with nil.

As a result, a workload requeued with PreemptionNoCandidates failed to arm a timed retry on its ClusterQueue or cohort and stayed inadmissible until an unrelated cluster event occurred. Retaining the earliest non-nil retryAt in recordAssignment preserves the retry deadline across in-cycle recomputations, with a regression test covering the TAS recompute path.

## AI summary

This PR keeps the earliest retry time for a workload across in-cycle assignment recomputations.

- `recordAssignment` in `pkg/scheduler/scheduler.go` sets `retryAt` with `cmputil.EarliestTime(e.retryAt, retryAt)`. The earlier code could overwrite the stored value.
- The assignment-error path in `nominateWorkload` also keeps the earliest `retryAt`.
- `getAssignments` no longer clears `retryAt` when an assignment fits or returns an error.
- `requeueAndUpdate` schedules a retry notification for `RequeueReasonGeneric`, in addition to `PreemptionNoCandidates` and `NoFit`.
- `pkg/scheduler/scheduler_preemption_retry_test.go` extends `TestRequeueAndUpdateRetryAt` with a generic requeue reason. It adds `TestRequeueAfterRetryAtTiming`, which uses `synctest`.
