## AI summary

This PR passes each ResourceSlice device's `AllowMultipleAllocations` value into the CEL device input. Before this change, Kueue left the field unset. The DRA CEL library reads an unset value as `false`. As a result, CEL selectors that check `device.allowMultipleAllocations` did not match devices that set the field to `true`.

The change touches two code paths:

- `buildDeviceListFromSlices` in `pkg/dra/claims.go` copies the field for ResourceClaimTemplate device checks.
- `matchDevicesWithSelectors` in `pkg/dra/counters.go` copies the field for capacity-source `deviceSelector` matching.

The PR also adds tests in `pkg/dra/claims_test.go` and `pkg/dra/pools_test.go`. These tests cover selectors that use `device.allowMultipleAllocations` and its negation. The diff covers 4 files, with 131 lines added and 6 removed.

The PR addresses `#18996`. It does not change CEL compilation or the `firstAvailable` check.

## Suggested release note

```text
DRA: Fixed a bug where CEL selectors that check `device.allowMultipleAllocations` matched no devices, even when the ResourceSlice device set the field to `true`. This caused ResourceClaimTemplate device checks and capacity-source `deviceSelector` matching to fail, and Workloads charged through those sources to stay pending. Kueue now copies the field from each ResourceSlice device, so these selectors match the device's actual value.
```
