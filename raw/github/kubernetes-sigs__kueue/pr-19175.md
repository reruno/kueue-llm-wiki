#### What this PR does / why we need it?

`exitAgnHost` runs `curl` inside the pod it asks to terminate, and the pod can terminate before it completes sending the response. The helper already ignores the exit code 137 for that case, but not the curl exit code 52 (empty reply from server), so the spec fails although the pod exited as requested. This PR ignores the exit code 52 too.

Seen in [pull-kueue-test-e2e-multikueue-extended-shard-0-main](https://prow.k8s.io/view/gs/kubernetes-ci-logs/pr-logs/pull/kubernetes-sigs_kueue/19173/pull-kueue-test-e2e-multikueue-extended-shard-0-main/2123515808335269888) on #19173:

```
[FAIL] MultiKueue when Creating a multikueue integration workload [It] Should run an appwrapper containing a job on worker if admitted [feature:appwrapper]

  STEP: Finishing the wrapped job's pods
  "level"=0 "msg"="Terminating pod" "pod"={"name"="job-1-9t89d" "namespace"="multikueue-6kxrf"}
  [FAILED] in [It] - test/e2e/multikueue/extended/appwrapper_test.go:87

  [FAILED] Expected success, but got an error:
      <exec.CodeExitError>:
      command terminated with exit code 52
```
