#### What this PR does / why we need it?

Fixes duplicate pending workload counts in ClusterQueue and LocalQueue metrics when ConcurrentAdmission and Workload custom metric labels are enabled.

Previously, the per-label metrics counted every Variant separately, causing a single Parent with three Variants to be reported as three pending workloads.

This change:

* Counts each Parent once, in one state, in the per-label pending workload metrics.
* Classifies a Parent as active if any Variant is active or inflight, and inadmissible otherwise. Within that state, the Parent counts once under each label value its Variants in that state carry.
* Fixes duplicate Variant counting in LocalQueue metrics when the ClusterQueue is absent, with or without custom labels.
* Keeps the per-label metrics consistent with the total pending workload counts when the Variants of a Parent carry the same label values, which is the normal case since Variants copy the Parent's labels.
* Documents the counting rule in the metrics reference.

Fixes #19174

Builds on #18748 and #18806.

Open question, also raised in #19174: when the Variants of a Parent carry different label values, the Parent counts once under each value carried in its state, so the per-label values can add up to more than the total. For example, active `team=a` with inadmissible `team=b` gives only active `a=1`, while two inadmissible Variants with `a` and `b` give `a=1` and `b=1`. Counting under the Parent's own labels would need the Parent's metadata in the queue. Please let me know if you'd prefer a different rule.
