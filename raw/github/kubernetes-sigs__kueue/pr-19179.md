#### What this PR does / why we need it?

Before admission, Kueue checks whether matching devices are available for each device request with CEL selectors in a `ResourceClaimTemplate`. Once a device matches an earlier request, Kueue excludes it from later requests in the same template. It applies this restriction to shared devices with `allowMultipleAllocations: true` as well.

However, `kube-scheduler` requires exclusivity across requests in the same claim only for exclusive devices, and allows shared devices to be allocated to multiple requests at the same time. Kueue should stop marking devices with `allowMultipleAllocations: true` as used across requests so later requests in the same `ResourceClaimTemplate` can still match them. Each request still evaluates its own CEL selectors and requires distinct devices when its count is greater than one.

## AI summary

This PR changes DRA CEL device matching in `pkg/dra/cel_device_matcher.go`. A device blocks later requests only when `AllowMultipleAllocations` is unset or false. The first-match pass, `pick`, and `holdAll` now apply this rule. Requests that need distinct devices still select distinct devices. The PR adds unit tests in `pkg/dra/claims_test.go` and an integration test in `dra_cc_test.go`.

### Suggested release note

```text
DRA: Fixed a bug that caused Kueue to reject workloads when multiple requests in a ResourceClaimTemplate matched the same device with allowMultipleAllocations: true. Now Kueue allows later requests to match that shared device, and each request still must satisfy its own CEL selectors.
```
