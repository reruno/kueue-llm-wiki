## AI summary

Fixes unstable classical preemption victim selection with AdmissionFairSharing (AFS) when `ClassicalPreemptionCandidateOrderCache` is disabled (`#19016`).

- `newCandidateIterator` in `candidate_generator.go` uses one `clock.Now()` timestamp for the whole ordering operation.
- With AFS enabled, candidates are ordered within each ClusterQueue. The next candidate is then selected by merging the queue heads.
- For the borrowing pass, candidates marked `ReclaimWithoutBorrowing` are excluded from a separate order when AFS is enabled.
- Tests cover ordering permutations, evicted-candidate ordering, victim stability, and an integration reclaim scenario.

### Suggested release note

```text
AFS: Fixed a bug that caused classical preemption to select different victims for the same state when ClassicalPreemptionCandidateOrderCache was disabled. Now Kueue selects victims consistently and respects LocalQueue usage ordering within AFS ClusterQueues. This behavior is gated by the ClassicalPreemptionCandidateOrderCache feature gate.
```

**Avoid scanning every ClusterQueue for every emitted candidate.**

The merge performs `(N+1)*Q` queue checks for N candidates across Q ClusterQueues. It continues to scan exhausted queues. With one candidate in each of 10,000 queues, construction performs 100,010,000 checks before `Next` can return a victim.

Use a heap of active queue heads to reduce merge work to `O(N log Q)`. Preserve the current ClusterQueue-name tie rule.
