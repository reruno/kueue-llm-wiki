#### What this PR does / why we need it?

The TAS hot-swap guide says Kueue evicts a workload after one failed replacement attempt. It mentions an exception for in-flight evictions but omits the recovery-timeout requirement and how Kueue decides whether to wait.

Document that `TASNodeReplacementDeferFailFastWhenUsefulInflightEvictions` is beta and enabled by default from v0.21. Explain that deferral requires a positive `waitForPodsReady.recoveryTimeout` and that Kueue retries placement when simulating the removal of in-flight evictions reveals a suitable replacement. Update the usage scenarios and feature-gate matrix to reflect that behavior.

Related to #15263, which introduced the deferral behavior.
