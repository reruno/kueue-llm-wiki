#### What this PR does / why we need it?

When Kueue manages a StatefulSet or a LeaderWorkerSet, its webhook keeps the Workload admitted and rejects only the Pod template updates that change quota. It compared `utilpod.SpecShape` of the old and new templates, which keeps only the container `requests` and `ports` and the Pod-level `resources.requests`. Since #4081, it accepted updates that change the effective requests of the Pods, so the Workload kept a quota that no longer matched its Pods:

- adding, changing or removing a container limit that has no matching request, since limits are used as missing requests,
- changing a Pod-level limit that has no matching Pod-level request,
- turning an init container into a sidecar container, whose requests then add up instead of being covered by the largest init container.

After the `SpecShape` check, `jobframework.ValidateImmutablePodGroupPodSpec` now compares the effective requests of the full old and new Pod specs, including the LimitRange defaults, and returns `Forbidden` when they differ. A new helper, `jobframework.AdjustmentInputsForUpdate`, lists the LimitRanges only when the containers, the init containers or the Pod-level resources change. In the LeaderWorkerSet webhook, the `AllowMutatingContainersWhenEffectiveRequestsDontChange` check no longer skips these changes. `SpecShape` is unchanged, because it feeds the role hash and the Workload hash.

The DisaggregatedSet webhook also calls `ValidateImmutablePodGroupPodSpec`, so it now resolves the LimitRange inputs the same way. It already used container and Pod-level limits as missing requests, so for DisaggregatedSet the check adds only the init container turned into a sidecar.

The check is behind the new Beta `ValidateEffectiveRequestsOnPodTemplateUpdate` feature gate, enabled by default. When it is disabled, the webhooks behave as before.

## AI summary

This PR adds effective-request validation for Pod template updates of managed StatefulSets and LeaderWorkerSets. It also applies the same validation in the DisaggregatedSet webhook.

- Kueue compares the effective Pod requests of the old and new Pod templates. The comparison uses limits as missing requests, Pod-level resources, sidecar requests, and namespace LimitRange defaults.

- The MultiKueue adapter compares init containers and regular containers separately.
- The StatefulSet, LeaderWorkerSet, and DisaggregatedSet guides and the feature gate list are updated. The DisaggregatedSet integration has not shipped, so the release note omits it.

### Comment by [@ivnovakov](https://github.com/ivnovakov) — 2026-11-24T11:36:26Z

The ACTION REQUIRED makes sense, since the gate is on by default. But "set matching requests" doesn't work for StatefulSets.
