#### What this PR does / why we need it?
Aligns logging in auxiliary binaries (`cmd/importer`, `cmd/experimental/kueue-populator`, `cmd/experimental/kueue-priority-booster`, `cmd/kueueviz/backend`) with the [Kueue Logging Policy](https://github.com/kubernetes-sigs/kueue/blob/main/site/content/en/community/contribution_guidelines/logging_policy.md):

- **`cmd/importer`:**
  - Moves per-pod/page logs (`check.go`, `import.go`, `process.go`) from `V(2)` to `V(3)` and final summary logs from `V(0)` to `V(1)`.
  - Renames `err` -> `error` on summary `Info` logs, drops duplicate `pod` key in `Import`, and removes double-logged `log.Error(err, "list")` in `ListPods`.
- **`cmd/experimental` (`kueue-populator`, `kueue-priority-booster`):**
  - Moves `"Starting manager"` from `V(0)` to `V(1)`.
  - Moves `LocalQueue` creation and `spec.priorityBoost` set/clear logs post-write at `V(3)` using `klog.KObj`.
  - Removes log-and-return in `KueuePopulatorReconciler.Reconcile` (returns wrapped errors) and removes `ctrl.Log`-backed `r.log` struct fields in favor of `ctrl.LoggerFrom(ctx)`.
- **`cmd/kueueviz/backend`:**
  - Unifies `middleware/cors.go` onto `slog` (`slog.Debug` / `slog.Error`), removing mixed `ctrllog` usage and the `V(2).Error` violation.
  - Capitalizes `slog.Warn` message in `handlers/cohorts.go`.

Part of #9801

#### Release note
```release-note
Observability: Aligned `kueue-importer`, experimental controllers (`kueue-populator`, `kueue-priority-booster`), and `kueueviz` backend logs with the logging policy. Startup and import/check summary logs moved to level 1, per-object and page-listing logs moved from level 2 to level 3, write transitions are logged after they succeed, duplicate error logs were removed, `kueueviz` CORS validation now logs via `slog`, and log keys were renamed (`err` to `error` in `kueue-importer`).

ACTION REQUIRED: If your dashboards, alerts or log queries depend on Kueue log messages, keys or verbosity levels, review them before upgrading. For the complete list of logging changes, see #19207. To keep the per-object logs, set the log level to 3 or higher.
```
