#### What this PR does / why we need it?

Extracts `extract_release_note()` in `hack/cherry_pick_pull.sh` so single-line inline release-note fenced blocks and notes starting on the opening fence line are parsed cleanly without skipping to a subsequent release-note block in the PR description.

Previously, the awk pattern `/<fence>/&&!d{f=1;next}` matching the opening release-note fence skipped the opening line even when the closing fence appeared on the same line (or when note text began on that line), leaving `f=1` and capturing a later block (such as an automated review block) instead of the intended release note.

This update:
- Handles single-line inline `release-note` and `release-notes` fenced blocks, stopping after the first block (`d=1`).
- Preserves note text starting on the opening fence line (e.g. notes starting immediately on the opening line like `release-note Fix X`).
- Preserves existing behavior for multiline release-note blocks, empty blocks, unrelated code fences, and large PR bodies.
- Reads strictly from `stdin` as an idiomatic Unix filter.
- Adds a sourcing guard to `hack/cherry_pick_pull.sh` and unit regression tests in `hack/testing/cherry_pick_pull_test.sh` wired into `hack/make/verify.mk`.

Fixes #19164
