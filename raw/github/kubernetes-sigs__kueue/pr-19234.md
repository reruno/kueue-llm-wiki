#### What this PR does / why we need it?

`LocalQueueMetrics` has been Beta and enabled by default since v0.17, but many tests still turn it on explicitly. The calls don't change the result, and they make it hard to tell which tests depend on the gate.

This PR removes those calls:
- 20 `SetFeatureGateDuringTest(..., true)` calls in `pkg/` unit tests,
- 19 `SetFeatureGateDuringTest(..., true)` calls in `test/integration`.

Two `BeforeEach` blocks contained only this call, so they are removed too.

Part of: #18993

#### Useful notes for your reviewer

I kept the calls that set the gate to `false` or to a per-case value, because they change the result:
- `TestRecordLocalQueueMetrics` and the other per-case calls in `pkg/cache/queue/manager_metrics_test.go`,
- `TestRecordLocalQueueMetricsForWorkload` (`pkg/cache/scheduler/localqueue_metrics_test.go`),
- the gate-off call in `pkg/cache/queue/manager_test.go`,
- the "CustomMetricLabels enabled but LocalQueueMetrics disabled" specs in `test/integration/singlecluster/controller/core/custom_labels_test.go`.

Tests only, no product code changes. Following the one-gate-per-PR approach discussed in #18993. The gate is on by default in every supported release, so this can be cherry-picked to release-0.19 and release-0.20.
