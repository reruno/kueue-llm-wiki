#### What this PR does / why we need it?

After an elastic Job with a slice topology request shrinks, its PodSet kept the whole topology assignment, so capacity in fully emptied slices stayed reserved. Follow-up to #17374, which trims the assignment exactly for PodSets without slices.

When the remaining Pods have ranks, the topology ungater now keeps the whole slices where the lowest ranks run (the remaining count rounded up to the outermost slice size) and releases the other slices. A partial slice stays fully reserved. Without ranks nothing is released. The Workload is patched only when the assignment changes.

Fixes #18371

#### Useful notes for your reviewer

- A release requires every remaining Pod to hold a rank inside the kept count and to run in a kept domain (the survivor check from #17374, applied to the kept slices). A slot a running Pod uses is never released.
- The kept slices follow where the lowest ranks run, not assignment order, because a scale-up merges assignments sorted by domain. When survivors are spread over more slices than the rounded count (after a regrow, or a Pod in a lent slot), all of those slices are kept.
- If one sliced PodSet cannot be trimmed, only that PodSet keeps its assignment. The Workload's other PodSets still shrink.
- Missing or invalid ranks (a bad index offset, a duplicate or missing rank) release nothing and are logged at V(3).
- The rounding uses the outermost slice size, the same size the scheduler's elastic scale-up check uses.
- Two existing unit cases that pinned "slice PodSets keep the full assignment" now use ranked Pods and expect the release. Unranked Pods and sliced PodSets without `PodIndexLabel` have their own cases.
- KEP-77's scale-down text is stale since #17374. I can update it in a follow-up.

AI assistance was used for this change. I reviewed and tested it.

#### Release note

```release-note
TAS: When an elastic Job with a slice topology request shrinks and its Pods have ranks (for example an Indexed Job), Kueue now releases the topology capacity of the slices that are no longer needed. A partially used slice stays reserved.
```

- Kueue keeps each whole slice that holds a remaining Pod. A partially used slice stays reserved.

- If sliced Pods lack node assignments or required topology labels, Kueue skips shrinking that PodSet.
