#### What this PR does / why we need it?

Adds the Workload custom metric labels to `kueue_cohort_subtree_admitted_active_workloads`, next to its ClusterQueue labels, the way `kueue_admitted_active_workloads` already has them.

Each ClusterQueue counts its admitted Workloads by Workload label values, read from the Workload object on add and remove. Cohort counts are keyed by the ClusterQueue values together with the Workload values. Workload events set their own series, resyncs and tree rebuilds walk the per-ClusterQueue counts, and a ClusterQueue relabel moves every Workload series. Without Workload labels configured, the series and counts are unchanged.

The shared custom label storage already takes a lock for every store, swap and delete. This PR adds a concurrency test for it that fails under the race detector if that lock is removed.

Fixes #14186

#### Useful notes for your reviewer

- ClusterQueue values have their own small comparable type (`cqVals`), held next to the Workload `labelValsSet` in `CQWorkloadVals`. ClusterQueue values never go into a `labelValsSet`, which keeps its capacity of 6. `ValsSetFrom` had no callers left and is removed.
- `LabelValsTracker` became an alias of a small generic tracker, so the Cohort counts can reuse the same Add, Count, Iter and Merge logic with the `CQWorkloadVals` key instead of a copy of it. Existing users of `LabelValsTracker` are unchanged.
- With Workload labels configured, a Cohort has no series for a set of values until a Workload with those values is admitted, as with `kueue_admitted_active_workloads`.

AI assistance was used for this change. I reviewed and tested it.

#### Release note

```release-note
Observability: `kueue_cohort_subtree_admitted_active_workloads` now carries the Workload custom metric labels next to the ClusterQueue ones, as `kueue_admitted_active_workloads` does. With Workload labels configured, a Cohort reports a series for a set of label values once a Workload with those values is admitted in its subtree. Without Workload labels, the metric is unchanged.
```
