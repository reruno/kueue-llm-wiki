## Description

#### What type of PR is this?

/kind cleanup
/area testing

#### What this PR does / why we need it?

#15927 made the "Creates variants for all flavors in the ClusterQueue" spec wait until one of its Variants is admitted. The spec only checks that a Variant exists for each flavor, so the wait was there to keep teardown from racing admission and leaving the `cq-constraints` ClusterQueue finalizer in place (#15921).

The product fixes for that race have landed:
- #18662 makes a deleted assumed Workload still request its ClusterQueue, and every `AfterEach` in this file now deletes the ClusterQueue before the LocalQueue;
- #18086 stops ConcurrentAdmission from creating Variants for a deleting Parent.

This PR removes the wait, the last wait-for-admission workaround in teardown. #14196 and #13493 changed the same file, but they fix in-spec flavor migration, not teardown, so they stay.

Fixes #15932

#### Useful notes for your reviewer

Tested locally. The spec passed 100 runs without the wait, and the concurrentadmission suite passed 3 times. The same removal also passed 150 runs before #18086, so the flake never reproduced locally. The evidence that the race is gone is the two fixes above.
