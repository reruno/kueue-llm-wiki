#### What this PR does / why we need it?

Fixes #19247, part of partial scale-up for elastic jobs tracked in #12100.

With the partial scale-up strategy, a pending scale-up slice (the probe after a partial admission, or a scale-up slice not admitted yet) copies `minCount` from the admitted slice. When the job scaled down below it, `EnsureWorkloadSlices` applied the new count to that pending slice, and the API server rejected the update (`minCount should be less or equal to count`). The job reconcile failed on every retry, so the admitted slice kept its quota, and was not finished when the job completed.

- `CanReduceMinCountOnScaleDown` (`pkg/workload/podsetscounts.go`) is now also true for a scale-up slice that is not admitted yet: a Workload with the `kueue.x-k8s.io/workload-slice-replacement-for` annotation, with or without quota reservation (a slice can hold a reservation while it waits for admission checks). `ApplyPodSetCounts` then caps its `minCount` at the new count, as #16742 does for admitted Workloads.
- The initial Workload keeps its `minCount` until it is admitted, so its admission stays all-or-nothing. Lowering it would let a 4 → 1 → 5 sequence admit it partially, which KEP-12100 lists as a non-goal (https://github.com/kubernetes-sigs/kueue/pull/16742#issuecomment-6137159184).
- KEP-12100 now describes the pending case.

#### Useful notes for your reviewer

- The other caller of `CanReduceMinCountOnScaleDown`, the Workload webhook, calls it only when the old Workload has quota reservation. It now also allows lowering `minCount` on scale-down for a scale-up slice that has reserved quota but waits for admission checks, so the update from `ApplyPodSetCounts` passes validation.
- A lower `minCount` on a pending scale-up slice does not allow a smaller admission while the replaced slice is admitted: the scheduler still requires the replacement to grow past that slice's grant.
- New integration test "Should follow a scale-down below minCount while a scale-up probe is pending" for batch/Job and RayCluster. Both fail without the fix. For RayCluster this is the path the KubeRay autoscaler takes when it lowers `replicas` on an idle cluster.
- The SparkApplication fix for #19226 depends on this PR: it raises the executor `minCount` to the initial executor count, so dynamic allocation reaches this path as soon as idle executors are removed.

#### Release note

```release-note
ElasticJobs: Fix a bug where an elastic job with the partial scale-up strategy stopped being reconciled, and kept its quota, when it scaled down below its initial count while a scale-up was pending.
```

### Comment by [@bolubo](https://github.com/bolubo) — 2026-11-22T03:53:39Z

I might be missing a state here: a replacement slice that has reserved quota but is still waiting for an admission check. `EnsureWorkloadSlices` also applies the counts to that slice (`manager.go:117`), and `normalizeActiveSlices` can pick it as the latest slice with a reservation (`workloadslicing.go:387`). It is not admitted yet, but `HasQuotaReservation` is true, so the new branch does not match and the minimum stays as is.

I tried `ApplyPodSetCounts` on such a slice (count 8, minCount 2, reserved, not admitted) with the new count of 1, and it ends at `count=1, minCount=2`. The PodSet CEL rule rejects that ("minCount should be less or equal to count", `workload_types.go:630`), so it looks like the same failure would return one state later.

Would keying the pending case on the annotation alone cover it? If the reserved-but-unadmitted state is intentionally out of scope, I would like to understand why.

### Comment by [@reruno](https://github.com/reruno) — 2026-11-23T11:16:29Z

You're right, thanks. With the old condition, a scale-up slice that had reserved quota but was still waiting for an admission check ended at `count=1, minCount=2`, which the CEL rule rejects. I dropped the `!HasQuotaReservation` term, so any scale-up slice that is not admitted can lower its minimum on scale-down, and added a unit case for this state. The Workload webhook now allows the same reduction for that slice; I updated the description.
