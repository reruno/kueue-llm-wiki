#### What this PR does / why we need it?

Manual cherry-pick of #17895 onto release-0.20; the robot's pick conflicted in `test/integration/multikueue/pod_test.go`.

The pod MultiKueue adapter deep-copies the manager Pod spec, including `spec.ephemeralContainers`, into the remote Pod. The API server rejects ephemeral containers on create, so a manager Pod debugged before dispatch was never created on the worker. This clears `EphemeralContainers` on the remote copy and adds an integration test.

Related: #17861

#### Useful notes for your reviewer

Conflict resolution: kept release-0.20's `StartManagerForSpec` helper and captured its manager client for the new ephemeral-containers spec. Existing specs are unchanged. The adapter change is identical to upstream.

Validation:
- `INTEGRATION_FILTERS='--focus=ephemeral.containers' make test-multikueue-integration`: fails without the adapter fix (`Eventually` timeout, `pods "pod1" not found`), passes with it.
- `INTEGRATION_FILTERS='--focus=MultiKueue.Pod' make test-multikueue-integration`: 6/6 passed.
- `go build ./...` and `go vet` on the touched packages passed.

This backport was prepared with AI coding agents (GPT-6.1 Terra, orchestrated by Claude Opus 5.5).

MultiKueue: Fix a bug where a Pod that had ephemeral containers added (for example, by `kubectl debug`) before dispatch was never created on the worker cluster.
