#### What this PR does / why we need it?

Manual cherry-pick of #17855 onto release-0.19; the robot's pick conflicted.

PodTemplates forbid ephemeral containers, so a Pod or pod group with ephemeral containers (for example added with `kubectl debug`) stayed pending when its ClusterQueue had a ProvisioningRequest admission check: the PodTemplate built for the ProvisioningRequest was rejected. This clears `EphemeralContainers` on the PodTemplate copy and adds unit and integration tests.

#### Useful notes for your reviewer

Conflict resolution: kept release-0.19's template-processing code and added the upstream fix and tests, adapting test literals and the integration manager setup (a pod controller option in `suite_test.go`) to release-0.19 APIs. Same file set as the release-0.20 pick, #19054.

Validation (Go 1.26):
- The new unit regression test fails without the fix; `go test ./pkg/controller/admissionchecks/provisioning/...` passes with it.
- Both new integration specs in `test/integration/singlecluster/controller/admissionchecks/provisioning` fail without the fix (PodTemplate forbidden error) and pass with it.
- `gofmt`, `go vet` on the touched packages, and `go build ./...` passed.

This backport was prepared with AI coding agents (GPT-6.1 Terra, orchestrated by Claude Opus 5.5).

#### Release note

```release-note
ProvisioningRequest: Fix a bug where a Pod or pod group with ephemeral containers (for example added with kubectl debug) remained pending when the ClusterQueue had a ProvisioningRequest admission check, because the PodTemplate created for the ProvisioningRequest was rejected.
```
