## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

With Fair Sharing and `PartialPreemption` enabled, a higher-priority Workload stays pending when shrinking the lower-priority Workloads does not free enough quota. Kueue should evict a lower-priority Workload whole instead, as it does without Fair Sharing.

Cause: the shrink pass used up the Fair Sharing candidates, so the whole-eviction search found none. Each search now gets its own copy.

Part of #975

#### Useful notes for your reviewer

|---|---|---|---|
| Fair Sharing evicts a victim whole when shrinking is not enough | unit | `go test ./pkg/scheduler/preemption/ -run TestPartialPreemptionGetTargets` pass; fails without the fix | |

<details><summary>Reproduce with Jobs</summary>

Kueue config:

```yaml
fairSharing:
  preemptionStrategies: [LessThanOrEqualToFinalShare, LessThanInitialShare]
featureGates:
  ElasticJobsViaWorkloadSlices: true
  PartialPreemption: true
```

1. Apply `00-setup.yaml` and `01-victims.yaml`, and wait until both Jobs run. They use all 5 Pods of quota.
2. Apply `02-preemptor.yaml`. It needs 3 Pods; shrinking `shrinkable` to its minimum of 2 frees only 1.
3. Run `kubectl get workloads -n pp-repro`. Without the fix, the preemptor stays pending with `insufficient unused quota for pods in flavor pp-repro-rf, 3 more needed`. With it, `shrinkable` is evicted and the preemptor is admitted.

`00-setup.yaml`:

```yaml

metadata:
  name: pp-repro
---
apiVersion: kueue.x-k8s.io/v1beta2
kind: ResourceFlavor
metadata:
  name: pp-repro-rf
---
apiVersion: kueue.x-k8s.io/v1beta2
kind: ClusterQueue
metadata:
  name: pp-repro-cq
spec:
  namespaceSelector: {}
  preemption:
    withinClusterQueue: LowerPriority
  resourceGroups:
  - coveredResources: [pods, cpu]
    flavors:
    - name: pp-repro-rf
      resources:
      - name: pods
        nominalQuota: 5
      - name: cpu
        nominalQuota: "10"
---
apiVersion: kueue.x-k8s.io/v1beta2
kind: LocalQueue
metadata:
  name: pp-repro-lq
  namespace: pp-repro
spec:
  clusterQueue: pp-repro-cq
---
apiVersion: kueue.x-k8s.io/v1beta2
kind: WorkloadPriorityClass
metadata:
  name: pp-repro-high
value: 1000
```
