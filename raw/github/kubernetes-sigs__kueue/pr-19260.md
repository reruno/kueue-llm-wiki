## AI summary

This PR documents and tests MultiKueue with `firstAvailable` ResourceClaimTemplates on workers with different devices.

- Docs: Users apply the same ResourceClaimTemplate on every worker. Each worker scheduler selects an alternative that its devices support.
- Docs: Every named DeviceClass must exist on each worker, including classes with no devices there. A worker that lacks a named class keeps the Workload inadmissible. Another worker can admit it.
- Tests: A new MultiKueue e2e scenario covers workers with different device availability. The Workload runs on the worker that can use the fallback alternative and is charged the shared `count`.
- Test config: The `gpu` device class mapping adds `gpu-preferred.example.com`.

No exported API declarations change.
