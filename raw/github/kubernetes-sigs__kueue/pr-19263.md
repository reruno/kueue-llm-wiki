#### What type of PR is this?

#### What this PR does / why we need it:
In `pkg/controller/tas/topology_ungater.go`, `podIndexOffsetFromAnnotation` parses the `kueue.x-k8s.io/pod-index-offset` annotation with `strconv.Atoi(offsetVal)`.

While webhook validation (`validatePodIndexOffsetAnnotation` in `pkg/controller/jobframework/tas/tas_validation.go`) rejects negative numbers and values exceeding 32-bit integer range (`strconv.ParseInt(offsetValue, 10, 32)` and `val < 0`), the controller lacked defense-in-depth bounds checking:
- A negative value (e.g. `"-1"`) was accepted without error and passed to `ReadRanksForLabels`, which shifts ranks via `*podIndex - int(offset)`.
- On 64-bit systems, a value exceeding `math.MaxInt32` (e.g. `2147483648`) was parsed without error and wrapped around into a negative integer upon `int32(parsed)` conversion.

This PR mirrors the webhook validation in `topology_ungater.go` by parsing with `strconv.ParseInt(offsetVal, 10, 32)` and explicitly checking that the offset is non-negative, returning `errParseOffsetAnnotation` if invalid.

#### Which issue(s) this PR fixes:
None

#### Special notes for your reviewer:
Added unit tests covering:
- missing annotation
- zero (`"0"`)
- positive integer (`"1"`)
- max int32 (`"2147483647"`)
- non-numeric string (`"invalid"`)
- negative integer (`"-1"`)
- integer exceeding 32-bit range (`"2147483648"`)
