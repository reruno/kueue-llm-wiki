#### What this PR does / why we need it?

Removes the milli rounding from `limitRequestRatioExceeded` in `pkg/util/limitrange/limitrange.go`, now that the minimum supported Kubernetes version is 1.38.

The rounding was added in #18931 to match the LimitRanger admission plugin in Kubernetes 1.35-1.37. Since Kubernetes 1.38 (kubernetes/kubernetes#141348), LimitRanger compares the exact quantities, so the rounding can admit a Workload whose Pods are then rejected (for example maximum `2.0001`, request `1`, limit `2001m`).

Changes:
- `limitRequestRatioExceeded` now compares the original quantities exactly: `limit > request * maxLimitRequestRatio`.
- Removed the `roundedUp` helper, the milli/whole-unit scale selection, and the TODO.
- Updated `TestValidatePodSpec`:
  - `2.0001` / `2001m` now expects the LimitRange error.
  - Added boundary cases (equal to a sub-milli maximum).
  - Added sub-milli request and limit cases (`300u`/`700u` rejected, `300u`/`600u` accepted).
  - Renamed cases that referred to rounding.

Fixes #19255

#### Useful notes for your reviewer

- This is only valid once Kubernetes 1.38 is the minimum supported version, as stated in the issue. On 1.35-1.37 the exact compare would reject Workloads whose Pods LimitRanger accepts.
