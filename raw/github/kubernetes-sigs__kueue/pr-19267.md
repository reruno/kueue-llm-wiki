## Description

#### What type of PR is this?

#### What this PR does / why we need it?

With Admission Fair Sharing, a LocalQueue whose `stopPolicy` is `Hold` or `HoldAndDrain` returned from `Reconcile` before sampling its consumed usage. Its admitted Workloads keep running (or are evicted, for `HoldAndDrain`), so its usage can change while it is stopped. Without samples, the first sample after the queue resumes applies the usage left at that moment to the whole stop. A Workload that finished or was evicted during the stop was therefore undercounted, and the queue looked less active than it was when it competed for admission again.

The reconciler now keeps sampling AFS consumed usage for a stopped LocalQueue, at the same sampling interval as for an active one. It does not rebuild the ClusterQueue in the queue manager for a stopped queue, because a stopped queue is not in the queueing system.

Two edge cases from the review on the held path:

- A stopped LocalQueue whose ClusterQueue does not exist skips the sample and returns no error. Before, the stopped path returned successfully, and the new sampling would otherwise have failed every reconcile until the ClusterQueue appeared. Nothing can be admitted without the ClusterQueue, so no usage is lost, and the ClusterQueue watch requeues the LocalQueue once it is created.
- The `kueue_local_queue_admission_fair_sharing_usage` series is not reported for a stopped LocalQueue. Stopping the queue clears its gauges, and a sample while stopped would otherwise recreate the series. The series comes back with the first sample after the queue resumes. Deleting the LocalQueue already clears it on main (#17968).

Out of scope: a LocalQueue whose ClusterQueue is inactive (for example a ClusterQueue on `Hold`) still returns before sampling, so it has the same gap. That path has more semantics to settle and can be tracked separately, as discussed in the review.

This takes over #15384 by @shashankvarma499, as @apullo777 offered there. Their two commits are kept and rebased onto main, and @apullo777's review comments are addressed in a follow-up commit, which also moves the integration spec to the `behavioral` helpers.

Fixes #15383

#### Useful notes for your reviewer

The sample uses the same accounted usage as an active queue, so with `AdmissionFairSharingAnchorAtQuotaReservation` (#15000) a stopped queue also counts its quota-reserved Workloads.

Tests:
- `TestLocalQueueReconcile`, "held local queue still updates AFS consumed usage" (from the original PR): fails on main.
- `TestLocalQueueReconcile`, "held local queue skips the AFS sample while its ClusterQueue is missing": the reconcile returns no error and keeps the usage history. It fails without the skip (`ErrCqNotFound`).
- `TestLocalQueueReconcileDoesNotReportAdmissionFairSharingUsageMetricWhileStopped`: a stopped LocalQueue is sampled, but its AFS usage series is not recreated. It fails without the stopped-queue check in `reportAfsUsage`.
- Integration, `fairsharing` suite, "keeps sampling AFS usage while the LocalQueue is held": a held LocalQueue keeps accruing the usage of its running Workload, and its usage decays after the Workload finishes, before the queue resumes. It fails on main. The whole `fairsharing` suite passes.

CI selection: the unit tests are in `pkg/controller/core`, run by `make test`. The integration spec is in the `singlecluster/scheduler/fairsharing` suite under the existing `feature:admissionfairsharing` label, and it is not labeled `slow` or `redundant`, so `make test-integration-baseline` runs it.

I used an AI assistant while preparing this PR.
