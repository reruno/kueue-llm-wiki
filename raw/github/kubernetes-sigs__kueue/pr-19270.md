#### What this PR does / why we need it?

Since `ManagedJobsNamespaceSelectorAlwaysRespected` went GA in v0.19, the job reconciler skips every job in a namespace that `managedJobsNamespaceSelector` doesn't match, with or without a `kueue.x-k8s.io/queue-name` label. `WorkloadShouldBeSuspended` still suspended any job with a queue name without checking the namespace, so a job created with a queue name in such a namespace (for example `kube-system` with the default selector) was suspended by the webhook and never unsuspended.

`ApplyDefaultForSuspend` now doesn't suspend a job in a namespace that the selector doesn't match. Jobs in matching namespaces, and jobs without a queue name, keep their behavior.

Fixes #19269

#### Useful notes for your reviewer

- `ApplyDefaultForSuspend` is used by the webhooks of the job kinds that the job reconciler handles (Job, JobSet, MPIJob, the Ray kinds, SparkApplication, and the BaseWebhook integrations). `WorkloadShouldBeSuspended` itself is unchanged: StatefulSet, Deployment and LeaderWorkerSet use it in their own reconcilers, and a queued StatefulSet outside the selected namespaces is still managed, as its integration test expects.
- The doc comment of `managedJobsNamespaceSelector` in the Configuration API still describes the pre-GA behavior for non-Pod integrations. I left it out to keep this PR to the fix; happy to update it here if you prefer.

Tests, which fail on main and pass with the fix:
- `TestDefault` (Job webhook): a Job with a queue name in an unmanaged namespace stays unsuspended; one in a managed namespace is still suspended.
- Integration, Job webhook suite: a Job with a queue name created in an unmanaged namespace stays unsuspended.

I used an AI assistant while preparing this PR.
