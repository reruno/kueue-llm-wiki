## Description

## Problem
`helm upgrade --reuse-values` on the packaged Kueue chart keeps the previous release's image tags: the upgrade applies the new chart's templates and CRDs, but the controller manager (and KueueViz) keeps running the old image. Fixes #19272.

## Root cause
`hack/helm-chart-package.sh` writes `${GIT_TAG}` into the packaged charts' `values.yaml` as `.image.tag` defaults. `--reuse-values` uses the previous release's values (including its chart defaults) as the base for the upgrade, so the old tag is carried forward even on a newer chart version.

## Fix
Stop setting `.image.tag` in the packaging script for the Kueue, KueueViz backend/frontend, populator and priority booster images (repository and pullPolicy are still set, as suggested in the issue). The kueue and KueueViz templates already render `image.tag | default .Chart.AppVersion`, and the same fallback is added to the populator and priority booster `templates/manager.yaml`, which had none, so fresh installs resolve the same images as before while `--reuse-values` upgrades now pick up the new chart's `appVersion` (set via `helm package --app-version "${GIT_TAG}"`).

## Testing
Verified the script no longer contains any `image.tag = "${GIT_TAG}"` mutation and that the two templates render `{{ .Values...image.tag | default .Chart.AppVersion }}`; diff is 7 lines across 3 files. The kind/OCI-chart reproduction from the issue is not runnable in this environment (no kind cluster); the chart unit test suggested in the issue (empty tag renders `<repository>:<appVersion>`) is a natural follow-up for CI.

### Comment by [@bfs2021](https://github.com/bfs2021) — 2026-11-21T22:12:37Z

`pull-kueue-verify-main` failed on c440efe, and the failure is real and introduced by this PR — fixed in 270f1a86.

Root cause: `helm-chart-package.sh` clears the tags with yq, and an empty tag can only be written double-quoted, so the node's style flips from plain to `tag: ""`. The revert then writes the default tag back into that double-quoted node, and yq keeps the node style — the working tree ends up with `tag: "main"` instead of the original `tag: main`. `make verify`'s `git diff --exit-code` catches it:

```diff
-      tag: main
+      tag: "main"
```

Reproduced locally with `GIT_TAG=v0.21.0-rc.1-10-g837b42a5f ./hack/helm-chart-package.sh` on the PR branch: the same three hunks in `charts/kueue/values.yaml` (blob `ad82ddf9f` → `2c242996b`), byte-identical to the prow failure.

Fix in 270f1a86: drop the yq revert and restore all three values files from copies taken before the temporary edits, so the tree comes back byte-exact. Verified after the change:

- script run leaves `git diff --exit-code charts/kueue cmd/experimental` clean
- all three packaged `.tgz` values files still carry `tag: ""` (plus the staging repository and `IfNotPresent`)
- `helm template` on the packaged chart still renders the manager image as `...kueue/kueue:v0.21.0-rc.1-10-g837b42a5f`, i.e. the AppVersion fallback still wins

The verify job will pick the fix up on the new commit.

+# Chart.yaml appVersion. The experimental charts bundle the kueue chart via

+# GIT_TAG differing from the committed appVersion would make every bundled
+# image (controller, kueueViz backend and frontend) fall back to the stale
+# committed appVersion; `--app-version` fixes only the top-level charts.
+#

+# git archive copy of the tree with a deliberately mismatched GIT_TAG, so it
