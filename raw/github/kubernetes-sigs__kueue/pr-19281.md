## Description

Cherry pick of #19172 on release-0.20.

#19172: DRA: search other devices when a CEL request falls short

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

The [`/cherry-pick release-0.20` run](https://github.com/kubernetes-sigs/kueue/pull/19172#issuecomment-7068879325) conflicted. This branch does not check `firstAvailable` requests against the devices (#19158 isn't here). So the matcher has one alternative per request, and the three `firstAvailable` unit cases are left out. The one that fails when the search tries device sets that cannot fit is replaced by its `exactly` version, which keeps only its second alternative. The KEP leaves out the `firstAvailable` part; the docs and the integration tests are the same as in #19172. On 613,118 generated claims with up to three `exactly` requests, the check returns the same errors here as on main.
