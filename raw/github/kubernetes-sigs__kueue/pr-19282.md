## Description

Cherry pick of #19172 on release-0.19.

#19172: DRA: search other devices when a CEL request falls short

For details on the cherry pick process, see the [cherry pick requests](https://git.k8s.io/community/contributors/devel/sig-release/cherry-picks.md) page.

The [`/cherry-pick release-0.19` run](https://github.com/kubernetes-sigs/kueue/pull/19172#issuecomment-7068871365) conflicted in six files. This branch rejects `firstAvailable`, `adminAccess` and `allocationMode: All` before the check. So the matcher has one alternative per request and no `holdAll`, and the three `firstAvailable` and six `adminAccess` unit cases are left out. The `firstAvailable` one that fails when the search tries device sets that cannot fit is replaced by its `exactly` version, which keeps only its second alternative. `Devices` goes to `pkg/util/testing`, next to this branch's ResourceSlice wrapper, and the new integration spec expects the `Inadmissible` reason, as the existing CEL spec does. The KEP leaves out the `firstAvailable` part, and the docs stay as they are because they do not describe the check here. On 498,883 generated claims with up to three `exactly` requests, the check returns the same errors here as on main.

_Disclosure: I used an AI coding assistant while preparing this PR._
