#### What this PR does / why we need it?

Manual backport of #18868 to `release-0.19`. The automatic cherry-pick hit [merge conflicts](https://github.com/kubernetes-sigs/kueue/pull/18868#issuecomment-7096549739).

Refresh the topology request on a StatefulSet's pending Workload when the Pod template topology annotation changes, including when the StatefulSet resumes from zero. Persist the request before clearing OnHold and leave Workloads with a quota reservation alone.

Related: #18867.

#### Useful notes for your reviewer

Source commit: `e7dad0e352eaf17fe40e2ffcf5d43d482c5853d0`. The backport uses the topology-request builder already present in release-0.19. It carries the StatefulSet regression cases and adapts the fixtures that exist on this branch.

| Coverage | Level | Local result |
| --- | --- | --- |
| Topology refresh, quota reservation boundary, and update failure | Unit | Passed with `go test -race -count=1 ./pkg/controller/jobs/statefulset` |
| Topology annotation edits and scale-up from zero | Integration | 20/20 StatefulSet envtest specs passed with the race detector. |

The local full `make verify` invocation hit the repository lint timeout.

StatefulSet: Fixed a bug where a pending Workload kept the old TAS topology request after the Pod template topology annotation changed, including on scale-up from zero replicas.
