## Description

#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it?

Splits long make prerequisite lists into one target per line:

- `verify-checks` in `hack/make/verify.mk` (30 targets, a 682-character line)
- `verify-artifacts` in `hack/make/verify.mk`
- `dep-crds` in `hack/make/deps.mk`

These lists grow whenever a new check or dependency CRD is added. Before this change, each addition rewrote the whole line, so the diff was hard to review and parallel PRs conflicted. Now an addition shows up as one added line.

The order of the targets is unchanged. The `## ...` help text moved to its own `target: ## ...` line, as `verify-checks` already does.

#### Useful notes for your reviewer

No behavior change (formatting only):
- `make help` output is identical before and after.
- `make -pn verify-checks dep-crds verify-artifacts` shows the same prerequisites for all three targets.

`GINKGO_ARGS=--label-filter=a,b,c` lines in `hack/make/test.mk` are intentionally left as-is: a backslash-newline would insert spaces into the comma-separated filter.
