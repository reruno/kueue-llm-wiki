#### What this PR does / why we need it?
Verify the OpenAPI validation constraints defined on the alpha PreemptionLimit CRD through the core webhook integration suite on both creation and update. This ensures invalid limits, out-of-range sliding time windows, and unsupported aggregation modes are rejected by the API server while valid boundary values are accepted.

Covered validation cases:
- Reject negative limit; allow 0 and positive limits.
- Reject 0 (both omitted and explicit), negative, and >7-day windowSeconds; allow 1 second and 7 days (604800 seconds).
- Reject empty and unknown aggregation values; allow all defined PreemptionLimitAggregation enum values.

Also adds a PreemptionLimitWrapper helper in pkg/util/testing/v1alpha1 for constructing test fixtures consistently with other v1alpha1 APIs.
