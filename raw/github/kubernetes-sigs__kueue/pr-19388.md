#### What this PR does / why we need it?

The KueueViz dashboard currently sends and renders every workload and its pod details. With a large retained workload history, both the WebSocket payload and browser table grow with the entire workload list.

Add optional backend pagination and dashboard controls with 25 rows by default and 25/50/100 choices. Sort and select the page before pod enrichment, preserve namespace-wide totals and live updates, and retain links to off-page preemptors. Namespace/page-size changes reset to the first page; deletions clamp the current page. Expansion and preemption notifications apply to displayed workloads. Requests without pagination parameters preserve the existing response for older frontends.

Fixes #19387

#### Useful notes for your reviewer

Draft pending frontend/build/browser and repository-wide validation in an environment with the required tooling. AI disclosure: OpenAI Codex assisted with investigating, implementing, testing, and drafting this contribution.

The dashboard still scans cached workloads for totals and ordering, and lists pods in namespaces represented on the page. This change bounds workload rows and off-page pod records in the response; it does not bound cached workload scans or pod counts within one workload. Lazy pod loading and pagination on other pages are outside this PR.

The frontend requires pagination metadata and reports an explicit upgrade error if connected to an older backend. Upgrade the backend first when deploying components separately. The shared WebSocket hook discards previous subscription data/errors on URL or identity changes and ignores closed-socket callbacks.
