#### What this PR does / why we need it?

The CapacityBuffer AdmissionCheck reconciler previously updated the `Active` condition only when its `Status` changed. This allowed `ObservedGeneration`, `Reason`, and `Message` to remain stale following parameter changes where the condition continued to report `True` or `False`.

This PR uses the change-detection result of `apimeta.SetStatusCondition` to publish all meaningful condition updates without introducing redundant API writes.

**Changes:**

- Refresh `ObservedGeneration` when a valid CapacityBufferConfig reference changes while `Active=True`.
- Refresh diagnostic messages and observed generation when an invalid reference changes while `Active=False`.
- Correct stale condition reasons and messages independently of status transitions.
- Preserve `LastTransitionTime` for same-status updates while retaining correct behavior for `True ↔ False` transitions.
- Avoid status-subresource writes when the resulting condition is unchanged.

The implementation intentionally reuses Kubernetes API machinery's existing condition-update semantics. No scheduler behavior, API definitions, or watch mechanisms are modified.

**Regression coverage**

Adds a dedicated table-driven `TestACReconcileCondition` suite covering eight scenarios, including initial condition publication, same-status metadata refreshes, both status transitions, and unchanged conditions.

Each case performs a second reconciliation to assert idempotency. Status writes are counted using the repository's existing `utiltesting.CountSubResourceUpdates` helper.

Fixes #19389

#### Useful notes for your reviewer

The production change is limited to the CapacityBuffer AdmissionCheck reconciler, with a separate focused regression test file.

The Go source was formatted locally. The package tests have not yet been executed because the available environment uses Go 1.23.2 while upstream requires Go 1.27.0. CI results are therefore pending.
