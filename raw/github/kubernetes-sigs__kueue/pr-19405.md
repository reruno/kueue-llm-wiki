#### What this PR does / why we need it?

When two MultiKueueCluster entries point to the same worker, cleanup through one entry can delete a running Job if the entry used by the admitted workload disconnects. The check added in #19393 relies on that connection to recognize the remote Workload as still in use.

This change defers cleanup until the connection recovers or the workload is evicted. On reconnect, the check from #19393 runs again. After eviction, cleanup can proceed.

Related: #19173, #19392

#### Useful notes for your reviewer

The regression test disconnects worker2 while worker2-alias stays connected. Before the fix, cleanup deleted both the remote Workload and Job in about a second, before workerLostTimeout expired. With the fix, both survive the disconnect.

Do we want to support multiple MultiKueueCluster entries pointing to the same worker? Either way this keeps the e2e suites, which rely on that setup, from losing running Jobs when a spec breaks a connection.

## AI summary

MultiKueue cleanup no longer deletes remote objects of a running Job when another `MultiKueueCluster` entry points to the same worker. If the workload's admitting cluster is unavailable and the workload is unfinished, cleanup is deferred and retried. Cleanup proceeds after the cluster reconnects or the workload is evicted. The change is in `pkg/controller/admissionchecks/multikueue/workload.go`, with unit tests in `workload_test.go` and an integration test in `test/integration/multikueue/jobs_test.go`.

### Suggested release note

```text
MultiKueue: Fixed a bug that caused a running Job and its remote Workload to be deleted when one MultiKueueCluster entry disconnected while another entry pointed to the same worker cluster. Now Kueue keeps the remote objects until the cluster reconnects or the workload is evicted.
```

  **Do not restart the retention window after disconnection.**
  
  The worker-loss timeout is three seconds. `BreakConnection` waits for the inactive condition before it returns.   If that delay exceeds 0.5 seconds, the assertion can overlap valid eviction and alias cleanup. The controller measures the timeout from the first loss, not from the helper's return. ([raw.githubusercontent.com](https://raw.githubusercontent.com/kubernetes-sigs/kueue/6962e4d7725565da1b8c9adb5941cd481cb77334/pkg/controller/admissionchecks/multikueue/multikueuecluster.go))
