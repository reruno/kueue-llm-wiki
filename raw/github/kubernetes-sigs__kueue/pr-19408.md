## Description

#### What type of PR is this?

/kind cleanup
/area testing

#### What this PR does / why we need it?

The CapacityBuffer timeout e2e test could miss the eviction: with `backoffBaseSeconds: 1`, the Workload reserves quota again about a second after it is evicted, which resets `Evicted`, so the test could wait for another cycle and then race the timeout of the next buffer.

As suggested in the issue, the test now uses a 1s `timeoutSeconds` with the default 60s backoff and ends at the eviction: it waits for the Workload to be evicted by the admission check, then checks that the CapacityBuffer and its PodTemplate are deleted. Both conditions persist, so polling cannot miss them. The run after requeue is covered by the other test in the file.

Fixes #19390

#### Useful notes for your reviewer

|---|---|---|---|

The test no longer waits for the buffer to appear: with a 1s timeout it lives about a second, and a first run missed it.
