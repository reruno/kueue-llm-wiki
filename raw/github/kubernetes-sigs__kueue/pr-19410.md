## What this PR does / why we need it

Updating `ProvisioningRequestConfig.spec.podSetMergePolicy` could leave an existing pending `ProvisioningRequest` with the previous PodSet grouping. There are two independent gaps: the config watch ignores policy-only updates, and the request synchronization check compares provisioning class and parameters but not the desired PodSet layout.

This PR fixes both paths:

1. **Config change propagation:** `prcHandler.Update` now considers `PodSetMergePolicy` changes, including unset → set, set → unset, and switches between supported merge strategies.
2. **Convergence of pending requests:** `activeOrLastPRForChecks` computes the current merged PodSets at most once per admission check in its selection pass and checks their deterministic PodTemplate references and counts before retaining a pending request. When the layout has changed, it uses Kueue's existing stale-request cleanup and creation path, rather than mutating an existing immutable request spec.
3. **Safety:** Provisioned requests with live bookings, admitted workloads, and checks beyond the Pending state are not replaced because of a merge-policy mismatch. Failed, expired, or revoked requests retain their existing retry-state handling. Errors deriving the desired layout are propagated instead of causing destructive cleanup.
4. **Test maintenance:** Corrects the existing request-selection test's deterministic PodTemplate references for different attempts.

## Regression tests added

- PRC update handling: `nil → IdenticalPodTemplates`, `IdenticalPodTemplates → nil`, policy switch, and unchanged policy.
- Exact layout matching: unchanged layout, changed count, changed PodTemplate reference, and changed grouping.
- Fake-client lifecycle: two unmerged PodSets → one merged PodSet → two unmerged PodSets following config-only changes while the check is Pending.
- Provisioned-request preservation: an already-provisioned request is retained across a policy-only config update.

This PR fixes stale PodSet layouts on pending ProvisioningRequests after a `ProvisioningRequestConfig.spec.podSetMergePolicy` change.

- The controller now queues affected Workloads when `PodSetMergePolicy` changes, including unset/set transitions and strategy switches.
