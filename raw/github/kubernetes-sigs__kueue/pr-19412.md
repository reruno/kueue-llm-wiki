## Description

#### What type of PR is this?

#### What this PR does / why we need it?

`CapacityBufferConfig.spec.retryStrategy` allowed `backoffBaseSeconds: 0` and `backoffMaxSeconds: 0`. Unlike ProvisioningRequestConfig, the CapacityBuffer check has no `backoffLimitCount` and retries without a limit, so a zero backoff would requeue a workload whose buffers never fit right after each timeout. There was also no check that the base is not above the max.

This PR requires both fields to be at least 1 and adds a CEL rule that `backoffBaseSeconds` is less than or equal to `backoffMaxSeconds`. The CRDs, Helm chart, apply configuration and API reference are regenerated.

Part of #19231 (validate retry backoff settings).
