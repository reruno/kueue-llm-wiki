## Description

#### What this PR does / why we need it?

When the CapacityBufferConfig of an admission check is deleted, the CapacityBuffer controller set every check that uses it to `Pending`, including checks that were already `Ready` on admitted workloads. Kueue does not evict admitted workloads for a `Pending` check, so they keep running, but the controller only releases a PodSet's buffer and ungates its Pods while the check is `Ready`. A workload that was still starting, for example an InOrder JobSet whose later PodSet has no Pods yet, kept that buffer and its Pods stayed gated until the config was recreated.

Releasing the buffers does not need the config, so for an admitted workload with a `Ready` check the controller now releases the buffers before it looks up the config. The checks of workloads that are not admitted still go back to `Pending`. The KEP Handling row is updated to match, as discussed in https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644495484.

Part of #19231 (behavior when a config in use is deleted).
