#### What this PR does / why we need it?

Converts four test tables in `pkg/cache/scheduler/clusterqueue_test.go` from slices to `map[string]struct` keyed by test case name, and updates the runners to use the map key in `t.Run`: `TestClusterQueueUpdateWithFlavors`, `TestClusterQueueUpdate`, `TestClusterQueueUpdateWithAdmissionCheck` and `TestClusterQueueReadinessWithTAS`. Existing cases and assertions are preserved. This follows the repository's map-based table-driven unit test guidelines.

The cases do not depend on execution order: each subtest creates its own cache and client. The ordered `steps` tables in `TestClusterQueueEffectiveQuotasInactive` and `TestClusterQueueAssignmentPlanner` share one cache across steps, so they stay as slices.

Part of #19429
Fixes #19450
