#### What this PR does / why we need it?

Converts six test tables in `pkg/scheduler/scheduler_test.go` from slices to `map[string]struct` keyed by test case name, and updates the runners to use the map key: `TestEntryOrdering`, `TestLastSchedulingContext`, `TestRequeueAndUpdate`, `TestEntryComparerLess`, `TestResourcesToReserve` and `TestRecordWorkloadAdmissionEvents`. `TestEntryOrdering` and `TestEntryComparerLess` use inline tables, so their `range []struct{...}{...}` loops become `range map[string]struct{...}{...}`. Existing cases and assertions are preserved. This follows the repository's map-based table-driven unit test guidelines.

The issue lists four tables for this file. `TestLastSchedulingContext` and `TestRequeueAndUpdate` were not counted because they build the subtest name with `fmt.Sprintf`; they are converted here as well.

The cases do not depend on execution order: each subtest builds its own client, cache and queue manager. `TestEntryOrdering` sorts the shared `input` slice in place, but its expected orders do not depend on the starting order; the test passed 300 consecutive runs with random map order.

Part of #19429
