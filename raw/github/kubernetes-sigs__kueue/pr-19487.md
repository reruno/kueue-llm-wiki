#### What this PR does / why we need it?

No MultiKueue integration or e2e test uses a cohort today: every worker ClusterQueue in `test/integration/multikueue` and `test/e2e/multikueue` only sets `withinClusterQueue`. So worker-side `reclaimWithinCohort` is not covered.

This PR adds an integration test for a fragmented-capacity case we hit in production:

- The manager ClusterQueue quota is the sum of the quotas of two workers.
- On each worker, a sibling ClusterQueue in the same cohort borrows 3 of the 4 cpus that belong to the team ClusterQueue.
- The MultiKueue workload needs 4 cpus. It fits in the manager quota, but no worker has 4 free cpus.

The test checks that:

- the manager reserves quota without preempting;
- exactly one worker reclaims the borrowed quota, with reason `InCohortReclamation` (MultiKueue orchestrated preemption, KEP-8303);
- the workload is admitted on that worker;
- the other worker keeps its workloads admitted and no longer has a copy of the MultiKueue workload.

Test-only change; no production code changes.
