## Description

Cherry pick of #19306 and #19270 on release-0.19.

The automated cherry-picks failed to apply. On release-0.19, `ApplyDefaultForSuspend`, `WorkloadShouldBeSuspended` and the integration test helpers are package functions in `jobframework`, not `IntegrationManager` methods. The conflicts in `trainjob_webhook.go`, `defaults.go` and the two webhook unit tests come only from that, and the logic is the same as on main.

The two PRs go together because #19270 builds on the `ApplyDefaultForManagedBy` change in #19306, and one of its test cases was updated after #19306 merged.

On release-0.19, `pkg/controller/jobframework/...`, `pkg/controller/jobs/...` and the webhook jobs integration suite pass.

/assign mimowo

```release-note
MultiKueue: Fixed a bug where a job in a namespace that doesn't match `managedJobsNamespaceSelector` got `spec.managedBy` set to MultiKueue when its LocalQueue used a MultiKueue ClusterQueue, so the job never ran.
Fixed a bug where a job with a `kueue.x-k8s.io/queue-name` label in a namespace that doesn't match `managedJobsNamespaceSelector` was suspended by the webhook and never unsuspended, because Kueue doesn't manage jobs in that namespace.
```
