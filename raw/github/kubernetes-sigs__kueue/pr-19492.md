## AI summary

`PartialPreemptionPodSet` now returns no shrinkable PodSet, so the victim is evicted whole, when either of these holds:
- The Workload has the `kueue.MultiKueueOriginLabel` label.
- The Workload has not reached `PodsReady`. A Workload has reached it when the condition is absent, its status is `True`, or its reason is `WorkloadWaitForRecovery`.

Tests cover the new cases: a not-yet-ready victim is evicted, a MultiKueue-origin victim is evicted, a victim in `WaitForRecovery` still shrinks, and a victim with `Unknown` readiness is evicted.

## Suggested release note

```text
Scheduling: Fixed a bug that caused partial preemption to shrink Workloads that had never become ready and MultiKueue worker Workloads. Now Kueue evicts these Workloads whole. This behavior is gated by the PartialPreemption feature gate.
```
