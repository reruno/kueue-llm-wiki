<h2>Changes by Kind</h2>
<h3>Bug or Regression</h3>
<ul>
<li>AdmissionChecks: Fixed retry backoff delaying eviction and unnecessarily retaining quota and topology reservations. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18785">#18785</a>, <a href="https://github.com/garg02"><code>@​garg02</code></a>)</li>
<li>CLI: Fixed a bug where <code>kueuectl create resourceflavor --tolerations key=:NoSchedule</code> created an <code>Exists</code> toleration that also matched taints with nonempty values. It now creates an <code>Equal</code> toleration with an empty value. To tolerate any value, omit the <code>=</code> (for example <code>key:NoSchedule</code>). (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18943">#18943</a>, <a href="https://github.com/git-jxj"><code>@​git-jxj</code></a>)</li>
<li>ClusterQueue: Fixed a bug where deleting a ClusterQueue could stay blocked by its <code>resource-in-use</code> finalizer when its LocalQueue was deleted before a Workload that the scheduler was admitting. Kueue now rechecks the ClusterQueue when such a Workload is deleted. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18975">#18975</a>, <a href="https://github.com/ivnovakov"><code>@​ivnovakov</code></a>)</li>
<li>ConcurrentAdmission: Fixed a bug where adding a flavor to a ClusterQueue created a new Variant Workload for each finished Parent Workload in it, which the scheduler could then admit. Kueue no longer creates Variants for a finished or deleting Parent Workload. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18961">#18961</a>, <a href="https://github.com/ivnovakov"><code>@​ivnovakov</code></a>)</li>
<li>ConcurrentAdmission: Fixed the ClusterQueue <code>status.pendingWorkloads</code> and the <code>kueue_pending_workloads</code> metric counting a pending Workload once per Variant. A Workload is now counted once.
ConcurrentAdmission: Fixed the LocalQueue <code>status.pendingWorkloads</code> and the <code>kueue_local_queue_pending_workloads</code> metric counting a pending Workload once per Variant. The LocalQueue status also no longer counts the Parent Workload after a Kueue restart or an eviction. A Workload is now counted once. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19075">#19075</a>, <a href="https://github.com/Narwhal-fish"><code>@​Narwhal-fish</code></a>)</li>
<li>DRA: Fixed a bug where a Workload whose quota charges were recomputed while the scheduler was processing it, for example after a DeviceClass listed in deviceClassMappings was created or a LimitRange default changed, could be requeued with its old charges and reserve quota with them. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18781">#18781</a>, <a href="https://github.com/digvijay-y"><code>@​digvijay-y</code></a>)</li>
<li>DRA: Fixed a bug where a deviceClassMappings entry with two counter or capacity sources for the same driver and name charged a device's quota twice. Kueue now rejects such entries at configuration validation, and checks every counter source when two mappings name the same DeviceClass. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18923">#18923</a>, <a href="https://github.com/sohankunkerkar"><code>@​sohankunkerkar</code></a>)</li>
<li>DRA: Fixed a bug where a workload whose ResourceClaimTemplate names a missing DeviceClass was admitted and held quota while its Pods could never schedule. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18936">#18936</a>, <a href="https://github.com/sohankunkerkar"><code>@​sohankunkerkar</code></a>)</li>
<li>FairSharing: Fixed a bug where a ClusterQueue could not reclaim its nominal quota by preemption from Workloads that kept running on a flavor removed from another ClusterQueue's quota. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18913">#18913</a>, <a href="https://github.com/YevheniiOrlovEngineering"><code>@​YevheniiOrlovEngineering</code></a>)</li>
<li>FlavorFungibility: Fixed a bug where a Workload that needed to borrow one resource and preempt for another in the same flavor was never admitted with <code>preference: PreemptionOverBorrowing</code>, because no lower-priority Workloads were preempted. With <code>whenCanPreempt: MayStopSearch</code>, such a flavor also no longer stops the search when a later flavor fits without borrowing. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18892">#18892</a>, <a href="https://github.com/YevheniiOrlovEngineering"><code>@​YevheniiOrlovEngineering</code></a>)</li>
<li>Importer: Fixed a bug where the Pod importer always used the first ResourceFlavor of a resource group, so a Pod could be imported with a flavor whose node labels or taints it does not match. The importer now uses the first flavor that fits the Pod's node selector, required node affinity and tolerations, and rejects the Pod when none does. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19000">#19000</a>, <a href="https://github.com/burrows99"><code>@​burrows99</code></a>)</li>
<li>KueueViz: Fixed Cohorts in a parent cycle missing from the Cohorts tree view. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18917">#18917</a>, <a href="https://github.com/onkar717"><code>@​onkar717</code></a>)</li>
<li>LeaderWorkerSet: Fixed a bug where Kueue logged an <code>already exists</code> error and requeued the LeaderWorkerSet when it tried to create a Workload it had already created. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18891">#18891</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>MultiKueue: Fixed a bug where <code>multikueue_workloads_dispatched_total</code>, <code>multikueue_workloads_admitted_total</code> and <code>multikueue_workloads_evicted_total</code> kept reporting a deleted ClusterQueue. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19050">#19050</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>MultiKueue: Fixed a bug where deleting a manager Job with <code>--cascade=orphan</code> left the remote Job and Workload running on the worker cluster. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19067">#19067</a>, <a href="https://github.com/JanKaczmarski"><code>@​JanKaczmarski</code></a>)</li>
<li>MultiKueue: Fixed a bug where removing a worker cluster from a MultiKueueConfig re-dispatched the Workloads admitted on that cluster to another cluster without deleting their remote objects, so the same job could run twice. Workloads already admitted on the removed cluster now keep running there until they finish. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18984">#18984</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>MultiKueue: Fixed a bug where requeueing all of a worker's Workloads after the worker reconnected could delay dispatching new Workloads. Kueue now requeues those Workloads at low priority. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18997">#18997</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
<li>MultiKueue: Fixed a bug where restarting the manager could delay dispatching new Workloads until all unfinished Workloads were reconciled. Kueue now queues those Workloads at low priority when the controller starts. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19094">#19094</a>, <a href="https://github.com/kevin85421"><code>@​kevin85421</code></a>)</li>
<li>MultiKueue: Fixed a bug where the Incremental dispatcher retried deleted Workloads with backoff until Kueue was restarted, logging an error on every retry. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19051">#19051</a>, <a href="https://github.com/Zhuoxi2000"><code>@​Zhuoxi2000</code></a>)</li>
<li>Observability: Fixed <code>kueue_cohort_subtree_admitted_active_workloads</code> keeping stale custom-label series after a ClusterQueue was relabeled with <code>CustomMetricLabels</code> enabled. The count now moves to the new label series immediately. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19059">#19059</a>, <a href="https://github.com/vshalpnjabi"><code>@​vshalpnjabi</code></a>)</li>
<li>Observability: Fixed a bug that caused LocalQueue pending workload metrics to report zero when the associated ClusterQueue did not exist or was deleted. Now Kueue reports these pending workloads as inadmissible and refreshes the metrics when a ClusterQueue is deleted. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19017">#19017</a>, <a href="https://github.com/akshat-lakhera"><code>@​akshat-lakhera</code></a>)</li>
<li>Observability: Fixed a bug where <code>kueue_cluster_queue_resource_reservation</code>, <code>kueue_cluster_queue_resource_usage</code> and <code>kueue_cohort_subtree_resource_reservations</code> kept stale values for a ClusterQueue being deleted while its admitted workloads finished. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19125">#19125</a>, <a href="https://github.com/ivnovakov"><code>@​ivnovakov</code></a>)</li>
<li>Observability: Fixed a bug where <code>kueue_local_queue_admitted_active_workloads</code> and <code>kueue_local_queue_reserving_active_workloads</code> could be missing, and the admitted gauge could later become negative, after a single LocalQueue update changed <code>spec.stopPolicy</code> together with a custom metric label value or a label matched by <code>metrics.localQueueMetrics.localQueueSelector</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19089">#19089</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>Observability: Fixed a bug where <code>kueue_local_queue_unadmitted_workloads</code> could be reported for a LocalQueue after it was deleted or stopped, and where a Workload outside the queue, such as an inactive one, stayed counted in its old LocalQueue after it moved to a LocalQueue that did not exist. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18789">#18789</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>Observability: Fixed a bug where deleting a pending Workload during a scheduling cycle could log a spurious &quot;Could not update Workload status&quot; error and record a Warning event for the deleted Workload. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18791">#18791</a>, <a href="https://github.com/bodyhedia44"><code>@​bodyhedia44</code></a>)</li>
<li>Pod: Fixed a bug where a stale single-pod reconcile request for a Pod that joined a pod group after creation, such as a StatefulSet or LeaderWorkerSet Pod, was retried with backoff until the Pod was deleted, repeatedly logging <code>got a single pod reconcile request for a pod group</code>. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19057">#19057</a>, <a href="https://github.com/henry3260"><code>@​henry3260</code></a>)</li>
<li>ProvisioningRequest: Fix a bug where a Pod or pod group with ephemeral containers (for example added with kubectl debug) remained pending when the ClusterQueue had a ProvisioningRequest admission check, because the PodTemplate created for the ProvisioningRequest was rejected. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19054">#19054</a>, <a href="https://github.com/vladikkuzn"><code>@​vladikkuzn</code></a>)</li>
<li>ProvisioningRequest: Fix a bug where a Workload stayed Pending on a ProvisioningRequest admission check when a PodSet had a container without an image, such as the KubeRay autoscaler or the RayJob SidecarMode submitter. The ProvisioningRequest PodTemplate now fills missing images with the placeholder image <code>kueue.x-k8s.io/placeholder-image:placeholder</code>, and already stuck Workloads recover without being recreated. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18839">#18839</a>, <a href="https://github.com/vladikkuzn"><code>@​vladikkuzn</code></a>)</li>
<li>Scheduling: Fixed a bug where an inadmissible Workload could stay pending until an unrelated event if Kueue temporarily failed to read its Namespace, for example due to an informer-cache miss. Kueue now retries these Workloads automatically. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19060">#19060</a>, <a href="https://github.com/Om-Beast"><code>@​Om-Beast</code></a>)</li>
<li>Scheduling: Fixed a bug where changing the boost on an admitted Workload with a Pod PriorityClass did not trigger reevaluation of pending Workloads. Kueue now reevaluates pending Workloads when the boost changes. This behavior is gated by PriorityBoost. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19015">#19015</a>, <a href="https://github.com/weizhoublue"><code>@​weizhoublue</code></a>)</li>
<li>Scheduling: Fixed a panic in the scheduler when <code>WorkloadRequestUseMergePatch</code> was enabled and a Workload released its quota while Kueue was evicting it, for example for preemption. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19048">#19048</a>, <a href="https://github.com/thc1006"><code>@​thc1006</code></a>)</li>
<li>TAS × ElasticJobsViaWorkloadSlices: Fixed a bug where an elastic Job kept unused topology capacity reserved after scaling down, preventing waiting Workloads from using it. Kueue now releases that capacity once the removed Pods terminate. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18928">#18928</a>, <a href="https://github.com/garg02"><code>@​garg02</code></a>)</li>
<li>TAS: Fixed a bug where a ResourceFlavor <code>nodeLabels</code> entry with an empty value (for example <code>key: &quot;&quot;</code>) also matched nodes that do not have the label. Nodes now match only if they have the label with exactly that value. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/19101">#19101</a>, <a href="https://github.com/kaushik229"><code>@​kaushik229</code></a>)</li>
<li>TAS: Fixed a bug where an AppWrapper without explicit TAS annotations, admitted to a TAS-only ClusterQueue, was suspended and started again repeatedly. With MultiKueue, the Workload on the worker cluster was finished as <code>OutOfSync</code> and the AppWrapper did not keep running. (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18999">#18999</a>, <a href="https://github.com/toruiwasa"><code>@​toruiwasa</code></a>)</li>
<li>TAS: Fixed a bug where replacing a failed node failed, or evicted the Workload, when another node in its topology assignment was cordoned or NotReady while its Pods kept running. This affected clusters with the <code>TASReplaceMultipleFailedNodes</code> feature gate disabled (the default). (<a href="https://redirect.github.com/kubernetes-sigs/kueue/issues/18788">#18788</a>, <a href="https://github.com/nsega"><code>@​nsega</code></a>)</li>
</ul>
