## Description

#### What this PR does / why we need it?

Cherry-pick of #19063.

On the ClusterQueue detail page, LocalQueues can disappear from the table when they have no reservation resources. If the first flavor has no resources, the remaining rows can appear without the LocalQueue link.

Show a fallback row with the LocalQueue link when reservation data is empty. When resources exist, show the link on the first populated flavor’s first row.

#### Useful notes for your reviewer

- Resolved the cherry-pick conflicts in the dashboard component and its tests. This backport uses the release branch’s short queue labels and namespace-qualified link destinations.
- Both regression tests reproduced the bug on the unpatched release branch. With the fix, `npm test` passed all 137 frontend tests and `npm run build` passed.
- Full `make verify` was blocked because Docker and Podman were unavailable.
- Generative AI assisted with conflict resolution, validation, and drafting this PR.

#### Release note

```release-note
KueueViz: The ClusterQueue detail page now shows LocalQueue links even when reservation data is empty.
```
