#### What this PR does / why we need it?
Adds `PreemptionLimitsSnapshot` for KEP-16925 (https://github.com/kubernetes-sigs/kueue/pull/17277) so a single scheduling cycle can evaluate and update preemption limit consumption without races against concurrent `PreemptionLimit` updates or deletions:

- Capture per-limit specs, in-window preemption counts (`preemptionCounts`), and the earliest in-window event timestamp per `(limit, aggregationKey)`.
- Add `Record` to account for preemptions issued later in the same scheduling cycle and update earliest event timestamps.
- Add `WithinLimits` to check whether a batch of preemptions fits together within remaining allowances (returning `false` for non-empty preemptions on a `nil` snapshot or missing limit).
- Add internal helpers (`allowance`, `aggregation`, `nextSlotTime`) for upcoming limiter, budget, and tracker PRs.

Part of #16925

#### Useful notes for your reviewer
- This PR introduces only the snapshot type and its unit tests to keep reviews small. Follow-up PRs will add `PreemptionLimitTracker` (which builds snapshots from tracked events and tests tracker-to-snapshot isolation) and wire the snapshot into the limiter and scheduler.
- **AI disclosure:** this change was written with AI assistance, then reviewed and adjusted by me.
