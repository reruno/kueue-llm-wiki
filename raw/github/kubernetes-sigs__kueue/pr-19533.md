#### What this PR does / why we need it?

When a ClusterQueue custom label value changes, `ClusterQueueReconciler.resyncClusterQueueGaugeMetrics` clears `kueue_admitted_active_workloads` without the cache lock, and then `clusterQueue.resyncAdmittedActiveWorkloads` adds 1 per admitted Workload under the cache read lock. A Workload removed between the two steps writes -1 into the series for the new label value, so with two admitted Workloads the gauge ends at 0 instead of 1. A Workload admitted in the same window is counted twice.

`resyncAdmittedActiveWorkloads` now clears the ClusterQueue series itself, under the cache read lock, through a new `metrics.ClearClusterQueueAdmittedActiveWorkloadsSeries`. A per-ClusterQueue `admittedActiveResync` mutex keeps two concurrent rebuilds from interleaving their clears and adds, as `lqAdmittedActiveResync` does for the LocalQueue series.

## AI summary

This PR fixes a race that can make `kueue_admitted_active_workloads` incorrect after a ClusterQueue custom label changes. The ClusterQueue series is now cleared inside `resyncAdmittedActiveWorkloads`, under the cache read lock. A per-ClusterQueue mutex serializes rebuilds. The PR adds tests for removal before rebuild and for concurrent resyncs.
