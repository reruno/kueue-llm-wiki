## Description

#### What type of PR is this?

/kind bug
/area multikueue

#### What this PR does / why we need it?

When Kueue restarts and the kubeconfig of a worker cluster cannot be loaded, for example because its Secret is missing, the MultiKueueCluster reconciler returns before it adds a client for that worker. Without a client, nothing records when the connection to the worker was lost, so the `workerLostTimeout` of the Workloads admitted there starts again on every reconcile. These Workloads stay admitted, hold quota, and are never retried on another worker.

The reconciler now adds the client before it loads the config, so the worker is tracked as disconnected and its Workloads are retried once `workerLostTimeout` expires, as when the connection is lost without a restart.

This is the scenario in https://github.com/kubernetes-sigs/kueue/issues/18440#issuecomment-6956980398, the last open part of the issue.

Fixes #18440

```release-note
MultiKueue: Fixed a bug where a Workload admitted on a worker cluster could stay admitted and hold quota indefinitely when Kueue restarted while the kubeconfig of that worker could not be loaded, for example because its Secret was missing. Kueue now retries the Workload after `workerLostTimeout`.
```

## AI summary

- `Reconcile` in `multikueuecluster.go` now creates the remote client before it loads the cluster's kubeconfig. If the kubeconfig fails to load, for example after a restart with a missing Secret, the cluster is tracked as disconnected. Admitted Workloads on that cluster can then be retried after `workerLostTimeout`.
- Unit tests: `multikueuecluster_test.go` adds a missing-Secret case that expects a `BadKubeConfig` condition. Cluster-profile failure cases now expect an empty remote-client entry.
- Integration tests: `jobs_test.go` adds a slow test for a manager restart while the worker's kubeconfig Secret is missing. It checks the retry after the timeout and the restored Secret. The removed-worker restart test now restores the Secret right after restart.
- Scope: this covers the kubeconfig-load-after-restart case in `#18440`. It does not implement delayed cleanup on removed workers or persisted cleanup history.

## Suggested release note

```text
MultiKueue: Fixed a bug where Workloads admitted on a MultiKueueCluster whose kubeconfig failed to load after a Kueue restart, for example because its Secret was missing, could keep their quota and never be retried. Kueue now tracks the cluster as disconnected and retries the Workloads after `workerLostTimeout`.
```
