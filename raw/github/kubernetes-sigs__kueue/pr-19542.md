#### What this PR does / why we need it?

`TASNodeFeasibilityForAllLevels` has been Beta and enabled by default since v0.20, but many tests still turn it on explicitly.

This PR removes those calls:
- 21 `SetFeatureGateDuringTest(..., true)` calls in `pkg/` unit tests and benchmarks,
- 14 `features.TASNodeFeasibilityForAllLevels: true` entries in table-driven `featureGates` maps in `pkg/`,
- 1 `SetFeatureGateDuringTest(..., true)` call in `test/integration`.

A comment in `BenchmarkTASFlavorSnapshotWithWorkloadUsage` that only explained the removed call is removed too.

Part of: #18993

#### Useful notes for your reviewer

I kept the calls that set the gate to `false` or to a per-case value, because they change the result:
- the two "feature gate off" cases in `TestFindTopologyAssignments` (`pkg/cache/scheduler/tas_cache_test.go`),
- the gate-off call and the two gate-off table entries in `pkg/cache/scheduler/tas_flavor_snapshot_test.go`,
- the per-case `tc.nodeFeasibility` call in `pkg/cache/scheduler/tas_topology_tree_test.go`.

Tests only, no product code changes. Following the one-gate-per-PR approach discussed in #18993. The gate was added in v0.20 (Beta, on by default) and does not exist in release-0.19, so this can be cherry-picked to release-0.20 only.

| TAS integration suite with the gate at its default | integration | `INTEGRATION_TARGET=./test/integration/singlecluster/tas make test-integration` passed, 190 of 190 specs |
