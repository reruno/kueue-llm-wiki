#### What this PR does / why we need it?

Adds `PreemptionLimitTracker` for KEP-16925 (#17277), building on `PreemptionLimitsSnapshot` (#19509), to track confirmed configurable preemption timestamps in memory per `PreemptionLimit` and aggregation key:

- Implement `PreemptionLimitTracker` in `pkg/scheduler/preemption/limits/tracker.go` (safe for concurrent use):
  - `Record`: records preemption timestamps per consumed limit/aggregation key while skipping stale entries (deleted, recreated, or reset limits).
  - `Snapshot`: captures a point-in-time `*PreemptionLimitsSnapshot` of tracked limits and their in-window events/earliest timestamps.
  - `Counts`: returns active in-window preemption counts per aggregation key for a tracked limit.
  - `Sync`: initializes tracking for new limits, resets tracked events when UID/aggregation/selectors change, preserves events on `limit`/`windowSeconds` updates, and reports whether the change may allow more preemptions.
  - `Prune`: drops expired events older than the limit's window plus a grace period and cleans up empty aggregation keys.
  - `Forget`: stops tracking a deleted limit and drops its recorded events.
- Add shared test helpers (`AggregationEvents`, `EventsByLimit`, `NewTrackerForTest`, `SnapshotForTest`) in `pkg/scheduler/preemption/limits/test_util.go` and unit/concurrency tests in `pkg/scheduler/preemption/limits/tracker_test.go`.
- Restore tracker-to-snapshot isolation tests (`Forget`, `Prune`, `Record` after `Snapshot`) and switch `pkg/scheduler/preemption/limits/snapshot_test.go` to the shared test helpers.
- Add `Generation` setter to `PreemptionLimitWrapper` in `pkg/util/testing/v1alpha1/wrappers.go`.

Part of #16925

#### Useful notes for your reviewer

- This PR only adds the in-memory tracker and its unit tests (no controller or scheduler wiring yet). Follow-up PRs will wire `PreemptionLimitTracker` into the `PreemptionLimit` controller, limiter, and scheduler.
- Follow-up from #19509: restores the tracker-to-snapshot isolation test cases in `snapshot_test.go` that were deferred until the tracker was introduced.

+func TestPreemptionLimitTrackerSyncAndPruneConcurrent(t *testing.T) {
+	const goroutines, recordsPerGoroutine = 10, 100
+	const records = goroutines * recordsPerGoroutine
+	const windowSeconds = 60
+	start := time.Date(2026, time.January, 1, 0, 0, 0, 0, time.UTC)
+	window := windowSeconds * time.Second
+	limit := utiltestingalpha.MakePreemptionLimit("per-cq", kueuealpha.ByPreemptorCQLimitAggregation).
+		Generation(1).WindowSeconds(windowSeconds).Obj()
+	otherLimit := utiltestingalpha.MakePreemptionLimit("global", kueuealpha.GlobalLimitAggregation).
+		Generation(1).WindowSeconds(windowSeconds).Obj()
+	limitRef := policy.PreemptionLimitReference(limit.Name)
+	otherLimitRef := policy.PreemptionLimitReference(otherLimit.Name)
+	consumed := policy.ConsumedLimits{
+		limitRef:      policy.NewConsumedLimit(limit, "cq-a"),
+		otherLimitRef: policy.NewConsumedLimit(otherLimit, policy.GlobalAggregationKey),
+	}
+	// Every recorded event is already expired, so Prune keeps dropping events from
+	// limit while Sync updates its state and Record keeps adding to it.
+	now := start.Add(records*time.Second + window + pruneGracePeriod)
+
+	tracker := NewPreemptionLimitTracker()
+	tracker.Sync(otherLimit)
+	var wg sync.WaitGroup
+	for g := range goroutines {
+		wg.Go(func() {
+			for i := range recordsPerGoroutine {
+				tracker.Sync(limit)
+				tracker.Prune(now, limitRef)
+				tracker.Record(start.Add(time.Duration(g*recordsPerGoroutine+i)*time.Second), consumed)
+			}
+		})
+	}
+	wg.Wait()
+
+	got := tracker.limits[otherLimitRef].eventsByAggregationKey[policy.GlobalAggregationKey]
+	if len(got) != records {
+		t.Errorf("Recorded %d events of the other limit, want %d", len(got), records)
+	}
+	if !slices.IsSortedFunc(got, time.Time.Compare) {
+		t.Errorf("Events of the other limit are not sorted: %v", got)
