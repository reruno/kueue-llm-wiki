## Description

#### What type of PR is this?

/kind cleanup

#### What this PR does / why we need it?

The CapacityBuffer reconciler only creates and evaluates buffers for `Pending` checks, but this was implied by a `switch` that skipped `Ready`, `Retry` and `Rejected`. The check is now an explicit `Pending` guard, and the handling of a pending check moves from `Reconcile` into `syncPendingCheck`, as suggested in https://github.com/kubernetes-sigs/kueue/pull/19416#discussion_r4677729926. The behavior does not change.

The PR also adds the unit test follow-ups from #19419:
- `TestReconcileWithTwoChecks` covers both check orders for a foreign CapacityBuffer and for an ordinary create error, takes the foreign buffers as a slice, and asserts the specific error (https://github.com/kubernetes-sigs/kueue/pull/19419#discussion_r4676344354, https://github.com/kubernetes-sigs/kueue/pull/19419#discussion_r4677786453, https://github.com/kubernetes-sigs/kueue/pull/19419#discussion_r4677794009).
- The "retry when the timeout expires" case now uses a buffer that reports `RequiresNewCapacity`, which covers a buffer that is created on time but does not reach `FitsExistingCapacity` before the timeout (https://github.com/kubernetes-sigs/kueue/pull/19419#discussion_r4677769606).

Fixes #19544
Part of #19545

The commits can be reviewed separately: the first one only changes tests, the second one is the refactor. The only difference is for a check state outside the API enum, such as an empty string: it reached the buffer handling before and is now skipped. The API validation rejects such states.

`Retry` checks are skipped because Kueue resets them to `Pending` when it evicts the workload, as the new comment says. This was confirmed with a temporary assertion in the integration test "Should evict the workload when its buffers cannot be created in time": the check became `Pending` with the message `Reset to Pending after eviction. Previously: Retry`. The CapacityBuffer controller never sets `Rejected`.
