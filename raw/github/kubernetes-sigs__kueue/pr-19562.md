#### What this PR does / why we need it?
SparkApplication manager RBAC grants CRUD on `sparkapplications` but omits `sparkapplications/finalizers`. On clusters with OwnerReferencesPermissionEnforcement (notably OpenShift), creating a Workload with `blockOwnerDeletion: true` fails, so the SparkApplication stays suspended with no Workload.
Add `sparkapplications/finalizers` (`get`, `update`) to the manager role (and regenerated Helm RBAC), matching Jobs/Ray and other integrations. 

<!--

Fixes #19549 

#### Useful notes for your reviewer
- Source of truth is the kubebuilder marker in `pkg/controller/jobs/sparkapplication/sparkapplication_controller.go`; `config/components/rbac/role.yaml` and Helm RBAC were regenerated via `make manifests update-helm`.
- Same omission pattern as older Jobs finalizer gaps; Spark was added with CRUD only.
- Manually verified on a cluster with OwnerReferencesPermissionEnforcement:
1.   without `sparkapplications/finalizers`: Workload create fails with `blockOwnerDeletion` forbidden; SparkApplication stays suspended
2.   with `get`/`update` on `sparkapplications/finalizers`: Workload is created with `blockOwnerDeletion: true` and the app unsuspends
