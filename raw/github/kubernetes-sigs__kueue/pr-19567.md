## Description

This is a manual cherry-pick of #19009

Adjustments for this branch:
- The feature gate is lowered to Alpha and disabled by default, as requested in #19009: `FairSharingPreemptWithinClusterQueueFallback` is `{0.20, false, Alpha}`, like `PodIntegrationVerifyRoleRequests` on this branch. The docs section says alpha, and the generated feature gate lists are regenerated.
- This branch lacks #19352, so the pick includes its change that lets the fair sharing candidate iterator take its candidate list, which the fallback needs to search only the own candidates. This branch still declares `cont` in that iterator.
- This branch has no `SchedulerLibraryDeepIntegration`, so the WAS planner TAS cases and the `was_planner_test.go` change are left out.
- The dependency on `FairSharingVerifyFinalTargets` stays. With the gate off by default it breaks no existing configuration, so the release note has no `ACTION REQUIRED`.

Verified locally on the release-0.20 tree: build, unit tests with `-race`, the scheduler and TAS integration suites (464/464 specs), lint and `make verify`.

I used AI tools to help prepare this cherry-pick; I reviewed and tested the result.

/assign mimowo

```release-note
FairSharing: Added the alpha `FairSharingPreemptWithinClusterQueueFallback` feature gate, disabled by default on this release. When it is enabled and the final fair sharing check rejects a Workload's preemption targets, Kueue retries with only the Workloads of its own ClusterQueue that `withinClusterQueue` allows it to preempt. The gate depends on `FairSharingVerifyFinalTargets`.
```
