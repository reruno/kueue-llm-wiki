#### What this PR does / why we need it?

Related: https://github.com/kubernetes-sigs/kueue/pull/19329

In the scenario of https://github.com/kubernetes-sigs/kueue/pull/19329, a scale-up slice is replaced on the worker before the worker RayJob adopts it. That slice has no owner reference on the worker, so the worker's garbage collector does not delete it with the RayJob. It is removed only by MultiKueue: the manager deletes the remote copy when the manager slice is deleted, and the MultiKueue garbage collector deletes remote Workloads whose manager Workload is gone.

This PR extends the e2e spec from https://github.com/kubernetes-sigs/kueue/pull/19329 to check that this slice does not leak. After the RayJob recovers, the spec checks that the replaced slice is still not adopted on the worker, deletes the RayJob on the manager, and expects every Workload of the RayJob's slice chain on the worker to be deleted, including the replaced slice that was never adopted.
