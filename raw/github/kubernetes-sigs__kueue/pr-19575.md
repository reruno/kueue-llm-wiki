#### What this PR does / why we need it?

Related: https://github.com/kubernetes-sigs/kueue/pull/19329, https://github.com/kubernetes-sigs/kueue/pull/19569

In the scenario of https://github.com/kubernetes-sigs/kueue/pull/19329, a scale-up slice is replaced on a worker before the worker Job adopts it, so the slice has no owner reference there and the worker's garbage collector never deletes it. Only MultiKueue removes it: either the manager deletes the remote copy when it observes the deletion of the manager slice, or the MultiKueue garbage collector deletes remote Workloads whose manager Workload is gone.

The first path keeps the deleted Workload only in memory, so it is lost when the manager restarts at the wrong time. https://github.com/kubernetes-sigs/kueue/pull/19569 covers the first path in e2e. This PR adds an integration test for the second one: the manager slice is deleted while the manager is stopped, and after the restart the MultiKueue garbage collector must delete the unowned replaced slice from the worker while keeping the worker Job and its current slice.
