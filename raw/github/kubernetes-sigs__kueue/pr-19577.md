Clarifies KEP-5133 for the review comments tracked in #19231. Each commit answers one comment:

| Comment | Change |
|---|---|
| https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644408859 | `FitsExistingCapacity` includes nodes that have launched but have not registered or initialized yet. New risk, with the upstream `Provisioned` condition ([kubernetes/autoscaler#10484](https://github.com/kubernetes/autoscaler/pull/10484)) as the mitigation and a Beta criterion. |
| https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644456332 | Alpha supports Karpenter only. | https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644478410 | New risk for gated Pods when Pod creation stalls, with `waitForPodsReady` as the mitigation. |
| https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644525671 | ConcurrentAdmission is not supported in alpha. Pods that integrations create one at a time after admission cannot be gated and can use the buffered capacity until the last Pod is created. |
| https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644552911 | Beta criterion: the `CapacityBufferConfig` CRD is installed by default before the gate is enabled by default. Capped buffers and infeasibility detection are already Beta criteria. |
| https://github.com/kubernetes-sigs/kueue/pull/14700#discussion_r4644566694 | A `Ready` check is final: a buffer that stops fitting does not set it back to `Pending` or `Retry`. The sniping appendix is corrected to match. |

Part of #19231

#### Useful notes for your reviewer

No behavior change (docs/typo).

The described behavior was checked against the code and with temporary tests that are not part of this PR:
- Karpenter code: a NodeClaim counts as existing capacity once it has a provider ID, before its Node registers; zero replicas give `BufferEmpty`.
- Cluster Autoscaler sets `Provisioning=True` with `FakePodsInjected`, and the CapacityBuffer API package defines no reasons.
- With `waitForPodsReady`, a workload with an incomplete, gated PodSet is evicted with `PodsReadyTimeout` and its buffer is deleted (integration).
- On a kind cluster, a StatefulSet with ordered startup is admitted with one Pod, and its later Pods run before the buffer is deleted; with `Parallel`, the buffer is deleted at admission (e2e).
- A `Ready` check stays `Ready` when its buffer reports `RequiresNewCapacity`, before and after admission (unit).

## AI summary

This PR updates the KEP-5133 design document only. It has no code changes.

- Adds risks for capacity reported before its nodes are ready, and for gated Pods when a PodSet's Pods are not all created.
- Limits Provisioning status reasons to those Karpenter sets. Only `FitsExistingCapacity=True` maps to `Ready`.
- States that Kueue does not recheck a buffer after its check becomes `Ready`. A later change does not reset the check.
- Documents that integrations creating Pods one at a time cannot gate them. Alpha does not support ConcurrentAdmission.
- Adds Beta criteria to wait for a shared `Provisioned` condition and to install the `CapacityBufferConfig` CRD by default.
