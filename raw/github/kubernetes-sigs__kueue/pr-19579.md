#### What this PR does / why we need it?
Manual cherry-pick of #19187 to `release-0.19`, as the automated cherry-pick hit merge conflicts in `pkg/controller/tas/node_controller.go`, `pkg/controller/tas/node_controller_test.go`, and `test/integration/singlecluster/tas/suite_test.go`.

Related: #19187

#### Useful notes for your reviewer
- Resolved conflict in `pkg/controller/tas/node_controller.go` by keeping `logName: TASNodeController` and adding `customLabels: options.customLabels`.
- Resolved conflict in `pkg/controller/tas/node_controller_test.go` by keeping only the needed `labels` import and using explicit `NamespacedName` fields in `reconcile.Request` literals to match `release-0.19`.
- Resolved conflicts in `test/integration/singlecluster/tas/suite_test.go` by passing `tas.WithCustomLabels(customLabels)` and `scheduler.WithCustomLabels(customLabels)` without options that do not exist on `release-0.19` (`tas.WithRequeueBatchInterval`, `scheduler.WithFailedTASReplacementRecoveryTimeout`).
- Adjusted `test/integration/singlecluster/tas/tas_custom_metric_labels_test.go` for `release-0.19`: enabled `features.CustomMetricLabels` explicitly (defaults to `false`), removed `features.TASReplaceMultipleFailedNodes` (added in 0.20), and inlined the `UnhealthyNodes` check because `behavioral.ExpectAdmittedWorkloadWithUnhealthyNodes` does not exist on `release-0.19`.

#### Release note
```release-note
TAS: Fixed a panic and missing eviction metrics during multi-node failure eviction when custom metric labels are configured.
```
