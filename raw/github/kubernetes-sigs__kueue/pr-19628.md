#### What this PR does / why we need it?

Adds a gocritic `ruleguard` rule that reports table-driven tests which range over a slice and name subtests with a field of the case (`t.Run(tc.name, ...)` or `t.Run(fmt.Sprintf(..., tc.name, ...), ...)`), so new tests follow the map-based tables required by the coding guidelines. This is a follow-up to #19429, which converts the existing tables.

- `hack/tools/ruleguard/rules.go` holds the rule; `.golangci.yaml` enables the `ruleguard` check of gocritic and loads it.
- ruleguard type-checks the rules file against each module that `make ci-lint` lints, so each of those modules must require `github.com/quasilyte/go-ruleguard/dsl`. `hack/tools` already did; this PR adds `v0.3.23` to the root module (vendored: 2 small packages, BSD-3), `cmd/kueueviz/backend` and `cmd/experimental/webhook-conversion-repro`. A blank import under the `ruleguard` build tag keeps the requirement through `go mod tidy` and out of every build.
- The coding guidelines say when a slice is still fine (cases that depend on their order) and how to suppress the report with `//nolint:gocritic // <why the order matters>`.

The table changes stay out of this PR on purpose, so CI shows that the rule finds the remaining slice tables.
