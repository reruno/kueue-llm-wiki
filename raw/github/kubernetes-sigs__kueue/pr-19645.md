## Description

#### What type of PR is this?

/kind bug

#### What this PR does / why we need it?

`kueuectl list workload --for TYPE/NAME -A` and `kueuectl list pods --for TYPE/NAME -A` resolved the owner across all namespaces and always took `infos[0]`. When the same name exists in multiple namespaces, that silently picked an arbitrary owner.

This change returns an error asking for `--namespace` when more than one match is found.

Fixes #19638

## AI summary

`kueuectl list workload` and `kueuectl list pods` now check `--for TYPE/NAME` results before they choose an owner. When `-A` is set and more than one owner matches, the command returns an ambiguity error (`ErrAmbiguousForObject`) that includes the match count. The command no longer selects the first API result in this case. Tests cover the `job/train` case across two namespaces.

### Suggested release note

```text
CLI: Fixed a bug that caused `kueuectl list workload|pods --for TYPE/NAME -A` to select an arbitrary owner when the same name existed in multiple namespaces. Now Kueue returns an error and asks you to specify `--namespace`.
```
