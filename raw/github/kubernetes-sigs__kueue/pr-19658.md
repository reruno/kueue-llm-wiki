#### What this PR does / why we need it?

With Fair Sharing in a CohortTree, the search for a preemption target walks down from the root Cohort and enters the child with the highest share value. When two child Cohorts have the same share value, it entered whichever came last in `ChildCohorts()`, which is a set, so the order is random. This causes both problems from #10131:

- Priority is ignored: in the issue's tree, the search picks the high-priority Workload of team-a as often as the normal-priority Workload of team-b.
- Over-preemption: in the next scheduling cycle, while the first target is still being evicted, the search can enter the other Cohort and preempt a second Workload. Once the first eviction finishes, the incoming Workload is admitted, and the second target is admitted again right away.

When several child Cohorts share the highest share value, the search now enters each of them and picks the target whose next candidate comes first in the usual candidates ordering. A Workload that is already being evicted comes first, then lower priority, then the most recently admitted. This is the approach @gabesaba suggested in #10131, and it extends what #6764 did for ClusterQueues with the same share value to Cohorts. Pruning while entering a Cohort that isn't chosen is safe, because a node is pruned only when it has nothing left to offer.

A tie between a Cohort and a ClusterQueue still goes to the Cohort, as before.

Fixes #10131

#### Useful notes for your reviewer

The two new `TestFairPreemptions` cases build the tree from the issue and run 100 times each. On main, the first fails within a few runs by picking `a-high`. The second fails by picking `b-normal` while `a-high` is already being evicted, which is the extra preemption.

#### Release note

```release-note
FairSharing: Fixed a bug where, in a CohortTree, preemption chose its target at random among Cohorts with the same share value. It could preempt a higher-priority Workload, and preempt one more Workload in the next scheduling cycle while the first was still being evicted. Kueue now picks the target whose candidate comes first in the usual candidates ordering.
```
