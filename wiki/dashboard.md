# Dashboard (KueueViz)

**Summary**: KueueViz is a web UI for Kueue: it reads the Kueue API (and, partially, the [[visibility-api]]) to show per-[[cluster-queue]] usage, pending workloads, cohort utilization, and per-namespace quotas. It's a separate component (backend + frontend) deployed alongside Kueue, not part of the controller-manager.

**Sources**: `raw/github/kubernetes-sigs__kueue/`; pr-13970.md, pr-16392.md, pr-16394.md, pr-16696.md, pr-16739.md, pr-16608.md; 2026-10-21 batch: pr-17088.md, pr-17135.md, pr-17143.md, pr-17230.md, pr-17246.md, pr-17249.md, pr-16849.md, pr-17104.md, pr-17105.md, pr-17175.md, pr-17235.md, pr-17236.md, pr-17272.md, pr-17273.md, pr-17491.md, pr-17493.md, pr-16278.md, issue-17073.md, issue-17142.md, issue-17178.md, issue-17248.md, issue-16694.md, issue-17102.md, issue-17103.md, issue-17232.md, issue-17270.md, issue-17271.md, issue-17492.md and their backports; `raw/kueue/CHANGELOG/CHANGELOG-0.20.md`, `CHANGELOG-0.19.md`, `CHANGELOG-0.18.md`; `raw/kueue/cmd/kueueviz/backend/`.

## Components

- **Backend** — service account with read access to Kueue CRDs and Workloads; exposes a JSON API consumed by the frontend.
- **Frontend** — a web UI for cluster admins and tenants.

## Scope

KueueViz is oriented at operational visibility, not management actions — edits happen through [[kueuectl]] or plain `kubectl`. The UI covers:

- Cluster-queue list with usage vs. nominal quota.
- Cohort-level views.
- Per-namespace / per-LocalQueue pending workloads.
- Resource utilization plots ([[issue-10072]] — UI improvements).

## Known issues / evolution

- "Kueueviz backend fails to list cohorts due to missing permissions" ([[issue-10091]]) — the backend ServiceAccount needed an RBAC update when cohorts became a first-class CRD.
- "KueueViz: add e2e tests for the resource utilization feature" ([[issue-10132]]) — test coverage catching up to features.

## LocalQueue details: filter by `spec.queueName`

The LocalQueue details page used to list **every** Workload in the namespace regardless of which LocalQueue was selected: the backend `fetchLocalQueueWorkloads` (`cmd/kueueviz/backend/handlers/local_queue_workloads.go`) accepted a `queueName` parameter but never applied it ([[pr-11199]], fixes [[issue-6613]]; cherry-picked to 0.16/0.17 in [[pr-11212]]/[[pr-11213]]). The fix filters `wql.Items` client-side on `item.Spec.QueueName == queueName`. A server-side field selector was rejected because `spec.queueName` is not registered as a selectable field on the Workload CRD — so client-side filtering is used, consistent with `kueuectl list workload localqueue`.

## MultiKueue stats

"Support worker resource stats visibility in MultiKueue manager cluster" ([[issue-10105]]) — KueueViz historically couldn't reach into worker clusters; this opened the path.

## Namespace selector: WebSocket closed with a status

Selecting a namespace on the dashboard produced a WebSocket `1005` error (no status code) because the backend closed the connection without one. [[pr-14788]] (cherry-picks [[pr-14789]], [[pr-14790]]) closes the socket with an explicit normal-closure status on error and on component cleanup.

## KueueViz cluster RBAC no longer carries a namespace

The Helm chart emitted `metadata.namespace` on KueueViz's `ClusterRole` and `ClusterRoleBinding`, which are cluster-scoped. The API server clears namespace metadata for cluster-scoped resources before validation, so this was a manifest-hygiene problem rather than a rejection; [[pr-14816]] (cherry-picks [[pr-14824]], [[pr-14825]]) removes it while keeping the namespace where it is valid — the ServiceAccount subject and the namespaced `Role`/`RoleBinding`. Regression coverage renders the chart with a non-default release namespace.

## Frontend backend-URL resolution

The frontend reads the backend WebSocket URL from `REACT_APP_WEBSOCKET_URL` / `VITE_WEBSOCKET_URL`. Two bugs produced a blank page or a silent failure: `getBackendWebSocketUrl` threw before render when unset, and the Helm template `frontend-configmap.yaml` built `"<scheme>://<host>"` from `kueueViz.backend.ingress.host`, so an empty host yielded the truthy bare `wss://` and connections to `wss:///ws/workloads` (`new URL()` throws). Fixes: the frontend falls back to the page's same origin when no URL (or a bare-scheme URL) is set, using `wss` on HTTPS pages (source: pr-15293.md; backports pr-15646.md, pr-15647.md); the chart applies `| default "backend.kueueviz.local"` to the host like the other consumers, and generates `ws` or `wss` from the TLS configuration (source: pr-15242.md, pr-15591.md; backports pr-15644.md, pr-15645.md). The frontend ConfigMap kustomize patch must carry `namespace: system` to match the resource, otherwise `kustomize build config/kueueviz` fails (source: pr-15696.md; backports pr-15707.md, pr-15708.md). The `Code generated by yaml-processor` marker was removed from the ConfigMap template since the processing plan never generated it.

## Single-host, path-routed Ingress

By default the browser opens the WebSocket straight at the backend Service, which needs two DNS names, an `env.js` ConfigMap carrying the backend's external address, and `KUEUEVIZ_ALLOWED_ORIGINS` matching the frontend origin. The opt-in Helm value `kueueViz.ingress` (disabled by default) renders one Ingress on one host: `/ws`, `/api` and `/auth` go to the `kueueviz-backend` Service, `/` to the frontend (source: pr-15574.md; backports pr-15673.md, pr-15676.md). The Ingress is generated from the shared config directory, so non-Helm installs get an equivalent single-host manifest (docs cover host, TLS and migration) (source: pr-15863.md, issue-15669.md).

## Per-user authorization (v0.20, action required)

When authentication is enabled, the backend now checks Kubernetes RBAC for every API and WebSocket request with a **SubjectAccessReview** on the caller's identity (user, groups, UID, extra) instead of serving everything with its own ServiceAccount. `middleware.RequireAuthorization` wraps each route (`/ws/workloads`, `/ws/workloads/dashboard`, `/ws/workload/:ns/:name[/events]`, `/ws/local-queues`, `/ws/local-queue/...`, `/ws/cluster-queues`, `/ws/cohorts`, `/ws/resource-flavors`, their detail routes, and `/api/:resourceType/:name`). `sarAuthorizer` caches each decision in an LRU keyed by identity + resource attributes, with separate TTLs for allow (`CacheTTL`) and deny (`NegativeCacheTTL`). Users need `get`, `list` and `watch` for the views they open; the backend ServiceAccount needs `create` on `subjectaccessreviews.authorization.k8s.io` (included in the Helm chart; custom RBAC installs must add it) (source: CHANGELOG-0.20.md #13810; `cmd/kueueviz/backend/middleware/auth.go`, `handlers/handlers.go`). See [[security-authn-authz]].

**Per-user authorization exists only on release-0.20 and main.** release-0.19 KueueViz authenticates the token but checks no per-user access, so the authorization fixes below were not backported there (source: pr-17246.md, pr-17088.md, pr-17249.md review threads).

## Backend shutdown

- `srv.Shutdown(context.Background())` had no upper bound, so an HTTP request that never finished hung termination. The shutdown context now has a **30 s timeout** (`shutdownTimeout`). Upgraded WebSocket connections are not tracked by `net/http.Server.Shutdown` and are not waited on (source: pr-17135.md, fixes issue-17134; v0.20.2 pr-17198, v0.19.9 pr-17199).
- The manager goroutine and HTTP server goroutine used to call `os.Exit(1)` on failure, which skipped deferred cleanup. `runComponents` (`cmd/kueueviz/backend/main.go`) now reports component failures to the main flow, cancels the shared context, shuts the server down with the same timeout, waits for both components, and returns all errors (source: pr-17230.md; backports pr-17471, pr-17472, merged after v0.20.2 / v0.19.9).

## WebSocket heartbeat

The backend sends a WebSocket **ping control frame every 30 seconds** (`Handlers.heartbeatInterval`, default `30 * time.Second` in `handlers.New`) inside `handleInformerUpdates`, even when no dashboard data has changed, so idle connections are not dropped by proxies or load balancers. The ticker is created only when the interval is positive. A failed ping write closes the connection (the handler returns); a reviewer noted that a single transient write error therefore ends the session. Shipped in v0.20.0 (source: pr-13970.md, fixes #13961; CHANGELOG-0.20.md).

## Empty results must serialize as `[]`, not `null`

Several bugs had the same cause. A Go handler that builds its result with `var xs []any` and finds nothing returns a **nil slice**, which `encoding/json` writes as `null`. The frontend treats `null` as "not loaded yet":

- **LocalQueue detail page.** `fetchLocalQueueWorkloads` returned `null` for a queue with no Workloads; `if (workloadsData)` skipped `setWorkloads`, so removed Workloads stayed on screen. The same PR added the missing Status `<TableCell>` (first condition type, or `Unknown`) to the "Admitted Workloads" table, whose header had a Status column that rows never filled. Shipped in v0.20.1 / v0.19.8 (source: pr-16392.md, fixes issue-16391; backports pr-16692, pr-16693).
- **Resource list pages.** The Local Queues, Cluster Queues, Cohorts and Resource Flavors pages spun forever when a successful query returned nothing, for example an admin opening Cohorts on a cluster with no Cohorts. Handlers now return non-nil empty slices, so the page shows `No Cohorts found.` and similar. Unit tests assert on the returned value with `cmp.Diff([]map[string]any{}, got)`, because comparing only extracted names cannot tell nil from empty (source: pr-16739.md).

Rule for new handlers: initialise result slices with `make([]T, 0)` (or a literal), never a bare `var`.

## Frontend crash fixes

- **Workloads page empty state.** `Workloads.jsx` used `<Alert severity="info">` for "No workloads found" without importing `Alert` from MUI, so an empty cluster crashed the page instead of showing the message. Shipped in v0.20.0, v0.19.7 and v0.18.11 (source: pr-16394.md, fixes issue-16393; backports pr-16396, pr-16397).
- Also in v0.20.0 (source: CHANGELOG-0.20.md): one notification per preemption instead of thousands of duplicate error toasts (#13175); no crash when error details contain values that cannot be serialized (#13984); debug `console.log`/`console.error` removed from the frontend (#13983); Helm `kueueViz.{backend,frontend}.ingress.tlsEnabled` to turn TLS on or off independently of `tlsSecretName` (#13784).

## Workload → Pod matching

The workloads dashboard (`buildWorkloadPodsIndex` in `cmd/kueueviz/backend/handlers/workloads_dashboard.go`) indexes Pods by their `controller-uid` label and looks up each Workload by its `kueue.x-k8s.io/job-uid` label. Pods without `controller-uid` (anything not created by a batch Job) all shared the empty key, and Workloads without a job UID (pod groups, for example) looked up that same key, so they showed **every unlabelled Pod in the namespace**. Pods without `controller-uid` are now skipped when building the index (source: pr-16696.md; backports pr-16702, pr-16707).

**Pod-group Workloads now show their Pods** (feature, v0.20.2 / v0.19.9): `buildWorkloadPodsIndex` also indexes Pods by pod-group name, read from the `kueue.x-k8s.io/pod-group-name` annotation or label, and when no Pod matches a Workload's job UID it looks the Workload up **by its own name**. This covers plain pod groups and the StatefulSet and LeaderWorkerSet Workloads built on them (source: pr-16849.md, fixes issue-16694; backports pr-17186, pr-17189).

## Workload detail: ClusterQueue and preemption restored

After the move to the typed client (pr-7663) the handlers returned bare objects. The workload detail handler `fetchWorkloadDetails` dropped `clusterQueueName` and `preemption`, so the page showed no ClusterQueue and linked to `/cluster-queue/undefined` ([[issue-16275]]). Fixed by #16279, shipped in v0.20.1 and v0.19.8 (source: pr-16608.md, pr-16905; CHANGELOG-0.20.md, CHANGELOG-0.19.md).

Still open at this snapshot: the `/ws/workloads` list returns the raw `WorkloadList`, so the "Preempted" column always shows "No" ([[issue-16276]]). **Correction (2026-10-21):** this page earlier named pr-17104 as the fix for issue-16276; pr-17104 fixes the Status column (issue-17102), not the Preempted column. Backend tests run in CI (source: pr-16257.md); the frontend image build retries `npm install` and backend tests retry `go mod download` against transient network failures (pr-16719, pr-16724).
