# Security — Supply Chain

**Summary**: Patterns from the 7 Supply Chain CVEs in `raw/cve/`. Smallest category in the corpus, but the one whose impact scales to every Kueue deployment because a compromised release artifact affects all downstream clusters at once.

**Sources**: `raw/cve/` — representative entries `CVE-2020-8564.md` and other supply-chain category CVEs; CWE-295 (improper cert validation) and CWE-494 (download of code without integrity check) entries broadly; 2026-09 additions `CVE-2026-50166.md`, `CVE-2026-52724.md`, `CVE-2026-100704.md`, `CVE-2026-100833.md`; 2026-10 additions `CVE-2026-105216.md`, `CVE-2026-105223.md`, `CVE-2026-109358.md`, `CVE-2026-107446.md`.

**Last updated**: 2026-10-21

## Why this matters for Kueue

Two pipelines define Kueue's supply chain:

1. **Build & release** — `kubernetes-sigs/kueue` → container image at `registry.k8s.io/kueue/kueue:vX.Y.Z`. The release process is described in [[release-process]]; [[reviewer-tenzen-y|tenzen-y]] is the de-facto release manager.
2. **Dependencies** — `go.mod` / `go.sum` — every Kubernetes client-go, controller-runtime, and integration SDK update flows through here. [[reviewer-mbobrovskyi|mbobrovskyi]] is the project's dependency-bump approver.

A compromise in either pipeline runs Kueue's controller pod with attacker-chosen code, inheriting the manager-role ClusterRole on every cluster running Kueue.

## Patterns to flag in review

From the shared `Security Code Patterns` block in supply-chain CVE files:

- **Image references without digest pinning** (`image: foo:latest`).
- **Missing image signature verification before admission.**

For the broader supply-chain surface, the additional patterns are:

- **`go.mod` updates without justification.** Every replace directive, every direct dependency added, every major version bump deserves an explicit reason in the PR body.
- **`go.sum` mutations divorced from `go.mod` changes** — sign of tampering.
- **Build-time scripts pulled from the internet** in `Dockerfile`, `Makefile`, or CI YAML (`curl ... | sh`). None should exist; verify on review.
- **Unpinned actions in GitHub workflows** (`uses: org/repo@main` rather than a SHA). Prow + the SIG infrastructure pin to SHAs by convention.

## Specific anti-patterns by CWE

### CWE-295 — Improper certificate validation

In Kueue, the canonical instances are:

- `tls.Config{InsecureSkipVerify: true}` anywhere in `pkg/`. Must never appear outside `_test.go` files. `git grep -n 'InsecureSkipVerify' pkg/` should return nothing.
- [[multikueue]] kubeconfigs with `insecure-skip-tls-verify: true`. The controller should reject worker kubeconfigs flagged insecure, or at least log a prominent warning.
- HTTP clients constructed without a custom `TLSClientConfig` — relying on Go defaults is fine for HTTPS, but any custom transport that omits cert pinning when talking to a non-API-server endpoint is suspect.

### CWE-494 — Download of code without integrity check

- Tooling installs in `hack/` scripts that `curl | sh` are the canonical case. Audit `hack/tools.go` and `hack/*.sh`.
- Helm chart dependencies — if Kueue's chart ever pulls a sub-chart, pin to digest, not version range.

## Release & artifact hygiene

Items that the project already does and reviewers should preserve:

- **Multi-arch images published to `registry.k8s.io/kueue/`** — the SIG infrastructure handles signing via the GCP KMS chain.
- **Reproducible builds** — `go build` with pinned compiler version via `.go-version`.
- **Release notes** — every release lists CVE-fix references when present (none yet for Kueue itself).

Items that aren't yet routine but should be flagged for new code:

- **Cosign signature verification example** in install docs for users who run Kueue under a strict policy controller.
- **SBOM publication** — generated by SIG-release tooling; verify it ships with each release.

## Mitigation pattern in CVE corpus

> Pin all container images to their digest (`:tag@sha256:...`). Enable image signature verification via Cosign/Sigstore. Use admission webhooks to reject unsigned or unpinned images.

Applied to Kueue itself:

- The bundled `config/default/manager.yaml` should reference `registry.k8s.io/kueue/kueue:vX.Y.Z@sha256:...` in release builds (the dev manifest uses `:devel` — that's fine for development).
- Downstream installers (Helm chart, kustomize) should preserve the digest when pinning.

## 2026-09 additions

- **TLS verification silently off when a CA file is omitted.** Kuma `kumactl` (CVE-2026-50166, CWE-295) and Universal-mode `kuma-dp` (CVE-2026-52724, CWE-295), fixed in 2.7.26, 2.9.16, 2.11.14, 2.12.11, 2.13.7 (no CVSS): connecting to an HTTPS control plane without `--ca-cert-file` disabled peer verification and sent API or dataplane tokens over the unverified connection (source: CVE-2026-50166.md, CVE-2026-52724.md). Rule: the absence of a trust anchor must fall back to the **system trust store or refuse**, never to `InsecureSkipVerify`. Applies to [[multikueue]] kubeconfigs that omit `certificate-authority-data`; keep the existing `InsecureSkipVerify` grep.
- **Policy exception broader than the exception.** Kyverno 1.14.0-1.19.0, CVE-2026-100704 (CWE-863, 7.7, fixed 1.19.1): the `ImageValidatingPolicy` evaluator ignored `spec.images` and `spec.allowedValues` of a `PolicyException`, so an exception for one trusted image skipped signature verification for **every** image on the matched resource (source: CVE-2026-100704.md). Rule: an exemption must be applied at the granularity in which it is written, and sibling policy types that read the same field differently (partial versus whole) are a bug magnet. For Kueue: a `ManagedJobsNamespaceSelector` exclusion or an AdmissionCheck exemption must not widen from "this object" to "this namespace".
- **Container image substitution in confidential computing.** Contrast CVE-2026-100833 (CWE-20, 8.2): policy accepted `image_guest_pull` storage without a digest check, so a cluster administrator could swap images (source: CVE-2026-100833.md). Digest pinning only helps if the verifier enforces it.
- **Untrusted image or artifact formats parsed by the node runtime.** containerd CVE-2026-53493 (crafted OCI index graph, CWE-400/770/834) and CRI-O CVE-2026-92574 (checkpoint restore keeps checkpoint credentials, CWE-250, 8.8); see [[security-denial-of-service]] and [[security-authn-authz]].
- **Control plane of a bundle-like source.** Flux source-controller CVE-2026-47680 and Fleet CVE-2026-93537 read or write outside their working directory from Git or bucket content; see [[security-injection-and-input-validation]].
- **CWE-494-style unverified download.** Envoy Gateway CVE-2026-53716/53717 fetch tenant-specified Wasm from a URL or OCI image where the optional sha256 check is not mandatory and no operator allow-list exists (source: CVE-2026-53716.md, CVE-2026-53717.md). If Kueue ever fetches content named in a CR, require a digest and an allow-list.
- **Insecure defaults in shipped charts.** Eclipse aeriOS CVE-2026-86464 (CWE-798/1188, no CVSS): default Keycloak and PostgreSQL passwords and NodePort exposure in Helm and Docker Compose (source: CVE-2026-86464.md). Fix pattern: generated random credentials in a Secret and internal-only Services.

## 2026-10 additions

None of these libraries or runtimes is a Kueue dependency: `go-micro`, `maclof/kubernetes-client`, containerd and overlaybd appear in no `go.mod`/`go.sum` under `raw/kueue/` ([[security#2026-10 wave: what the 26 new CVEs add]]).

- **Insecure TLS as a library default.** go-micro before 6.0.0, CVE-2026-105216 (CWE-295, 7.4): the shared TLS helper set `InsecureSkipVerify: true` by default. That exposed gRPC transport, HTTP and RabbitMQ broker, and Consul or etcd registry traffic, including tokens, to man-in-the-middle (source: CVE-2026-105216.md). Rule: when a dependency bump or new dependency brings its own TLS helper, check its default. A `git grep InsecureSkipVerify pkg/` does not see defaults inside imported helpers, so read the helper.
- **Verification dropped when the kubeconfig has no CA.** maclof kubernetes-client 0.17.0 to before 0.32.0, CVE-2026-105223 (CWE-295, 7.4): `parseKubeconfig()` turned verification off when `certificate-authority-data` was missing and ignored `insecure-skip-tls-verify` (source: CVE-2026-105223.md). This is the third instance of the Kuma rule above. client-go falls back to system roots in this case, and Kueue's [[multikueue]] `validateKubeconfig` additionally rejects `insecure-skip-tls-verify: true` and CA *file* paths.
- **World-writable files from a privileged installer.** Edgeless Contrast 1.8.0 to before 1.24.1, CVE-2026-109358 (CWE-732, 7.8): the node installer wrote the containerd config with mode `0666`, so a local unprivileged user could change the `runc` path and escalate (source: CVE-2026-109358.md). Kueue's `pkg/` and `cmd/` contain no `os.WriteFile` calls; webhook serving certificates are written by the vendored `open-policy-agent/cert-controller`. Rule: file modes in new code are reviewed like RBAC.
- **Untrusted image formats parsed by the runtime.** containerd overlaybd <= 1.0.18, CVE-2026-107446 (CWE-190, 6.8): an integer overflow in `do_load_index` on `index_bytes` led to an out-of-bounds heap access from an untrusted registry blob (source: CVE-2026-107446.md). This is a node-side issue and reinforces digest pinning of every image Kueue's charts reference, including KueueViz.
